# AI 审 AI 审出来的裁判会塌缩：评分挤扁、语义同质，TrustReviewer 两边止血

你有没有过这种体验：LLM-as-judge / 自动审稿越用越顺，合成评语也开始回流进公开语料和下一代训练——下一任「裁判」其实在学上一任的判断口径。马里兰大学这篇（arXiv:2609.20942；亦见 2026-09-21 HF Daily Papers）在受控设定里走**一步递归**：先用 Llama 3.1 8B 在 ICLR 2018–2023 官方审稿上训出 \(M_1\)，再对 ICLR 2024 按每篇 0/1/2/3 条合成审稿混入官方审稿，训出 \(M_2^{p}\)（\(p\in\{0\%,33\%,66%,100\%\}\)）。结果不是单纯变松或变严，而是**科学判断塌缩（scientific-judgment collapse）**：评分分布被压缩，同篇与语料级语义多样性单调下降。缓解侧给出开源系统 TrustReviewer——单阶段精选语料训练 + 测试时成对激活转向。看完我的感受是：这对 Byron 关心的 [LLM-as-Judge](./20260917_LLM-as-Judge_论文解读_裁判只是评测栈的一层如何搭闭环.md) 闭环，钉死了一条具体失败模式——**用合成裁判数据训下一任裁判，会先丢多样性**。

## 核心摘要

受控递归实验固定初始化、过滤与优化超参，只改合成暴露比例 \(p\)。官方参考评分分布 STD **1.73**、熵 **2.38**；官方-only \(M_2^{0\%}\) 为 **1.63 / 2.31**；引入 **33%** 合成后进一步落到 **1.44 / 2.14**，66%/100% 仍低于 \(0\%\) 基线。均值非单调（\(0\%\) **5.30** → \(33\%\) **5.85** → \(100\%\) **5.70**）——塌缩主轴是**分散度**，不是系统性松严。同篇语义距离（embedding 平均两两余弦距离）从 \(M_2^{0\%}\) 约 **0.159** 依次到 **0.153 / 0.147 / 0.142**（\(0\%\to100\%\) 约 **−11%**）；语料级相对质心 spread 从约 **0.609** 到 **0.584 / 0.580 / 0.579**（约 **−5%**）。缓解：精选 ICLR 2018–2025 官方审稿得 **112,743** 条 paper–review（约 **1.9B** tokens），Llama 3.1 8B 单阶段 SFT 得核心审稿模型 \(M_\mathrm{TR}\)；再在 \(K=5{,}000\) 同篇「官方 vs \(M_\mathrm{TR}\)」对上估层向转向向量，推理时在末层残差加 \(\alpha=0.15\)。Held-out（2,000 篇跨年留出）上 TrustReviewer exact match **75.40%**、MAD **1.079**、熵 **2.18**，优于 OpenReviewer（73.10 / 1.113 / 2.10）、Qwen3.6-35B-A3B（61.85 / 1.335 / 1.94）与 Llama 初始化（33.93 / 2.679 / 1.53）；相对无转向同 checkpoint，exact match **73.85→75.40（+1.55pp）**，熵 **2.13→2.18**。作者强调：只测了**一步**递归；多样性≠质量；与官方评分一致≠科学正确。

## 🎯 递归审稿不是科幻：合成暴露一抬，判断口径就变窄

背景钉在两条已知线索上：模型塌缩文献（合成数据反复拟合会抹掉低概率尾）提醒风险；Gerstgrasser 等又表明**保留并累积真实数据**时塌缩未必必然。同行评审的特殊点在于：监督信号本身是**条件科学判断**（对同一稿件的评分与论证），不是无条件文本。Liang 等已估计部分 AI 会议审稿语料存在实质性 LLM 修改痕迹——但无法逐条贴标签。本文不做「真实污染率测量」，而是把「已知数量的 \(M_1\) 合成审稿」当唯一计划差异，问：**下一任审稿模型的判断分布会不会变窄？**

术语上坚持叫 **official** 而非 human：ChatGPT 普及后的「官方」审稿可能已含未观测 AI 辅助；\(p\) 度量的是**明确由 \(M_1\) 生成的比例**，不是总 AI 患病率。这对 judge 闭环工程很重要——你以为在用「真人金标」，可能已经在喂上一代模型的口径。

## 🏗️ 机制：一步递归实验台 + TrustReviewer 双阶段干预

### 受控递归框架（Sec. 2）

- \(M_0\): Meta-Llama-3.1-8B-Instruct；\(M_1=T(M_0,D_{2018:2023}^\mathrm{off})\)。
- 截止到 2023：既降低 ChatGPT 时代污染，又对齐 Llama 3.1 预训练截止（2023-12），降低 \(M_0\) 已见过 ICLR 2024 官方审稿的风险。
- 每篇贡献 3 条审稿；\(p=0/33/66/100\%\) 对应 0/1/2/3 条合成。\(M_2^p=T\bigl(M_1,D_{2024}^p(M_1)\bigr)\)。
- 训练：LlamaFactory + LoRA（rank 64，\(\alpha_\mathrm{LoRA}=128\)，dropout 0.05）；\(M_1\) LR \(2\times10^{-5}\)，各 \(M_2\) LR \(2\times10^{-6}\)；上下文 64k；三 epoch。过滤：畸形/跟帖、过短、重复 n-gram、超长等统一管线。
- 评测：留出 **2,000** 篇（2018–2025 分层抽样），训练与转向估计均排除；各模型在同一集合上生成审稿再比。

### TrustReviewer（Sec. 3）

1. **训练时预防**：对 2018–2025 官方审稿统一过滤得 \(D_\mathrm{curated}\)（112,743 例 / ~1.9B tokens），**单阶段** SFT，不做「先训 \(M_1\) 再递归混合成」的第二阶段——直接减少低质与语义退化监督。
2. **测试时纠正**：在 5,000 校准对上，用末非 padding token 隐状态差估 \(v_\mathrm{steer}^{(\ell)}=\mathbb{E}[\phi_\ell(r^\mathrm{off})-\phi_\ell(r^\mathrm{TR})]\)；生成时在所选层残差末位置加 \(\alpha v_\mathrm{steer}\)。验证 100 对搜层与强度，选定末层 \(\ell=31\)、\(\alpha=0.15\)。参数不动、无需额外专家标注。

管线一句话：\(D_\mathrm{raw}\xrightarrow{C}D_\mathrm{curated}\xrightarrow{\text{one-stage SFT}}M_\mathrm{TR}\xrightarrow{\text{steering}}M_\mathrm{TR}^\mathrm{steered}\)。

## 🧪 关键证据：压缩是单调的，松严不是

### 塌缩三件套（Fig. 2–3）

- **评分分散度**：33% 合成就把 STD/熵相对 \(M_2^{0\%}\) 明显压扁；更高 \(p\) 仍低于官方-only。均值先升后降——若只看平均分，会误判「没大问题」。
- **同篇同质化**：独立多次生成的同稿审稿越来越像；\(0\%\to100\%\) 约 **11%** 距离下降。
- **语料收缩**：paper-level embedding 相对质心 spread 约 **5%** 收缩；最大一跳发生在「从 0 到引入合成」，之后继续缓降。

### TrustReviewer 对照（Table 1 / Fig. 4）

| Model | Exact Match ↑ | MAD ↓ | Entropy ↑ |
| --- | --- | --- | --- |
| Official（参考） | – | – | 2.38 |
| Llama 3.1 8B Instruct | 33.93 | 2.679 | 1.53 |
| Qwen3.6-35B-A3B | 61.85 | 1.335 | 1.94 |
| OpenReviewer | 73.10 | 1.113 | 2.10 |
| TrustReviewer w/o steering | 73.85 | 1.077 | 2.13 |
| **TrustReviewer** | **75.40** | **1.079** | **2.18** |

转向额外抬 exact match **+1.55pp**、熵 **+0.05**，语料 spread 也扩；同篇距离略降但仍远高于通用 Llama/Qwen。作者诚实写：不是每个多样性指标都单调变好——转向优先改善**与官方推荐对齐 + 聚合判断广度**，而非万能多样性旋钮。语料公开可复现，对比 OpenReviewer 训练语料未公开，这是工程加分项。

## 🔬 最有意思的部分：给 judge 闭环的「反例教材」

把这篇嵌进 Byron 的评测栈叙事（[LLM-as-Judge](./20260917_LLM-as-Judge_论文解读_裁判只是评测栈的一层如何搭闭环.md)）：先有 rubric / 代码检查，再上 LLM judge，再 golden+holdout——**TrustReviewer 警告的是「用 judge 输出当下一任 judge 的监督」这一环**。它不是说「永远别用合成」，而是：合成比例一抬，先塌的是**判断分布的宽度**；若闭环还把合成当金标回流，你会在不知不觉中训出「口径一致但视野变窄」的裁判族。和 model collapse 文献的对接也很干净：保留真实/官方数据、避免被合成替换，是训练时止血；成对激活转向则是**不重训**时纠 residual 同质化倾向——类似把 representation engineering 接到评审行为上。

局限（Appx. G）必须一起读：仅一步递归、一族基座、一个会议域；多样性≠正确性；exact match/MAD 量的是与官方评分分布的一致，不是科学对错；embedding 距离是代理，不能直接证明「抓到了不同有效科学关切」。人类对 critique 正确性、具体性、覆盖面的评估仍缺。

## 🤔 我的判断

定位：**递归 AI 审稿的受控失败模式测量 + 开源缓解系统**，对 LLM-as-judge / evals 闭环是「必须写进风险清单」的一篇。亮点三：

1. 实验干净：只拧合成比例旋钮，把「松严漂移」与「多样性塌缩」拆开；
2. 数字可引用：同篇约 −11%、语料约 −5%、评分 STD/熵被压——失败模式可监测；
3. 缓解可落地：单阶段精选语料 + 末层 \(\alpha=0.15\) 成对转向，且语料/代码公开。

局限与代价：一步递归能否代际复合未知；「官方」≠纯人类金标；对齐官方不等于更好科学判断；激活转向对同篇多样性略有代价。对 Byron：自建 judge / 审稿助手时，**(a)** 训练语料标注合成比例并设上限；**(b)** 监测评分熵、同题多样本语义距离、语料 spread，而不只盯均分；**(c)** 优先 rubric + 代码检查 + golden holdout，LLM judge 当一层而非唯一回流源；**(d)** 若必须用合成，累积真实数据、避免替换式递归——这篇把「为什么」测清楚了。

一句话收束：AI 可以帮人审稿，但若让 AI 的判断成为下一代审稿模型的主粮，先塌掉的往往不是准确率口号，而是**判断还敢不敢不一样**。
