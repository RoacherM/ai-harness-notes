# 专家工具库帮了也害了：失败驱动自进化，才敢把新工具装进 Agent

你有没有过这种体验：给 coding agent / 时间序列 agent 塞进一堆「专家觉得很有用」的 Skills 或工具，平均分好像涨了一点，但某一类任务（异常检测、某档预测）却稳稳掉分；再开一轮 Self-Refine，改了上百条答案，修好的和搞坏的几乎打平，总分几乎不动，你还以为「没事」。Visa Research × UIC 这篇 TimeEvo（arXiv:2609.27277）把这两种现象钉死成 **Human–Agent Tool Misalignment** 与 **Silent Harm**，然后反问：能不能让 agent **从自己的失败里合成缺的工具**，并且用配对门禁挡住「修了 A 却砸了 B」的静默伤害？看完我的感受：时序只是实验床——机制直接对着 Byron 关心的 **skills 自进化 / SkillPivot / 准入门禁 / harness 闭环**；和 [SkillPivot](../week4/20260925_SkillPivot_论文解读_失败别整轨反思_先找偏航点再对比后缀改技能.md) / [EvoSkill-GUI](../week3/20260918_EvoSkill-GUI_论文解读_技能不是静态文档_部署时无训练自进化.md) 同族，但把「admit 时要数清修了多少、害了多少」写成了硬闸门。

## 核心摘要

TimeEvo 是一个面向时间序列 QA 的 **失败驱动工具库自进化** 框架。基座 TSAgent 从空库起步（仅保留预测根工具），每轮：在训练集上重放 → 把错题聚成 failure buckets → 为每个桶写测量合同（测什么、成功标准、适用范围与反范围、CREATE/REFINE/RETIRE）→ 合成 **evidence-only** 候选工具 → 先做 per-tool 预筛，再整库过 **paired admission gate**（同一验证题上对比旧库 vs 候选库，统计 helped / harmed，要求净修复且下界为正；失败则剪枝一次再测）。十任务 × 三 backbone（GPT-5.6-luna / terra / GPT-5.4-mini）上，TimeEvo **是唯一在每个任务、每个 backbone 上都正增益** 的方法（均值约 +7.2～+8.8 pp）；专家库 TimeART 21 tools 在异常检测上反而 −5.8～−8.8 pp；Self-Refine 改 147 题却净 −0.9 pp。更刺眼的迁移结果：luna 进化出的库装进 Claude Opus/Sonnet 5 与 GPT-5.6-sol，十任务均值仍涨约 +8.3～+10.7 pp。代码：https://github.com/Muyiiiii/TimeEvo。

## 🎯 为什么这件事值得写

工具/技能供给长期假设「人配好、agent 用好」：TimeART、Voyager 技能库、SkillOpt / CoEvoSkills 一类工作要么固定库、要么用最终分或 per-task 检查做准入。TimeEvo 的诊断指出两个结构性漏洞：

1. **供给粒度 ≠ 收益粒度**：工具按任务族提前装好，但「这道题要不要用它」是 runtime 决策——库越大，越可能把 agent 引到错误调用路径。
2. **最终分会洗白伤害**：Self-Refine 修 49、砸 56，总分几乎不动——这正是 skills 进化最危险的地方：你只盯 mean accuracy，静默回归会进生产。

对 Byron（skills / RSI / harness）：日常闭环里「失败→改技能→再测」已是标配，但多数门禁仍是「整体分涨了就合入」。TimeEvo 把门禁改成 **配对计数：helped vs harmed**，并要求证据型工具（只产出可核验测量，不做主观总结）。这比「再写一条教训进 prompt」更接近可版本化的 Manifest 变更。

## 🏗️ 机制：失败桶 → 测量合同 → evidence-only 工具 → 双层准入

**诊断侧。** 当前库 \(L_{r-1}\) 在训练集重放，错题按失败模式分成不相交 buckets；每个桶生成一份 measurement contract：要测的量、成功准则、scope / anti-scope，以及库动作类型 CREATE / REFINE / RETIRE。范围冲突会收窄或合并，避免「万能工具」吞掉半个任务族。

**合成侧。** 合同被编译成 **evidence-only** 可执行工具：统计决策留给准入门，工具本身只负责产出可复现的测量结果。作者刻意不让工具在库内「自判好坏」，防止把验证信号提前泄漏进工具逻辑。

**准入侧（核心）。**  
- Level-1：per-tool 预筛（内部平衡准确率等，样本量门槛）。  
- Level-2：**Paired Admission Gate**——旧库与候选库在完整验证集上配对跑，只比较双方都完成的题；统计 \(h=|\mathrm{helped}|\)、\(m=|\mathrm{harmed}|\) 与配对 delta 的下界 \(\delta_{lb}\)；严格通过条件为 \(h>0\) 且 \(\delta_{lb}>0\)（另有净修复 ≥3 题或 ≥2% 的补充规则）。失败则按验证伤害剪枝一次再测，通过后才链入 \(L_r\)。  
这直接针对 Silent Harm：更新不再用「平均分涨了没」做唯一判据。

**协议。** 空根库起步、单轮进化、train-only 校准、test 只报告；与 Chronos-2 固定工具、TimeART 21 tools、Self-Refine、vote@5、few-shot ICL 同拆分对照。

## 🧪 关键证据

**全任务全 backbone 正增益。** Table 1：TimeEvo 在 luna / terra / mini 上十任务均值分别 +8.79 / +7.21 / +8.73 pp，且 30/30 格子为正。专家库 TimeART 均值只 +0.3～+2.4，却在 Anomaly 上系统性掉 5.8～8.8 点——「有专用异常工具」也不能保收益。Self-Refine 均值接近零或负，与 intro 的 147 改 / 56 砸一致。

**迁移：便宜模型长出的库能装进更强模型。** luna 进化库 → Claude Opus-5 / Sonnet-5 / GPT-5.6-sol，十任务均值分别 +10.50 / +10.65 / +8.27；Anomaly 上甚至出现 +21～+26 pp 量级增益。说明进化产物更像 **可移植能力包**，而不只是某 backbone 的过拟合补丁。

**消融指向门禁与范围。** 去掉校准 / 门禁 / scope、或把 21 个人工工具硬塞进进化链，会损害「只修不砸」的性质；残差链（多轮累积）与「域外题保持不变」的行为也支持：好的进化是局部能力补丁，不是全局重写人格。

## 🔬 最有意思的部分

1. **Silent Harm 是评测与进化的共同盲区。** 和 [GameArena](../week4/20260928_GameArena_论文解读_主观裁判太吵静态榜又饱和_用胜负当地面真值的对战评测台.md) 的「能程序判定就别请主观裁判」同构：这里是「能配对计数修/害，就别只看最终分」。
2. **Evidence-only 工具 = 把技能写成可测合同。** 接近 [SkillSpec](../week4/20260923_SkillSpec_论文解读_第一次用Hoare规格验Agent技能_515个近半有缺陷.md) 的精神——技能/工具要带前置后置与范围，而不是一段散文 checklist。
3. **Human misalignment 不是「工具不够」而是「固定供给 vs runtime 收益」。** 对 MCP / Skills 清单膨胀的警告：多装不等于多能，可能稳定地伤害某一切片。
4. **跨模型迁移成功**，暗示 skills 进化产物可以做成「弱模型挖矿 → 强模型安装」的流水线——对算力预算极友好。
5. **与 SkillPivot 的分工：** SkillPivot 改已有技能的偏航后缀；TimeEvo 从失败桶合成新测量工具并整库门禁。两者可叠：先 Pivot 修文本技能，再对工具面走 TimeEvo 式 paired admit。

## 🤔 我的判断

定位：**以失败为监督、以配对修/害为门禁的工具库自进化样本**（时序 QA 为床，机制可迁到 coding skills / MCP）。亮点三：

1. 把 Human–Agent Tool Misalignment 与 Silent Harm 测成可复现现象，而不只是 anecdata；
2. Paired Admission Gate 把「进化安全」从均值神话拉回计数；
3. 弱模型进化库可迁移到强模型，暗示 skills 供应链可以分层。

局限：主实验偏单轮进化、任务面仍是时序 QA；evidence-only 约束对「需要综合判断的技能」是否过严待证；门禁依赖可自动判对错的标签——开放主观任务仍要接 [DIAL](../week4/20260928_DIAL_论文解读_消掉位置偏差还不够_少量人工把多裁判偏好校准成人味.md) / JEV 一类。对 Byron：在 MMP / Skills 合入流水线加一条硬规则——**任何技能或工具变更必须报告 helped/harmed（或 golden 切片），禁止只报总分**；合成新工具时优先 evidence-only（测、检、算），把叙述留给 reader。和 [RRSI](../week4/20260923_RRSI_论文解读_Harness_RSI会过拟合正则提案与筛选才保住OOD.md) 合读：RSI 提案要正则与筛选，TimeEvo 把筛选写成了配对门。

一句话收束：**工具该不该进库，别问专家好不好看，问它在配对题上修了多少、砸了多少**——TimeEvo 把这句话做成了可跑的进化环。
