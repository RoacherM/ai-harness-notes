# 技能不够成考场：能力难度模式，才把环境造硬

你有没有过这种体验：手里有一堆 ClawHub / Agent Skills 的 `SKILL.md`，里面写清了 CLI、步骤、模板，但一说「拿来训 agent」就卡住——技能描述的是**怎么用工具**，训练需要的是**可执行任务 + 工作区 + 对齐目标的评测**。AllSpark 团队这篇 **Skill2Env**（arXiv:2609.33772）把缺口说透：从 skill 到环境中间还差一层 **capability demand → difficulty pattern → task blueprint**，再用 solver 轨迹做 **Iterative Task Hardening**。看完我的感受：这正好接在 Byron 的 **skills / harness / rubric 评测** 线上——比「再合成一万条指令」更关键的是**按能力轴造难、用执行证据加硬**；1.5K 条高分轨迹 SFT 就能在七个 agent 榜上抬平均 +8.4。

## 核心摘要

Skill2Env 从 ClawHub 筛出 3K+ 可落地 skill，用五维能力需求（环境理解 / 规划 / 技能使用 / 长程一致性 / 错误恢复）与约 100 个可复用 **difficulty pattern** 驱动合成：先写 **task blueprint**（目标、挑战、环境事实、信息边界、验收标准），再联合生成指令、执行基底、工作区与 **rubric 评测器**（程序化项 + LLM judge 加权）。对高奖励任务触发 **Iterative Task Hardening**：诊断「已被轻松通过」的挑战，加强或追加 pattern，同步改 blueprint 与环境，并可把新挑战沉淀回 pattern 池。最终 **2,963** 个可执行任务；用 DeepSeek-V4-Flash 教师轨迹筛 \(r>0.9\) 的 **1.5K** 条 SFT Qwen3.6-35B-A3B 后，七榜未加权均分 36.6→45.0（Terminal-Bench 2.1 +13.5、SkillsBench +14.3、SWE-bench Multilingual +7.7 等），且在 pi / Terminus-2 / OpenCode / Claude Code 四套 harness 上 Terminal-Bench 均升。硬化两轮使配对任务满分率 48.4%→15.4%、交互轮次约 +50%，同预算 SFT 下游均分再抬约 2.3。

## 🎯 为什么这件事值得写

Skill 热潮之后，下一批瓶颈是 **post-training 用的可执行环境**。SkillSynth / Terminal-World / FACET / SKT 已从 skill 图或场景重建推任务；Skill2Env 多问一句：**给定 skill，如何按 agent 能力缺口来造环境？** 答案不是更大的 prompt 模板，而是把能力需求操作化成 difficulty pattern，并用 blueprint 当「作者侧合同」锁住指令–基底–工作区–评测四件套一致性。对 Byron：这是「skills 资产 → 训练/评测环境工厂」的清晰流水线，且评测侧默认 **rubric（可执行优先 + LLM 补主观项）**，贴合他偏好的 judge 建设顺序。

## 🏗️ 机制：Pattern → Blueprint → Hardening

**形式化。** Skill \(\kappa\) + 执行基底 \(\mathcal{X}\) + 初值工作区 \(W_0\) 构成环境 \(\mathcal{E}\)；任务 \(\mathcal{T}=(g,\mathcal{E},V)\)。Rollout 后 \(r=V(s_L)=\sum_c w_c q_c\)。

**五维能力 × pattern 池。** 理解 / 规划 / 技能使用 / 长程一致 / 错误恢复各挂一批可调强度的模式（如分布式证据、状态依赖、资源预算、跨格式一致、故障定位等；附录列约 100 条）。合成 agent 按 skill 工作流选兼容子集 \(\mathcal{P}_\kappa\)。

**Blueprint。** 作为作者侧合同：目标与挑战如何落在事实上、信息边界（指令给什么 / 工作区可发现什么 / 须推断什么）、执行需求、验收标准。再据此生成 \(g,\mathcal{X},W_0,V\)；工作区混合合成材料与检索真实材料。

**一致性校验。** Solver 跑完后 validation agent 对照 blueprint 查任务条件与 rubric；合同问题联动改四件套，实现问题按原合同修；污染证据不进硬化诊断。

**Iterative Task Hardening。** 奖励超阈值（文中 0.7）的任务进入硬化：Diagnose → ProposeHardening（加强已有 pattern 或加兼容新 pattern）→ ReviseBlueprint → Reconstruct。可把新挑战抽象进 \(\mathcal{P}\)。Docling 案例：文档技能 → 供应商对账环境，两轮硬化从 10 文件/3 差异扩到 21 文件/12 差异，并把「OCR 路径写错仍靠读图兜底」改成必须可靠抽取的扫描 PDF。

## 🧪 关键证据

**主结果（Qwen3.6-35B-A3B）。** 七榜均分 +8.4；SkillsBench（skills on）+14.3，skills off 仍 +10.4；媒体 / 数理 / 软件工程域增益最大。相对更大基座 Qwen3.5-397B-A17B 在六榜上仍更高——作者归因于**可迁移的能力向监督**而非堆规模。Frontier 闭源仍明显领先，头上有空间。

**Harness 泛化。** Terminal-Bench 2.1：pi +11.2、Terminus-2 +13.5、OpenCode +16.9、Claude Code harness +12.3——同一套 SFT 不绑定单一脚手架。

**硬化效用。** 500 配对任务、DeepSeek-V4-Flash+pi：满分率 48.4→24.8→15.4，助手轮次 25.9→36.5→38.9。同 500 条 \(r>0.9\) 轨迹预算下，0/1/2 轮硬化后七榜均分 40.58→42.51→42.87。

**泼冷水。** 合成用 Kimi-K3、硬化 solver 固定 Qwen3.6-35B-A3B、rubric LLM 用更大 Qwen——跨模型泛化未完全拆；SkillsBench 金融域 skills-on 持平；相对 FACET 等基线对照不完整（表中多处 “-”）；2.9K 任务的「能力覆盖均匀性」依赖 taxonomy 标签质量。

## 🔬 最有意思的部分

1. **Blueprint 是合同不是摘要。** 信息边界写清「权威 brief 在工作区、费率在合同附件、归档发票故意诱饵」——这比「生成一个难任务」更能防止评测泄漏与捷径。
2. **硬化触发是成功而非失败。** 对 \(r\) 高的任务加难，直接对抗「合成环境被当前 solver 刷穿」。
3. **Pattern 池可增长。** 执行中发现的可泛化挑战回流——环境工厂带一点 continual curriculum 味道。
4. **与 ExpVoyager 对偶。** 本周归档的 ExpVoyager 是任务时导航原始经验再写 skill；Skill2Env 是**从 skill 反造可执行考场**。一条链路：经验→技能→环境→更强轨迹→再经验。
5. **Rubric 权重显式。** 对账案例里 CSV/JSON/corrections/memo 分权，确定性项为主、memo 用 LLM——工程上可直接抄进 harness 评测栈。

## 🤔 我的判断

定位：**以 skill 为锚的能力向环境合成 + 执行驱动加硬**（方法 + 可复用工厂样本）。亮点三：

1. 把「skill 有了为何还不够训」拆成可操作的 pattern/blueprint 层；
2. Hardening 用成功轨迹当加难信号，而不是只修失败环境；
3. 少量高分轨迹跨榜、跨 harness 迁移，说明监督对准的是共享执行能力。

局限：合成/裁判模型族耦合；与其它 skill-env 工作的公平对照不足；长程 RL（相对 SFT）未展开。对 Byron：若你在攒 skills 库——**下一步工厂顺序**可以是：筛 runtime 可行 skill → 挂五维 difficulty 清单出 blueprint → 程序化 rubric 先行 → 用固定弱 solver 做 hardening 循环 → 再采教师轨迹。评测侧把「信息边界 / 验收项」版本化进 Manifest，避免技能文档与考场漂移。接 [ExpVoyager](./20260930_ExpVoyager_论文解读_技能别提前烤死_按需在经验上导航再合成.md)：那边管「何时写 skill」，这边管「skill 如何变成够硬的训练环境」。

一句话收束：**技能说明书不是考场——Skill2Env 用能力难度模式和加硬循环，把 skill 锻成 agent 真正咬得动的可执行任务。**
