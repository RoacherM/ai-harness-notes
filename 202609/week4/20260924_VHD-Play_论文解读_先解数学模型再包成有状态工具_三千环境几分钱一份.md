# 先解数学模型，再包成有状态工具：三千环境，几分钱一份

你有没有过这种体验：想扩 agentic RL 环境，却卡在「先造 E，再事后对齐奖励」——动力学写完了，outcome 规则靠 checklist / 学来的 judge，验签成本与漂移一起涨；或者模型笔答优化题接近满分，一进多轮有状态工具调用就崩？阿里 Token Foundry / Qwen 技术报告线这篇 VHD-Play（Verifiable Hidden Dynamics Play，arXiv:2609.27321）把顺序反过来：**先采样并解数学机制 \(M(\theta)\)**，钉死参考 \(z_\theta\) 与奖励 \(\mathcal{R}_\theta\)，再实现动力学 \(D(\theta)\)、包成有状态工具环境 \(E(\theta)\)；玩家看不见参数与解，只能靠交互探测。看完我的感受是：这和 [CodeMidas](./20260922_CodeMidas_论文解读_只靠源码榨出五千可验证coding_RL环境.md) 同属「可验证环境工厂」，但验签来自 **预解的 OR/优化机制**，不是挖源码——最大学习缺口在 **有状态交互**（信息采集 + 绑定承诺），不是裸解题。

## 核心摘要

VHD-Play 主张 mechanism-first：environment-first 管线先造 \(E\) 再事后定义 \(\mathcal{R}_E\) 或标注轨迹；本文先解 \(M(\theta)\to z_\theta\)，再 realize / wrap。语料 grounding 的 setter 用真实文档段落渲染场景语言、关系库与 ≥10 个有状态工具；准入检查可执行性与参考回放一致。规模：**3,300** 个准入环境，单份约 **几美分（≈$0.01–$0.03）**。用 GRPO 训 Qwen3.6-35B-A3B：五族诊断上平均 agentic 分 **0.204→0.815**；held-out 训练族与 **8** 个未见机制族均涨；外部：E-Commerce Bench **零破产**、期末余额约 **3.4×** base 并超过 Qwen3.7-Max；BFCL V4 交互向十格 **+2.84**；TravelBench 计划分 **0.700→0.794**。笔答（written-out）近天花板时，同题 agentic 仍大崩——训练主要补的是 stateful policy，不是数学能力。

## 🎯 为什么这件事值得写

长程 agent 任务要：多样环境、可靠 outcome 信号、低扩展成本。笔答数学 / 搜索给廉价精确信号，却把信息塞进提示词；手写模拟器可交互但每族要专家；人类反馈贵；学来的 judge / rubric 自己要被验。生成式工具与环境（AutoForge、EnvScaler、ScaleEnv 等）降写作成本，却常 **先有 E，再对齐奖励**——动力学与评价事后磨合。

VHD-Play 的分野：运筹 / 优化模型自带成熟求解器与可参数化实例；**同一份预解参考**同时生成隐藏动力学与轨迹打分。对 Byron（agent RL / harness / MCP 工具面）：这是「可验证奖励」从答案级扩到 **轨迹级** 的一条工程路径，也直接解释为何 coding / 商务 agent 笔试强、上场弱。

## 🏗️ 机制：先解，再实现，再包工具

构造箭头对比：

- Environment-first：\(E \xrightarrow{\mathrm{define}} \mathcal{R}_E\) 或 \((E,\pi)\to\tau\to y\)
- VHD-Play：\(M(\theta)\xrightarrow{\mathrm{solve}} z_\theta \xrightarrow{\mathrm{fix}} \mathcal{R}_\theta\)；并行 \(M(\theta)\xrightarrow{\mathrm{realize}} D(\theta)\xrightarrow{\mathrm{wrap}} E(\theta)\)；\(y_\pi=\mathcal{R}_\theta(\tau_\pi;z_\theta)\)

\(D(\theta)=(\mathcal{S},\Lambda_\theta,U_\theta)\)；\(E(\theta)\) 再加观测映射 \(\Omega_\theta\)、动作集、回合预算 \(T\)。探针动作 \(\mathcal{A}_{\mathrm{probe}}\) 与决策动作共享预算：一边采信息，一边做不可逆承诺（下单占容量、未售损失等）。Builder \(G\) 看见完整 \(\theta\) 与语料种子；政策 \(\pi\) 只看见接口观测——信息边界显式可控。

奖励用求解器锚定：

\[
z_\theta=(u^*(\theta),u_0(\theta)),\qquad
r=\mathrm{clip}_{[0,1]}\!\left(\frac{u(\pi;\theta)-u_0(\theta)}{u^*(\theta)-u_0(\theta)}\right).
\]

默认政策 → 0，全信息最优 → 1；**无 LLM 估计任一端点**。参考可用闭式、枚举、DP、HiGHS/SLSQP 等；十一族涵盖库存 DP、路径、背包、LP/QP、调度、谈判、序贯停止/搜索、设施选址等。

Setter（可用冻结的同款 35B，更强模型主要抬产量）：吃完整参数 + 独立采样的真实文档段落 → 场景、DB、工具 schema/body、玩家指令。准入：可执行、默认区合法、最优回放在公差内。审计：八族各抽 10 环境 × 三政策 × 两遍，480 次执行无异常、重复终局一致、无超参考。

## 🧪 关键证据：交互缺口、迁移、共缩放

**三呈现对照（五族宏平均，Base → 训练后）**

| 呈现 | 含义 | 分数 |
| --- | --- | --- |
| Written-out \(F\) | 完整题面 + Python 工具 | 0.962 → 0.992 |
| Informed-agentic \(I\) | 参数全揭，但仍多步有状态 | 0.231 → 0.875 |
| Agentic \(A\) | 参数须交互获取 | **0.204 → 0.815** |

\(F\to I\) 已崩大半——问题不是「不会算」，而是 **跨期状态、共享约束、持久承诺**；再藏参数只再掉一点。训练关上约 **84%** 的参数已揭 stateful 缺口、约 **77%** 的 \(F\to A\) 缺口，同时保住笔答。

**生成族迁移**：held-out 训练族均涨约 **+0.56**；近 OOD 未见优化族约 **+0.63**；远 OOD（决策结构变 / 探针受限）约 **+0.24 / +0.16**。

**外部**

| 基准 | Base | Trained | 备注 |
| --- | --- | --- | --- |
| BFCL V4 十交互格均值 | 61.25 | **64.08（+2.84）** | 与训练实例/接口无重叠 |
| TravelBench plan | 0.700 | 0.794 | Max 参考 0.891 |
| E-Commerce 365 天期末余额 | 54,294 | **182,844（3.4×）** | 5/5 完赛、0 破产；Max 165,224 |

店面回合 **1,147–1,825**，远超生成族均值约 **59.7** 轮——长程迁移是真的。

**与 EnvScaler（environment-first）同起点对照**：同 35B、同 GRPO、同 34 step / 2200 条；EnvScaler 在 TravelBench 有涨、店面全完赛，但 BFCL 十格均值 **58.56 < Base 61.25**，店面余额贴近 Base；VHD-Play 三外部聚合全涨——**预解参考**在强起点续训时更稳。

**共缩放**：冻结同款 35B 当 setter，玩家从 Base 起在 6×5 → 11×11 背包配置上匹配训练；增益 **+0.412 → +0.861**，大配置头寸更大——构造端能造出比当前政策更难的环境，且缺口仍可学。

轨迹对照：Base 写「每期找最优组合」提前花光共享预算；训练后写「需要跨 7 期规划」一次解出地平线方案。另一例 Base 只探 4/8 项就承诺；训练后探全再规划。代码工具采用率上升解释不了大部分增益（层内固定 strata 仍占主）。

## 🔬 最有意思的部分

1. **可学习缺口主要在 stateful interaction**：\(I\) 已接近 \(A\) 的崩法——harness 若只测笔答或单轮工具，会系统低估上场失败。
2. **机制先于环境**：把「验签从哪来」从事后 checklist 前移到预解 \(z_\theta\)——和 CodeMidas「执行原码 grounding」同哲学、不同原料。
3. **Setter 不必是前沿**：同款 35B 作 setter 已能出合格环境（约 70% 有效准入）；更强模型主要省尝试次数与精修率，单环境成本仍在几美分。
4. **信息边界是一等旋钮**：同一 \(M(\theta)\) 可切 \(F/I/A\) 三呈现，干净消融「解题 vs 交互」。
5. **环境–政策共缩放**：构造端持续打开比当前政策更难的空间——比「固定题库刷分」更像可持续训练底物。

## 🤔 我的判断

定位：**mechanism-first 的可验证 agentic RL 环境工厂 + Qwen 线训练证据**，不是又一个单域模拟器。亮点三：

1. 构造顺序反转写清楚，并与 EnvScaler 做同起点对照；
2. \(F/I/A\) 把「会算不会上场」测成可复现缺口；
3. 3.4× 店面 + BFCL/Travel 外部迁移，说明不是过拟合生成族皮相。

局限：机制族仍偏 OR/优化抽象，不覆盖开放软件工程杂波；奖励是回合终局标量，过程信用需另接；远 OOD 增益较小；公开复现细节依赖附录与内部管线。对 Byron（agent RL / CodeMidas 对照 / MCP 工具面）：**扩环境时优先问「参考解从哪来」**——源码榨任务（CodeMidas）与机制预解（VHD-Play）可并行：前者贴真实仓库分布，后者贴廉价精确信号与可控信息边界；训练课表应显式包含 **探针预算下的绑定决策**，而不是只堆笔答难度。

一句话收束：agentic 训练要扩，别急着先堆场景皮——**先解一个可验证机制，再把它藏进有状态工具里，让模型在交互里把解找回来**。
