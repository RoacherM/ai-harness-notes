# 记忆别在写入时裁剪：读时按任务现场策展，同一条轨迹能榨出不同课

你有没有过这种体验：agent 跑完一条轨迹，系统立刻写成 reflection / skill / workflow 塞进记忆库——看起来很「持续学习」，下次任务一来却发现 **当初丢掉的细节刚好是这题要的**，或者同一条家居交互本可以教「状态转移」也可以教「拿放顺序」，却被压成一句与查询无关的摘要。Salesforce AI Research 这篇 Just-in-Time Memory（JITMem，arXiv:2609.27334）的反转很硬：**写入时只存原始情景轨迹，策展挪到读时**——retriever 捞轨迹，**curator 在已知当前任务 \(x_t\) 时** 合成紧凑、任务自适应的 payload 再交给冻结的 executor。同一条轨迹 → 不同任务榨出不同课，作者把它对齐认知科学里 **reconstructive episodic memory**。看完我的感受：这和 Byron 关心的 [LIMBO](./20260924_LIMBO_论文解读_经验回放别全塞进提示_按任务在线配记忆预算.md) / skills / continual learning 正好互补——LIMBO 管「预算下是否/回放多少」，JITMem 管「读时策展什么内容」；也和写时 SkillOS 式技能策展形成分野。

## 核心摘要

主流 agentic memory（Reflection、ReasoningBank、MemP、SkillOS 等）在 **write time** 把轨迹蒸馏成固定制品，再用相似度检索。写时策展有两宗罪：信息损失过早且不可逆；单一制品要服务未知未来查询。学习写时 curator 更难——存储决策的效用可能很多任务后才显现，信用分配跨长程，往往要像 SkillOS 那样 **人为把相关任务编组** 才能造延迟奖励。JITMem 把 memory bank 做成被动 raw episodic store；读时 pipeline：Retrieve → Curate\((x_t,\hat\xi_t)\) → Execute。Curator 用 **GRPO** 训练：冻结 executor 拿候选 payload 试同一任务，即时任务奖励，信用塌缩到单步，无需任务编组。ALFWorld / WebShop / \(\tau^2\)-bench 上相对最强基线绝对 SR **+16.2 / +16.3 / +3.9**。即便未训练的读时策展也很强：WebShop 上 untrained JITMem-gemini **61.0** SR vs SkillOS **41.0**（同用 Gemini-2.5-Pro 作 curator+executor）。训练后的 curator 可迁移到更强 executor 而无需重训。消融表明：任务条件、成功轨迹过滤、保留 raw 轨迹各自独立贡献；去掉检索轨迹后 RL 增益基本蒸发——学的是「怎么蒸馏取回的经验」，不是参数里瞎编 hint。

## 🎯 为什么这件事值得写

「记忆该何时塑形」比「记忆用向量库还是文档」更底层。写时蒸馏把 agent 经验锁成 query-independent 摘要，和 coding-agent 里过早把失败轨迹写成 skill checklist 是同一类病：看起来干净，其实把未来任务需要的证据提前扔掉。JITMem 把 **storage 与 curation 解耦**，用即时同任务奖励训练 curator，工程上直接降低了 SkillOS 式编组与额外 judge 奖励的复杂度。

对 Byron（continual learning / skills / harness / MCP）：读时策展意味着 **同一情景库可服务多种下游技能形态**——不必为每个 skill 类型预先决定摘要粒度。对照 [LIMBO](./20260924_LIMBO_论文解读_经验回放别全塞进提示_按任务在线配记忆预算.md)：一个管量，一个管质；对照 [SkillPivot](./20260925_SkillPivot_论文解读_失败别整轨反思_先找偏航点再对比后缀改技能.md)：SkillPivot 改技能文本，JITMem 改「从 raw 轨迹现场合成什么」。Harness 里值得试的是：memory 层默认 raw + 成功过滤，curator 挂在 retrieve 之后、executor 之前。

## 🏗️ 机制：存 raw → 读时策展 → GRPO

**Memory bank \(\mathcal{M}\)**：只存完整未抽象轨迹；写时不做 reflection / skill / workflow。成功过滤作为存储策略（消融显示优于「全存+对错标签」）。

**Retriever \(\mathcal{R}\)**：固定 BM25，\(k=3\)；训练与测试同一套，不参与梯度。

**Curator \(\pi_\phi\)**：输入 = 当前任务 \(x_t\) + 取回的 raw 轨迹；输出 = 紧凑自然语言 payload（策略、步骤指引、任务相关要点），供冻结 executor \(\pi_L\) 使用。同一 \(\xi\) 在不同 \(x_t\) 下可被策展成不同内容。

**训练（GRPO）**：对训练任务取回 \(\hat\xi_t\)，curator 生成 \(G\) 个候选 payload；executor 执行得任务奖励 \(r_t\in[0,1]\)（ALFWorld/\(\tau^2\) 二值；WebShop 连续分数）；组内优势 \(\hat A_i=r_t-\mathrm{mean}_j r_t\)。Curator 初始化自 Qwen3-8B（thinking off），100 step，lr \(1\times10^{-6}\)，batch 32，group 8；训练期 executor 用 Qwen3-8B。训练 bank 由无 curator 的 base executor 跑训练集一次构成并固定；测试时 bank 随 curator-augmented 轨迹在线增长——存在温和分布偏移，但实验显示可承受。

**与写时 SkillOS 的关键差**：SkillOS 要复合奖励 + 相关任务编组制造延迟信号；JITMem **只用任务奖励**，信用分配零延迟。

## 🧪 关键证据

**Table 1（节选，Executor = Qwen3-8B）**

| 方法 | Curator | ALFWorld SR | WebShop Score | WebShop SR |
| --- | --- | ---: | ---: | ---: |
| No Memory | — | 47.9 | 33.3 | 9.8 |
| ReasoningBank | Qwen3-8B | 55.7 | 35.4 | 11.4 |
| SkillOS | Qwen3-8B | 61.2 | 40.6 | 16.5 |
| JITMem-base | Qwen3-8B | 60.5 | 32.5 | 11.7 |
| **JITMem** | **Qwen3-8B** | **77.4 (+16.2)** | **61.1 (+20.5)** | **32.8 (+16.3)** |

相对同块最强基线 SkillOS：**+16.2 / +16.3** SR。Gemini-2.5-Pro executor 上：JITMem **86.2** vs SkillOS **80.2**（ALFWorld，+6.0）；WebShop SR **50.5** vs **41.3**（+9.2）。未训练读时：JITMem-gemini 在 WebShop SR **61.0**，同设置 SkillOS-gemini **41.0**——读时任务自适应本身就是大头，RL 再叠加。

**Table 2（\(\tau^2\)-bench，Executor = GPT-5.4）**

| 方法 | Macro Avg. | Micro Avg. |
| --- | ---: | ---: |
| No Memory | 65.0 | 65.0 |
| ReasoningBank (GPT-5.4) | 70.4 | 71.7 |
| SkillOS-gpt | 66.6 | 66.4 |
| **JITMem-gpt** | **73.4 (+3.0)** | **75.6 (+3.9)** |

增益集中在 Telecom（复杂多步政策核对，约 +11.0）；Airline / Retail 记忆方法多在方差内——读时策展更吃「要合成程序指引」的任务，而不只是事实检索。\(\tau^2\) 无标准训练划分，故只报 training-free 变体。

**迁移（Table 3，ALFWorld）**：用 Qwen3-8B executor 训出的 curator 迁到 GPT-5.4，达 **86.7**，与「直接用 GPT-5.4 executor 训练」的 **88.1** 仅差 **1.4**——学的是可迁移策展策略。相对 JITMem-base，迁移 curator 在更强 executor 上仍稳定抬分。

**效率（Table 4，ALFWorld / GPT-5.4）**：JITMem-base 相对 No Memory 只多约 **1.9K** 输入 token（ReasoningBank +10.7K，SkillOS-base +13.4K），步数降约 18.5%–21.9%；RL 后再压输入/输出/步数（相对 base 约 −10.1% / −13.0% / −12.1%）。

**消融**：去任务条件——base 最多 −3.1/−4.6，训练后最多 **−11.4 / −10.4**（RL 在学用任务信号）；去成功过滤、改存全轨迹+标签——仍掉分；改存 ReasoningBank 式写时蒸馏——WebShop 最多 **−6.8～−8.2**；空检索——RL 增益塌到甚至低于 base（最多 −14.8 / −15.2 SR）。

## 🔬 最有意思的部分

1. **写时 vs 读时是一等设计轴**：未训练读时就能打赢强写时基线——机制本身比「更大 curator 模型」更值钱。
2. **弱 curator + 读时 > 强 curator + 写时**：GPT-5.4 executor 上，Qwen3-8B 的 JITMem-base（79.3）可压过用 GPT-5.4 的 ReasoningBank（77.9）与 SkillOS-gpt（70.0）。
3. **信用分配简化是工程红利**：同任务即时奖励 → 不必编组、不必额外内容 judge——对照写时 SkillOS 的复杂度。
4. **与 LIMBO 正交**：LIMBO（[笔记](./20260924_LIMBO_论文解读_经验回放别全塞进提示_按任务在线配记忆预算.md)）优化推理时记忆预算；JITMem 优化 payload 内容生成。可叠：先 LIMBO 定额度，再 JITMem 在额度内策展。
5. **Concurrent MemHarness**：也读时策展，但单策略绑死 executor、难迁移；JITMem 刻意 curator⊥executor。

## 🤔 我的判断

定位：**把 agentic memory 的策展时刻从写时搬到读时的方法论文 + 可迁移 curator 训练配方**；对 skills / 持续学习叙事是一次「存储无损、按需重建」的纠偏。亮点三：

1. 问题定义干净——过早不可逆损失 vs reconstructive 读时合成；
2. 主结果跨三榜、跨三 executor，未训练读时与 RL 叠加都有独立故事；
3. 消融把任务条件、raw 保留、成功过滤、检索依赖钉死，避免「只是会写漂亮 prompt」。

局限：训练 bank 固定带来 train/test 分布差；成功过滤依赖「何为成功」的外部判据；\(\tau^2\) 尚无标准训分、增益域间不均；BM25 + \(k=3\) 偏简，更强 retriever 是否改变结论未充分展开；raw 库增长的存储与隐私治理（对照 Qwen-Planner-Agent 的 memory safety）需工程补课。对 Byron：在 Pi / OpenClaw / coding harness 里，**别急着把每条轨迹写成 skill 文件**——默认落 raw（或成功 raw），在 retrieve 后加任务条件 curator；评测要切「程序合成型 vs 事实回忆型」任务；curator 与 executor 解耦，便于换 Claude/Codex 骨干而不重训记忆策略。和 [ComposeCL](../week3/20260916_ComposeCL_论文解读_持续学习机制组合起来才扛得住百任务记忆.md) 合读：持续学习机制要组合，**写时压缩只是其中一种，而且常常该后置**。

一句话收束：经验别在写入时被盖棺定论——**库里留 raw 情景，读时按当前任务现场策展；同一条轨迹，本来就该能教出不同的课**。
