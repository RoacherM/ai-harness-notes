# 从 1,072 个公开技能里挖出 17,865 个决策点，训一个 4B 打分器替大模型做选择题：比直接读技能的 agent 省 75% 到 91% 成本、成功率持平；但大头来自先把技能编译成程序，不加置信门的话 ALFWorld 从 96.3% 掉到 40.3%

你有没有过这种体验：看 agent 的账单，发现大部分 token 花在一些根本不需要「想」的地方。用户问的是「帮我看看落地页哪里不对」，agent 要先判断这是设计、开发、评审还是修 bug，四选一；商品页上这件衣服是不是用户要的尺码，是或否。每一个这种选择题，都要把越来越长的上下文整个喂给旗舰模型、等它推理一两秒。已经有人用小模型做「System-1」接管这些选择，但每个工作流都得有人手工标出哪里是决策点、单独训一个。**换一个新工作流就得重来一遍，有没有办法让一个小模型通吃所有工作流的选择题？**

中国科学技术大学和南洋理工大学的 **Thinking Fast, Anywhere: One System-1 for the Decision Points of Any Agent Workflow** 给的答案是：决策点不用手工标，agent skills（SKILL.md）里本来就写着「在哪儿判断、有哪些选项」。他们从 1,072 个公开技能里自动挖出决策点，在隔离容器里跑真实任务收集状态，训了一个 4B 指针模型，运行时按置信度决定自己答还是交给大模型。看完我的感受是：**这篇最有价值的不是那个 4B 模型，而是它把「技能」重新理解成一张带类型的控制流图：确定性步骤跑代码，开放生成交给大模型，有限选项的判断交给小模型。而论文自己的表也说明，省钱的大头其实来自这张图本身。**

## 核心摘要

作者把技能执行中的每一步分成三类：D 节点（确定性，完全由结构化状态决定，直接跑代码）、G 节点（开放生成，留给 System-2 大模型）、E 节点（从技能里写明或可从状态列出的有限选项中选一个，适合交给 System-1）。离线阶段，LLM 分析器把每个 SKILL.md 独立读三遍，抽取带原文引用的候选决策点，合并后保留至少两遍都出现的 E 节点；再为每个技能合成多阶段任务（带输入文件、参考解和隐藏验证器，并配两个跨类别干扰技能），在断网容器里用 OpenHands 执行，截取每个决策点之前的原始观测作为状态，用两次选项顺序相反的教师打标、只保留两次一致的样本。得到的 Any-DP 有 17,865 个决策点、2,846 个容器验证任务、25,986 条共识样本，E 节点占全部节点 64.5%。System-1 是在 Qwen3.5-4B-Base 上接一个选项交互指针头，用 ε=0.1 的标签平滑训练。运行时，System-1 最大概率超过阈值 τ 就采纳，否则交给 System-2；τ 有冷启动（153 个留出样本拟合一个全局阈值 τ=0.918，零目标工作流运行）和热启动（50 个无标注开发回合里拿 System-2 的选择拟合）两种。在三个与训练技能零重叠的基准（SOPBench、ALFWorld、WebShop）和两个 System-2（DeepSeek-V4.1-Flash、GPT-6 Sol）上，相对直接读技能的未编译 agent，AnyS1 热启动省 75% 到 91% 的回合成本、减少 63% 到 92% 的关键路径模型时间，成功率与「编译后全用大模型」持平。但编译本身就已经省了 56% 到 86%、还把成功率拉高约 17 到 18 个点。这篇的价值定位是：**为「harness 里的路由决策交给专属小模型」提供了一套不依赖手工钩子的数据管线和校准门。**

## 🎯 为什么这件事值得写

主流 agent 在每一步都调用大模型，上下文越滚越长，延迟和成本随之膨胀。但很多中间步骤其实只是在少数已知选项里挑一个。类型化决策模型（Jev 这一类）正是为此而生：给定状态、问题和候选项，一次前向输出选项分布。已有的双系统 agent 在搜索和特定工具 harness 里用它大幅降低了延迟和成本，但它们都**依赖为单一固定工作流手工定义的决策点**，训练监督也只在这些硬编码钩子上收集。通用 agent 遇到没有预先声明钩子的新工作流时，每个判断都只能回退到大模型。

作者的观察是：通用 agent 越来越多地通过 agent skills 获得工作流，公开仓库里已有超过十万个技能。每个技能都是一段结构化流程，它的分支和检查隐式地定义了「在哪儿判断、在哪些选项之间判断」。所以技能天然就是一个与工作流无关的决策点来源。

这和我们关注的「harness 专属的小模型适配」是一条线：不是把小模型 RL 成一个全能 agent，而是只让它接管 harness 里那些有限选项的判断，其余交给大模型，用校准过的置信度做路由。

## 🏗️ 机制：挖决策点、收真实状态、训校准打分器、按置信度路由

### 成本的上限由 E 节点份额决定

设 C 和 C^S2 分别是双系统配置和「全部用大模型」（All-S2）的每回合成本，按节点拆开：

$$
\frac{C}{C^{S2}}=\underbrace{\frac{C_G}{C^{S2}}}_{\approx 1-s_E}+\frac{C_E^{S2}}{C^{S2}}+\underbrace{\frac{C^{S1}}{C^{S2}}}_{\kappa}
$$

其中 s_E 是 All-S2 成本里花在 E 节点上的份额，κ 是 System-1 的开销。在轨迹不变的前提下，节省上限就是 s_E − κ。目标是学一个能泛化到没见过的技能的决策模型 f 和一个轻量门 g，尽量去掉 E 节点上的大模型成本，同时成功率不低于 All-S2。

### 从技能里挖决策点

对每个技能，LLM 分析器独立读 SKILL.md 及其附带文档三次，每次返回带类型的候选决策点、选项，以及一段经精确字符串匹配校验的原文引用。再用 LLM 合并三次运行里等价的决策点，记录支持度 σ∈{1,2,3}，每个字段取多数值，并根据技能原文给每个选项写一句定义，用来区分同名选项。只保留 σ≥2、并且仅凭状态就能回答的 E 节点，形成模板 (q, O, d)：问题、选项及定义，外加一个「以上都不是」。所有离线 LLM 步骤都用 DeepSeek-V4.1-Flash。

### 收集真实执行状态

光有模板不够，训练还需要真实运行时的状态。作者发现直接让 LLM 编造状态，会得到干净的散文式摘要，和真实轨迹里零碎的工具输出对不上。所以对每个技能（事先按仓库级别划分训练集和留出集以防泄漏），让 LLM 合成自包含的多阶段任务：输入文件、参考解、隐藏验证器，并配两个跨类别干扰技能，要求 agent 既选对技能又推进多个依赖阶段，至少包含一个过期或冲突的信息源要调和。任务只有在断网容器里验证器拒绝初始文件、接受参考解时才保留。

然后用 OpenHands agent 在隔离容器里执行每个验证过的任务，由一个 LLM 定位器把轨迹对齐到技能的决策点，逐字截取决策发生前的观测（任务指令、用户消息、原始工具输出，不含 agent 自己的推理）作为状态 s。执行 agent 本身的动作可能不是最优，单次 LLM 教师又有选项顺序偏差，所以每个状态问两次教师，第二次把选项顺序反过来，只保留两次答案一致的样本。

| Any-DP 统计 | 数值 |
| --- | --- |
| 公开技能 | 1,072（来自 SkillMD-138K） |
| 技能类别 | 16 |
| 决策点（D / E / G） | 17,865（21.3% / 64.5% / 14.2%） |
| 至少含一个 E 节点的技能 | 100% |
| 合成任务 | 2,846 |
| 共识状态 | 25,986 |
| 教师一致率 | 89.2% |

另外，64.6% 的 E 节点需要上下文语义推断，只有 17.8% 是字面查找，作者据此认为静态规则替代不了学出来的 System-1。所有与评测相关的技能都在仓库级别排除了。

### 校准过的 4B 指针模型

System-1 是在 Qwen3.5-4B-Base 上接一个选项交互指针头。输入把状态、问题、每个选项及定义用结构化分隔符串成一个序列；一次前向后，把决策位置的隐状态和每个选项结束位置的隐状态送进一个无位置编码的双向自注意力层，让选项彼此参照，再把每个选项和决策位置匹配，softmax 得到选项分布。

因为运行时的路由依赖概率能否反映真实正确率，而硬标签交叉熵会让模型过度自信，训练直接用标签平滑：目标分布是 (1−ε)·one-hot + ε·均匀分布，ε=0.1。

### 置信门

只有 System-1 的最大概率 c(x) 超过阈值 τ 时才采纳它的答案，τ 取「在校准决策上使 c(x)≥τ 的样本至少 95% 与参照一致」的最小阈值。两种模式都在任何测试运行之前固定：

- **冷启动（AnyS1cold）**：用 153 个来自留出开发技能的样本拟合一个全局 τ（=0.918），原样用到所有基准，目标工作流零运行。
- **热启动（AnyS1warm）**：在目标工作流上用 System-2 跑 50 个不相交的开发回合，同时记录 System-1 的打分，以 System-2 的选择为参照拟合 τ，不需要人工标注。

### 运行时：编译后的 D/E/G 程序

评测时技能先被编译成显式的 D/E/G 程序：SOPBench 由一个确定性规则编译器把机器可读的 SOP、工具 schema 和约束谓词翻成节点；ALFWorld 和 WebShop 由一个 LLM 编译器把 SkillRL 技能库翻成每个任务族一个程序（ALFWorld 6 个、WebShop 7 个商品类别）。D 节点跑代码，G 节点交给 System-2，E 节点先问 System-1。

## 🧪 关键证据

### 评测设置

三个与 Any-DP 零技能重叠的基准：SOPBench（268 个留出的多轮客服任务，有严格流程和数据库约束）、ALFWorld（134 个没见过的文本家居任务）、WebShop（500 条购物指令，118 万商品目录，15 步上限）。System-2 是 DeepSeek-V4.1-Flash 和跨家族的 GPT-6 Sol，解码温度 0，G 节点开推理、E 节点关推理。对照有三个：直接读原始技能文档的未编译 agent、编译后每个 E 和 G 节点都交给 System-2 的 All-S2、用商用 Jev（jev-1.14.0）当 System-1。成本按官方 API 标价算（Jev 输入 $0.042/百万 token、输出 $0），自托管 4B 按 L4 GPU 吞吐折算为每千次单次决策 $0.0045。所有阈值在测试前预先登记，每个配置和 All-S2 共享完全相同的 System-2 请求缓存，所以运行只在 System-1 作答的地方发生分歧。

### 节省由什么决定（Figure 3）

编译之后，委派能动的只是剩下的 E 份额：ALFWorld 和 WebShop 上 E 节点占未编译成本的 17% 到 22%、时间的 11% 到 18%；SOPBench 上 E 节点占成本 4%、时间 19%。本地 System-1 一次打分全部选项的中位耗时 21.8 到 31.7 毫秒，比 1.51 到 1.78 秒的 System-2 调用快 56 到 81 倍，商用 Jev 的远程往返是 0.65 到 0.67 秒。热启动下 System-1 本身只占未编译回合时间的 0.2% 到 0.3%，模型时间占比从 All-S2 的 13% 到 49% 降到 8% 到 30%。

### 置信度挑得对不对（Figure 4，Table 5）

在 All-S2 的测试 E 决策上扫 τ，任何低于 100% 的覆盖率下，System-1 高置信的选择都比同样大小的随机子集更接近 System-2，AURC 降低 2 到 6 倍。在热启动的在线阈值上：ALFWorld 委派 50%、与 System-2 一致 92.4%（随机 68.2%，每百次分歧 3.8 对 16.0）；WebShop 委派 41%、一致 84.3%（随机 69.8%）；SOPBench 委派 98%（总体一致 91%）。

冷启动的全局阈值不可能对所有域都合适：在 SOPBench 上偏保守（委派 40%、一致 100%），在 WebShop 上过度委派（委派 55%、一致 80.0%）。目标工作流上只用 20 个开发回合校准，委派率就能与完整拟合相差 1 点以内；只用 5 个回合时，WebShop 的委派率在 19% 到 75% 之间波动（第 10 到第 90 百分位）。

## 🔬 最有意思的部分

**一，省钱的大头是编译，不是小模型。** 这篇的标题是「一个 System-1」，但 Table 2 说得很清楚：DeepSeek-V4.1-Flash 下编译 All-S2 已经平均省掉 81%，还把效果拉高约 18 点；AnyS1warm 把节省提到 89%。按表里的数字折算，All-S2 的成本约是未编译的 19%，AnyS1warm 约 11%，也就是 System-1 在编译之后再砍掉剩余成本的四成左右。这仍然可观，但读者要清楚：「75% 到 91%」这个数字主要是在夸技能编译成 D/E/G 程序这件事，而这一步在 SOPBench 上靠的是确定性规则编译器，在 ALFWorld 和 WebShop 上靠 LLM 编译器，论文局限里也承认自动编译开放仓库技能是下一步。

**二，不加门的小模型在长时程任务上是灾难。** All-S1 在短程路由类工作流上没问题（SOPBench 84.3%），但在 ALFWorld 从 96.3% 掉到 40.3%。长时程探索里一个错误分支会把后续轨迹带偏。这和我们关注的长时程评测是同一个教训：短程准确率高不代表能放手，**错误的复合效应只在长轨迹上暴露**，所以门控和校准必须在长时程任务上验证。

**三，训练状态必须来自真实执行。** 同一个模型，用 LLM 编的状态摘要训练，留出集上低 18.8 点。这对所有想用合成数据训 harness 专属小模型的人都是提醒：harness 里的状态是被截断的终端输出、零碎的工具返回，不是整洁的散文。要在容器里真跑一遍，截取原样观测。

**四，「与 System-2 一致」不等于「正确」。** 热启动的阈值是对着 System-2 的选择拟合的，Figure 4 的一致率也是相对 System-2。也就是说这套门的上限是复刻大模型的判断，大模型错的地方小模型照样错。WebShop 上 AnyS1 得分略高于 All-S2，作者解释为压住了过度推理，这说明大模型的判断本身也不是金标准。

## 🤔 我的判断

定位：**数据管线加工程框架**。核心贡献是 Any-DP 的构造方法（技能挖点、容器执行、双教师一致）和「标签平滑 + 置信门」这套小模型路由的校准方案。

亮点三条：

- **决策点来源从手工钩子变成技能文本。** 三遍抽取、原文引用精确匹配、多数投票，是一个可复用的结构化抽取范式。
- **评测协议控制得比较好。** 阈值预先登记、配置之间共享 System-2 请求缓存，使得差异严格只来自 System-1 作答的位置。
- **把节省的天花板讲清楚了。** 用 E 节点份额解释为什么 SOPBench 上能委派 98% 却省不了太多额外成本，避免了「小模型越多越好」的误读。

问题与局限：

- **大部分收益来自编译这一步，而编译在评测基准上有现成结构可用**（SOPBench 有机器可读 SOP，ALFWorld/WebShop 有 SkillRL 技能库）。开放仓库里的技能能否这样编译，论文没有验证。
- **未编译 baseline 比较弱**，比 All-S2 低 16.8 到 17.8 点，相对它算出的节省百分比会显得很大。
- **端到端结果没有报告多种子或置信区间**（解码温度 0），只有 Table 3b 报了三个种子。热启动相对 All-S2 的 +0.5 点和冷启动在 Sol 上的 −0.8 点，都落在单次运行波动可能覆盖的范围里，作者的结论「持平」是恰当的，但不宜读成「更好」。
- **热启动需要约 50 个开发回合**，期间 System-2 回答每一个 E 节点，作者在局限里写了；从被延迟的 System-2 调用里在线调阈值留给了未来。
- **离线全部用 DeepSeek-V4.1-Flash 做教师**，System-1 学的是这个教师的判断分布；换教师会怎样没有测。

对工程的直接启发：

1. 在做「小模型接管 harness 决策」之前，先把技能或流程编译成显式的 D/E/G 结构。论文显示仅这一步就省掉 56% 到 86% 的成本并提升成功率。
2. 只把有限选项的判断交给小模型，开放生成留给大模型，确定性步骤直接写代码。
3. 小模型训练数据要在隔离容器里真实执行收集，原样截取工具输出，不要让 LLM 写状态摘要。
4. 小模型的置信度必须校准（标签平滑这一类），并且在长时程任务上验证门控，不加门的 All-S1 在 ALFWorld 上会崩。
5. 冷启动阈值可以先上，但每个工作流最好补 20 个左右开发回合做本地校准；5 个回合的估计波动太大。

一句话：让小模型接管 harness 里的选择题是可行的，但前提是先把技能拆成一张分得清「哪儿要想、哪儿要选、哪儿照做」的图；图画对了，大部分钱已经省下来了，小模型负责的是再砍剩下的四成。
