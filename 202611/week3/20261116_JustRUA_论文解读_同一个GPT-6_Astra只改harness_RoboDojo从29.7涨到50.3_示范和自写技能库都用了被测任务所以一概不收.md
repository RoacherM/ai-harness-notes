# 榜单上那些机器人 agent 的涨分，到底是新组件的功劳还是 harness 的功劳？JustRUA：把每个设计拆开在同一张测试集上重测，只改 harness 就从 29.7 到 50.3

你有没有过这种体验：一个榜单上，某个系统宣布涨了十几分，细看它换了 harness、换了测试子集、换了预算，还同时加了深度图、示范、技能库和自我改进循环。你想复现其中一项，根本分不清哪部分在起作用。更糟的是，有些组件本身就在用被测任务的数据，分数和标准评测已经不是一回事。

这件事在 **robot-use agent（RUA）** 上尤其明显。GPT-6 Astra 可以不经过任何 VLA 模型，直接通过一个固定 harness 驱动双臂机器人：看相机图像，决定每只夹爪下一步去哪，读结果，就像 computer-use agent 看屏幕点鼠标。RoboDojo 上基于它的系统分数涨得很快。**问题是：涨分到底来自哪里？** 清华、北大、华中科大、面壁和腾讯等机构的这篇 JustRUA 没有再提出一个系统，而是把近期系统加的设计沿四个轴拆开，在同一测试平台、同一评测集上逐个重测。看完我的感受是：这是一篇典型的 harness 配置审计，最有价值的不是最后的 50.3，而是它**拒绝收录任何用到被测任务的经验复用，不管分数多高**。

## 核心摘要

作者从 RoboDojo 官方 L3 harness（GPT-6 Astra 榜单条目背后的那一套）出发，用 Codex 会话承载对话（关闭 shell、搜索和看图工具），保留官方 harness 的动作解析、运动规划和逆运动学代码不变，沿四个轴依次测试：harness（保留多少历史、推理强度）、动作接口（指令格式、每段运动执行多久）、经验复用（视觉示范、文本轨迹、自写技能库）、场景几何（机器人读数、深度图、预计算可供性、用代码求三维坐标）。为了在可承受的成本下比较，他们构造了一个 111 回合的评测集：覆盖全部 42 个任务，把四个固定布局分给方差最大的 23 个任务，其余 19 个任务各跑一个布局；自助法估计的总分标准差比每个任务跑三次（126 回合）还小。每个配置还由一个不参与控制机器人的 GPT-6.1 Sol 逐回合看视频和日志，统计空抓、掉落等分数看不到的行为，并报告每回合按缓存价计费的成本下界。保留标准是三条：在评测集上有帮助、成本合理、不使用被测任务。最终保留三类改动：完整回合历史加每段运动最多执行 20 个控制步、观测里加精简的夹爪读数和从 RGB 预测的深度、允许模型写代码从像素求三维坐标。在没有学习策略、没有自我改进循环、没有任务特定调参的前提下，评测集分数从 29.7 到 50.3。示范和自写技能库改变了行为但没有明显超过默认配置，而且都用了被测任务，**一概不收**。这篇的价值定位是：**一份可复用的 harness 审计方法，外加一个很强的提醒：先把 harness 修好，再谈模型能力不行。**

## 🎯 为什么这件事值得写

起点是一个矛盾。GPT-6 Astra 在 RoboDojo 官方 L3 harness 下的首次评测显示它在精度类任务上很弱，另一项更广的研究也看到它的任务决策和可靠物理控制之间有差距。可作者发现，对 harness 和动作循环做几个合理修正，不需要任何精巧设计，它的 Precision 分就接近当时榜单上最强的 VLA 模型 DM0.5。**他们由此怀疑，很多被报告的「模型弱点」其实在 harness 里。**

如果 harness 影响这么大，近期系统报告的涨分就很难解读：起点 harness 不同，测试子集和预算不同，经常一次改好几处。完整复现每个系统会把这些差异也一起带过来。所以作者选择拆开测。

这和我们这个仓库反复出现的主题完全一致：PolicyIsHarness 发现字段顺序一倒成功率从 85 掉到 19，CoDesignBench 发现同一模型换个 harness 能差 19 点，MICA 比较同一能力用 MCP 还是 CLI 暴露，CodingOrCheating 和今天另一篇 CriteriaExposure 讨论 agent 怎么吃到评测本身的信息。JustRUA 是把这套审计思路搬到具身场景的一个干净样本。

## 🏗️ 机制 / 任务定义

**基准**。RoboDojo 有 42 个仿真双臂任务，分五组：Generalization、Precision、Long-horizon、Memory、Open。每个任务 0 到 100 分，很多任务对中间阶段给部分分。官方评测每个任务跑 50 个布局，共 2,100 回合，先在组内平均，再五组等权平均。

**起点 harness（官方 L3 Inspect EEF）**。每回合开头给任务指令和来自 RoboDojo wiki 的任务说明（描述任务和计分阶段，不给动作序列）。每次决策模型看到头部和两个腕部共三路 RGB，以及两臂的抓取点和关节状态；通过 `move_eef` 给出世界坐标系下的抓取点目标（位置、姿态、夹爪开度），或用 `give_up` 结束回合。CuRobo 规划关节路径，仿真器回放，下一次观测报告抓取点离目标多远。模型不获得深度、物体位姿、布局元数据或计分信号。官方 harness 只保留最近两次观测的图像，500 个控制步用完回合结束。

**测试平台**。同样的循环跑在 Codex 0.153.4 会话里（固定版本，避免版本差异影响结果），推理强度 medium。Codex 只负责承载长对话和上下文压缩，自带工具全部关闭。工具定义以文本给出，模型每次返回一个 JSON（包含备注和调用），解析、规划和执行都用官方 harness 原封不动的代码。所有对比限每回合 100 次决策，只有最终配置取消这一限制。除了继承来的任务说明，没有任何任务特定的工具、提示或代码。

**四个轴与「一条路径」**。作者按 harness、动作、经验复用、场景几何的顺序推进，每个备选都和测试时已保留的配置比较，保留下来的设计构成一条从官方 harness 到 JustRUA 的路径。作者明确说这是一条路径，**不是全因子实验**：它回答的是「在已有基础上加这个有没有用」，这正是系统构建者面对的问题，但不测试所有组合。

**评测集怎么来的**。作者先用默认测试平台在 low 和 medium 两种推理强度下各跑八轮，每轮按固定顺序取每个任务的下一个布局，发现大部分波动来自一类任务：成功得 100，任何部分结果最多 50，而模型在有的布局上成功、有的不成功，一次差一点就让任务分数摆动 50 分以上。于是规则是：部分结果最多 50 分且八轮内既成功过又失败过的任务跑四个固定布局，这恰好选出了方差最高的 23 个任务；其余 19 个跑一个布局，共 111 回合。medium 强度下单轮总分的自助标准差是 4.8 分，评测集是 2.6 分，接近每个任务跑四次（168 回合）的 2.4 分。

一个典型例子是 swap_T：两个 T 形块要在 20 毫米内互换位置，各自朝向误差在 3 度以内，两臂回到休息位才得 100，否则 0 分。默认测试平台第一轮在 low 和 medium 下都是 0，八轮里两种强度各成功四次。

**行为复核和成本**。每个配置的 42 个首轮回合各由一个独立的 GPT-6.1 Sol agent 看完整动作日志和三路视频，每个计数事件都绑定到能看到它的帧，第二遍再对照证据和原始日志核查。只计证据能确定的事件，所以计数是下界。成本按「所有可缓存输入都命中缓存」计费，因为每次决策都要重发完整历史，一个回合读入几百万输入 token，只写出几千。

官方 harness 一行的分组分和成功率来自它的 2,100 回合完整评测，在那次评测里它总分 29.0。

**四条结论**：

1. **精简的 harness 走得很远**。保留完整回合历史、每段运动最多执行 20 个控制步，分数从 29.7 到 38.0。把循环搬进 Codex 但不保留完整历史本身没有帮助，所以作者把增益归于两者共同作用。相对目标、语义技能和模型自选步数都没有超过朴素的绝对目标。
2. **经验复用不是免费午餐**。示范和自写技能库改变了模型的行为，但都没有明显超过默认配置，每回合更贵，而且都用了被测任务。
3. **场景几何帮助最大**。深度图把首轮空抓从 41 次降到 16 次，哪怕深度是 Depth Pro 从单张 RGB 预测的、误差几十厘米。加上代码求坐标并取消决策上限，分数到 50.3。预计算可供性这个最复杂的组件没有帮助。
4. **剩下的失败大多是长尾**。最终配置下 42 个首轮任务里有 21 个低于 50 分，失败原因大多是特定任务的问题。

**泼点冷水**。作者的局限说明写得很直接：全部在仿真里、一个基准、一个模型；每个配置在评测集上只跑一次；每个备选只在它被加入的那个位置测试，不测所有组合；经验复用的运行用了被测任务，自我改进循环只跑了五轮、每个任务只练一次；评测集是从自家默认测试平台的历史里挑出来的，而且 Generalization 组随机布局的权重是 75%，官方是 50%，**所以评测集分数不是榜单分数**。我再补两点：最终一步同时引入了代码执行和取消 100 次决策上限，作者也说明这两件事是一起报告的，无法拆开；最终配置每回合成本 12.53 美元，比默认测试平台的 4.94 高出一倍多，50.3 不是免费的。

## 🔬 最有意思的部分

**1. 20 步截断：不是让规划更准，而是让坏动作走不远。** 作者看回放发现 CuRobo 偶尔会返回不稳定的规划，手臂随即做出一个明显不合理的大动作；官方循环里整段运动执行完模型才看到下一帧，这种动作就会不受检查地完成。截断后每段最多执行规划的前 20 个控制步（约 0.8 秒），剩余部分直接丢弃而不是在后台继续，夹爪保持最后实际执行的指令；反馈仍按原目标计算，并告诉模型执行了多少步，让模型知道「还没到」而不是「已完成」。作者的原话大意是：截断不会让规划器更准，它缩短的是手臂在没有新观测的情况下运动的距离。增益集中在 Precision 组，从完整历史那一行的 9.4 涨到截断后的 25.0。

这条和自写技能库那一节形成了有趣的呼应：Codex agent 根据失败自动修改技能库时，**大部分修改都是让某个操作更早停下来，好让模型在继续之前检查结果**。两条独立路径得出同一个设计原则：在长程执行里，频繁的观测检查点比更聪明的单步动作更值钱。

**2. 语义技能改变了模型做什么，没改变做得多好。** 语义操作把原始目标包装成 `approach`、`transport`、`pick`、`handover`、`adjust_view` 等命名技能，模型在大部分调用里用了它们。行为复核显示，视角调整从 59 次涨到 211 次，掉落从 26 次涨到 35 次，总分从 38.0 降到 34.6。相对目标让手臂撞到物体的次数从 7 次涨到 20 次，作者推测是因为模型读到的所有坐标（从任务说明到测得位姿）都在世界坐标系里，相对偏移要求它每步多做一次减法。「每次决策最多四个动作」虽然涨到 42.0，但作者查明增益主要来自少数原本会耗尽 100 次决策预算的回合，**反映的是预算而不是接口**，所以最终配置选择直接取消预算。

**3. 预测深度误差几十厘米，照样几乎和真深度一样有用。** RoboDojo 榜单不接受智能体条目读取仿真器深度（维护者在审核中明确说过），所以作者同时测了仿真器深度和 Depth Pro 从单张 RGB 预测的深度。在 make_kong 和 fill_egg_holder 的头部相机帧上，原始预测的平均绝对误差 73.7 厘米，给真实焦距后 40.1 厘米，逐帧缩放后 7.3 厘米，但皮尔逊和斯皮尔曼相关都在 0.99 以上。逐帧缩放会漂移、腕部相机也没法拟合，所以 JustRUA 直接传原始预测。结果首轮空抓：无深度 41 次、仿真器深度 17 次、预测深度 16 次；精细放置失败预测深度反而更少（7 次对 15 次）。作者的解读是：**预测深度对的是深度的排序，而这似乎就够了。**

**4. 读数写成什么格式，和读数包含什么同样重要。** 机器人读数（指尖位置和力、接触力、腕部负载）写成完整 JSON 时每次决策多 3,100 字符，把很多首轮回合推进了上下文压缩，而默认测试平台从没触发过压缩；改成选定字段、固定单位、四舍五入的短文本后每次决策 1,800 字符，没有首轮回合被压缩，空抓也略降（47 到 41）。因为场景信息每次决策都会到达并留在历史里，**每多一个字符都要付很多次钱**。

**5. 代码几乎全用在一件事上：几何求解。** 最终配置首轮 132 次代码运行里，123 次（93.2%）是三角测量之类的几何计算：从像素经相机标定投射射线，再在两路相机间三角化或与已知平面高度求交。代码只用模型已有的图像和文本，从不读深度图。在 insert_tubes 的同一布局上，预测深度得 40 分，代码求坐标得 100 分，决策数从 65 降到 57。

**6. 把评分条件写进任务说明，分数会涨，但作者不收。** 错误分析里有 5 个任务看起来简单，问题出在提示或计分，比如 fasten_screws 螺丝都拧进去了，模型可能无法判断是否达到计分器要求的公差。把这 5 个任务的说明改写成明确说出计分器检查的条件，首轮分数从 54.0 到 55.6。**因为这一改动用到了每个被测任务的计分器，作者只报告、不计入 JustRUA。** 剩下的失败（策略不适合手臂 8 个、碰撞 6 个、抓取不稳 6 个）要逐任务试错才能修，作者认为那已经接近在测试任务上调参。

## 🤔 我的判断

**定位**：受控研究和测量方法论。它不提出新系统，产出的 JustRUA 配置是审计的副产品。

**亮点三条**：

1. 审计规则写死在前面：在评测集上有帮助、成本合理、不使用被测任务，三条同时满足才保留。示范、自写技能库、按计分器改写提示，分数再好也不收。
2. 评测集设计务实：用八轮历史找出高方差任务，把重复回合花在最不可靠的地方，用自助法量化了它比均匀加跑更省更稳，同时诚实标注它和官方协议的差异。
3. 分数之外有行为复核和成本：两个同分配置可以以完全不同的方式失败，空抓、掉落、撞击这些计数让「为什么涨、为什么不涨」变得可读。

**问题与局限**：单模型、单基准、全仿真、每个配置只跑一次；路径式而非全因子设计，组合效应没测；评测集挑选依赖自家默认平台的历史，不保证对每个新设计的排序与完整评测一致；行为复核由模型完成，作者通过证据绑定和二次核查控制质量，计数是下界；最终一步代码求坐标和取消决策上限捆绑；成本翻倍。

**对工程的直接启发**：不只是机器人。任何 harness 对比，都可以照这篇的清单走一遍。一是先问基线 harness 有没有明显的执行缺陷（这里是只留两帧图像、整段运动执行完才看），很多「模型弱点」修完 harness 就没了。二是把每个改动的增益归因到预算还是接口，「每次多给几个动作」涨分，可能只是少数回合不再耗尽预算。三是把「是否使用被测任务信息」列为硬性一票否决项，示范、技能库、按评分器改提示都要单独标注，不和标准评测混在一张表里。四是观测里每次都要重发的信息，格式压缩本身就是优化项。
