# agent 自己写出来的改动，凭什么留下？冻结候选、新鲜配对审计、裁判单独校准：裁判偏乐观 0.25 时，朴素置信门 3000 次里放进有害更新 2997 次，校准门 0 次

你有没有过这种体验：自进化 harness 跑了一晚上，日志里写着「新 prompt 在最近 50 个任务上胜率 +6%，已采纳」。第二天你发现旧任务挂了一片，再一查，那 50 个任务恰好就是生成这条 prompt 时反复看过的任务，判分的还是一个会偏爱新输出风格的 LLM judge。行业里把这类东西叫 self-evolving agent、harness evolution、自动 prompt 优化，大家都在卷「怎么生成更好的改动」，但很少有人回答另一半：**一个看起来更好的改动，要拿什么证据才能变成持久状态？**

独立研究者 Subodh Lonkar 的 **Evidence-Governed Adoption of Self-Generated Updates in Autonomous AI Agents** 正好只做这一半。它提出 Evidence-Governed Evolution（EGE）：生成和采纳分开，候选先冻结再抽新鲜审计样本，主目标要过「有实际意义的提升」门槛，受保护能力对一个版本化参考做非劣效检验，再过硬性治理检查和有界 canary，最后才提交。核心统计结果是一个「带裁判校准的同时下界」，对任意多个自适应生成的候选同时成立。看完我的感受是：**这是一篇把「harness 演化的统计接受门」写成可以照着实现的协议的论文，但它自己也老实承认，还没在任何真实 agent 上跑过。**

## 核心摘要

EGE 把一次 agent 配置更新（prompt、记忆、工具、工作流、路由、治理约束都算）拆成四个状态：Candidate（冻结）、Audit-passed（统计与治理检查通过）、Canary（有界流量或权限下运行）、Committed（持久配置）。统计门的关键是区分两种裁判：日常用的 operational evaluator（比如 LLM judge）和预先指定的 reference procedure（确定性验证器、盲评人工裁决等）。对每个冻结候选，EGE 同时抽两份独立样本：一份新鲜配对审计样本算 operational 分差的 Hoeffding 下界，一份候选专属的校准样本估计「operational 分差减 reference 分差」的偏差上界，两者相减得到对 reference 估计量的下界。误差预算按 $3\alpha/(\pi^2 j^2 R)$ 分给第 $j$ 个审计事件的每个检验，因为 $\sum j^{-2}=\pi^2/6$，所以无论候选怎么自适应生成、生成多少个，所有下界同时成立的概率至少 $1-\alpha$。在此之上，参考基线的替换要走单独的 bridge test，作者证明了沿参考谱系的累积退化上界。唯一的实验是合成蒙特卡洛：裁判对主指标乐观 0.25 时，不做校准的置信下界门在 3000 个 campaign 里有 2997 个放进了至少一个有害候选，校准门在九个设定下都是 0；代价是审计样本只有 5000 时，有益候选的接受率只有 52.6% 到 76.2%。作者明确写了：这不是对部署 agent 的评测。

## 🎯 为什么这件事值得写

作者把「采纳问题」和普通离线模型选择区分开，列了四个性质：

1. **候选是自适应的**：下一个提议依赖之前的成败、裁判反馈和部署轨迹，所以开发阶段用过的数据不能再当确认样本。
2. **候选可以修改产生证据的机制本身**：改 prompt、检索策略、工具选择规则，甚至改「面向裁判的输出格式」，都会改变裁判看到的东西。
3. **优化窄目标，却要保住宽能力**：主目标涨了，退化可能藏在没测的地方。
4. **部署不是纯统计事件**：能过 benchmark 的候选可能在生产负载下出事，而且回滚配置撤销不了已经发生的外部副作用。

相关工作里，Reflexion、Self-Refine、Voyager、EvoPrompt 解决的是「怎么生成改动」；安全策略改进、可复用 holdout、confidence sequence 提供统计工具；EvoAgentBench 一类基准测「改动有没有让能力迁移」。作者特别引了 Lin 等人「harness 更新能力不等于 harness 获益能力」这条线，然后把 EGE 定位在一个很窄的位置：**改动生成出来之后，到底需要什么证据，才允许它改写持久状态。** 作者也明确说新意不在 Hoeffding 或 union bound 本身，而在这套组合和由此得到的保证。

## 🏗️ 机制：一条接受谓词，四层互不替代

### 配置与估计量

第 $j$ 个候选评估前的现任配置写成 $I_j=(M_j,P_j,\mathcal M_j,T_j,C_j,G_j)$：模型、prompt 与策略、持久记忆、工具、编排逻辑、治理约束。生成器 $\tilde A_j=U(I_j,E_j)$ 可以是优化器、LLM 编辑器、搜索或人。

指标分两组，必须在看审计结果前声明：主目标集合 $\mathcal J$（和现任 $I_j$ 比）和受保护能力集合 $\mathcal K$（和一个固定版本化参考 $A_{\text{ref}}$ 比）。分数归一到 $[0,1]$。总体层面的接受要求是：

$$\exists r\in\mathcal J:\ \Delta^R_{j,r}\ge\delta_r,\qquad \forall r\in\mathcal K:\ \Delta^R_{j,r}\ge-\epsilon_r,\qquad \forall m\in\mathcal G:\ G_m(\tilde A_j)=\text{true}$$

$\delta_r$ 是「有实际意义的最小提升」，$\epsilon_r$ 是可容忍的最大退化，都要提前定死。注意受保护能力比的是固定参考而不是上一版现任，否则每次小退化都会悄悄挪基线。

### 裁判校准：把 judge 偏差当成要估计的量

令 $D^E$ 为 operational 裁判下的配对分差，$D^R$ 为 reference 程序下的配对分差，偏差 $W=D^E-D^R\in[-2,2]$，均值 $b_{j,r}$。于是

$$L^E_{j,r}=\bar d^E_{j,r}-\sqrt{\frac{2\ln(1/e_{j,r})}{n_{j,r}}},\qquad U^b_{j,r}=\bar w_{j,r}+\sqrt{\frac{8\ln(1/c_{j,r})}{m_{j,r}}},\qquad L^R_{j,r}=L^E_{j,r}-U^b_{j,r}$$

校准是**单边**的：只有「裁判偏乐观」会让下界高估真实效果，所以只减偏差上界。作者坚持校准样本必须**按候选单独抽**，因为一个更新可能改变输出风格，从而改变裁判和参考的一致程度；全局校准只有在另有覆盖整个候选类和自适应选择过程的一致泛化论证时才能替代。

### 误差预算与定理

$$e_{j,r}=c_{j,r}=\frac{3\alpha}{\pi^2 j^2 R}$$

定理 1：在条件新鲜采样、指标族有限且预先声明、参考程序有效这三条假设下，对所有 $j\ge1$ 和所有检验 $r$，$L^R_{j,r}\le\Delta^R_{j,r}$ 同时成立的概率至少 $1-\alpha$。推论：整个审计 campaign 里任何一个「总体上不合格」的候选被统计门接受的概率至多 $\alpha$。

一个很工程的细节：$j$ 是**全局审计事件编号**，由审计控制器统一分配，候选检验和参考替换的 bridge 检验共用，被拒、回滚、换提议策略之后都**不能重置**。

### 参考谱系

参考 $A^{(0)},\dots,A^{(K)}$ 每次替换都要做一次 bridge test，新参考相对旧参考的下界要过 $-\rho_{k,r}$，并消耗新的误差预算。定理 2 给出相对最初参考的累积退化上界：

$$Q^R_r(A)-Q^R_r(A^{(0)})\ge-\Big(\epsilon_{K,r}+\sum_{k=0}^{K-1}\rho_{k,r}\Big)$$

也就是说，换基线不是行政操作，而是要花统计证据、记成谱系里的一次转移，最大允许退化只能通过声明过的容差累加。

### 四层分工

| 层 | 管什么 | 不能替代什么 |
| --- | --- | --- |
| 生成器 | 探索设计空间 | 不控制确认审计 |
| 统计门 | 冻结候选、新鲜样本、下界过阈值 | 不证明裁判测到了真实能力 |
| 治理门 | 工具权限白名单、schema、出网限制、资源上限、人工审批、不可变审计日志 | 高分不能抵消硬约束失败 |
| canary | 限流量、限租户、限工具类别、限调用次数，有独立的停止权 | 不被离线定理覆盖，回滚撤不了外部副作用 |

结果有三种：接受、拒绝、不确定。保守策略下后两者都保留现任，但日志里必须区分，因为对后续候选开发和审计成本分析意义不同；只有预先规定了采样计划或用序贯有效的方法，才能「再多抽一点」。

## 🧪 关键证据：只有一个合成实验，而且作者反复强调这一点

### 蒙特卡洛：裁判偏差与审计规模

设计：每个条件 3000 个 campaign，每个 10 个候选，有益或有害各一半；reference 主效应有益 +0.25、有害 −0.10，保护效应为 0；$\delta=0.05$，$\epsilon=0.20$，$\alpha=0.05$；裁判主指标乐观度 $b\in\{0,0.10,0.25\}$；$n=m\in\{5000,20000,80000\}$；种子 20261112。

| n=m | 偏差 b | EGE 有害 campaign | 朴素门有害 campaign | EGE 有益接受率 | 朴素门有益接受率 |
| --- | --- | --- | --- | --- | --- |
| 5,000 | 0.00 | 0/3,000 | 0/3,000 | 52.6% | 100.0% |
| 5,000 | 0.10 | 0/3,000 | 0/3,000 | 76.2% | 100.0% |
| 5,000 | 0.25 | 0/3,000 | 2,997/3,000 | 65.7% | 100.0% |
| 20,000 | 0.25 | 0/3,000 | 2,997/3,000 | 100.0% | 100.0% |
| 80,000 | 0.25 | 0/3,000 | 2,997/3,000 | 100.0% | 100.0% |

（20,000 和 80,000 下 b=0 与 0.10 时两种门都是 0 次有害、100% 有益接受。）朴素门用同一个评估下界但不做校准。作者自己泼了两盆冷水：b=0 和 0.10 时朴素门在这个设计里也没放进有害候选，所以这个对比只针对选定的偏差与效应组合；100% 的接受率来自刻意拉开的效应，不是普遍的功效保证。

### 故意违反假设：校准样本不具代表性

再跑一个错配条件：10 个候选全是有害的，$n=m=100{,}000$，审计时裁判实际乐观 +0.25，但校准样本里只乐观 +0.05。结果 3000 个 campaign 全部放进了有害候选（100%，Clopper–Pearson 区间约 [0.9988, 1.0000]）。作者的说法是：这不是定理的反例，而是说明**形式化的置信界补救不了一个不具代表性的校准设计**。

| 全局事件编号 j | 每检验 e=c | n 最小 | m 最小 | 合计 |

## 🔬 最有意思的部分

**「裁判偏差要按候选单独估」是这篇最反直觉也最有用的一点。** 大家习惯先在一批数据上测一次 LLM judge 和人工的一致率，然后一直用下去。EGE 指出，自进化候选恰恰可能改变输出风格和结构，让同一个 judge 在新候选上更乐观。作者在「真实 agent 评测协议」里专门要求加一个裁判操纵条件：候选只改输出风格或结构、任务成功不变，按候选类别和风格报告裁判与参考的分歧。这和我们关注的「被测系统改了自己的检查」是同一个问题，只是这里发生在统计层。

**全局事件编号不可重置。** 这是一个很容易被实现成 bug 的地方：被拒之后换个提议策略重新从 j=1 开始，误差预算就被偷偷重复花了。EGE 把它写进了实现检查清单（附录 D 一共 10 条），包括候选和对照在审计期间不可变、审计样本不回流到开发循环、canary 由独立于候选的控制器叫停、回滚和补偿动作先测过再上线。

**canary 期间候选不能自改。** 否则被监控的对象就不是通过离线审计的那个对象了；如果确实要在 canary 期间适应，每个新版本都当新候选处理。对 always-on agent 来说，这条比任何统计公式都更容易被违反。

**罕见灾难不该被平均进分数。** 作者在局限里提到，归一到 $[0,1]$ 的平均分会稀释严重度，罕见的灾难性事件应该单独做硬约束、尾部风险或事件率要求，而不是混进能力分。

## 🤔 我的判断

定位：**一份形式化的采纳协议，不是方法突破，也还不是经过验证的系统。** 它的贡献是把「harness 演化里的接受门」应该满足什么，写成了带假设、带定理、带检查清单的东西。

亮点三条：

1. **生成和采纳分开，并且把信息流讲清楚**：开发、验证、审计三个分区，审计结果一旦喂回候选，那份样本对改过的候选就不再新鲜。
2. **把 judge 偏差当成要估计、要付样本的量**，而不是一个拍脑袋的容差；单边校准的理由也讲得很干净。
3. **参考谱系和 bridge test**：受保护能力对固定参考比，换参考要花证据，累积退化有显式上界。这正是「每次只退一点点、半年后退一大截」的解药。

问题与局限：

- **没有任何真实 agent 实验**，作者在摘要、正文、结论里都说了。唯一的实验是合成二值分布，效应量刻意拉开。
- **样本需求很重**：第 1 个候选每个检验就要约 8.5 万个观测，第 100 个要 23 万。对 harness 演化这种一次评测要跑真实任务的场景，按 Hoeffding 的最坏情况界几乎不可用；作者也提到 empirical Bernstein、confidence sequence、有限候选上限是替代方向，但没给数字。
- **独立性假设和真实轨迹冲突**：同一用户会话、共享状态的任务不能直接当独立样本，作者明确说这时 Hoeffding 结论不自动成立。
- **保证只相对参考程序**：参考验证器本身错了，保证也只是对错的东西成立。
- 论文声明用 ChatGPT 辅助规划、检索和起草文字，数学和代码由作者负责核对。

对工程的直接启发：如果你的 harness 有自动接受改动的环节，至少可以照搬三件事。第一，候选做内容哈希冻结后再抽审计样本，审计集访问记录到日志，审计结果不回流。第二，judge 在每类候选上单独抽一小批人工或确定性验证器对照，报告偏差，而不是只报一次全局一致率。第三，受保护能力对一个固定的版本化基线比，换基线单独审批、单独记账。至于严格的同时覆盖保证，在样本成本下来之前，更现实的做法是固定候选上限再做多重比较校正。

一句话：生成一个看起来合理的改动，并不构成它应该成为持久状态的证据；这篇的价值是把这句话变成了一张可以逐条核对的清单，而不是又一个分数。
