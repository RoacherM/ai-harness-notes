# 研究 agent 带着一份共享研究记忆跑了约 600 次实验来训决策模型：训练 KL 一路从 2.19 降到 0.64，同一批 341 道题的判对数却先多 78 道再少 13 道；同一配方下老骨干的视觉分反超新骨干；但多数被保留的改动不到 1 个点，也没报方差

你有没有过这种体验：让 agent 帮你跑后训练实验，它调数据配比、改学习率、合并 checkpoint，一晚上跑了几十个分支。早上一看，loss 曲线都很好看，排行榜分数也涨了一点。但你说不清哪个改动真的有用，哪些分支其实是在另一个能力上悄悄退步，那些「失败」的分支是不是就该删掉。**当模型开发本身交给 agent 驱动的自我改进循环，它需要记住什么、用什么来判断一次改动该不该留下？**

Piccolo Team（Data-Juicer 与 AgentScope 生态）的 **Piccolo: Co-Evolving Decision Models and Data through Recursive Self-Improvement** 发布了一个 0.8B 到 27B 的多模态决策模型家族，同时把它的开发过程描述成一个由研究 agent 驱动、带共享研究记忆的递归自我改进（RSI）循环。看完我的感受是：**作为模型发布，它的榜单成绩很强；作为 RSI 方法论，它最有价值的是几条「loss 和准确率脱钩」「单基准涨分掩盖跨任务退步」「失败分支也有可复用的更新方向」的经验，而它自己的接受门恰恰是这类循环里最弱的一环。**

## 核心摘要

Piccolo 是一个 Jev 式的决策模型：给定状态、问题和候选集，直接从语言模型头读出每个候选标签的 logit，softmax 得到候选概率，支持 Choice（多选）、Score（有序打分）、Noul（是/否）三种接口，用于通用判断、游戏实时交互、agent harness 里的工具审核/权限/上下文管理、数据处理工作流。开发过程被形式化为一个预算约束下的优化：在 accelerator-hours 预算 B 内，通过一系列实验提议 ψ_t 最大化留出开发集上最佳模型的分数。每一轮是「提议 → 构建并实验 → 诊断并更新」：研究状态 R_t 记录可用模型、标注过的数据资产、已完成的对比、研究记忆和剩余预算；反馈按语义切片汇总训练动态、推理结果和数据统计；诊断把涨跌关联到切片和设置；更新把资产和发现写回共享研究记忆，并调整提议优先级。人类研究者设定目标、审核重大改动、引入新方法和数据源。作者称约 600 次实验运行（约 2.8×10²¹ FLOPs，约 6,300 PPU-ZW810E accelerator-hours）得出三条反直觉结论：骨干与配方要协同选择，老骨干在视觉上可以超过新一代；定向数据整理能让 4B 到 9B 在特定工作流上逼近 27B；连续的 loss 下降可以与离散决策准确率脱钩甚至反向。Piccolo-27B 在 Decision Index Vision 上 Full 75.59、Private 70.97，排第一。这篇的价值定位是：**一份把 agent 驱动的数据中心后训练当作研究循环来记录的工程报告，给出了几条对任何 RSI 接受门都适用的警示。**

## 🎯 为什么这件事值得写

决策模型这条线我们已经跟了一阵（SO-Arena、HDM、DecisionTeacher 都在本周）：它们是 harness 里做工具选择、权限判断、路由的那个 System-1。Piccolo 有两层意思值得看。

第一层是模型本身。它在 harness 场景下有专门的评测 HarnessJevBench（覆盖工具使用、权限、记忆和执行），27B 得 84.41；AgentScope 的 QwenPaw 已经用它做工具审核和上下文压缩。

第二层是开发方法。作者把后训练从「在静态数据上优化动态模型」改写成「数据和模型的耦合动力系统」：模型能力边界在移动，最优的数据分布和配方也要跟着移动。这件事交给研究 agent 去做，并用一份共享研究记忆把所有成功和退步的实验串起来。这和我们一直关注的 harness 自我进化（SIM 的优化器记忆、ResolutionHypothesis 的分辨率问题）是同一个问题在权重层面的版本：**提议器有了，记忆有了，接受门够不够细？**

## 🏗️ 机制：决策读出、研究状态、原子迭代循环

### 决策模型的读出方式

一个训练样本是 (s, u, C, q)：s 是文本、图像或结构化观测，u 是问题，C=(c₁,…,c_K) 是候选，q 是目标分布。每个候选分配一个单 token 标签 τ(k) 连同描述放进输入；图像经视觉编码器和连接器送入语言骨干，可选一个旁路 OCR 模型提供图中文字。在答案位置，骨干输出隐状态，经原生语言模型头投影到词表 logit，只取各候选标签的 logit 做 softmax：

$$
z_{\theta,k}(x)=\big[W_{LM}\,h_\theta(x)\big]_{\tau(k)},\qquad p_{\theta,k}(x)=\frac{\exp z_{\theta,k}(x)}{\sum_{j=1}^{K}\exp z_{\theta,j}(x)}
$$

骨干在 full-attention 块里对 prompt 用双向注意力，混合骨干的线性注意力块保持因果。监督训练对候选分布做交叉熵，硬目标和软目标都支持。

### 研究状态与优化目标

$$
\max_{\psi_{1:T}} S_{dev}\big(m^{best}_T;V\big)\quad \text{s.t.}\quad \sum_{t=1}^{T}c_t\le B
$$

ψ_t 是一次实验提议，指定起始模型、数据策略（来源选择、配比、修订、合成）和允许的训练或推理改动；m^best_T 是 T 次实验后（含起始模型）最好的模型；c_t 是这次实验的执行加评测成本（accelerator-hours）。模型在统一的计分规则下比较，再用独立的确认集评估迁移。

### 原子迭代循环

$$
R_{t-1}\xrightarrow{\ \text{Propose}\ }\psi_t\xrightarrow{\ \text{Experiment}\ }(m_t,f_t,c_t)\xrightarrow{\ \text{Diagnose \& Update}\ }R_t
$$

编排器围绕这个循环组织了五个功能：

- **结构化反馈**：用语义标签把训练动态、推理结果、数据统计按来源、监督形式、候选数对齐。硬目标看正确候选的交叉熵，软目标看目标与预测的 KL；重复推理追踪「修好了哪些、新错了哪些」。按切片汇总能看出共享领域和能力标签的样本之间学习进度的差异，再链接回样本记录，找覆盖缺口、学习不均和标签冲突，驱动降采样、重配比、修标签、定向合成。
- **持久资产与研究记忆**：把提议、数据、模型、配置、协议和结果链接起来，用 DataJuicer-Panel 管理。标准化记录支持跨分支检索，lineage 追踪模型祖先和复用的配方与发现；记忆把涨跌关联到切片和设置，指导从其他起始模型出发的实验。
- **可组合的实验执行**：用 DataJuicer-Sandbox 把数据、训练、推理、评测步骤组合起来（Factories 提供能力，Hooks 绑定资产和设置，Pipelines 编排步骤）。
- **验证与对比**：开发集比较追踪改进和保留的能力，不相交的确认集和更宽的评测评估迁移；按来源和构造身份划分数据，审计检查样本有效性、输入版本和评测完整性。附录给的数据配比研究规模是约 4,000 道调优题和 2,000 道不相交的确认题。
- **提议选择与人类引导**：agent 按预期改进、保留的能力、信息价值和成本给提议排序，记录目标、父模型、动作和对照；短诊断消解不确定性，长运行推进有希望的方向。人类研究者设优先级、审核重大改动、引入新方法和数据源。

### 一个真实迭代（Figure 5）

1. **执行检索提议 P1**：从保留模型 M0 出发，80% 回放加 20% 从数据池检索的补充，训练出 M1。
2. **诊断退步**：arts（艺术/人文）从 55.19 掉到 52.66；把预测和所选数据记录关联后发现训练题里 arts 只占 3.1%。诊断 K1 把 arts 覆盖定为下一次实验的重点，资产记录保存了所选组、配置和父模型。
3. **修订配比并比较**：P2 从同一个 M0 出发，共享回放组、学习率和种子，测试只加知识类（M2）和知识+arts 均衡（M3，arts 占 20.6%）两种补充。均衡的 M3 比 M2 整体高 0.30 点、arts 高 0.70 点（M0：65.83 / 55.19；M1：65.56 / 52.66；M2：65.59 / 54.05；M3：65.89 / 54.75）。记忆 K2 保留了这次比较和 arts 相对 M0 仍有的差距。

### Loss 和判对数脱钩（Table 1）

在 341 道固定的数据处理和 agent 工作流硬目标题上：

| 阶段 | 平均 KL | 判对数净变化 | 该桶配比 |
| --- | --- | --- | --- |
| 前期 | 2.19 → 0.66 | +78 | 5.36% → 5.14% |
| 后期 | 0.66 → 0.64 | −13 | （同上） |

KL 单调下降，判对数却先大涨再反转。编排器捕捉到这个背离后，把这个桶的配比从 5.36% 调到 5.14%。附录 B 给了理论解释：对硬目标，错误指示有上界 1[ŷ≠y] ≤ −log p_{θ,y} / log 2，但在有限实验里平均 loss 追踪的是概率在样本上的变化，准确率追踪的是哪些候选越过了决策边界，两者都要报。

### 数据演化（Section 4.2）

- **反馈引导的数据修订**：替换早期配方的 10%，比同比例随机替换高 2.11 个开发点（56.56 对 54.45）。恢复欠代表的偏好覆盖后，arts/偏好分量从 48.91 升到 53.42。新合成任务上模型通过率：状态追踪 63.43%、参数校验 100%、预算分配 15.38%，用来定位还缺难例的地方。
- **按训练动态自适应分配**：重配比让 Public Text 到 67.93（固定配方 67.36）；再加过滤后 Harness 到 84.58、Data 到 82.20，Text 是 66.98。不同数据动作产生不同的能力画像。
- **联合配方**：一个 Qwen3.6-27B 后代在一次整合节点上 Vision 71.89→79.59、Harness 68.64→81.36、Data 73.20→81.40。

### 模型演化（Section 4.3）

- **训练**：训练和推理都用双向注意力时 Text 开发分 69.01，因果注意力 68.20，只在推理时双向 68.14。同一父模型、同样样本下，固定权重 GRPO 77.13、候选 CE 77.31、置信/进度加权 GRPO 77.35（Public Vision）。
- **组合**：跨模态合并把 Public Text 从 67.89 提到 68.15，但 Vision 从 77.29 掉到 75.70。一个权重空间编辑配置（9 到 17 块视觉注意力投影约加强 5%、8 到 23 层语言前馈轻微衰减、部分后期门控注意力块的 log-decay 偏移、30 到 31 层输出投影的 rank-8 更新）把 Public Vision 从 70.10 提到 70.75，Harness 掉 0.68。合并五个数据专精后代，Public Text 到 63.11，高于最强单分支的 62.78。
- **推理**：自适应重读在 1.02× 输入量下 Public Text 68.56；完整重读 68.64；两视图、三视图聚合 68.69、68.71，输入量 1.90×、2.08×。层复用：对两个相邻层段各做两次半步，Text 开发分从 69.15 到 69.75，Harness 从 80.85 到 87.12；只复用一个层段 69.58；步长降到四分之一则掉到 67.41。另一个递归配置把 2B 的 Public Vision 从 65.85 提到 66.64。

### 跨任务退步（Section 5，Figure 11）

- **不动权重也会此消彼长**：只改输入排布，Public Text +1.14，DataJevBench −3.00。
- **固定数据池上加算力会损害泛化**：在一个固定池上跟踪 11 个 checkpoint、累计 102.4 万次样本曝光，Data 分涨 0.60，Text 和 Harness 分别掉 1.29 和 1.69。
- **失败分支有可用信号**：一个续训分支在开发集上掉到父模型以下，但提取它参数更新的特定分量、以负系数加回去，得到了一个获胜的权重空间合并。

## 🔬 最有意思的部分

**一，loss 是一个会骗人的接受信号。** Table 1 是全文最干净的一张表：KL 从 0.66 降到 0.64，看起来还在变好，同一批 341 道题却少判对 13 道。对任何用训练信号做自动接受的 RSI 循环，这都是一条硬约束：**接受门要看离散决策的修好/新错，而不是连续的 loss**。作者的编排器正是靠「修好了哪些、新错了哪些」这类重复推理读数捕捉到背离的。

**二，单基准涨分几乎总伴随别处退步。** 不动权重改输入排布就能 Text +1.14、Data −3.00；固定池多训 Data +0.60、Text −1.29、Harness −1.69；跨模态合并 Text +0.26、Vision −1.59。这说明 RSI 的接受门必须是多任务的，并且要有「保留的能力」这一维。论文的提议排序里确实有「retained skills」这一项，这是对的。

**三，记忆的价值在于把失败分支变成资产。** 负系数复用退步分支的更新方向，这个例子虽然只有一句话的描述，但它说明了为什么研究记忆要保存完整 lineage（父 checkpoint、参数差、切片级响应），而不只是保存「最好的那个模型」。这和 SIM 那篇「优化器要有按问题归档的改动账本」是一个方向，只是落在权重空间。

**四，骨干选择不是越新越好。** 同配方下 Qwen3.5 视觉最好、Qwen3.8 harness 最好，相差 2 到 5 个点。对给 harness 选小模型底座的人，这是一个直接的提醒：要按目标部署域选骨干，在你自己的任务上比。

## 🤔 我的判断

定位：**模型发布加 RSI 工程记录**。榜单结果扎实，方法论部分更像一份经验总结，而不是被严格检验过的方法。

亮点三条：

- **把 loss 和决策准确率分开报。** Table 1 和附录 B 的界给出了一个简单但常被忽略的原则。
- **跨任务退步的例子很具体。** 每个「涨」都配了「掉」，提醒接受门要多任务。
- **研究记忆的结构讲得清楚。** 提议、数据、模型、配置、协议、结果全部链接，lineage 同时记录模型祖先和研究推理链。

问题与局限：

- **接受门的统计强度不够。** 被当作成功案例的 Figure 5 里，M3 比 M2 只高 0.30 点整体、0.70 点 arts；很多被保留的改动在 0.2 到 0.7 点之间（比如 77.13/77.31/77.35、68.56/68.64/68.69/68.71、70.10→70.75）。论文没有报种子方差或置信区间（数据配比研究的调优集约 4,000 题）。在今天另一篇 ResolutionHypothesis 指出「中位领先小于同一方法跑两次的差距」的背景下，这些小差距能否区分真改进和噪声，存疑。
- **研究 agent 本身几乎是黑箱。** 论文没说研究 agent 用的是什么模型、哪些提议是 agent 发起的、哪些是人类引入的，也没有「agent 引导 vs 人工调参」或「有记忆 vs 无记忆」的消融。人类设目标、审重大改动，所以 RSI 中「自主」的比例无法判断。
- **约 600 次运行与附录里「27B 战役 647 次训练尝试」的口径不完全一致**，算力是按峰值 BF16 估算的上界式数字。
- **两个应用评测与 Piccolo 同属一个生态**：HarnessJevBench 和 DataJevBench 的引用链接分别指向 agentscope-ai 和 datajuicer 的 GitHub 组织；「比最强外部 Harness 基线高 1.36 点」也限定在「已完成的那一批」。
- **榜单快照距提交只有一天**，参赛者 86 个，排名会随时间变化。

对工程的直接启发：

1. 自动接受改动时，看离散决策的「修好/新错」而不是 loss。loss 还在降时判对数可能已经开始倒退。
2. 接受门至少覆盖三类任务，并把「保留的能力」写进门的判据。单基准涨 1 点、别处掉 3 点在这篇里是常态。
3. 研究记忆保存完整 lineage 和参数差，不要只留最好的 checkpoint；退步分支的更新方向可能是下一次合并的原料。
4. 给 harness 选决策模型底座时，在目标任务上做同配方的骨干对比，新骨干不一定在你的域上更好。
5. 如果你也在做类似的 agent 驱动后训练循环，给每个小于 1 点的改动配上多种子或配对检验再决定是否保留，这是 Piccolo 没做、但最该补上的一环。

一句话：Piccolo 证明了 agent 驱动的数据中心后训练能把一个决策模型家族推到榜首，也顺手记录下了这类循环最容易被骗的地方：loss 会骗人，单基准会骗人，零点几的涨幅也可能在骗人。
