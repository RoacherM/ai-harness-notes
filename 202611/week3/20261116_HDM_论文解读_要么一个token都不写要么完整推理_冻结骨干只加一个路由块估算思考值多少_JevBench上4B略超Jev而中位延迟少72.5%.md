# 决策模型和推理模型非得二选一吗？HDM：同一个冻结骨干，一次前向直接给答案，只在「思考真的值钱」的题上才开口写推理

你有没有过这种体验：harness 里一个路由或验收节点，平时接 Jev 这类 System One 决策模型，一百多毫秒出一个概率分布，又快又好用；可总有一小撮题它答不对，换成会写思维链的推理模型就能答对，但每道题都让推理模型想一遍，token 和延迟又扛不住。于是你在两个模型之间写一个路由，结果路由本身又要一次调用，而且「这题它有没有把握」和「这题让它想一想会不会变对」根本不是一回事。

业界做自适应推理大致两条路：一条让推理模型少写一点，问「该想多久」；另一条在模型之间做路由或级联，选项是「贵的答案还是便宜的答案」，但两边都在逐 token 生成答案。**能不能让一个模型同时保留两种优势：该一个 token 都不写的时候就不写，该推理的时候完整推理？** 华为诺亚方舟实验室、利物浦大学和 UCL 的这篇论文把它叫做 **zero-or-T thinking**。看完我的感受是：它最值得记住的不是 JevBench 上那 0.7% 的领先，而是**路由信号该问「思考会不会改变答案」，而不是「快答案有多大把握」**，以及这个信号可以直接从快模式那次前向的隐藏状态里读出来。

## 核心摘要

HDM（hybrid decision model，混合决策模型）由一个冻结的语言模型骨干和一个很小的自路由块组成，全文唯一需要学习的权重就在这个块里。请求进来，骨干先做一次前向，在读出位置用候选项编码对应的 logits 直接给出快答案，不生成任何 token；自路由块读取这个位置某一层的隐藏状态，加上快答案输出分布的八个统计量，预测「快模式对不对 × 慢模式对不对」的四种联合结果，由此得到**思考的价值** $v_i=\log\frac{P(\text{slow}\checkmark)}{P(\text{fast}\checkmark)}$。只有当 $v_i$ 超过请求方按次设定的价格 $\lambda$ 时，才让同一个骨干接着已有的 KV 缓存自回归推理，不需要第二次 prefill。有逐题标签时，块用四分类交叉熵训练；在多轮 agent 任务里没有逐步标签，作者提出 CDPO（Calibrated Decision Policy Optimisation），一种基于 PPO、从回合回报里学习的配方。块只在 MMLU-Pro 的 11 个科目上训练，就迁移到 3 个留出科目、AGIEval、GPQA-Diamond、JevBench 和 BANKING77。主要数字：JevBench 公开 231 题上 HDM-4B 在 $\lambda=0$ 时 0.857 对 Jev 1.13.0 的 0.851，中位延迟 0.179 秒对 0.652 秒；BANKING77 上 $\lambda=0.05$ 时 0.920 准确率每题只花 1.1 个思考 token；MiniWoB 上 HDM-27B 思考 token 降 80.1%，奖励从总是思考的 0.519 降到 0.469。这篇的价值定位是：**把「要不要推理」变成一个在已有前向里就能做出的、按请求定价的决策，而且明确告诉你该估计的量是什么。**

## 🎯 为什么这件事值得写

决策模型这条线，我们这个仓库已经积累了不少：Drex、DecisionRank 在比谁更快更准，DecisionConflict 让决策模型接手 LLM 的判断，今天另一篇 DecisionTeacher 讨论决策模型当老师，同批的 SO-Arena 则测出 System One 模型在多步推导类题上明显落后 System Two。**快模式不够用的时候怎么办**，是一个绕不开的问题。

现有答案有两类。一类是推理模型内部提效，缩短思维链但不让它可选，问的是「想多久」而不是「这题需不需要想」。另一类是模型间路由或级联（FrugalGPT、RouteLLM 等），每个分支都是一个生成答案的模型。HDM 的不同在于：**快模式根本不生成，慢模式就是同一个骨干的正常推理，路由发生在快模式已经算完的那次前向之后，不额外加前向也不加 token。**

对做 harness 的人来说，这个设计直接对应一个常见架构选择：门控节点是用一个快模型加一个慢模型、中间再接一个路由器，还是用一个模型自己判断该不该升级。

## 🏗️ 机制 / 任务定义

**效用与价格**。每种模式在题 $i$ 上的效用就是对错：

$$u_{i}(m)=\mathbf{1}[\text{模式 } m \text{ 答对 } i]\in\{0,1\},\quad m\in\{\text{fast},\text{slow}\}$$

同时跑两种模式会观测到四种结果之一：都对、只有快的对、只有慢的对、都不对。作者认为答案越晚越不值钱，所以用指数折扣而非减法：

$$r_{i}(m,\rho)=u_{i}(m)\,e^{-\rho T_{i}^{m}}$$

快模式不生成 token，回报就是 $P(\text{fast}\checkmark)$；慢模式回报是 $P(\text{slow}\checkmark)e^{-\rho T_i^{\text{slow}}}$。升级划算当且仅当 $v_i>\rho T_i^{\text{slow}}$。由于 $T_i^{\text{slow}}$ 要跑完才知道，作者用慢模式平均长度定价，得到按次升级的价格 $\lambda=\rho\bar{T}^{\text{slow}}$，路由规则只剩一个阈值：

$$\text{escalate}_i=\mathbf{1}[v_i>\lambda]$$

作者强调用对数比值而不是差值，因为差值在思考最值钱的地方反而会变小。

**为什么不用置信度**。置信度回答的是「快答案有多确定」，思考的价值回答的是「慢模式会不会答得不一样」。两者在两个方向上都会分离：思考有时会把快模式本来答对的题改错，在两种模式都会答对的题上思考则毫无增益。所以路由器必须估计联合结果。

**架构**。三步按顺序执行：

1. 快模式：提示里列出带编码的候选，以一个边界字符串结尾，使答案成为骨干预测的下一个 token；一次前向后，用输出投影在候选编码上的 logits 给出快答案。
2. 自路由块：读取读出位置某层隐藏状态 $\bm{h}_i$ 和快答案分布的八个统计量 $\bm{s}_i$，输出四种联合结果的分布 $\bm{o}_i$，同时得到置信度 $c_i=P(\text{fast}\checkmark)$ 和思考价值 $v_i$。
3. 慢模式：仅对升级的题，从快模式已经编码的前缀继续自回归推理，最多 $B$ 个 token，路由块不再被调用。

**统一请求格式**。请求包含提示、可选的显式问题和可选的候选集，只有提示是必需的。这让两种模式可以互换：调用方无论哪种模式作答，都拿到同一种类型的答案，`choice`、`noul`（是或否）、`score`（等级）和自由生成共用一个骨干和一个块。

**两种训练方式**：

- 有标签时：温度为零时冻结骨干是确定性映射，慢模式在某道题上的对错固定。对一批有答案的题同时跑快慢两种模式，得到四分类标签 $y_i$，用交叉熵拟合块：$\mathcal{L}(\theta)=-\frac{1}{|\mathcal{D}|}\sum_{i}\log P_{\theta}(y_{i}\mid\bm{h}_{i},\bm{s}_{i})$。损失里没有价格，一次拟合服务所有 $\lambda$。
- 回合式 agent 任务：单步对错往往不决定任务成败，也没有逐步标签。CDPO 为每次决策抽一个价格，目标是按升级次数折扣后的回合回报；用软化的阈值规则使其可微；离策略数据按每次决策的比值 $\rho_t=\pi_\theta/\mu$ 重加权，比值在每个决策内放进 PPO 的截断代理目标，而不是沿几十步连乘；优势 $A_t=G_t-\bar{G}$，基线是相同抽样价格下的平均回报。作者明确说这是该目标的代理，不是梯度的无偏估计。

## 🧪 关键证据或主结果

**设置**。骨干为 Qwen3.5-4B 和 Qwen3.8-27B，思考预算 $B=4096$，慢模式贪心解码；在这个上限下慢模式在 4B 上 36.1% 的题被截断、27B 上 14.9%，所以相关 token 数和准确率是下界。训练集取自 MMLU-Pro 测试划分的 1,500 题（14 个科目每 8 题取 1），化学、经济、心理三科共 346 题留出，其余 11 科 1,154 题训练，留出科目由科目名的确定性哈希选出。训练时 $\lambda$ 在 $[-0.2,0.5]$ 中逐例抽样。所有实验读取最后一层。

**通用问答（表 1，部分）**：

| 骨干 | 策略 | $\lambda$ | MMLU-Pro 升级率 / 准确率 / token | AGIEval 升级率 / 准确率 / token |
|---|---|---|---|---|
| 4B | 只快 | – | 0% / 0.543 / 0 | 0% / 0.606 / 0 |
| 4B | 只慢 | – | 100% / 0.853 / 2281 | 100% / 0.842 / 2364 |
| 4B | HDM | 0 | 66% / 0.844 / 1845 | 71% / 0.830 / 1801 |
| 4B | HDM | 0.5 | 39% / 0.772 / 1166 | 39% / 0.797 / 991 |
| 27B | 只快 | – | 0% / 0.650 / 0 | 0% / 0.710 / 0 |
| 27B | 只慢 | – | 100% / 0.902 / 778 | 100% / 0.925 / 824 |
| 27B | HDM | 0 | 63% / 0.896 / 664 | 79% / 0.919 / 725 |
| 27B | HDM | 0.5 | 38% / 0.873 / 486 | 40% / 0.890 / 439 |

27B 在 $\lambda=0.5$ 时，MMLU-Pro 上比总是思考低 0.029、token 少 38%，AGIEval 上低 0.035、token 少 47%。换个角度：思考相对快模式的增益在 MMLU-Pro 上是 0.252、AGIEval 上是 0.215，HDM 保住了其中 88% 和 84%，只花了 62% 和 53% 的 token。GPQA-Diamond 上路由更保守，4B 在 $\lambda=0$ 时升级 93%。

**对比其他 System One 模型（JevBench v1 公开 231 题）**：

| 系统 | 升级率 | 准确率 | P50（秒） |
|---|---|---|---|
| Jev 1.13.0 | — | 0.851 | 0.652 |
| AnyJev Tacit-9B，只快 | 0% | 0.823 | — |
| AnyJev Tacit-9B，自适应 | — | 0.887 | — |
| HDM-4B，只快 | 0% | 0.762 | 0.226 |
| HDM-4B，总是思考 | 100% | 0.931 | 3.86 |
| HDM-4B，路由 $\lambda=0$ | 30% | 0.857 | 0.179 |
| HDM-27B，只快 | 0% | 0.879 | 0.411 |
| HDM-27B，总是思考 | 100% | 0.991 | 4.81 |
| HDM-27B，路由 $\lambda=0$ | 54% | 0.987 | 2.49 |

JevBench 的 231 题里有 139 道 `choice`、74 道 `noul`、18 道 `score`，而块只在多选题上训练过；在 $\lambda=0$ 时它对 `noul` 的升级率是 0.784，对 `choice` 是 0.417，说明它能迁移到没训练过的题型。

**BANKING77（20 类意图，300 题，27B）**。这里思考不划算：总是思考 0.913、每题 135.3 个 token，只快 0.923、零 token。HDM 在 $\lambda=0.05$ 时升级 0.3%、准确率 0.920、每题 1.1 个 token。作者用 AnyJev 官方代码在同样 300 题上跑了 Tacit-9B + AnyJev 的自适应规则：升级 6.0%、准确率 0.913、每题 140.2 个 token。

| 环境 | 策略 | 升级率 | 奖励 | token/回合 | 秒/回合 |
|---|---|---|---|---|---|
| ALFWorld（134 局） | 只快 | 0% | 0.463 | 0 | 55.4 |
| | 只慢 | 100% | 0.642 | 6254 | 185.2 |
| | HDM | 46% | 0.560 | 3015 | 108.4 |
| MiniWoB（27 个点击任务） | 只快 | 0% | 0.407 | 0 | 21.3 |

ALFWorld 上用 48% 的思考 token 拿到 54% 的可得增益；MiniWoB 上放弃 0.05 奖励，思考 token 降 80.1%，墙钟降 67.4%。

**泼点冷水**。第一，作者在结论里自己说得很清楚：**对已发表系统主张的是「更低 token 成本下有竞争力」，不是全面领先**；BANKING77 上有两个对比配置准确率比 HDM 高（AnyJev 接 Qwen3.8-27B 在 $\tau=0.5$ 时 0.933、$\tau=1.0$ 时 0.923），引用的其他工作的延迟是在别的后端上测的。第二，HDM-4B 路由后的 0.857 虽然略高于 Jev，但离它自己总是思考的 0.931 还差不少，「追平 Jev」靠的是 30% 的升级率，不是快模式本身（快模式只有 0.762）。路由后 P50 0.179 秒还低于它自己只快模式的 0.226 秒，论文没有解释这个差异。第三，agent 实验规模小：ALFWorld 只跑一次，块在随机路由下收集的一轮 150 个回合上拟合；MiniWoB 路由行是三个种子合并、两个端点各跑一次。第四，消融（表 5）只有一个种子。第五，4B 上慢模式有 36.1% 被截断，慢模式的准确率和 token 都是下界，这会影响「思考值多少」的标签本身。

## 🔬 最有意思的部分

**1. 隐藏状态比输出分布更知道「思考会不会救回来」。** 表 5 在 Qwen3.5-4B、$B=1024$ 上测路由块区分两件事的 AUROC：rescue（思考是否把错的快答案改对）和 right（快答案本身是否已经对）。

| 输入 | 维度 | CV rescue | CV right | 留出 rescue | 留出 right |
|---|---|---|---|---|---|
| 只用统计量 | 8 | 0.671 | 0.763 | 0.701 | 0.840 |
| 最后一层，原始 | 2568 | 0.765 | 0.758 | 0.716 | 0.821 |
| 第 24 层，原始 | 2568 | 0.778 | 0.764 | 0.762 | 0.827 |
| 第 24 层，PCA-64，无统计量 | 64 | 0.728 | 0.655 | 0.708 | 0.758 |

只看快答案的输出分布，预测「快答案对不对」不差（留出 0.840），预测「思考能不能救回来」就弱得多（0.701）。加上隐藏状态后 rescue 明显上升。这正好印证了作者的核心论点：**置信度和思考价值是两个不同的量**，前者从输出分布就能读，后者要往模型内部看。另外第 24 层比最后一层更好（留出 rescue 高 0.046），作者为了跨骨干通用仍然全文读最后一层。

**2. 省下的 token 来自挑哪些题，而不是挑多少题。** 27B 在 $\lambda=0.5$ 时只对 38% 的 MMLU-Pro 题升级，token 也省了 38%；如果升级的题长度和平均一样，应该省 62%。也就是说，块倾向于把长推理的题留给慢模式，因为那些恰好是思考最可能改变答案的题。

**3. 按固定准确率看成本，学习到的路由才有优势，而且优势不大。** 表 6 在 JevBench 上比「达到总是思考准确率 90% 需要多少思考 token」：

| 规则 | Qwen3.8-27B | Qwen3.5-4B |
|---|---|---|
| 总是思考 | 591 | 1709 |
| 随机升级 | 213 | 991 |
| 置信度阈值 | 138 | 945 |
| ThinkSwitcher（复现） | 352 | 1709 |
| RouteLLM（复现） | 112 | 822 |
| HDM | 103 | 792 |

RouteLLM 是在同样的隐藏状态和统计量、同样训练科目上拟合的二分类版本，所以这一组比较隔离的是估计器本身。HDM 对 RouteLLM 的领先只有 9 和 30 个 token，作者也承认排序随目标点而变。ThinkSwitcher 的复现版甚至比随机升级还贵。

**4. 价格可以是负数。** 训练时 $\lambda$ 从 $-0.2$ 开始抽。表 1 里 $\lambda=-0.1$ 那一行，4B 在 AGIEval 和 GPQA 上几乎全升级。这给调用方留了一个「宁可多想」的旋钮，适合验收门这种错放一个比多花几百 token 更贵的场景。

## 🤔 我的判断

**定位**：方法改进加一个清楚的问题重述。不是全面碾压 Jev 的新模型，而是一套在冻结骨干上加几百 KB 参数就能用的快慢切换机制。

**亮点三条**：

1. 把路由目标从置信度换成「慢模式相对快模式的成功率对数比」，并用四分类联合标签去估计它，消融证明这确实是不同的信号。
2. 路由发生在快模式已经算完的前向之后，慢模式复用同一前缀的 KV 缓存，没有第二个模型、第二次前向或第二次 prefill。
3. 价格按请求设定，一次训练覆盖整条成本准确率曲线；CDPO 把同一个块推广到没有逐步标签的回合式任务。

**问题与局限**：作者自己限定了主张范围（有竞争力而非领先）；agent 实验和消融的种子数都很少；4B 的慢模式截断率高，标签本身有偏；代码链接尚未公开；JevBench 上「略超 Jev」的结论依赖升级率，快模式单独仍明显弱于 Jev。

**对工程的直接启发**：如果你在 harness 里已经同时用着一个决策模型和一个推理模型，可以先做一件便宜的事：在一批有标签的门控题上，把两个模式都跑一遍，按「都对、只快对、只慢对、都错」四类统计。「只快对」那一类就是思考会把事情搞砸的地方，「只慢对」才是值得付费升级的地方。光这张四格表就能告诉你，现在按置信度阈值升级的策略到底浪费在哪。如果骨干是自己部署的开源模型，再往前一步就是 HDM 的做法：从读出位置的隐藏状态学一个小分类器，直接预测这四格。

一句话收束：**HDM 的取舍是承认快模式不够强，然后把力气花在一个更准的问题上：不是「我有多确定」，而是「多想一会儿会不会不一样」。**
