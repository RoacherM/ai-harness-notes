# 五个用户、七个 agent 共用一份记忆，每条经验先定「谁能读」：MixUA 通过率比无记忆高 16 点，偏好留住九成，隐私探针泄漏至多 0.02%

你有没有过这种体验：团队里几个人分别用 Claude Code、Codex、OpenClaw 干活，某人踩过的坑（某个库的版本 bug、某个测试框架的怪脾气）别人还得再踩一遍；可真要把所有人的 agent 记忆合成一份，你又立刻担心两件事：张三「报告别用破折号」的偏好会不会污染李四的输出，张三工作目录里的私人信息会不会被写进大家都能读的记忆。现在的自进化记忆、共享 skill 库，基本只回答了「要不要共享」，没回答 **「这条经验应该给谁读、哪些东西必须留在原主人那里」**。

AWS Agentic AI 和南加州大学的 **Who Remembers What? Multi-Granularity Memory Extraction for Multi-User, Multi-Agent Interaction** 把这个设定叫 cross-learning：一群相互独立的用户和异构 agent 互相从对方的经验里学。他们提出 MixUA，一个把每条经验放进四种作用域之一的记忆系统，并造了 CrossLearnBench 同时测效用、偏好保留和隐私泄漏。看完我的感受是：**这篇最值得抄的不是四个作用域本身，而是「隐私不靠写入者自觉标注，而靠双流隔离写入」这个结构性设计，以及记忆条目自带来源记录。**

## 核心摘要

作者把用户集合 $\mathcal{U}$ 和 agent 集合 $\mathcal{A}$（每个 agent 是一个固定的 LLM 加 harness 配置）的笛卡尔积当作读者空间，每条记忆有一个泛化范围 $\mathcal{G}(e)$（对谁有效）和一个披露边界 $\mathcal{D}(e)$（最多能给谁看而不暴露原主人），授权读者必须落在两者交集里。四个作用域是 Pair（这个用户配这个 agent）、User（这个用户的所有 agent）、Agent（这个 agent 的所有用户）、Global（所有人）。写入时每条轨迹先被一个隐私切分器拆成可复用流和受保护流，送给两个相互隔离的写入器；条目的作用域上限由它来自哪条流决定，而不是由写入器自报，所以受保护条目只能落进原主人的 User 或 Pair。每轮结束后可选做一次全库审查，重新定作用域并合并重复。评测用 5 个合成用户、7 个 LLM-harness 组合（Claude Code 配 Opus 5 或 Sonnet 5、Hermes 和 OpenClaw 配 Sonnet 5、Codex 配 GPT-5.6 Sol、Luna、Terra），任务取自 AutoCodeBench、FeatureBench、SpreadsheetBench、SWT-Bench、USACO、Terminal-Bench 2.0、VMax Tasks 七个数据集，在 Docker 沙箱里跑。主结果上，无记忆第 3 轮通过率 72.0%，MixUA（LLM 写入器）加审查到 89.8%，2 到 3 轮比无记忆高 16.3 点；单一全局记忆高 11.5 点但偏好保留只有 11%，和无记忆一样。在之前只被「既不同用户也不同 agent」的组合尝试过的任务上，MixUA 高 11 到 14 点，全局记忆 8.9 点，私有 Pair 记忆 1.6 点。偏好保留最高 90%，摘要报告隐私探针在禁止作用域里找到植入私密事实的比例至多 0.02%。

## 🎯 为什么这件事值得写

作者画了一张四格演化图：一个 agent 服务一个用户；一个固定 agent 团队服务一个用户；一个 agent 服务很多用户，用户间隐私变成一等问题；最后是一群独立用户和异构 agent 一起演化。前两格已经有大量工作，第三格开始有人关注，第四格基本是空的。

现有系统里，谁能读一条记忆几乎都是设计时写死的。作者的对照表把它们映射到四个作用域：MemGPT、A-Mem、MIRIX 服务一个 pair 或一个用户；G-Memory、SkillClaw、FederatedSkill、ShareMem 是共享或联邦存储，接收者固定；Collaborative Memory 和 AIM 按访问策略设定。MixUA 是表里唯一「每条条目单独学习作用域」的。

这和我们一直关心的多 agent 记忆来源与边界问题直接相关：**一条经验从谁的轨迹来、能给谁读、谁写的，都需要在记忆格式里显式表达**，否则共享记忆就是一个泄漏面加一个污染面。

## 🏗️ 机制：四个作用域 + 双流写入 + 全库审查

### 作用域与读视图

| 作用域 | 读者 | 适合放什么（论文的例子） |
| --- | --- | --- |
| Pair | $\{u\}\times\{a\}$ | 跨 agent 会冲突的偏好，比如对啰嗦的 agent 要简洁、对简洁的 agent 要详细 |
| User | $\{u\}\times\mathcal{A}$ | 用户偏好，比如文档格式 |
| Agent | $\mathcal{U}\times\{a\}$ | 某个 agent 的工具调用怪癖、常犯错误 |
| Global | $\mathcal{U}\times\mathcal{A}$ | 库缺陷、某个任务的修法 |

一个 pair 的读视图 $V(u,a)$ 是自己的 Pair、自己用户的 User、自己 agent 的 Agent，加上 Global，永远看不到别的用户的 User 或别的 pair 的 Pair。只有「打开用户轴」这一步会把条目暴露给别的用户，所以只有这一步过隐私闸门。

$$\mathrm{Aud}(e)\subseteq\mathcal{G}(e)\cap\mathcal{D}(e)$$

### 双流写入

每轮里，每个 pair 用自己能读的记忆做完任务，然后这一轮的轨迹被一条一条写进存储。写之前，隐私切分器把每条已判分轨迹拆成两段：

- **可复用流**：可迁移的技术经验，任务要什么、哪里失败、怎么修好、验证器说了什么。保留命令、参数、报错和版本号，识别性细节泛化而不是删除，比如 `/home/alice/proj/run.sh` 变成 `<path>/run.sh`。
- **受保护流**：关于这个用户而不是这个任务的事实，身份、雇主、团队、项目、时区，以及输出、命名、工具上的习惯。
- **两流都不许出现**：身份号码和任何凭据的值。

两段送给两个隔离的写入器，看过受保护内容的写入器永远不能写共享条目。每个条目包含情境（何时适用）、经验、作用域和来源（来自哪些任务、哪些 pair、哪一轮、结果如何）。写入器提示里还有一条值得记住的规则：**记录下来的判分结果优先于 agent 自己的说法**，判分失败是强证据，超时或报错什么都不证明。

### 检索

默认按条目情境和任务提示的 embedding 余弦相似度排序，每个作用域有字符预算。另一个变体是把读视图按作用域写成文件放进容器，让 agent 自己读或 grep，这更像编码 harness 的常见做法。

### CrossLearnBench

在原任务环境里为每个用户植入隐私事实：每个合成人设有 9 项始终私密的 PII，加上 Pew Research Center 2014 年隐私调查每个类别一条事实，事实的隐私标签来自每个用户自己的问卷回答，所以同一个类别对一个人私密、对另一个人可以公开，系统必须逐用户判断。偏好则是让 agent 每个任务结束写一份摘要文档，每个用户有四个文档偏好（文件名、署名日期格式、有序章节、一个禁用标记比如破折号），只在第 1 轮说一次，之后全靠记忆。

## 🧪 关键证据

### 主结果（排程任务，三次运行均值）

| 条件 | 第 3 轮通过率 | Δ（pp） | Δcross（pp） | 偏好保留 | 偏好泄漏 | 打开植入文件 |
| --- | --- | --- | --- | --- | --- | --- |
| 无记忆 | 72.0 | – | – | 11 | n/a | 8 |
| 仅 Pair | 77.6 | +4.3 | +1.6 | 80 | n/a | 20 |
| 仅 User | 80.4 | +8.8 | +3.3 | 37 | n/a | 12 |
| 仅 Global | 85.5 | +11.5 | +8.9 | 11 | 0.4 | 6 |
| 仅 Global + 受保护流 | 86.9 | +13.2 | +12.6 | 15 | 5.5 | 8 |
| MixUA（LLM） | 88.1 | +15.3 | +13.0 | 90 | 4.8 | 26 |
| MixUA（LLM）+ 审查 | 89.8 | +16.3 | +13.9 | 89 | 3.6 | 24 |
| MixUA（agentic）+ 审查 | 87.1 | +14.0 | +10.7 | 86 | 0.9 | 12 |

（仅 Global 不带受保护流时偏好泄漏不可直接比较，论文有注明。）单一作用域都是在效用和偏好之间二选一：Global 拿到最多效用但几乎不记偏好，Pair 正好反过来，只有 MixUA 的四个变体同时拿到两者。除了已经接近天花板的 Claude Code 配 Opus，每个 agent 都涨了 11 到 23 点。

隐私上：使用 MixUA 时 agent 在 11% 到 26% 的尝试里打开过植入文件，但四个变体里有三个在大约 18k 次探针中没有把任何植入事实放进禁止作用域，全库审查把 agentic 写入器的 4 次违规清掉了。

### 随机任务（更接近部署）

8 轮，每轮从 546 个任务池里抽 60 个随机分给 pair。2 到 8 轮的 821 次尝试里有 526 次是「没有任何 pair 做过的任务」，这些任务上 MixUA 比无记忆高 10.1 点（$p<10^{-7}$），单一全局记忆只高 5.5 点，而且差距随轮次拉大。偏好保留第 8 轮还有 76%，仅 Pair 从 87% 降到 44%，作者推测是偏好条目和 1.7k 条任务条目挤同一个预算。

### 是不是只是塞了更多上下文？

| 每作用域预算 | 每任务上下文（k 字符） | Δ（pp） | 留出集偏好保留 |
| --- | --- | --- | --- |
| 1k | 5.7 | +8.4 | 60.3 |
| 10k | 22.8 | +13.1 | 78.0 |
| 20k | 37.8 | +14.0 | 87.3 |
| 40k | 61.4 | +16.3 | 90.9 |
| 仅 Global（40k） | 39.7 | +11.5 | – |

10k 每作用域时 MixUA 每任务只用 22.8k 字符，不到仅 Global 的 60%，仍然多涨（13.1 对 11.5）。换成文件 grep 的方式涨了 14.5 点，但 agent 轮数从 13.9 升到 17.0，偏好保留从 90% 降到 75%。

## 🔬 最有意思的部分

**去掉 Agent 和 Pair 在主基准上几乎看不出影响，但专门的探针一测就露馅。** 从 MixUA 里一次去掉一个作用域：去掉 Global 时 Δ 从 15.3 跌到 9.0、Δcross 从 13.0 跌到 4.6；去掉 User 时偏好保留从 90% 降到 81%；去掉 Agent 或 Pair 变化很小。于是作者构造了作用域探针：当每个 agent 都需要自己的构建模式、每个作用域的预算只够放一条时，去掉 Agent 让通过率从 89% 掉到 40%，串到别的 agent 模式的比例从 44% 升到 67%；去掉 Pair 后，用户要求只留在某个 agent 的工作上下文泄漏到其他 agent 的比例从 22% 飙到 95%。**主基准平均分会掩盖边界类错误，必须针对性设计探针。**

**留出集上的作用域遮罩证明了条目确实各就其位。** 冻结演化后的存储，在 20 个留出任务上只给 agent 看一个作用域：只看 Global 或只看 Agent 时偏好保留和空库一样（8% 到 12%），说明用户习惯确实住在 User 和 Pair 里；全部作用域在审查后保留 84% 到 90%，接近直接重述偏好的 99%；换成另一个用户的记忆，通过率不变，偏好保留只剩约四分之一。

**一个跨用户跨 agent 迁移的具体样本。** 第 2 轮 Codex-Sol 为用户 u4 解了一道 AutoCodeBench 的 Dart 题，写入器存了一条 Global 经验：文件调用本身就会抛 FileSystemException，它实现了 Dart 的 IOException 接口。这种「库的行为事实」正是最应该放 Global 的东西。

## 🤔 我的判断

定位：**一份把多用户多 agent 共享记忆的「谁能读」问题形式化、并配上联合测效用、偏好、隐私基准的系统工作**，属于测量基础设施加一个可用基线。

亮点三条：

1. 作用域上限由来源流决定而不是写入器自报，隐私边界是结构性的，这比「让 LLM 判断这条要不要共享」更可审计。
2. 条目自带情境和来源（任务、pair、轮次、结果），撤回和删除有落点，论文在伦理部分也点明了这一点。
3. 评测诚实：做了预算对照排除「只是更多上下文」，做了作用域探针补主基准看不见的边界错误，显著性用精确 McNemar 检验。

问题与局限：

- **隐私的第一道闸是一个 LLM 切分器**：受保护流的划分本身靠模型判断，切分器漏判时，可复用流里的私密信息就会进入共享条目。低泄漏率测的是这一套提示加 Opus 5 写入器的组合，不是结构性保证。作者自己也说低泄漏不足以证明可以不加访问控制和隐私审查就部署。
- **写入是串行的**：每轮结束后轨迹一条一条写入，再统一审查。真实部署里多个 agent 同时写同一份存储的并发冲突、写入顺序依赖、审查与写入交错，论文完全没碰。
- **没有对抗写入者**：作者在伦理部分承认没有评估故意写误导经验的贡献者，而共享 Global 记忆恰恰是投毒的理想目标。
- **规模小、用户合成**：5、20、100 个合成用户，7 个 agent，最多 546 个任务 8 轮；作用域只有「一个或全部」，团队、部门这种中间层级的知识无处安放。
- **写入成本**：写入器用 Claude Opus 5。按附录资源表，每次演化运行无记忆的 agent 花费约 154 美元、记忆写入为 0；MixUA（LLM）加审查是 agent 193 美元加记忆写入 1,191 美元，写记忆比干活贵六倍多。存储无限增长时，审查也没法一次读完全库。

对工程的直接启发：给多 agent 共享记忆定格式时，**至少要有作用域字段和来源字段，而且作用域上限由数据来源决定，不由写入方模型决定**；把「判分结果优先于 agent 自述」写进写入规则；评测时别只看平均通过率，要专门造「某作用域缺失」的探针。如果要上真并发，这篇只给了一个串行的上界，锁、版本和冲突合并得自己补。

一句话：共享记忆的难点不是存什么，而是每一条该给谁读；MixUA 给了一个可审计的起点，但隐私和并发都还只是在受控条件下成立。
