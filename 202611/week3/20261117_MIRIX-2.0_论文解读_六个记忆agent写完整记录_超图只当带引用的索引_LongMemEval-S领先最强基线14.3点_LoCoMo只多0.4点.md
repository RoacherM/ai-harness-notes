# 六个记忆 agent 写完整记录，超图只当带引用的索引：MIRIX-2.0 在 LongMemEval-S 上领先最强基线 14.3 点，LoCoMo 上只多 0.4 点；合并只动索引不动证据，失败的图写入永远不回滚已存的记忆

你有没有过这种体验：给 agent 接了一套「会自我整理」的长期记忆，用了两个月，某天问它「我上次去东京是几号」，它答得很自信，日期却是两次行程揉在一起的。翻底层存储才发现，所谓的 consolidation 把两条措辞相近的事件合成了一条摘要，原始记录早被覆盖了。另一种极端是什么都存、从不整理，检索要扫的东西越来越多，越用越慢。论文点名的 Claude Code auto memory 这类文件系统记忆也有类似问题：一个限长的索引文件每次会话都加载，靠一行摘要决定打开哪个笔记文件，摘要没提到的细节只能字符串搜，索引超过上限的条目开局不加载。**记忆系统到底能不能同时做到不丢细节、检索有界、整理安全？**

MIRIX AI 团队的 **MIRIX-2.0: Multi-Agent Memory System** 给出的答案是分层：完整记录存在向量库里当唯一的事实来源，超图只做索引，每一条图上的事实都必须引用它来自哪几行；检索按预算走，整理只改「证据怎么连」，不改「有哪些证据」。看完我最大的感受是：**这是一篇把「记忆 provenance 和整理的不变量」写得最清楚的系统论文之一，但标题级数字要和它自己的局限一起读。**

## 核心摘要

MIRIX-2.0 沿用 MIRIX 的多 agent 设计：一个 Meta Memory Manager 把输入路由给六类记忆的写入 agent（Core、Episodic、Semantic、Procedural、Resource、Knowledge Vault），每个写入者只负责自己类型的 schema 和更新操作。情景和语义记录先提交到向量库，再由一个**保留来源的 n 元超图**索引其中的实体、事件、关系、角色和时间，每个事实帧都带上它引用的行 ID。查询时一个确定性规划器先定操作类型和两条证据通道的预算，检索从与问题匹配的锚点进入图，返回图事实和它们引用的原始行。AutoDream 在写入路径之外运行：对语义记忆只合并重复实体锚点，不重写任何记录；对程序记忆把任务会话提炼成技能，技能编辑可以引用背后的经验，引用只在原文引用核对通过后才记录。结果：LoCoMo 91.4%（作者自跑的 HyperMem 91.0%），LongMemEval-S 72.6%（领先最强基线 14.3 点）；关掉 AutoDream 时 SHDocQA、MHDocQA 分别 83.0% 和 71.0%，比 HyperMem 高 31.0 和 22.0 点；作为程序记忆，ALFWorld（GPT-6 Luna）76.4%、WebShop 37.4%，在对比的记忆方法里均值最高；MetaClaw-Bench（GPT-5.2）49.2%，对比 MetaClaw 技能库报告的 44.0%。作者自己承认：消融是按组件组加的，用户记忆结果都是单次运行，agent 结果三次运行方差很大。

## 🎯 为什么这件事值得写

作者把现有记忆系统的取舍讲得很直白：参数化记忆要训练，用不了闭源模型；整理式记忆可能永久丢细节；全存则要搜的东西越来越多；二元三元组图会把一个 n 元事实拆成碎片。按主题分层的超图记忆和文件系统记忆，都是「自顶向下剪枝来控成本，再用摘要没反映的细节召回率来还账」。

论文还区分了两种用途，引用的研究认为它们面对的挑战方向相反：

- **用户中心记忆**：要宽、要连，因为以后的问题可能依赖历史里任何一个细节。
- **agent 中心记忆**：要精、要提炼，把轨迹浓缩成策略和技能，检索太多反而会把注意力从下一步需要的上下文里拉走。

作者声称就他们所知，MIRIX-2.0 是第一个用一份存储同时服务这两种用途的记忆系统。对我们关心的「多 agent 记忆 provenance」来说，这篇最有价值的不是分数，而是它明确写下了**无论模型怎么表现都成立的不变量**，以及哪些决策交给模型、哪些必须由确定性代码掌控。

## 🏗️ 机制：存储和索引分开，三条路径各管一摊

### 三个技术要求

1. **来源保真**：具体证据在写入后、整理后都能找回。
2. **有界访问**：一个查询只检查一小块图邻域和有限的被引用行，不扫全量历史。
3. **时间身份**：同一事件的重复描述可以共享证据，但不同的发生不能只因措辞相似就合并。

### 写入路径：先提交，再索引

Meta Memory Manager 选出要更新的记忆类型，每个被选中的写入者读当前存储生成一条记录。情景和语义记录的形式是 $m=(i,k,y,\tau_e,\tau_m,\rho,z)$：不可变行 ID、类型、文本、事件时间、提及时间、来源与分块 provenance、检索向量。写入者的提示要求保留完整列表、名字、数量、标题、地点和日期，不要换成主题概括；情景写入者存事件发生的时间而不是被提及的时间，计划中的事件带计划日期。

**向量库写入在图构建之前提交**，图抽取是一个 fail-soft 的索引钩子：图写入失败只记日志，绝不回滚已存的记忆。只有情景和语义记录进超图，其余四类走各自的类型化检索路径；敏感的原文值放在 Knowledge Vault 里，超图不索引。

### 超图：锚点、n 元帧、发生身份

- **锚点**存规范名、实体类型、名字向量，以及提到它的情景行和语义行 ID。一个确定性键把大小写、标点、虚词、词序、单复数归一但保留数字；确定性准入门拒绝泛化的归档词和对话角色伪实体，每条记录准入的锚点有上限（情景 16、语义 18）。
- **规范化**：对每个抽取出的实体做近邻检索找已有锚点，一条记录一次模型调用做保守的同实体判断。**只有选中一个被检索出的候选时才接受重命名，向量只负责提出比较，永远不能单独授权合并。**
- **n 元帧** $f=(p,\{(r_j,a_j)\},\ell_f,\tau_e,\tau_m,C_f)$：谓词、开放词表角色与锚点、字面属性、时间、引用的行 ID 集合。一次航班是一个帧，带出发地、目的地、承运人、同伴等多个角色臂，而不是几条互不相连的三元组。日期、价格、数量、时长作为字面量挂在帧上。至少解析出两个不同锚点才实体化。确定性审计发现漏抽高信号细节时，允许一次有界的修复调用补帧，但不能删除主抽取产出的任何东西。
- **发生身份**：语义帧 ID 是哈希(用户, 谓词, 排序后的角色锚点键)，同一持久事实的重复支持累积在一个节点上；情景帧再加一个发生键，有显式事件时间就用时间，没有就用不可变的记忆 ID。于是同一个有日期的事件的两次提及共享一个帧，而两个措辞相近、没有日期的事件（比如不同日子的两次跑步）保持分开。

### 读取路径：图负责选，向量库只负责取

情景和语义候选**必须从图进入**，向量库只解引用和重排图遍历选中的 ID。作者说这条边界是为了防止一个隐藏的全表搜索替图干了活。只有图读取报错才回退到直接证据检索。

- **规划器**是确定性的，把问题映射到五种操作之一：single、temporal、intersection、list-union、count，并设两个预算，基础召回行数和关系引用行数。单值查询是 6 和 4，计数是 8 和 12。
- **锚点进入**：先按名字向量召回 15 个锚点，加上问题里精确点名的锚点，打分里向量分占主导，精确匹配、词重叠、谓词兼容、多词特异性打破平局，对数度惩罚压制通用枢纽。
- **两条通道**：基础召回通道从锚点直接拿关联行，穿过关联帧再拿帧的引用行和一部分共同参与者的行；关系引用通道在问题含关系时开启，过滤谓词后最多 240 个帧，按九项加性分排序，最多渲染预算数量的图事实。
- **融合**：先取引用行，再取基础行，余量从两通道补，行 ID 不重复。返回的证据同时包含图事实和为它们背书的原始行。
- **答题时校验**（在评测 harness 里，不在记忆服务里）：答题 agent 最多调用 5 次检索；初稿出现显式不确定、计数没有数字或与列出的数量不一致、时间题没给时间、答案里的数字或月份既不在证据账本也不在问题里、计划中的事件被计进计数题时，触发一次额外搜索加一次重写；所有交集题都触发。这个检查**从不看参考答案**。

### AutoDream：整理只改连接，不改证据

**语义侧**是一个从不自我调度的显式服务调用，契约是 $\text{Dream}(P_u,G_u;\Delta_u)=(P_u,\tilde G_u)$：证据库原样返回。只考虑新写入语义行背后、属于人、组织、地点、物体、概念这五种身份稳定类型的锚点；事件、日期、内容、方法等类型故意排除，因为合并它们可能把不同的发生或时间上下文压在一起。每个锚点取 4 个最近邻，余弦不低于 0.86 且同类型才成为候选对，由 LLM 判断是否同一实体，输出只能是提交的那一对里的名字，编造的代表名会被拒。合并时行 ID 取并集、别名保留、提及数相加、准入分取最大，所有帧臂改指向保留者；并、加、取最大都满足交换律和结合律，所以合并顺序不改变可达证据。每轮最多验证 80 个新对，最后一轮 120 个，如有合并再做一轮最多 60 个的修复；显式否决会缓存，以后不再付费重判，没轮到的对不算否决。

**程序侧**在攒够 5 个待处理会话后在后台启动。distiller 依据转录里的引用判断每个会话的结果，引用在转录里找不到的结果降级为「不明确」；提炼出「值得复用的经验」和「值得避免的错误」，curator 据此创建、编辑或删除技能，也可以把经验标记为已覆盖、不值得成技能或延后。技能编辑可以引用背后的经验并附上新增文字的原文，**只有原文核对通过才记录引用**，所以技能里一个被引用的步骤能一路追溯到具体会话。

### 四条硬不变量

附录 A.6 写明，无论模型怎么表现都成立：

1. 每条返回的图事实都暴露其来源记忆的 ID。
2. 来自不同记忆行、没有日期的情景发生，拿到不同的帧身份。
3. 检索和 Dream 都在显式的候选上限和输出上限下运行。
4. 失败的图写入不能销毁已提交的记忆，报错的图读取回退到直接证据检索。

模型负责路由、写入、抽取帧、修复漏抽、判断同实体、提炼和整理程序经验；**确定性代码掌控安全关键边界**：可准入的锚点名、候选白名单、帧身份、事件及其状态的表示、provenance 挂载、查询操作、通道预算、合并代数、变更顺序。作者的例子：LLM 可以提议两个锚点相同，但它不能指定候选集之外的锚点，也不能直接删除证据。

## 🧪 关键证据

### 实验设置

用户记忆评测：答题和抽取用 gpt-4.1-mini（温度 0，种子 42），主题抽取用 gpt-4.1-nano，向量用 text-embedding-3-small；LoCoMo 和 LongMemEval-S 用 gpt-4o-mini 裁判三票多数；文档 QA 用子串匹配和字母精确匹配。配置分三档：M0 是无图无 AutoDream 的扁平向量记忆（相当于 MIRIX-1.0），M1 加图但关 AutoDream，M2 全开（摄入时每 5 个分块调用一次语义 AutoDream，最后再一次）。

### LoCoMo（1,540 个非对抗问题）

| 方法 | 总体 | 多跳 | 时间 | 开放域 | 单跳 |
| --- | --- | --- | --- | --- | --- |
| mem0 | 82.9 | 80.5 | 80.4 | 66.7 | 86.6 |
| HyperMem | 91.0 | 91.1 | 84.4 | 76.0 | 95.2 |
| M0（扁平） | 85.7 | 83.3 | 85.0 | 70.8 | 88.3 |
| M1（+图） | 88.4 | 89.0 | 86.0 | 71.9 | 91.1 |
| M2（+图+Dream） | 91.4 | 91.8 | 89.4 | 74.0 | 94.1 |

从 M0 到 M1 多跳涨 5.7 点、时间只涨 1.0 点；从 M1 到 M2 每一类都涨，时间题涨 3.4 点。对 HyperMem 只领先 0.4 点，优势集中在时间（+5.0）和多跳（+0.7），HyperMem 在开放域和单跳上更高。作者特别注明：HyperMem 的 91.0% 是他们按原设置自跑的结果，低于 HyperMem 自报的 92.7%。

### LongMemEval-S 与文档 QA

LongMemEval-S 上 M0、M1、M2 分别 58.8%、70.0%、72.6%，**图本身贡献 11.2 点**，AutoDream 再加 2.6 点，领先最强基线 14.3 点。但作者说手上没有分类别结果，说不清哪类问题贡献了这部分增益。

文档 QA 只有 M1：SHDocQA 83.0%、MHDocQA 71.0%，比 HyperMem 高 31.0 和 22.0 点。DetectiveQA 是反例：M1 64.8%，低于 MemoryBank 67.6% 和 HyperMem 66.2%；作者说没有错误分析就分不清是证据漏召回还是推理失败。MemoryCD 跨域评论摘要上四个指标都最高（ROUGE-L 0.1510 对最强基线 0.1430，BLEU-4 0.0209 对 0.0162），但记录里没写是哪个配置，所以不能据此说图或 AutoDream 有贡献。

### 程序记忆：held-out 任务

ALFWorld 39 个训练任务、WebShop 40 个，学完后冻结记忆，在 134 个 ALFWorld 留出回合（50 步上限）和 140 个 WebShop 指令（15 步上限）上评测，三次运行平均：

| 基准 | 方法 | 训练 token（M） | 测试 token（M） | 成功率 |
| --- | --- | --- | --- | --- |
| ALFWorld | 无记忆 | 0 | 2.147 | 69.4±0.7 |
| ALFWorld | ReasoningBank | 1.747 | 3.351 | 66.9±2.8 |
| ALFWorld | AWM | 2.749 | 3.674 | 73.6±1.9 |
| ALFWorld | MIRIX-2.0 | 2.253 | 3.813 | 76.4±6.2 |
| WebShop | 无记忆 | 0 | 4.238 | 31.9±1.8 |
| WebShop | ReasoningBank | 2.010 | 6.620 | 25.7±3.8 |
| WebShop | AWM | 1.909 | 5.448 | 36.0±4.3 |
| WebShop | MIRIX-2.0 | 1.815 | 4.975 | 37.4±2.1 |

（均为 GPT-6 Luna；GPT-5.6 Luna 上 ALFWorld 为 61.7%，对比无记忆 54.2%、AWM 58.0%。）作者自己说：MIRIX-2.0 在两个骨干上的标准差是 6.2 和 14.0 点，**三次运行不足以确立对 AWM 的稳定优势**。按任务类型看，Clean 从 60.2% 到 74.2%，Heat 从 47.8% 到 73.9%，Pick、Look、Pick Two 反而低于无记忆，作者的解释是检索到的流程可能干扰 actor 本来就会的任务。ReasoningBank 在两个交互基准上都低于无记忆，说明「加经验记忆」本身不保证变好。

### MetaClaw-Bench Part I（346 题，跨 30 天）

GPT-5.2：基线 41.1%，MetaClaw 技能 44.0%，MIRIX-2.0 49.2%；224 道文件检查题的完成率 14.7%、17.1%、27.7%。Qwen3.6-35B-A3B：40.3%、51.8%、52.7%，完成率后两者都是 30.8%。作者注明 GPT-5.2 的两个基线是 MetaClaw 论文报告值，不是受控重跑，也没有方差和程序组件消融。

### 成本

关掉 AutoDream 时，M1 在五个计时基准上答题都比 HyperMem 快（SHDocQA 5.45 秒对 10.55 秒，MHDocQA 9.01 对 10.65，DetectiveQA 7.24 对 13.05），对话基准的摄入时间也更短。代价在长文档摄入：相对 M0，M1 的文档摄入时间是 3.8 到 4.0 倍，答题延迟也比 M0 高，作者明说图检索并不天然比扁平检索便宜。DetectiveQA 上 M1 答题 token 1.16M，HyperMem 0.35M。**带 AutoDream 的完整系统没有计时**，检索上界管的是一个问题检查的证据量，不是随历史增长测得的延迟。

## 🔬 最有意思的部分

**「图只是索引」这一句话，决定了一整套失败语义。** 先提交再索引、图写入失败不回滚、图读取报错回退直接检索，这三条放在一起，意味着索引层出任何问题都不会损失事实层。很多记忆系统把图当主存储，抽取一出错就是数据丢失；MIRIX-2.0 把图降级成可以重建的派生物。

**用发生键防止事件被合并，是一个很便宜但很关键的设计。** 有显式时间用时间，没有时间就用不可变的行 ID，于是两次没写日期的跑步永远是两次。整理阶段又把事件、日期类锚点整个排除在合并候选之外。「措辞相似不等于同一件事」被同时写进了身份函数和整理规则。

**模型只能「提议」，确定性代码负责「授权」。** 同实体判断只能在检索出的候选里选，Dream 的输出只能是提交的那一对里的名字，技能引用只有原文核对通过才记录，distiller 的结果引用找不到就降级。这和我们在 agent 安全里说的「LLM 出主意、确定性门做决定」是同一个模式，只是这里用在了记忆写入上。

**连作者都在主动泼冷水。** 正文里反复出现「这是对聚合结果的解释，要确立机制需要直接审计检索记录和合并锚点」「三次运行不足以确立稳定优势」「文档结果不能证明 AutoDream 有用」。一篇系统论文这么写局限，值得点赞。

## 🤔 我的判断

定位：**一个工程上很考究的记忆系统，provenance 和整理不变量是真正的贡献；标题里的 SOTA 在不同基准上强弱差异很大。** 它适合当「多 agent 共享记忆该满足哪些硬约束」的参考实现来读。

亮点三条：

1. **存储与索引分离，加上四条硬不变量**，把「记忆不会因为整理或索引失败而丢」从口号变成了可以检查的属性。
2. **整理只改连接、不改证据**，合并代数满足交换律和结合律，合并顺序无关，这对并发或分批整理很友好。
3. **用户记忆和程序记忆一套存储**，程序侧的技能编辑也带可核对的引用，把 provenance 延伸到了技能库。

问题与局限：

- **消融粒度粗**：作者自己承认没有分别隔离 n 元帧、引用行、发生身份、答题时校验，以及程序记忆里的裁判、distiller、curator，所以第三节里的组件解释都只是解释。
- **统计强度弱**：用户记忆结果都是单次运行、部分由 LLM 裁判打分；agent 结果三次运行方差大；部分基线是作者自报值。LoCoMo 上对 HyperMem 只多 0.4 点，而且 HyperMem 是自跑的低于自报值。
- **没测的东西很多**：合并精度、源细节保留率、技能 provenance 覆盖率、六写入者路由策略的贡献、记忆长度、用户记忆摄入 token，正文明确说都没量。
- **完整系统没计时**：效率结论都来自关掉 AutoDream 的 M1。
- **「多 agent」指的是内部六个写入者，不是多个外部 agent 共享一份记忆**。论文没有讨论多个独立 agent 并发写同一用户存储时的冲突、权限和投毒问题；伦理部分也只说部署应让用户查看、修改、删除记忆，并按用户隔离，这些不由系统本身保证。

对工程的直接启发：如果你在给 always-on agent 或多 agent 系统做共享记忆，可以直接借三条。第一，原始记录是唯一事实来源，任何摘要、图、索引都是可重建的派生物，派生层写入失败不能回滚事实层。第二，事件身份里加发生键，没有时间就用不可变 ID，整理时对事件类实体一律不合并。第三，所有「两个东西是不是一个」的模型判断，都只能在确定性代码给出的候选集里选，输出越界就拒。

一句话：记忆系统最值钱的不是多答对几道题，而是保证整理和索引永远不会悄悄改写你记过的事；MIRIX-2.0 把这条保证写成了四条不变量，分数部分则要打个折看。
