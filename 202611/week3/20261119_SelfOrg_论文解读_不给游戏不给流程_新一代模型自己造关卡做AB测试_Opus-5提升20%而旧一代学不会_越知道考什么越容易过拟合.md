# 不给游戏、不给训练流程，只给读写、Bash 和一个「看别人试玩」的工具：新一代模型会自己造关卡、做 A/B 测试、写回归集，Opus-5 在 PuzzleScript 上提升 20%，旧一代模型学不会；而越清楚考什么，越容易过拟合

现在的自我改进方法，几乎都由人来规定流程：GEPA 规定怎么反思轨迹、怎么做进化搜索，ACE 规定怎么维护 playbook，Meta-Harness 规定候选怎么评估，异构自博弈规定老师怎么出题、怎么采样、怎么更新。模型负责的只是流程里的某个环节。**可如果模型已经足够强，我们还有必要告诉它「该怎么自我改进」吗？给它一台空电脑、一个目标、一点预算，它会不会自己设计出一套像样的学习方法？如果会，它学到的东西能不能迁移到没见过的任务上？**

MIT CSAIL 和图宾根大学的 **Do LLM Agents Still Need to Be Told How to Self-Improve?** 用游戏做试验场来回答这个问题。看完我的感受是：**这篇最有价值的不是「强模型能自我改进」这个结论，而是它把自我改进的「元能力」当成一个随模型代际变化的量来测，并且把「老师知道多少考试信息」和「过拟合」之间的关系做成了可控实验。**对于关心 harness 自进化、关心 agent 会不会对评测环境过拟合的人，后者尤其值得看。

## 核心摘要

设定是老师和玩家：同一个冻结权重的模型，一个实例当老师，另一个实例当玩家。老师运行在一个精简过的持久 harness 会话里（Claude 模型用 Claude Code，其他模型用 Pi），默认系统提示、自动记忆、联网搜索、子 agent 等全部关闭，只给 Read/Write、Bash 和一个 Gameplay 工具。Gameplay 工具接收老师写的游戏源文件（主实验用 PuzzleScript，一种 2D 网格解谜游戏语言）和可选的玩家文本目录，在一个全新的外部玩家会话里跑这个游戏，返回分数和完整记录。老师的目标是改写玩家的文本上下文（提示词、技能文件等），让玩家在**没见过的**游戏上表现更好。**不给任何真实游戏，也不规定学习流程。**预算分两部分：最多 20 次更新（每次对玩家目录的一次编辑调用算一次），最多 150 次试玩。评测用四个由近到远的外部基准：PuzzleScript-t20（20 关，最优解长度不超过 12，20 回合）、PuzzleScript-t30（20 关，解长 13 到 22，30 回合）、ARC-AGI-3 第一关、MazeBench（3D 等距 ASCII 投影的寻宝导航，16 个房间，100 回合）。主要结论：Claude Opus-5、GPT 6-Astra、GLM 5.3 这三个较新的模型在 PuzzleScript-t20 上分别提升 20%、10%、6%，而 Claude Opus-4.6、GPT 5.6-Sol、GLM 4.7 这些较老的代际几乎没有提升；Opus-5 自组织学习的效果与 GEPA 在 20 关真实游戏上做规定流程优化相当；学到的文本迁移到 PuzzleScript-t30 提升 9%、ARC-AGI-L1 提升 21%、MazeBench SPL 提升 0.15；文本还能跨模型使用，GPT 6-Astra 学到的文本让 Opus-5 在 PuzzleScript-t20 上从 25.4% 提到 47.5%。与此同时，老师越了解评测设置，生成的练习越贴近，但也越容易专门化。这篇的价值定位是：自我改进的「元能力」可以被测量，并且在代际之间明显上升；而控制老师掌握多少评测信息，本身就是防过拟合的一个旋钮。

## 🎯 为什么这件事值得写

作者在相关工作里按「学习过程中哪些部分仍由外部规定」把自我改进方法排了一遍：

| 方法族 | 自己生成什么 | 仍由外部规定什么 |
| --- | --- | --- |
| 异构自博弈 | 学生的题目 | 更新节奏、老师奖励、每批采样数，以及防崩溃的裁判或真实难题锚点 |
| 上下文和 harness 优化（GEPA、ACE、MCE、Meta-Harness） | 提示词、playbook、harness 代码 | 任务分布、候选评估目标 |
| 自修改 agent（Darwin Gödel Machine、Hyperagents） | agent 代码乃至元层改进流程 | 任务和评测设置 |
| 本文 | 练习任务、学习流程、评估方法 | 只有目标、工具、预算 |

每往下一行，模型控制的部分就多一些。本文走到了很靠下的位置：**题是自己出的，流程是自己定的，进度怎么测也是自己决定的**，外部只在最后用没见过的基准打分。

这件事有两层意义。一是能力层面：如果强模型可以自己搭学习回路，那人为设计的自我改进流程可能会像深度学习里很多人工归纳偏置一样被逐渐淘汰。二是安全层面：作者在讨论里写得很直白，自组织改进不是「等着被发现」的能力，它已经在受控环境里出现了，随着能力增强，需要科学地理解和刻画它。

## 🏗️ 机制：老师、玩家、两个预算

### 老师和玩家

玩家上下文 $c=(c_P, c_L)$，$c_P$ 是玩家提示词，$c_L$ 是辅助文本文件。老师是同一模型的另一个实例，负责修改 $c$。自我改进量定义为 $J(c_{final})-J(c_0)>0$，其中 $J$ 是玩家在未见测试集上的平均奖励，每局用全新的玩家会话。

选择在文本空间而非权重空间优化，作者给了三个理由：可以研究闭源模型；老师可以反思玩家的轨迹，动态决定是出题、收集经验还是更新知识；更新本身是可读的，玩家行为为什么变了有据可查。

### 老师的环境

| 项目 | 设置 |
| --- | --- |
| harness | Claude 模型用 Claude Code v2.1.232，其他模型通过 OpenRouter 用 Pi v0.85.1 |
| 容器 | Singularity 容器，全新沙箱目录，挂载为 /workspace |
| 关闭的功能 | 默认系统提示（替换为作者的）、联网搜索与抓取、子 agent、任务管理工具、所有扩展和技能、自动记忆、人类交互 |
| 工具 | Read/Write（含 Edit、Glob、Grep）、Bash、Gameplay，按白名单授予 |
| 初始文件 | player_folder（含默认玩家提示词）、PuzzleScript 文档或 Python 游戏接口说明 |

Gameplay 工具会拒绝不能编译、或经 BFS 求解器证明无法获胜的 PuzzleScript 游戏（求解超时则放行）；Python 游戏另做网络访问、文件访问等安全检查。玩家会话只有 Read 和 Glob。返回给老师的是：玩家得分、结束原因（回合耗尽、token 耗尽或获胜）、预算余量，以及一份包含玩家推理、动作和观测的记录路径。

老师的系统提示给两个目标：主目标是通过写文本提升玩家在单人游戏上的表现；泛化目标是这些文本要对机制或任务不同的新游戏也有用。**不规定文本怎么组织，也不规定怎么用预算。**两个预算任一用完，会话结束；老师没用完就停下时，会被提示继续。

### 实验规模

六个模型、三个家族：Claude Opus-4.6 和 Opus-5，GPT 5.6-Sol 和 6-Astra，GLM-4.7 和 5.3。老师和玩家都用低推理强度，每轮输出上限 20k token。每个模型跑三个独立老师会话。

## 🧪 关键证据

### 代际差异：新模型会自学，老模型不会

在 PuzzleScript-t20 上，三个较新的模型相对默认上下文玩家都有提升：Claude Opus-5 提升 20%，GPT 6-Astra 提升 10%，GLM 5.3 提升 6%（论文以百分比表述）。较老的代际几乎没有提升。作者据此提出的核心观点是：**关键不是某一代 agent 能自我改进，而是这种元能力在代际之间变强。**

### 与规定流程的对照

在匹配试玩预算下，Opus-5 在无数据设定中的自组织学习，在 PuzzleScript-t20 上的效果与 GEPA 相当；而 GEPA 是在 20 关真实的同分布 PuzzleScript 游戏（10 关训练、10 关验证，且与测试集不共享基础游戏）上做规定的提示词优化。作者把这个结果定位为「标定上下文优化能带来多大增益」的参照。

### 迁移

| 基准 | 与训练设定的距离 | Opus-5 学到的文本带来的变化 |
| --- | --- | --- |
| PuzzleScript-t20 | 同引擎、同回合数 | +20% |
| PuzzleScript-t30 | 同引擎、更长解长和回合数 | +9% |
| ARC-AGI-L1 | 不同 2D 引擎和表示 | +21% |
| MazeBench | 3D 导航、等距 ASCII、更长回合 | SPL +0.15 |

### 工具消融：自己生成的经验确实有用

| 老师工具 | 结果 |
| --- | --- |
| 只有 Read/Write | 优于基线，说明有一部分提升来自老师对已有知识的反思；但在 MazeBench 以外的基准上，恢复不到 Gameplay 老师增益的一半 |
| 加 Bash | 优于只读写，但仍追不上有独立试玩工具的设置；其中一个会话在提示里完全没提试玩的情况下，自己写了命令行游戏模拟器来测试自己的建议 |
| Gameplay（30 回合 PuzzleScript） | 所有基准上最好，甚至在 PuzzleScript-t20 上也超过了按 t20 约束训练的设置 |
| Gameplay（Python 游戏） | 4 个对比里有 3 个基本恢复了 PuzzleScript 试玩的全部增益 |

### 跨模型迁移

| 玩家 | 文本来源 | 胜率（%） |
| --- | --- | --- |
| Opus 5 | 无 | 25.4 ± 3.6 |
| Opus 5 | GPT-6 Astra 学到的 | 47.5 ± 4.5 |
| GPT-6 Astra | 无 | 67.1 ± 3.8 |
| GPT-6 Astra | Opus 5 学到的 | 72.1 ± 4.0 |

文本双向可迁移，包括从基线更低的 Opus 5 迁到基线更高的 GPT-6 Astra。

### 没有把会的弄丢

作者挑了 10 个基线 Opus-5 玩家 8 次全胜的关卡，用三个 Opus-5 老师会话的最终文本重测：整体胜率 98.8%，只有 Philosophy（L61）降到 91.7% 和 Sokofun Clone（L0）降到 95.8%，其余都保持 100%。

### 老师看到的提升是真的吗

对 Opus-5 三个会话里每一对「更新加生成游戏」，作者用更新前后的文本各跑 8 次独立玩家 rollout。结论是对大多数自生成游戏，更新后表现确实提高，老师观察到的提升与实测提升在平均意义上相关。这一步很重要：它排除了「老师只是在自己的小样本里看到了噪声就以为进步了」这种自欺。

## 🔬 最有意思的部分

### 自学者用的是可辨认的学习策略

作者从两个角度刻画会自学的模型做了什么：

**可直接计数的行为**：会自学的模型更常把同一个游戏在有文本和无文本两种条件下各跑一次（A/B 测试），生成的平凡游戏（最优解长度小于 5 且老师观察胜率 100%）更少，生成的游戏最优解更长。Opus-5 和 GPT 6-Astra 的一些会话自己写了程序化关卡生成器，并用 BFS 求解器把关卡难度校准到更长的解长。

**任务选择**：大多数生成的游戏都很简单，但会很快被丢弃；100% 胜率的游戏很少被重玩，胜率低于 50% 的游戏重玩率更高。Opus-5 和 GLM 5.3 的重玩集中在观察胜率 20% 到 60% 的游戏上，一些 agent 呈现出倒 U 形，类似异构自博弈和无监督环境设计里鼓励中等难度任务的「可学性」奖励，而这完全没有被引导。

**自我调节学习对齐**：作者把 Zimmerman 的自我调节学习循环（前瞻、执行、反思三阶段）改写成 13 个子过程的行为评分细则，每项 0 到 3 分，用 GPT 6-Astra 当裁判。会自学的模型在多数子过程上得分更高。论文给的 Opus-5 片段里，老师写了随机关卡生成器和 BFS 求解器过滤难度，用 A/B 测试定位文本在哪些地方有用；还专门设计了一个对抗性游戏来压测自己的建议，并在早先的游戏上跑验证集找回退。

附录 E.1 的 GPT 6-Astra 片段很有画面感：它把自己的文本版本叫 v6、v7、v8，发现「模型稳定性不是单调的」，决定对基线做完整样本对比；在剩 44 次试玩时开始考虑「现在的提示可能太长、约束太多」，计划压缩到大约 600 词、5 个明确要点，并确保所有已验证的成功都被保留。这几乎就是一个人类工程师在做消融和回归测试。

### 越知道考什么，越容易专门化

这是我认为最值得 harness 进化研究者关注的部分。论文并没有给老师外部任务或验证反馈，但评测设置的信息可以通过两条渠道漏给老师：

- **通过上下文**：用 Python 试玩工具（这样提示词是唯一的游戏语义来源），给老师 0、234、659、1519、3313、6551 token 的 PuzzleScript-Narrow（9 个推箱子风格游戏）摘要。随着摘要变详细，PuzzleScript-Narrow 和 ARC-AGI-3 起初都在提升；到最长的摘要时，PuzzleScript-Narrow 继续涨，ARC-AGI-3 进入平台并略有下降。
- **通过工具**：逐步加工具和约束，从只读写、加 Bash、加不限回合的 PuzzleScript 试玩，到强加 t20 的 token 预算，再到强加 t20 的回合和 token 预算。前面几步 t20 和 t30 都在涨；最后强加与 t20 完全一致的约束后，t20 继续涨而 t30 迁移下降。

作者的结论很朴素：**对评测设置了解越多，老师越会生成相关经验，但也越容易专门化。**放到 harness 自进化的语境里，这就是一个可控的过拟合旋钮：你在优化器的提示词和工具里泄露了多少评测细节，直接决定它学到的是通用策略还是考试技巧。

### 平台期

作者观察到持续修订有收益递减。附录 D.3 加大更新和试玩预算后性能更高，但仍然出现平台。作者把开放问题留在这里：20 次更新能学到这些，100 次、1000 次呢？这可能是模型自我改进能力的上限，也可能是上下文学习本身的上限。

## 🤔 我的判断

定位：**实证研究型论文**。没有提出新方法，贡献在于一个干净的实验设定，以及围绕「谁会自学、怎么自学、学到的能不能迁移、信息泄露如何导致过拟合」的系统测量。

亮点三条：

1. **把自我改进的元能力当成随代际变化的量来测**。同一套极简环境里，新一代会、老一代不会，这比任何单一方法的提升都更能说明趋势。
2. **评测完全外置**。老师从头到尾没见过任何真实游戏，所有提升都是在四个由近到远的外部基准上测的，还补了「已会关卡不退步」和「老师观察到的提升是否真实」两项检查。
3. **信息泄露与过拟合的可控实验**。通过上下文长度和工具约束两个旋钮，展示了「越贴近考试越不泛化」的拐点，对设计任何自我改进或 harness 进化流程都有直接参考价值。

问题与局限：

- **模型家族与 harness 混在一起**：Claude 模型跑在 Claude Code 里，GPT 和 GLM 跑在 Pi 里。虽然都关闭了大部分功能，但工具实现、上下文管理等差异仍可能影响结果，论文没有做同模型换 harness 的对照。
- **每个模型只有三个老师会话**，代际差异的结论样本不大；迁移、消融、跨模型等第 5 节实验基本只用了 Opus-5。
- **主结果以百分比表述，具体数值多在图里**，提升是绝对百分点还是相对百分比，正文没有明确说明。
- **SRL 对齐用 GPT 6-Astra 当裁判**，而它本身是被评估的模型之一，存在同源偏差的可能；作者也承认这些策略与改进之间的因果关系没有拆开，可能还有不那么好辨认的行为在起作用。
- **领域偏置**：游戏有大量关于课程设计和可学任务生成的文献，模型很可能都读过。作者用 Python 游戏消融说明 PuzzleScript 不是关键，但在模型先验更弱的开放领域，结论能否成立未知。
- **规模和时长有限**：低推理强度、20 次更新、简单解谜任务，并且已经出现平台期。

对工程的直接启发：第一，做 harness 或提示词自进化时，可以先试试「只给目标、工具和预算」的极简设置作为基线，强模型可能不需要你精心设计的循环。第二，给优化器暴露多少评测细节要当成一个显式的超参数来管理：评测的回合上限、token 预算、任务语义描述，泄露得越多越容易学成考试技巧，最好保留一个与训练设定刻意不同的远迁移基准来监控。第三，自进化流程里要求优化器自己做 A/B 对照和回归验证集，并像本文一样事后用独立 rollout 核对「它以为的提升」是不是真的。第四，学到的文本产物可以跨模型复用，做模型替换时不妨把旧模型学到的技能文件当作新模型的起点再评估。

一句话：强模型已经不太需要人告诉它怎么自学了，它会自己出题、自己对照、自己查回退；人真正需要管的，是它在学习时能看到多少关于考试的信息。
