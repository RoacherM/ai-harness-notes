# 选择器挑出更好技能的概率只有 49.7%，跟抛硬币一样；九篇论文的中位领先 3.4 点，比同一方法跑两次的差距还小；最大的涨幅一句话就能复现，修好评测后从 17.6 点掉到 0.8 点

你有没有过这种体验：照着一篇 agent 自进化论文的方法，在 Terminal-Bench 上跑 GEPA 或者 SkillOpt 这类 prompt、技能、记忆优化，循环里的验证分数一轮比一轮高，曲线很好看。拿最终产物去重新评测，涨幅基本没了。换一个种子再跑一次，得到的技能库和上一次差很多，分数也差几个点。你开始怀疑是自己复现得不对，或者这个基准就是不好进化。行业里管这件事叫 agent evolution（冻结权重，只进化外部产物：prompt、技能、记忆、harness），**但大家默认了一件没人系统验证过的事：评测分数真的能分辨出哪个产物更好吗？**

上海科技大学团队的 **The Resolution Hypothesis: Agent Evolution's Key Is Identifying Improvements** 用 1030 次独立进化运行、超过 210 万条测试轨迹、超过 1000 万次 LLM 调用回答了这个问题：分辨不出来。提议器其实能写出更好的产物，瓶颈在选择。看完我的感受是：**这篇是今年 harness 和技能自进化方向最需要被每个做 RSI 的人读一遍的「测量学」论文，它把「方法 A 比方法 B 好 3 个点」这类结论的地基直接抽掉了。**

## 核心摘要

作者提出「分辨率假说」：agent 进化停滞，不是因为提议器写不出更好的产物，而是因为有噪声的评测无法可靠识别它们。他们用全方差公式把单次观测分数的方差拆成两部分：同一个产物反复评测的评测噪声 $\sigma^2$，以及不同进化运行产出的产物真实质量差异 $\tau^2$。判断一个固定产物比基线好，受 $\sigma^2$ 限制；判断方法 A 比方法 B 好，受 $\tau^2+\sigma^2$ 限制。实验覆盖七个方法（GEPA、SkillOpt-Lite、Trace2Skill、ReasoningBank 四个文本产物方法，HarnessLens、Meta-Harness、AHE 三个 harness 方法）、六个模型（GPT-5.4 nano、GPT-5.6 Luna 和 Terra、DeepSeek-V4-Flash、Kimi-K3、GLM-5.2）、四个基准（ALFWorld、SpreadsheetBench、OfficeQA、Terminal-Bench v2.1）。方法层面：评测噪声标准差在前三个基准是 1.0 到 3.7 点，Terminal-Bench 到 4.5 点，运行间标准差 0 到 12.3 点；超过 60% 的同模型同基准配置对，全运行均值之差小于一次单运行比较的标准差。九篇进化论文 171 个结果的中位领先只有 3.4 点，没有一个报方差估计。要以 80% 功效识别 3.4 点，Terminal-Bench 需要每个方法约 23 次独立运行；单运行结果表在 Terminal-Bench 上只有 33% 的概率选对四个文本方法里真正最好的那个，随机猜是 25%。历史上 10 到 40 点的大涨幅，作者逐条审计后发现一条规则就能复现中位 90% 的涨幅，这条规则通常是迎合只认一种答案格式的评分器，或迎合偏离官方评测的移植版本；把评测修好后，中位涨幅从 17.6 点掉到 0.8 点。候选层面：100 个候选技能里确实有好东西（最好的共享技能比池均值高 8.3 点），但执行分数选择器两两对比只有 49.7% 的概率选对，被接受的候选里 62.1% 其实更差，三种 LLM judge 也都在 45.4% 到 49.0%。循环内涨幅长到 6.9 到 9.0 点，独立重评只有 +0.4 到 -3.2 点。这篇的价值定位是：把 agent 自进化的瓶颈从「提议」挪到「识别」，并给出可操作的诊断工具。

## 🎯 为什么这件事值得写

过去一年，「冻结模型、进化外部产物」几乎成了 agent 自我改进的默认路线：GEPA 进化 prompt，SkillOpt、Trace2Skill 进化技能，ReasoningBank 进化记忆，Meta-Harness、AHE 直接改 harness 代码。论文一篇接一篇宣称超过前作，但从业者看到的是另一幅图：同一个方法在 A 基准有效、在 B 基准无效，排名在不同论文里互换；Terminal-Bench 这类 coding agent 基准上，进化方法屡次被报告「起不来」。

作者的判断是，这些互相矛盾的结论可能来自同一个原因：评测分数被用在两个地方，一是循环内部决定保留哪个候选，二是论文里给方法排名，而这两处都默认分数能分辨出改进。如果这个前提不成立，循环会把噪声当信号累积，论文表格会把运气当方法优势。

这和我们最近几天读的几篇是一条线：PACE 发现多 agent 配置的大部分优势在同预算单 agent 基线下消失，SIM 用十对配对 t 检验证明跨模型 harness 迁移收益，EGE 讨论自我修改该不该留下需要校准过的门。这篇则是把「门为什么需要统计」这件事，从个案做到了全景测量。

## 🏗️ 机制：两种方差，两个层面，三个预测

### 方差分解

对一个进化方法产出的产物 $A$，单次评测分数 $\hat{Y}(A)=Y(A)+\epsilon$，其中 $Y(A)$ 是重复评测的期望（真实质量），$\epsilon$ 是零均值评测噪声。由全方差公式：

$$
\mathrm{Var}(\hat{Y})=\underbrace{\mathbb{E}_{A}[\mathrm{Var}(\hat{Y}\mid A)]}_{\sigma^{2}}+\underbrace{\mathrm{Var}_{A}(\mathbb{E}[\hat{Y}\mid A])}_{\tau^{2}}
$$

关键区分在于：问「这个产物比基线好吗」，只受 $\sigma^2$ 限制；问「方法 A 比方法 B 好吗」，受 $\tau^2+\sigma^2$ 限制，因为每跑一次方法都会抽出一个新产物。而常见做法是「跑一次、评一次」，两种方差混在一起。

识别真实差距 $\Delta$（80% 功效，$\alpha=0.05$）所需的每方法独立运行数：

$$
N\geq 2\cdot\left(\frac{z_{1-\alpha/2}+z_{1-\beta}}{\Delta}\right)^{2}\cdot(\tau^{2}+\sigma^{2})
$$

### 分辨率的定义

作者把评测流水线的「分辨率」定义为它能可靠区分于噪声的最小真实改进。真实改进低于分辨率时，候选选择退化成随机，进化积累不起来。提议决定「有多大的改进可供选择」，分辨率决定「多小的改进还能被认出来」。

### 四组实验

| 实验组 | 内容 | 规模 |
| --- | --- | --- |
| 方差测量 | 七个方法在四个基准上反复进化、反复评测 | 150 个配置，1030 次独立进化运行，超过 210 万条测试轨迹 |
| 涨幅审计 | 十二个基准上的最大已报告涨幅，在原评测和修复评测下重测，其中四个基准重新进化 | 三个模型 |
| 候选池 | 提议池和选择池，各 100 个技能，隔离测提议质量和选择可靠性 | 提议池 10 个训练题生成、10 个不相交测试题评测，每对 16 次 rollout，共 16000 次 |
| 轨迹重评 | SkillOpt-Lite 和 GEPA 各 8 次运行的每个中间产物，每题重评 8 次 | Terminal-Bench |

从假说导出的三个预测：P1 候选池里有真正更好的产物；P2 常见选择机制在识别更好产物上接近随机；P3 每轮的选择错误跨轮累积，造成同方法独立运行间的大差异。

## 🧪 关键证据

### 方法层面：单次报告排不出名次

- 评测噪声标准差 $\sigma$：SpreadsheetBench、OfficeQA、ALFWorld 上 1.0 到 3.7 点，Terminal-Bench 上 4.5 点；运行间标准差 $\tau$：0 到 12.3 点。合起来，一个方法「进化一次评测一次」的典型分数标准差是 1.7 到 4.1 点（各基准配置的中位数）。
- 超过 60% 的同模型同基准配置对，两者全运行均值之差小于一次单运行比较的标准差；逐方法看，每个方法有 53% 到 79% 的比较落在这个范围内。
- 九篇 agent 进化论文主表的 171 个基准和模型结果里，所提方法领先最强对手的中位数是 3.4 点，四分位距 1.2 到 6.6 点。这些结果没有一个报方差估计，只有 6 个平均了多次进化运行。
- 要以 80% 功效识别 3.4 点：SpreadsheetBench 约 5 次，OfficeQA 约 10 次，ALFWorld 约 19 次，Terminal-Bench 约 23 次；如果差距是下四分位的 1.2 点，Terminal-Bench 需要 181 次。
- 单运行结果表选对四个文本方法里最好那个的概率：前三个基准 51% 到 73%，Terminal-Bench 只有 33%，随机猜是 25%。

### 大涨幅来自评测捷径

SkillOpt-Lite 原论文在 SpreadsheetBench 上对四个 GPT-5 模型报告 36 到 45 点涨幅，在 LiveMathematicianBench 上 20 到 37 点；作者自己的运行也复现出同量级（SpreadsheetBench 29 到 38 点）。这些远超分辨率的涨幅看起来像是「进化终究能找到大改进」的反例，但审计结果正好相反：

- **一句话复现**：逐条审计 GEPA、SkillOpt-Lite 发布的产物和自己进化的产物（LLM agent 先标出候选指令，作者逐条人工核对），只把最可能负责涨幅的那一条规则追加到未进化基线上。在 27 个涨幅超过 3 点的模型和基准对上，这一句话中位能复现 90% 的涨幅。
- **修好评测就没了**：恢复官方评测或改为按语义判分后，用同样的产物重评，中位涨幅从 17.6 点掉到 0.8 点。在修复后的评测下重新进化文本产物方法，涨幅也回不来。

几条具体捷径（论文 Table 9 和 Table 10）：

| 基准 | 评测漏洞 | 那一句规则（节选） | 修复方式 |
| --- | --- | --- | --- |
| SpreadsheetBench | 评分器认字面值不认公式 | 往答案单元格写计算好的字面值，永远别写 Excel 公式 | 用 LibreOffice 重新计算 |
| LiveMathematicianBench | 「可以证明更强结果」这个选项只要出现就是正确答案 | 如果某选项说其余某选项正确但能证明更强结论，选它 | 只评不含该选项的题 |
| OfficeQA | SkillOpt-Lite 发布的版本删掉了官方「只答裸值」的指令 | 答案标签里只放裸值，不带单位和货币符号 | 恢复官方指令和奖励 |
| HotpotQA、SearchQA | 精确匹配拒绝写法不同的正确答案 | 只输出最短答案片段 | 语义判分 |
| AIME 2025 | 解析器只接受裸整数 | 严格按要求格式给最终答案 | 去掉 LaTeX 包装后做等价判断 |

PUPA、ALFWorld、HoVer、IFBench 没找到捷径。ALFWorld 那条规则是一段搜索流程，不是关于评测的。

### 候选层面：好东西存在，但挑不出来

**P1 成立**。提议池里，Quality@K（随机抽 K 个技能、每题保留最好那个的期望成功率）在 2 小时预算下从 K=1 的 49.2% 涨到 K=100 的 61.8%；原始超时下从 39.7% 涨到 51.6%。作者配了「100 个候选真实质量完全相同」的等质量零假设曲线，观测曲线在 K=5 就明显高于零假设，K=100 时领先 3.3 到 3.4 点。单个共享技能在全部 160 次测试 rollout 上的平均成功率跨度超过 15 点：最强的 artifact-063 是 57.5%，池均值 49.2%（+8.3 点），最弱 41.9%。

**P2 成立**。选择池（100 个技能，来自 Terminal-Bench 和 DeepSWE 轨迹，11 个分五档难度的 Terminal-Bench 题），选择器只看第一次 rollout，真实质量用剩余留出 rollout 衡量：

| 选择方式 | 两两准确率 (%) | 错误接受率 (%) |
| --- | --- | --- |
| 随机 | 50.0 ± 0.0 | 30.5 ± 14.0 |
| 执行分数（1 次 rollout） | 49.7 ± 1.9 | 62.1 ± 42.9 |
| SkillOpt-Lite 原生（2 次 rollout） | 48.6 ± 2.6 | 59.4 ± 46.2 |
| GEPA 原生（2 次 rollout） | 48.6 ± 2.6 | 31.6 ± 14.5 |
| LLM judge 逐点 | 45.4 ± 4.5 | 39.9 ± 17.5 |
| LLM judge 两两 | 49.0 ± 2.2 | 57.6 ± 23.3 |
| LLM judge（ACE） | 46.9 ± 3.5 | 39.0 ± 15.6 |

更差的候选占池子的 30.5%，却占执行分数选择器接受候选的 62.1%。单次执行分数和后验产物质量的秩相关只有 0.054。候选预算从 1 加到 100，所有实用选择器的收益曲线都贴着随机基线走平，而 oracle 在 K<5 时就已经超过它们看完 100 个候选后的水平。

**P3 成立**。把 SkillOpt-Lite 和 GEPA 各 8 次运行的每个中间产物在同一验证集上每题重评 8 次：循环内涨幅随轮次长到 6.9 到 9.0 点，独立重评涨幅始终在 +0.4 到 -3.2 点之间。所有运行从同一产物出发（$\tau^2_0=0$），到最后一轮，噪声校正后的运行间方差达到 4.2 到 24.5（平方点）。同一方法两次独立运行之间的差，已经和文献里方法之间的差一样大。

## 🔬 最有意思的部分

**一，「接受比当前分数高的候选」本身就是在挑噪声上尾。** 接受规则拿候选的噪声分数和当前产物的噪声分数比，每一轮都在挑噪声分布上尾的幸运抽样。所以循环内分数一定涨，能力不一定涨。这件事在统计上不新（最优臂识别、PACE 的错误提交分析都谈过），但这篇第一次在 agent 进化上用 16000 次 rollout 的池子把它定量钉死。

**二，LLM judge 不但没救回来，还可能更糟。** 直觉上读完整轨迹的 judge 应该比看一个通过与否的终局分数信息更多。作者的解释是 judge 本身能力有限，它的阅读噪声和评测噪声相互独立，两者叠加而不是抵消。逐点 judge 的两两准确率 45.4%，比随机还低。这对「用 judge 当进化门」的工程做法是很直接的警告。

**三，过程指标的噪声小 13 到 57 倍，但它是诊断不是选择器。** 附录 H 在 DeepSeek-V4-Flash 上比较了终局通过与否和一个过程指标（检查命令里没有被掩盖失败诊断的比例），后者的评测噪声小 13 到 57 倍。「改完文件立刻跑测试」的比例也能看到终局分数看不到的行为变化：Trace2Skill 把它提高 8.73 点（z=2.17），AHE 在 GPT-5.6 Luna 上把它降低 17.98 点（z=-4.19），而这两个变化在同批运行的终局成功率里都检测不到。作者很克制地说明，一个触发更多检查的产物不一定解出更多题，拿过程指标当选择器会面临它自己的分辨率问题。

**四，更强模型并没有自动解决问题。** 在 Terminal-Bench 这种还有大量提升空间的基准上，三个模型的评测噪声中位数都停在 3.5 到 4.0 点；噪声变小主要发生在接近天花板的 ALFWorld，那里本来也没什么空间可涨。

**五，建议是可操作的。** 方法层面把端到端比较拆成两条：提议器用 Quality@K 曲线评，选择器用固定候选池上的「被选产物质量随预算变化」曲线评。端到端一个低于分辨率的比较，拆成两个高于分辨率的比较。报告时同时给 $\hat{\sigma}$ 和 $\hat{\tau}$。

## 🤔 我的判断

定位：**测量基础设施和方法论纠偏**。它不提新的进化算法，而是告诉你现有算法为什么看起来时灵时不灵，以及该怎么评。

亮点三条：

- **规模和设计都对得上问题**。每个方法每个模型每个基准跑 8 次（部分 16 次），每个产物评 8 到 16 次，把 $\sigma$ 和 $\tau$ 分开估，这是这个方向第一次有人把两种方差都量出来。
- **涨幅审计非常狠**。「一句规则复现 90% 涨幅、修评测后 17.6 掉到 0.8」是对整个技能进化文献的一次 benchmark 作弊和配置审计，和前几天 HF Harness Leaderboard 审计 changelog 是同一类工作，只是更系统。
- **候选池隔离实验**。用冻结的 100 候选池把提议和选择拆开测，直接回答了「瓶颈在哪」这个之前只能猜的问题。

问题与局限：

- **候选层面证据只在 Terminal-Bench v2.1 上**，提议池和选择池都只有 100 个技能，轨迹重评只覆盖两个方法两个模型。作者在局限里写明了。
- **只研究冻结权重的进化**。RL 改权重的路线有不同的梯度动力学，结论不一定适用。
- **审计规则是看过产物之后写的**，所以证明的是「一句话足以复现」，不是「涨幅必须靠这句话」。HoVer 的涨幅分散在多个策略里，一句规则测试就失效。
- **程序进化（GPU kernel、ARC-AGI-2 这类确定性打分）不在范围内**，作者认为那类任务因为可以便宜地并行重评确定性代码，结构上噪声更低。
- 论文没给出一个能真正替代终局分数的选择器，只给了诊断工具。「怎么造一个高分辨率的门」仍是开放问题。

对工程的直接启发：

1. 自己的 harness 或技能进化循环里，每个被接受的候选至少要在留出集上重评多次再进主线；单 rollout 的分数比较基本是抛硬币。
2. 论文或内部报告里说「新 harness 比旧的好 3 点」，先算一下 $\tau$ 和 $\sigma$。Terminal-Bench 这类噪声大的基准，单运行 3 点差距没有意义。
3. 进化出来的大涨幅，先做一句规则测试：只把最可疑的那条指令加到基线上，看能复现多少。复现得越多，越该怀疑评分器。
4. 用 LLM judge 当进化门之前，先在一个已知真实质量的候选池上测它的两两准确率。
5. 「改完立刻跑测试」这类过程指标值得加进监控面板，它能看到终局分数看不到的行为漂移，但别直接拿它当接受条件。

一句话：会写更好候选的提议器已经有了，缺的是能把小改进从噪声里认出来的那把尺子；尺子不够细，进化循环就只是在噪声上走随机游走。
