# 同一批 ARC 任务换新输入反复回来：三个现成 harness 开着持久化，都没比「只缓存示范」的笨基线省得多；训权重的 DAgger 在没见过的任务上省下 29%

你有没有过这种体验：给 agent 开了记忆、技能库、后台反思、定时整理，跑了一周，回头看 MEMORY.md 里写满了「先仔细观察输入」「注意边界情况」这类正确但没用的话；同一类活第三次来的时候，它还是从头摸索，连上次花钱买到的例子都没留。行业里把这叫 harness-based continual learning，被当成不训权重也能「越用越熟」的路线。**问题是：在一个模型没有预训练先验的领域里，harness 到底记住了什么？它和真的去改权重比，差多少？**

Unify 的 **Continual-ARC: Measuring Skill Acquisition over a Working Lifetime** 把 ARC 改造成一条终身任务流：同一个任务隔一段时间换一个全新输入回来，新任务不断加入，要示范、答错都要付费，流结束后冻结学习者，分别在见过任务的新实例和完全没见过的任务上测。memory 类和权重类学习者用同一把尺子量。看完我的感受是：**这是一篇对现成 harness 持久化机制非常不客气的测量论文，而且它把每一个失败都追到了 harness 设计里具体的那一步。**

## 核心摘要

每个实例上学习者可以提交答案（只返回对或错，错一次花 1）、买一个示范（花 1，每实例最多 8 个）、或在 harness 里行动；解不出来记满预算 16。ARC-AGI-1 轨道从 400 个训练任务里抽 25 个，用 Re-ARC 生成器供 200 个新鲜实例，同时活跃 4 个任务，一段持续约 3 个实例、休眠约 30 个，约每 4 个实例来一个新任务。分数用「相对 reset 省下的预算份额」：reset 是同一学习者每个实例前清空状态。流结束后两个测试各 100 个实例：见过任务的新实例测记忆（$S_{seen}$），100 个从没出现的评测任务测泛化（$S_{held}$）。主要用 prime-agent 跑 Qwen3.5-9B 和 GLM-5.3 Flash，另用 GPT-6 Luna 跑 prime-agent、hermes-agent、openclaw。结论有三条：现成 harness 按出厂提示词跑，几乎都没比「把买过的示范缓存下来」的基线省得多（demo-cache 的 $S_{seen}$ 是 0.37 和 0.44）；加上「每个任务写程序、用示范验证、存下来复用」的专家指导后，GE 的 $S_{seen}$ 到 0.74，GPT-6 Luna 上三个 harness 到 0.62 到 0.72；但没有任何 harness 方法在未见任务上有可测的收益，而用 DAgger 让 Qwen 模仿 GLM、训 LoRA，$S_{held}=0.29$，两用户和四用户时到 0.40 和 0.39。

## 🎯 为什么这件事值得写

作者认为现有的 agent 持续学习基准有三个问题：

1. **都绑在一个应用领域**（编码、办公），模型在预训练里已经知道很多，涨分可能只是把已有知识激发出来。
2. **大多数实例只出现一次**，同一个概念任务不会带着新输入回来，所以分不清「记住了答案」和「学会了更抽象的技能」。
3. **大多只假设一种学习者**：微调套件测梯度更新，agent 基准测 prompt 和记忆，两者很少在同一把尺子上比。

作者筛了大约两百个基准和方法，列了五个性质：每次暴露都是新实例、隔不定间隔复现、任务集随流增长、二值反馈且要付费、协议对 prompt/记忆/权重开放。他们说没有找到同时具备五条的工作。ARC 的好处是任务只需要核心先验（物体性、计数），规则必须从少量示范里归纳；Chollet 2019 年就提过一个「可以向生成器要例子、反复提交、以消耗的反馈计分」的交互版 ARC，作者说据他们所知此前没有人实现过，这篇就是这个设想的实现。

## 🏗️ 机制：一条付费的流，两个冻结后的测试

### 单个实例的计费

$$c_i=\begin{cases}c_w w_i+c_d d_i & s_i=1\\ C_{max} & s_i=0\end{cases},\qquad C_{max}=c_w w_{max}+c_d d_{max}=16,\qquad u_i=100\,\frac{c_i}{C_{max}}$$

失败记满预算，所以「失败永远不比求助便宜」，示范只有在帮忙解出实例时才算花得值。反馈刻意保持二值，因为失败时返回正确网格就把流变成了监督学习。任务 id 每次都给，但用每次运行随机抽的别名。

### 流

第 $t$ 轮从活跃集合 $A_t$ 里均匀抽任务；进入活跃集合的任务持续 $\beta\sim\text{Exp}(b)$ 个实例，然后休眠 $\rho\sim\text{LogNormal}(\ln m,\sigma)$；新任务每 $\alpha\sim\text{Exp}(a)$ 个实例到达。ARC-AGI-1 上每个任务一共给 8 个实例，最后一个新任务在第 97 轮到达；所有结果用种子 0，所以每个系统看到的任务、顺序、实例都一样。ARC-AGI-2 和 ARC-AGI-3 有各自的生成器，只在附录给了初步结果。

### 只量「学到的」部分

$$L=\frac{U_0(I)-U(I)}{\Lambda},\quad \Lambda=U_0(I)-U^*(I),\qquad S=\frac{U_0(E)-U(E)}{U_0(E)}$$

$U_0$ 是 reset，$U^*$ 是完美记忆（首次暴露付 reset 的钱，之后全免费）。$L$ 把基础能力归一化掉，只量流上学到多少；$S_{seen}$ 量记忆，$S_{held}$ 量泛化。每个测试从流结束时的状态出发玩四遍，reset 也玩四遍，置信区间按任务算。

### 学习者

| 记号 | 是什么 |
| --- | --- |
| C0 / C | 无状态循环 / 额外缓存买过的示范并免费重放（控制「只记住示范」） |
| P | 程序库：让模型写 Python 程序，复现示范就自动存，回来时先跑程序 |
| Q / G | prime-agent 跑 Qwen3.5-9B / GLM-5.3 Flash，每实例新会话，只有写下来的状态能延续 |
| Q0 / G0 | 每个实例前清空 harness 状态 |
| QA / GA | 每次判定后要求「尽量多存」 |
| QE / GE | 加专家指导：每个任务写程序、用示范验证、存下来复用 |
| QT / QTE / QETE | GLM 玩完整条流并写笔记，Qwen 从老师的状态出发玩（上界实验） |
| QDE | DAgger：Qwen 在同一 harness 里，回合之间更新 LoRA，模仿读了专家指导的 GLM |

还有一个集体模式：一个系统同时服务 2 或 4 个用户，每人 25 个互不重叠的任务，所有用户共享同一份笔记和权重，系统只在回合之间更新。

## 🧪 关键证据

### ARC-AGI-1 主表（括号为 95% 区间，节选）

| 方法 | L | $S_{seen}$ | $S_{held}$ |
| --- | --- | --- | --- |
| QC（Qwen 示范缓存） | +0.31 [0.19, 0.45] | +0.37 [0.26, 0.51] | −0.01 [−0.05, 0.03] |
| GC（GLM 示范缓存） | +0.41 [0.29, 0.53] | +0.44 [0.34, 0.57] | −0.02 [−0.11, 0.06] |
| QP（Qwen 程序库） | +0.43 [0.25, 0.64] | +0.65 [0.46, 0.86] | +0.03 [−0.02, 0.09] |
| GP（GLM 程序库） | +0.68 [0.49, 0.87] | +0.81 [0.59, 1.00] | +0.05 [−0.06, 0.14] |
| Q（prime-agent） | −0.02 [−0.09, 0.04] | −0.01 [−0.04, 0.03] | −0.01 [−0.05, 0.03] |
| QE（加专家指导） | +0.05 [−0.06, 0.16] | +0.03 [−0.08, 0.13] | −0.01 [−0.05, 0.03] |
| GE（加专家指导） | +0.62 [0.49, 0.75] | +0.74 [0.64, 0.84] | +0.07 [−0.02, 0.16] |
| QETE（老师带指导写笔记） | +0.29 [0.19, 0.40] | +0.34 [0.26, 0.42] | −0.05 [−0.10, 0.00] |
| QDE（DAgger 训权重） | +0.43 [0.33, 0.54] | +0.57 [0.48, 0.67] | +0.29 [0.23, 0.35] |

几条读法：

- **出厂 harness**：在三个 harness、四个模型、GPT-6 Luna 三档推理强度里，只有 G 在任何一个测试上有可测的节省（三次运行 $S_{seen}=0.25$ [0.17, 0.33]）。尽管每个会话开头都写明了「任务会带新输入复现、每个实例是新对话、每个示范和错答花 1」。Q 和 G 都没赢过各自的示范缓存基线。
- **要求多存**：GPT-6 Luna 驱动时只有 prime-agent 有可测收益（$S_{seen}=0.42$），hermes-agent 0.18 [−0.01, 0.39]、openclaw 0.07 [−0.02, 0.17] 都在噪声里；GLM 0.26，Qwen 0.02。
- **专家指导**：GE 到 0.74，GPT-6 Luna 上三个 harness 到 0.62 到 0.72。作者的结论是 harness 本身有能力做好，失败来自模型判断力不足加上 harness 提示词在这个领域没引导对。
- **小模型吃不进老师的笔记**：QT、QTE 里老师留了 106 和 104 条笔记和文件，Qwen 的 $S_{seen}$ 只在 0.01 到 0.06；只有老师和学生都给了指导（QETE）才到 0.34。

### 泛化：只有权重动了

Re-ARC 的 400 个训练规则都由同一个 160 个原语函数的库组合而来，所以理论上 harness 可以把共享积木抽象出来存住。但没有任何 harness 方法在未见任务上有可测收益，包括 GLM 带指导玩完整条流、写了每个程序和笔记、解了 98% 实例的 QETE。DAgger 则 $S_{held}=0.29$，约为它 $S_{seen}$ 的一半。

还有一个隐藏因素：未训练的 Qwen 在 prime-agent 里反而更差，100 个未见任务只解 18 个，无状态循环能解 31 个。所以 DAgger 学到的一部分只是「怎么驱动这个 harness」。给未训练 Qwen 加专家指导，每遍能解 22 到 33 个；DAgger 解 47 到 52 个，超过两者，作者据此认为它还学到了一些关于 ARC 本身的东西。集体模式下，两用户 $S_{held}=0.40$、四用户 0.39，两用户之后边际收益递减。

## 🔬 最有意思的部分

**每个失败都能指到 harness 里具体的那一行设计。** 作者读了三个 harness 存下来的状态（附录 E）：

- **prime-agent + GPT-6 Luna**：只有 `global_=True` 的条目才进跨会话的全局库，默认都写到会话库，会话结束就丢。600 个会话里全局库一次都没建；而且 prime-agent 的 Python 技能（包括 refine）在这些运行里都没能导入。于是每次复现都打开一句「No saved harness entries yet.」，和无状态方法花一样多的预算。
- **prime-agent + GLM-5.3 Flash**：GLM 确实写了全局库，106 条记忆，25 个任务每个都有文字规则，没有一条是程序。但 harness 每实例开头只列六条，每条截几行，**而且是在任务显示之前选的**。175 次复现里 154 次对应的任务已有条目，摘要只命中了 40 次；命中时平均买 0.88 个示范、花 10.6% 预算、全部解出，没命中的 114 次买 2.11 个、花 23.7%、解出 108 个，和 G0 差不多。作者原话的意思是：省不省钱，是 harness 决定的，不是模型。
- **hermes-agent**：技能几乎每次都加载（175 次复现里 175、175、174 次），但存的是通用方法建议；必须加载技能还挤掉了它自己的代码工具调用（每实例 2.7、1.8、2.0 次，对比无状态时 15.4、13.2、8.4 次）。持久化在任何推理档上都既不省也不亏。
- **openclaw**：每小时一次的 dreaming 整理从来没把任何记忆提升进 MEMORY.md，因为它的门槛要三个召回信号加三次不同查询，而短期库里没有一条超过两个信号。之前答对过的答案，在复现时一次也没回来过。
- **三家都不留示范**：复现时 hermes-agent 和 openclaw 每实例买 2.3 到 3.9 对示范，prime-agent 3.5、2.9、2.8 对，而示范缓存基线只买 2.6、2.0、1.4 对。

**沙箱和代理那段同样值得抄。** 每个 harness 跑在 bubblewrap 里，文件系统只读，基准源码、数据、所有虚拟环境和其他 cell 的运行目录用空 tmpfs 遮住，只有私有状态目录、HOME、TMPDIR 可写；独立 PID 和网络命名空间，唯一出口是一个 UNIX socket 接到本地反向代理，真实凭据只在代理手里，所有请求和计费都记账。即便如此，早期代理对任何路径都转发，开放模型方法里 agent 自己的代码发了 5302 个别的请求，大多是编造的路径，几乎都被拒；除了读模型列表，有 20 个成功了，分布在 5 局里，其中 8 个打到 OpenRouter 的 responses 端点、由它指定的别的模型应答，agent 还向那个模型要任务的示范（那个模型不可能知道），最后靠游戏本身给的示范解出了这一局。作者在正文里也写了「有一个 harness 在早期运行里碰到了评测本身」。发布版代理只转发 chat completions 和模型列表，并强制所有补全走方法指定的模型。外部提交在一台没有公网、不持有规则和密钥的机器上，用作者自己的 50 条私有规则验证，只回传数字。

## 🤔 我的判断

定位：**测量基础设施 + 对现成 harness 持久化的负面结果**。它最大的价值不是「权重赢了」，而是证明了在没有领域先验的地方，harness 的「学习」大部分卡在检索选择、提升门槛、默认写入范围这些工程细节上。

亮点三条：

1. **同一把尺子量 memory 和 weights**：按反馈预算计分、以 reset 归一，见过和没见过的任务分开测，第一次让「harness 学了多少」和「权重学了多少」可以直接比。
2. **一个笨基线就戳破很多叙事**：只缓存买过的示范，就比三个现成 harness 的持久化省得多。
3. **失败归因到设计**：任务显示前就选好的六条摘要、默认写会话库、三信号提升门槛，都是可以直接改的东西。

问题与局限：

- **模型偏小、轨道偏简单**：大部分实验是 9B 和 Flash 档模型在 ARC-AGI-1 上，作者自己说强模型在 ARC-AGI-2、3 上的表现留给以后。
- **单一种子、单一流**：所有结果用种子 0，同一条流。
- **harness 配置有瑕疵**：prime-agent 的 Python 技能在第一轨所有运行里没能导入，openclaw 的记忆搜索没配，找的是沙箱访问不到的 OpenAI embedding。作者都披露了，也发布了适配器让 harness 作者核对，但这确实会影响「出厂表现」的结论强度。
- **DAgger 需要更强老师且读得到推理 token**，不是无老师的持续学习；作者附录里试的策略梯度和自蒸馏没成功。
- **集体模式不测跨用户泄漏**，作者在伦理声明里明确说了。
- 论文声明大部分文字和代码由 Claude 起草或编写，作者逐行审改。

对工程的直接启发：评估一个 harness 的记忆或技能系统时，先跑一个「只缓存原始证据」的笨基线，再跑一个每实例清空状态的 reset，二者都赢不了就别谈学习。检索时机要放在任务已知之后，写入默认范围要和你期望的复用范围一致，任何整理或提升门槛都要能在你的负载下真的触发。另外，代理只转发白名单端点、强制模型，这条在跑任何自写代码的 agent 时都该是默认值。

一句话：harness 记不住东西，往往不是模型不行，而是它存的那条规则在需要的时候没被摆到模型面前；而真想在新任务上变强，目前还得动权重。
