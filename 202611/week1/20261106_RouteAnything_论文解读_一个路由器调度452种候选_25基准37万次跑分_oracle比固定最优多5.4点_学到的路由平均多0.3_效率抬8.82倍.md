# 一个路由器调度一切？NUS Route Anything 用 25 个基准、374,401 次计分、452 种候选画出全模态轨迹矩阵：逐输入 oracle 比固定最优多 5.4 点，学到的路由平均多 0.3、视频生成多 2.1、机器人多 1.1 还少 24% 策略时间；相对参考模型效率平均抬 8.82×

你有没有过这种体验：产品里同时挂着强模型、便宜模型、图像生成器、视频模型和几套机器人策略，每次请求都有人拍脑袋写 if-else；你知道「这题该换人」，却说不清换人的上限在哪、学一个路由器又能吃掉上限的百分之几，更不敢保证省钱的时候质量地板还在。

这就是 **model / policy routing** 从语言模型级联走向通用 AI 系统时卡住的地方。NUS InfRec 这篇 *Route Anything* 的核心问题是：**在质量–成本权衡下，路由器到底值多少，信息观测到哪一层才能拿到那笔钱？** 看完我的感受是：**矩阵本身比任何一个路由器更值钱；它把「oracle 还有 5.4 点」「类型标签只能吃掉约 8%」「要学结果别学冠军标签」和「零损失约束下效率能到 25.5×」放在同一套理论刻度上。**

## 核心摘要

Route Anything 给出统一的路由价值理论：在价格 \(\lambda\) 下最大化 \(\mathbb{E}[V]-\lambda\mathbb{E}[D]\)，并用相对参考策略的质量变化 \(Q\)、节省 \(S\)、效率 \(\eta\) 描述「更便宜是否够好」。信息阶梯界定路由器可及上界：只看基准/类型、看输入内容、直到逐输入 oracle。作者构建全模态轨迹矩阵：25 个基准，覆盖文本与图文理解、图像 / 视频 / 语音生成、代码与职场 agent、机器人操作；452 种候选配置、374,401 次计分。在 19,814 条「池内候选全有分」的测试输入上，逐输入 oracle 比每基准固定最优高 5.38≈5.4 点（语音生成仅 0.68，视频生成 18.93，机器人 18.40）。基于 Qwen3.5-4B 的 capability-tree 路由器在 16 个基准上拿到 79.98，对固定最优 79.68（+0.30），oracle 84.80；视频生成 +2.12，机器人 outcome 路由 71.55 vs 70.45（+1.10）且策略时间 11.05 vs 14.51 秒（−24%）。学「每策略成功」远好于学「谁是赢家」（机器人 71.6% vs 42.8%）。相对参考模型，四类价道路由平均效率 8.82×（代码 25.5×、文本问答 7.1×、图像 1.35×、机器人 1.33×）。价值定位是：一份可复用的全模态路由实验床 + 理论，而不是单一刷分路由器。

## 🎯 为什么这件事值得写

路由文献长期困在「文本模型级联 / 偏好路由器」里。这篇把同一套问题扩到生成模态和机器人策略，有三点超出普通路由论文：

1. **先量天花板，再谈学得会不会。** 5.4 点的 oracle 间隙、类型级只能回收约 8%，直接解释了为什么很多「任务分类再选模型」方案看起来很聪明、实际吃不满。
2. **训练目标比骨干更致命。** 同样输入、同样 4B，学 outcome 与学 winner-label 在机器人上差到 71.6% vs 42.8%；只因延迟平局决定了 94% 的冠军标签。
3. **效率和地板一起谈。** 不是报一个「省了多少钱」，而是用参考相对效率 \(\eta/\eta_B\) 和可认证的质量地板（certified floor）约束「零损失路由」。

对多模型网关、agent 工具路由、机器人策略切换，这是一份可以把争论钉在数字上的基础设施。

## 🏗️ 机制：价值、信息阶梯、三类路由器

### 路由价值

候选 \(u\) 有质量 \(V_u\) 与代价 \(D_u\)（美元或秒）。路由器观测状态 \(s=\sigma(x)\) 后选 \(u\)。价格 \(\lambda\) 下目标为 \(J_\lambda=\mathbb{E}[V]-\lambda\mathbb{E}[D]\)。相对参考 \(B\)：

$$
Q=\mathbb{E}[V_g-Y_B],\quad S=\mathbb{E}[D_B-D_g],\quad \eta=\mathbb{E}[V]/\mathbb{E}[D]
$$

引理：\(\eta-\eta_B=(Q+\eta_B S)/\mathbb{E}[D_g]\)。质量和代价两边都要动，只靠「偶尔对、特别便宜」不够。

### 信息阶梯（可及上界）

| 观测 | 角色 |
| --- | --- |
| 无 / 仅基准 | 固定最优候选（外档下界） |
| 任务类型 / capability leaf | 类型级查找表 |
| 输入内容（文本、图像、相机帧） | 可学习路由器 |
| 逐输入真实最优 | per-input oracle（外档上界） |

### 路由器形态

| 类型 | 做法 |
| --- | --- |
| Outcome router | 对每个（输入, 候选画像）打分，交叉熵拟合归一化结果，选最高分 |
| Type / capability-tree router | 分类到能力树叶子，查训练拟合的「叶子→最佳候选」表；分不出则回退固定最优 |
| Winner-label router | 直接预测「谁该赢」 |

骨干统一为 Qwen3.5-4B；机器人额外吃三帧 240×320 相机与本体状态。语言模型候选含 Claude Opus 5.5、GPT-6.1 Sol、DeepSeek V4.1 Flash，长上下文 / 知识 / agent 任务再加 GPT-6 Astra。

### 数据矩阵规模

| 项 | 数 |
| --- | --- |
| 基准 | 25（潜力表按 24 个「全候选有分」集合汇总） |
| 计分 runs | 374,401 |
| 候选配置 | 452 |
| 测试输入（全候选有分） | 19,814 |
| 划分 | 70/10/20 按 source group；RoboTwin 2,000 测试场景来自训练未见的 10 个任务 |

## 🧪 关键证据

### 潜力：oracle − fixed ≈ 5.4（Table 1）

| 组 | 基准数 | 输入 | Fixed | Oracle | Gap |
| --- | --- | --- | --- | --- | --- |
| Text QA | 7 | 9,482 | 83.27 | 87.56 | 4.28 |
| Image-text QA | 3 | 5,708 | 85.32 | 88.02 | 2.70 |
| Image generation | 5 | 1,515 | 82.93 | 87.92 | 4.99 |
| Video generation | 1 | 158 | 62.43 | 81.36 | 18.93 |
| Speech generation | 2 | 608 | 98.62 | 99.30 | 0.68 |
| Code & workplace agents | 5 | 343 | 69.17 | 77.29 | 8.11 |
| Robot manipulation | 1 | 2,000 | 70.45 | 88.85 | 18.40 |
| **All** | **24** | **19,814** | **82.60** | **87.98** | **5.38** |

事后按基准再挑一次固定候选，只能从 82.60 到 82.62。在 18 个基准、107 个规则叶子的能力树上，叶子级事后最优回收约 **8%** 的间隙；RoboTwin 上按任务×场景条件的事后最优回收 **23%** 的 18.4 点间隙。路由的钱主要埋在类型内部的逐输入差异，而不是「先分个大类」。

### 学到的路由器（Table 3）

| 组 | Inputs | Fixed | Router | Oracle | Router−fixed |
| --- | --- | --- | --- | --- | --- |
| Text QA (3) | 588 | 65.14 | 64.97 | 71.43 | −0.17 |
| Code & workplace (5) | 519 | 69.24 | 70.01 | 74.78 | +0.77 |
| Image generation (5) | 1,559 | 82.96 | 83.21 | 87.92 | +0.25 |
| Video generation (1) | 161 | 62.17 | 64.28 | 80.22 | +2.12 |
| Speech generation (2) | 617 | 98.63 | 98.63 | 99.30 | 0.00 |
| **All 16** | **3,444** | **79.68** | **79.98** | **84.80** | **+0.30** |
| Robot (outcome) | 2,000 | 70.45 | 71.55 | 88.85 | +1.10 |

细节：叶子分类准确率 86–89%，但 83–86% 的输入仍落到固定最优，因为许多基准内部几乎总是同一个候选赢。增益集中在 Terminal-Bench（+8.3 / 36 输入）、VBench-2.0（+2.1）、OneIG（+1.1）、GDP.pdf（+1.0）；最大亏损 AA-LCR（−2.4）。图像生成上 31 种设计、124 个配置，**没有一个**在区间意义上稳定打赢固定生成器。未训练的 Qwen3.5-4B 直接挑候选，反而低 1.15 点。

### 机器人：读场景、省时间

Outcome 路由把 929/1000 干净场景送给 PatchWAM，842/1000 随机化场景送给 ME-Dex。干净场景 81.6%（PatchWAM 81.7，ME-Dex 78.4）；随机化 61.5%（ME-Dex 62.5，PatchWAM 45.6）。总成功 71.55% vs 固定最优 70.45%，策略时间 11.05 vs 14.51 秒（−24%，约 1.33× 每秒成功）。条件级选择 alone 可到 72.1%；剩下到 oracle 的 17% 需要逐场景预判。

### 学 outcome，别学 winner

| 目标 | 机器人成功 |
| --- | --- |
| Outcome regression | 71.6% |
| Best single policy | 70.5% |
| Winner-label classifier | 42.8% |

31,408 次训练成功里，有 24,556 次因为延迟平局被标成「错类」；分类器学会了挑快策略（约 1.9 秒/场景）却经常失败。16 基准上的生成式 winner-label 最好也只到 78.87，低于固定最优 79.44。

### 匹配输入：缺分会翻转结论

11 基准研究里，若固定基线要求「训练输入全有分」才准入，Opus 5.5 因 HLE 缺 11/1,122 等被踢掉，HLE 基线从 58.24 掉到 52.90，AA-Omniscience 从 77.50 到 70.00；池化固定分 68.30→65.52，outcome 路由相对固定的 −0.40 会变成 +2.38。作者强调：**候选比较必须在同一输入集合上**，缺分回退规则要写进协议。

### 价道路由与效率（Table 5）

| 测试床 | 参考 | 路由 | ΔV (points) | \(\eta/\eta_B\) |
| --- | --- | --- | --- | --- |
| CodeRouterBench ($) | Always Opus 4.6 | Fitted \(\epsilon=0\) | −0.44 | **25.5×** |
| 同上 | 同上 | Certified \(\epsilon=0\) | ≥0 @200/200 | 19.4×（中位） |
| RouterBench 文本问答 ($) | Always GPT-4 | Fitted \(\epsilon=0\) | −0.40 | **7.1×** |
| 图像生成 ($) | 固定生成器 | Fitted \(\epsilon=0.5\) | −0.47 | **1.35×** |
| 机器人 (s) | 固定策略 | Outcome router | +1.10 | **1.33×** |

四者平均 **8.82×**。CodeRouterBench 上 Opus 的准入价格低于零损失地板价，于是零损失最优路由按推论 **从不调用 Opus**，把每题派给更便宜模型；总是调用最便宜的 Qwen3-Max 已有 20.1×（质量 −4.2），按状态路由能把质量缺口补回并再加约 27% 效率。拟合地板在 200 次对半重切里只有 12.5% 仍在测试集成立；按命题做认证后 200/200 成立，中位 19.4×。图像侧半点容忍可降本 26%。4B 路由器单次决策约 0.13 秒（一卡 H20），相对图像 27–158 秒、视频 211–314 秒的生成时延可忽略。

## 🔬 最有意思的部分

1. **潜力几乎都在类型内部。** 类型标签、甚至叶子标签，回收不了多少；这解释了「先分类再选模」为什么经常看起来有用、数字上却刺痛。
2. **Winner label 是有毒监督。** 多候选同时成功时，标签被延迟 / 成本 / 固定次序决定，模型学的是「谁便宜」而不是「谁能成」。
3. **零损失路由可以名正言顺地永不调用最强参考。** 当参考的准入价格低于效率最优价格，理论直接宣判「别叫它」；CodeRouterBench 的 25.5× 不是玄学省钱，是价格路径上的可行点。
4. **认证地板比拟合地板诚实。** 同一套零损失目标，拟合在重切分上大面积翻车，认证后才稳定。路由上线不能只看拟合集上的 \(\epsilon\)。

## 🤔 我的判断

**定位：测量与理论基础设施型论文，附带一组可复现的学习型路由器；最大资产是 37 万次计分的全模态轨迹矩阵，以及把质量、成本、信息观测绑在同一套记号里的路由价值论。**

亮点：

1. **先量 oracle 间隙，再谈学习**，避免「路由器涨了 0.3 就宣布通吃」。
2. **outcome vs winner** 的对照足够狠，可直接改训练配方。
3. **效率与可认证质量地板** 一起给工程，不只是平均省钱故事。

问题与局限：

- **学到的平均增益只有 +0.3**，相对 5.4 的 oracle 只吃到约 6%；多数基准上路由器几乎等于固定最优。
- **图像生成路由尚未打赢固定生成器**，124 个配置的失败本身是重要负结果，也说明矩阵里噪声很大（GenEval2 上逐 prompt 差分标准差 31–38）。
- **机器人 +1.10 的置信区间含 0**（[−0.40, +2.55]），时间节省更硬，成功率优势还谈不上铁板。
- **理解类大基准（MMLU-Pro 等）多数留给潜力分析，不在学习路由主表**，正是输入量和间隙的大头所在。
- **路由器自身成本、级联失败传染**（文中：CodeRouterBench 上一次失败大约把下一模型成功机会减半）在主叙事里着墨相对少，工程上却很关键。

对工程的直接启发：

- **先建「同输入、多候选」轨迹矩阵**，再决定要不要上学习路由；没有矩阵就没有天花板。
- **监督信号回归各候选结果，不要分类「谁赢」。**
- **固定基线的准入规则写死**：缺分如何回退、组合变更时如何在同一任务集上重比。
- **省钱路由必须带质量地板**；上线用认证流程，不只看拟合集 \(\epsilon=0\)。
- **类型路由当先验可以，别指望它吃掉大部分间隙**；钱在类型内逐输入互补处。

一句话收束：**Route Anything 想证明的不是「我们训出了最强路由器」，而是「在通用 AI 系统里，路由值得被当成一等模块来测、来证、来学」。**
