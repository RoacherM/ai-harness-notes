# 模型冻住只改脚手架：三千行 CLEO 在留出集上 83.8%，离 Claude Code 的 85.0% 只差 1.2 点

你有没有过这种体验：业务方要求「证据不能出域、模型必须可自托管」，你却习惯了把 Claude Code 一类重型 agent 脚手架直接搬进生产？换开源模型后，要么正确率掉一截，要么为了追分把脚手架越堆越胖，最后没人说得清哪一段提示、哪一个工具是真正必要的。行业口头禅常是「换更强模型」；Dream Security 这篇 CIKM 2026 Industry Day 论文把口号反过来：**Optimize the Harness, Not the Model**。

Shai Nahum Gefen、Vered Chassida、Dmitry Basin、Guy Feigenblat 的 **CLEO: Optimize the Harness, Not the Model: Fitting a Minimal Agent to a Self-Hostable LLM for Investigative Analysis**（arXiv:2611.03434）在固定自托管模型 GLM-5.1 上，用自底向上的约束循环把近空 ReAct 拟合成约 3k LOC 的最小 harness。留出 240 题上，CLEO 硬通过率 83.8%、软分 8.41、延迟 114s；同模型下 Claude Code SDK（约 512k LOC）85.0%，差距只有 1.2 个百分点。

## 核心摘要

CLEO 全称 Constrained Loop for Environment Optimization：在**模型权重冻结**的前提下，只优化环境与 harness，且每一步改动必须同时满足「提高准确率」与「通用、可审计、精简」的 justify gate。起点是近乎空的 ReAct（ls / read / grep / 沙箱 python），监督者用 Opus-4.8 做 propose–test–keep。评测环用 44 道问答（32 固定 + 12 新鲜），并周期性做 OOD 轮换；另有 240 道题全程不进优化环，只做最终留出。同是 GLM-5.1：Claude Code SDK ~512k LOC 得 85.0%；PI bare ~75k 得 80.8%；PI+CLEO prompts 83.8%；CLEO 本体 ~3k LOC 也是 83.8%。自顶向下从 PI 裁，准确率能对齐，体积几乎压不下去；自底向上才只加真正需要的部件（记忆读写、非答案安全与重试），`cite()` 助手因未使用被回退。领域是政府调查分析：在杂乱证据语料上做可审计作答。

## 🎯 为什么这件事值得写

三件当下很真实的约束叠在一起：

1. **模型不能随便换。** 调查、政务、防扩散场景往往要求自托管、可审计、数据不出域。旗舰闭源 coding agent 再强，也可能进不了部署清单。
2. **脚手架膨胀没有刹车。** 从「能跑」到「像 Claude Code」，LOC 可以从三千漂到几十万。功能堆上去容易，证明「删了会掉分」很难。
3. **优化环本身会污染评测。** 若拿来调 harness 的题和最终汇报的题混用，涨分故事不可信。CLEO 把 240 题彻底留出，这点对工业论文尤其重要。

它回答的不是「开源模型能不能打过 Claude」，而是：**在同一自托管模型上，一个刻意长不大的 harness，能不能逼近重型脚手架的留出表现。**

## 🏗️ 机制：自底向上的约束优化环

### 固定物与可变物

| 固定 | 可变 |
| --- | --- |
| 自托管 LLM：GLM-5.1 | 工具、提示、循环策略、少量辅助模块 |
| 领域：政府调查分析 / 杂乱证据语料 | harness 代码与配置 |
| 安全与审计诉求 | 每一次被 justify gate 放行的改动 |

### 起点：近空 ReAct

几乎只有文件系统与代码探查能力：`ls`、`read`、`grep`、沙箱 `python`。没有先入为主的「调查 agent 标准组件清单」，避免一上来就带着 PI / Claude Code 的全套假设。

### Justify gate

提议的改动必须同时满足：

1. **提高准确率**（在优化用的 44 题环上可测）
2. **通用**：不是只为某一题开的特判
3. **可审计**：改动本身说得清、留得下痕迹
4. **精简（lean）**：能不加就不加

过不了 gate 的改动不进入保留集。`cite()` 这类「看起来很调查」的助手因为实际未被使用，最终被回退，是 gate 在起作用的具体例子。

### 监督者与评测分层

- **Supervisor**：Opus-4.8，propose–test–keep
- **优化评测**：44 Q&A（32 固定 + 12 新鲜），并周期性 OOD swap，降低对固定 32 题过拟合
- **真正报告用的留出**：240 题，**从未进入优化环**

### 两条拟合路线

| 路线 | 做法 | 结果直觉 |
| --- | --- | --- |
| Top-down | 从 PI（~75k LOC）往下裁 | 准确率能对齐，体积几乎压不下去 |
| Bottom-up（CLEO） | 从近空 ReAct 往上加 | 只留下必要部件，最终 ~3k LOC |

Bottom-up 实际加上去的关键能力包括：**记忆读写**、**非答案（non-answer）安全与重试**。前者服务长证据链；后者避免「不会就硬编」在调查场景里变成高危行为。

## 🧪 关键证据

### 留出集（同一 GLM-5.1）

| 系统 | 约略规模 | 硬通过率 | 其他 |
| --- | --- | --- | --- |
| Claude Code SDK | ~512k LOC | 85.0% | — |
| PI bare | ~75k LOC | 80.8% | — |
| PI + CLEO prompts | （PI 体量） | 83.8% | 提示侧吸收 CLEO 经验 |
| **CLEO** | **~3k LOC** | **83.8%** | soft 8.41；延迟 114s |

CLEO 相对 Claude Code 只差 **1.2pp**，相对 PI bare 高 3.0pp，和「把 CLEO 提示灌进 PI」打平，但代码体量小两个数量级以上（相对 Claude Code）。

### 路线对比的工程含义

- **Top-down 匹配准确率却几乎不瘦身**：说明重型 harness 里大量代码是「沉没结构」。准确率饱和后，删减缺少梯度信号，gate 也帮不上忙，因为「删了是否掉分」的实验成本高、局部性差。
- **Bottom-up 只加用得上的块**：记忆 R/W、非答案安全+retry 留下了；`cite()` 没用上就回退。这比事后做 dead-code 清理更干净：从未长出来的代码，不需要证明它无害。

### 优化环防过拟合

44 题里混入 12 道新鲜题，并做周期性 OOD 轮换，目的很明确：阻止 supervisor 把 harness 特化成「这 32 道固定题的解答手册」。最终叙事完全落在 240 留出题上，工业读者可以按「未见题」理解。

## 🔬 最有意思的部分

1. **标题就是方法边界。** 「Optimize the Harness, Not the Model」不是营销句，而是实验设计：GLM-5.1 始终冻结。所有涨分都记在脚手架与环境上，避免「其实是换模型」的归因混乱。
2. **1.2pp 的差距配上 512k vs 3k。** 在调查分析这种重证据、重审计的任务上，重型 coding agent 的边际收益可能远小于其审计与供应链成本。CLEO 把这个 trade-off 写成了可引用的数。
3. **Justify gate 比「自动进化」更像工业口味。** 许多 harness 搜索只优化分数；CLEO 额外要求通用、可审计、精简。`cite()` 被回退说明 gate 真的会否决「看起来正确」的功能。
4. **PI+CLEO prompts = CLEO 准确率**，暗示一部分收益其实是**提示与交互协议**，不必捆绑整份重型运行时。对已经绑死在某套 agent 框架上的团队，这是一条更便宜的迁移路径：先搬协议，再谈重写。

## 🤔 我的判断

**定位：一篇把「最小可自托管调查 agent」写成工业约束优化问题的样本，测量清晰，取舍老实。**

亮点：

1. **留出 240 题从不进环**，避免自进化论文常见的评测污染。
2. **同模型对照 Claude Code / PI / CLEO**，把脚手架体量拉进同一张表，结论可读。
3. **Bottom-up vs Top-down** 对照直接服务工程决策：想瘦身，从空壳加，比从巨石拆更有效。
4. **领域真实**：政府调查分析、杂乱证据、可审计，不是又一版通用聊天玩具。

问题与局限：

- **监督者是 Opus-4.8。** 优化环本身依赖强模型提改动；部署模型自托管，不代表「造 harness 的过程」自托管。工业落地时要单独算这条供应链。
- **任务面是调查问答，不是通用 SWE。** 83.8% 靠近 Claude Code，不能外推到修仓库、写 PR。
- **公开事实未展开完整误差条与多次种子。** 1.2pp 很诱人，复制时仍建议自己重跑留出。
- **Lean 约束依赖人工/监督者品味。** 「通用、可审计、精简」有主观空间，换一组 reviewer 可能留下不同最小集。
- **延迟 114s** 对交互式分析是否可接受，取决于工作流；论文把它报出来是好事，但产品侧还要拆「检索 / 工具 / 生成」各占多少。

对工程的直接启发：

- **先冻结模型，再问脚手架该有多厚。** 尤其在必须自托管时，把「换 GPT」从选项里拿掉，优化目标会突然清晰。
- **优化环与汇报集严格隔离。** 再加一点新鲜题和 OOD 轮换，防止 harness 背题。
- **新功能默认不进主路径，除非过 justify gate。** 准确率、通用性、可审计、精简四条里缺一不可；没用上的 helper 要能回退。
- **想瘦身就别从 75k 行开始删。** 从 ls/read/grep/python 往上长，往往更快得到「真正最小集」。
- **调查场景优先做非答案安全。** 「不会就拒答/重试」比「硬编一个带 cite 的答案」更符合取证伦理。

一句话收束：**模型被政策锁死的时候，CLEO 说明你仍有一条路：把近空 ReAct 在约束门后一点点拟合到离重型脚手架只差 1.2 点，而不是先把 50 万行代码搬进内网。**
