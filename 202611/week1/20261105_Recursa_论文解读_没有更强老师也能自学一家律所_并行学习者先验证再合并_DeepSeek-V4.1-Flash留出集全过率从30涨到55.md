# 没有更强的老师，模型能不能自己学会一家律所？Recursa 只改 skills、指令和记忆，留出集全过率从 30% 涨到 55%

你有没有过这种体验：把 agent 丢进一个陌生的知识库，比如公司几千份合同和备忘录，它每次接任务都从头搜一遍，第一次把「No Solicitation」条款当成无关内容，第二次又犯同样的错。你想让它「记住」，可这个领域没有成堆的专家标注数据，也没有一个更强的模型愿意替它写复盘。

这正是 **递归自我改进（RSI）** 和 **skill 自进化** 落到知识密集型行业时的真实处境：**只用系统自己的模型，从领域材料和任务反馈里同时补上「不知道」和「知道却用错」两种缺口，能走多远？**

阿里巴巴研究院的 **Recursa** 给出的回答是：模型和 harness 冻住，只学一个由指令、skills、记忆组成的知识库；先从语料自举，再让多个并行学习者分头修、验证后合并。在 Harvey LAB 的 Firm Knowledge 基准上，DeepSeek-V4.1-Flash 的留出集全过率从 30.0% 涨到 55.0%。看完我的感受是：**涨分的主角不是「递归」这个词，而是「拆分、验证、合并」这套多学习者流程；单个学习者自己闭门修，反而会把训练集修坏。**

## 核心摘要

Recursa 把「基础模型系统」拆成三类可学组件：知识库（指令、按 Agent Skills 格式按需加载的 skills、学习者写下的反思记忆）、harness、基础模型；本文只学知识库，harness 与模型固定。学习分两个阶段：自举阶段并行 agent 分块阅读语料，构建带来源链接的导航结构与探索笔记，再用从材料生成的练习题自我练习，目标是补「知识缺口」；递归自我改进阶段由学习者调用并行求解者，诊断失败、编辑 skills 和指令、在受影响任务加一批已通过任务上重跑验证，只保留不引入回退的编辑，上层学习者把任务按主题拆给子学习者、合并它们的修改并反思，目标是补「行为缺口」。全程由同一个模型担任求解者和学习者，不依赖更强模型。harness 用持久 Python REPL 做代码式工具组合，把完整交互历史放在只追加的事件日志里按需检索。Harvey LAB Firm Knowledge（46 个虚构客户、266 个案件、9,288 个文件、约 1.08 亿 token，250 道题分 150 训练 / 100 测试）上：同模型 Qwen3.8-27B 仅靠 harness 就把全过率做到 37.2%（修订评分标准），高于公开参考的 31.0%；自举把交互轮数和输入 token 降低约五分之一到四分之一，准确率只小涨；多学习者学习把 DeepSeek-V4.1-Flash 测试全过率从 30.0% 提到 55.0%，Qwen3.8-Flash 从 35.0% 提到 46.0%，而单学习者分别只到 43.0% 和 37.0%。它的价值在于把 skills 生命周期（生成、验证、合并、反思）在一个难以自动判对的长文本领域里跑通，并且诚实地暴露了轮次之间的明显波动。

## 🎯 为什么这件事值得写

作者把现有工作的缺口说得很直接：

1. **大多只学系统的一部分。** 有学指令的、学 harness 的、学 skills 和子 agent 的、学学习方法本身的；从任务反馈学的偏「行为缺口」，只读语料的偏「知识缺口」，两者很少合在一起。
2. **评测偏代码、数学、游戏。** 这些领域常常只看短而精确的答案，或允许在同一题上反复自测，不检查答案背后的证据。
3. **经常靠更强模型来驱动学习。** 那就不是「自我」改进。

法律、金融这类领域更难：知识散落、没有统一组织，同一份证据在不同语境下支持不同结论，正确性很难自动核验。这对 skill 自进化是个真考场：**你没法靠一个单元测试判对错，只能靠 rubric judge 和反复验证。**

## 🏗️ 机制：知识库 + 两阶段学习 + 为长程而建的 harness

### 两个角色

$$
(y,\tau)=\textsc{Solve}(x,K),\qquad (K',\mathcal{T})=\textsc{Learn}(D,K)
$$

求解者用当前组件 $K$ 做题，返回答案和轨迹；学习者调用求解者、看答案轨迹和反馈、修订 $K$，或者把任务拆给子学习者再合并，返回新组件和学习轨迹。

### 可学组件

| 组 | 内容 | 本文是否学习 |
| --- | --- | --- |
| 知识库 | 指令（系统提示、护栏）、skills（按需加载，可带脚本和参考材料）、记忆（学习者对过往执行与学习的反思） | 是 |
| harness | 执行循环与上下文管理、工具、子 agent | 否 |
| 基础模型 | 每个 agent 和子 agent 各配一个 | 否 |

先学知识库的理由：它是文本，下一个任务就能用，还能拿来和源材料对账。

### harness 的三个设计

1. **工具组合**：模型每步写一段 Python，在持久 REPL 里执行；文档搜索、文件访问、外部 API 都是可调用的库。中间结果留在变量里，只把选中的输出回传上下文；长输出截断并落盘。
2. **程序化上下文管理**：完整历史放在只追加的事件日志里，上下文只保留近期历史和一个「已驱逐区间」索引，需要时用代码按日志地址取回。学习者诊断时也这样组装证据，不必重载整条求解轨迹。
3. **多 agent 编排**：agent 可在 REPL 里派子 agent 到隔离沙箱处理一部分工作，再合并结果。

### 阶段一：自举（补知识缺口）

- **导航结构**：适合大而杂的集合，摘要链接到源位置，结构化元数据（实体、文档类型、状态、日期）缩小搜索范围。
- **探索笔记**：适合窄而结构化的领域，记术语、约定和后续调查指引。
- 每条都保留来源链接，写明不确定性和适用范围，并记录环境边界：有什么、没有什么、只覆盖了一部分的是什么。
- **自我练习**：从读过的材料生成练习题，学习者评估尝试、把反思写进记忆、更新 skills。

### 阶段二：递归自我改进（补行为缺口）

叶子学习者的循环：

```text
Solve：每个任务一个求解者，并行
Diagnose：读失败轨迹和反馈，区分真错误与噪声或含糊反馈
Edit：修订指令和 skills，参考以往反思
Validate：重跑受影响任务 + 一批已通过的任务，修好且无回退才保留
直到没有改进或预算用完
```

上层学习者：

- **拆分**：按主题、失败模式、要改的 skill 或要练的工具分子集，目的是减少重复劳动和合并冲突。
- **合并**：去重、调和冲突编辑、把跨子集反复出现的教训泛化；再抽样重跑子任务，确认合并没把收益抹掉。
- **反思**：读子学习者的轨迹，找没改进的子集、冲突的编辑和反馈不可靠的任务，写进记忆，再发新一轮学习任务。

作者还提出「学习浪费」这个概念：**停顿**（等依赖或结果时的空闲）和 **返工**（重读没变的状态、重新发现目录结构、重查别人已经诊断过的失败）。学习者会分析自己的轨迹来识别两类浪费，并把对策写进记忆。

## 🧪 关键证据

### harness 本身就是强基线（Qwen3.8-27B）

| 设定 | 条目通过率 | 全过率 |
| --- | --- | --- |
| 公开参考：基础 agent（不学习） | 58.2% | 21.6% |
| 公开参考：高强度学习后 | 70.1% | 31.0% |
| Recursa harness，原评分标准 | 78.9% | 35.2% |
| Recursa harness，修订评分标准 | 79.1% | 37.2% |

作者注明两边的评测与适配流程不同，这张表只能作参照。所有实验的条目由 Qwen3.8-Max 判。

### 自举：主要省成本

用 DeepSeek-V4.1-Flash 在全部 250 题上，自举产出 14 个 skills：一个把 266 个案件关联到笔记和源文件的导航 skill，加 13 个从练习中提炼的 skill（如从案件编号确定任务范围、追踪版本链、在冲突来源间核对数字和日期）。交互轮数和输入 token 各降约五分之一到四分之一，全过率小涨，条目通过率不变。作者的解释是：没有语料知识时，agent 可以多搜几轮弥补；语料知识主要是缩短搜索。

### 自我改进：多学习者 vs 单学习者（修订评分标准）

| 组件 | 训练 全过 | 训练 条目 | 测试 全过 | 测试 条目 |
| --- | --- | --- | --- | --- |
| **DeepSeek-V4.1-Flash** | | | | |
| 不学习 | 32.0 | 79.8 | 30.0 | 80.0 |
| 自举 | 34.7 | 80.6 | 33.0 | 78.9 |
| 单学习者 $K^{(4)}$ | 34.7 | 75.3 | 43.0 | 78.8 |
| 多学习者 $K^{(2)}$ | 48.7 | 86.3 | **55.0** | 84.1 |
| **Qwen3.8-Flash** | | | | |
| 不学习 | 35.3 | 80.6 | 35.0 | 83.2 |
| 自举 | 37.3 | 83.2 | 34.0 | 80.5 |
| 单学习者 $K^{(5)}$ | 30.0 | 73.1 | 37.0 | 77.7 |
| 多学习者 $K^{(1)}$ | 47.3 | 85.6 | **46.0** | 84.4 |

DeepSeek 那条：上层学习者按主题（如银行金融条款、信贷先例、资本市场发行文件、并购协议条款）拆给叶子学习者，合并成 $K^{(1)}$（32 个 skills），再在全部 150 道训练题上跑四轮得到 $K^{(2)}$ 到 $K^{(5)}$。收益主要集中在全过率：学习把「部分正确」变成「完全正确」，并迁移到从没参与学习的测试题上。

单学习者的冷水很重：Qwen3.8-Flash 单学习者的训练全过率从自举后的 37.3% **掉到** 30.0%，条目通过率也从 83.2% 掉到 73.1%。

| --- | --- |
| $K^{(1)}$ 合并 | 48.0 |
| $K^{(2)}$ | 55.0 |

## 🔬 最有意思的部分

1. **学到的是「判断规则」，不是事实。** 两个测试题案例：Q157 问最近签署的含 no-shop 条款的并购交易，没学习的 Qwen3.8-Flash 只认标题叫「No-Shop」的条款，选了 2025-05-20 签的协议；学习后它从一开始就同时搜「no-shop」「Exclusivity」「No Solicitation」，按条款实际限制什么来读，还排除了一笔记在 Real Estate 下的酒店收购和一份没签最终协议的意向书，找到 2025-06-16 签署的那笔。Q078 问所有以和解结案的 IP 案件，没学习的 DeepSeek 按「patent」「trade secret」关键词返回 8 个，其中混进一个带商业秘密主张的竞业限制纠纷；学习后先从委托记录确定负责业务组，再查有没有已执行的和解，返回 7 个，那个竞业纠纷其实记在 Labor & Employment。**区分「这个案子碰到了 IP」和「律所把它当 IP 案件办」，正是 skill 该沉淀的东西。**

2. **基准自己也有错。** 作者在 30 道题里找到 46 条评分条目与题面或源文档冲突，分五类：与题面矛盾、只认指定文件、漏掉合格项、放进了该排除的项、占位符没展开（比如「[same 37-entry set]」）。只在源文档支持时修订，题面、条目编号和其余 220 题不动；修订让大多数分数涨最多 4 分，只有一项掉 1 分。对做 judge 和 rubric 的人，这是一份很实用的「评分标准常见错误」清单。

3. **验证门是本地的。** 叶子学习者的门槛是「修好失败且不在已通过样本上回退」，合并时再抽样重跑。这和本周看到的统计验收门思路一致，但这里没有成对重复执行或显著性检验，于是轮次之间的大波动就直接暴露了出来。

4. **harness 先拿走了一大块。** 不学习时同模型已经比公开参考的「学习后」还高。很多 RSI 论文的涨幅里混着 harness 的贡献，这篇把它单独列了出来。

## 🤔 我的判断

**定位：知识库级（指令、skills、记忆）递归自我改进的系统样本；模型和 harness 冻结，用多学习者拆分、验证、合并补知识与行为两个缺口，属于工程系统论文而非方法突破。**

亮点：

1. **不靠更强老师。** 同一个模型自举、做题、学习，测试端 DeepSeek +25 个点、Qwen +11 个点。
2. **多学习者对单学习者的对照很有说服力。** 同起点、同模型，单学习者在 Qwen 上甚至把训练集修坏；拆分加合并才是增益来源。
3. **skill 有来源、有范围、有不确定性。** 自举产物每条都链回源文档并写明适用边界，这是让 skill 能被审计、能被后续修订的前提。

问题与局限：

- **测试集只有 100 题，且只有一个基准。** 没有置信区间、没有重复运行，几个点的差距难以判断显著性。
- **报告的是挑出来的那一轮。** DeepSeek 报 $K^{(2)}$、Qwen 报 $K^{(1)}$，而后续轮次测试全过率回落到 43.0% 和 39.0%；按什么规则选报告轮次，正文没有给出一个独立于测试集的选择依据，这是我最在意的一点。
- **judge 是另一个 LLM。** 所有条目由 Qwen3.8-Max 判，长文本法律答案的判卷本身有误差，作者修评分标准也说明了这一点。
- **评分标准被修订过。** 修订有依据也有公开清单，但和其他系统的数字不再严格可比。
- **只学了知识库。** harness 和模型学习是后续工作；作者自己列出依赖语料质量、算力开销大、错误或偏见数据会沿学习过程传播，以及自主探索与记忆带来的隐私安全风险（实验在隔离、无外网的沙箱里跑）。

对工程的直接启发：

- **skill 自进化先拆再修再合。** 按主题或失败模式把任务分给并行学习者，合并时去重、调和冲突、抽样重跑，比单线程反复改一个 prompt 稳得多。
- **每条编辑都过「修好 + 不回退」两道检查。** 已通过样本的回归集是 skill 演化的最低配验收门。
- **在门上再加统计检验和留出选轮规则。** 本文轮次波动说明，没有成对重复执行和事先定好的选择规则，最终报告的那一轮很可能只是峰值。
- **skill 产物要带来源和适用范围。** 方便后续验证、撤回和审计。
- **记忆只给学习者，不给求解者。** Recursa 的 harness 让求解者和学习者对知识库有不同访问级别，反思记忆只在学习者上下文里加载；这是一种很自然的记忆读写分离。
- **把评分标准当代码审。** 46 条有问题的评分条目提醒你：judge 判错，很多时候是 rubric 先错了。

一句话收束：**Recursa 证明了一个中等模型只靠自己写 skills 也能把一家律所学到全过率翻番，但它同样暴露了这件事最危险的地方：没有统计验收和事先定好的选轮规则，「自我改进」的曲线会上下乱跳，你最后看到的可能只是最高的那一点。**
