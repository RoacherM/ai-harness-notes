# 没有标注也能调记忆系统：从用户历史里倒推带证据的问答，比官方标注还高 1.1 分，失败先分清是存储、检索还是作答

给 agent 做长期记忆的人，迟早会撞上一个问题：**记忆系统到底该怎么设计，换一个用户还适不适用？** 有人的历史主要是聊天，有人是邮件加照片加视频，有人一年才有几百条记录，有人每天几十条。存成什么粒度、用什么检索、上下文怎么拼，对不同的历史最优解可能完全不同。

最近一批工作（MemEvolve、ALMA、M⋆）开始让 LLM 自动搜索记忆设计，但它们都需要下游反馈来打分。可执行任务有天然的成败信号，个人记忆没有：用户不会每天告诉你「你昨天那条回忆找错了」。能用的只有人工标注的问答对，而给每个新用户的历史手工出题、写答案、标证据，成本高得不现实。

北京大学和微软亚洲研究院的 **MemSteer: Turning User Histories into Supervision for Agent Memory Optimization**（arXiv:2610.39276）问的就是：**没有标注的用户历史，能不能自己变成调记忆系统的监督信号？** 答案是可以，而且在 ATM-Bench 上用自动生成的监督调出来的系统，比用官方标注调的还略高一点。

## 核心摘要

MemSteer 分两部分。第一部分把无标注的用户历史变成「问题、参考答案、支撑证据」三元组：先把历史记录组织成图，从图上采一个相关记录的子图作为素材；然后让 LLM 先写一份**证据锚定的答案计划**，说清楚要问什么、答案是什么、哪几条记录的哪些片段支撑它、这些事实要怎么组合；程序先检查计划的结构和出处覆盖，通过后再单独调用一次生成问题；最后经过两道核验，一是让审查模型逐条核对事实出处，二是让一个只看问题和原始记录的「盲读者」独立作答，答案必须完全一致，引用必须覆盖所有证据记录。

第二部分是 MemSteer-Opt，一个用这些监督来改记忆设计的优化器。它把设计拆成存储、检索、上下文构造三块，对每个答错的问题用证据标注做**分层归因**：证据都在上下文里却答错了，算作答失败；证据缺了但记忆里能找到，算检索失败；记忆里根本找不回来，算存储失败。然后按失败类别分层抽样喂给设计提议器，改完在验证集上更好才接受。

在 ATM-Bench 上，MemSteer-Opt 把 Base-BM25 的 Question Score 从 54.9 提到 68.3（官方标注调出来是 67.3），困难多跳子集从 8.2 提到 29.1。在 RHELM 上分别提高 4.1 和 6.6 点（不含和含外部数据），比官方标注版本低 0.1 和 0.8 点。生成的监督交给 M⋆ 和 MemEvolve 两个现有优化器也同样有效。

## 🎯 为什么这件事值得写

记忆设计自动优化这条线有两个结构性难题：

1. **个人记忆没有天然的成败信号。** 编程 agent 跑测试，网页 agent 看订单状态，都有客观结果。个人助理回答「我去年在哪家餐厅给妈妈过的生日」，答对答错没人告诉你。
2. **一份监督不够用，还得能诊断。** 光有参考答案只能给设计打分，不能告诉优化器「为什么错」。错在没存下来、没检索到、还是检索到了没用上，对应的改法完全不同。

已有用合成问答做记忆的工作，比如 MemBuilder 用合成问答做强化学习奖励训练记忆构建模型，MemMA 用问答探针修补记忆库。MemSteer 的定位不同：它用合成问答**评价和改进记忆系统的设计本身**，不训练模型，也不改存储的内容。

## 🏗️ 机制：先想好答案和证据，再出题

### 图引导的素材准备

每个用户的历史被组织成一张记录图，保留原文、标识符和源数据自带的结构信息。边连接这些记录：同一段对话、相邻的文档段落、明确互相引用、或者词汇重叠足够多。从一个种子记录出发沿路径扩展，采出一个连通子图，在上下文预算内打包成一份素材包，每条事实都能追溯到具体的源片段。

这一步的意义是让问题天然是**多记录**的：要回答它，得把几条相关记录拼起来，这正是记忆系统最容易出错的地方。

### 证据锚定的答案计划

这是 MemSteer 最核心的设计。常规做法是让 LLM 看素材直接出问题和答案，MemSteer 反过来：**先写答案计划，再根据计划出题。** 计划包括：

- 要问什么（主体、属性、约束）
- 参考答案
- 支撑事实及其源片段引用，比如事实 f2 同时出自记录 r1 的片段 s2 和记录 r2 的片段 s1
- 每条证据记录的贡献，比如 r1 提供身份，r2 提供数值
- 组合这些事实需要的操作

计划先过一遍程序检查（结构一致性、出处覆盖），不合格的直接丢掉，然后单独调用一次生成独立成句的问题。

### 两道核验

1. **源头审计。** 审查模型拿着素材、计划和问题，逐项给出结构化判断：答案有没有支撑、问题和计划是否一致、每条事实有没有源支撑、每条证据记录的作用是否属实。全部通过才能进入下一步。
2. **盲答复原。** 一个只看问题、答案类型和原始记录的阅读模型独立作答并给出引用。必须同时满足三条：它认为问题可答，答案在类型归一化之后和参考答案完全一致，引用覆盖了所有选定的证据记录。

生成的问答对再分成互不重叠的训练集和验证集，前者用来生成修改建议，后者用来选设计。

### MemSteer-Opt：分清是哪一层的错

设计空间是一个三元组 d = (存储 s，检索 r，上下文构造 c)。回答模型、它的指令提示词和最终上下文预算在所有设计之间保持固定，只改记忆系统本身。

对每个答错的训练题，用证据标注做归因：

| 情况 | 归因 |
| --- | --- |
| 所需证据都在最终上下文里，仍然答错 | 作答失败 |
| 有证据缺失，但当前记忆系统能找回所有缺失记录 | 检索失败 |
| 有缺失记录在当前记忆里找不回来 | 存储失败 |

然后**按失败类别分层抽样**，每类最多十个案例，避免最常见的失败类型占满提议器的输入预算。每个案例带上问题、参考答案、证据、当前回答和诊断结果。提议器给出修改后的设计和理由，系统按新设计重建记忆、在固定验证集上评估，严格更好才替换，接受后在训练集上重跑以刷新诊断。

## 🧪 关键证据

### 主结果：自动监督不输官方标注

ATM-Bench 是一个约四年个人记录（11,034 条邮件、图片、视频）的多模态个人记忆基准，主集 1,013 题，困难多跳子集 31 题。回答、开放题评判和设计提议都用 DeepSeek-V4-Flash。

| 方法 | 主集 QS | 主集 R@10 | 困难集 QS | 困难集 R@10 |
| --- | --- | --- | --- | --- |
| Base-BM25 | 54.9 | 61.7 | 8.2 | 10.0 |
| 加官方标注优化 | 67.3 | 83.5 | 27.9 | 42.2 |
| 加 MemSteer 监督优化 | 68.3 | 84.1 | 29.1 | 43.6 |
| M⋆ 起点 | 47.4 | 55.2 | 1.9 | 13.6 |
| M⋆ 加官方标注 | 51.8 | 69.4 | 9.5 | 26.0 |
| M⋆ 加 MemSteer | 53.4 | 69.8 | 12.9 | 25.6 |
| MemEvolve 起点 | 35.1 | 41.3 | 7.1 | 18.7 |
| MemEvolve 加官方标注 | 53.7 | 63.8 | 11.4 | 21.6 |
| MemEvolve 加 MemSteer | 53.7 | 63.7 | 9.5 | 18.6 |

注意一个容易忽略的细节：官方标注版本用了 1,013 道官方题里的 600 道做训练和验证，这些题**还在评测集里**；MemSteer 一道评测题都没用。即便如此，MemSteer 在四个指标上都略高。作为参照，ATM 排行榜上的 Memexa 主集 QS 是 65.3，用金标证据的 Oracle 是 71.8。

效果也不是处处都好：MemEvolve 在困难集上用 MemSteer 监督的提升比官方标注小，R@10 还比起点低了 0.1。

RHELM 有十个人设、21,142 条交互记录，用 GPT-4.1-mini 回答和评判：

| 方法 | 不含外部数据 | 含邮件和文档 |
| --- | --- | --- |
| RAG（k=50） | 28.9 | 32.6 |
| MemU | 23.1 | 33.6 |
| GPT-4.1-mini 1M 长上下文 | 24.0 | 33.9 |
| Base-BM25 | 22.3 | 33.3 |
| 加官方标注优化 | 26.5 | 40.7 |
| 加 MemSteer 优化 | 26.4 | 39.9 |

含外部数据时 MemSteer 调出来的系统 39.9，比列出的最强基线 33.9 高 6 个点；不含外部数据时还比 RAG（k=50）低 2.5 个点。

### 能不能迁移、能不能继续调

- **跨基准。** 把在 ATM-Bench 上调好的设计冻结，直接用到 RHELM，比 Base-BM25 高 4.1 和 5.3 点。再用 RHELM 历史生成的监督继续调，分别到 30.6 和 42.8，和用官方标注继续调（31.5 和 42.9）很接近。
- **跨用户。** 用六个用户调出一个共享设计，直接给两个没见过的用户用：Martin Keller 从 41.2 掉到 37.7，David R. Ellis 从 37.3 涨到 38.6。然后用每个人自己的历史生成监督继续调：Martin 到 44.3，David 到 39.2。这个实验直接支撑了论文的出发点，**一个设计不一定适合所有人**，而且用户自己的历史就能把它调回来。

### 什么样的监督才好用

在 ATM-Bench 上比较三种出题方法，各自带不带核验：

| 方法 | 主集 QS | 困难集 QS | 问答质量（两个评审平均） | 核验后保留比例 |
| --- | --- | --- | --- | --- |
| 随机拼素材出题 | 54.2 | 5.3 | 63.5 | 无过滤 |
| 随机拼素材加核验 | 64.8 | 24.4 | 77.4 | 21.2% |
| Ragas 多跳生成 | 63.0 | 23.3 | 71.4 | 无过滤 |
| Ragas 加核验 | 65.1 | 20.7 | 82.5 | 42.1% |
| MemSteer 不加核验 | 65.2 | 22.0 | 75.4 | 无过滤 |
| MemSteer 完整版 | 68.3 | 29.1 | 90.9 | 47.9% |

几个观察：随机拼素材出的题几乎没用，主集只比不优化的 54.9 低 0.7 分，加上核验后猛涨十分多，但只有约五分之一能留下来；核验对三种方法的问答质量都有帮助；两个独立评审（GPT-5-mini 和 DeepSeek-V4-Flash）给的质量分趋势一致，而且和下游 QS 大体对得上，说明问答质量分可以作为监督好坏的便宜代理指标。

答案计划本身也单独测了，同样 600 个任务：直接一次生成问题、答案和证据，质量 67.8%；同一次调用里先写计划再出题，73.1%；计划先过程序检查再单独出题，85.9%，但每题 token 从 6.4 万涨到 10.5 万。

训练题数量从 100 涨到 200 时提升最大，超过 200 以后检索召回基本饱和。

### 诊断比给金标证据更有用

四种喂给提议器的反馈方式，都用 MemSteer 监督、都从 Base-BM25 开始：

| 反馈方式 | 主集 QS |
| --- | --- |
| Base-BM25（不优化） | 54.9 |
| 随机 30 个失败案例 | 58.3 |
| 随机 30 个加金标证据 | 58.4 |
| 随机 30 个加分层诊断 | 62.7 |
| 分层诊断加按类别分层抽样（完整版） | 68.3 |

**光把正确证据告诉提议器几乎没用**（58.3 到 58.4），明确告诉它「这是检索的错还是存储的错」才有用。分层抽样再加 5.6 分。困难集上，诊断加随机抽样的证据召回（44.1）反而略高于完整版（43.6）。

附录里一条被接受的优化轨迹很有代表性：从 BM25 原始查询加直接阅读开始，九次被接受的修改依次加入 BGE-M3 稠密检索、混合检索加重排、问题分解、HyDE 查询改写和二次检索、更大的候选池、最后加上答案校验。最终设计是四路 HyDE 查询、重排 120 个候选、读 25 条记录。修改顺序是先改检索表示和排序，再改多查询的上下文构造，最后改答案校验。

## 🔬 最有意思的部分

1. **出题的顺序反过来了。** 常规思路是「看材料，出问题，再找答案」。MemSteer 是「先定答案和证据，想好要怎么组合，再倒推出问题」。这样生成的题天生带着可核验的证据链，而且是多记录组合的，正好打在记忆系统最薄弱的地方。
2. **监督的用处有两层，打分和诊断。** 参考答案用来给设计打分，证据标注用来定位错在哪一层。消融显示后者的价值远大于前者：同样多的失败案例，告诉提议器「这是检索失败」比把金标证据贴给它有用得多。这和前几天 MICA 那篇「先分清是决策错还是表达错」是一个思路：**归因先于修改。**
3. **共享设计会伤害个别用户。** Martin 用六人共享设计掉了 3.5 分，这在做产品时是很真实的风险：平均分涨了，但有一部分用户体验变差，而且你可能根本不知道。用户自己的历史就能生成监督，意味着个性化调优不需要额外标注成本。

## 🤔 我的判断

**定位：一个把「没有标注」这个现实约束认真对待的工作。监督生成管线做得扎实，分层诊断的思路可以直接用在任何检索增强系统的调优上。**

亮点：

1. **对照公平且偏向基线。** 官方标注版本的训练题留在评测集里，MemSteer 一道都没用，还是略高，这个结论比较硬。
2. **核验设计得严。** 盲答复原要求答案完全一致且引用覆盖所有证据，保留率不到一半，宁可少不要错。
3. **监督可以跨优化器用。** 交给 M⋆ 和 MemEvolve 也有效，说明它是一种通用的监督来源，不是和自家优化器绑定的技巧。
4. **跨用户实验很有价值。** 直接证明了「共享设计不一定适合每个人」以及「自己的历史就能调回来」。

问题与局限：

- **全链路都是 LLM，没有人工认证。** 答案计划、审计、盲答都可能共享同一种错误，作者在局限里也承认了这一点。盲答复原只能证明答案可以从这些记录里得出，不能证明每条记录都是必要的。
- **生成的问题跟着历史的分布走，不跟着用户真正的需求走。** 用户真正想问的可能是「我上次说要还谁钱」，而素材图采出来的问题可能是一些用户根本不关心的组合。
- **设计空间偏检索。** 九步优化轨迹几乎都在改检索和重排，存储结构本身（比如要不要做事件抽取、要不要建实体档案）探索得不多。
- **评测只有两个基准，其中 RHELM 是合成人设。** 真实、杂乱的个人历史上的证据有限。
- **成本没有系统报告。** 两阶段出题每题 10.5 万 token，几百道题乘上 20 轮优化，在单个用户身上跑一遍的花费值得算一算。
- **隐私问题被一笔带过。** 把多条记录拼成问题，恰恰可能暴露单条记录里看不出来的敏感信息，而这条管线需要把这些记录整段交给 LLM 处理。

对工程的直接启发：

- **给记忆或 RAG 系统做评测时，先从自己的数据里倒推题目。** 先选几条相关记录、写出答案和证据，再出题，最后用一个只看原文的模型独立作答做核对。这比让 LLM 直接看材料出题质量高得多。
- **调检索系统时，失败案例先分层。** 证据在上下文里却答错、证据能找到却没检索到、证据根本没存下来，三种情况分别交给作答、检索、存储去改。
- **按失败类型分配反馈预算。** 不要让最常见的失败类型把提议器的上下文占满。
- **共享配置上线前，抽几个用户单独看。** 平均分涨了不代表每个人都受益，个别用户可能明显退步。

一句话收束：**记忆系统调不动，往往不是因为没有优化器，而是因为没有监督；MemSteer 说明用户自己的历史就能出题，但前提是先把答案和证据想清楚，再分清每次失败错在哪一层。**
