# 多轮 agentic RL 到底提升了什么？CASIA 用 Pass@(K,T) 证明轨迹级收益高度依赖交互预算：紧预算下优势缩没甚至反转；逐步决策质量并不全面抬升，强的是纠错和长程韧性；BudgetMix 训练时混预算，紧档相对 full-budget RL 平均多出 7.5 / 5.3 / 4.0 点

你有没有过这种体验：同一套多轮 RL 训出来的 agent，在 bench 上放开步数时明显强于基座，一上线改成「最多十步必须停」或「不可逆操作前不许试错」，优势就塌回去，有时甚至不如没训过的模型。你开始怀疑：榜上多出来的那几分，究竟是每一步都更聪明了，还是只是更会在长轨迹里把自己捞回来？

这就是 **multi-turn agentic RL** 的解释缺口。行业默认把终局成功率当成「能力提升」的同义词；CASIA 这篇的核心问题是：**多轮 RL 真正改善的是什么，它的收益在交互预算变紧时还稳不稳？** 看完我的感受是：**Pass@(K,T) 把采样宽度和交互深度拆开之后，故事变得刺耳：轨迹级红利不等于逐步决策红利；如果你的部署场景步数紧、容错低，只看 full-budget Pass@K 会高估可靠性。**

## 核心摘要

论文在 BFCL v3、DeepCoder-MT、InterCode-SQL、FrozenLake 等交互任务上，用 GRPO（并扩展到 GiGPO、PPO）训练 Qwen3-4B/8B，再用二维指标 Pass@(K,T) 评估。Pass@K 维度上，多轮 RL 能把轨迹级成功推到基座经验边界之外；但固定采样宽度扫交互深度 T 时，预算充足时 RL 优势明显，预算收紧后优势显著缩小，部分任务上消失甚至反转。逐步对照显示：在匹配状态下，RL 只在 46.8%（DeepCoder-MT）和 42.8%（FrozenLake）的状态上逐步质量更好；一到错误状态，比例翻到 65.7% / 67.3%，从相同错误态继续跑的终局成功也更高（FrozenLake 51.3% vs 38.6%，DeepCoder-MT 38.5% vs 22.9%）。优势还随轨迹深度后移：早期步甚至弱于基座。机制上，RL 单步动作在基座策略下仍局部合理（Terminal-Bench 上 Action NLL 均值 12.20 vs 10.25），但完整轨迹的似然比向 RL 策略累积偏移。训练动态上，full-budget RL 的轨迹奖励 Rmulti 上升时，逐步奖励 Rsingle 可下降（DeepCoder-MT：Rmulti +0.331，Rsingle −0.097）。作者讨论过程监督的收益与瓶颈后，提出 BudgetMix RL：每个任务实例按满预算 Tmax 的离散比例均匀采样训练预算。在 25%/50%/75%/100% Tmax 的 Pass@T（Pass@8）上，BudgetMix 相对 full-budget RL 平均分别高 7.5、5.3、4.0 个百分点，满预算时基本持平，并缓解逐步质量侵蚀。价值定位是：给 agentic RL 一份「预算稳健性」评测语言，以及几乎零改动的训练补丁。

## 🎯 为什么这件事值得写

agentic RL 最近很热，但多数报告停在「放开预算后的终局成功率」。这篇把问题拆成三层，正好戳到部署痛点：

1. **评测语言升级。** Pass@K 只看采样宽度；交互 agent 还有深度轴 T。Pass@(K,T) 让「多采样几次」和「允许多走几步」不再混成一句话。
2. **能力归因更诚实。** 多轮 RL 不像单轮 RLVR 那样主要是在基座已有解上重加权；它可以扩张轨迹级边界，但扩张依赖足够的回合预算，且主要落在纠错与长程韧性。
3. **给出几乎可插拔的缓解。** BudgetMix 不换奖励、不换算法，只改训练时预算分布，就能把紧预算档的坍塌补回来。

对 irreversible tool use、数据库写操作、金融下单这类「错一步就贵」的场景，这篇该被当成必读的风险说明，而不是又一篇刷榜笔记。

## 🏗️ 机制：Pass@(K,T)、逐步质量、BudgetMix

### Pass@(K,T)

任务 \(x\)、策略 \(\pi\)、预算 \(T\)、采样 \(K\) 条独立轨迹：

$$
\mathrm{Pass@(K,T)}=\Pr\big(\exists i\in\{1,\ldots,K\}: R(\tau_{\le T}^{(i)})=1\big)
$$

固定 \(K=C\) 扫 \(T\) 得到 Pass@T，专门看交互深度。主文 Pass@T 取 \(k=8\)。

### 训练与任务

| 项 | 设置 |
| --- | --- |
| 算法 | 主线 GRPO；对照 GiGPO、PPO |
| 模型 | Qwen3-4B、Qwen3-8B |
| 任务 | FrozenLake（\(T_{max}=70\)）、DeepCoder-MT（10）、BFCL-v3（24）、InterCode-SQL（10）；附录含 Terminal-Bench（50） |
| 奖励 | 终局 verifier；GiGPO 另有状态锚定的逐步优势 |

### 逐步质量怎么测

DeepCoder-MT：用单测通过率打逐步分。FrozenLake：在剩余预算内用最优延拓算 \(Q^*\)（\(\gamma=0.95\)）。两边都构造基座与 RL 共有的状态池，避免「RL 只去简单状态」的访问偏差。

### BudgetMix

对实例 \(x\) 的满预算 \(T_{max}(x)\)，构造候选集合

$$
\mathcal{T}(x)=\mathrm{Unique}\Big\{\big\lceil k\cdot T_{max}(x)/10\big\rceil:k=1,\ldots,10\Big\},\quad T(x)\sim\mathrm{Uniform}(\mathcal{T}(x))
$$

训练时按抽到的 \(T(x)\) 截断交互；算法与 full-budget 完全相同，可套在 GRPO / GiGPO / PPO 上。评测仍告知模型当前允许的最大回合数。

## 🧪 关键证据

### 现象一：Pass@K 扩张边界，Pass@T 却预算敏感

扫采样宽度时，RL 曲线持续高于基座，作者据此认为多轮 agentic RL **可以**把轨迹级成功推到基座经验 Pass@K 边界之外（与若干单轮 RLVR「不扩张边界」的观察对照）。

但固定 \(k=8\) 扫 \(T\) 时（Figure 3），故事翻面：大预算下 RL 优势明显；紧预算下优势收缩，个别设置持平或反转。示意（论文 Figure 1）：\(T=2\) 时 Base 与 RL 都是 0.56；\(T=3\) 时 Base 0.74、RL 0.84。结论不是「RL 没用」，而是「**它的轨迹级红利以足够的交互深度为前提**」。

### 现象二：逐步质量不全面抬升，纠错更强

| 对照 | DeepCoder-MT | FrozenLake |
| --- | --- | --- |
| 匹配状态上 RL 更好的比例 | 46.8% | 42.8% |
| 错误状态下 RL 更好的比例 | 67.3% | 65.7% |
| 从相同错误态继续的终局成功 | 38.5% vs 22.9%（基座） | 51.3% vs 38.6% |

按归一化深度 \(d_t=t/T_{max}\) 切片：早期 RL 甚至弱于基座，后段差距收窄并反转。Takeaway 写得很干脆：多轮 agentic RL **并不稳定地提升单步决策质量**；优势集中在错误态与轨迹后段。

### 现象三：局部动作仍像基座，轨迹偏好在累积

Terminal-Bench 上，把 RL 与基座动作放回基座策略算 Action NLL：均值 12.20 vs 10.25，分布大幅重叠，说明单步并不「离经叛道」。完整轨迹的 cumulative LLR 却向 RL 策略偏移，成功轨迹尤甚。作者解读：多轮 RL 更像在学「如何把整条轨迹走完」，而不是每一步都换一套更优原子动作。

### 训练动态：轨迹奖励涨、逐步奖励可跌

DeepCoder-MT 上 full-budget RL：\(R_{multi}+0.331\)，\(R_{single}-0.097\)。BudgetMix：\(R_{multi}+0.323\)，\(R_{single}+0.006\)。也就是说，只优化终局时，模型可以靠「后面再救」换轨迹成功，代价是局部决策变糙；混预算训练能挡住这条捷径。

### BudgetMix 主结果（Pass@8，%）

## 🔬 最有意思的部分

1. **和单轮 RLVR 叙事的裂缝。** 单轮文献常说 RL 主要重加权已有解；这里 Pass@K 显示多轮设定可以扩张轨迹级边界。但扩张不等于「每一步都更强」，而是更会在长交互里恢复。
2. **错误态才是 RL 的主场。** 全体匹配状态上 RL 甚至略弱；一限制到错误态，优势立刻清晰。若你的线上分布很少给第二、第三次机会，榜上的 RL 增益可能大部分兑现不了。
3. **BudgetMix 把评测轴变成训练轴。** Pass@(K,T) 里的 \(T\) 不再只是测的时候扫一圈，而是训练分布本身。改动极小，却同时稳住紧预算表现和逐步奖励。
4. **提示词里写明剩余回合。** 训练和评测共用预算感知模板（`[MAX TURNS]` 等）。预算稳健性不只是采样问题，也是「模型知不知道自己还剩几步」的条件化问题。

## 🤔 我的判断

**定位：一篇机制澄清 + 轻量训练补丁的论文；真正的贡献是把「agentic RL 赢在哪儿、输在哪儿」说清楚，并用 BudgetMix 证明预算依赖可以被训练分布部分吸收。**

亮点：

1. **Pass@(K,T) 双轴评测**，避免只用大预算终局成功率叙事。
2. **匹配状态上的逐步质量解剖**，把「纠错 / 长程韧性」从口号变成可复现数字。
3. **BudgetMix 几乎零侵入**，可挂在现有 GRPO / GiGPO / PPO 上。

问题与局限：

- **任务仍偏可重置环境。** FrozenLake、交互代码、工具调用与真实不可逆生产操作仍有距离；作者自己把金融 / 数据库写成动机，实验并未直接覆盖。
- **逐步质量依赖可算的 \(Q^*\) 或单测**，BFCL 等只能靠案例与 LLM judge 辅助，过程监督结论是初步的。
- **BudgetMix 是均匀离散比例**，不是针对部署预算分布的最优设计；更细的课程或自适应预算未展开。
- **主结果以 Pass@8 报告**，与线上「只跑一条轨迹」的体验仍有缝。
- **模型规模停在 4B/8B**，更强基座上「逐步质量是否仍不涨」需要再测。

对工程的直接启发：

- **上线前按目标预算扫 Pass@T**，不要只报满预算分数。
- **区分「终局成功率」和「单步保守性」**；不可逆工具链应单独测错误态恢复与首步质量。
- **训练时混合交互预算**，哪怕只是均匀抽 \(T_{max}\) 的比例档。
- **系统提示写明剩余 / 最大回合**，让策略条件化在真实约束上。
- **过程奖励缺真值时别迷信算法名**；先问监督信号是否在该任务上可及。

一句话收束：**多轮 RL 教给 agent 的，常常是「走远了怎么把自己捞回来」，而不是「每一步都更稳」；BudgetMix 则是提醒它：捞回来的机会，训练时就别默认总有。**
