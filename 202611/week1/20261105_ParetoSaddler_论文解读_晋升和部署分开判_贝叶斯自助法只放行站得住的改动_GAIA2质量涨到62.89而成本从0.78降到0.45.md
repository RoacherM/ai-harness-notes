# 自动改 harness 时，一个变贵了的补丁该不该留？ParetoSaddler：把「值得继续探索」和「值得上线」分开判，GAIA2 质量 56.22→62.89、单任务成本 $0.78→$0.45

你有没有过这种体验：让一个优化器自动改 agent 的 prompt、skill、工具描述，你给它定了规矩「既要分数高，又不能更贵」。结果它提了一个补丁，修好了 agent 动不动提前收工的毛病，分数涨了，成本也涨了一截，按规矩当场被拒。后面本可以在这个补丁上继续砍掉冗余调用的那条路，也就再没人走了。

这就是 **自动 harness 优化（AHO, automatic harness optimization）** 走到「质量加成本」双目标时最容易踩的坑：**部署偏好应该在中间每一步都当硬门槛用，还是只在最后挑方案时才用？** 另一个更隐蔽的坑是：同一个 harness 跑三次，分数和花费都可能差一大截，你看到的「涨了」可能只是运气。

Microsoft 与 UCL 等机构的 **ParetoSaddler** 把这两件事分开处理：中间晋升只看「质量或成本至少一边有站得住的进步」，用 Bayesian bootstrap 判这个进步站不站得住；部署偏好留到预算花完再用。看完我的感受是：**这其实就是一道带统计检验的验收门，只不过它刻意把门槛分成了两层。**

## 核心摘要

ParetoSaddler 面向冻结模型权重、只改 harness（prompt、工具、中间件、控制逻辑）的分阶段优化。每轮优化器从父 harness 生成候选，父子在同一小批训练任务上各重复执行 R 次，得到成对的质量与成本观测；再用 Bayesian bootstrap（对每个任务的 R 次执行抽 Dirichlet 权重，质量和成本共用同一组权重）估计「候选在质量上变好且成本没失控，或成本下降且质量掉得不超过允许值」的支持度，支持度达到 γ 才晋升到更大的开发集评估。被评过的候选全部留作后续父代，而部署偏好（Pareto 集、或在质量下限内最小化成本）只在最后挑选时生效。在 ClawMark（OpenClaw + GPT-5.4）和 GAIA2（ReAct 默认 harness + GPT-5.5）的领域不相交划分上，质量端最优方案把 ClawMark 从 70.86% 提到 81.35%、成本从 $1.17 降到 $1.01，把 GAIA2 从 56.22% 提到 62.89%、成本从 $0.78 降到 $0.45；它还比只优化质量的 AutoSaddler 基线高 7.49 分（ClawMark）和 5.56 分（GAIA2），同时更便宜。消融显示：换成按部署偏好做局部门槛，晋升数从 11 个降到 3 个，并卡在相似的成本墙附近；换成按均值比较的门，测试端质量明显更低。这篇的价值不在又涨了几分，而在于给「harness 演化的验收门」提供了一个可照抄的统计配方。

## 🎯 为什么这件事值得写

过去这一轮 harness 优化工作（Meta-Harness、AutoSaddler、GEPA 一系）的共同点是：模型冻住，只改外面那层；目标几乎都只有质量。但真部署时，每个任务花多少 token 钱和分数一样要紧。

把成本加进来，不只是目标函数多一项。作者点出一个结构性的错配：

1. **分阶段评估本身就在做「谁能活下去」的决定。** 小批筛选不只是省评估钱，它决定了哪些中间 harness 还能被当父代继续改。
2. **长程 agent 的成本和进度是耦合的。** 一个 harness 看起来便宜，可能只是因为它总在半路收工；修好这个毛病的补丁必然让成本上涨。用部署偏好在这一步硬卡，会把后面本可以「先变强再变省」的路径剪掉。
3. **执行是随机的。** 附录里在 20 个 ClawMark 开发任务上，同一 harness 重复执行的任务内变异系数质量为 18.8%、成本为 25.6%。只看均值的比较，很容易把运气当进步。

所以这篇回答的是两个问题：**中间哪些移动值得保留？这些移动在统计上站得住吗？** 这两个问题，对任何做「冻结模型 + 自动演化 harness」的人都绕不过去。

## 🏗️ 机制：两层门 + 统计晋升

### 问题设定

harness 记作 $h$，底座模型 $m$ 全程固定。每条轨迹给出质量 $q(\tau)\in[0,1]$ 和成本 $c(\tau)$，成本按新输入、缓存输入、输出 token 分开计价：

$$
c(\tau)=\sum_{j=1}^{M(\tau)}\left(\rho_{\mathrm{in}}T_{j,\mathrm{in}}+\rho_{\mathrm{cache}}T_{j,\mathrm{cache}}+\rho_{\mathrm{out}}T_{j,\mathrm{out}}\right)
$$

部署偏好 $\pi$ 有三种形态：加权和、约束优化（比如质量不低于 $Q_{\min}$ 时最小化成本）、Pareto 集。论文实验覆盖后两种。

### 一轮迭代

```text
选父 harness h_t
  → 优化器读执行轨迹，生成候选 h'_t
  → 父子在同一小批训练任务上各跑 R 次
  → Bayesian bootstrap 估计晋升支持度 p̂_t
      p̂_t ≥ γ：晋升，跑开发集，加入已评集合 V 和 Pareto 档案 A
      否则：不晋升
  → V、A、累积状态和 π 一起引导下一个父代
预算用完 → 才用 π 在 V 上挑最终 harness
```

### 统计晋升规则

每次 bootstrap 抽样 $j$，对每个筛选任务、每个 harness，在它的 R 次执行上抽 $\operatorname{Dirichlet}(\mathbf{1}_R)$ 权重，质量和成本用同一组权重，再按任务等权平均。然后计算质量差 $\Delta Q$ 和相对成本变化 $\Delta C$，判定这一抽是否支持晋升：

$$
E^{(j)}=\bigl[\Delta Q^{(j)}>0\land\Delta C^{(j)}\le\epsilon_C\bigr]\lor\bigl[\Delta C^{(j)}<0\land\Delta Q^{(j)}\ge-\epsilon_Q\bigr]
$$

$$
\widehat{p}=\frac{1}{J}\sum_{j=1}^{J}\mathbf{1}\{E^{(j)}\},\qquad \text{晋升}\iff \widehat{p}\ge\gamma
$$

关键在那个「或」：**任一目标上有可信进步就放行**，不要求它当下已经满足部署偏好。$\epsilon_Q,\epsilon_C$ 只是防止另一边严重退化的松护栏。

### 实验里的具体参数

| 参数 | 取值 |
| --- | --- |
| 每任务执行次数 R | 3 |
| bootstrap 抽样数 J | 10,000（蒙特卡洛标准误不超过 0.005，不额外调用 LLM） |
| 晋升阈值 γ | 0.7（事先固定） |
| 局部质量损失允许 $\epsilon_Q$ | 0.1 |
| 局部成本上涨上限 $\epsilon_C$ | 不设（$+\infty$），理由是成本上涨可能反映真实进度 |
| 训练小批 | 3 个任务 |
| 优化器 | GitHub Copilot SDK + GPT-5.5（xhigh） |
| PS-MinCost 质量下限 | 不低于初始 harness 10 个百分点以内 |

实现上它套在 AutoSaddler 之上：同一个小批既用于生成补丁也用于筛选，父代的执行可以复用。

## 🧪 关键证据

### 主结果：领域不相交的测试集

ClawMark 按场景划分（训练 50 / 开发 20 / 测试 22 个任务），GAIA2 按 Universe 划分（训练 U29 75 个 / 开发 U30 65 个 / 测试 U21、U22、U27 共 300 个）。

| 设定 | ClawMark 质量 | ClawMark 成本 | GAIA2 质量 | GAIA2 成本 |
| --- | --- | --- | --- | --- |
| 默认 agent | 70.86 | $1.17 | 56.22 | $0.78 |
| AS-Quality（只优化质量） | 73.86 | $1.24 | 57.33 | $0.61 |
| MH-MinCost | 70.02 | $1.16 | 39.78 | $0.62 |
| MH-Pareto Q | 73.25 | $1.06 | 54.33 | $0.83 |
| PS-MinCost | 75.16 | $0.82 | 56.11 | $0.44 |
| PS-Pareto C | 79.60 | $0.92 | 62.11 | $0.47 |
| **PS-Pareto Q** | **81.35** | $1.01 | **62.89** | $0.45 |

几条读法：

- PS-Pareto Q 在 ClawMark 上质量相对涨 14.8%、成本降 13.7%；在 GAIA2 上质量相对涨 11.9%、成本降 42.3%。
- **加了成本目标，质量反而比只优化质量的基线更高**：ClawMark 高 7.49 分，GAIA2 高 5.56 分。作者自己也说这「有点出乎意料」。
- PS-MinCost 把成本压到 ClawMark $0.82、GAIA2 $0.44，并在两个基准上质量和成本都优于 MH-MinCost（GAIA2 上 MH-MinCost 质量掉到 39.78）。
- GAIA2 另跑了一次独立优化（Run 2），两个端点总体质量 61.44% 到 62.22%、成本 $0.44 到 $0.46，结论没翻。

### RQ1：晋升门换成部署偏好会怎样

在 PS-MinCost 里把 Pareto 晋升换成「必须成本下降」的局部 MinCost 门（保留重复执行和 bootstrap）：

| 晋升门 | 晋升候选数 | 结果 |
| --- | --- | --- |
| Pareto 门 | 11 | 测试端更好的工作点 |
| MinCost 局部门 | 3 | 卡在相似的成本墙附近 |

转折点是 I-11：小批质量 83.65%→87.62%，成本涨 10.5%。MinCost 门会拒，Pareto 门放行，后面才有 I-14、I-16。

另一个例子 I-7：父代在三个小批任务的三次执行里全是满分，I-7 小批成本降 17.22%、质量掉 1.33 分，只看质量的门会拒；放行后在开发集上质量 72.94% 对 72.27%、成本 $0.88 对 $1.13，两边都更好。GAIA2 的 I-9、I-17 更极端：父子筛选质量都是 100%，只看质量的门因为要求严格提升而必然拒绝，Pareto 门支持度 1.0 放行，开发集上两项都改善。**局部质量饱和，不代表 harness 已经没东西可改。**

### RQ2：每任务跑 3 次 vs 跑 1 次

| 设定 | 质量 | 成本 |
| --- | --- | --- |
| 单次 C | 76.95 | $0.95 |
| 单次 Q | 75.71 | $0.97 |
| 三次 C | 79.60 | $0.92 |
| 三次 Q | 81.35 | $1.01 |

作者诚实注明：三次执行必然花更多执行预算，这不是算力对齐的比较，只能解读为「重复执行支撑的优化协议」整体更好。

### RQ3：Bayesian 门 vs 均值门

| 设定 | 均值门 质量 / 成本 | Bayesian 门 质量 / 成本 |
| --- | --- | --- |
| PS-Pareto C | 76.86 / $1.09 | 79.60 / $0.92 |
| PS-Pareto Q | 76.53 / $1.15 | 81.35 / $1.01 |

回放同一批 17 个候选，均值门会晋升 14 个，Bayesian 门 12 个。

### 优化器自身的账

GAIA2 上每个补丁的优化器成本：PS-Pareto $9.62、AS-Quality $6.01、MH-Pareto $5.42；PS-MinCost $8.02、MH-MinCost $3.58。ParetoSaddler 的优化侧更贵，换来的是测试端更好的质量成本点。

## 🔬 最有意思的部分

1. **I-12：均值说「可以」，分布说「不行」。** 这个候选小批平均质量掉 5.55 分、成本降 7.19%，落在允许范围内，均值门会放行。但拆开看，几乎所有成本下降都来自一个任务（Research assistant 4），而这个任务的质量从三次全 100 掉到 13、67、87；另外两个任务反而变贵了。bootstrap 支持度只有 0.55，低于 0.7。事后开发集评估证实：I-12 比父代差 2.80 分、贵 10.66%。**这就是统计门比点估计门值钱的地方：它看得见「平均数掩盖的单点崩坏」。**

2. **故意不设成本上涨上限。** $\epsilon_C=+\infty$ 看着激进，背后的逻辑很工程：修好提前终止必然变贵，这种上涨事先没法估。这等于承认在长程 agent 里，成本不是越低越好，而是要和进度一起看。

3. **重复执行本身就是诊断材料。** 附录列了几类只有多跑几次才看得见的证据：三次都满分但成本是 $0.72、$1.58、$0.69，贵的那次多了三次子 agent 派生调用；用药差异检查 P/F/F，第一次过、后两次漏；出租车报销金额检查 F/F/F，才算系统性缺陷。补丁后前者恢复到三次都满分且成本收窄，用药检查失败从 2/3 降到 0/3，报销检查从 3/3 降到 2/3。作者特意提醒，这些是描述性证据，不是单个编辑的因果估计。

4. **最终改动全是可读的文本和小代码。** ClawMark I-16 相对初始 harness 改了 6 个 skill 和源文件：gog、mcporter、notion、openai-whisper 的 SKILL.md，system-prompt.ts，image-tool.ts。内容多是「先产出必需交付物再做可选探索」「限制 schema 探测」「独立问题保留为独立证据行」这类。PS-MinCost 那次运行则动了 15 个文件，包括把超过 20,000 字符的 MCP schema 输出压到最多 80 个函数签名。**分数涨的来源，是一堆可审计的 harness 补丁，而不是权重。**

## 🤔 我的判断

**定位：冻结模型 harness 演化的「验收门」方法论文；核心贡献是两层门（探索晋升 vs 部署选择）加 Bayesian bootstrap 统计晋升，而不是新的补丁生成器。**

亮点：

1. **把晋升和部署拆开，有干净的对照。** MinCost 局部门只晋升 3 个，Pareto 门 11 个，测试端差距明显；这不是只靠观察性案例讲故事。
2. **统计门有可复现的细节。** 成对执行、共用 Dirichlet 权重、γ 事先固定为 0.7、J=10,000、阈值敏感性回放显示 0.7 落在局部稳定区。直接可以搬进自己的 eval 流水线。
3. **双目标没有牺牲质量。** PS-Pareto Q 在两个基准上都比只优化质量的基线更高更便宜，打掉了「省钱一定掉分」的默认假设。

问题与局限：

- **R=3 很小。** 作者自己承认罕见结果可能看不到，靠近阈值的候选的支持度估计对观测到的几次执行很敏感。
- **测试集不大。** ClawMark 测试只有 22 个任务，标准差在 2 到 3 分级别，部分差距要谨慎看待；跨运行稳定性只在 GAIA2 上补跑了一次。
- **单次运行三次的消融不对齐算力。** RQ2 的结论是「协议更好」，不是「每多一次执行值多少」。
- **优化侧更贵。** GAIA2 上每个补丁的优化器成本是对应基线的约 1.6 到 2.2 倍，部署量小的场景未必划算。
- **只算 token 钱。** 不评估安全、隐私、公平；作者明确说质量和成本改善不代表可以放心部署到真实环境。
- **ClawMark 被改过。** 为并行评估做了 Notion 根目录隔离、按 ID 查资源等适配，作者称不改变任务目标与评分标准，但复现时要注意。

对工程的直接启发：

- **自动改 harness 的流水线，晋升门不要直接等于上线门。** 中间放宽到「任一目标有可信进步」，上线时再用业务偏好挑。
- **父子必须在同一批任务上成对重复执行。** 至少 3 次，用 bootstrap 支持度而不是均值差做判定，阈值事先写死。
- **门要能看见单任务崩坏。** I-12 这种「均值过关、单任务塌方」的情况，就是统计门该拦下的典型。
- **成本上涨不要一刀切。** 修复提前终止类问题时，允许局部变贵，给后续补丁留出压缩冗余的空间。
- **把补丁当代码审。** 最终产物是 SKILL.md 和 system prompt 的 diff，配合 git 和评审流程，比黑盒权重好管得多。

一句话收束：**ParetoSaddler 把 harness 演化里最容易被拍脑袋的那一步，「这个补丁留不留」，变成了一道有统计支持、分两层判的验收门；它省下的钱和涨出的分，都来自不过早地替未来做决定。**
