# 技能卡什么时候该撤：每组 rollout 随机藏一张做对照，出题只挑撤卡后还分得出胜负的题，零技能部署 ALFWorld 从 47 涨到 90

给多智能体编排器喂技能卡（skill card）已经是很常见的做法：一张卡写着「多跳问答先拆子问题」，另一张写着「代码题先写测试」，编排器看到对应任务就按卡上的套路搭 agent 图。卡越写越多，效果也确实越来越好。

但这里藏着一个很少被追问的问题：**这些卡是在教编排器，还是在替编排器做事？** 如果撤掉所有卡以后编排器就不会了，那训练出来的其实是一个「会读卡的执行者」，不是一个学会了编排的模型。部署时卡要占上下文、要维护、换个领域还得重写。更麻烦的是，你很难知道哪张卡已经被模型吸收了、可以撤，哪张卡还在起作用。

港中大（深圳）、复旦、UIUC、清华和 NUS 合作的 **R²Orch: Recursive Learnability and Skill Withdrawal for Self-Play Orchestration**（arXiv:2610.22740）给了一个很漂亮的回答：**每组 rollout 都随机藏起一张卡，藏和不藏的结果一对比，就是这张卡此刻的边际价值；价值降到零附近就撤掉，撤掉后还会抽查，必要时请回来。** 最终部署时一张卡都不带，在 12 个基准上都比所有带技能的基线高。

## 核心摘要

R²Orch 训练一个 Director 模型，它通过一串原子编辑（加 agent、设提示词、设模型、设层级、声明关系、删 agent、设输出、结束）搭出一张多智能体图，交给冻结的 Worker 执行。另一个 Proposer 负责从任务池里挑题。内层是用 GRPO 做的自博弈，外层是技能撤除（Skill Withdrawal）。

两层由同一个设计串起来：**每个 GRPO 组的五条 rollout 被随机分成两份，三条看不到某张候选技能卡（隐藏组），两条能看到（可见组）。**

- 对 Director 来说，五条都是普通的组内样本，照常算组相对优势。
- 对 Proposer 来说，它的奖励只看隐藏组：用收缩后的 Beta 估计算隐藏组成功率 p，奖励是 4p(1−p)。也就是说，它被鼓励去挑**撤掉技能以后仍然分得出胜负**的题，而不是那些带着卡才能做、或者怎么都做得出的题。这就是论文说的「递归可学性」（Recursive Learnability）：可学性是针对**当前**脚手架下撤掉技能的那个版本来定义的，随着技能被撤，标准会一起变。
- 对技能撤除来说，可见组均值减隐藏组均值 z 是这张卡边际贡献的无偏估计。每张卡维护一个贝叶斯自助法后验，用 Thompson 采样决定下一次测哪张。后验显示正向贡献的期望不超过 0.02、并且至少测了 12 次，就撤卡；被撤的卡在 30% 的任务上会重新测试，显著有用就恢复。

整个选择过程不额外花一次 rollout。用 Qwen3.5-9B 做全部角色，零技能部署时 ALFWorld 从直接作答的 47.19 涨到 90.63，SWE-Bench 从 15.78 涨到 42.81，12 个基准上都高过最强的带技能基线。

## 🎯 为什么这件事值得写

技能卡和课程学习单独看都不新鲜，难点在于它们会互相干扰：

1. **课程信号被技能污染。** 常规的可学性课程（挑成功率在 50% 附近的题）看的是带技能时的表现。一道题带卡能做一半，撤卡可能一道都做不出来，按这个标准它很「可学」，但学到的只是读卡。
2. **技能贡献没有便宜的测量方法。** 想知道一张卡有没有用，常规做法是单独做消融，带卡跑一批、不带卡跑一批，成本翻倍，而且模型每一步都在变，昨天的消融结论今天就可能过期。
3. **撤卡缺少安全网。** 撤早了会掉分，撤晚了模型永远依赖它。已有方法用固定的预算（SKILL0）、阈值（PATS）或验证集差距（SLIM）决定撤卡，都没有不确定性估计，也很少考虑撤错以后恢复。

R²Orch 的回答是把「测技能贡献」嵌进训练本身：反正每组都要跑五条 rollout，随机藏卡就能顺手得到对照实验。

## 🏗️ 机制：一组 rollout，三种用途

### 编排是一串原子编辑

Director 不直接写答案，而是输出一串编辑动作来搭一张 agent 图：AddAgent 加节点，SetPrompt 和 SetModel 设定每个 agent 的提示词和模型，SetLayer 安排执行层级，ConsiderRelation 声明节点间的依赖，DeleteAgent 删节点，SetOutput 指定输出，Finish 结束。冻结的 Worker 按这张图执行，最终结果按任务的评测标准打分。这样一来，「编排能力」就是一个可以用强化学习训练的序列决策问题。

### 隐藏组和可见组

每个 GRPO 组 5 条 rollout，随机分成 3 条隐藏、2 条可见。被测试的那张候选技能卡只出现在可见组的上下文里。

| 使用者 | 怎么用这一组 rollout |
| --- | --- |
| Director | 五条都算普通组内样本，正常算组相对优势 |
| Proposer | 只看隐藏组，奖励是撤卡后可学性 4p(1−p) |
| 技能撤除 | 可见组均值减隐藏组均值，作为这张卡边际贡献的样本 |

### Proposer 的奖励：递归可学性

Proposer 的奖励是 ℓ(p) = 4p(1−p)，p 是隐藏组成功率的收缩 Beta 估计（先验强度 m=2，避免三条样本时估计太跳）。p=0.5 时奖励最高，p=0 或 1 时为零。另外两个修正：如果只有可见组成功、隐藏组全失败，奖励打五折（γ=0.5），说明这题靠卡才能做；如果整组塌缩成全对或全错，额外扣 0.2（λ_P=0.2），因为塌缩组对 GRPO 没有梯度。

「递归」体现在：随着技能被撤，脚手架变了，同一道题的撤卡成功率也变了，Proposer 的选题标准会自动跟着移动。

### 技能撤除：带不确定性的边际价值

每张卡的贡献样本 z = ȳ可见 − ȳ隐藏。由于组内是随机分配的，这是一个无偏的 Neyman 估计。每张卡在最近 30 个周期的窗口里用贝叶斯自助法采 2,000 次，得到边际贡献的后验，再用 Thompson 采样决定这一轮测哪张卡，越不确定的卡越容易被测到。

| 决策 | 条件 |
| --- | --- |
| 撤卡 | 正向贡献的后验期望 E[Δ+] ≤ ε=0.02，且样本数 n ≥ 12 |
| 恢复 | 被撤的卡在重测时显著有用（q ≤ α=0.05） |
| 重测 | 30% 的任务用于重测已撤的卡 |
| 改卡 | LLM 编辑器修改最没用的卡；从隐藏组和可见组都失败的组里提炼新卡 |

整个机制不需要额外 rollout，测量成本完全摊在训练里。

### 训练配置

Director、Proposer 和 Worker 都用 Qwen3.5-9B，LoRA rank 64，Director 更新 200 次，每个周期 24 道题。每个数据集起始有 3 张人工编写的种子卡。每个测试集 128 题（AIME 是 30 题），结果是 5 次运行的平均。

### 消融：每个零件都有用

零技能部署时的成绩（AIME / ALFWorld / WebShop）：

| 变体 | AIME | ALFWorld | WebShop |
| --- | --- | --- | --- |
| 只用 GRPO | 59.33 | 73.44 | 71.72 |
| 训练时不给技能 | 64.00 | 77.81 | 76.09 |
| 固定脚手架 | 66.67 | 77.81 | 76.09 |
| Proposer 均匀选题 | 66.67 | 86.88 | 87.03 |
| Proposer 按失败率奖励 | 64.00 | 84.06 | 83.13 |
| 可学性按当前脚手架算（不藏卡） | 70.67 | 86.88 | 85.94 |
| Proposer 改用 DAPO 式动态采样 | 68.67 | 87.50 | 87.81 |
| 撤卡规则换成 PATS 阈值 | 74.67 | 87.81 | 87.66 |
| 撤卡规则换成 SKILL0 预算 | 70.67 | 86.09 | 85.00 |
| 撤卡规则换成 SLIM 验证差距 | 72.67 | 88.28 | 89.22 |
| 完整 R²Orch | 81.33 | 90.63 | 91.09 |

几个值得注意的对比：

- **可学性在哪个脚手架上算很重要。** 同样是 4p(1−p) 奖励，按带卡的当前脚手架算只有 70.67，按藏卡的隐藏组算是 81.33，AIME 上差了十个多点。
- **撤卡规则是关键。** 把撤卡规则换成另外三种已有方法，AIME 掉 6.7 到 10.7 点。
- **训练时干脆不给技能也不行。** 64.00，说明技能卡在训练早期确实在起作用，问题只是什么时候撤。

### 训练过程中发生了什么

- **零技能准确率在训练中途反超带技能准确率。** 也就是说，过了某个点以后，卡反而成了干扰。
- **Proposer 学会了挑中等难度的题。** 隐藏组成功率在中间的题进入「有对有错」组的频率约是 p=0 或 1 的题的 4 倍，训练后的 Proposer 也学会跳过已经稳定做对的题。
- **撤卡都很保守，也确实会恢复。** 全部 12 次撤卡都满足 E[Δ+] ≤ 0.019；MedQA 的一张拓扑卡在第 6 个周期被撤，后来又被恢复。

### 换 Worker 也能用

训练好的 Director 不重新训练，直接调度另外 6 个后端模型（deepseek-v4-flash、gemini-3.5-flash、gpt-5.6-luna、grok-4.5、claude-haiku-5-5、glm-5.3-flash）都有提升，分布内基准上不同后端之间的分数极差从 25.7 点缩小到 6.4 点。也就是说，编排能力在一定程度上抹平了 Worker 之间的差距。

## 🔬 最有意思的部分

1. **对照实验是免费的。** GRPO 本来就要一组多条 rollout，把它随机切成藏卡和不藏卡两份，Director 的训练信号不受影响，却顺手得到了一个随机对照实验。这是把「评测」嵌进「训练」的一个非常干净的例子，比事后单独做消融便宜得多，而且永远是针对当前模型的。
2. **课程和撤卡用的是同一个量。** Proposer 挑的是撤卡后分得出胜负的题，撤卡规则看的是撤卡前后的差。两者都围绕「如果没有这张卡会怎样」这个问题，课程自然地推着模型去学卡上的东西，撤卡规则负责确认学会了。
3. **撤卡要可逆。** 30% 的任务专门重测已撤的卡，MedQA 拓扑卡被撤又被请回来。很多技能治理方案只考虑「什么时候删」，不考虑「删错了怎么办」，这里给了一个具体的答案。
4. **可以直接借鉴到技能库治理。** 我们日常维护 agent 的技能库也面临同样的问题：技能越积越多，哪些还有用没人知道。随机藏一部分技能、对比有无差异、带不确定性地决定去留，这套方法不依赖 RL，在线 A/B 也能做。

## 🤔 我的判断

**定位：一个在统计设计上很讲究的技能治理方案。它把「技能卡何时可以撤」变成一个带不确定性估计、可逆、零额外成本的在线因果推断问题，思路可以迁移到任何带技能库或提示片段的 agent 系统上。**

亮点：

1. **因果估计做得规范。** 组内随机分配保证无偏，贝叶斯自助法给出不确定性，Thompson 采样平衡探索，撤卡要求最小样本数，规则清清楚楚。
2. **消融全面。** Proposer 的选题目标、撤卡规则、脚手架是否固定都换过一遍，每个零件的贡献都有数据。
3. **零技能部署是一个干净的目标。** 部署时不带卡，节省上下文，也不再需要维护卡片。
4. **代码开源，后端迁移实验也有说服力。**

问题与局限：

- **起始技能卡是每个数据集人工写的三张。** 作者也承认这一点。如果卡写得不好，或者一个领域根本没人写卡，整套方法的起点就不成立。分布外基准用的是什么卡、卡和测试任务有多接近，值得仔细看。
- **每组只有 5 条 rollout，隐藏组只有 3 条。** 单次的贡献估计噪声很大，全靠多周期累积和后验平滑，对奖励稀疏、方差大的任务能不能稳定工作，论文证据有限。
- **基线的分数提升幅度大得惊人。** NQ 的 EM 从 23.59 到 86.09，TriviaQA 从 44.53 到 95.31，这样的涨幅一部分来自编排本身（检索、多 agent 验证），不全是技能撤除的功劳。和「直接作答」比不完全公平，更应该看和 PATS 这类带技能基线的差距，那些差距是几个点量级。
- **测试集每个只有 128 题（AIME 30 题），** 几个点的差异要结合标准差看。
- **撤卡阈值 ε=0.02 和 n≥12 是固定的超参数。** 不同任务的噪声水平不同，同一个阈值未必都合适。

对工程的直接启发：

- **维护技能库时，随机藏一部分技能做对照。** 线上流量里随机对一小部分请求隐去某个技能，对比结果差异，比拍脑袋决定删哪个可靠得多。
- **删技能要有恢复机制。** 被撤的技能定期在小比例流量上重新测试，发现掉分就请回来。
- **评估技能贡献时带上不确定性。** 只看均值差容易被几次运气误导，至少要有最小样本数和置信区间。
- **训练或挑选任务时，按「去掉辅助后的表现」来衡量难度。** 带着提示能做、去掉就不会的题，才是最该练的题。

一句话收束：**技能卡最好的结局是被模型吸收以后撤掉；R²Orch 说明，只要每组 rollout 都随机藏起一张卡，就能免费知道它什么时候可以撤，撤错了也能请回来。**
