# 诊断对不对别看标注看回放：换掉一步动作让原 agent 接着跑，事后最会诊断的模型盯现场反而垫底

你有没有过这种体验：agent 跑挂了一个六十多步的任务，你把轨迹丢给另一个大模型做「根因分析」，它写得头头是道：第 43 步漏发了邮件，第 34 步没查订单。你点头称是，然后发现自己根本没法验证它说得对不对。换个模型来分析，它指向另一个步骤，理由也一样通顺。

**一份诊断写得像不像对的，和照着它改了之后能不能成功，是两件事。**

失败归因（failure attribution）这条线，从 Who&When 到 Who&When Pro、LongRCA、TraceElephant，打分方式基本都是和人或模型给的「决定性步骤」标注比对。论文引用 Naagarajan 和 Streif 的结果：在现有套件上，永远指最后一步就有 67% 到 96% 的正确率。Jeremy Canale 和 Fabien Soulis 的 **ReplayRCA: Measuring Post-hoc Diagnosis and Live Oversight of Agent Failures by Counterfactual Replay**（arXiv:2610.41025）换了一个真值标准：把环境精确恢复到那一步之前，用诊断者给的动作替换 agent 自己的动作，让同一个 agent 接着跑，看能不能成功；再减去一个配对的安慰剂，扣掉 agent 本来就会自己恢复的那部分。

看完我的感受：这是一篇典型的「把裁判换成回放」的测量论文，判官和标注全部从打分路径里拿掉了。它最值得 harness 工程师记住的结论是：**事后诊断强的模型，不一定是好的现场监督者**，而一个小的开源模型可能就够当监督者。

## 核心摘要

ReplayRCA 的打分规则叫因果修复（causal repair）：诊断者给出一个步骤和一个替换动作，环境恢复到该步之前的状态（重放之前所有动作并逐字节校验每个观察），执行替换动作，同一个 worker 用相同设置接着跑 k = 5 次；再在同一步重放 worker 自己原来的动作，也接着跑 5 次作为安慰剂；两者成功率之差就是得分。同一套协议有两条赛道：事后尸检，诊断者看到完整失败轨迹并被告知它失败了；现场监督，监督者逐步看着运行，在每个不可逆动作前决定放行还是替换一次，不知道结局，混入本会成功的运行来测误报，每次干预扣 5 分。环境 OpsWorld 是确定性、按种子生成的电商后台模拟，15 个工具、三个任务族、六个难度级，第 6 级把信息放进二维码、照片和手写。在 62 个经过校准的系统性失败上，13 个前沿模型里最高的 Grok 4.7 达到 +51.3 点，但 78 对两两比较在多重比较校正后没有一对显著，排名不是可靠的层级；两家最大厂商的旗舰 GPT-6 Astra 和 Claude Fable 5.1 排第 8 和第 12（Claude 系列没跑到最高推理档）；5 个题没有任何模型修好。强迫模型只在最后一步干预会让它少 17.1 点，标注式基准里的「最后一步」捷径在这里失效。在 87 次运行的现场赛道里，两个最好的监督者分不出高下，其中一个是小的开源模型 DeepSeek V4.1 Flash；事后诊断名列前茅的 GPT-6.1 Sol 是最弱的现场监督者，同一批运行上差了 14.5 点（p = 0.002）。

## 🎯 为什么这件事值得写

作者指出标注式失败归因有两个问题。一是标注本身可争议：标注者的「决定性步骤」是一个判断，另一个同样有效的修复点会被判错。二是标注式分数容易被结构性捷径刷：永远选最后一步就能拿很高的分，只有在能用回放确认决定性步骤的那部分失败上，这种捷径才降到接近随机。

回放式反事实重执行本身不新，AgenTracer、Causal Agent Replay、CausalFlow、REFLECT、SymTrace 都用过，作者也明说不声称原创。区别在于：那些工作里回放服务于它们自己的方法；ReplayRCA 把回放当成评测任意诊断模型的打分规则，每个分数都相对于同一步的配对安慰剂（作者说以上工作都没报告这个），同一批失败和同一个指标同时服务事后和现场两条赛道，环境可程序化生成并校验恢复。作者也坦白，这个分数衡量的是「有效干预」，比根因归因更窄、更可操作。

这对 harness 很实用：我们越来越多地在不可逆动作前放一个监督者或审批器，而挑选它的依据往往是它在事后分析任务上的表现。这篇正好检验了这个挑法靠不靠谱。

## 🏗️ 机制：一个动作、一次回放、一个安慰剂

**1. 设定。** worker 智能体 $\pi_w$ 在确定性环境里用工具行动，轨迹 $\tau = (a_1, o_1, \dots, a_T, o_T)$，结束后检查器 $C$ 把最终环境状态和任务的预期效果比较，给出 $y \in \{0, 1\}$。环境状态是一个普通数据结构，恢复 $s_{t-1}$ 就是从初始状态重放 $a_1, \dots, a_{t-1}$，实现里会逐字节校验每个观察都复现了，才允许干预。

**2. 因果修复。** 干预是一对 $(t, a')$。恢复到 $s_{t-1}$，执行 $a'$ 并把观察追加进 worker 上下文，同一个 worker 接着跑到宣布完成或耗尽步数预算：

$$\hat{\rho}(t, a') = \frac{1}{k}\sum_{j=1}^{k} Y_j(t, a') - \frac{1}{k}\sum_{j=1}^{k} Y_j(t, a_t)$$

第二项是安慰剂：在同一步通过同样的恢复加继续机制重放 worker 原来的动作 $a_t$。它吸收了 worker 从那一步起自己恢复的概率、被重启本身的影响和采样方差。k = 5，单位是百分点。

**3. 两条赛道。**

| | 事后尸检 | 现场监督 |
| --- | --- | --- |
| 看到什么 | 任务、worker 系统提示、工具列表、完整轨迹（含 worker 打开过的图片），被告知失败了但不说为什么 | 到每个不可逆动作为止的运行，以及待执行的动作 |
| 能在哪里动手 | 任意一步 | 只在检查点，即退款、取消、发邮件、调整库存或最终完成调用之前 |
| 次数 | 一个步骤加一个替换动作 | 每次运行最多干预一次 |
| 计分 | $\hat{\rho}$ | $\hat{\rho} - \lambda \cdot 1[\text{intervened}]$，λ = 5，不干预得 0 |

**4. 为什么只允许一个动作。** 一个替换动作装不下一整套计划。替换动作里的自由文本参数（reason、summary）在执行前被丢弃，其余字符串参数被截断，工具观察也不会回显自由文本，所以诊断者没法给 worker 递纸条，只能通过世界状态影响它。分数因此衡量的是：诊断者是否理解轨迹在哪里还能被掰回来、需要什么信息或动作。

**5. OpsWorld。** 模拟一家网店的后台：客户、订单、退款、内部文档、工单、三个仓库的库存和发件箱。三个任务族都是「漏掉一个事实就做错」的类型：

| 任务族 | 陷阱举例 |
| --- | --- |
| 延迟交付补偿 | 新旧两版政策、阈值和比例、扣掉之前的退款、排除促销订单、同名客户、一份标题不起眼却因罢工改了承诺日期的备忘录、按交付日期顺序套年度上限、工单里的虚假说法 |
| 产品召回 | 批次是带例外的区间、修订备忘录追加一个批次、旧 SKU 编码和组合商品藏着受影响订单、部分订单已全部或部分退款、动作取决于订单状态 |
| 仓损登记 | 更正是替换不是累加、重复报告、不同箱规、仓库别名、在途损坏记在目的仓、部分修复、撤回的报告 |

第 1 到 3 级开固定的陷阱子集，第 4 级随机抽四五个，第 5 级全开，第 6 级再把部分信息挪进图片：订单号只在二维码里、真实交付日期是日在前的手写；重贴的包装标签上印的批次过时，二维码才是准的；拍照的损坏表单上产品只能靠标签二维码识别，有时数量还被手写更正并签了缩写。检查器精确比较最终状态：每单退款精确到分、取消、每个 SKU 每个仓库的净库存变化、必须发出的邮件（收件人和必需内容）。一个从预期效果推导出的 oracle 求解器通过全部生成实例，空策略全部失败，两者都在 720 个实例上验证过。打分路径上没有任何模型判官。

**6. 题库怎么来。** 用小模型当 worker（其中两个开源：DeepSeek V4.1 Flash、Qwen 3.8 Flash），在第 4 到 6 级任务上做了 792 次首次尝试。失败只有在三次独立尝试里至少挂两次才算系统性失败；因基础设施问题或步数耗尽结束的排除，因为一次干预修不了低效。78 个系统性失败和 65 个成功进入校准：在第一个检查点重放 worker 自己的动作 5 次，失败保留自发成功率 ≤ 20% 的，成功保留 ≥ 80% 的。143 个候选里留下 103 个：62 个失败（保留失败的平均自发成功率 3.5%）和 41 个成功。62 个失败平均 66 步（中位数 59，33 到 152），渲染给诊断者平均 14,347 token，最长 57,655。

随机步基线的原始继续成功率是 27.7%，这就是安慰剂从每个分数里扣掉的自发恢复量。78 对两两比较经 Holm 校正后 0 对显著；和 Grok 4.7 相比，不校正时第一个显著更差的是排第 9 的 DeepSeek V4 Pro。区间大约 ±10 点，作者强调前八名不应读成排序，没检测出差异也不等于等价。对每个题挑表现最好的模型，继续成功率是 72.3%（这是对已测模型的 oracle 选择，不是单次修正的上界）；5 个题在所有继续里都没有任何模型修好；35% 的题模型平均修复低于 20 点，19% 高于 80 点。

所有模型都在 64,000 token 的共享输出预算内用各自能用的最高推理档。Anthropic 模型在最高档会把预算填满（Claude Sonnet 5.5 有一次诊断产生了 93,000 推理 token 还没给出答案），所以只能跑 high。消融显示把预算加到 100,000、Claude Haiku 5.5 跑 max 时得 +47.4（推理 47,602 token），比 high 高 15.2 点，那个分数能排第 4。因此表里四个 Claude 的排名是下界，跨厂商比较并不在同等推理强度下。推理 token 和因果修复的秩相关是 0.54（p = 0.056），正相关但不精确。

## 🔬 最有意思的部分

**第一，会解释不等于会阻止。** 四个模型两条赛道都测了，在同样 62 个失败运行上配对比较：Gemini 3.8 Flash 差 −1.6，Claude Haiku 5.5 差 +3.2，GPT-6 Luna 差 −4.2，都不显著；GPT-6.1 Sol 事后 +45.2、现场 +30.6，差 −14.5（[−23, −5]，p = 0.002，Holm 校正后 p = 0.010）。作者排除了「现场动作空间更窄」的解释：Sol 90% 的有效事后诊断本来就选在检查点上，这些诊断的修复是 +48.2（n = 56）。它的现场干预有两个特点：在失败运行上 81% 的干预是让 worker 去读点什么（文档、订单），而不是重做待执行的动作，其他监督者是 41% 到 48%；而且来得早，16% 落在第一个不可逆动作上（其他人最多 11%），平均相对位置 0.31，五个里最早，40% 的运行里它在现场干预的位置比它自己事后指出的步骤更早。早早让 worker 去读一份文件，后面的决定还是交给 worker，它可能重犯同一个错；事后的回答则正好落在错误发生的地方。作者也说明，这个差距有多大、是不是只属于这个模型，还要更多运行和更多模型来确认。

**第二，按标注打分会排出另一张榜。** 如果把每个题上其他模型最常选的步骤当标注，GPT-6 Astra 会排第一（87% 的题选中了共识步），Grok 4.7 排第三；这个标注分和因果修复的秩相关只有 0.43。模型之间在 62% 的模型对上对决定性步骤意见一致，选共识步的修复是 +48.1，选别的步是 +30.5。**和别人一致地指出哪里出错，与真的能把它修好，是不同的量。** 共识步是最后一步的只有 21% 的题（13/62），而 Naagarajan 和 Streif 考察的套件上是 67% 到 96%。

**第三，「最后一步」捷径在回放下是负资产。** GPT-6.1 Sol 被强制选最后一步（替换动作仍可自由选）时得 +28.1，自由选步是 +45.2，差 −17.1（[−28, −6]，p = 0.004）。模型自己选最后一步的情况很少（Sol 是 23% 的题），选择步的平均相对位置 0.80。自愿选最后一步的 117 个诊断成功率 90%，但那是自选出来的一批题，失败本身就是末尾少了一个动作。中段的干预效果最差。

**第四，一个例子看清「差一步差很多」。** 分歧最大的题是延迟交付第 5 级，失败 worker 是 DeepSeek V4.1 Flash，44 步，检查器违规是漏发或没发全给客户的邮件。七个模型在第 43 步替换成一封正确的 send_email，5 次全成功，安慰剂 1/5，得 +80；DeepSeek V4 Pro 和 GPT-6 Luna 也选第 43 步但只有 4/5，得 +60；Claude Fable 5.1 和 Haiku 5.5 选第 34 步让它查一个订单，3/5 对 0/5，也得 +60；Claude Sonnet 5.5 在第 34 步查了另一个订单，只得 +20；Gemini 3.8 Flash 在第 42 步改了一笔退款金额，0/5 对 3/5，得 −60。这说明两点：早期补信息和晚期直接修动作都可能是有效答案，根因标注只会接受其中一个；而同一步换个参数，结果可以从帮忙变成添乱。

**第五，诊断本身的抖动不小。** GPT-6 Luna 同一提示再采样一次，74% 的题选了同一步，分数 +33.5 对 +37.1（差 −3.5，p = 0.525），逐题效果相关只有 0.58，每题平均绝对差 21 点。换一种措辞的提示是 +30.6（差 −6.5，p = 0.157），两版提示 71% 的题选同一步。所以排名相邻的模型差几个点，完全在一次改写或一次重采样能挪动的范围内。

**第六，多模态级的修复往往只是「去看一眼」。** 62 个题里 33 个是第 6 级失败，其中 17 个 worker 根本没打开附件，这些更好修（模型平均 +50.2，worker 看过图的 +27.6）。按模型汇总，因果修复从第 4 到 5 级的 +47.0 降到第 6 级的 +39.3；两个看不到图的纯文本模型在第 6 级仍有 +42.4 和 +39.4，因为好的修复常常就是让 worker 打开图片，不需要自己看懂它。

**第七，自我更新的设想没跑通。** 作者想用更强的 Qwen 3.8 Flash 重新收割失败：在 70 个延迟交付任务上做了 210 次首次尝试，只有 3 个系统性失败，校准后一个都没留下（重放自发成功率 60%、80%、80%）；同样流程用 DeepSeek V4.1 Flash 在前 20 个任务上收出了 21 个校准失败。worker 首次通过率到 92% 时，稳健的系统性失败变得非常稀少。

## 🤔 我的判断

**定位：测量协议。** 作者自己说得很清楚，这是一个可复用的协议，不是排行榜；能迁移的是协议本身，以及两个不依赖具体排名的发现：标注式基准里的结构性捷径在回放下失效，事后诊断和现场监督会把同一批模型排得不一样。

亮点：

1. **配对安慰剂。** 在同一步重放原动作，把 worker 自己会恢复的部分扣掉。随机步基线原始成功率 27.7%、因果修复 −0.6，一眼就能看出不扣安慰剂会虚高多少。
2. **打分路径上没有判官，也没有标注。** 判官被单个 token 骗、标注被「最后一步」刷，这两条都从设计上绕开了；题目按种子生成，泄露了可以换新实例。
3. **把「解释」和「阻止」放在同一把尺子上。** 同样的失败、同样的指标，才让 Sol 两条赛道 −14.5 的差距有意义。

问题与局限：

- **样本小。** 62 个题、87 次运行，区间约 ±10 点，事后排名的折半信度只有 0.47，要以 80% 功效区分相差 10 点的两个模型大约需要 84 个题。
- **一个模拟环境。** 仓损这个族在当前 worker 上几乎不产生系统性失败，题库实际由两个族主导；62 个题里 41 个来自 DeepSeek V4.1 Flash 一个 worker，所有 worker 都是小模型。协议声称能迁移到容器、数据库、虚拟机，但没演示。
- **推理强度不对等。** Claude 系列跑的是 high，排名是下界。
- **一个动作、一次干预。** 有些失败需要不止一处修正；这是为了可解释性的设计取舍。
- **每条赛道只有一个提示**，现场赛道的提示没变过；API 模型会随时间漂移。
- 现场赛道里成功对照有 18/25 来自 Qwen 3.8 Flash，存在「认出 worker 风格就能猜结局」的风险。作者检查过：对较弱 worker 的成功运行误报率 8%，对 Qwen 成功运行 18%，去掉所有 Qwen 运行后五个监督者顺序不变，但完全按 worker 匹配的设计没做。
- 作者在致谢里披露，基准、代码、实验和稿件都是在 AI 系统辅助下完成的。

对工程的直接启发：

- **挑监督者要在监督场景里测。** 别拿事后分析的表现去选不可逆动作前的审批器或监督者；用和部署一致的设置（不知道结局、只能在检查点出手、有打断成本）去评估。
- **小模型可能够用。** 每个不可逆动作前都要调一次监督者，成本很敏感；这里一个小开源模型和最好的监督者并列。作者也提醒，这需要更大规模来确认。
- **可恢复的环境是好 harness 的基础设施。** 如果你的工具状态能快照、能重放、能逐字节校验，就能用因果修复来评估诊断、监督、自修复模块，而不必依赖判官。
- **自修复要看位置。** 早期让 agent 补读信息，后续决定还是交给它；在出错的那一步直接给出正确动作通常更稳。设计 harness 里的纠错 hook 时，可以优先在不可逆动作前直接替换，而不是只追加一条提醒。
- **单次诊断不可靠。** 同一模型重采样逐题差 21 点，生产环境里的自动根因分析最好多采样或配回放验证。

一句话收束：**诊断的价值不在它讲得通不通，而在照它改一步之后，这个 agent 是不是真的比原来更常成功。**
