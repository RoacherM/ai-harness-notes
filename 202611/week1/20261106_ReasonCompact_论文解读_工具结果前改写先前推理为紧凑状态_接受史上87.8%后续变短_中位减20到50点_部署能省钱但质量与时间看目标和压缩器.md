# 何必为长推理买单：工具结果揭晓前把先前 scratchpad 改写成紧凑状态记录，六条开源路由上接受史里 151/172（87.8%）后续推理变短、路由中位数 −20.2% 到 −50.5%；编码案例里扩展复核从 61.1% 降到 0；SWE-bench Verified Mini 50 题上多配置能省花费，但质量与含改写时间取决于目标模型与压缩器

你有没有过这种体验：agent 账单里一大半是推理 token，同一轮里它把早先已经想过的约束、否决和下一步计划又写一遍；你想压缩上下文，又怕把「不确定」和「本意动作」压没。专有模型的隐藏 scratchpad 又看不着，没法对照实验。

这就是 **reasoning history compaction** 的研究缺口。这篇的核心问题是：**不重新训练，只改写模型自己更早的思考形式，能不能让后续生成更短；在软件 agent 部署里这账能不能算过来？** 看完我的感受是：**在接受的历史上，紧凑续写通常真的更短，且目标没有收到「请简短」的新指令；但部署侧必须按目标×压缩器逐对评估——省花费不等于保质量，也不等于含改写的时间一定更短。**

## 核心摘要

作者观察到推理可占生成 token 与 API 成本的大头（文中引用 Artificial Analysis：GLM 5.2 推理占生成 token 84.9%，Claude Fable 5 为 75.1%；DeepSeek V4 Pro 仅推理输出就占总成本 53.4%）。专有模型隐藏 scratchpad 限制直接研究，于是在开源权重、推理可见的模型上做控制干预：压缩器 LLM 在动作已请求、工具结果尚未执行/揭晓时，把历史 assistant scratchpad 改写成更短的状态记录，保留决策相关事实、数字、不确定性、结论与意图动作；系统/用户消息、工具调用与观测原样保留；目标权重与当前指令不变，也**不**另下「请简短」指令。共享采集后在分叉处冻结，原史（clean）与改写史（compact）独立续写。六条路由、各 12 道多阶段确定性工具任务：58/72 源史通过动作与保真门控；每源三对续写，得 174 质量对、172 可比较 token 对。接受史上 **151/172（87.8%）** 变短，路由中位数 **−20.2% 到 −50.5%**；精确成功 165/174→166/174（仅过滤最狠的路由净赚）。长度匹配的释义对照中位数仅 **+0.7%** 且成功大跌，说明不是「随便改写」就会短。LiveCodeBench 筛查里，成功 DeepSeek 分支提交轮「扩展复核」（≥350 推理 token）从 clean 的 **61.1%** 降到 compact 的 **0**。连续压缩部署在固定 50 题 SWE-bench Verified Mini 上：八配置里六配置花费下降；目标请求时间（不含改写）七配置下降；含改写时间则只有部分 MiniMax 配置真正下降。价值定位：推理历史是削减**未来**推理 token 的一条杠杆；实用政策必须按模型评估效率与保留能力，不能从「轨迹变短」直接推断。

## 🎯 为什么这件事值得写

上下文折叠、agent memory、concise CoT、Reasoning Shift 都在碰「别让推理太长」，但这篇的干预更窄、更可因果：

1. **只动自己的先前推理形式**，其它消息不动，未来工具结果对压缩器不可见（outcome-blind）。
2. **测量的是未来新生成的推理 token**，不只是输入变短那一截即时节省。
3. **同时给控制续写与 coding-agent 部署两张表**，避免「实验室变短 = 线上赚钱」。

对按推理 token 计费的 coding / tool agent，这篇提供的是可插的推理期干预假说，而不是又一个训练期「教模型短一点」的配方。

## 🏗️ 机制：outcome-blind 分叉、接受门、估計量

### Reasoning-only compaction

压缩器把历史 assistant scratchpad 写成更短状态记录；保留决策相关内容、去掉重复。GPT 5.6 Sol 写改写并在**另一次**基于 rubric 的调用里当法官。目标侧字段级校验：首请求除 assistant 推理外全部一致。

### Outcome-blind timing

动作请求之后、结果揭晓之前完成改写；分叉后两臂接收同一 pending 结果再独立续写。因此首轮对比测量的是历史干预效应；更后轮次还可含治疗诱导的轨迹变化。

### 接受与估計量

路由须证明会功能性地使用回放推理。动作门与保真门在续写前筛选源史；估計量以**接受的治疗史**为条件。报告 \(100(R_K/R_C-1)\)；token 比较要求分叉后回合数相等。区间对源史做 10,000 次 bootstrap。

六条路由：DeepSeek V4 Flash、Laguna S 2.1、MiniMax M3、GLM 4.7 Flash、GLM 5.1、DeepSeek V4 Pro（不同 provider / effort）。

| DeepSeek V4 Flash | 12/12 | 30/36 | −29.5% [−39.5, −16.5] | 36/36→35/36 |
| Laguna S 2.1 | 12/12 | 32/36 | −46.2% [−56.3, −29.6] | 36/36→35/36 |
| MiniMax M3 | 10/12 | 25/30 | −27.3% [−38.4, −17.1] | 30/30→30/30 |
| GLM 4.7 Flash | 5/12 | 13/13 | −50.5% [−66.6, −40.1] | 11/15→14/15 |
| GLM 5.1 | 10/12 | 28/30 | −20.2% [−28.6, −12.5] | 25/30→25/30 |
| DeepSeek V4 Pro | 9/12 | 23/27 | −32.6% [−43.4, −12.2] | 27/27→27/27 |

合计：**151/172（87.8%）** 变短；20 对变长、1 对持平；中位绝对变化 −178 token；最大变长 2,807。精确成功 165→166。留一路由：中位缩短稳健（约 −29% 到 −37%），但总体质量符号会被拿掉 GLM 4.7 Flash 翻转——**缩短稳健，质量符号不稳健**。

回合视角（初始 DeepSeek/Laguna 72 对）：池化缩短从第 1 轮 8.8% 增到第 3 轮 56.1%。风格扫描：更紧凑的史风格对应更大的中位缩短（探索性，机制未拆清）。

### 对照与编码行为

- **长度匹配释义（90–110% 词数）**：65 对中位 **+0.7%** [−8.2, +9.7]；成功 68/69→59/69。近零缩短 + 质量损伤 → 不能把主结果归因为「任意改写」。
- **LiveCodeBench 筛查（成功体制条件化）**：可比较对 29/33 变短、中位 −57.1%；成功 DeepSeek 提交轮扩展复核 clean **11/18（61.1%）**、compact **0**；中位末轮推理从 489 降到 12 token。说明在共享候选已在手的设定下，紧凑史可伴随更少提交前反复验算——但不能一般化成「删核查无害」。

## 🔬 最有意思的部分

1. **目标没被要求简短，后续仍常变短。** 先前推理像 in-context 文风示范；改形式可能改「接下来怎么写」。
2. **释义对照近零缩短。** 主效应更像「紧凑状态化」，不是「换个说法」。
3. **部署账是三维的。** 花费、工具调用、含改写时间可以各走各的；Kimi 外部压缩省一点钱却多干活。
4. **质量门很脆。** 控制实验净成功几乎持平，但留一路由会翻符号；部署最多差 3/50 仍未建立非劣。

## 🤔 我的判断

**定位：一篇推理期、无训练的历史改写因果探测 + 软件 agent 经济性样本；真正贡献是把「短推理」从训练目标拆成可对照的历史干预，并强迫你同时看效率与能力。**

亮点：

1. **Outcome-blind 分叉**把「输入变短」和「未来生成变短」拆开测。
2. **跨模型族的高频缩短**（接受条件化）有数字、有区间、有留一敏感。
3. **部署表诚实**：花费、步数、时间、分数分列，不把短轨迹写成胜利宣言。

问题与局限：

- **接受不对称**，缩短估計量以通过门控的治疗史为条件；保留率差的路由（如 GLM 4.7 Flash）不可直接排名。
- **同模写改写又做法官**；人工保真审计样本小、非专家、含事后加长批。
- **缺匹配的删除/截断/抽取基线**，相对「免费替代」的比较优势未测。
- **部署单样本、无重复种子、混合 provider**，因果解读受限；质量非劣未立。
- **可见推理 token 与客户端请求时长**不覆盖隐藏计算与完整任务墙钟。

对工程的直接启发：

- **在工具结果返回前压缩「自己的先前推理」**，保留不确定与意图动作，系统/工具消息别一起糊。
- **按目标×压缩器扫三维**：任务成功、含改写总成本、含改写时间；不要只看推理词数。
- **自压缩 vs 外压缩分开测**；外压缩有数据外泄与文风失配风险。
- **可疑时降压缩频率或给压缩器更多对话上下文**，文内建议每 N 步、带更多前缀的变体仍待比。
- **编码场景单独盯「提交前复核是否被误删」**，短不等于稳。

一句话收束：**长推理未必是能力本身，有时只是历史教模型「继续用同一种啰嗦写法」；改写先前思考可以砍未来 token，但省下来的钱和时间，得按每个目标和压缩器重新算一遍。**
