# 自进化 agent 把纠错记成了例外清单：四层隐藏规则最多只涨 5 点，一句命名约定就多出十五六点

你有没有过这种体验：给 agent 配了一套「越用越聪明」的记忆，ACE 的 playbook 也好，Dynamic Cheatsheet 也好，每次它做错你都给一条纠正，它也认真地写进了自己的状态。过一周你翻开那份 playbook，里面全是「Lufthansa 和 Thai Airways 不算，ITA Airways 要算」这样的条目。下次遇到 United Airlines，它照样算错。它记住了你纠正过的每一个值，却从没想过你纠正它的背后是同一条规则。

**agent 的状态在变长，不等于它学会了什么。**

自进化 agent 这条线我们写过很多：ACE、GEPA、Dynamic Cheatsheet、ReasoningBank、Training-Free GRPO、EvoSkill，以及前几周的 SelfEvolvingCL、CLE、MCCL。它们的共同承诺是：环境的反馈会变成 agent 原本没有的知识，并且能迁移到新情况。新加坡管理大学和广东工业大学的 Chenjie Qiu、Boyan Xu、Shaobin Shi、Bingfeng Chen、Ruichu Cai、Dongsheng Luo 的 **More Rules, Longer Lists? Benchmarking Self-Evolving Agents on a Hidden-Rule Curriculum**（arXiv:2610.40758）把这个承诺单独拎出来测：只给零星的纠错，agent 能不能归纳出一条没人告诉过它的规则，再用到从没见过的值上？

看完我的感受：这篇的设计非常干净，结论也很扎心。在用来认证题目的那个模型上，六个方法基本都没学会，它们的状态把每次纠错写成一条例外，清单越拉越长。缺的不是证据，而是「这个标签其实指的是一个有名字的分组」这一步推断，一句话的约定就能把它们抬起来十几个点。

## 核心摘要

CLR-Bench（Curriculum of Latent Rules）由 20 条课程链组成，覆盖 10 个领域，每条链 4 层，每层叠加一条隐藏规则，共 80 条隐藏规则、80 个练习任务和 80 个测试任务。每条规则作用在一个不透明标签上（比如「review queue B8 里的航段不计数」），标签背后是网上公开的一个命名分组（比如星空联盟的创始成员），任务只给一个示例值；练习阶段的反馈再透露一个成员和一个非成员，测试检查没见过的成员和相似的非成员。四个探针保证模型认识这个分组的成员、不给反馈时猜不出它、有约定时证据足以唯一确定它。作者用 GPT-6-Luna 认证题目并评测了六种方法：只靠反馈时，最好的方法比冻结 agent 只多 5 个点，只把 6% 到 12% 的未见成员排除出计数，还不如直接把原始练习历史塞进提示（20%）。给更新步骤加一段固定的「课」，说明标签代表有名字的分组，同样的方法就涨 14.5 到 16.5 个点。它们的状态在 75% 到 98% 的情况下记着被透露的那个成员，几乎从不写分组名。换成更强的 GPT-6-Sol，ACE 和 Dynamic Cheatsheet 只靠反馈就能到 78% 左右，并超过原始历史。所以这个基准量的是 agent 学得怎么样，而且这种能力随底座模型差异很大。

## 🎯 为什么这件事值得写

作者列了现有评测很少单独检验「从反馈里学到新知识」的四个原因：

| 问题 | 具体表现 |
| --- | --- |
| 分数上涨来路不明 | 可能来自记住重复出现的实例、遵守任务本来就写明的规则、修好输出格式和工具调用，都不需要推断新东西 |
| 不知道模型原本懂什么 | 没测反馈之前的知识，涨了不好归功于反馈，没涨也不好怪方法 |
| 总分掩盖学到了什么 | 记住被纠正的个例和归纳出背后规则的 agent，分数可以一样 |
| 目标可能本身就模糊 | 很少有基准检查证据是否足以确定该学什么，低分可能只是目标歧义 |

所以 CLR-Bench 只问一个更窄的问题：**给出稀疏的纠错反馈，自进化 agent 能不能归纳出一条隐藏规则，并用到它从没见过的情况上？**

隐藏类别都是网上公开的分组：航空联盟的成员、经济集团的国家、安全分类法里的弱点、股票指数的成分股。作者的理由很实在：agent 越来越多地在 Web 数据和服务上干活，这些分组是组织和标准机构公开维护的，任务很少直接点名，agent 只能从例子和纠正里碰到它们。真实反馈也是这个形状：你在个例上被纠正，得自己推断出背后的规则。

## 🏗️ 机制：一层藏一条规则，练习和测试奖励的东西不一样

**1. 课程链。** 每条链对应一个数据领域，有部门、员工、报销单、航段这类实体和记录，基础任务是写一个程序按实体统计记录数。链有 4 层，规则逐层累加。第 j 层在某个字段上加一条带不透明标签 $\ell_j$ 的排除规则，标签背后是隐藏类别 $C_j$，任务只给一个示例 $a_j \in C_j$，并为这一层输入里可能出现的每个值附一句事实描述，包括没见过的成员和非成员，所以认识这个分组的 agent 能认出成员。每个类别另有三个成员 $m_0, m_1, m_2$、一个练习非成员 $n_p$ 和七个测试非成员 $N_t$，非成员优先取自同样包含示例的竞争分组。

**2. 练习。** 第 k 层的练习用同样的记录和规则，但问的是最大的实体总数。agent 最多提交三个程序，每个程序在一个公开示例和 $2k+1$ 个隐藏输入上运行：一个输入把示例值挪到其他记录上；对每条规则 $j \le k$，一个输入插入 $m_0$，另一个同时插入 $m_0$ 和 $n_p$。失败的输入作为反例返回，并说明每个被改动的值是否和示例同属这个标签。方法每次尝试后跑一次更新步骤，带门控的方法可以拒绝更新。

**3. 测试。** 测试有 5 个隐藏输入，叫单元格。$5-k$ 个干净单元格只含示例值；$k$ 个单一单元格各对应一条规则，加入两个未见成员和七个测试非成员。只把每条规则用在示例上的程序得 $(5-k)/5$，即冻结阶梯：

$$0.80,\ 0.60,\ 0.40,\ 0.20$$

任何高于阶梯的分数都来自把规则用到了未见成员上、同时保住了非成员。关键设计是：**记住示例和 $m_0$ 就能通过练习，所以练习从不直接奖励泛化。**

**4. 四个认证探针。**

| 探针 | 给模型什么 | 要求 |
| --- | --- | --- |
| Known | 候选值、一轮反馈、课 | 说出分组名，软分 ≥ 0.8 |
| Hidden | 只有标签和示例，没有反馈 | 恢复不出类别 |
| Learnable | 练习反馈，没有课 | 未见成员分对 1/6 到 2/3 |
| Solvable | 反馈加课 | 软分 ≥ 0.8 |

这四个探针把每个类别放在「反馈有用」的区间：模型不会直接猜中，也不至于学不会。构造约束还堵了捷径：示例必须同时属于至少两个其他列表，不能有单一属性能把成员和非成员分开，有争议或最近变动过的成员一律不用。最终每个示例平均同时属于 6.5 个其他公开列表，最多 20 个，证据必须把真类别从真实的竞争者里挑出来。实际测得的冻结 agent 分数是 0.80、0.57、0.34、0.20，接近设计阶梯。

**5. 诊断指标和对照条件。** 除了层分数，还报告单一单元格准确率（只按规则用于示例的 agent 为 0），以及两个值级诊断：$inc_u$ 是未见成员 $m_1, m_2$ 被排除的比例，低说明泛化不足；$exc$ 是非成员被保留的比例，低说明过度泛化。对照条件包括冻结 agent、把原始练习程序和反馈全塞进提示的 History，以及在更新步骤里加一段固定「课」：说明标签代表一个包含示例和已确认成员、排除被拒绝值的知名命名分组，再给一个运用证据的流程，但不点名任何类别。

## 🧪 关键证据

**GPT-6-Luna 只靠反馈：几乎没学会。**

| 条件 | 平均准确率 | 单一单元格 | $inc_u$ | $exc$ |
| --- | --- | --- | --- | --- |
| Frozen | 47.8 | 0 | 1 | 94 |
| History | 52.3 | 13 | 20 | 82 |
| ACE | 52.5 | 8 | 12 | 92 |
| GEPA | 49.5 | 3 | 6 | 96 |
| Dynamic Cheatsheet | 52.8 | 8 | 12 | 95 |
| Training-Free GRPO | 48.0 | 0 | 2 | 94 |
| EvoSkill | 46.0 | 1 | 2 | 84 |

ACE、GEPA、Dynamic Cheatsheet 只比冻结 agent 多 1.8 到 5.0 个点，每一层都贴着阶梯。更新步骤让程序更精确，保住 92% 到 95% 的非成员，History 只保住 82%，**但没有带来任何泛化**。

**三种方法输在接受更新的方式上。** Training-Free GRPO 只从结果有好有坏的组里提取经验，EvoSkill 只接受能提高练习分的技能，而练习结果是全有或全无。结果是 Training-Free GRPO 的每一个状态都是空的（两个底座模型都是），EvoSkill 在 20 条链里有 9 条一个技能都没接受，它的 449 个提议里有三分之一格式错误，用 Luna 时 70% 的状态没有技能（Sol 是 14%）。ReasoningBank 则检索出「推断字段示例背后的完整类别」这类泛泛的策略，求解器于是光凭描述就排除值，只保住 51% 的非成员，比冻结 agent 还低 14 个点。

**加一段课：缺的是推断，不是证据。** 更新步骤里加上课之后，ACE、GEPA、Dynamic Cheatsheet 分别到 67.0%、66.0%、68.3%，单一单元格解出 39% 到 46%，和 History 加课的 63.5% 相当。同样的证据足以学会这些规则。规则越积越多差距越大：第 4 层 ACE 加课 48%、不加 23%，GEPA 42% 和 22%，Dynamic Cheatsheet 42% 和 24%。

**换更强的底座：能学了，但不是所有方法都受益。** 不给反馈时 GPT-6-Sol 在 80 个层分数里只猜中 1 次，冻结 agent 甚至掉到阶梯下面的 32.5%，因为它的程序会按「总部在欧洲国家的航空公司」这类猜出来的属性类别把非成员也删了。只靠反馈，ACE 和 Dynamic Cheatsheet 到 78.3% 和 78.5%，单一单元格解出 59% 到 60%（Luna 下是 8%），排除 68% 到 76% 的未见成员，并超过 History 的 70.3%。课对 Sol 只再加 3.0 和 5.5 个点。但 GEPA 和 EvoSkill 在 Sol 下排除了更多未见成员（48% 和 41%），却只保住 66% 和 53% 的非成员；Training-Free GRPO 依旧提取不到经验，ReasoningBank 只保住 21% 的非成员，两者都比 Luna 时更低（35.8% 和 24.8%）。**更新步骤不存规则的方法，换更强模型、给约定都救不了。**

## 🔬 最有意思的部分

**第一，状态里写的是例外，不是类别。** ACE 排除练习中透露的成员的比例是 92.5%，排除两个未见成员只有 12.2%；Dynamic Cheatsheet 是 80.0% 对 11.8%，GEPA 是 87.0% 对 5.8%。按字符串匹配，被透露的成员出现在 ACE、GEPA、Dynamic Cheatsheet 75% 到 98% 的最终状态里，完整类别名最多出现在 3%（加课后 8% 到 18%）。论文给了一个星空联盟创始成员那条链的例子，ACE 第一层后的 playbook 写的是：「已确认成员包括 Lufthansa 和 Thai Airways；ITA Airways 确认不是成员，仍要计数。按航空公司的精确值判断成员，不要按名字相似。」加课之后写的是：「B8 是 Star Alliance：排除 Lufthansa 和 Thai Airways，但计数 ITA Airways。」后者写下的是一个分组，就能迁移。

作者还用 GPT-6-Luna 当标注器（能看到隐藏类别和练习证据，看不到测试结果）给每层后的状态分类。Luna 只靠反馈时，ACE 和 Dynamic Cheatsheet 91% 的状态只含练习里见过的值或者什么都没写，6% 写出了类别或列出了成员；Sol 是 58%。状态内容几乎决定程序行为：状态写出类别时，程序排除 89% 的未见成员、保留 93% 的非成员；只写见过的值时，只排除 9%。**方法的问题在于没能把纠错变成类别，一旦类别存进去了，它们用得很好。**

**第二，起作用的是「约定」，不是「流程」。** 作者把课拆成两部分，放在同样中性的标题「UPDATE NOTE」下面。只给流程（判断示例背后的类别，再对每个描述过的值应用它），ACE 和 Dynamic Cheatsheet 到 55.0%，只多 2.5 和 2.2 个点。只给约定（标签代表一个为契合纠错而选的知名命名分组），涨到 71.5% 和 65.8%，多了 19.0 和 13.0 个点，所以效果不依赖原标题的权威感。History 只加约定是 64.8%，和加整段课的 63.5% 一样。把类别名连同反馈一起给，ACE 和 Dynamic Cheatsheet 到 73.5% 和 75.8%；而只告诉求解器类别名、不给任何反馈，只有 58.0%，保住 58% 的非成员。**方法卡在识别类别；类别识别出来之后，反馈负责划定边界。** 还有一个细节：Dynamic Cheatsheet 在中性标题下拿到整段课反而只有 53.8%，69% 的状态已经不提这个标签了，因为 cheatsheet 每次整体重写，规则被丢掉了。

**第三，约定只说一次，大部分效果能留住。** 只在第 1 层的更新步骤里给约定、第 2 层起撤掉，ACE 和 Dynamic Cheatsheet 到 63.8% 和 64.3%，介于只靠反馈（52.5% 和 52.8%）和每层都给（71.5% 和 65.8%）之间。在从没给过约定的第 2 到 4 层，ACE 得 75%、58%、39%，只靠反馈是 64%、44%、23%。效果褪去的地方，方法退回到属性规则，比如把「OPEC 成员国的机场」写成「非洲的机场」。

**第四，给更多正例，方法也只是把清单再加长一行。** 为了排除「从两正一负就不泛化只是谨慎」的解释，作者设了奖励型练习：第二次和第三次尝试的隐藏输入里再透露 $m_1$。ACE、GEPA、Dynamic Cheatsheet 于是排除新透露的 $m_1$（ACE 在 93.5% 的情况下），但对从没出现过的 $m_2$，排除率是 9.5%、4.0%、14.0%，和标准练习的 12.0%、4.5%、11.0% 差不多。同样的信号让 History 对 $m_2$ 的排除率从 19.5% 翻倍多到 42.0%。**原始历史会利用「清单失败了」这条证据，方法不会。**

**第五，练习通过率是很差的学习信号。** ACE 通过 95% 的练习层，History 通过 91%，单一单元格却只解出 8% 和 13%，因为例外清单就足以通过练习。成本也很说明问题：EvoSkill 每条链在练习上花约 600 万输入 token，什么也没学会；ACE 花约 90 万；History 只花约 7 万，却是只靠反馈的条件里泛化最好的。保持力方面，ACE 和 Dynamic Cheatsheet 到第 4 层时对第 1 条规则未见成员的排除率都在第 1 层水平的 3 个点以内（ACE 用 Luna 从 15.0% 到 17.5%，用 Sol 从 72.5% 到 70.0%），但旧规则保留非成员的比例在下降，比如 Dynamic Cheatsheet 用 Sol 从 99.4% 降到 77.5%。

## 🤔 我的判断

**定位：测量基础设施。** 它不提新方法，而是给「自进化到底学到了什么」提供一个可认证、可诊断、可自动扩展的考场。

亮点：

1. **把「学到了」和「记住了」拆开。** 练习只奖励记住，测试只奖励归纳，再配上 $inc_u$ 和 $exc$ 两个值级诊断，泛化不足和过度泛化分得清清楚楚。这比看一条上升的分数曲线诚实得多。
2. **用探针认证先验。** 模型认识成员、不会盲猜、证据在约定下充分，这三件事都先验证过，低分就不能推给题目歧义或者模型不懂。
3. **定位到了具体的缺失环节。** 一句约定就能补上十几个点，而流程说明几乎没用，这把问题从「方法不行」收窄成「更新步骤不会提出类别假设」。

问题与局限：

- 规则类型单一：都是「某个命名分组的成员不计数」这一种排除规则，类别都来自网上公开的列表，能不能代表真实工作中的隐性规则（比如团队约定、业务口径）要打个问号。
- 结论强依赖底座模型。Sol 只靠反馈就能学会，作者也承认难度是按认证模型校准的，换强模型后前两层已经超过 80%。
- 每个条件每条链只跑一次；状态标注用的也是 LLM 标注器。
- 所谓「课」本质上是把基准的构造约定告诉了 agent，现实里你不一定知道该告诉它哪条约定。

对工程的直接启发：

- **别用练习通过率衡量记忆系统。** 一份越来越长的例外清单能让通过率很好看。要像 CLR-Bench 一样留出没被纠正过的同类样本，专门测迁移。
- **更新步骤要会提出假设。** 收到纠错时，让更新步骤显式回答「这些被纠正的值属于哪个命名类别」，再拿模型自己的知识或检索工具去核对。作者提的三个方向也是这个意思：更新时提出命名分组并核对、给更新步骤查公开分组的工具、接受规则别依赖奖励的方差。
- **门控更新在二值奖励下会饿死。** 如果你的 harness 只在「有对有错」或「分数上涨」时才接受经验，而反馈又是全有或全无，那它可能根本不会更新。Training-Free GRPO 全空、EvoSkill 九条链零技能就是例子。
- **一句好的约定比一套流程值钱。** 写进 harness 的元知识，优先写「这类标签/错误通常代表什么」，而不是「请先分析再总结」。
- **原始历史是很强的基线。** 便宜，而且在 Luna 下泛化最好。上复杂记忆系统之前，先和「把练习历史原样塞进去」比一比。

一句话收束：**会把每次纠正都记下来的 agent 很勤奋，会问「这些纠正是在告诉我哪条规则」的 agent 才是在学习。**
