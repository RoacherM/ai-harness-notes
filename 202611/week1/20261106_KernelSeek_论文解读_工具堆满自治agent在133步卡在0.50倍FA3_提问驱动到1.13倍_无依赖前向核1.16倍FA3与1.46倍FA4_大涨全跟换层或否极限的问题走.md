# 别再给 coding agent 堆工具：工具堆满的自治进化 agent 在 133 步卡在 0.50× FlashAttention-3；提问驱动的 KernelSeek 同任务同机同周到 1.13×，再做出无 CUTLASS/CuTe/cuBLAS/cuDNN 依赖的 Hopper/Blackwell 前向核——182 场景全对、几何均值 1.16× FA3 与 1.46× FA4；162 条人工消息、11.5K 次工具调用里，每一次大涨都跟着「换层」或「否极限」的问题走，从不跟着喂信息的消息走

你有没有过这种体验：为了榨 GPU kernel，你给 agent 配上解析过的 NCU、反汇编 diff、文档检索、lesson 知识库，再加进化循环；跑了上百步，正确率很高，速度却死死卡在上游一半。你开始怀疑：缺的到底是不是信息？

这就是 **kernel coding agent** 的结构–自由度两端困境。Snowflake × CMU 这篇的核心问题是：**深目标上，脚本化与开放搜索各自缺什么；一个恰当时刻的短问题，能不能在不收窄下一步动作空间的前提下给出方向？** 看完我的感受是：**信息往往够了，缺的是「该怀疑哪一层」的方向；KernelSeek 用最小可验证 harness + 决策点提问，把同一评测上 0.50× 的平台推到 1.13×，并交出可落地的无依赖 FA 前向核。**

## 核心摘要

作者把现有 GPU kernel agent 摆在结构–自由度光谱两端：脚本化 agent（固定循环、优化菜单、固定角色）样本效率高但菜单错了就塌；开放进化 agent 让模型当变异算子，用大量试错买自由。两边共同的应对是「再装备」——解析 profiler、检索文档与参考库、存 lesson。论文主张两端都缺 **direction**：关于剩余差距在哪的假说；而一个不含答案、要求可测的短问题，能在不收窄动作空间的前提下给出方向。KernelSeek 由三部分组成：最小 harness（编译、对照种子与 fp32 参考验正确、与种子同卡背靠背计时、禁依赖用符号检查、Stop hook 强制可验证目标谓词）、通用 coding agent（无脚本、无预消化上下文）、决策点问题（先人工，再固化为自问 skill / question bank）。头对头：同一任务、同一评测器、同一 H200、同一周，按主流配方搭的工具富自治 agent（Arsenal）在 133 个模型驱动步后平台在 **0.50×** FA3（文内 Table 2 记 lineage 冠军 **0.48×**，最差配置 0.24×，0/26 达平价）；KernelSeek 到 **1.13×**（22/26 ≥1.0×，最差 0.87×）。完整战役交出 `fa3_hopper.cu` / `fa4_blackwell.cu`：Hopper **182/182** 正确、几何均值 **1.16×** FA3（含 cuDNN 等最快可用基线为 1.10×）；Blackwell 可跑场景全对、对 FA4 也跑的配对集几何均值 **1.46×**（最快可用 1.07×）。16 个会话共 **162** 条人工消息、**11,532** 次工具调用；大增益无一例外跟在「把 agent 推到另一系统层」或「拒绝声称极限」的问题后面，从不跟在提供信息的消息后面。价值定位：深优化里稀缺的是方向不是装备；提问是可复用、可银行化、可与进化循环组合的操控面。

## 🎯 为什么这件事值得写

KernelBench、AVO、AlphaEvolve、FlashInfer 竞赛 harness 都在证明「agent 能写/改 CUDA」，但少有人在**同一目标、同一评测、同一硬件**上对照两种操控策略。这篇恰好填这个缝：

1. **把失败模式钉在一个装备充分的 agent 上。** 不是抽象批评，而是 133 步、312/313 正确、却 0.50× 平台的完整尸检。
2. **把「人在环」从写代码改成问问题。** 人工不贡献 CUDA 机制，贡献的是怀疑的时机与测量对象。
3. **产出可复用资产。** 无依赖 FA3/FA4 级前向核、可验证目标 hook、101 条核心 question bank、完整轨迹。

对「再给 agent 多挂一个 MCP / 再灌一波文档」的工程惯性，这篇是直接反例。

## 🏗️ 机制：Ask vs Equip、最小 harness、问题银行

### 共同框架

候选 = kernel 源码；适应度 = 各场景相对种子的加速向量（任一错误则塌零）；谱系单调如 AVO。设计者能改的，是**什么、何时进入变异算子的上下文**。Equipped：预消化瓶颈标签、检索文档、参考库 hints、typed knowledge store。Asked：任务 + harness 原始输出 + 谱系 + 决策点短问题；工具仍是开发机上的编译器/profiler/反汇编/消毒器，但不预消化。

### 最小 harness 与可验证目标

一条命令：编译、对照种子与 fp32、同卡背靠背计时、报几何均值。案例约束（禁 CUTLASS/CuTe/cuBLAS/cuDNN）检查二进制符号。目标是评测输出上的谓词，装成 Stop hook：agent 试图结束回合时，未满足条款被机械打回。教训两条：谓词要量化**每个**场景而非聚合；能算的不要交给模型法官——作者有一次把裁决委托给模型法官，接受了过早「达标」，随后被人推翻。

### 何时问、问什么

大增益前的问题共享六属性：不含答案、要求可用现成工具得到的测量、跨层（kernel → host launch → 路由 → benchmark 本身）、拒绝过早闭合、便宜（几十 token 对几万 token 检索）、对抗顺从。案例中人工问题八类：测量检查、界差分、benchmark 有效性、差距分诊、agent 过程、挑战极限、策略选项、假说检查。问在决策点：战役开始定范围、平台期、声称极限/完成、可疑大胜、正确性异常被解释掉时；之间 agent 独自工作，约 71 次工具调用 / 条人工消息。

### Question bank 与自问

轨迹蒸馏先得 48 条，去掉「点名上游 / 点名 attention」后释放版：101 核心条目分十组（范围与分诊、界与工况、harness 与测量、host/launch/路由、存储层次、计算发射、占用与寄存器、异步流水、调度、低精度数值）+ 架构 checklist + 算子插件槽。可写成 skill：目标、硬规则、循环、自问列表、评测与 profiler 命令；子代理按假说扇出，回报假说与测量而非补丁。也可包进 AVO 式进化：指令改成「要测的假说」而非「要做的编辑」。

## 🧪 关键证据

### Arsenal：装备充分却平台

任务：无依赖单文件实现 vLLM FA3 算子（H200），26 配置至少平价 FA3，且 vLLM greedy decode token 级相等。编排器拥有循环；Claude Opus 每步新鲜会话当 brain；16 个手写 lever 按 NCU 瓶颈标签塞进提示；中位步提示 22.6K 字符，37% 为预取参考。结果：313 步 / 4.2 天，另 117 步被人回滚；模型活跃约 62 小时、API 约 $660；报告预算 **133** 模型驱动步。最佳 **0.50×** FA3（Table 2：**0.48×**），最差 0.24×，无配置达平价；进展停在约第 35 步。312/313 正确——搜索几乎不冒险。尸检：82% 自己读的字符是自己的 kernel；92 次文档查询多为「证明不该改」；36/37 rewrite 分支种子自同一步；记忆文件把「65536 寄存器墙」写成 DEFINIVE，而 FA3 并不撞这墙；诊断全停在 kernel 层，后来 KernelSeek 补上的差距在 **host launch path**。

### 头对头（Table 2）

| 项 | Equipped | KernelSeek |
| --- | --- | --- |
| 人工文本进提示 | 无 | 40 回合、17 问 |
| 模型驱动步/回合 | 133 步 | 40 回合 |
| 到最佳墙钟 | 44.7 h / 62.4 h | 68.0 h（41.3 h 活跃） |
| 正确候选 | 132/133 | 全部报告正确 |
| 最佳几何均值 | **0.48×** | **1.13×** |
| 最差配置 | 0.24× | 0.87× |
| ≥1.0× 配置 | 0/26 | 22/26 |
| 预推参考材料 | 提示 37% | 无 |
| 重读自己 kernel | 82% | 26% |
| NCU | 每步解析 | 429 次原始输出 |

KernelSeek 从 0.009×（paged/GQA 掉进标量回退）起，21 h → 0.96×，66 h → 1.02×，68 h → 1.13×。作者承认：前两天已在 40 场景网格上建过核、前端不同、各一跑——公平读法是「同一日历周，有人舵的过了平价，无人舵的加算力也没到一半」。

### 完整战役（Table 1）

| 集合 | Hopper vs FA3 | Blackwell vs FA4 |
| --- | --- | --- |
| all | 182/182，**1.16×**（最快可用 1.10×） | 配对 124 场景 **1.46×**（最快可用 1.07×）；可跑 154/154 正确 |
| 平价以上 | 135/182 vs upstream | 98/124 vs upstream |

若干决定性收益在核体外：约 38 µs/次的同步 host copy、陈旧路由门、发散 lane 上发的 TMA gather、被编译器放进 local memory 的 ring state。进化包装：第一代问题把稠密 prefill 从 0.29× 拉到 0.68×；再三代合计约 +0.10× 后平台在 0.78×——最后 22 点来自「时间花在哪」的问题，发现同步 host copy，而不是又一代变异。

### 哪些问题真的改航向（Table 3）

例：「哪些配置拖垮几何均值？」→ 发现 hd96/192/256 在标量回退 0.01× → 4 小时 0.44→0.96。「这是硬件天花板还是我们的设计？核外时间去哪了？」→ host 侧 2–5 µs tensor fill → split-KV 0.87→0.97，几何均值 1.02→1.13。「场景覆盖算子真实调用面吗？」→ 移植完整测试网格，52/58 正确暴露 sink/left-pad 偏差 → 修到 58/58。「目标真达成了吗？我们还远低于平价。」→ 揭穿 Stop-hook 模型法官的过早胜利。模式：**大跳变 = 换层或否极限；触发的测量 agent 早就有能力做，缺的是去做的理由。**

## 🔬 最有意思的部分

1. **正确率可以是搜索胆小的签名。** 312/313 正确 + 平台，说明目标与晋升规则奖励了「不冒险的局部编辑」。
2. **知识库可以有害。** 预消化参考占提示三分之一，却强化错误结论的代际继承；去掉编排、只留机械评测，反而更干净。
3. **进化放大方向，不创造方向。** 同一层内搜索有效；没被指向的层，代数再多也走不到。
4. **提问 ≠ 少用工具。** KernelSeek 工具调用更多（429 NCU、372 SASS/PTX），但瞄准了该测的东西。

## 🤔 我的判断

**定位：一篇深优化场景下的 harness / 人机分工论文；贡献是对照实验 + 可释放的无依赖核与问题银行，而不是又一个「多 agent 角色」脚手架。**

亮点：

1. **同任务同评测同硬件同周的 Ask vs Equip 对照**，把「再装备」叙事直接证伪到一半速度。
2. **可验证 Stop hook + 场景级谓词**，机械拒绝过早完成。
3. **问题可银行化、可自问、可接进化**，把一次性人工怀疑沉淀成资产。

问题与局限：

- **头对头各一跑**，前端与是否有人舵不完全对称；作者自己把 Table 2 读成「差距存在且大」。
- **案例几乎全是 attention**，无参考实现战役尚未跑；银行里 72 条公开来源条目还没真正舵过 agent。
- **人工有系统经验**，决定「测什么、何时测」；银行能否替代人是文内未做的四臂实验。
- **Hopper/Blackwell 仍有洞**（如 fp8 稠密 prefill、部分头维）；反向未覆盖。
- **墙钟加速含 dispatch**，edge 集合部分 1.5–2× 含上游调度开销。

对工程的直接启发：

- **深目标优先加「可验证停止条件」和「决策点提问」，而不是再挂解析器。**
- **平台期先问「在哪一层」**：host / 路由 / benchmark / kernel，再改代码。
- **声称极限与可疑大胜时强制测量**，拒绝模型法官单独裁决达标。
- **进化指令写成假说**，不要写成菜单编辑。
- **轨迹里标「换层 / 否极限」问题**，作为可复用 skill 的种子。

一句话收束：**深 kernel 优化里，agent 缺的往往不是更多装备，而是一句迫使它换层或为自己声称的天花板举证的问题；方向对了，工具会自己变多——只是用在该用的地方。**
