# 进化完分数涨了，丢掉的那些题谁来数？十六个自进化 agent 无一例外边得边丢，最高分的父本也不一定最能长

你有没有过这种体验：跑了一晚上 harness 自进化，早上一看 Champion 比 Seed 高了五个点，心里踏实了，直接合进主干；过两天线上反馈说，原来稳稳能做的几类任务突然开始翻车，账单还比之前贵。行业里这叫 **harness evolution**，也是现在最流行的一种不动权重的递归自我改进（RSI）：模型冻住，让 agent 自己改 prompt、skill、工具接口、编排甚至源码。大家报的都是一个平均分。问题是，**平均分涨了，到底是 agent 变好了，还是它把一批题换成了另一批题？**

这篇来自 USTC、Berkeley、Simple Agent Lab、BIGAI、上交的论文（Beneath the Surface）把四种主流进化方法、两种 harness、两类任务全部重跑，每个 Seed 和 Champion 都配对跑八遍，逐题对账。看完我的感受是：这是我目前见过最像「审计报告」的一篇进化论文，它不是又一个新算法，而是告诉你现有算法里 select、analyze、mutate、gate 四个环节各自在哪里骗了你，最后再顺手把审计结论装回去做了一个 AGE。

## 核心摘要

作者把 agent 写成 \(A=(M,H)\)，模型 M 冻结，只进化 harness H；进化过程拆成七个算子（select 选父本、rollout 收证据、analyze 诊断、mutate 出候选、validate 可选校验、gate 决定是否收录、record 归档），重点审计其中四个。实验覆盖 AHE、HyperAgents（偏实现改造）和 A-Evolve、GEPA（偏反思提炼）四种方法，MiniSWE 2.4.5（可改源码）和 Codex 0.143.0（只能改外层 prompt、skill、配置）两种 harness，τ³-Banking（97 题）和 Terminal-Bench 2（89 题）两类任务，主模型都是 GPT-5.4。核心发现有五条。第一，十六条进化谱系里，**每一个 Champion 都同时获得了新题、丢掉了旧题**，没有一个是单调扩张的；其中 HyperAgents 在 MiniSWE 的 τ³-Banking 上可靠性涨了 5.2 点，却丢了 10 道原本能做的题。第二，十一个可靠性提升的 Champion 里有八个单次运行更贵。第三，用 Train/Validation 分数挑父本，在通用任务上命中「后续最能涨的父本」的概率低于随机（17.5% 和 8.8%，随机是 25%），在编码任务上又高于随机（59.5% 和 55.7%）。第四，从轨迹里提炼出的具体改动，16 个里有 15 个在可靠性上胜过「记得检查工具、记得验证结果」这类通用提醒；但具体改动组合起来又可能互相干扰。第五，更严的 gate 会把最佳候选的保留池数从 15 个压到 6 个。最后作者用一个叫 EvoAudit 的 agent 辅助审计流程，把这些诊断变成四条算子修订，装进 A-Evolve 得到 AGE：在四个（任务乘 harness）设置里可靠性和覆盖率全部超过 A-Evolve，丢题数三格更少一格持平；而且在四格里 Avg@8 都是所有方法最高；MiniSWE 的 τ³-Banking 上 Avg@8 从 Seed 的 27.4 到 34.0，丢题只有 2 道。真正的价值定位是：**把「进化有没有用」从一个分数问题，拆成每个决策各自该用什么证据来检验的问题。**

## 🎯 为什么这件事值得写

过去一年 harness 进化的论文几乎都用同一个叙事：闭环跑「执行、诊断、改动、评测」，基准分往上走，于是宣布 RSI 可行。我们仓库里已经收过不少这一路的东西，ContinualHarness 里 Meta-Harness 在 FeatureBench 上五轮掉到 32、CLEO 只改脚手架追 Claude Code、ParetoSaddler 用贝叶斯自助法管晋升。它们共同的隐患是：**平均分是对任务和试次取平均，新做对的题可以把丢掉的题盖住**，部署成本和进化没见过的任务表现也都看不见。

这篇的切入点很朴素：别再只看一个数，把 Seed 和 Champion 放在同一批题上配对跑八遍，看每道题的成功次数从几变成几。这样「涨」被拆成了三件不同的事：可靠性（Avg@k，平均每次做对的比例）、覆盖（Pass@k，k 次里至少对一次的题占比）、以及任务翻转（得了几道、丢了几道）。再加上部署成本 \(C_{dep}@k\)，进化的账就算得清楚多了。

## 🏗️ 机制 / 任务定义

进化算法 E 从 Seed \(A_0=(M,H_0)\) 出发跑 G 代，第 g 代产出候选集合 \(C_g\)，最后由规则 Q 从全部归档版本里选出 Champion：

$$
\bigcup_{g=1}^{G} C_g = E(H_{<g}, Z_{<g}, D_{evo}; B_{evo}),\qquad H^\star = Q\Big(\{H_0\}\cup \bigcup_g C_g\Big)
$$

评测指标：

$$
\text{Avg@}k=\frac{1}{Nk}\sum_{n=1}^{N}\sum_{i=1}^{k}Y_{ni},\qquad \text{Pass@}k=\frac{1}{N}\sum_{n=1}^{N}\mathbb{I}\big[\max_i Y_{ni}=1\big]
$$

部署成本 \(C_{dep}@k = k\cdot \bar c^{(k)}_{dep}\)，即前 k 遍的平均单题花费乘以 k。

四个被审计的算子和对应实验：

| 算子 | 它做的决定 | 本文怎么测 |
|---|---|---|
| select | 下一代从哪个父本改 | 每个 Champion 用同一套 A-Evolve 流程各生三个候选，看谁的后续增益最大，原规则命中率对比 25% 随机 |
| analyze | 证据支持改什么 | 把 Champion 拆成功能相关的组件，对比通用提醒 |
| mutate | 改动怎么组合 | 单组件 A、B 与完整 Champion 对比，估交互 |
| gate | 收不收录 | 原规则对比「均值更高且相对现任回退不超过 0.05」的约束规则，在冻结池上回放 |

两种 harness 的差别也很关键：MiniSWE 可以改内部源码，Codex 只能改外层（prompt、skill、配置、外部编排）。很多结论在这两类上方向相反。

## 🧪 关键证据或主结果

先看 Seed 对 Champion 的八遍配对（节选）：

| 任务 | Harness | 方法 | Avg@8 | ΔAvg | Pass@8 | ΔPass | 得 / 丢 |
|---|---|---|---|---|---|---|---|
| τ³-Banking | MiniSWE | Seed | 27.4 | 无 | 54.6 | 无 | 无 |
| | | AHE | 32.9 | +5.4 | 66.0 | +11.3 | 15 / 4 |
| | | HyperAgents | 32.6 | +5.2 | 57.7 | +3.1 | 13 / 10 |
| | | A-Evolve | 26.3 | −1.2 | 55.7 | +1.0 | 7 / 6 |
| | | GEPA | 28.2 | +0.8 | 58.8 | +4.1 | 10 / 6 |
| | | **AGE** | **34.0** | **+6.6** | **66.0** | **+11.3** | **13 / 2** |
| Terminal-Bench 2 | Codex | Seed | 69.9 | 无 | 89.9 | 无 | 无 |
| | | HyperAgents | 72.6 | +2.7 | 86.5 | −3.4 | 2 / 5 |
| | | GEPA | 68.1 | −1.8 | 86.5 | −3.4 | 2 / 5 |
| | | **AGE** | **73.5** | **+3.5** | **92.1** | **+2.2** | **3 / 1** |

几个值得记住的数：

- 十六条谱系里可靠性涨了十一条、覆盖涨了十条；有四条两个指标反方向走，还有一条只涨可靠性。**一致性和覆盖面是两件事，必须分开报。**
- 成本：十一个可靠性提升的 Champion 里八个单次更贵，三个更便宜的都是 MiniSWE 跑编码任务。但单次贵不等于部署贵：AHE 在 MiniSWE 的 τ³-Banking 上四遍就达到 56.7% 覆盖，超过 Seed 八遍的 54.6%，总花费反而更低。
- 泛化：Test 集可靠性有十条谱系提升，其中偏实现的方法八条里占七条；偏反思的方法在只改外层的 Codex 上 Test 全部下降。跨基准迁移更有意思：从 τ³-Banking 迁到完整 τ²-bench，八个 Champion 里七个覆盖下降；从 Terminal-Bench 2 迁到 DeepSWE v1.1，八个里七个覆盖上升。
- AGE 的进化成本在 980 到 1480 美元之间，和 A-Evolve 同量级，远低于 GEPA 的 1600 到 2400 美元。

泼点冷水。第一，题量不大（97 和 89 题），八遍配对已经很用心，但每格得丢几道题的差异，单格看统计意义有限，论文更多是靠「十六格里有几格」的计数来说话。第二，AGE 只装进了 A-Evolve，而 A-Evolve 在原表里是四种方法里最弱的一个，「全超 A-Evolve」本身说服力有限。横向看，AGE 在四格里的 Avg@8 其实都是最高（34.0、38.1、71.8、73.5），覆盖也都最高或并列最高；但它比各格现有最好方法只多 0.9 到 1.6 点，而这些方法自己八遍之间的标准差就在 2 到 4 点，进化本身也只跑了一个随机种子，所以「AGE 最好」更应读成「AGE 在不牺牲分数的前提下相对参考方法 A-Evolve 少丢题」（在 Codex 的 τ³-Banking 上它丢了 5 道，仍多于 HyperAgents 的 2 道）。第三，EvoAudit 的四条修订由八位专家评审，平均 6.75 位赞成进入验证，这是一个有用但很软的信号。

## 🔬 最有意思的部分

**挑父本这件事在两个领域里正好相反。** 原生的选择规则在 τ³-Banking 上挑中最能长的父本的概率只有 17.5%（MiniSWE）和 8.8%（Codex），低于随机；在 Terminal-Bench 2 上却有 59.5% 和 55.7%。也就是说「当前分最高」和「还能往上长」在通用对话任务上几乎不相关，甚至负相关。我的解读是，通用任务的高分版本往往已经把容易的模式吃完了，剩下的改动空间更多是在别处制造回退；编码任务里能力更可叠加。不管原因是什么，结论很硬：**评 select 要看后续增益，不能只看现分。**

**通用提醒基本没用。** 在 Seed 上加一句「检查工具、验证结果」之类的通用提醒，四格里 Avg@8 最多涨 0.4，Codex 的 Terminal-Bench 2 上反而从 69.9 掉到 65.7。而从轨迹里提炼的具体组件 16 个里 15 个胜过它。这和我们之前收的 CLR-Bench（一句命名约定就多十五六点）是一个方向：**有效的改动是具体的、有依赖的，不是态度上的。**

**组合会变味。** 八个 Champion 里六个比任一单组件都强，所有编码任务都是这样；但通用任务里两格反而是子集更好，还有一格编码任务只有组合才比 Seed 好。所以 mutate 不能把改动当成独立可加的补丁。

**行为层面的得丢。** 作者挑了 22 组成功次数变化大的任务对比轨迹。涨的那一侧主要是「状态和依赖管理」（7 涨 1 降：保留输入、尊重动作依赖、留下自包含的可执行结果）；降的那一侧主要是「精确对齐」（1 涨 4 降：日期、产品条件、输出字符没对上证据）。这非常像真实生产里的感受：进化很容易教会 agent 更稳的流程，却同时让它在细节上变松。

**AGE 的四条修订都很克制。** select 只在分数并列时用「相对 Seed 的回退题数最少」打破平局；analyze 让一个裁判只看行为轨迹（工具调用、成功失败的返回、完成信号），**明确剔除基准奖励、验证器输出、隐藏测试和原题文本**，输出 0 到 10 的行为分并区分「Observed」和「Inference」；mutate 要求先写出观察到的行为、推断的机制、替代行为、激活条件和预期代价，再做一次依赖闭合的改动；gate 保留「严格涨分才收」，只在同分时允许成本更低的候选进来。没有一条推翻原目标，全是在原目标外面加证据约束。

## 🤔 我的判断

**定位**：测量基础设施加一份方法论审计，附带一个保守的工程改进样本。它的主要贡献不是 AGE，而是那张「得 / 丢」矩阵和「每个决策要用对应证据检验」的框架。

**亮点三条**：

1. 把 Champion 对 Seed 的比较从一个均值换成逐题、八遍、得丢分开的对账，这个口径应该成为所有 harness 进化论文的最低标准。
2. 用冻结池回放来审计 select 和 gate，不重跑进化就能检验规则好坏，成本低、可复现。
3. analyze 的裁判输入里刻意去掉奖励和验证器输出，只给行为证据。这是给进化里的裁判做「去泄漏」，和我们关注的 judge 防操纵、读写分离是一条线。

**问题与局限**：题量小、单一主模型 GPT-5.4；AGE 只在最弱基线上验证；跨基准迁移只有两对，覆盖在 τ²-bench 上下降而在 DeepSWE 上上升，作者给的解释（反馈比改动的影响面窄）合理但未被直接检验；专家评审是软证据。

**对工程的直接启发**：

- 我们自己的 harness 进化闸，晋升条件里至少要并列三项：可靠性不降、相对 Seed 的丢题数有上限、部署成本 \(C_{dep}@k\) 不超预算。单一均值做 gate 是不够的。
- 选父本时记录一个「后续增益」的回放指标，定期检查当前选择规则是不是在某类任务上低于随机。
- 拒绝「通用提醒式」的 mutation，要求每个改动附上观察、机制、激活条件和预期代价四件套，这一条几乎零成本，可以直接写进 mutate 的 prompt。
- 只改外层（Codex 那类）的 harness 做反思式进化时，Test 泛化最容易掉，要额外加留出集。

一句话收束：**自进化不是让分数涨，而是让涨的那部分在你没看的地方也站得住；这篇的价值在于，它第一次把「没看的地方」系统地数了出来。**
