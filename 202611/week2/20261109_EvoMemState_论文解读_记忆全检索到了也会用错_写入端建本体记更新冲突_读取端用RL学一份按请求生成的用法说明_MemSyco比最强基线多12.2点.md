# 记忆全检索到了也会用错：EvoMemState 写入端建本体记下「谁更新了谁、谁和谁冲突」，读取端用 RL 学一份按请求生成的用法说明，MemSyco-Bench 比最强基线多 12.2 点

你有没有过这种体验：助手记得你三个月前说过爱吃辣，也记得你上周说最近胃不好要清淡，结果推荐餐厅时还是给你一家川菜馆。两条记忆都检索到了，它没搞清楚哪条现在还算数、哪条只在特定场景生效。问题变成：**长期记忆除了存事实，要不要显式记录事实之间的更新、冲突和适用范围？检索全了之后，「这次该怎么用这些记忆」能不能从经验里学出来？**

厦门大学等机构的 **EvoMemState: Evolving Memory State for Personal Agents** 把记忆从「一堆独立事实」改成「事实 + 两种状态」：**Relational State** 持久保存每条事实当前是否有效、作用范围、以及和其他事实的 SUPERSEDES / CONFLICTS_WITH 关系；**Reasoning State** 由一个单独用 GRPO 训练的 4B 策略模型针对每次请求生成，说明哪些记忆适用、扮演什么角色、谁优先。看完我的感受是：**这其实是一套干净的记忆读写分离：写入端是离线建本体，读取端是学出来的用法策略，两边各自能换、各自能评。**

## 核心摘要

作者先在 MemSyco-Bench 的 Valid Memory Selection 子集上做了两个预实验：MemoryBank、LightMem、Supermemory 分别有 58.9%、61.8%、58.0% 的题没检索全；五个系统里四个在检索全时准确率比没检索全高 5.9 到 33.3 点；而在证据完整时让 agent 固定自我反思一遍，平均准确率反而从 50.5% 掉到 48.9%。EvoMemState 对应三个组件：**Ontology-Guided Memory State Induction** 按时间顺序抽取原子事实，增量维护一棵个人记忆本体（PARENT_OF / CONTAINS 结构边，CREATE / MERGE / SPLIT 改概念层级，SUPERSEDES / CONFLICTS_WITH 关系边），原始事实不覆盖；**RL-Based State Evolution** 用 GRPO 训练 Memory State Evolution Policy，奖励是冻结 agent「带 Reasoning State 作答」减「同样证据不带 Reasoning State 作答」的得分差；**State-Aware Reasoning** 先按语义检索种子事实，再沿关系边双向扩展，把事实、关系状态和生成的推理状态一起交给 agent。Qwen3-8B 下 MemSyco-Bench 平均 57.6%、GPT-4o-mini 下 58.9%，分别比最强基线高 12.2 和 5.9 点；四基准总平均 59.9 和 61.2，均为最高。代码在 https://github.com/XMUDeepLIT/EvoMemState 。

## 🎯 为什么这件事值得写

记忆系统这两年的主线是「事实中心」：Mem0 抽取与更新原子事实，A-MEM 动态链接相关记忆，MemGPT 分层存储，LightMem 压缩加选择性检索，Supermemory 与 SimpleMem 做生命周期管理。它们解决的是存什么、怎么找。

论文指出的两个洞都在「找到之后」：

1. **关系没被保留**：单独维护、单独检索的事实，可能缺了让它被正确解读的那条更新或冲突记录。
2. **全找到也不会用**：哪条适用、哪条已过期、冲突时谁优先，agent 每次都在现场重新判断，固定的反思提示还会让结果更差。

对关心记忆读写分离的人，这篇的结构很好借鉴：写入端产出的是带关系的持久状态，读取端产出的是一次性的用法说明，后者由一个单独模型学习，不污染存储。

## 🏗️ 机制：本体写入 + 学习型读取

### 写入端：本体引导的状态归纳

离线用 DeepSeek-V4-Flash 从对话里按时间顺序抽取 Persistent Facts，每条只含一个关于偏好、经历、信念、处境或约束的命题，带来源和时间。每来一条事实就并入本体：挂到最具体的概念节点，必要时新建、合并或拆分概念，并标注它是否取代了旧事实或与之冲突。每条事实的 Relational State = 当前有效性与范围 + 概念挂载与关系。后来的事实可以改这些属性和关系，但不改原文。事实用 bge-m3 编码做检索。

### 读取端：RL 学出来的 Reasoning State

策略模型从 Qwen3-4B-Instruct-2507 初始化。对每个训练样本，采样一组候选 Reasoning State，交给冻结的 Qwen3-8B agent 作答，奖励是「带该候选的得分」减「同证据不带推理状态的得分」，正奖励说明它让 agent 用对了证据，负奖励惩罚歪曲或削弱证据的候选。组内归一化后用 GRPO 更新，只训策略模型。

训练数据约 60K 条问题与记忆样本，来自 FEVER、SciFact 和 PersonaMem：客观题从事实核验改造，再从个人信念、身份、自认专业等角度构造与客观证据冲突的用户记忆；偏好题构造当前偏好、历史偏好、偏好更新场景；两类都混入干扰记忆，包括同一对话场景里不同话题的真实偏好，逼模型按内容与适用性判断，而不是看记忆条数或位置。

### 推理：检索 + 关系扩展 + 状态感知作答

按语义检索种子事实，沿关系边双向遍历把相关的更新、冲突、约束一并带出，去重后连同关系状态交给策略生成 Reasoning State，最后 agent 基于两种状态作答。

## 🧪 关键证据

### 主结果（四个基准，部分列）

| 系统（Qwen3-8B） | MemSyco 平均 | WTU 谄媚率（越低越好） | MemTrap 平均 | LoCoMo-R 裁判分 | 总平均 |
| --- | --- | --- | --- | --- | --- |
| A-MEM | 45.4 | 49.1 | 74.6 | 41.8 | 49.6 |
| SimpleMem | 37.7 | 58.6 | 79.9 | 51.3 | 53.6 |
| MemoryBank | 44.2 | 57.6 | 70.7 | 44.9 | 49.9 |
| **EvoMemState** | **57.6** | **38.0** | 79.1 | **57.4** | **59.9** |

GPT-4o-mini 下 EvoMemState 的 MemSyco 平均 58.9、MemTrap 平均 78.7、LoCoMo-R 裁判分 60.8、总平均 61.2，均为最高。LoCoMo-Refined 裁判分在两个模型上分别比最强基线高 6.1 和 7.0 点。

### 记忆状态是否起作用（Qwen3-8B）

- 平均完整检索率 85.6%，与最好的基线相当。
- 证据完整的题上，LoCoMo-Refined 准确率 70.8%、MemSyco-Bench 68.5%，分别比最强基线高 11.5 和 31.2 点。这一条最能说明「检索全了还要会用」。

### 跨系统迁移

把训好的策略接到六个基线记忆系统上，全部提升，幅度 0.2 到 4.9 点；NaiveRAG 和 MemoryBank 最多（4.9、4.8），A-MEM 3.4。

### 消融（Qwen3-8B）

| 变体 | MemSyco | LoCoMo-R | LoCoMo | MemTrap | 总平均 |
| --- | --- | --- | --- | --- | --- |
| 完整 | 57.6 | 57.4 | 45.5 | 79.1 | 59.9 |
| 去掉 Relational State | 48.7 | 54.9 | 45.2 | 72.7 | 55.4 |
| 去掉 Reasoning State | 49.6 | 55.8 | 42.5 | 64.1 | 53.0 |
| 有 Reasoning State 但不做 RL | 49.7 | 55.4 | 45.0 | 62.7 | 53.2 |

### 效率

LoCoMo-Refined 上平均每题检索上下文 565 token，命中率 0.816；MemoryBank 和 A-MEM 都是 0.789，分别用 816 和 1,440 token。LightMem 和 Mem0 上下文更短，但命中率只有 0.166 和 0.110。

## 🔬 最有意思的部分

**「不做 RL 的推理状态」和「没有推理状态」几乎一样差。** 消融里 MemSyco 49.6 对 49.7，总平均 53.0 对 53.2。也就是说，让一个 4B 模型照着提示写「记忆用法规则」本身没价值，价值全部来自用「对下游答案有没有帮助」做奖励的 RL。附录 C.2 的对照更直接：让作答模型自己生成指导（Self-Guide），学出来的策略在 MemSyco 上分别多 8.2 和 6.1 点，MemTrap 多 16.8 和 11.0 点，但在 LoCoMo 召回类任务上只多 0.9 和 1.0 点，GPT-4o-mini 的 LoCoMo-Refined 甚至降了 1.4 点。

这和预实验里「固定自我反思反而掉分」是一条线：**会不会用记忆不是靠多想一遍，而是靠一个用结果反馈训出来的、独立于作答模型的用法策略**。奖励设计成「带与不带的差」也很聪明，等于每个候选都在和同证据的基线做配对比较。

附录 C.1 里，和 MemGate（按查询过滤记忆）、Dynamic Partition（推理时分组）对比，学出来的规则在偏好变更题上 72.7%、偏好冲突题上 42.0%，比最强替代方案高 8.0 和 17.0 点；而 Dynamic Partition 把 Mem0 的偏好冲突准确率从 22.3% 拉到 8.7%。只过滤或分组，解决不了「哪条该说了算」。

## 🤔 我的判断

定位：**一套写入端建关系、读取端学用法的个人记忆框架**，在「记忆该不该用、怎么用」类基准上提升明显，召回类基准上优势有限。

亮点三条：

1. 预实验把「检索不全」和「检索全了也用错」两个问题分开测，后面的方法和评测都对着这两点设计，逻辑闭环。
2. 读写分离干净：本体与关系离线维护、原文不覆盖；Reasoning State 是一次性产物，策略可以单独迁移到其他记忆系统。
3. 配对式奖励（同证据有无推理状态的得分差）是一个可复用的「增量价值」训练信号。

问题与局限：

- **召回类指标并不总是最好**：Qwen3-8B 下 LoCoMo 的 token F1 是 41.6，低于 SimpleMem 的 46.4；MemTrap 平均 79.1 略低于 SimpleMem 79.9 和 LightMem 79.7，其中 Cognitive Bias 62.3 在各系统里偏低。
- **训练与评测的 agent 重合**：奖励用的冻结 agent 是 Qwen3-8B，主评测也用 Qwen3-8B；GPT-4o-mini 上的结果说明有一定迁移，但没有更大或更多样的作答模型。
- **裁判与写入共用一家模型**：本体构建和需要外部裁判的评测都用 DeepSeek-V4-Flash，论文没讨论这层耦合。
- **成本只报了检索上下文**：离线建本体每轮都要调 DeepSeek-V4-Flash，加上每次请求多跑一次 4B 策略，这些开销没有量化；也只覆盖文本，论文自己承认多模态没做。
- 没有报告多次运行方差或显著性检验。

对工程的直接启发：做 agent 记忆时，**写入端别只追加事实，至少记下 SUPERSEDES 与 CONFLICTS_WITH 两类边并在检索时沿边扩展；读取端别再加「请再检查一遍记忆」的提示，它可能是负收益**。如果要学用法策略，就用「同证据有无指导的答案得分差」作奖励，并把它挂成可单独评估的读取层。

一句话：EvoMemState 说明个人记忆的瓶颈不只在存和找，还在用；把关系写进存储、把用法交给一个用结果反馈训练的小策略，才让「全检索到」变成「用对了」。
