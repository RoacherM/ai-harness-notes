# 只奖励答对，agent 会学会不翻书：上海 AI Lab 用 158 本数学教材训「边读边证」，RL 后证明正确率从 51.5% 到 79.5%

你有没有过这种体验：给 agent 配了一个检索工具，或者挂了一份很长的参考文档，训练或调优一段时间后发现它越来越少去查了。分数在涨，你以为它学会了，其实它只是学会了靠自己硬做。等遇到真正陌生、必须翻资料的问题，它还是不翻。

这篇论文把这种能力叫作**自学习**（self-learning）：在任务进行中自主地检索、研读、应用长篇参考材料里的知识。它和 RAG 的区别在于，不是把检索结果拼进上下文就完了，而是推导卡住时发现缺一个前置定理、读到新定理后改写证明思路，两件事要互相推动。**问题是：怎么用强化学习把这种「边学边做」的习惯训出来，而且不让它在训练中退化成不查资料？** 看完我的感受是：这篇最有价值的不是最终分数，而是消融里那组工具使用率的数字。它把「只用结果奖励训 agent 会抑制探索」这件事量化得很干净，也给出了一个便宜的修法：用冻结的初始模型自己当逐轮工具裁判。

## 核心摘要

作者把 158 本本科和研究生数学教材解析成按章节索引的文本，把习题和答案从正文里分出来，答案对模型不可见，得到 5,183 道证明题，每本书平均 56 节、20.8 万 token。模型通过一个叫 BookNavigator 的接口读书，只有三个动作：`get_toc` 看目录，`search_index` 按关键词检索返回章节号和片段，`read_section` 读整节。最终证明由 GLM-5.2 对照隐藏的参考答案做 8 次独立评审，全部判对才给 +1，否则 −1。训练在 GRPO 上加了两样东西：一个**退火探索奖励**，答对且至少成功调用过一次工具的轨迹额外加分，系数按余弦从 1 降到 0.25；一个**逐轮工具信用**，用冻结的初始模型判断每一轮读书是有用、中性还是有害（看不到参考答案和最终对错），再把轨迹级优势按轮次重新分配，同时保持按 token 加权的平均优势不变。在 Intern-S2-Preview-35B 上训 50 步，自学习协议的整体证明正确率从 51.5% 升到 79.5%，比 RL 训过的最强固定检索基线（Top-k 章节，73.1%）高 6.4 点，在未见过的教材和未见过的学科上分别到 85.2% 和 86.7%。不用 BookNavigator、直接按原协议评测时，BrowseComp-Plus 和 CL-bench 也分别比基座高 1.7 和 2.3 点。反直觉的地方在于：训练前，让模型自己翻书反而比不给书还差（51.5% 对 55.7%）；只用正确性奖励训练时，正确率能涨到 74.9%，但带工具调用的轨迹从 36.9% 掉到 6.7%。这篇的定位是：**一个关于「结果奖励会让 agent 放弃工具」的干净证据，加一个低成本的过程信用方案**。

## 🎯 为什么这件事值得写

已有几条相关路线。Search-R1、R1-Searcher 一类用结果奖励训搜索策略；上下文学习研究看模型能不能从给定材料里学；元强化学习和测试时适应从环境反馈里学。这篇的设定卡在它们之间：参考材料是静态的长书，不是可以反复试错的环境；材料也不是预先组装好的上下文，模型得自己决定读什么；而且知识获取和推理必须交替进行。

数学证明是一个好选择，因为习题的答案已经从书里删掉了，模型没法直接检索到答案，只能找定义和定理再自己推。作者还特意剔除了题面里引用章节号的题，保证题目自洽。评测分四层泛化：同书新题（ID-Book，4 本书 205 题）、同学科新书（OOD-Book，7 本书 155 题）、新学科（OOD-Subject，19 本概率统计教材 266 题）、新任务类型（BrowseComp-Plus 和 CL-bench）。这个分层让「学会了怎么读书」和「背下了训练用的书」可以分开看。

## 🏗️ 机制拆解

**任务形式**：每个非终止轮 $t$，策略先产生推理 $z_t$，再选一个读书动作 $a_t$，拿到观察 $o_t$：

$$
(z_t, a_t) \sim \pi_\theta(\cdot \mid q, (z_i, a_i, o_i)_{i=1}^{t-1})
$$

终止轮不再读书，直接给出证明 $\hat{y}$。最多 8 轮交互，轨迹总长不超过 64k token。

**奖励**：

$$
R_n(\tau) = r(\tau) + \beta_n\, b(\tau)\, \mathbb{I}[r(\tau) = 1]
$$

$r(\tau) \in \{-1, 1\}$ 来自 8 次悲观评审；$b(\tau) = 1$ 当且仅当轨迹里至少有一次成功的工具调用；$\beta_n$ 按余弦从 1 退火到 0.25，保留一个正下限。注意探索奖励只发给答对的轨迹，所以不会奖励「乱翻书但答错」。

**工具信用**：冻结的初始模型作为工具裁判，看题目、截至当前观察的交互历史、以及下一轮的推理，给每一轮打标签。有用指拿到了相关新信息、澄清了一个未解决的条件或找到有意义的导航线索；中性指合理的探索或验证但没有体现收益；有害指明显冗余或无关的检索、重复已失败的请求、违反协议。映射为有害 0.5、有用或中性 1。然后

$$
\bar{c} = \frac{\sum_t m_t c_t}{\sum_t m_t},\qquad \tilde{A}_t = A + \alpha |A| (c_t - \bar{c})
$$

$m_t$ 是第 $t$ 轮里策略生成的 token 数，$\alpha = 1$。中心化保证按 token 加权的平均优势还是 $A$，只是把信用从有害轮次挪到其他轮次。工具返回的观察不进策略损失。

**对照协议**：不给书；Top-k 章节（先检索再把最多 8 节按相关度拼进 64k 上下文）；长上下文（按原书顺序拼）；Oracle 章节（直接给出题目来源那一节）。这几种都是一次性生成，没有交互。

## 🧪 关键证据

**主结果**（整体证明正确率，四次采样取平均）：

| 协议 | 训练前 | RL 后 | 提升 |
|---|---|---|---|
| 不给书 | 55.7 | 68.5 | +12.9 |
| Top-k 章节 | 62.2 | 73.1 | +10.9 |
| 长上下文 | 56.7 | 72.2 | +15.5 |
| Oracle 章节 | 60.9 | 71.0 | +10.0 |
| 自学习 | 51.5 | 79.5 | +28.0 |

训练前自学习是最差的，比不给书还低 4.2 点；RL 后变成最好的，涨幅也最大。连直接给出题目来源章节的 Oracle 都只有 71.0。这说明「给对材料」不如「学会边推边找材料」。

**收益归因**（同一个 RL 后策略，换参考条件评测）：

| 条件 | 训练前 | RL 后 |
|---|---|---|
| 原配教材 | 51.5 | 79.5 |
| 不给书 | 55.7 | 71.7 |
| 换一本同学科教材 | 49.6 | 75.2 |
| 删掉来源节及前后各 4 节 | 49.0 | 74.6 |
| 随机删掉 9 个其他节 | 53.0 | 79.8 |

两个读法。第一，RL 让不看书的能力也涨了 16 点，但看书仍然多出 7.8 点，所以不只是推理变强。第二，换书或删掉来源附近的内容，成绩仍高于不给书，说明策略能从别的书或别的章节找到需要的东西；但删来源附近比随机删同样数量的节低 5.2 点，说明删哪里确实有关系。

**跨任务迁移**：BrowseComp-Plus 用它原本的 BM25 检索，CL-bench 直接从给定上下文生成，都不用 BookNavigator。自学习训出的策略分别是 51.9 和 17.1，比基座高 1.7 和 2.3；而固定检索协议训出的策略在 BrowseComp-Plus 上全部低于基座。不过 CL-bench 的「程序性任务执行」一类，所有 RL 策略都低于基座，自学习掉 0.6 点。作者的解释是证明训练奖励的是构造推导，而程序性执行更看重照着既定流程满足细致的操作约束。

**诚实泼冷水**：跨任务的提升只有一两个点，没有报告方差或显著性。正确性由单一模型族的 8 次评审决定，悲观评审会降低假阳性，但没有和人类评审对照。只训了 50 步、只用了一个 35B 基座。

## 🔬 最有意思的部分

消融表是全文最值得抄下来的一张：

| 设置 | 整体正确率 | 带工具的轨迹比例 | 每条轨迹调用数 |
|---|---|---|---|
| 基座 | 51.5 | 36.9% | 1.5 |
| 只用正确性奖励 | 74.9 | 6.7% | 0.3 |
| 加工具信用 | 76.2 | 7.0% | 0.3 |
| 加探索奖励 | 77.0 | 79.9% | 5.9 |
| 两者都加 | 79.5 | 58.4% | 3.0 |

第一，**只用结果奖励，agent 学会了不翻书**。正确率涨了 23 点，工具使用却几乎归零。作者的解释很朴素：解题能力变强后，不查资料也能做对更多题，查资料的动机就没了。这类策略在需要主动获取知识的陌生问题上迁移会受限，对应的证据是工具信用单独加上时，OOD-Book 和 OOD-Subject 只变了 −0.8 和 +1.0。

第二，**工具信用和探索奖励是互补的，最好的组合并不是调用最多的那个**。只加探索奖励，调用数冲到每条 5.9 次，正确率 77.0；两者都加，调用数回落到 3.0，正确率反而最高。探索奖励负责「去查」，工具信用负责「别瞎查」。

第三，**过程裁判不需要比策略更强**。工具裁判就是冻结的初始模型，加上它后 ID-Book 涨了 3.3 点。作者的说法是收益来自监督粒度，而不是裁判能力。这对算力有限的团队很实用：不用为过程奖励单独找一个更大的判官。

## 🤔 我的判断

**定位**：方法论文，配一个构造很干净的训练环境；它对「持续学习」更准确的贡献是任务内的即时学习，而不是跨任务的参数更新。

**亮点三条**：

1. 用删除答案的教材构造了一个只能靠研读来解的环境，并用换书、删来源节、随机删节三组对照把「学会读书」和「记住书」分开。
2. 量化了结果奖励对工具探索的抑制：正确率在涨，工具使用从 36.9% 掉到 6.7%。这是很多 agent RL 训练里被分数掩盖的退化。
3. 逐轮工具信用用冻结初始模型当裁判、看下一轮推理做回顾判断、中心化保持平均优势，便宜且不改变结果信号的总量。

**问题与局限**：探索奖励的门槛是「至少成功调用一次工具」，这个门槛很低，策略可能学会象征性地调一次；论文用工具信用来抑制，但没有报告第一次调用的有用率。工具裁判的标签映射只有 0.5 和 1 两档，中性和有用不加区分，信用信号比较粗。跨任务迁移幅度小，而程序性执行一类退化，说明这种自学习未必适合工作流型 agent。

**对工程的直接启发**：如果你在用结果奖励或通过率门槛迭代 agent，请把工具使用率当成一个必须同时监控的指标，正确率上涨同时工具调用骤降是一个危险信号，意味着 agent 在放弃获取外部信息。过程裁判可以先用你当前的基线模型，冻结下来专门判「这一步读得有没有用」，并让它只看下一步推理而不看最终答案，避免把结果信息泄漏进过程信用。对 harness 设计者来说，BookNavigator 的目录、检索、整节阅读三件套也是一个值得借鉴的长文档工具接口：先给结构，再给定位，最后给完整上下文。

一句话收束：**这篇提醒我们，agent 不查资料不一定是不会查，更可能是你的奖励让它觉得不值得查。**
