# 把 agent 压到 4 比特，它为什么会先读文件再进目录？SteerDistill：让全精度老师只在出岔子的那一回合开口，改法让学生自己想

你把一个 8B 的 agent 模型量化成 INT4，部署成本立刻下来了，可任务成功率也跟着掉。翻失败轨迹会看到很具体的毛病：它想读一个文件，却忘了读文件工具只能访问当前目录，于是在进入目录之前就去读；或者它按要求创建了几个文件，其中一些却是空的，忘了写进指定内容。模型没有忘记怎么调用工具，它是**漏看了任务要求或环境条件**。

作者把这种现象叫**行为分歧**（behavioral divergence）：量化后的 agent 产生了和成功的全精度参考不同的环境状态转移。难点在于怎么纠正。离线数据是独立于学生收集的，未必覆盖学生出错的那些情境；让学生自己 on-policy 重试，又很少能在那些情境里碰对。作者在 BFCL V4 多轮诊断里测过，学生在分歧回合不加引导重试四次，至少有一次做对的比例只有 9.6%。**问题于是变成：怎么在学生真正出错的地方，造出它自己能做出来的正确示范？** 看完我的感受是：这是一个把「老师引导、局部验证、蒸馏内化」做成闭环的量化恢复方法，它的思路对任何「小模型接大模型的班」的场景都有参考价值，不止量化。

## 核心摘要

SteerDistill 是一种面向 LLM agent 的量化感知蒸馏方法，每个训练周期分两步。第一步是**老师引导的轨迹修订**：对学生的每条失败轨迹，找一条同任务同初始状态的全精度老师成功轨迹做参考，按环境状态对齐两条轨迹，定位第一个行为分歧回合；把历史和环境恢复到该回合之前，老师对比失败回答和参考，写一段结构化的引导提示，说明差异、适用条件和纠正规则；学生在这段提示下重新生成并执行动作，然后把产生的环境状态和返回信息与参考对比，不通过就由老师根据反馈改写引导，学生从同一个出错前状态再试，直到局部验证通过或用完每回合的尝试预算。通过的修正会被保留，哪怕整个任务最后仍然失败。第二步是**内化**：训练时学生看不到任何引导提示，在修正过的回合用前向 KL 去拟合「带引导的学生快照」的预测，在其他回合用反向 KL 去拟合全精度老师的预测。结果是推理时只用量化后的学生，没有老师也没有提示。在 Qwen3-8B、Qwen3.5-4B、Gemma 4 12B-it 三个模型和五个 agent 基准上，W4A16 下平均分比最强的量化基线 QeRL 高 1.67 到 2.18 分，和 BF16 的差距都在一分以内；同一诊断里引导把分歧回合的 Pass@4 从 9.6% 拉到 82.3%。这篇真正的价值在于：**纠错数据要在学生自己的失败情境里造，而且要让学生自己写出来，老师只负责指出漏了什么。**

## 🎯 为什么这件事值得写

量化恢复已经有两条成熟路线。一条提高量化表示本身的保真度，比如 GPTQ 这类权重重建、缩放和旋转方法。另一条用训练把能力补回来：用硬标签的量化感知训练（EfficientQAT）、用全精度老师软分布的离线蒸馏（BitDistiller）、on-policy 蒸馏（论文按 NVIDIA NeMo-RL 的工作流实现了 On-Policy QAD），以及用可验证奖励做强化学习的 QeRL。

这些方法放在 agent 上有个共同缺口：**训练数据里可能根本没有学生出错情境下的有效纠正**。离线数据不知道学生会在哪里出错；on-policy 数据知道在哪里出错，但学生自己很少能做对，奖励信号就很稀。老师直接接管又会产生学生很难模仿的回答。

这件事对做 harness 的人也有意义。我们一直在讨论「强模型开局、弱模型收尾」「大模型做计划、小模型执行」这类组合，SteerDistill 给出的是另一种思路：**不在推理时组合，而是在训练时让大模型在小模型出错的那一刻教一次，然后把这次教学蒸馏掉。**

## 🏗️ 机制 / 任务定义

**设定**。冻结的全精度老师 $\pi_T$，可训练的量化学生 $\pi_{Q(\theta)}$，两者来自同一个检查点，$Q$ 是固定的量化算子。第 $t$ 回合学生根据历史 $h_t$（任务、之前的回答和环境观察）生成回答。

**定位干预回合**。按环境状态对齐学生和参考轨迹，只看状态是否匹配；产生相同状态转移的不同动作视为等价。干预点是第一个行为分歧。

**闭环引导**。老师给出结构化引导提示 $g$，包含三部分：差异是什么、在什么条件下适用、纠正规则是什么。学生在 $g$ 下生成并执行。局部验证比较环境状态和返回信息。失败则老师根据反馈改写 $g$，从同一个出错前状态重试。

**修正保留**。通过验证的回答替换失败回合，学生在无引导下继续生成；若任务仍失败，再和参考对齐找下一个分歧。修订在任务成功、找不到分歧或某次干预用完预算时停止。即使任务未解决，已验证的修正也保留下来。

**内化目标**。设 $x$ 为去掉所有引导提示的历史和回答前缀。在修正回合，冻结的带引导学生快照基于 $(x, g)$ 预测，学习者只基于 $x$ 预测，最小化前向 KL：

$$\mathcal{L}_{corr} = \mathrm{KL}\big(\pi_{\text{steered}}(\cdot \mid x, g)\,\|\,\pi_{Q(\theta)}(\cdot \mid x)\big)$$

其余回合（包括修正之后未再纠正的续写回合），在学生生成的回答上用老师监督，最小化反向 KL：

$$\mathcal{L}_{other} = \mathrm{KL}\big(\pi_{Q(\theta)}(\cdot \mid x)\,\|\,\pi_T(\cdot \mid x)\big)$$

损失按回合分配，在所有保留的助手 token 上取平均。

## 🧪 关键证据或主结果

**五个基准**：BFCL V4（官方 Overall）、τ²-Bench（Pass@1）、WebShop 和 ALFWorld（成功率）、Search QA（七个问答数据集的 EM 均值，NQ 和 HotpotQA 为域内）。每个模型先用 GRPO 后训练得到任务专用的 BF16 检查点，作为老师和所有量化方法的起点。

Qwen3-8B 的主要结果：

| 精度 | 方法 | BFCL V4 | τ²-Bench | WebShop | ALFWorld | Search QA | 平均 |
|---|---|---|---|---|---|---|---|
| BF16 | | 46.89 | 32.64 | 68.58 | 79.92 | 39.65 | 53.54 |
| W4A16 | GPTQ | 40.73 | 26.85 | 59.24 | 71.32 | 33.64 | 46.36 |
| W4A16 | QeRL | 44.91 | 29.84 | 65.29 | 77.04 | 37.94 | 51.00 |
| W4A16 | SteerDistill | 46.84 | 31.79 | 68.41 | 79.75 | 39.12 | 53.18 |
| W2A16 | On-Policy QAD | 32.88 | 20.57 | 53.08 | 58.41 | 32.96 | 39.58 |
| W2A16 | SteerDistill | 38.12 | 23.68 | 55.71 | 63.27 | 34.05 | 42.97 |

W4A16 下距 BF16 只差 0.36 分。Qwen3.5-4B 上平均 60.95 对 BF16 的 61.68，Gemma 4 12B-it 上 64.31 对 65.13。W4A8 下比 QeRL 高 1.93 分，W2A16 下比 On-Policy QAD 高 3.39 分。唯一被反超的单项是 W2A16 下的 Search QA，BitDistiller 34.22 对 34.05。

**训练成本**。τ²-Bench 上，SteerDistill 在 32 GPU 小时的中间检查点就达到 31.68%，比 On-Policy QAD 在约 40 GPU 小时收敛的分数高 2.91 个百分点；比 QeRL 在 96 GPU 小时的结果高 1.84 个百分点，GPU 小时少 67%。这里的 GPU 小时已经包含老师引导和验证的开销，全部在 8 张 A100 80GB 上跑。

**推理成本**。τ²-Bench 上成功任务平均输出 4.0K token，BF16 是 3.9K，其他量化基线是 4.1K 到 5.2K；成功轨迹的交互步数和工具调用也更少。

**泼点冷水**。第一，所有方法都从 GRPO 后训练过的检查点出发，作者在附录给了直接从原始 Qwen3-8B 出发的结果，但主结论建立在这个更强的起点上。第二，NeMo-RL 的 QAD 流程和 QeRL 原本是为 Hopper 或 Blackwell 上的 NVFP4 设计的，作者把它们改到了 A100 上的分组整数量化，基线可能没有跑在最适合它的配置上。第三，方法依赖三个前提：要有老师的成功参考、能恢复出错前的历史和环境状态、局部验证可靠。作者在局限里明确说，**没有状态恢复或可靠局部验证的环境是否适用，还没有测过**；没有成功参考的失败轨迹会原样保留，拿不到任何修正。

## 🔬 最有意思的部分

消融都在 BFCL V4、Qwen3-8B、W4A16 上做，每一组都很有信息量：

| 问题 | 变体 | Overall |
|---|---|---|
| 完整方法 | | 46.84 |
| 在哪干预 | 随机可干预回合 | 43.52 |
| | 第一个动作不一致 | 45.01 |
| 怎么纠正 | 学生无引导重试 | 44.46 |
| | 老师直接接管 | 45.06 |
| 引导由谁写、什么格式 | 老师写自由文本 | 44.78 |
| | 学生自己写结构化 | 41.74 |
| | GPT-5.6-Sol 写结构化 | 45.27 |
| 保留什么 | 不做局部验证 | 42.18 |
| | 只留最终成功的 | 46.30 |
| KL 方向 | 全程反向 KL | 45.29 |
| | 全程前向 KL | 44.58 |
| | 方向对调 | 44.28 |

几个反直觉点：

**按环境状态找分歧，比按动作找更好**。不同动作可能产生同样的状态转移，按动作不一致去干预，会往蒸馏数据里塞进不必要的修改。随机选回合干预甚至低于 On-Policy QAD 的 44.43。

**老师接管不如老师指点**。同样从恢复后的状态出发，老师直接替学生回答只拿 45.06，让学生在引导下自己改拿 46.84。学生自己写出来的回答更贴近它自己的分布，蒸馏时更容易学会。

**自家老师比更强的外部模型更会教**。用全精度老师写结构化引导比用 GPT-5.6-Sol 写高 1.57 分，比学生自己写高 5.10 分。作者没有深入解释，我的猜测是同源老师更清楚学生在量化后丢了什么，这只是推测。

**局部验证比终局成功更重要**。去掉局部验证掉到 42.18，是所有消融里最大的跌幅之一；反过来，在局部验证之后再加「整个任务必须成功」的过滤，反而略降到 46.30，因为它丢掉了来自失败轨迹的有效修正。这一条和我们最近反复看到的结论一致：**过程级的可验证信号，往往比终局 pass/fail 更值钱。**

## 🤔 我的判断

**定位**：方法改进，面向量化 agent 的能力恢复，但闭环引导加局部验证的数据构造方式可以推广到更一般的大带小蒸馏。

**亮点三条**：

1. 把纠错数据的构造位置精确地放在学生自己的第一个行为分歧上，用环境状态而不是动作文本来判断分歧。
2. 老师只给结构化的指点，回答由学生在引导下自己生成，再用上下文蒸馏把引导去掉。这比老师代答更容易内化。
3. 用局部验证替代终局成功做数据过滤，既提高了数据量也提高了质量，训练时间还比 QeRL 少三分之二。

**问题与局限**：对可恢复状态和可验证转移的环境依赖很强，BFCL、WebShop、ALFWorld 这类模拟环境天然满足，真实的代码仓库或浏览器会难得多；基线迁移到 A100 整数量化后可能不在最佳状态；局部验证只检查当下的状态影响，不保证最终成功，也不保证回答里每一步推理都对。

**对工程的直接启发**：如果你在把一个大模型 agent 换成量化版或者更小的模型，先别急着跑大规模 RL。先拿几百条失败轨迹，和大模型的成功轨迹按环境状态对齐，看第一个分歧回合到底漏了什么条件。这一步本身就是一份很好的失败分类报告。再往前走一步，就是让大模型写一段「差异、条件、规则」三段式提示，看小模型能不能在提示下自己改对，能改对的那些就是最值得蒸馏的数据。

一句话收束：**SteerDistill 的取舍是用一次昂贵的闭环教学换一份精确定位的纠错数据，它赌的是：学生缺的不是能力，而是在关键那一步被人提醒一句。**
