# harness 进化论文终于肯说实话了：情绪识别涨了 13 点，进化本身只贡献不到 1 点，而且一个都过不了 Holm 校正

你有没有过这种体验：看一篇「冻结模型 + 自动进化 harness」的论文，摘要里写着提升十几个点，你想把它的进化循环搬回自己的系统，结果复现时发现大头其实来自「多给了模型一份输入」，进化循环本身几乎没动分数。行业里这一路叫 **Meta-Harness / harness evolution**：模型权重不动，让一个更强的 Builder LLM 读失败轨迹、改 prompt、改设置、改验证代码。问题是，**涨分到底是进化循环挣来的，还是人手写的脚手架和额外证据挣来的？**

这篇来自 UIUC、UC Davis、斯坦福的 EmoHarness 做的是多模态情绪识别：小模型在画面、语言、语气互相矛盾时容易判错，作者给它套一个 harness，再用 Meta-Harness Evolving（MHE）去进化。难得的是，它把收益一层一层拆开，用配对 bootstrap 和 Holm 校正去检验每一层。看完我的感受是：这是一篇**把自己方法的增量测成「统计上不显著」还照实写进摘要**的论文，比结论本身更有参考价值的是它的拆账方式和那几道 gate 的副作用。

## 核心摘要

EmoHarness 把一个冻结的小多模态模型（student）放进 harness 里：固定预处理用 Whisper large-v3 出转写、用 openSMILE eGeMAPSv02 出韵律描述（只描述「音高偏高」这类，不给情绪标签）、按 2 fps 缓存帧；人写的初始脚手架 Shared 用四次 student 调用，Observe 把面部、肢体、场景、时间线索编号成 v1、v2……，转写和韵律编号成 a1、a2……，Propose 给出带置信度和证据编号的候选标签，确定性代码核对编号再排序，Review 复查，一个固定控制器最多选三个标签，Explain 写解释但改不了标签。MHE 用 GPT-5.6 Luna 或 GPT-6.1 Sol 当 Builder，跑 4 代，每代读 student 在构建集上的失败（按混淆对和跨模态冲突聚类）提最多 4 个候选改动；候选先过文件范围、schema、可加载、静态代码检查和一个审稿人，再在独立验证集上过四道门：验证 Recognition 必须更高、已解出题的回退率不超过 5%、平均调用不超过 4.5 次、推理质量代理分不低于现任减 0.02。Builder 看不到验证分数和 gate 决定，更看不到评测集。在 5,507 道 MME-Emotion 评测题上，四个 student（Qwen3-VL-8B、Qwen3-VL-4B、Qwen3.5-4B、Gemma-4-E4B）乘两个 Builder，EmoHarness 比单次纯视频调用高 7.6 到 13.4 点；但其中转写和韵律文本单独就贡献 +5.38 到 +10.71，脚手架相对「视频加音频文本单次调用」是 -0.79 到 +2.54，**进化出来的改动相对脚手架只有 -0.07 到 +0.95，八个对比没有一个通过 Holm 校正**（最小校正后 p = .192）。它真正的价值定位是：**一份关于「harness 进化收益该怎么拆账、gate 会怎么限制进化」的负结果报告。**

## 🎯 为什么这件事值得写

情绪识别本身不在我们仓库的主线上，但这篇的实验设计正好踩在我们关心的问题上：**冻结模型 + 进化 harness + 统计验收门**。我们前面收过 EvoAudit（十六个进化 agent 全都边得边丢）、ParetoSaddler（贝叶斯自助法管晋升）、ContinualHarness（Meta-Harness 五轮反而掉分），讨论的都是「进化循环到底贡献了什么」。EmoHarness 给了一个干净的四级对照：

| 条件 | 含义 |
|---|---|
| Video | student 看视频，单次调用 |
| Audio | 再加转写和韵律文本，仍是单次调用 |
| Shared | 人写的四调用脚手架 |
| MHE | Builder 进化 4 代后冻结的 harness |

于是 Audio 减 Video 是「多给证据」的收益，Shared 减 Audio 是「人写流程」的收益（但混了四件事：多步流程、调用次数变多、后续调用只看文本记录、预测标签变多），MHE 减 Shared 才是进化本身的收益。很多论文只报「最终 vs 最朴素基线」，这一拆，结论就完全不一样了。

## 🏗️ 机制 / 任务定义

harness H 调用冻结 student \(M_\theta\)，输入视频 v、固定预处理 P(v)、请求 q 和允许标签 \(Y_q\)，输出标签、解释和轨迹：

$$
(\hat{Y}, z, \tau) = H(M_\theta;\, v, P(v), q, Y_q)
$$

MHE 只能改 H 里的 prompt、设置（比如转写怎么呈现）和受限的验证代码；感知工具、证据与输出 schema、输出控制器都锁死。

回退率定义为：设 \(S_t\) 是到目前为止任一现任 harness 在验证集上解出过的题，

$$
\rho_t(H) = \frac{|S_t \setminus \mathrm{Solved}(H; D_v)|}{|S_t|}
$$

候选替换现任的条件是四条同时成立：

$$
\hat{R}_v(H) > \hat{R}_v(H_t),\quad \rho_t(H) \le \delta,\quad c(H) \le B,\quad \hat{Q}_v(H) \ge \hat{Q}_v(H_t) - \epsilon
$$

其中 \(\delta = 0.05\)、\(B = 4.5\)、\(\epsilon = 0.02\)，\(\hat{Q}_v\) 是 GPT-5.6 Luna 在固定 200 题子集上给非最终推理步打的正确率，只用于选择。没有候选通过，就保留现任；4 代都没晋升，最终 harness 就是 Shared 本身。

数据切分：构建集 399 题、验证集 394 题、评测 5,507 题（去掉所有与构建、验证和 129 题保留集媒体重叠的条目），其中 2,963 题属于构建时见过的三类任务，2,544 题属于五类没见过的任务。评分 Recognition 在本地算，不用 LLM judge；单标签看第一个预测，多标签算召回式的覆盖比例（多报不扣分）。所有区间是任务分层的配对 bootstrap（10,000 次重采样），八个 MHE 减 Shared 对比算一个 Holm 族。

## 🧪 关键证据或主结果

| Student | Video | Audio | Shared | MHE Luna | MHE Sol |
|---|---|---|---|---|---|
| Qwen3-VL-8B | 29.95 | 39.15 | 40.47 | 40.68 | 40.52 |
| Qwen3-VL-4B | 29.39 | 38.39 | 37.60 | 38.56 | 37.85 |
| Qwen3.5-4B | 29.62 | 34.99 | 37.23 | 37.23（未晋升） | 37.25 |
| Gemma-4-E4B | 27.03 | 37.74 | 40.28 | 40.21 | 40.39 |

（任务宏平均 Recognition，%）

几条读法：

- **大头是证据，不是流程，更不是进化**。Audio 减 Video 是 +5.38 到 +10.71；进化相对 Shared 最大的一格是 GPT-5.6 Luna 在 Qwen3-VL-4B 上 +0.95（95% CI [+0.12, +1.82]），校正后 p = .192。GPT-6.1 Sol 的四个 harness 都只比 Shared 高 0.03 到 0.25。
- **脚手架的收益有一部分是评分规则送的**。在细粒度和多标签两类任务上，Shared 比 Audio 报更多标签，而召回式评分不罚多报。改用集合 F1 评这两类，Shared 减 Audio 从 +2.23、+2.54、+1.32、-0.79 变成 +1.10、+1.00、-0.25、-1.41；**F1 口径下，两个 Qwen3-VL 的所有 harness，不论人写的还是进化的，都低于单次 Audio 调用**。
- **验证集上的增益到评测集就缩水**。两个 Builder 一共晋升了 11 次（Luna 6 次、Sol 5 次），验证集上最多涨 2.54 点；按验证集同样的口径在 2,963 道见过类型的评测题上算，七个被晋升的 harness 变化在 -0.20 到 +0.30 之间；Luna 在 Qwen3-VL-8B 上那个 harness 从 2.54 掉到 0.10。
- **迁移到意图问答**（IntentQA，2,134 题）：加入 harness 写的情绪上下文，三个 student 小幅上涨（+0.23 到 +1.87），Qwen3.5-4B 掉 1.50 和 1.41；八个对比都没过 Holm（最小校正后 p = .085）。作者也承认没有长度匹配的对照，涨的可能只是输入变长。

作者自己交代的污染：评测集里有 986 道题在开发期间被人看过，具体是哪些已经无法识别。这可能影响人写的脚手架，但 Builder 从来没见过评测题。

## 🔬 最有意思的部分

**第一，回退门把所有大改动都挡掉了。** 两个 Builder 提出的候选里，有 12 个在验证集上多解出了至少 8 道题（2.03 点），**全部因为回退率超过 5% 被拒**，其中 9 个是 Qwen3.5-4B 的：它的 prompt 改动平均会翻转 56 道构建题的对错，其他 student 只有 23 到 27 道。剩下被晋升的 harness 都很保守，每个只改了不到 4% 评测题的标签集。这正好是 EvoAudit 那篇「边得边丢」的另一面：**你用回退门保护已解出的题，就同时堵死了大幅重写的路**，到底哪种更能泛化，作者说需要单独的测试集来回答。

**第二，晋升门没有设最小幅度。** 每代从最多 4 个候选里在 394 题上挑最好的，赢家在验证集上的增益天然高估；更夸张的是，11 次晋升里有 3 次只靠验证集上多对 1 道题（0.25 点）。这是一个非常具体、可以直接修的 gate 漏洞：Recognition 门应该要求超过一个 bootstrap 区间或至少几道题的差距。

**第三，改动是「写给 student 的指令」，student 不一定听。** 作者挑的失败案例里，Luna 为「中性被判成沮丧」专门加了一条规则：把中性当作严肃的备选，不要把话题本身的难受当成情绪表露。结果 Gemma-4-E4B 的复查输出里根本没提中性，还继续引用了一个任何采样帧里都没有的「双臂交叉」。全量看，这个 harness 改了 Shared 在 169 道题上的标签集，46 道变好、45 道变差、78 道不变。**Builder 改得再对，执行者的指令遵循能力才是上限。** 作者建议未来的 gate 检查轨迹是否真的应用了改动、引用是否和媒体一致，这一条我很认同。

**第四，唯一显著点的那格恰好是「脚手架比单次调用还差」的那个 student。** Qwen3-VL-4B 是唯一一个 Shared 低于 Audio 的 student，也是进化收益最大的一格（+0.95，主要在没见过的任务类型上 +1.24），改了 21.6% 题目的标签集，281 道变好、233 道变差。换句话说，进化最有用的时候，是在修人写脚手架的坑。

## 🤔 我的判断

**定位**：测量与拆账样本，外加一份诚实的负结果。方法本身是 Meta-Harness 的一个变体（Builder 只看单个 student 的聚类失败、验证分数对 Builder 不可见、单一现任链），不算突破。

**亮点三条**：

1. 四级对照（Video、Audio、Shared、MHE）把「证据、流程、进化」三种收益分开报，这应该成为 harness 进化论文的默认写法。
2. 配对 bootstrap 加 Holm 校正，并且把「没有一个进化增量通过校正」写进摘要，统计上很干净。
3. 对 gate 副作用的分析（回退门挡掉全部大改动、无最小幅度导致单题晋升、验证增益在评测上缩水）非常具体，可以直接拿来改自己的晋升规则。

**问题与局限**：每个 student 和 Builder 组合只跑了一条四代进化，没有进化本身的方差；验证集只有 394 题，四道门在这个规模上很难区分 1 点以内的差别；评测集有 986 题被人看过；召回式评分对多报宽松，作者用 F1 补了一刀但主表仍是召回式；IntentQA 迁移没有长度匹配对照。

**对工程的直接启发**：

- 报 harness 进化收益时，至少要拆出「多给的输入」「人写的流程」「进化的改动」三层，各自给配对区间。
- 晋升门加最小幅度，比如超过验证集 bootstrap 区间的下界，否则 4 选 1 加小验证集几乎必然高估。
- 回退门的阈值要和 student 的「翻转率」一起看：对改一句 prompt 就翻 56 道题的模型，5% 回退门等于禁止进化。
- 加一道「改动是否被执行」的检查：抽样轨迹，看新加的规则有没有在推理里被提及和使用，引用的证据编号是否真在输入里。
- 小模型的 harness 进化，先把输入做全（这里是转写和韵律），往往比让 Builder 反复改 prompt 划算得多。

一句话收束：**这篇最该被引用的不是 13.4 点，而是那句「没有一个进化增量通过 Holm 校正」；它提醒我们，harness 进化的第一道门，应该是先证明进化本身有贡献。**
