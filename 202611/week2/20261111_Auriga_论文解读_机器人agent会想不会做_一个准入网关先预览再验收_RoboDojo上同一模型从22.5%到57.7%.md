# 让大模型不碰机械臂直接挪物体能成 76%，一上手臂只剩 22.5%：Auriga 用一个准入网关把差距补回了 68%

你有没有过这种体验：让 agent 写一段操作脚本，脚本正常退出、返回码 0，你以为事情办完了，回头一看，它中途有一步根本没生效，后面八步全是在错误状态上继续跑的。软件里这叫「静默失败」，到了机器人上就更狠：抓空几毫米、运输途中掉了、撞到容器边缘，而且**场景不能 reset，失败会永久改变现场**。行业里把这类问题叫 **planning-execution gap**：模型知道该干什么，就是做不到。那么，**缺的到底是更好的策略模型，还是一层会预览、会验收、会喊停的 harness？**

这篇 Auriga 技术报告给出的答案是后者。它是一个任务无关的 agent harness：模型做全部决策，harness 只负责测量、预览、执行、验收和报告。看完我的感受是：虽然场景是具身操作，但它的「单一准入网关 + 执行回执」设计，和我们在软件 agent 里讨论的「工具调用必须带可验证 receipt」是同一个思想，而且它用消融把 code-as-policy 的静默失败量化了出来。

## 核心摘要

作者先在 RoboDojo 的 42 个任务上做了一个 210 回合的诊断：给 GPT-6 Astra 一个特权动作，让物体沿选定路点直接移动、不经过机械臂，成功率 76.2%；改用基准自带的末端执行器参考接口 RoboProbe 驱动机械臂，只剩 22.5%。模型通常认对了物体和目的地，错在执行。Auriga 的做法是把决策、能力、准入三层分开：模型在一个持续会话里维护显式任务信念 \(B_t\)（当前计划、未决问题、任务前提的 pending、supported、contradicted、unknown 状态），完整交互日志放在上下文外的证据记录 \(E_t\) 里按需检索；能力层提供相机标定、VGGT-Omega 深度、SAM 3.1 分割、射线与平面求交、双视角三角化、手内滑移测量，动作目标以手指接触区域而非腕部法兰来指定，双臂共享一条时间线；所有物理动作，无论模型直接调用还是模型写的 Python 程序发起，都必须经过单一准入网关 \(\mathcal{A}\)：先在仿真暂停时生成轨迹预览（路径、步数代价、净空警告），执行时按模型给的每段到达容差 \(\tau_k=(\delta_p,\delta_\theta)\)、夹爪开度和观测检查点逐段验收，一旦某段超差就停机，返回一张回执，列出已完成段、实测偏差、未执行段和新的相机视图。经过 13 轮跨任务能力迭代后冻结，Auriga 在 RoboDojo 42 个任务、6,300 回合上拿到 57.7% 成功率（64.0 分），是同模型参考 harness（22.5%、29.0 分）的两倍多，排行榜总分第一；在诊断集上补回了 68.3% 的 planning-execution gap；在 RoboCasa365 的 50 个未见厨房任务上成功率 73.2%。它的价值定位是：**证明在通用模型之上，一层「预览、验收、回执」的执行 harness 比换策略模型更能缩小知行差距。**

## 🎯 为什么这件事值得写

把通用模型放到机器人上，常见两条路，作者认为都只是间接地处理了执行：

- **逐步输出动作**（参考 harness 和 VLA 策略）：每次调用只发一步或一小段动作，模型提交前看不到完整路线，失败要等读到下一帧才发现，那时机械臂已经动了。
- **代码即策略**：模型写程序直接控制接口，执行判断交给一个看不见场景的程序。程序只有被写了检查才能发现失败，而且动作失败了也可能正常退出。

另一类方法（论文提到 HexaShell、EmbodiedEvo、SEAR）则在目标任务上反复 reset、多次试，调坐标偏移、脚本或失败笔记。作者引用一个 L0 到 L5 的 RSI 分级：这类属于 L0 到 L2 的「任务内搜索」，收益主要留在练过的布局上，布局一变就掉。Auriga 宣称自己做的是 L3 到 L5：把跨任务反复出现的失败，变成共享工具、接口和验证步骤的升级，而评测时严格单回合零样本，不在目标任务上做任何预演、示范或 reset。

这个分野对软件 agent 一样适用：**你是在给某个 benchmark 调 prompt，还是在补 harness 缺的通用能力？**

## 🏗️ 机制 / 任务定义

三层分工：

| 层 | 负责什么 | 不做什么 |
|---|---|---|
| 决策（模型） | 计划、选动作、设容差、放检查点、恢复策略 | 不直接碰电机 |
| 能力（工具） | 3D 测量、手指参考的双臂动作、历史检索、程序运行 | 不替模型做任务判断 |
| 准入（网关 \(\mathcal{A}\)） | 预览、逐段验收、超差停机、写回执 | 不含任何任务特定规则 |

保持任务无关的三条规矩：没有任务特定逻辑和特权仿真状态、只提供通用测量和控制工具、所有物理动作只有一个入口。

一次物理动作的生命周期是 preview、execute、verify：

1. 模型提交一个多段双臂动作序列（可以来自直接调用，也可以来自模型写的程序）。
2. 仿真暂停，\(\mathcal{A}\) 规划轨迹并给出预览：路径、步数代价、净空警告，还能投影到相机图像上。
3. 模型审阅后放行，执行过程中 \(\mathcal{A}\) 按每段的 \(\tau_k\)、夹爪开度、检查点验收。
4. 超差即停，返回回执 \(r_t\)，模型在当前状态上原地恢复，而不是重来。

13 轮开发迭代的关键里程碑：#2 动作预览（26.2 分）、#3 统一双臂动作、#4 按原文传入任务说明的 harness 重构（45.5 分，42 任务成功率 36.2%）、#6 标定 3D 几何加历史检索（46.6 分）、#7 ROI 放大、#9 分段容差与障碍检查、#11 显式运动控制、#12 换上 VGGT-Omega 和 SAM 3.1 后冻结（64.0 分，57.7%）。最初的 #0（基础模型循环）在 50 个诊断案例上只有 21.5 分、4.0% 成功率。

## 🧪 关键证据或主结果

**RoboDojo 主结果**（42 任务、五个维度、三个 seed、6,300 回合）：Auriga 平均 64.0 分、57.7% 成功率，排在榜首；第二名是 agent 加世界动作模型的 GO-3 Nano Preview（61.90 分、56.42%）。agent 组里，PyRUA-Lean、HexaShell-Preview、EmbodiedEvo、RoboProbe 都用 gpt-6-astra，和 Auriga 是同一个基础模型，Auriga 领先 agent 组全部 12 列，次优的 PyRUA-Lean 是 55.26 分、50.35%。

**诊断集上的差距补回**（210 回合）：

| 方法 | 平均成功率 | 精度维度 | 长程维度 | 记忆维度 |
|---|---|---|---|---|
| 特权直接移动物体 | 76.2 | 65.0 | 70.0 | 96.7 |
| RoboProbe 参考接口 | 22.5 | 2.5 | 7.5 | 40.8 |
| Auriga | 59.2 | 50.0 | 45.0 | 90.0 |

**场景随机化**：12 个泛化任务上，学习型策略在随机布局上成功率最多掉 33.9%；Auriga 在标准场景 52.3%、随机场景 45.6%，两者都排第一。

**RoboCasa365**（50 个 Target50 移动操作任务，未见厨房，250 回合）：总成功率 73.2%（已见原子任务 92.2%、已见组合任务 67.5%、未见组合任务 57.5%），不用学习型策略也不用跨回合记忆。

**消融**（固定配置，10 个任务，各 30 到 50 个案例）：

| 去掉什么 | 完整版 | 消融版 |
|---|---|---|
| 全部几何工具 | 46/50，94.9 分 | 30/50，67.1 分（首次抓取保持率 65.3%） |
| 轨迹预览 | 42/50，88.5 分 | 36/50，74.7 分（每回合 4.31 次未审阅动作） |
| 净空审查 | 36/50，79.8 分 | 31/50，69.1 分 |
| 超差停机 | 36/50，79.8 分 | 34/50，75.1 分 |
| 手指参考目标（改用腕部法兰） | 39/50，83.9 分 | 37/50，77.1 分 |
| 程序发起动作需经网关并带回执（改成 code as policy） | 30/30，100 分 | 20/30，77.2 分 |

**成本**：每回合平均 47.5 次模型调用、563 万输入 token（85.4% 命中 prompt cache，未缓存 82 万）、1.83 万输出 token、18.8 分钟；PyRUA-Lean 是 25.7 次调用、75 万输入 token、12.7 分钟。也就是说，Auriga 的输入 token 大约是 PyRUA-Lean 的 7.5 倍。

泼几盆冷水：

- **「零样本」只针对评测回合成立**。13 轮开发迭代本身就是在 RoboDojo 42 个任务上看失败、补能力、测分数的（论文写得很清楚，分数从 #4 的 36.2% 一路到 57.7%）。没有对目标任务 reset 调参不假，但 harness 的设计选择是在同一个基准上迭代出来的，这和「在一个基准上调 prompt」的界限，比作者的 L0 到 L5 分级显得更模糊。RoboCasa365 那个 73.2% 是更干净的证据，但论文没有和更多同协议的强基线做对比。
- **消融只在 10 个任务上做**，每格 30 到 50 个案例，像「超差停机」这一项 36 对 34，差距很小，没有给置信区间。
- **成本口径不完全对等**：作者指出跨回合进化的方法还有评测前的试验成本没算进单回合数字，这是公平的；但 Auriga 单回合的 token 和时间明显更高，实际部署时这是一笔账。
- 全部是仿真结果，作者把力敏感的连续操作、降低思考延迟列为未来工作。

## 🔬 最有意思的部分

**第一，code as policy 的静默失败被量化了。** Code as policy 那一格的程序在 30 个回合里发起了 120 个物理动作，其中 2 个因为超出到达容差被停、1 个停在检查点；因为没有回执，**这些程序全部以退出码 0 结束，其中一个在出错后又继续发了 8 个动作**。完整版里，程序可以自由做计算和查询，但每个物理请求都必须进网关、等模型审阅预览、拿回执，结果 30/30 全成，而且每回合模型调用从 71.8 次降到 46.2 次。这对软件 agent 的启发非常直接：**让 agent 写脚本批量调工具可以，但每个有副作用的调用都应该经过同一个闸并返回结构化回执，而不是只看脚本的返回码。**

**第二，「只在模型选的地方暂停」比「处处暂停」好。** 每次夹爪动作后都强制插检查点，每回合暂停 13.82 次，成绩反而从 42/50 掉到 37/50。验收要有，但让模型自己决定在哪儿看，比 harness 机械地到处设卡更有效。这和我们在 human-in-the-loop 审批上的经验一致：审批点太密，信号就被稀释了。

**第三，任务信念的四值状态。** 抓取成功、运输保持、放置稳定被当作三个独立条件记在 \(B_t\) 里。swap_T 任务里，机械臂报告运动完成、夹爪开度归零，但蓝色积木其实滑到了桌上；模型把「蓝块保持」标成 contradicted，同时保留已经放好的粉块为 supported，换用离得近的左臂完成交换。**把「工具说成功了」和「世界状态确实如此」分开记，并允许后者推翻前者**，是长程 agent 不丢进度的关键。

**第四，大部分提升来自让模型看得见、量得准。** 去掉几何工具掉得最多（46 到 30），这时首次抓取只有 65.3% 能保持住；只留射线与平面求交时是 40/50、85.7%。论文开头那个结论，模型会想不会做，在消融里被具体化为：它缺的首先是毫米级的测量，其次才是更聪明的计划。

## 🤔 我的判断

**定位**：工程样本，而且是「harness 比模型更重要」这一论点在具身领域里最有说服力的一份证据之一。方法上的每一块（轨迹预览、分段容差、显式信念）单独都不新，新的是用单一准入网关把它们串起来，并坚持任务无关。

**亮点三条**：

1. 先用「特权直接移动物体」测出上限，再报补回了多少差距，这种先量化 gap 再做系统的写法很干净。
2. 单一准入网关加结构化回执，让模型写的程序也能被验收，并用消融证明了 code as policy 的静默失败代价。
3. 显式任务信念加上下文外的证据记录，在长回合里控制上下文，同时允许执行反馈推翻工具的自报结果。

**问题与局限**：harness 在评测基准上迭代开发，「零样本」的含义需要读者自己掂量；消融规模小、没给区间；单回合成本明显高于同模型的其他 agent 方法；只有仿真；正文没有列出机构信息。

**对工程的直接启发**：

- 给有副作用的工具设单一入口，所有调用（包括脚本里发起的）都要返回回执：完成了哪些步、偏差多少、还剩哪些没执行。
- 让模型在提交前能看到「这一批动作会做什么」的预览，对软件 agent 来说就是 dry-run 或 diff 预览。
- 容差和检查点交给模型按任务设，harness 负责严格执行和停机，而不是 harness 自己到处设卡。
- 信念状态区分「工具报告」和「世界观测」，允许后者把前者标成 contradicted。
- 改 harness 时问一句：这是给某个任务的补丁，还是给所有任务的能力？只收后者。

一句话收束：**模型已经知道该做什么了，Auriga 证明剩下的那一大截差距，可以靠一层只管「先看再做、做完验收」的 harness 补回来，代价是更多的 token 和时间。**
