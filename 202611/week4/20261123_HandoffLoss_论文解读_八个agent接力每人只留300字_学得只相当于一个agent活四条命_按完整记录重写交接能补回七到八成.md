# 八个 agent 接力，每人只给下一个留 300 字，学到的只相当于一个 agent 活了四条命；交接笔记改成每次从完整记录重写，同样 300 字能补回七到八成损失

你有没有过这种体验：一个长任务跑到上下文快满，harness 自动做了一次 compaction，agent 拿着摘要接着干，前面已经排除掉的几种可能又被试了一遍；或者主 agent 给子 agent 写了一份 brief，子 agent 回来的报告又被压成下一份 brief，几轮之后，最开始那几次失败里藏着的线索谁也不记得了。行业里管这件事叫 handoff、compaction、rolling summary，名字不同，操作是同一个：**把自己学到的东西压成一段短文本，让下一个接手的人从文本而不是从经历继续。问题是，一个 agent 自己还没想明白的东西，能不能靠一张便条传下去？**

北京邮电大学 Yibo Liu 的单作者论文 **Agents Cannot Hand Over What They Have Not Yet Understood** 专门测了这件事。它造了 56 个带隐藏规则的小世界，让规则本身成为有标准答案的「要交接的知识」，然后把交接损失拆成三块分别量。看完我的感受是：**这篇给「rolling summary 为什么会越滚越差」提供了第一份可以分解的证据，而且结论很具体：贵的不是压缩本身，是拿摘要去写摘要。**

## 核心摘要

每个世界是一个确定性的文字小程序，agent 每「条命」读屏幕、回一到五个动作，直到步数用完、触发终止规则或到达目标；屏幕上有 5 个进度标记，一条命的得分是到达的最高标记。不告诉规则的 agent 一条命内基本失败，拿到设计者写的 300 字以内规则说明（中位 253 字）的 agent 几乎总能成功；每个世界有 16 个布局不同的实例，相邻两条命用不同实例，所以传路线没用，只有传规则有用。规则被拆成 323 条可判对错的事实（每个世界 5 到 8 条），交接笔记可以逐条打分。核心对比是 Memory（一个 agent 连玩八条命、保留全部历史）和 Relay（八个 agent 各玩一条命，只继承上一个写的 300 字笔记）。六个模型全部在接力里学得更少：第八代接力的得分只相当于单 agent 第 4 条命左右（两个较弱模型是 2.5 和 3.0），模型从历史里学到的东西有 19% 到 48% 没穿过笔记。再加两个对照把损失拆开：每个新 agent 直接拿到之前所有命的完整记录（Record relay）时和 Memory 一样好，说明换 agent 本身不亏；笔记仍限 300 字但写的人可以看全部历史记录（Compaction relay）时，两个最强模型在损失最大的十个世界上补回了 70% 和 82%。换句话说，损失大头来自「从上一张笔记加一条命去写下一张笔记」这种反复压缩。要求写证据、改写旧笔记、写确认/排除/待定账本都没用；笔记放长到 1,500 字有帮助，但看完整记录写的 300 字已经接近甚至超过普通的 1,500 字笔记。这篇的价值定位是：**一套能把交接损失拆成「换人、压一次、反复压」三份的测量协议，加上一条可以直接落到 harness 的建议：保留原始记录，每次从记录而不是从上一份摘要重写。**

## 🎯 为什么这件事值得写

agent 跨上下文窗口工作、或者多个 agent 分工，都绕不开同一个动作：写一段短文本交给继任者。context compaction 在一次运行内做，reflection 和长期记忆跨 episode 做，子 agent 汇报和接管别人没做完的活跨 agent 做。作者把这些统称为 handoff。

现有评测测不清这里丢了什么，原因很根本：**真实任务里，写交接的那个 agent 到底「知道」什么是观测不到的**。一次失败的交接有两种可能，要么它压根没搞懂，要么它搞懂了没写出来。于是已有的 handoff 和 compaction 研究只能测下游成本或完成率，记忆基准只能测 agent 被告知过的事实能不能回忆起来。没有人测过：**agent 自己摸索出来的东西，有多少能活过「写下来」这一步。**

论文 Table 1 把这一点列得很清楚：对比人类传递链实验（Tessler et al. 2021）、LLM 传话游戏、Handoff Debt、Lost in Compaction、LongMemEval、ARC-AGI-3 等，只有这篇同时满足五个条件：要交接的知识必须由 agent 自己归纳出来；交接文本逐条对照真值打分；有多次连续交接；有一个不压缩、直接传完整历史的基线；把「压一次」和「压了再压」分开。

## 🏗️ 机制：可打分的世界，六个只差一处的条件

### 世界怎么造

- 6 个主题：grid、machine、craft、tool、care、trade，分别对应规则「露脸」方式不同。grid 世界里规则一触发就看得到；machine 世界里一个指示灯的含义要从多种配置里推断，一条命只能看到其中几种。
- 每个世界组合 3 到 5 个机制，名称是随机生成的伪词，并禁止屏幕出现有含义的词，防止从预训练里「回忆」出规则。
- 准入是三段式：每个主题写一个引擎和机制库，用 coding agent 辅助起草 60 个世界，再过自动检查和模型检查。自动检查要求求解器在每个实例上用 55% 到 70% 的步数到达目标，2,000 条随机动作的命最多到达目标两次、到第四标记的不超过 1%，至少 10% 的命被规则终止，屏幕确定。模型检查用最弱的 deepseek-v4.1-flash：有设计者笔记时 10 条命至少 8 次到达目标，没有时最多 2 次。最终 56 个准入，4 个 care 世界没过被丢弃。准入世界上，参考模型无笔记到达目标 0.6%，有设计者笔记 95.8%。

一个旁证很有意思：**好几份已经写全所有规则的设计者笔记，最初也没过模型检查，改写措辞后才过**。300 字写到别人能照着做，本身就不容易。

### 六个条件

| 条件 | 下一条命拿到什么 | 写笔记的人能看到什么 | 换不换 agent |
| --- | --- | --- | --- |
| Solo | 什么都没有 | 不写 | 单条命 |
| Oracle | 设计者笔记 | 不写 | 单条命 |
| Relay | 上一张 300 字笔记 | 上一张笔记 + 自己这条命 | 每条命换 |
| Compaction relay | 300 字笔记 | 之前所有命的完整记录 | 每条命换 |
| Record relay | 之前所有命的完整记录 | 不写 | 每条命换 |
| Memory | 自己的全部历史 | 不写 | 不换 |

四个序列条件在第 $i$ 条命用同一个实例，遇到的情况和顺序完全一样。相邻条件只差一处，于是交接损失可以精确拆成三份：

$$
\underbrace{M-R}_{\text{handoff loss}}=\underbrace{(C-R)}_{\text{反复压缩}}+\underbrace{(K-C)}_{\text{压一次}}+\underbrace{(M-K)}_{\text{换 agent}}
$$

其中 $R,C,K,M$ 分别是 Relay、Compaction relay、Record relay、Memory 在第 5 到 8 条命的平均得分。另外两个量用来定位：$R-S$ 是笔记的价值，$O-M$ 是「discovery gap」，即有全部历史也没摸出来的部分。由于不同模型分数尺度不同，损失还换算成「占所学的比例」$(M-R)/(M-S)$ 和「汇率」：Memory 曲线第几条命追上第八代 Relay。

### 笔记怎么打分

一个固定的 reader 模型只拿到笔记和该世界的事实选择题（选项里有「笔记没说」），据此判每条事实对、错、缺。两个 reader 在 1,591 个判断上一致 91.1%，抽查分歧时默认 reader 10 次全对。另一个 reader 拿着真实规则，把每条笔记的陈述分成「每局都成立的规则」「错误陈述」「单局流水账」三类。

规模：六个模型（两家提供商），推理强度能调就调 high；Solo、Oracle、Relay、Memory 覆盖全部 56 个世界，总共超过 25,000 条命。

## 🧪 关键证据

### 每个模型都在交接里亏

| 模型 | Solo | Relay | Memory | Oracle | 损失 | 占所学 | 汇率 | 到达目标 Relay/Memory |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| gpt-6-astra | 2.21 | 4.12 | 4.57 | 4.99 | 0.44 | 19% | 4.0 | 65% / 82% |
| gpt-6.1-sol | 1.96 | 3.77 | 4.41 | 4.96 | 0.64 | 26% | 4.1 | 57% / 74% |
| gpt-5.6-terra | 1.41 | 2.40 | 3.07 | 4.68 | 0.67 | 40% | 3.9 | 17% / 27% |
| gpt-5.6-luna | 1.30 | 1.94 | 2.52 | 4.61 | 0.59 | 48% | 2.5 | 7% / 15% |
| gpt-6-luna | 1.25 | 1.87 | 2.13 | 4.62 | 0.26 | 30% | 3.9 | 4% / 10% |
| deepseek-v4.1-flash（31 个世界） | 1.12 | 1.79 | 2.22 | 4.89 | 0.43 | 39% | 3.0 | 6% / 14% |

（分数为 0 到 5 的平均标记数，序列条件取第 5 到 8 条命。）

几点要读出来：

- 有设计者笔记时所有模型都在 4.61 以上，说明大家都能「照规则做」；没信息时没有一个超过 2.21。模型之间的差距主要在 discovery gap：两个最强的是 0.42 和 0.55，其余四个 1.61 到 2.67。
- 六个模型的损失 95% 区间都不含零。
- **只看完成率会漏掉**：四个弱模型很少到达目标（4% 到 17% 对 10% 到 27%），损失主要体现在标记数上。
- **会学和会交接是两种能力**：gpt-6-luna 学得最少、损失占 30%；gpt-5.6-luna 学得更多，却损失 48%。

### 损失主要来自反复压缩

在每个模型损失最大的十个世界上（Table 4）：

| 模型 | 反复压缩 | 压一次 | 换 agent |
| --- | --- | --- | --- |
| gpt-6-astra | 1.08 | 0.72 | -0.49（新 agent 反而略好） |
| gpt-6.1-sol | 1.82 | 0.83 | -0.05 |
| gpt-5.6-terra | 0.81 | 0.92 | 0.30 |

- **换 agent 不花钱**：拿到完整记录的新 agent 和亲历者一样好，区间都含零。
- **压一次有代价**：写的人看着完整记录但只能写 300 字，下一条命比直接拿记录少 0.72 到 0.92 个标记。
- **反复压缩最贵**：同样 300 字，只看上一张笔记和自己一条命写出来的，对两个强模型多亏 1.82 和 1.08，占它们在这些世界上损失的 70% 和 82%。弱一点的 gpt-5.6-terra 这一项只占 40%，压一次也一样贵，因为它对完整记录的总结能力也弱。
- 放到全部 56 个世界：Compaction relay 把 gpt-6.1-sol 从 3.77 拉到 4.16，补回 0.64 中的 0.39；gpt-6-astra 在 29 个世界上补回 0.54 中的 0.45。

### 长度不是瓶颈，换说法没用

- 看完整记录写的 300 字，接近或超过普通的 1,500 字笔记：gpt-6.1-sol 3.47 对 3.83，gpt-6-astra 4.18 对 3.97，gpt-5.6-terra 2.37 对 2.31。给它 1,500 字也不再涨（3.47）。
- 普通笔记确实随长度变好：gpt-6.1-sol 从 300 字的 1.65 到 1,500 字的 3.83，3,000 字没有再涨（3.65）。作者的解读是长笔记有空间把「观测」和「结论」一起带过去，部分替代了原始记录。
- 换写法几乎没用：要求改写旧笔记 1.98；要求写「已确认/已排除/待定」账本，300 字 1.57、600 字 1.95（普通请求分别是 1.65 和 2.48）；1,500 字下要求标出验证过的和解释不了的观测 3.49（普通 3.83）。**没有任何一种写作指令能补回「看得到记录」补回的东西。**

## 🔬 最有意思的部分

**一，损失落在每个模型能力的边缘。** 两个最强模型的损失几乎只在 machine 和 craft 世界：gpt-6.1-sol 分别亏 2.23 和 0.96，gpt-6-astra 1.20 和 0.79；grid、care、trade 世界都不超过 0.22。按 Memory 第一次到达目标的命数分组，gpt-6.1-sol 两条命内就解出的 13 个世界只亏 0.03，第 3 到 4 条命解出的 20 个亏 0.62，更晚或解不出的 23 个亏 1.01。四个弱模型则相反，machine 世界用 Memory 也只有 1.2 到 1.9 分，那里反而只亏 0.2 到 0.7，损失集中在强模型觉得简单的 tool、care、trade 世界（最高 1.22）。**更强的模型不会消除交接损失，只会把它挪到刚进入自己能力范围的那批任务上。**

**二，接力链擅长搬运结论，不擅长得出结论。** gpt-6.1-sol 的 Relay 笔记里正确事实的占比从第一代的 30% 涨到第五代的 50% 然后停住（gpt-6-astra 从 24% 到 50%），设计者笔记在同样篇幅里是 100%；machine 世界后期笔记只写对 17%。一条事实一旦写对，下一张笔记 89%（gpt-6-astra 87%）还对；一条缺失的事实，下一张补上的只有 14% 和 15%；写错的事实被纠正 16% 和 20%，被照抄 60% 和 49%。每个写手只能加进一条命能让它看出来的东西。

**三，失败的笔记不是被流水账挤掉了规则，而是根本没走到规则那一步。** 高损失世界里 gpt-6.1-sol 后期笔记 16% 是真规则、18% 是错误陈述、65% 是单局记录；无损失世界是 44%、8%、48%。gpt-6-astra 两组的单局记录占比都是 53%。而且目标、危险、机制、顺序、数量五类事实在 machine 世界都很少被写出（4% 到 27%），在其他世界都更常见（37% 到 69%），不存在某类规则特别难写。

**四，和人类实验的反差。** Tessler et al. 2021 里八人传递链（每人两条命）学得和无限命的个体差不多，这里的模型链做不到。作者也承认设置不同：这里继任者遇到新实例，路线没法传；很多世界一条命看不出规则。世界有图形界面，可以直接拿人来对比，留给后续。

## 🤔 我的判断

定位：**测量基础设施**。不是提出新的记忆系统，而是一套能把交接损失拆开的受控协议，外加一个可以直接照做的工程结论。

亮点三条：

- **把「要交接的知识」做成有真值的对象**。规则是有限的可判事实，交接文本能逐条对照，于是「写的人没懂」和「懂了没写」第一次可以分开。
- **六个条件相邻只差一处，损失可以精确相加拆分**。换人、压一次、反复压三份各自有数，而且排序在测过的模型上一致。
- **对写作指令做了负面结果**。证据、账本、改写这些我们在 harness 里常加的提示，在这里都没用，这比又一个「加了某提示涨几点」更有信息量。

问题与局限：

- **世界是合成的、很小**，作者明确说不主张损失大小能迁移到软件工程等真实工作，只主张各部分可测、排序一致。
- **贵的对照只在局部跑**：Compaction relay 只有一个模型覆盖全部 56 个世界，另一个 29 个，第三个 10 个；Record relay 和笔记变体只在每个模型损失最大的十个世界上跑。在「损失最大的十个世界」上算的 70% 和 82% 有选择效应，全量世界上 gpt-6.1-sol 补回的是 0.39/0.64 约六成。
- **模型只来自两家提供商**，六个里五个是 gpt 系列，另一个是 deepseek-v4.1-flash（只跑了 31 个世界）。
- **笔记打分依赖 reader 模型**，两 reader 一致 91%，作者说结论都能在 agent 实际得分上看到，不只靠打分。
- **单作者、代码不公开**，复现只能靠论文描述。
- 「300 字」这个预算本身是人为的，真实 compaction 的预算远大于此；不过 1,500 和 3,000 字的变体给了一些趋势信息。

对工程的直接启发：

1. **compaction 和 rolling summary 别从上一份摘要滚动生成**。把原始轨迹存在上下文外面（文件、日志、对象存储），每次需要摘要时让写手读原始记录重写。作者原话是这只花存储，不花上下文。
2. 给子 agent 写 brief、或者子 agent 回报时，同样原则：链条越长，越要让写手回到一手记录，而不是转述上一手的转述。
3. 存不了原始记录时，宁可给更长的摘要预算，让观测和结论一起过去；别指望靠更复杂的写作指令（账本、证据栏）补救。
4. 评估多 agent 或长时程系统时，要有一个「不交接、全历史」的参照条件，并用分级进度而不是只看完成率，否则弱模型上的损失会被完全藏起来。
5. 交接损失集中在「刚好够得着」的任务上，换更强的模型不会让它消失，只是换一批任务出问题。做 harness 的模型升级回归时，值得专门盯那批刚从解不出变成解得出的任务。

一句话：一张便条只能装写的人已经想明白的东西，还没想明白的线索留在没传下去的那些经历里；想让接力不掉链子，就得让每个写手都能回头翻原始记录。
