# 日常任务里换模型比换 harness 影响大：前三名只差 1.1 点，Sol 大约只要 Astra 六分之一的钱就能几乎打平

你有没有过这种体验：要让助手帮你订餐厅、回诊所、核一笔运费，先纠结该换模型还是换脚手架；榜上大家比的是编程和浏览，你的桌面却堆着过期导出、钓鱼邮件和互相打架的日历。行业里把「模型 × harness × 推理强度」叫配置，日常任务很少被放进同一套对照里。**问题是：在带混乱工作区、既要做对又要安全的日常任务上，到底是换模型影响大，还是换 harness 影响大，领先的那几个是不是贵得有道理？**

这篇 **ShellBench: What Matters More for AI Agents, Models, or Harness for Everyday Tasks** 做了一次很大的因子实验：100 道从超过一千万条真实请求里长出来的日常任务，12 个模型、5 个 harness、3 档推理强度，一共 53,100 次 rollout。看完我的感受是：**平均分上模型选择远比换脚手架重要，但前三名只隔着 1.1 个百分点；GPT-6.1 Sol 大约只要 GPT-6 Astra 六分之一的预估费用，就能几乎打平。真正拉开名次的，常常是「有没有写清用过哪些文件」这种来源标准，而不是会不会选对那家餐厅。**

## 核心摘要

作者从超过一千万条真实用户请求出发，用嵌入聚类和人工审稿做成 100 道 Harbor 任务，每道都放在文件很杂、证据还互相打架的工作区里，正确性和安全性一起判，而且是全过才算过。90 道用 LLM 裁判、10 道用代码测试，合计 721 条标准，其中 381 条是安全标准；工作区中位文件数 188。评测覆盖 Claude Code、Codex、Hermes、OpenClaw 和 Pi 五个开箱即用的 harness，以及 GPT-6 Astra、Claude Fable 5.2、GPT-6.1 Sol 等 12 个模型，每个组合三档推理、每档三次尝试，时间窗口是 2026 年 11 月 7 日到 20 日，共 59 个配置、53,100 次运行，其中 20 道任务公开，对应 10,620 次公开 rollout。按 harness 平均，Astra、Fable、Sol 的 Pass@1 分别是 62.5%、61.9% 和 61.4%，只差 1.1 个百分点；其余九个从 Gemini 4 Carbon 的 58.7% 掉到 GPT-6 Luna 的 18.8%。59 个配置的总平均 Pass@1 是 44.4%，三次里至少一次过是 61.2%，三次全过只有 28.2%。在十一模型全覆盖的 55 个配置均值上，双向方差分析里模型主效应占到总平方和的 95.7%，harness 只有 0.36%，交互 4.0%；如果只看 Pass@1 超过 47% 的五个强模型，模型仍解释 65.6%，harness 升到 16.5%，同一模型换脚手架的中位跨度是 9.9 个百分点。费用按 2026 年 11 月 18 日 OpenRouter 标价和记录到的 token 估算：Sol 每次约 0.19 美元，Fable 0.83 美元，Astra 1.10 美元，Sol 大约是 Astra 的六分之一；一百次尝试里，Astra 大概只多对一题，却大约多花 91 美元。安全同样主要由模型决定：全部运行里 15.7% 至少挂掉一条安全标准，Astra 9.4%，DeepSeek V4 Pro 24.4%；在十一模型里，模型解释安全失败率变异的 75.5%，harness 只有 4.7%。把来源使用和过期信息这两类标准拿掉再给同一批提交打分，Codex 会从第四升到第一。这篇的价值定位是：**一份面向日常个人任务、同时打正确性和安全性、并且把模型和 harness 放在同一套因子设计里的测量基础设施，而不是再发一个只比编程或只比单一脚手架的日常助手榜。**

## 🎯 为什么这件事值得写

2026 年，聊天助手已经大规模用在订餐、对账单、改预约这类非编程事务上。同一套模型往往能跑进好几个 coding / 终端 harness，用户真正要选的是「模型加脚手架」这一整套配置。现有榜要么偏网页和桌面、要么偏职业工作流，要么专门测抗注入；像 MyPCBench、Workspace-Bench、ClawBench 已经靠近日常生活，但很少同时满足这几件事：真实个人请求、一开始就很乱的工作区、正确性和安全标准写在同一套量规里，并且把多个流行 harness 放进同一套对照。

ShellBench 要回答的就是这句很朴素的话：**在日常任务上，换模型、换 harness、把推理开到最高，各自能改掉多少正确率和安全率，贵的那个是不是真的值？**

## 🏗️ 机制：从一千万条请求到全过才算过的 Harbor 任务

任务不是出题人凭空编的。作者用 Qwen3-Embedding-8B 嵌入真实请求，做 K-means，再把最大的 250 个簇交给 GPT-6.1 Sol，每个簇看 100 条请求判是否连贯，233 个簇通过后再写成场景说明。场景交给独立开发者，按 Parsewave 给实验室做 RL 任务的六步流程扩成 Harbor 环境：先搭真实文件和可调 API 的应用，自动检查环境像不像真的，两名标注员验收，原作者再写成完整任务，用 GPT-6.1 Sol 和 Claude Opus 5.5 的 rollout 看难度和公平性，最后两名资深审稿人必须都通过。同一题在流程里被拒超过三次就永久淘汰。引言里说每道任务除原作者外还经过四名独立审稿，和「两名环境标注 + 两名资深审稿」对得上。

做出来的工作区里有邮件、日历导出、表格、保存的网页、聊天记录、收据和 PDF，有的还夹着钓鱼邮件和过期信息。90 道裁判题一共 16,296 个文件，10 道代码测试题再加 668 个；中位请求只有 43 个词。每道题是一组是非标准，分成正确性和安全性，**全部通过才算过**。77 道题里有 87 条「来源标准」，要检查答案有没有点名所依据的文件。公开的「晚饭任务」最能说明这种严厉：531 次尝试里 522 次选对了餐厅，只有 152 次过完九条标准，331 次仅仅因为没写清来源而整题判失败，跟推荐了一家当晚包场的店是同一个二分分数。

90 道题的裁判是跑在 Pi 里、开到高推理的 GPT-6.1 Sol：它打开 agent 改过的文件，一轮只判一条，最多两次格式纠正，看不到参考答案。86 道看最终工作区，4 道看应用内状态；如果标准都没失败但裁判认为有一条含糊，记为未解决，算没过。作者抽了 290 条标准级决定做盲评，278 条形成人类共识，裁判与共识一致率 89.9%，Cohen's $\kappa=0.75$。这测的是单条标准，不是整题对错。

五个 harness 都用发布版本和默认工具：OpenClaw 2026.10.5、Pi 1.3.0、Hermes v2026.9.24、Codex 0.163.0、Claude Code 2.1.292。唯一例外是 DeepSeek V4.1 Flash 没跑 Hermes，因为要钉死供应商就得改脚手架，作者选择保持「开箱即用」。Pass@1 是单次通过率，Pass@3 是三次里至少一次，Pass3 是三次全过。

## 🧪 关键证据或主结果

主结果很刺眼。前三名几乎叠在一起，费用却完全不是一个量级。在 OpenClaw 上，Sol 是 63.0%、每次约 0.33 美元，Astra 是 62.4%、每次约 1.94 美元。按 harness 平均，Astra 对 Fable 的领先也不稳定：在 Pi 里领先 4.3 个点，在 Claude Code 里反而落后 7.6 个点。帕累托前线上还有更便宜的点：Luna 约 1.4 美分、18.8%，DeepSeek V4.1 Flash 约 5.4 美分、39.7%，然后才是 Sol 的 19 美分、61.4%。这些费用都不含裁判调用。脚手架本身也改费用：在五个 harness 都有报价的十个模型上，每次平均是 Pi 0.29 美元、Codex 0.32、Hermes 0.33、Claude Code 0.51、OpenClaw 0.53；有 token 记录的十一个模型里，九个都是 Pi 最便宜。

说「harness 几乎没影响」之前，要看你在比谁。把弱模型也算进去，模型效应会把方差吃满；只看五个强模型，脚手架就能解释 16.5%。Claude Code 对模型最不「中性」，残差标准差 4.7 个点，OpenClaw 只有 1.4。59 个配置里最高是 65.3%（Astra 配 Pi、Fable 配 Hermes），最低是 Luna 配 Claude Code 的 15.1%；Muse Wonder Full 在 Claude Code 上比它自己的跨脚手架均值低 9.2 个点，Sol 在 Claude Code 上也低 8.2 个点。推理强度也不是单调的：十二个里十一个在最高档高于最低档，Claude Sonnet 5.5 平均能涨 19.1 个点，Gemini 4 Carbon 反而掉 4.1 个点。

安全一侧，模型仍然是主因。正确性全过的 26,151 次里，仍有 2,589 次（9.9%）挂在安全要求上。单条安全标准的通过率其实有 94.0%，失败集中在少数几条：362 条里失败最多的十条贡献了 39.0% 的安全失败。公开发布的运费对账任务上，214/531（40.3%）建议了重复或错误付款；失败最多的一条要求计划里必须保住孩子放学接送，422/531（79.5%）没过，连只字不提也算失败。作者自己也说，公开子集里失败最多的十条里有六条，部分测的是答案全不全，而不只是有没有泄密。

把同一批提交拿掉来源和过期信息标准再打分，分数普遍上窜，harness 排名也会动：Codex 从第四升到第一，OpenClaw 从并列领先掉到后面。晚饭那道题已经预告了这件事：选对餐厅远远不够，没点名依据文件就整题为零。

## 🔬 最有意思的部分

最有意思的不是「模型比脚手架重要」这句口号，而是它和交互项、量规设计叠在一起之后的形状。平均分上五个 harness 挤在 42.9%（Claude Code）到 45.2%（OpenClaw）之间，工具行为却差得很远：Claude Code 读回和改写的文件文本更多，Pi 更快也更省输入 token（十个全覆盖模型上，Pi 平均每次约 19.2 万输入、7,800 输出，Claude Code 是 50 万和 10,800）。分数差不多，并不等于跑法一样。

另一件反直觉的事是一致性。Astra 的 Pass@1 是 62.5%，三次全过只有 48.8%。对日常助手来说，「再试一次可能就对」和「这次就能用」不是同一个产品问题。再加上全过才算过，来源命名这种看起来像写作规范的标准，会把已经选对餐厅的提交大批量打成失败，也会在拿掉这些标准之后改写 harness 排行。这让 ShellBench 很诚实，也让「45% 左右的 harness 均值」不能直接读成「这些脚手架差不多能用」。

## 🤔 我的判断

定位：**测量基础设施。** 真正的贡献是把日常个人任务、混乱工作区、正确性加安全、以及五个正在被广泛使用的 harness 放进同一套 53,100 次的因子设计里，而不是再讲一个新助手系统。

亮点三条：

- **把「换模型还是换脚手架」量成了可分解的账。** 全模型池子里模型效应占绝对主导，但只看强模型时，harness 仍然能解释约六分之一，而且 Claude Code 会让部分模型掉出自己的均值一大截。
- **前三名分差很小，费用差很大。** Sol 用大约六分之一的预估费用几乎打平 Astra；一百次里多对一题大约要多花 91 美元。这对「默认上最贵的旗舰」是一次很具体的泼冷水。
- **量规本身会改写结论。** 全过才算过、来源和过期信息、以及「不写接送计划也算不安全」，让正确性、引用纪律和安全缠在一起；拿掉两类标准后 Codex 能从第四跳到第一。

问题与局限：

- 九十道题依赖单一家族的 LLM 裁判，只在标准级做了人类对照，没有整题的独立人工判决；另有检查显示，40 份未改动的提交里有 6 份在重复自动评判中既得过也没过。
- 一次换掉的是 harness 的提示、工具和运行时整体，分不出到底是哪一层在起作用；Flash 缺了 Hermes，脚手架对照只能用十一模型。
- 费用是按记录 token 和列表价估的，缓存命中靠启发式，和真实账单不会完全一致；OpenClaw 会打码过长工具输出，文件阅读量不好和别的脚手架比。
- 安全结果是量规上的是否合规，不是对真实伤害的分级度量；失败最多的几条里，有的更接近「写全没有」。
- 公开的只有 20 道任务，其余 80 道仍不开放，复现完整榜有门槛。

对工程的直接启发：

1. **先选模型档，再在强模型里挑费用，而不是先为日常任务重写一套 harness。** 但如果你已经锁死 Claude Code 或某个「个性很强」的脚手架，还是要单独看这个组合，不要用跨脚手架均值替它说话。
2. **推理开到最高不是免费的单调节阀。** 有的模型能涨十几二十个点，有的反而掉。
3. **日常任务的验收不要只看最终建议对不对。** 来源有没有点名、有没有引用过期材料、该保密的有没有写进回复，都会在全过制下决定整题生死。
4. **安全失败里有相当一部分发生在正确性已经全过之后。** 只盯着任务成功，会漏掉约一成「事情做对了但不该说、不该付、不该改期」的提交。
5. **比费用时把裁判调用和真实缓存单独记账。** 论文里的美元数字只覆盖解题模型，而且是列表价估算。

一句话：在这些混乱的日常工作区里，换模型仍然比换脚手架更能改平均分，但前三名几乎挤在一起，真正贵的往往不是那 1.1 个点，而是你愿不愿意为多过一题付五六倍的钱；至于脚手架排行，则还取决于你的量规到底在不在乎「有没有写清依据」。
