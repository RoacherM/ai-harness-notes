# 策略失败就让 coding agent 改 harness：八轮后 LIBERO-PRO 独立策略从 11.0% 涨到 84.1%，混合执行到 90.5%，API 花费从 430.63 美元降到 98.92 美元

你有没有过这种体验：底层策略在熟悉场景里很流畅，换个布置就不会了；反过来让基础模型 agent 调机器人 API，又能摸索出办法，可每次都要推理、修程序、再试一遍，延迟和 API 账单很快就受不了。行业里一边把 VLA 或世界动作模型当高效控制器，一边把 coding agent 当成能写技能、能修失败的 harness。**问题是：只进化 harness、冻住策略，新学会的技能进不了控制器；只拿 agent 去采数据训练策略、却不改 harness，策略变强之后，失败类型和可用的动作原语都变了，原来的技能库和路由也会过时。**

这篇 **RoboEvo2: Recursive Robot Self-Improvement via Harness–Policy Co-Evolution** 把这两边写成一对互相反哺的环：Policy-to-Harness（P2H）用当前策略的失败去驱使 coding agent 搜索补丁，Harness-to-Policy（H2P）再用验证过的轨迹和配对的失败–修正去更新策略。看完我的感受是：**它真正有用的不是再演示一次「agent 能修机器人」，而是把技能、记忆、路由和策略放进同一条递归环里，并且用数字说明：策略越来越能自己做，agent 的 API 花费才会跟着降下来。**

## 核心摘要

作者认为机器人应当能在陌生环境里靠交互学会新技能，再通过练习把它们做熟练。现有 VLA 和世界动作模型执行效率高，但场景一变往往要再采大量人工示范；基础模型 agent 能靠先验和机器人 API 发现解法，反复推理和修复却贵。RoboEvo2 把 harness 明确写成可执行技能、持久记忆和路由策略的组合，用当前策略失败同时驱动两侧更新。P2H 里，VLM coding agent（主实验用 GPT-6 Astra，推理强度 xhigh）对每次失败并行搜索三条路线：Code 改控制程序，Code+ICL 加上示范引导，Code+Policy 把程序和已学会的运动技能组合起来；执行反馈驱动迭代修复，成功候选在匹配条件下选归一化运动 jerk 最低的那条，再把兼容的修补写回技能、路由和记忆。H2P 里，验证轨迹做监督训练，同时用 Counterfactual Preference Distillation（CPD）：从同一起始状态取出失败和修正后的续段，相对冻结参考策略优化动作预测损失的间隔，再用非对称邻近惩罚避免修正行为被冲掉、也避免把失败替代方案压得过狠，并配上失败感知采样和持续学习正则。主结果按策略 π0.5 报告：LIBERO-PRO 上八轮后，独立策略成功率从 11.0% 升到 84.1%，混合执行（策略加 harness）从 30.4% 升到 90.5%，每轮 coding-agent API 花费从 430.63 美元降到 98.92 美元；RoboTwin C2R 上五轮后，独立策略从 46.0% 到 77.5%，混合从 48.8% 到 87.4%，API 花费从 719.05 美元降到 323.84 美元。在 RoboTwin C2R 上，用 7.5K 条轨迹的 RoboEvo2 独立策略达到 77.5%，对得上常规训练用 27.5K 条轨迹得到的 76.8%。MolmoSpaces 上自主提出任务后，独立策略平均 57.0%、混合 65.8%，高于 RATs 的 38.0% 和 CaP-Agent0 的 21.0%。把在 ALOHA AgileX 上进化出的冻结 harness 迁到双臂 ARX-X5 和 Franka-Panda，成功率分别是 45.8%、42.5% 和 41.0%。仿真里进化的 harness 迁到真实 Unitree G1-D 后，仅用代码技能的固定 harness 平均 47.5%；用自动采集的 120 条示范训练的 RoboEvo2 策略到 85.0%，超过 200 条人工遥操作示范训练的 π0.5（80.0%），混合执行到 95.0%。这篇的价值定位是：**给「冻住模型、打磨 harness」补上策略侧的内化环，说明 skills / memory / routing 和底层策略必须一起版本化，否则 agent 会一直替策略付修理费。**

## 🎯 为什么这件事值得写

做 agent 和机器人的人，这两年反复碰到同一道选择题：把能力写进技能库和路由，还是把能力烤进策略权重。只改 harness 的递归自我改进，能把程序和经验越积越多，但电机层如果不动，下次还得再请 agent 上场；只让基础模型帮忙采数据、更新控制器，harness 却还停在旧策略的失败模式上，搜索空间和可用原语会对不上新控制器。作者把这种互为条件写成共进化：策略变了，需要探索和修复的失败会变，也能为 Code+Policy 提供更强的运动原语；harness 变了，能交给策略内化的正确轨迹也会变。

对关心 skills、harness 演进和持续学习的人来说，这几乎是一条可对照的工程样本。技能不是写完就挂在那里的文档，而是失败驱动、多路搜索、验证后才入库的可执行修复；记忆留下失败情境、尝试过的方案和通过验证的引导；路由决定下一次还要不要请 agent。后面的 API 花费下降，靠的不是把 agent 换便宜，而是策略把一部分修复内化了，重复的 agentic 干预才会减少。

## 🏗️ 机制：P2H 发现补丁，H2P 把补丁内化进策略

闭环按任务批次推进。当前策略先在一批任务上 rollout，失败交给 P2H；验证过的修复更新技能、记忆和路由，同时把成功轨迹和配对的失败–修正交给 H2P；更新后的策略再进入下一轮，既自己执行，也作为 Code+Policy 路线里的运动技能。

P2H 的关键是同一失败上的并行多路搜索，而不是只改一稿程序。Code 路线精炼控制程序；Code+ICL 把示范指导引进来；Code+Policy 让程序调用已经学会的运动技能。三条路都是先用现有 harness 试跑，失败后再按执行反馈迭代修复。选成功候选时，作者在匹配条件下比较归一化运动 jerk，偏向更平滑的修正。兼容的修补才会写回技能和路由，持久记忆则保留失败上下文、尝试过的方案和通过验证的指导，供后续诊断检索。

H2P 不只做成功轨迹上的监督。CPD 从同一起始状态取出失败续段和修正续段，相对冻结参考策略拉大两者动作预测损失的间隔，让策略既学会该复现哪些修正，也学会该回避哪些失败替代。非对称邻近惩罚用来保护已经学到的修正，同时避免把失败方案压得过狠。失败感知采样把更新集中到还需要补的能力上，持续学习正则则用来保住旧能力。作者把这一套称为：发现互补能力、把纠正能力内化、再让更新后的策略改变下一轮还要探索什么。

主实验的 coding agent 是 GPT-6 Astra。作者在附录里把同一套进化轮次换成 Qwen3.8-27B，只换 agent、初始策略和 harness 不变：独立策略 76.0%、混合 82.5%，低于 Astra 的 84.1% 和 90.5%，说明共进化框架能换更小的开源 agent 跑起来，但修复和内化的上限仍受 agent 能力影响。

## 🧪 关键证据或主结果

最硬的账是多轮进化和花费一起报。LIBERO-PRO 八轮：独立策略 11.0% → 84.1%，混合 30.4% → 90.5%，每轮 coding-agent API 花费 430.63 → 98.92 美元，对应文中写的花费减少 77.0%、策略提升 73.1 个点。RoboTwin C2R 五轮：独立策略 46.0% → 77.5%，混合 48.8% → 87.4%，API 花费 719.05 → 323.84 美元，策略提升 31.5 个点、花费减少 55.0%。作者强调，这是能力上升和 agentic 成本下降同时发生，而不是用更多调用换分数。

数据效率在 RoboTwin C2R 的表 1。π0.5 再加 25K 条随机示范，总数据 27.5K，成功率 76.8%；RoboEvo2 的 π0.5 用 2.5K 基础加 5K 进化数据、共 7.5K，独立策略就到 77.5%，混合执行到 87.4%。也就是说，验证过的失败修正，比堆更多随机示范更值钱。

共进化不是摆设。表 3 把前三轮拆开：只做 P2H、策略固定，混合成功率第三轮是 46.1%；只做 H2P、harness 固定，独立策略 33.6%、混合 49.0%；完整 RoboEvo2 则是 52.3% 和 68.3%。只让一边长，两边都到不了全环的位置。

P2H 的三条路线也确实互补。从表 4 的第一轮看，初始独立策略是 11.0%。单路加修复后，Code 到 29.4%（净增 7.8 点），Code+ICL 到 44.9%（+13.4），Code+Policy 到 45.6%（+14.8）；三路合在一起到 49.1%。用这些轨迹训练策略后，独立成功率分别到 21.0%、28.6%、29.0% 和 32.1%。发现阶段的互补，会变成内化阶段的差距。

CPD 的拆解在表 5：同样的数据、初始化和 EWC 设置下，只做监督是 20.1%，加上偏好间隔到 29.9%，再加上非对称邻近项到 32.1%。修正对要教的不只是「模仿成功」，还有「别再走那条失败续段」。

迁移和真机是另一组证据。MolmoSpaces 的 40 个开、关、抓取和抓放任务上，RoboEvo2 独立策略 57.0%、混合 65.8%，高于 RATs 的 38.0%。跨本体时，冻结 harness 只换机器人接口，ALOHA AgileX、双 ARX-X5、双 Franka-Panda 分别是 45.8%、42.5%、41.0%，掉幅不大。Unitree G1-D 上四个双臂任务、每任务 10 次：固定代码 harness 平均 47.5%，200 条遥操作示范的 π0.5 是 80.0%，120 条自动示范训练的 RoboEvo2 策略是 85.0%，混合到 95.0%。仿真里长出来的 harness，既能在真机上直接跑，也能反过来给策略提供监督。

作者还报告了更强的策略变体：π0.5 加 PPO 后，LIBERO-PRO 上独立 94.8%、混合 96.8%。主文叙事仍以未加 PPO 的 π0.5 为准。和 Zetta、DynaHarness、EmbodiedRSI 等 harness 进化方法的对照表附有声明：公开数字沿用各自原来的评测协议，不能当成完全同一把尺。

## 🔬 最有意思的部分

最有意思的不是「混合执行更高」，而是 API 花费为什么会掉。混合系统之所以越来越便宜，是因为越来越多的任务被内化后的策略直接做掉，coding agent 不再对同一类失败反复出场。如果只看混合成功率、不看每轮 API 花费，会把「agent 一直在场帮衬」误认成系统变强。

另一处是多路修复的职责划分。Code+Policy 单独的修复增益最大，但三路合在一起才拿到最高的 49.1%。这说明策略原语、示范和纯程序修补不是互相替代的搜索预算，而是覆盖不同失败模式。只保留一条「让 agent 写脚本」的路线，会把本可以交给已有运动技能的问题，重新写成脆弱的长程序。

真机那组数字也很克制。迁过去的冻结 harness 单独只有 47.5%，并没有被写成「harness 到真机就能用」；真正拉起来的是自动采集的 120 条示范加上混合执行。harness 的可迁移性，首先体现为能在新本体和新环境里继续当验收集和补丁器，而不必一上来假装自己就是全部控制器。

## 🤔 我的判断

定位：**方法突破，兼工程样本。** 贡献是把失败驱动的多路 harness 修复，和把验证过的修正内化进策略，写成一条可递归的共进化环，并且用花费下降来证明内化真的发生了。

亮点三条：

- **把 skills、memory、routing 和策略放进同一条版本化的环。** 不是只堆积技能文件，也不是只往策略里灌示范，两边按当前失败互相改。
- **账是对得上的。** LIBERO-PRO 八轮独立策略从 11.0% 到 84.1%、混合到 90.5%，API 花费从 430.63 美元到 98.92 美元；只做 P2H 或只做 H2P 都明显更弱；7.5K 条验证轨迹对得上 27.5K 条常规数据。
- **真机和跨本体没有把故事说满。** 冻结 harness 迁移掉幅很小，但真机上固定 harness 只有 47.5%，要靠自动示范和混合执行才到 95.0%，分寸清楚。

问题与局限：

- 正文没有单独的局限节，对评测协议差异、真机任务规模和花费统计口径的讨论分散在图表说明里。
- G1-D 只有四个任务、每任务 10 次，适合作为 sim-to-real 可行性证据，还不够当成广泛的真机结论。
- 主结果依赖 GPT-6 Astra；换成 Qwen3.8-27B 后仍能进化，但独立策略从 84.1% 降到 76.0%，框架并不能把弱 agent 补到同一上限。
- 与其他 harness 进化方法的对照沿用了各自原来的协议，表 2 的绝对分数不宜直接当排行榜。
- 代码和模型声明将公开，仓库页面可访问，但这次解读没有逐项核对发行内容和可复现脚本是否已经齐。

对工程的直接启发：

1. **如果 agent 每个月都在修同一类失败，先问策略有没有把修正内化，而不是再加一张技能卡。** 技能库膨胀、API 花费不降，往往是内化环缺了。
2. **修复搜索不要只留一条写代码的路。** 示范引导和已有策略原语，经常能覆盖纯程序修补到不了的失败。
3. **验收共进化时，同时看成功率和每轮 agent 花费。** 只看混合分数，看不出系统是变强了还是更依赖现场修理。
4. **迁移 harness 时，先把它当成可复用的验收集和补丁器，再决定要不要在新本体上重新进化技能。** 本文跨本体实验只改了控制接口，冻结技能、路由和记忆仍然能用。
5. **用配对的失败–修正做蒸馏，比只模仿成功轨迹更针对。** CPD 的间隔项和邻近项，就是在教「这条该复现、那条别再走」。

一句话：策略不会做的时候让 coding agent 改 harness，这只是上半场；RoboEvo2 把验证过的修正再写回策略，下半场才会出现「更能自己做、也更少付修理费」。
