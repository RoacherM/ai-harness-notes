# 懒 agent 会在自己还写着几种可能时就交卷：用可验证后验奖励何时该停，九个设置平均涨 17.1 个点，够证据才答的比例从 8%、0.4%、36% 提到 51%、12%、74%

你有没有过这种体验：长程 agent 明明还在自己的信念里写着「还剩两种可能」，下一句却已经交卷了，好像先猜一个运气好也能得分。这种过早提交常被叫做懒惰。结果奖励只看最终答案对不对，幸运的猜测和证据充分的回答拿同样的分，过程奖励若交给看见了隐藏答案的裁判，又可能奖励碰巧猜对、惩罚仍然诚实不确定的信念。**问题是：模拟器其实知道隐藏目标和每一步会揭开什么，它能不能在每一步算出证据所支持的精确后验，直接教 agent 何时该继续、何时才能提交，而不再靠裁判或结果对错来猜这个时机？**

这篇 **Lazy Agents Answer Against Their Own Beliefs: Reinforcement Learning with Verifiable Beliefs Teaches Them to Act on What They Believe** 提出 RLVB：用精确后验构造可验证的过程奖励，奖励在后验仍允许多种答案时继续搜集证据，并在证据充分后提交。奖励不读 agent 自己写的信念行，但更新会把这行和动作一起训练。看完我的感受是：**涨分主要不是因为模型把同一堆证据读得更准，而是因为它更常等到证据够了再答，并且开始按照自己写下来的信念行动；只在 harness 里拒收第一次答案，替代不了这件事。**

## 核心摘要

作者把长程证据搜集写成一个最优停止问题。agent 每一步写出思考、一行信念和动作，信念行命名它认为仍可能的答案集合，历史只保留过去的动作、观察和上一行信念，不保留更早的推理。结果奖励对了就给分、错了或没有答案就为零，再加时间折扣，因此幸运猜测会和有证据的回答拿同样的结果分。RL 常用的结果奖励框架在这里会出问题：GRPO 把整条轨迹的优势分给每一步，同一次有用的举起可能因为最后猜错而被罚；看见真实隐藏答案的 LLM 裁判，则可能给幸运猜测打高分，给仍然正确但不确定的信念打低分。RLVB 改用模拟器在每一步算出的精确后验。这个后验只依赖于已经搜集到的证据，不依赖于这一局里物体碰巧藏在哪。后验教师据此给每个动作打分：证据还不够时，几乎把质量放在继续搜集上；证据一旦充分，就奖励提交。主奖励是动作在教师策略下的对数概率，不读信念行；可选的信念项才直接核对此行与后验是否一致，但主结果默认关掉它。训练在同一个历史上采样多个回合，用类似 GRPO、但分组是「同一历史下的多条回合」的相对权重更新 LoRA。他们还做了用期望最大化的学习者 RLVB (EM)。实验训练三个开源视觉语言模型：Qwen3-VL-4B-Thinking、Qwen3-VL-8B-Thinking 和 Qwen3.5-4B，最多 50 次更新，在同样的任务上比较。训练任务来自 HiddenGames 的七项已有基准，测试是其中 756 局从未见过的种子、地图和颜色；另外两个基准训练时完全没见过：作者提出的 Pro-Worlds 用小窗口看大世界，15 个游戏各 20 局，最多 35 步，从八个候选里作答（Jigsaw 为十个），后验教师平均 14.7 步就能解完；以及没有精确后验的 RoboQuest，十个移动操作任务各 50 局，用来看能否迁到无法逐步计算后验的环境。RLVB 在全部九个设置上超过底模，平均高 17.1 个点，EM 变体平均高 10.4 个点；两者至少有一个在表 1 的九列里拿下八列第一。结果奖励下，GRPO 平均比底模低 1.0 个点，动作-only 的 PPO 低 5.1 个点。带 LLM 裁判过程奖励的 PPO（信念加动作）平均比底模高 7.9 个点，RLVB 再高出 9.3 个点，唯一例外是 Qwen3.5-4B 的 RoboQuest。在 Qwen3.5-4B 和 A100 上，这种裁判 PPO 要用 120.1 个 GPU 小时和大约 12,600 次裁判调用，RLVB 是 74.2 个 GPU 小时，正好是 1.6 倍之差。涨分来自提交时机：三个基准上，训练后的 agent 在证据充分时作答的比例分别是 51%、12% 和 74%，底模只有 8%、0.4% 和 36%。任意方法在证据充分时给出的答案，有 66% 到 92% 是对的，所以同一证据水平上，训练后的答案并不更准，准是因为更常在高证据处作答。信念行则说明它如何走到这些证据：在证据不足且自己的行仍写着多种可能时，它只在 0.1% 到 2.2% 的回合提交，对照带信念行的底模是 3% 到 68%。这篇的价值定位是：**给证据搜集型 agent 提供一个不需要裁判的、可验证的过程奖励，专门把「何时该停」教对，并展示涨分来自按自己的信念行动，而不是来自把观察读得更精确。**

## 🎯 为什么这件事值得写

长程 agent 的一个典型失败，不是最后不会算，而是证据还不够就交卷。提示词可以写「只有证据锁定答案时才提交」，模型也可以在信念行里老老实实写还剩几种可能，然后照样猜。作者把这拆成元认知的两半：监测自己知道什么，以及据此控制下一步。语言模型常常能写出自己还不确定，却不会按这行字行动。

这和只看最终对错的 RLVR 正好撞上。数学和代码里，最终答案往往足以提供可验证奖励；多步搜证据时，最终对错既说不清哪一步有用，也会把幸运猜测Reinforce进去。过程奖励是条出路，可一旦裁判或评论者能看见隐藏答案，奖励就不再是「证据是否足够」，而变成「你是不是碰巧说对了」。RLVB 抓住的是模拟器里多出来的那部分特权信息：不是把真实状态塞给教师去直接示范对的杯子，而是用它计算 agent 现在应该持有的后验。对做 harness 和 agent 训练的人来说，这几乎是在问：你到底在奖励「说对了」，还是在奖励「知道自己什么时候该停」。

## 🏗️ 机制：精确后验当教师，奖励读证据不读信念行

任务被写成 POMDP，隐藏目标在一局内固定。模拟器枚举可能的目标，每一步按已有观察把先验限制成与证据相容的后验。仍被允许的答案集合记为精确信念；信念行若刚好写出这个集合就是精确的，少写了是过窄，多写了是过宽。

后验教师用这个信念给每个动作估值。提交某个答案，价值是经时间折扣和实测答题准确率调整后的对数机会；继续搜集，价值是观察之后验的期望。教师用这些价值决定现在该提交还是该继续，并在同类动作里做 Boltzmann 选择。主奖励是 agent 实际动作在这个教师策略下的对数概率。证据仍允许多种答案时，它奖励继续；证据充分后，它奖励提交。时间折扣让证据已经足够后再多走一步只付很小的代价。可选的信念项才直接按这一行与后验的符合程度打分，主结果把这项关掉，也就是：**模型被要求写出信念行，但梯度并不直接批改这行字，而是通过「要不要提交」把行动和这行字绑在一起。**

更新不按整条轨迹共用一个优势。RLVB 在同一个历史上采样多条回合，每条的权重是它的奖励减去同组其他回合的均值，有点像 GRPO，但组的单位是历史而不是整局。RLVB (EM) 换了一种加权，并且保留信念项。所有方法都只看到完整的动作和观察历史，看不到自己更早的推理，因此信念行承担了把信念带到下一轮的任务。对照很完整：不写信念的底模、写信念但不训练的底模、在获胜教师动作上做 SFT、用结果奖励的 GRPO 和 PPO，以及用 DeepSeek V4.1 Flash 当裁判、按真实隐藏状态打分信念的 PPO（信念加动作）。后者的逐步奖励只打在信念上，是否继续仍只靠整局结果回传。

## 🧪 关键证据或主结果

九个设置里，RLVB 相对底模的增益都是正的。以表 2 中与表 1 一致的准确率来看：Qwen3.5-4B 在 HiddenGames、Pro-Worlds、RoboQuest 上从 26.5、20.2、39.6 走到 48.5、32.1、54.0；Qwen3-VL-4B 从 24.6、17.2、28.4 走到 36.2、28.7、61.2；Qwen3-VL-8B 从 22.9、14.8、36.2 走到 31.1、29.9、62.7。其中 RoboQuest 上 4B 思考模型的 32.8 个点，就是正文所说「最高迁到 32.8 个点」的来源；Pro-Worlds 上最高迁到 17.6 个点。三个模型、三个基准平均下来，RLVB 是 42.7%，EM 是 36.0%。后验教师在 HiddenGames 和 Pro-Worlds 上分别是 97.5% 和 100%，RoboQuest 没有精确后验，所以没有教师分。训练后的模型离教师还很远，例如 Pro-Worlds 上最好也只有 32.4%。

结果奖励几乎帮不上忙，平均还往下掉。用同一个相对学习者时，后验过程奖励比结果奖励平均高 18.1 个点。写信念行本身就有用：不训练的「底模加信念行」在九个设置里有八个更好，平均高 3.8 个点，Qwen3.5-4B 在 HiddenGames 上高 11.6 个点，但过早提交并没有被这句话拦住。带裁判的 PPO 平均能高 7.9 个点，可过早作答仍然很多：HiddenGames 上 58.9% 到 94.3% 的答案来得太早，对照 RLVB 的 34.5% 到 43.1%。行为上，RLVB 步数更多、过早答案更少，但信念行并不在任何设置里最常写精确。Qwen3.5-4B 上，RLVB 在 HiddenGames 的过早作答从带信念底模的 64.2% 降到 34.7%，步数从 3.8 加到 8.2；RoboQuest 上过早作答从 48.5% 降到 28.9%，步数从 6.0 加到 8.0。

代价方面，表 4 写得很清楚。Qwen3.5-4B 用 A100：裁判 PPO 120.1 个 GPU 小时加约 12,600 次调用（文中列出大约 9.8 美元的裁判 API 费用），RLVB 74.2，EM 只要 29.7。两个 VL 模型在 H200 上，RLVB 分别是 30.7 和 46.2 个 GPU 小时，EM 是 13.6 和 15.0。RLVB 的步 KL 限制让它在 20 到 35 次更新时就提前结束，并没有跑满 50 次。EM 更省，只要 RLVB 的 32% 到 44% GPU 小时，但过早作答更多，九列里只在一列超过 RLVB。加上信念项并不会把准确率抬得更高。

分解更关键。把作答时的证据分层之后，RLVB 的增益几乎全部来自「更常在高证据处作答」，同一证据水平上的准确率并不比底模更好，有时在 HiddenGames 上还略差。作者把它写进了局限：在已经有足够证据时仍然答错的比例，会从 2% 到 4% 升到 10% 到 15%，主要出现在 Tabletop 任务上，也就是看错了其实已经锁定答案的观察，然后把自己信念行里那个错的答案交了出去。

## 🔬 最有意思的部分

最有意思的是「它按自己的信念行行动，但这行并没有变得更精确」。训练之后，模型并没有稳定地把证据读得更准，每一步新加的证据也和底模差不多。Pro-Worlds 上，后验教师一步能把后验抬高 5.9 个百分点，任何方法的一步只有 0.7 到 1.3 个百分点。涨分几乎全部来自：当自己的行还写着多种可能时，不要交卷。一旦这行收成单一答案，它就几乎把这个答案交出去，哪怕证据其实还不够。三个模型在 Tabletop 上，证据不足和证据充分时，它在单一答案回合的提交率几乎一样，分别是 78.5% 和 78.6%。若在第一次写出单一答案时就提交，准确率和真正跑完最多只差 2.3 个点。也就是说，它学会的是「听自己那一行」，还没学会「这一行现在是否被证据支持」。

这也解释了为什么 harness 里拒收第一次答案代替不了训练。harness 看不见观察，不知道证据够不够，只能再问一次。这个检查在 RoboQuest 上能把底模提高 6.1 到 11.3 个点，在 HiddenGames 和 Pro-Worlds 上最多只动 1.9 个点；Tabletop 里底模在被询问之后继续搜集的比例只有 2% 到 17%，其余就是重复原答案。该停不停、不该停却停，只能由读过观察的 agent 自己决定。

增益也只出现在一步真能带来证据的任务上。Tabletop 上几乎每一步都增加证据，灯和杯子上分别涨 51 和 35 个点；RoboQuest 大约五步里有一步满足要件，涨 14 到 33 个点；Pro-Worlds 大约二十步里才有一步加证据，涨 12 到 15 个点。MiniGrid 和 MineSweeper 上一步往往只把正确后验抬高约 1 个点或更少，RLVB 没有增益。HiddenGames 里 19% 的局以没有答案结束，对照底模的 7%，几乎都发生在 MineSweeper：步骤不再增加证据、或已经没有步数时，它还没有学会就自己当前最好的答案交卷。

## 🤔 我的判断

定位：**方法突破，附带一个新的视觉证据基准 Pro-Worlds。** 真正锐利的不是又一个过程奖励公式，而是把「证据是否足够」变成模拟器可验证的量，并据此把提交时机从结果对错里拆出来。

亮点三条：

- **奖励只依赖于证据，不依赖这一局的隐藏答案，也不读模型自己写的信念行。** 幸运猜测不再被当成高分轨迹，也不需要再训一个裁判或评论者。
- **九个设置全部超过底模，平均 17.1 个点，并且能迁到两个训练未见过的基准，包括没有精确后验的 RoboQuest。** 同样的学习者下，后验过程奖励大幅超过结果奖励，也平均超过带 LLM 裁判的过程奖励，还更省计算。
- **把涨分的来源说清楚了。** 不是读证据读得更好，而是更常在高证据处作答，并且在自己的信念行仍开放时几乎不再交卷。

问题与局限：

- 精确后验要求已知先验和观察似然。规则未知或开放的任务只能改成估计后验；动作空间很大时，教师的前瞻也要变浅或改成采样，成本会随动作和观察数上升。
- 信念行只能写出一个等可能的答案集合，表达不了更细的置信度。
- 训练后，证据已经足够却仍然答错的比例上升了，模型会把自己误读后的单一答案交出去；它也还没学会选择信息量更大的一步，离后验教师仍很远。
- 在一步几乎加不到证据的任务上没有增益，MineSweeper 上还更容易不交卷。准确率在不同训练 run 之间最多能差 4 个点。
- RoboQuest 上的迁移说明策略可以带走，但那里并没有逐步的后验奖励，作者也没有声称这套奖励能在开放环境里直接算出来。

对工程的直接启发：

1. **长程任务上，不要只用最终对错来教「何时该停」。** 幸运猜测和有证据的回答在结果奖励里是一样的，过早提交会被强化。
2. **Harness 里拒收第一次答案，解决不了模型不按自己信念行动的问题。** 证据够不够取决于它看见了什么，只有 agent 自己读过观察才能判断。
3. **若环境规则已知，优先用模拟器算后验，而不是再雇一个看见了答案的 LLM 裁判。** 这样既可验证，也更省，还不容易奖励幸运猜测。
4. **写信念行有用，但真正要学的是按这行行动，并且最终还要把「这行是否已被证据支持」学对。** 只把提交和开放的信念行解绑，已经能涨很多分，但误读观察之后仍会跟着错行交卷。
5. **先把这种方法用在一步确实能增加证据的任务上。** 步骤几乎不提供新信息时，学会「继续走」并不会自动变成更好的答案。

一句话：懒惰往往不是最后算错，而是证据还不够就交卷，而且模型完全可能一边写着还剩几种可能、一边把答案交出去；RLVB 用可验证的后验把「何时该停」单独教对，涨分来自开始听自己的信念，而不是来自把世界看得更准。
