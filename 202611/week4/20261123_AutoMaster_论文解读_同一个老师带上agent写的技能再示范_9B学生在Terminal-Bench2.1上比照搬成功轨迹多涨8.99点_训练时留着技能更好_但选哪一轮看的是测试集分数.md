# 同一个老师模型，只在示范时多带几条 agent 自己写的技能，9B 学生在 Terminal-Bench 2.1 上比照搬成功轨迹多涨 8.99 点；训练时把技能留在 prompt 里反而更好，但挑哪一轮的依据就是测试集分数

你有没有过这种体验：想给小模型做 agent 蒸馏，于是让大模型在任务池上跑一遍，把成功的轨迹挑出来做 SFT。数字确实涨了一点，但你翻轨迹会发现，很多「成功」是蒙对的：它声称做了验证但只跑了一个样例，改不过测试就把期望值改了，搜索卡住就反复猜同一个答案。这些坏习惯和正确动作一起被学进了学生模型。行业里的叫法是 successful-trajectory distillation 或 rejection-sampling SFT，**问题是：「任务成功」这个标签根本没告诉你应该强化哪些行为，那老师示范的过程能不能被主动塑形？**

人大高瓴的 **AutoMaster: Autonomous Post-Training by Making the Same Model a Better Teacher** 的回答是：给老师加自然语言技能（skill）去压制坏习惯、引出少见的好行为，再让一个 LLM agent 自己完成「分析轨迹、写技能、挑数据、看学生评测结果、再改」的整个后训练循环。看完我的感受是：**技能用来塑造示范行为、并且训练时保留技能上下文，这两个发现对做 harness 专用小模型的人很有用；但这个 agent 每一轮都能看到测试基准上的分数和轨迹，最终还根据这些反馈选检查点，这一点必须先摆在台面上。**

## 核心摘要

Skill-FT 的做法是：对任务 x，把选中的技能文本 s 追加到系统提示 p 后面让老师生成轨迹，学生用标准 SFT 学这些轨迹，**训练输入里保留老师当时看到的技能**；评测时学生按官方协议跑，不带任何生成的技能。AutoMaster 用两层循环自动化这件事：内层由 agent 读老师和初始学生的轨迹，设计技能，在小批量 pilot rollout 里试，改技能和适用范围，放大到批量 rollout 后挑 512 条轨迹；外层每轮都从同一个初始检查点做全参数 SFT（3 个 epoch，学习率 1e-5，batch 32），评测学生，再把分数和轨迹交还给 agent，最多 5 轮。agent 是 Codex 里的 GPT-6 Astra（xhigh），老师是 DeepSeek-V4-Pro-Preview（high），学生是 Qwen3.5-4B 和 9B，三个领域分别评测 Terminal-Bench 2.1（89 题）、BrowseComp-Lite（185 题）、Doc2Repo（50 个仓库），每个领域训练任务池固定为 1,000 个。和在成功的无引导老师轨迹里随机抽 512 条的 Vanilla SFT 相比，AutoMaster 在六个设置上全部更高，幅度 1.42 到 8.99 点，最大的是 9B 在 Terminal-Bench 2.1 上从 26.59% 到 35.58%；配对 bootstrap 下 9B 三个基准的 95% 置信区间下界都大于零，4B 在 BrowseComp 和 Doc2Repo 上的区间跨过零。去掉技能引导或去掉 agent 挑数据，六个设置的均值都下降；训练时保留技能比删掉技能高 2.15 到 4.01 点，六个设置一致。这篇的价值定位是：**老师的「过程质量」是蒸馏里被低估的一块余量，而技能是一个便宜的塑形工具；但它报告的增益来自一个看着测试集迭代、按测试集反馈挑检查点的流程，应当按开发集结果来读。**

## 🎯 为什么这件事值得写

让 LLM agent 自己做模型开发已经是一条明确的路线：从生成训练数据到跑后训练流水线。论文相关工作里列了按评测反馈改训练代码的系统，FT-Agent 用结构化规划和反馈分析改数据与训练策略，RSI-Master 用持久实验记录和审稿人式指导组织研究探索。

但这些系统要「改什么」？agent 后训练最常见的做法是在成功轨迹上做 SFT。作者的论点是：**任务成功并不指定该强化哪些行为。** 无依据的假设、无效的重复、走过场的验证可以导致失败，也可以出现在最后做对了的轨迹里。用这些成功轨迹微调，会把坏行为和支撑成功的动作一起强化；而真正有用的行为在成功轨迹里也可能很少见。所以后训练不该只「挑」示范，还要「塑」示范。

已有的相邻工作分两类：一类优化技能或 prompt 本身，不更新参数（GEPA 等）；一类把技能和训练绑在一起，比如 Skill-to-LoRA 为每个技能训一个 adapter，Skill-SD 用带技能的老师给学生自己的 rollout 打 token 分做在线自蒸馏，Behavior Priming 挑出有好行为的轨迹，PROOF-Gen 用逐任务 prompt 优化从老师的失败里救回可验证的示范。这篇的切入点是：**在老师已经能做对的任务上也去改它的做法**，并且研究训练时技能该留还是该删。

## 🏗️ 机制：Skill-FT 加两层循环

### Skill-FT

$$
\tau \sim \mathrm{Rollout}(\pi_T, x;\ p \oplus s)
$$

- 技能描述在什么情况下怎么推理或行动，可以是行为原则、具体流程或领域知识；可以跨任务共享，也可以组合。
- 学生 SFT 时保留每条轨迹原始的系统提示，**包括技能**；损失只算在 assistant 输出上（推理、回复、工具调用），系统、用户、工具消息只作为上下文。
- 评测时不给学生任何生成的技能。

### 内层循环：设计行为干预

agent 先看训练任务、无引导老师和初始学生的轨迹，找要压制的习惯和老师很少表现出的好行为，包括在老师已经能解的任务上。后面几轮它还会看学生的评测轨迹，看目标行为有没有出现、哪些弱点还在。候选技能先在 pilot rollout 里试，看能不能引出想要的行为、会不会引入新问题；然后改技能内容和适用范围，有希望的放大到批量 rollout，再按任务结果和行为表现挑训练轨迹。无引导的老师轨迹如果本身就有好行为，也可以被选进去。

### 外层循环：训练与反馈

$$
\theta_r = \mathrm{SFT}(\theta_0, \mathcal{D}_r)
$$

每轮都从同一个初始检查点 θ₀ 训练，只有实验历史在轮与轮之间累积。agent 拿到评测分数和评测轨迹，与之前的技能、老师 rollout、训练集对照，决定下一轮改技能、改覆盖范围还是换示范。

### 基础设施

agent 在自己的 Docker 容器里通过 **MCP** 访问任务和初始轨迹、提交老师 rollout 任务、对选中的示范启动 SFT。rollout harness 调老师 API，评测 harness 查询 SGLang 部署的学生；两者共用一个沙箱集群，任务工具和验证器跑在隔离的 Docker 容器里。SFT 结束后执行控制器确认检查点可用，自动调度评测；训练和评测 GPU 集群共享检查点存储，SGLang 直接从 SFT 写入的位置加载，不做中间拷贝；控制器记录作业进度，推理 worker 挂了可以续跑评测而不必重跑 SFT。每个学生的评测分数和轨迹都链接到它的检查点、训练集和老师 rollout 用过的技能。

### 实验设置一览

| 项 | 设置 |
| --- | --- |
| 研究 agent | Codex + GPT-6 Astra，xhigh 推理 |
| 老师 | DeepSeek-V4-Pro-Preview，high 推理，温度 1.0 |
| 学生 | Qwen3.5-4B、Qwen3.5-9B |
| 训练任务池 | 每领域从公开数据随机抽 1,000 题：CalibForge（Terminal）、FORT-Searcher（Search）、DeNovoSWE（SWE） |
| 评测 | Terminal-Bench 2.1（89 题，准确率）、BrowseComp-Lite（185 题，准确率）、Doc2Repo（50 个仓库，平均测试通过率；SWE harness 禁用搜索工具） |
| SFT | 全参数，512 条轨迹，3 epoch，lr 1e-5，global batch 32，最长 131,072 token |
| 评测细节 | 最终 epoch 检查点，温度 1.0，top-p 0.95，每题最多 600 步；Terminal-Bench 每题 3 小时，Doc2Repo 4 小时，BrowseComp 不限时 |
| 预算 | 最多 5 轮外层循环 |
| 报告方式 | agent 根据累积的评测反馈选最终检查点，再跑 3 次新评测取均值和标准差 |

## 🧪 关键证据

### 主结果（Table 1）

| 方法 | TB2.1 4B | TB2.1 9B | BC 4B | BC 9B | Doc2Repo 4B | Doc2Repo 9B |
| --- | --- | --- | --- | --- | --- | --- |
| Base | 15.73 | 25.47 | 33.69 | 35.50 | 21.39 | 33.42 |
| Vanilla SFT | 22.47 | 26.59 | 43.24 | 46.85 | 32.30 | 36.05 |
| AutoMaster | 28.09 | 35.58 | 46.13 | 51.53 | 33.72 | 40.79 |
| Δ vs Vanilla | +5.62 | +8.99 | +2.88 | +4.68 | +1.42 | +4.74 |

- 9B 在 Terminal-Bench 2.1 上，Vanilla SFT 只把 25.47% 提到 26.59%，AutoMaster 到 35.58%。作者的解读是：**照搬成功的无引导轨迹，低估了同一个老师能教给这个学生的东西。**
- 增益在三个领域都是 9B 大于 4B。

### 配对置信区间（Table A6，10,000 次 bootstrap，按题重采样）

| 基准 | 模型 | N | Δ | 95% CI |
| --- | --- | --- | --- | --- |
| Terminal-Bench 2.1 | 4B | 89 | +5.62 | [1.12, 10.49] |
| Terminal-Bench 2.1 | 9B | 89 | +8.99 | [2.25, 16.10] |
| BrowseComp | 4B | 185 | +2.88 | [-1.08, 6.85] |
| BrowseComp | 9B | 185 | +4.68 | [0.72, 8.83] |
| Doc2Repo | 4B | 50 | +1.42 | [-1.94, 5.33] |
| Doc2Repo | 9B | 50 | +4.74 | [0.65, 8.93] |

六个设置里有两个（4B 的 BrowseComp 和 Doc2Repo）区间跨零。区间只反映题目层面的波动，不包含训练随机性和「从多轮里挑最好一轮」带来的选择效应。

### 消融（Table A4）

| 方法 | TB2.1 4B | TB2.1 9B | BC 4B | BC 9B | Doc2Repo 4B | Doc2Repo 9B |
| --- | --- | --- | --- | --- | --- | --- |
| AutoMaster | 28.09 | 35.58 | 46.13 | 51.53 | 33.72 | 40.79 |
| 去掉技能引导（只从无引导轨迹里挑） | 17.60 | 28.46 | 45.77 | 49.19 | 32.03 | 36.97 |
| 去掉数据挑选（固定随机任务子集上加技能） | 20.22 | 34.08 | 43.78 | 50.27 | 31.43 | 38.29 |
| Task-Matched SFT | 17.98 | 27.72 | 44.32 | 50.45 | 32.37 | 36.93 |
| Vanilla SFT | 22.47 | 26.59 | 43.24 | 46.85 | 32.30 | 36.05 |

- 去掉任一组件，六个设置的均值都下降，但两者的相对贡献随领域变化：Terminal-Bench 4B 上「只加技能」20.22% 高于「只挑数据」17.60%，两者都低于 Vanilla SFT 的 22.47%，完整方法 28.09%；BrowseComp 4B 上顺序反过来，只挑数据 45.77% 高于只加技能 43.78%。作者的解释是：老师本来就会的行为靠挑，老师很少做的行为靠引。
- **Task-Matched SFT** 用同一个老师的无引导 rollout，任务 ID 和每题样本数都对齐 AutoMaster 的最终训练集，AutoMaster 仍高 1.08 到 10.11 点。
- Table A5 看配对示范：Terminal 和 Search 四个训练集里，AutoMaster 的示范与对应的无引导 rollout **都成功的占 79.3% 到 91.2%**；从失败变成功的有 45 到 106 条（每组 512 条），没有一条从成功变失败。SWE 上按分数比较，4B 训练集 43 条变好、433 条不变、36 条变差，9B 是 24、483、5。

### 训练时技能留着更好（§5.2）

Keep 保留技能指令，Remove 只删掉技能指令，轨迹和 SFT 配方完全相同，评测都不给技能。直觉上 Remove 让训练 prompt 更像评测 prompt，应该更好。结果**六个设置里 Keep 都更高，高 2.15 到 4.01 点**。

### 多轮探索（§5.3，Figure 8）

六个设置的最高均值都出现在第 2 到第 4 轮，比第 1 轮高 2.16 到 4.87 点。BrowseComp 9B 前三轮都在 49% 左右，第 4 轮到 51.53%。9B 在三个领域每一轮都高于 Vanilla SFT，4B 只有 Terminal-Bench 2.1 是五轮都高于 Vanilla。

## 🔬 最有意思的部分

**成功轨迹之间的差别，才是这篇真正的研究对象。** Figure 5 的三个对照很典型。Terminal：两次求解都满足误差阈值，无引导的老师声称四阶精度，实测收敛只有约二阶；带技能的老师换成九点模板，在逐步加密的网格上直接求解验证了四阶收敛。Search：两次都找对了剧集，无引导的老师反复猜奖项，带技能的老师从片尾字幕找导演再核对线索。SWE：两次都先写了一个输入和规格不一致的自测，无引导的老师把全局排序规则反过来去迁就错的预期，带技能的老师检查了 UTF-16 编码，修正自测输入，保留规格要求的升序，38 个测试全过，对比 32 个。**只看成功与否的过滤器，前两对是分不出来的。** 对应的技能（Appendix B）也很有工程味：execute-numeric-decision 要求把验收条件写进实际运行的断言，「不要放宽规定的容差，不要把失败的输入换成能通过的输入」；contract-checkpoint 要求「改代码之前先读真实的失败断言和输入」。

**训练时保留技能，和「训练分布要贴近评测分布」的直觉相反。** 作者给的解释来自训练样本（Figure 7）：老师在推理里会直接引用技能，比如「脚本是通过解释器执行的，所以不需要改执行权限」，或者引用技能里给的文法来决定表达式怎么分组。删掉技能，监督信号里仍然有这些引用，但输入里没有了出处，学生只能自己去猜「这条规则什么时候适用」。保留技能，相当于把「规则」和「适用条件」都显式地放进了训练输入。对做 harness 专用小模型的人，这是一个很便宜、值得复现的实验。

**基础设施部分比方法本身更像可复用的东西。** agent 通过 MCP 提交 rollout 和 SFT，评测自动调度，检查点就地加载，每个评测结果能追溯到训练集和技能。这其实是一个「研究 agent 的 harness」，和我们之前看过的自进化 harness、冻结模型加接受门的思路是一类东西，只是被优化的对象换成了学生权重。

## 🤔 我的判断

定位：**方法加系统**。Skill-FT 是一个简单、可迁移的数据生成技巧，AutoMaster 是把它自动化的研究 agent 框架，Keep vs Remove 是一个干净的小发现。

亮点三条：

- **把「过程质量」从「结果标签」里分离出来**。Table A5 显示 79.3% 到 91.2% 的配对示范两边都成功，增益主要来自同样成功、但做法不同的轨迹。
- **对照设计考虑得比较周到**：老师、任务池、训练集大小、SFT 配方固定，另做了任务对齐的 SFT 对照和两个组件消融。
- **Keep vs Remove 是一个只改输入、不改监督的干净对照**，六个设置方向一致。

问题与局限：

- **测试集反馈进了循环**。附录 A.4 写明这些基准评测「为后续实验提供分数和执行轨迹」，最终检查点由 AutoMaster「根据累积的评测反馈」选出，然后再跑 3 次新评测报告。论文没有描述独立的验证集。也就是说，agent 每一轮都能看到 Terminal-Bench 2.1 89 道题、BrowseComp-Lite 185 道题、Doc2Repo 50 个仓库上的分数**和学生轨迹**，据此改技能、换数据，再在最多 5 个候选里挑一个。Vanilla SFT 只有一个检查点，没有这种选择机会。「再跑 3 次」只消除了评测采样噪声，消除不了选择偏差。这正是我们反复看到的那类问题：自进化系统能看到验证器或测试集时，学到的可能是测试集而不是任务。
- **Task-Matched SFT 不是一个纯粹的对照**。附录写明它保留了无引导 rollout 的成功和失败轨迹，而 AutoMaster 的 Terminal/Search 训练集按 Table A5 没有「两边都失败」或「成功变失败」，等于 AutoMaster 一侧天然多了一层成功过滤。在 Terminal 4B 上这意味着 Task-Matched 一侧有 106 条对应的无引导失败轨迹。
- **统计强度有限**：4B 的两个设置置信区间跨零；Terminal-Bench 2.1 只有 89 题，单题就是 1.12 点；每个检查点只训一次，没有训练种子方差。
- **作者团队自家的基准和数据**：Doc2Repo、CalibForge、DeNovoSWE、Search harness 都来自作者团队的相关工作。没有商业利益冲突，但外部复现会更有说服力。
- 只有一个老师（DeepSeek-V4-Pro-Preview）、一个研究 agent（GPT-6 Astra）、一个学生家族（Qwen3.5），研究 agent 本身的成本（token、GPU 小时）没有报告。

对工程的直接启发：

1. **蒸馏前先看成功轨迹的「做法」**。验证是否真跑了、失败时是先诊断还是先改期望、搜索卡住时有没有换线索，这些都可以写成技能去引导老师重跑。
2. **SFT 数据里保留老师当时看到的技能/系统提示**，至少作为一个消融去试，别默认「训练 prompt 必须和推理 prompt 一致」。
3. **做自动后训练 agent 时，把评测集分成 agent 可见的开发集和最终报告用的锁定测试集**。只要 agent 能看到测试轨迹，就要把报告数字当成开发集数字来读。
4. 这套「MCP 提交 rollout/SFT、评测自动调度、结果可追溯到数据和技能」的基础设施，本身就适合拿来做 harness 专用小模型的适配流水线，换成 RL 或换成别的 harness 都不需要改架构。
