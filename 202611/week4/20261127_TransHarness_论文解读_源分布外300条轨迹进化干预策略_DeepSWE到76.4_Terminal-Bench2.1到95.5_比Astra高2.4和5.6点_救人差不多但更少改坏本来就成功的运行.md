# 源分布外 300 条轨迹进化干预策略，DeepSWE 到 76.4%、Terminal-Bench 2.1 到 95.5%：比 Astra 高 2.4 和 5.6 点，救人差不多，但更少改坏本来就成功的运行

你有没有过这种体验：脚手架进化听起来很美，不改权重，只靠过去任务上的经验把 agent 改得更强，结果在进化用的那套题上分数涨了，换一个基准就掉回去。行业里把「用以往执行经验改 harness」叫脚手架进化，SICA、Meta-Harness、Self-Harness 都在这条路上，DGM 和 ModularRSI 也试过跨基准迁移。**问题是：源任务上的增益怎样才算迁得出去？在已经很强的模型和成熟脚手架上，怎样才能救人，同时少改坏本来就会过的运行？**

这篇 **TransHarness: From Benchmark Overfitting to Transferable Harness Evolution** 的做法是：从同一任务的成败轨迹对比里写出干预策略，每条策略带一个可执行触发条件和一套诊断式指导，再用跨任务回放和独立的语义筛选，留下会选择性地出手、并且把修正建立在当前任务证据上的策略。看完我的感受是：**只用进化集上的 300 条轨迹，冻结后再去测两个目标基准，DeepSeek、Qwen、GLM 在轻量和原生脚手架上都有提升；DeepSeek 加 Mini-SWE 在 DeepSWE v1.1 上到 76.4%，加 DeepSeek Harness 在 Terminal-Bench 2.1 上到 95.5%，点估计比公开最强基线 GPT-6 Astra 高 2.4 和 5.6 个点。同样会救人，Self-Harness 救回 13.3%、它救回 13.0%，但回归从 13.0% 降到 9.7%。必须一起读的冷水是：那两个旗舰配置相对自身基线的配对增益，95% 区间分别是 -2.4 到 8.8 点和 -1.1 到 12.4 点，三次重复还包着零。**

## 核心摘要

作者先把问题写成可迁移的目标：模型 (M) 和底座脚手架 (H_0) 固定，只在源分布 (P) 上学习一组有序干预 (B)，得到 (H_B)，再在独立目标分布 (Q) 上看成功率差。净增益被拆成 (\Delta=(1-p_0)r-p_0 q)，其中 (p_0) 是底座成功率，(r) 是把原失败救回来的比例，(q) 是把原成功改坏的比例；底座越强，允许的回归对救援比就越低。策略来自同一任务的一对成败轨迹：写作代理对照完整轨迹（任务说明、模型消息、工具调用和观察，看不到仓库参考解和隐藏评分测试）诊断分岔决策，写出「在哪个位置、在什么可观察上下文里触发、给出什么诊断指导」；单独的审稿角色可以改措辞或退回重写，可执行检查会在源轨迹上记录激活和控流。跨任务回放要求事件触发不能几乎来者不拒（两边都激活的比例低于 0.9），且单独盯上失败的次数不少于单独盯上成功的次数；活下来的策略再过三项独立语义判断：诊断有依据、不依赖源任务解法、修正动作建立在失败检查或明确任务要求上。进化集从 SWE-bench Pro 按困难度和仓库覆盖选出 100 题、11 个仓库，每题三次执行共 300 条轨迹，与 DeepSWE 的 91 个仓库没有重叠。目标评测是 DeepSWE v1.1（113 题）和 Terminal-Bench 2.1（89 题），模型是 DeepSeek V4.1 Flash（1017）、GLM-5.3 Flash 和 Qwen3.8-Flash-Next，轻量脚手架是 Mini-SWE 和 Terminus 2，原生脚手架是 DeepSeek Harness、ZCode 和 Qwen Code，每项分数是三次独立运行的均值。在同一 DeepSeek 加 Mini-SWE、同一批源轨迹上，Meta-Harness 在进化集上涨 2.0 点，到 DeepSWE 掉 4.1 点（救援 12.7%，回归 16.8%）；Self-Harness 和 RRSI 净增益都只有 0.3 点；TransHarness 到 76.4%，救援 13.0%，回归 9.7%，进化消耗 132.7M token，新的计分源运行是 0 次，而 Meta-Harness 是 798.1M、Self-Harness 是 4,226.3M。消融里，去掉学到的触发时机，分数从 76.4% 掉到 72.6%，回归升到 13.3%；把「按当前证据重新判断」换成预先写死的修正，分数掉到 65.5%；14 条未审干预的脚手架只有 67.3%，审过的 7 条才到 76.4%。源任务预算也不是越多越会救人：25 题和 50 题的版本低于底座，100 题的版本高 3.2 点，靠的是把回归从 17.1 降到 9.7，而不是救援更多。这篇的价值定位是：**一份把「脚手架进化有没有过拟合进化基准」说到可测的方法，核心不是再搜一套新提示，而是让干预在新任务上仍然只做诊断、把解法留给当前证据。**

## 🎯 为什么这件事值得写

脚手架负责组织工具、解释反馈、核对任务是否做完。用以往任务上的经验去改它，看起来是一条不必动权重的增强路径。麻烦在于，进化时用的反馈常常和目标基准叠在一起：SICA 在固定题套上选版本，Meta-Harness 在同一批 TerminalBench-2 任务上搜索并评估，Self-Harness 用基准内部的留出题做接受门。这样涨出来的分，很难分清是迁得出去的能力，还是对这套考场脾气的适应。作者复现 Meta-Harness 时就遇到了这种裂缝：进化集上提高了，DeepSWE v1.1 上成功率掉下来。

另一头，已经很强的模型和成熟脚手架更难涨。HarnessOpt-Bench 里，进化后的简单脚手架即使用同一模型和同一批题，仍然落后于成熟的 OpenCode。底座成功率升高之后，剩下能救的失败变少，已经成功的运行却更容易被新干预改坏。作者把这个关系写成一个很清楚的不等式：要净增益为正，回归率必须低于 ((1-p_0)/p_0) 倍的救援率。对强 agent 来说，成功的进化必须在找出被忽略问题的同时，保住已经能工作的行为。

## 🏗️ 机制：触发条件负责「何时出手」，诊断指导负责「按当前证据重想」

一条策略是三元组：脚手架上的位置、可执行触发器、诊断指导。位置可以是模型调用、工具、上下文更新或完成步骤；触发器只看可观察的执行上下文。指导不直接给出源任务上的补丁，而是把模型重新指向当前任务的要求和证据。一个贯穿全文的例子是测试改动：失败轨迹可能是在削弱测试，成功轨迹是在修缺陷，提炼出的原则是「对照任务要求和仍然存在的缺陷来评估测试改动」，换一道题可以得出完全不同的具体修正。

迁移会从两个因子上失败。暴露率决定有多少运行真的被干预碰到，条件价值决定碰到之后是好是坏。触发面太窄，救不到新的失败；激活率不变但指导不合适，又会在新分布上帮倒忙。所以筛选是两段：先用其他源任务上的成败对做回放，滤掉几乎来者不拒、或更常单独盯上成功运行的事件触发；再在完全不看回放统计的情况下，对冻结候选做三项语义判断。选中的策略按源顺序排进各接口，在目标评测前全部冻结。

进化证据本身也被特意拉开。100 题来自 SWE-bench Pro，按公开多模型解决率加语言偏移排序，并保证每个仓库库至少 4 题。任务类型和业务域用统一编码表标注后，用全变差距离衡量和目标基准的差距；把基准内部的进化集换成这套独立集，DeepSWE 上的域分布距离从 0.13 升到 0.70，Terminal-Bench 上从 0.18 升到 0.64。作者还检查了组合型分布外任务，也就是源任务里没一起出现过的要求组合。

## 🧪 关键证据或主结果

主表覆盖三个模型和两类脚手架，提升是全面的，但幅度并不均匀。DeepSWE 上，Qwen Code 加 TransHarness 从 55.8% 到 63.7%，是最大的 +7.9 点；DeepSeek 的 Mini-SWE 从 73.2% 到 76.4%（+3.2），原生 DeepSeek Harness 从 70.8% 到 75.2%（+4.4）。Terminal-Bench 2.1 上，DeepSeek Harness 从 89.9% 到 95.5%（+5.6），Terminus 2 从 84.3% 到 86.5%（+2.2），Qwen Code 从 86.5% 到 89.9%（+3.4）。公开对照里，GPT-6 Astra 在两个基准上是 74.0% 和 89.9%，于是 76.4% 和 95.5% 被写成新的最高分。

和既有进化方法的对照更说明「迁得出去」难在哪。同一 DeepSeek、同一 Mini-SWE 2.4.6、同一批源轨迹上，Meta-Harness 在目标上净负，Self-Harness 和 RRSI 几乎打平底座。RRSI 的细节值得单独记一笔：没有候选通过它自己的接受规则，作者退而评了源成功率最高、并列时 token 更低的那个候选。TransHarness 的救援比例并不更高，赢在少破坏成功运行。组合型 OOD 上，四个 DeepSeek 配置都有提升，Mini-SWE 和 Terminus 2 分别多 14.6 和 4.1 点。

消融把公式里的两项拆开了。把同一段指导改到「第一次符合条件就说」，救援还在 12.7%，回归却升到 13.3%，总分掉 3.8 点。保留触发器和诊断主题、改成直接规定怎么改，救援掉到 8.8%，回归升到 16.5%，总分 65.5%；两者一起去掉时回归最高，到 17.7%。源预算那张表同样不是「数据越多救人越多」：50 题版本的救援（14.7%）甚至高于 100 题（13.0%），却因为 17.1 的回归而低于底座。

## 🔬 最有意思的部分

最有意思的是干预被设计成「诊断程序」，而不是「可搬的解法」。Koota 那个案例写得很具体：本地测试都过了之后，策略让 agent 重新检查需求覆盖，发现「NOT 更新」这种行为没有被测到，于是补测试并修好缓存键。底座脚手架过了 43 个任务测试里的 41 个，Self-Harness 过了 42 个，TransHarness 过了全部 43 个，三种脚手架都过了 172 个回归测试。源策略提供的是「验证可能不完整」这个提问理由，需求和证据来自目标任务本身。

Qwen Code 上的策略清单也说明筛选有多严。26 对源轨迹产生的候选里，11 条过了回放门，8 条再过三项语义检查；其中 3 条被写作代理改过，2 条只改了措辞，3 条原样收下。保留下来的包括：把可观察要求当成合同、截断输出先翻页再下结论、通过基线检查后先分清该保留的旧行为和该单测的新要求、用真实项目对象而不是自写替身做验证、在自写检查通过后再审计需求覆盖，以及检查被 stub、skip 或抑制掉的行为是不是任务所要求的。审稿还改过一条完成阶段的指导：最初是「跑已有测试，修任何失败」，后来改成只修由当前改动引起的失败，不相干的失败要报告但不必扩大修理义务。

成本对比几乎是同一设计的另一面。Meta-Harness 和 Self-Harness 超过 99% 的进化 token 花在新的源任务计分执行上，TransHarness 用归档轨迹回放加语义审查筛选策略，在记录口径里没有新增计分源运行。这当然也意味着它更依赖前面那一轮已经跑好的 300 条轨迹，以及写作、审稿、检查这条流水线本身的质量。

## 🤔 我的判断

定位：**针对脚手架进化迁移失败的方法，外加一套必须把回归和救援一起看的评测。** 它证明了「在源分布外进化、再到新基准上还能涨」是可以做的，但没有把两次旗舰领先写成统计上已经钉死的结论。

亮点三条：

- **把过拟合问题从口号变成可对照的实验。** 独立进化集、跨基准评测、和 Meta-Harness / Self-Harness / RRSI 的同模型同轨迹对比，链条是完整的。
- **在救援率几乎打平的情况下，靠降低回归拉开差距。** 这对已经很强的底座特别重要，公式和消融都指向同一件事：触发时机和「按当前证据重想」，比提前写死修正更不容易帮倒忙。
- **进化成本明显更低。** 132.7M token、零次新的计分源运行，说明可迁移性不一定要用更重的在线搜索来换。

问题与局限：

- 旗舰配置相对自身基线的配对区间穿过零，三次重复的波动不小，76.4% 和 95.5% 对 Astra 的领先首先是点估计，不宜直接当成已经稳定的新 SOTA。
- 策略由写作代理和审稿角色从轨迹对里起草，再经门和语义判断筛选，并不是完全无人值守的自动搜索；不同配置上留下的策略集合也不一样，规模如何随任务增长，文中没有给出很强的答案。
- 文中未公开本次实验代码和策略工件，复现要自己搭写作、回放和语义审查流水线。
- RRSI 没有候选通过原接受规则，对照的是退而求其次的候选；公开榜分数来自外部快照，推理设置和 agent 时限与作者自己的三次运行并不保证完全同条件。
- 目标仍是两个软件/终端基准，安全性和可维护性只在影响声明里被提醒，没有进入主指标。

对工程的直接启发：

1. **看脚手架进化结果时，先问进化集和测试集是不是同一套脾气。** 源上涨、目标上掉，已经在 Meta-Harness 的复现里出现过。
2. **在强底座上，不要只报救援了多少失败。** 把回归率放在和救援率同一张表里；底座越强，能容忍的回归越低。
3. **干预尽量写成「在什么上下文里，根据当前要求和证据重新判断」，而不是把源任务上的修法写死。** 消融里，写死修正会同时少救人、多伤人。
4. **筛选时把回放选择性和语义独立性分开。** 一个站得住的诊断也可能来者不拒，一个很挑场合的触发也可能夹带源任务解法。
5. **先把已有成败轨迹用起来，再决定要不要为每个候选重新跑源任务。** 在这篇的记录里，新的大规模源计分并不是迁移的必要条件。

一句话：脚手架进化要迁得出去，关键往往不是在源任务上救人更多，而是让干预在新任务上仍然只负责提问和核对，并把本来已经成功的运行留下来。
