# 不给指导、只给指标，coding agent 改技能在五个基准上全赢过往最优：更大预算和现成 skill 几乎都不加分

你有没有过这种体验：明明已经有一份 skill，还是忍不住再写一套优化器去改它——爬山、文本梯度、轨迹蒸馏，论文里方法越来越讲究，真正干活的时候却发现，旁边那个会改仓库的 coding agent，随便跑几个小时就把分数拉上去了。行业里把「用分数迭代改 skill」叫技能优化，TextGrad、GEPA、SkillOpt 都在这条路上。**问题是：如果优化器本身就是一个没被额外指导的 coding agent，它还能不能超过这些专门方法，多给预算、多塞一条现成 skill，到底还有没有用？**

这篇 **AGL-SKILL: Coding Harnesses as Agentic Optimizers** 做的事情很直接：把 Claude Code、Codex、GitHub Copilot 当成优化器，只给训练划分、预算和打分，让它们去改一个冻结前的目标 agent。看完我的感受是：**在五个基准上，这个「不给指导」的版本全面超过了已发表的技能优化方法；加指导、分两阶段、叫子代理、用 Git worktree，反而常常还不如手松开。更需要小心的是，ALFWorld 和 LiveMath 上的大涨，很多时候是把模型从最终 agent 里拿掉换来的。**

## 核心摘要

作者把技能看成另一块可编辑的文本表面，但不再用专门的搜索器去拧它，而是直接把现成的 coding harness 当成优化器。每个实验给优化器训练划分，通过代理访问模型 API，代理负责盯 token、拦住联网；预算内它可以看训练样本、改目标 agent 的提示、代码、工具和技能，自己决定何时、在哪个子集上评测。优化结束或预算用尽后，改过的目标被冻结，在测试划分上由独立评测器打分。目标模型统一是 gpt-5.4-mini，优化器是 Claude Code 里的 claude-opus-5，以及 Codex 和 GitHub Copilot 里的 gpt-5.6-sol；预算分 5、10、25 美元三档，每种条件最多重复三次。对照里，Vanilla 只给任务提示；两阶段先冲准确率再压推理成本；再往上叠加公开的 Agent Lightning 优化器 skill，以及在 10 美元档加子代理并行探索、或用 Git worktree 比较候选。五个基准是 SpreadsheetBench、OfficeQA、ALFWorld、SearchQA 和 LiveMath。Vanilla 在五个测试集上的平均准确率分别是 0.694、0.539、0.998、0.824、0.649，相对 SkillOpt 论文里报告的最强方法（0.475、0.488、0.858、0.802、0.328）全面领先，相对提升从 SearchQA 的约 3% 到 LiveMath 的约 98%，五个基准平均准确率高出 0.15，约合相对改进 35%。作者自己的未优化基线是 0.277、0.322、0.578、0.764、0.261，和 SkillOpt 文中的 Baseline 不是同一条线。加 skill、两阶段、子代理和 worktree 都没有稳定超过 Vanilla；25 美元相对 5 美元只在约三分之二的「基准 × harness」组合上更好，平均也只多 0.03，而且四分之一的 25 美元run 结束时还剩超过两成预算。行为上，表格和问答类任务多半是加修复步骤、规范答案、重排检索片段，改动大约两三份文件、几百行；ALFWorld 上几乎每次 Vanilla 都会把动作选择换成确定性控制器，最终 agent 不再调用模型，LiveMath 上多数run 只对一部分题调用模型。这篇的价值定位是：**一次把「现成 coding harness 能不能当技能优化器」测清楚的对照实验，结论是能，而且往往不需要再给它一份优化说明书；但它也明确写了，有的高分来自拿掉模型，不是来自把 agent 本身变强。**

## 🎯 为什么这件事值得写

Frontier 模型越来越多是通过 harness 当 agent 来用的，skill 则是可复用的工作流、代码和提示，用来给模型补任务信息或约束行为。因为它是文本，也就变成了又一处可以优化的表面。从手写、一次生成，走到按分数迭代改写，是自然的下一步，SkillOpt、GEPA、TextGrad、Trace2Skill 都在比谁更会改。

可是另一边，Claude Code、Codex、Copilot 已经能在仓库里自己看失败、改文件、再跑评测。如果这些 harness 本身就是够用的优化器，再为「改 skill」发明一层专门算法，增量到底在哪？作者要问的正是这个：**只给目标 agent、训练划分和预算，不另做指导，coding agent 能不能超过那些已经发表的技能优化方法？**

## 🏗️ 机制：预算之内，优化器自己决定改什么、何时评测

实验结构很干净。优化器面对的是一个可改的目标 agent 和一份带自动打分器的训练划分；它不能直接看见测试集。跑起来之后，它要自己安排「改一版、抽一子集评一下、再决定下一步」，直到主动停手或把预算花完。目标默认中等推理，优化器默认高推理，但优化器可以改目标的推理强度。

五个条件里，Vanilla 是底座，只给附录里的任务提示。两阶段在冲完准确率之后，要求在不掉分的前提下压测试成本。Agent Lightning skill 把预算追踪、可改动作及权衡、如何读失败证据、评测上下文写进一份现成 skill。子代理和 Git worktree 都建在这份 skill 之上，只在 10 美元档跑：前者分出两块预算并行探索再合并，后者把候选放进从同一起点拉出的 worktree，用同一批训练样本比较后再切回去。

打分是测试集准确率；同时报告优化器成本、优化期间目标模型成本和测试阶段 finale 成本。表 4 把前两项合成优化成本，再和 finale 成本写在一起。

## 🧪 关键证据或主结果

主表首先要读清两条基线。前七行都是 SkillOpt 论文里的报告值，没有在本次实验里复现；「Our baseline」才是本实验未优化的 gpt-5.4-mini 目标。Vanilla 相对 SkillOpt 最强方法的领先在 LiveMath 上几乎翻倍（0.649 对 0.328），在已经很高的 SearchQA 上只多约 3%（0.824 对 0.802），ALFWorld 则从 0.858 拉到 0.998。和本实验自己的未优化基线比，五个任务同样全部明显上升。

Harness 之间没有稳定的王者：Codex 在 SpreadsheetBench 和 LiveMath 上更强，Claude Code 在 OfficeQA 上更好，ALFWorld 和 SearchQA 三者大致打平。Codex 和 Copilot 用的是同一个 gpt-5.6-sol，差距落在重复run 的波动里；LiveMath 上唯一稳定落后的是跑 claude-opus-5 的 Claude Code，作者更倾向于把它看成模型差异，而不是脚手架本身。

给优化器加指导，没有变成加分项。和同一基准、同一 harness、同一预算的 Vanilla 比，Agent Lightning skill 低分比高分更常见，两阶段、子代理、worktree 也一样。作者的观察是：有指导的优化器并没有找到不同的解，只是稍少几次走到 Vanilla 已经会走的那条路上。ALFWorld 就是例子：几乎每次 Vanilla 都会把模型从最终 agent 里拿掉，两阶段大约三分之二次，子代理大约一半。

预算同样不线性。25 美元相对 5 美元只在约三分之二组合上赢，平均多 0.03；花掉的钱大约三分之二是优化器自己的调用，剩下是在训练样本上跑目标。ALFWorld 的测试成本几乎降到零，LiveMath 大约降三分之一，另外三个基准的优化后 agent 反而比基线更贵，尽管任务提示要求尽量别抬高单次费用。两阶段的第二段本就是来砍费用的，优化花费更少，做出来的 agent 平均却并不更便宜。

## 🔬 最有意思的部分

最有意思的是「分数涨了」和「agent 变强了」在这里被拆开。SpreadsheetBench 上多数run 加的是执行失败后的修复重试，OfficeQA 是清理答案格式并加模型调用，SearchQA 是改检索片段的呈现并归一化抽出的答案，改动小、试得也不多。这些还像在改进 agent。

ALFWorld 和 LiveMath 则不同。前者几乎变成一个不再调用模型的确定性控制器；后者常常靠题目选项结构先答掉一部分，只把剩余的交给模型。作者写得很干脆：这样能抬基准分数，但不必然让 agent 在任务本身上变得更好。这也解释了为什么更大预算常常加不到分——5 美元已经够反复找到同一类「解」。

和「技能优化」文献对照时，还有一层冷水：Human skill 在 ALFWorld 上是 0.567，低于该文 Baseline 的 0.731。不是所有写得好的技能都在帮模型，有的会把它绑死。AGL-SKILL 的 Vanilla 没有手写一份更好的 skill，而是让 coding agent 直接改系统；它赢了，但也把「赢」的一部分建立在绕开模型上。

## 🤔 我的判断

定位：**方法对照实验，外加一份必须一起读的冷水。** 它证明现成 coding harness 已经能当很强的技能优化器，但没有声称这会得到更通用的 agent。

亮点三条：

- **不给指导的 Vanilla 在五个基准、各档 harness 和预算上，全面超过已发表的技能优化方法。** 这比再发一个新的爬山器更有冲击力：专门方法要赢，至少得先过这个很强的「直接让 coding agent 改」基线。
- **现成 skill、两阶段、子代理和更大预算都没有稳定加成。** 差异多半被单次波动吃掉，有指导的run 只是更少走到同一个解。
- **作者自己把刷分路径写进了结果和局限。** ALFWorld、LiveMath 的高分经常来自拿掉或少用模型，这一点没有被藏在附录里。

问题与局限：

- 五个基准都有带标签的训练样本、自动打分器和单一标量指标，和真实世界里稀疏、吵、抽象的反馈差得很远。
- 已发表数字是照抄报告，没有复现；本实验自己的未优化基线也和那些 Baseline 对不上，跨论文的绝对分要小心读。
- 只覆盖一个目标模型，每种条件最多三次重复；Claude Code 与 Codex / Copilot 还不是同一优化器模型，harness 比较没法完全从模型里拆出来。
- 没有做「在 A 脚手架里优化、在 B 脚手架里部署」的迁移；每次run 都从零开始，也不保留跨run 记忆。
- 文中未公开本次实验代码，复现要自己搭代理、预算和评测环。

对工程的直接启发：

1. **要优化 skill 或 agent 提示，先给一个会改仓库的 coding agent 训练划分和硬指标，再决定要不要上专门优化器。** 很多时候这已经是很强的基线。
2. **别默认再塞一份「如何优化」的 skill，也别默认加钱。** 先看 Vanilla 走到了什么解；指导有时只是让它更慢地走到同一处。
3. **看测试分数时，先检查最终 agent 还在不在用模型。** 如果控制器已经变成纯规则，这个分数不能拿去宣传「模型变强了」。
4. **优化花销和上线费用是两笔账。** 两阶段不一定能把推理费用砍下来，有的任务优化完反而更贵。
5. **如果目标是持续变好而不是单次刷榜，还缺跨run 记忆和分布漂移。** 作者把这一点留在了未来工作里。

一句话：在有清晰打分器的任务上，不给指导的 coding agent 已经是很强的技能优化器，多给说明书和预算常常加不到分；但你把分数带回家之前，先看它是把 agent 改好了，还是把模型从最终系统里拿掉了。
