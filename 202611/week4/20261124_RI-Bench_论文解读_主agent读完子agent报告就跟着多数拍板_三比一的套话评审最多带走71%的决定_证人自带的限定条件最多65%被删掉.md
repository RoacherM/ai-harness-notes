# 主 agent 读完子 agent 的报告就跟着多数拍板：三比一的套话评审最多带走 71% 的决定，证人自带的限定条件最多 65% 在最终报告里被删掉

你有没有过这种体验：开了一个 orchestrator 加几个 subagent 的多 agent 流程，几个子 agent 各自去查、各自写报告，主 agent 汇总出一份引用齐全、文笔流畅的结论，你读着挺满意。直到某次你翻回子 agent 的原始报告，才发现其中一个明确写了「样本只有 30 个，结论只适用于欧洲市场」，到了主 agent 那里变成了一句无条件的事实；或者四份报告里三份是泛泛而谈的套话、一份是真正读了材料的细致分析，主 agent 跟着那三份走了。行业里把这种结构叫 orchestrator–worker、manager–subagent、hierarchical agents，大家都在评最终答案对不对。**问题是，一份写得漂亮的最终答案，根本说明不了上层 agent 是真的权衡了下级的材料，还是只是数了票、做了拼接。**

南京大学、中山大学等团队的 **Do Senior Agents Do Their Job? Measuring Role Integrity in How LLM Agents Use Subordinate Material** 把这件事做成了一个可以测的对象，叫 role integrity。它借了三个真实机构层级的规则和公开记录：会议审稿（领域主席和程序主席）、美国最高法院（法官和双方律师）、英国议会特别委员会（主席和证人），专门测上层角色对下级材料的三种义务：**权衡、核实、转述**。看完我的感受是：**这篇最有价值的地方不是「模型会从众」这个结论，而是它把「上层 agent 有没有尽职」从看结果改成了看干预响应，而且三种义务的失败率差了一个数量级，同一个模型在不同义务上排名完全不同。**

## 核心摘要

RI-Bench 只测层级中的一步：上层 agent 把下级交来的材料变成决定、裁决或报告的那一刻。下级材料事先写好并固定，每个场景只改材料的一个属性，其余全部不变，然后看上层输出怎么随之变化。OpenReview 场景里，论文和 rebuttal 不变，只交换「细致的评审」站在哪一边，看程序主席的决定会不会跟着「套话多数」走；Court 场景里，案卷始终正确，只在一方律师的陈述里埋一个错误的程序事实，看裁决会不会照抄；Parliament 场景里，两位立场相反的证人各给一条带两个限定条件的核心主张，看委员会报告引用时限定条件还在不在。被测角色全部跑在 pi coding agent 里，只有 read、ls、grep 三个只读工具。八个模型、超过 12,000 个 agent episode 的结果是：**可以对照案卷核对的程序性错误很少被采纳（2.9% 的裁决）**；但需要判断下级说得好不好的义务经常失守：在给定论文全文的情况下，跟着一个反向的套话 3:1 多数走的比例按模型从 0.20 到 0.71，证人的限定条件在引用中全部丢失的比例从 0.20 到 0.65。在 prompt 里写明角色义务（Obligation prompt）能降低这些失败但消不掉，而且连对照条件里的行为也被改变了。综合三项的 RI 分数在 Vanilla 下从 0.55 到 0.86，排序与第三方通用能力指数并不一致。附带一个小实验：同一模型换 harness（pi 对 Codex CLI，pi 对 DeepSeek 自家 harness），在困难子集上 RI 的变化可以和改 prompt 一样大，也可能被运行间方差淹没。这篇的价值定位是：**一套用「控制变量改输入、看上层输出响应」来测 manager agent 是否尽职的方法，加上一份「上层 agent 会核事实，但不怎么权衡质量、也不怎么保留限定」的跨模型证据。**

## 🎯 为什么这件事值得写

长任务正在越来越多地被拆给多个 agent：子 agent 并行干活、向上汇报，上层 agent 把报告变成最终答案。这种分工有没有用，前提是每个角色、尤其是上层角色真的履行了它的职责。论文开头引了几条早期迹象：Anthropic 报告过 hidden-profile 实验里 agent 小组没法可靠地合并关键的私有证据，在另一组游戏开发实验里加一个「CEO 层级」提示「没什么区别」；在单 agent 问答实验里，模拟的同伴把原本答对的 agent 带偏，比把答错的拉回来容易得多；中心化结构让集体判断对中心节点特别敏感。放到层级里，这些倾向恰好落在**那个输出会替代所有人工作的 agent** 身上，而它的轨迹依然流畅、程序上合规，只是角色的功能没了。

现有评测基本没法回答这个问题：

- 能力基准把 agent 当独立解题者打分；
- 轨迹审计（MAST 的失败分类、失败归因到 agent 和步骤、长时程崩溃诊断）都是事后诊断，而不是主动干预上层收到的材料再看它怎么反应；
- LLM-as-judge 评输出质量也有同样的盲区，**一个权衡后同意多数的主席和一个只数票的主席，写出来的东西读起来一样**。

作者的关键一招是：既然只看输出分不出来，就**设计上层 agent 的输入**，让尽职和偷懒两种行为把输出往不同方向拉，其他一切不变，再从输出读出它到底做了哪一种。

## 🏗️ 机制：三个机构、三种义务、三个失败率

### 什么叫 role integrity

一个角色义务 = 上层角色对下级材料的一种用法 + 这种用法必须遵守的证据约束。作者选的三种：

| 义务 | 场景 | 上层角色欠下级什么 | 干预 | 失败率（越低越好） |
| --- | --- | --- | --- | --- |
| 权衡（weigh） | OpenReview（ICLR） | 决定要基于评审论证的强弱并对照论文本身，而不是看几票倾向哪边 | 论文和 rebuttal 不变，交换细致评审与套话评审所在的一边 | Majority following：程序主席决定跟着套话多数、背离论文历史决定的比例 |
| 核实（verify） | Court（美国最高法院） | 先对照案卷核实律师的说法，再依赖它 | 案卷保持正确，在一方律师的陈述里错写一个程序事实（多数是下级法院的处置结果） | Error adoption：裁决把这个错误当作事实陈述的比例 |
| 转述（relay） | Parliament（英国特别委员会） | 报告要连同证人自己附加的限定一起转述证据 | 两位立场相反的证人各一条核心实证主张，改写为各带两个限定（样本量、范围、时间窗、暂定状态） | Limitation loss：被引用的主张两个限定都丢掉的比例 |

RI 定义为三个失败率的补数的算术平均。作者反复强调：RI 只总结「避免了这三种被测失败」，**不证明角色在其他方面都尽职了**，所以永远和三个分量一起报。

### 三个场景怎么搭

**OpenReview**：用真实 ICLR 投稿的全文和作者 rebuttal。领域主席 agent 读论文、评审和 rebuttal，写 meta-review 并给出建议；程序主席 agent 拿到这份 meta-review 加同样的材料，给出最终决定。所有 OpenReview 指标都算在程序主席的决定上。评审文本由一个固定模型重新生成（它通过和被测对象一样的工具读论文），有两种风格：具体评审引用论文内容，套话评审保持模板化。两种设计：

- **真实票数**：保留投稿真实的 3:1 分数分布，细致评审站在多数（A 组）或少数（B 组），看决定动不动。
- **构造票数**：以论文的 ICLR 历史决定为参照方向。对照组里细致的 3:1 多数指向它、一个套话评审反对；对抗组里套话的 3:1 多数（分数 3/3/2 或 7/7/8）指向反方向，唯一细致的异见者指向参照方向。

**Court**：真实案件的事实、问题陈述和双方辩论摘录，上层角色写裁决。在一方的摘录里错写一个程序事实，而给法官的案卷是对的，所以错误可以核对。A 组把错放在胜诉方，B 组放在败诉方，真实结果不给。裁决被标为 ADOPTED、CORRECTED、TRUTH STATED 或 SILENT。

**Parliament**：真实调查的全部书面证据，上层角色写报告。每份报告被标为对每条主张 CITED WITH LIMITATIONS、CITED WITHOUT、OMITTED。只有一组，因为两位证人在同一份报告里。

### 实验配置

- **被测模型（8 个）**：Claude Opus 5、GPT-5.6 Sol / Terra / Luna、GLM-5.3、GLM-5.3-Flash、Qwen3.5-35B-A3B、DeepSeek-V4.1-Flash，都请求 medium reasoning。
- **两种提示**：Vanilla 只给角色名和任务；Obligation 加一小段职责清单，比如告诉程序主席要独立决定、在领域主席的理由只是数票时推翻它，告诉法官依据法律论证和案卷证据，告诉委员会主席综合所有证人的证据。
- **数据**：OpenReview 真实票数 119 篇 ICLR 2024–2026 投稿（真实 3:1 分布），构造票数 118 篇（58 接收、60 拒稿，不与前者重叠）；Court 120 个按难度分层的案件；Parliament 从处理过的 469 个调查里得到 132 个有合格对立证人对的，用其中 120 个。
- **规模**：12,392 个 episode（OpenReview 6,632、Court 3,840、Parliament 1,920），另有 800 个用于 harness 对比。
- **harness**：上层角色跑在 pi coding agent 里，只有 read、ls、grep。拿到任务描述和一份新拷贝的案件目录清单，目录里没有结果元数据；什么都不预加载，所以「从没打开少数派评审」和「打开了读完再否掉」会留下不同的工具轨迹。
- **评分**：OpenReview 的决定从必填 schema 读取（6,632 个输出里 6,615 个含有）。Court 和 Parliament 是两层：每个案件的模式规则给第一个标签，然后 Gemini 3.8 Flash 对相关段落分类，**并且必须返回一段裁决或报告里的原文引用，作者核对引用确实存在**，只有核对通过的判断才覆盖模式标签。
- **干预材料的质量控制**：GPT-5.6 Sol 生成 Court 和 Parliament 的干预，Claude Sonnet 5 生成 OpenReview 评审，所有材料先过机械检查和 Gemini 3.8 Flash 盲评。在 60 条随机抽取的真实票数评审上盲评 1–5 分具体性：具体评审 5.00，套话评审 2.83，长度几乎一样（226 对 233 词）。
- **成本**：上层角色调用约 13 亿输入 token、6,800 万输出 token，按列表价约 3,000 美元；harness 对比和所有评判调用另加约 150 美元。

## 🧪 关键证据

### 权衡：套话多数能把决定带走

构造票数设计下，论文和 rebuttal 固定、评审包反转，**每个模型都是「跟着新多数转」多于「反着转」**。八个模型合计 1,878 对配对决定里，对照组里与参照一致的决定有 621 个在对抗组里跟着套话多数转向，反向只有 5 个。

| 模型 | Vanilla 对抗组跟随率 [95% CI] | Obligation 对抗组跟随率 [95% CI] |
| --- | --- | --- |
| Claude Opus 5 | 0.20 [0.14, 0.28] | 0.19 [0.13, 0.27] |
| GPT-5.6 Sol | 0.51 [0.42, 0.59] | 0.25 [0.17, 0.32] |
| GPT-5.6 Terra | 0.47 [0.38, 0.57] | 0.30 [0.21, 0.38] |
| GPT-5.6 Luna | 0.50 [0.41, 0.58] | 0.36 [0.27, 0.44] |
| GLM-5.3 | 0.71 [0.63, 0.80] | 0.33 [0.25, 0.42] |
| GLM-5.3-Flash | 0.43 [0.35, 0.53] | 0.23 [0.15, 0.31] |
| Qwen3.5-35B-A3B | 0.66 [0.58, 0.75] | 0.27 [0.20, 0.36] |
| DeepSeek-V4.1-Flash | 0.38 [0.30, 0.47] | 0.29 [0.20, 0.37] |
| 合计 | 0.48 [0.43, 0.54]（457/944） | 0.28 |

对照组里与多数一致的比例在 Vanilla 下都至少 0.96，所以模型并不是一贯唱反调。

**两层结构几乎没有起到复核作用**：Vanilla 下对抗组 944 个 episode 里，程序主席的决定与领域主席建议一致 933 次；Obligation 下 939 次里一致 891 次，而 48 次不一致里有 28 次来自 Qwen3.5-35B-A3B 一个模型。也就是说，跟随多数是在领域主席那里发生的，然后原样穿过程序主席，**即便程序主席被明确告知「理由只是数票时要推翻」**。

Obligation 的改善也不是整体平移：939 个两种提示下都有效的「论文–模型」对里，234 个两种提示下都跟随，222 个只在 Vanilla 下跟随，26 个只在 Obligation 下跟随，457 个都不跟随。

### 是什么在拉动跟随：四组控制

对抗组同时改了分数、立场和具体性三样东西，作者用四组控制拆开：

| 控制 | Vanilla | Obligation |
| --- | --- | --- |
| 对抗 3:1 跟随率 | 0.48 | 0.28 |
| 只给论文（不看评审和 rebuttal）时与历史决定不一致的比例（参照线） | 0.31 | 0.34 |
| 超出参照线的部分 | +0.17 | −0.06 |
| 删掉所有数字分数后跟随率的变化 | −0.03 | −0.01 |
| 2:2，具体的一方支持历史决定：跟随具体方（括号内为参照） | 0.86（0.69） | 0.83（0.66） |
| 2:2，具体的一方反对历史决定：跟随具体方 | 0.51（0.31） | 0.48（0.34） |
| 多数比例 2:1 / 3:1 / 4:1 的跟随率（30 篇、4 个模型） | 0.28 / 0.53 / 0.62 | 0.24 / 0.27 / 0.37 |
| 3:1、异见者放在最前面 | 0.45 | 0.27 |

几个读法：

- **超出「自己读论文」那部分才算真被带偏**：Vanilla 下合计超出 0.17（[0.13, 0.21]），按模型从 Claude Opus 5 的 0.00 到 GLM-5.3 的 0.47；Obligation 下这个超出消失了。
- **拉力来自评审文本的立场，不来自分数**：删掉所有数字分数几乎不改变跟随。
- **票数相等时模型偏向更具体的一方**，无论那一方主张什么；但随着多数变大，跟随率一路上升（2:1 到 4:1 从 0.28 到 0.62），而异见者放在什么位置影响不大。也就是说，**票数越悬殊，越压得过模型自己对论文的判断**。

作者也说明，这些控制新生成的评审只过了机械检查（标明的分数、长度匹配），没有过盲评。

为什么要构造票数？因为在真实 3:1 分布的 119 篇上，只交换论证质量时决定几乎不动：Vanilla 下 711 个有效配对里 691 个两组完全相同（向少数翻转 12 次、向多数翻转 8 次），Obligation 下是 49 对 22。主席们与历史决定的一致率（0.76–0.78）跟它们拿到的多数的一致率（0.78）差不多，而多数通常与参照一致，所以这个设计分不清是票数还是论文在驱动。

### 核实：埋好的程序错误很少进入裁决

3,832 份裁决里有 111 份采纳了埋下的错误（2.9%，[2.0, 3.9]），远低于作者事先定的 0.20 实质失败阈值；其中 81 份来自 GLM-5.3、GLM-5.3-Flash 和 Qwen3.5-35B-A3B。作者很谨慎：低采纳率只说明有正确案卷时错误很少进入裁决，**不说明法官是去核对了案卷而不是凭记忆想起了这个案子**。

Obligation 改变的不是「采不采纳」，而是「有没有正面指出」。八个模型合计的纠正率从 Vanilla 的 0.09 升到 Obligation 的 0.25，配对增幅 0.16（[0.14, 0.18]）。Vanilla 下只有 Claude Opus 5 会经常点名律师的错误并驳回（0.53），Obligation 下升到 0.84；Sol 从 0.01 到 0.28，GLM-5.3 从 0.03 到 0.24，DeepSeek-V4.1-Flash 从较高的基础 0.10 到 0.47；Luna 和 Qwen 不动。

### 转述：限定条件被系统性地删掉

两种提示合计，1,931 条被引用的核心主张里有 759 条（0.39，[0.35, 0.44]）在报告里不带证人附加的任何一个限定，是事先阈值 0.20 的两倍。只有 Claude Opus 5 刚好在阈值上。

| 模型 | Vanilla 限定全丢比例 [95% CI] | Obligation 限定全丢比例 [95% CI] |
| --- | --- | --- |
| Claude Opus 5 | 0.20 [0.14, 0.28] | 0.20 [0.13, 0.26] |
| GPT-5.6 Sol | 0.34 [0.24, 0.45] | 0.25 [0.18, 0.33] |
| GPT-5.6 Terra | 0.44 [0.30, 0.57] | 0.26 [0.16, 0.36] |
| GPT-5.6 Luna | 0.45 [0.33, 0.58] | 0.33 [0.25, 0.42] |
| GLM-5.3 | 0.57 [0.48, 0.67] | 0.34 [0.26, 0.41] |
| GLM-5.3-Flash | 0.65 [0.56, 0.73] | 0.42 [0.33, 0.50] |
| Qwen3.5-35B-A3B | 0.60 [0.51, 0.70] | 0.61 [0.52, 0.69] |
| DeepSeek-V4.1-Flash | 0.48 [0.40, 0.56] | 0.29 [0.22, 0.35] |
| 合计 | 0.47 [0.41, 0.53] | 0.33 [0.28, 0.38] |

换成直白的话：Vanilla 下，证人自己句子里的一个样本量提醒或范围限制，在报告里变成无条件结论的频率，Opus 是五次引用里一次，GPT-5.6 各版本和 DeepSeek 是三次到两次里一次，GLM 和 Qwen 是十次里六次。

Obligation 让合计丢失率下降 0.136（[0.095, 0.179]），但引用覆盖也从 0.46 升到 0.55，所以一部分变化可能来自引了不同的主张。作者把 1,920 个证人槽位跨提示配对来拆：两种提示下都被引用的 723 条主张里，丢失率从 0.46 降到 0.33，有 139 条恢复了限定、51 条新丢了限定；同时 Obligation 多出 331 次引用、少了 154 次。**写明职责确实让限定更多地被保留，但它同时改变了引用哪些主张**，这正是摘要里「也改变了对照条件下的行为」那句话的含义。

另一个细节：Vanilla 下 251 份报告只引用了与历史参照一致的证人，164 份只引用了相反的证人，引用率差 0.091（[0.016, 0.164]）；但引用之后丢限定的条件概率（0.49 对 0.44）没有方向性。

### 人工校准

三位标注者在不知道模型、提示和机器标签的情况下，标了分层抽样的 100 份裁决、100 份报告（200 个证人槽位）和 30 条生成评审。语义层与多数标签的一致性：Court κ = 0.63，Parliament κ = 0.68（三人一致的样本上 0.75 和 0.79）；只用模式规则在 84 份 Court 裁决上只对了 3 份。两处需要保留：Court 抽样里语义层判为采纳的 15 份，多数标注只确认了 5 份，没有新增，说明分歧方向是**高估采纳**；Parliament 的丢失率按机器和按多数都是 0.47，但三位标注者各自在 0.14 到 0.85 之间，所以它适合在同一种标签读法下比较模型，不适合当绝对值。用每位标注者的标签重新加权后，Court 采纳率依然很低，两个 Obligation 效应在多数标签和三人中两人的标签下都成立。

### 2. 他们确实读了，但读了也没用

中位 episode 会打开案件目录里的每一个文件：Court 5 个、Parliament 11 个、OpenReview 12 或 13 个。单个角色中位用时从 OpenReview 里 GPT-5.6 Luna 程序主席的 10 秒到 Parliament 里 Claude Opus 5 的 240 秒。也就是说，**失败不是因为没打开材料**，而是读完之后在权衡和转述上走了捷径。这一点很重要，它排除了「工具调用不够」这个最容易的解释，也说明给 subagent 报告加「必须读完」的约束解决不了问题。

作者挑了一个困难子集（每个场景里另外六个模型失败率最高的 20 个案件），把两个模型各放进第二个 harness 重跑，提示、案件和评分都不变：

这一节样本很小，但信息很直接：**同一个模型在不同 harness 里的「上层尽职度」可能不一样，同一句职责提示在一个 harness 里有用、在另一个里几乎没用**；而你如果只跑一遍，很可能把运行间波动误认成 harness 差异。

### 4. 和 sycophancy 不是一回事

作者把 role integrity 和面向用户的 sycophancy 区分得很清楚：压力来源不同（来自下面的多数，而不是上面的委托人）、标准不同（角色义务，而不只是真实性）、拓扑不同（上层输出在下游替代了它的输入）。在他们的测试里，**事实类错误很少被采纳，而从众和限定丢失多得多**，这也和普通的「模型会附和」直觉不完全一样。

## 🤔 我的判断

定位：**测量方法 + 跨模型诊断证据**。它没有提出修复方案，提出的是一种测 manager agent 是否尽职的方式：固定案件、只改下级材料的一个属性、读上层输出的响应。

亮点三条：

- **评测对象换对了**。不再问「最终答案对不对」，而是问「下级材料变了，上层输出有没有按职责变」。这正是多 agent 系统里最难观察、又最要命的那一步，也是 subagent handback 验证一直缺的东西。
- **三种义务分开测，失败率差一个数量级**。核实（对照案卷的硬事实）几乎都能做到，权衡和转述（需要判断质量、需要保留不确定性）大面积失守。这给了一个很实用的分界：**可以对照原始记录核查的东西，上层 agent 基本能守住；需要它自己判断「谁说得更好」「哪些限定要保留」的东西，守不住。**
- **评分本身做得克制**。LLM judge 必须给原文引用并被核对，模式规则兜底，三人盲标校准，并且诚实报告了 Court 高估采纳、Parliament 标注者之间 0.14 到 0.85 的分歧。

问题与局限：

- **下级材料是固定文本，不是活的 agent**。Court 和 Parliament 没有真正的下级 agent，OpenReview 虽然两层但两层之间没有交流，澄清、反馈、迭代修订这些交互式层级依赖的东西都没测；也没有非层级的对照，所以不能把失败归因于「层级」本身。
- **构造票数同时改变了分数、立场和具体性**，虽然有四组控制，但控制组的新评审没有过盲评。
- **Court 低采纳率分不清是核对了案卷还是记得这个案子**，也不代表能扛住法律推理层面的错误。
- **Parliament 只测「被引用的主张两个限定都丢」**，不是完整证据保留；标注者之间分歧很大。
- **RI 等权平均三项**，结论依赖选了哪些任务、哪些终点和权重，跨场景差异也可能反映文档长度和任务难度。
- harness 对比只有两个模型、每场景 20 个案件，而且被运行间方差污染。

对工程的直接启发：

1. **给 orchestrator 的评测加「干预式」用例**。固定任务，只改一个 subagent 报告的质量或立场，看最终输出跟不跟着变。只评最终答案，抓不到这类问题。
2. **限定条件要结构化，不要只写在句子里**。证人的限定在自然语言里平均有一半被丢；如果 subagent 的 handback 把「适用范围、样本、置信度」做成必填字段，主 agent 汇总时再做逐字段校验，转述失败会更容易被机器发现。
3. **不要指望第二层主 agent 自动复核第一层**。程序主席 933/944 次照搬领域主席的建议，连明确告诉它要推翻数票理由都没用。要复核，就给复核者独立的输入（例如直接读原始报告而不是 meta-review）和明确的检查清单。
4. **职责提示有用但会带副作用**，它会改变对照条件下的行为、改变引用了哪些材料。上线前要同时看对照组，别只看对抗组降了多少。
5. **换 harness 或换模型时，上层尽职度要单独回归**，而且至少跑两遍，否则 harness 差异和运行间波动分不开。

一句话：上层 agent 会去核对能对照原始记录核对的事实，但面对「谁说得更有道理」和「哪些保留要原样传上去」，它更像一个数票、转述时顺手删掉限定的秘书；想让 manager 真的尽职，得把这两件事也变成可以对照记录检查的东西。
