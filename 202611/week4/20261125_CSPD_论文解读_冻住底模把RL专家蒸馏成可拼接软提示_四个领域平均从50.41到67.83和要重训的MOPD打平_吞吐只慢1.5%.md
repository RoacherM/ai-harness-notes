# 冻住底模，把 RL 专家蒸馏成可拼接的软提示：四个领域平均从 50.41 走到 67.83，和要重训的 MOPD 打平，吞吐只慢 1.5%

你有没有过这种体验：每个领域先用强化学习训出一个专家，再用权重合并或多教师蒸馏把它们收进同一个模型。新专家一来，整套巩固就要重做一遍；合并系数和路由还得重调，原来会的东西开始掉，服务端还要为每个适配器在每一层付额外计算。持续学习在这里不像一条流水线，更像每次都把整栋楼拆了再建。

这篇问的是：**能不能把新专家做成一个装得上、也拆得掉的模块，底模永远不动？** CSPD 的答案是把每个 RL 专家独立蒸馏成一段软提示，推理时直接在系统消息里拼接，不做联合训练。看完我的感受是：它把「持续后训练」从改权重，换成了在输入空间里装模块，而且在四个领域上把这个想法做到了和要重训学生的 MOPD 打平。

## 核心摘要

Composable Soft-Prompt Distillation（CSPD）在冻结的预训练后、强化学习前的底模上，把每个后训练专家蒸馏成一段 256 维向量的软提示，再用拼接来组合专家。蒸馏是序列级的：只在教师通过验证器的回答上训练提示，底模权重不动；为了让提示以后能接在别人后面，一半训练样本会在前面加一段 128 到 256 个 token 的随机前缀。23 个数学、代码和 agent 设置里，单段软提示在 22 个设置中收回了教师相对底模增益的至少 90%，15 个设置持平或超过教师。多专家实验沿用 M2RL 的设定，学生是冻结的 M2RL-SFT（从 Qwen3-4B-Base 做完 SFT），教师是指令遵循、科学、代码和数学四个 RL 专家。四个提示按到达顺序逐个加上去，四域平均从 50.41 一路升到 67.83，完整组合与 MOPD 的 67.79 持平，并超过各专家单独平均的 66.61。六个留出基准（XSTest、TruthfulQA、BFCL、TriviaQA、BBEH、FinQA）上，CSPD 均分 56.6，高于 MOPD 的 53.5。因为适配发生在输入里，不同提示的请求可以在同一条底模上批处理：单张 B200 上，软提示吞吐相对未适配底模只差 1.5% 以内，32 路并发且每路不同适配器时，是 rank-4 LoRA 的 2.40 倍。

## 🎯 为什么这件事值得写

持续后训练有一个很实际的目标函数：新专家带来的能力要进来，旧能力和通用能力不能被冲掉，而且更新成本只取决于新专家，不取决于已经装了多少个。现有两条路都不完全满足。一条把所有专家收进同一套权重：联合多任务 RL 每次都要在全部领域上重跑；顺序 RL 会把前面的增益改坏；权重合并会互相干扰；多教师在线蒸馏（MOPD）必须对着所有教师重训学生，而且会对每个请求使用同一个固定混合物，底模权重被覆盖之后，目标域之外还可能掉点。另一条把专家分开、按请求路由，路由器难训、不能在一次请求里组合专家，还得为每个专家托管完整模型；按请求合并 LoRA 能绕开一部分问题，却要在每个解码步给每一层加适配计算。

这和我们关心的几条线是对得上的。G-CAST 说 harness 每扩一批工具，旧 checkpoint 就会掉分，奖励函数也要过门；Continual-ARC 说现成 harness 不见得比只缓存示范更省；TinyAstral 则是冻住模型、进化 harness。CSPD 把「冻结」用在后训练巩固上：专家不住在权重里，住在输入里。Byron 最近把持续学习正式写进了观察清单，这篇几乎是按那张清单来的：遗忘、模块化、LoRA 之外的记忆形式、以及能不能在不重训整网的前提下继续加能力。

## 🏗️ 机制：独立蒸馏，推理时再拼接

记 p_θ0 为强化学习前的底模，p_θj 是从它训出来的第 j 个专家。软提示 P_j 是一段长度为 L、维度与词嵌入相同的向量序列，默认 L = 256，插在系统消息里、问题之前。训练目标是序列级蒸馏：先对领域问题采样教师回答，只留下通过验证器的样本，然后只更新 P_j，用长度归一化的回答 token 负对数似然。底模全程冻结。

组合之所以不是把提示随便首尾相连就完事，是因为训练时每个提示都是单独出现的，推理时却要跟在别的提示后面。作者用 prefix-robust training 处理这件事：一半样本会在提示前放一段从其他样本里抽的 128 到 256 个 token 前缀，让它习惯「前面已经有别的东西」。没有这段训练，四个提示拼起来的平均会从 67.83 掉到 64.50。

加一个专家只需要训它自己的提示，减一个专家只需要拿掉那段提示，不必重配合并系数，也不必重训路由。服务时，不同提示的请求仍然共享同一条底模，只是上下文更长一点。

多专家主实验完全复用 M2RL 的学生和教师，作者没有重训 SFT 模型和 RL 专家。四个领域分别在 AIME24、LiveCodeBench v5、GPQA-Diamond 和 IFBench 上评，温度 0.6，最大生成长度 32k，采样次数 K = 64/8/16/8。每个提示用 Muon 优化器更新 200 步，取最终 checkpoint。默认拼接顺序是 MCSI（数学、代码、科学、指令遵循），也报了反序 ISCM。

## 🧪 关键证据

### 一、单专家：23 个设置里 22 个收回至少 90% 的增益

多样性是有意设计的，覆盖数学推理、LiveCodeBench 上的代码，以及 SWE-bench Verified 这类 agent 设置。几个具体数字：

- GPT-OSS-Swallow-20B 的数学：学生 76.53，教师 90.21，提示后 89.67，收回 96.06%。
- Qwen3-Swallow-30B-A3B 数学：收回 99.79%。
- 最低的一档是 MiMo-7B 的代码，收回 88.08%，也是唯一低于 90% 的。
- 若干设置里提示后超过教师，例如 Qwen3-32B 蒸馏 DeepSWE-Preview，在 SWE-bench Verified 上从学生 24.90、教师 44.05 走到 45.65，收回 108.36%；Qwen3.6-27B 蒸馏 TMax-27B，收回 200.00%。后一类要小心读：教师相对学生的绝对增益本身很小，回收率会被放大，作者也提醒小增益会让回收比变吵，所以正文始终同时报绝对分数。

提示不必很长。在 GPT-OSS 数学的长度扫描里，2、8、32 个向量分别收回 51.23%、74.11%、90.01%，256 和 512 是 93.10% 和 87.83%。大部分收益在 32 个向量时就已经到了。验证器过滤也不是严格必需：混入错误回答会把回收从 96.06% 降到 90.54%，仍然可用，但正确-only 更好。

### 二、四个提示拼起来，和 MOPD 打平

Table 2 的四域平均（AIME24 / LCB v5 / GPQA-D / IFBench）：

| 方法 | 平均 | 相对专家增益的回收 |
| --- | --- | --- |
| 学生（无提示） | 50.41 | 0.0 |
| 单域专家（oracle 路由） | 66.61 | 100.0 |
| 权重合并 TIES | 67.47 | 105.2 |
| MOPD | 67.79 | 107.2 |
| 单域软提示平均 | 65.38 | 92.4 |
| CSPD，不做前缀鲁棒训练 | 64.50 | 87.0 |
| CSPD（ISCM） | 67.72 | 106.8 |
| CSPD（MCSI） | 67.83 | 107.5 |

组合以后，GPQA-Diamond 从单域提示的 49.24 升到 57.77，IFBench 从 66.71 升到 68.42，AIME24 则从 80.89 微降到 80.47。也就是说，模块可以在自己的训练域之外做正贡献，但不是每个域都被均匀抬高。CSPD 在 GPQA-Diamond 和 IFBench 上高于 MOPD，MOPD 在 AIME24 和 LiveCodeBench 上更好。整体已经和在权重空间做巩固打平，而每个专家仍然是独立训出来的模块。

### 三、持续加专家：平均每次都在涨，但域间有干扰

从无提示学生出发，按指令遵循、科学、代码、数学的顺序把新提示放到最前面，四域平均依次为 50.41、60.99、61.67、63.67、67.83，最终超过专家单独平均的 66.61，中间没有重训任何已有模块。单个域会上下波动：加上代码后 IFBench 从 66.71 降到 64.58，再加数学又升到 68.42。

从完整的 MCSI 里一次拿掉一个提示，每个模块对自己的域和四域平均都是正贡献。拿掉数学平均掉 4.16 分，其中 GPQA-Diamond 掉 6.54 分；拿掉指令遵循，IFBench 掉 12.88 分。负交互也存在：拿掉数学，LiveCodeBench 反而升 1.87 分。

一个很有信息量的对照是 Progressive Prompts：每个新提示在前面那些已经冻结的提示之后训练，按理说更适应最终组合。结果却全程落后于独立训练，三阶段平均是 56.44、58.28、65.17，对上独立训练的 61.67、63.67、67.83，而且最早装上的指令遵循能力被侵蚀，IFBench 一度掉到 50.88。独立训练反而更简单，也好用。和 TIES 权重合并比，独立提示也全程更高；IF 专家单独就会把 LiveCodeBench 从学生的 58.61 压到 52.69，合并科学专家之后还停在 52.54。改权重去迁就一个域，会伤害另一个域。独立提示不改底模，这两个阶段的 LiveCodeBench 仍是 62.57 和 60.55。

### 四、留出域和推理成本

六个留出基准上，CSPD 均分 56.6（相对学生 +6.4），MOPD 是 53.5（+3.3）。CSPD 在六个里的四个领先，其中 BFCL 工具调用 55.6（+8.0），XSTest 88.2（+7.8），FinQA 72.5（+6.2）。TruthfulQA 上它是 64.2，相对学生微降 0.4，但 MOPD 在这题掉了 3.6。

服务实验用 GPT-OSS-20B、BF16、单张 B200、SGLang。软提示只是把上下文加长 256 个位置，在七个并发水平上吞吐都在未适配底模的 1.5% 以内；32 路请求、每路不同适配器时，输出吞吐是未合并 rank-4 LoRA 的 2.40 倍。256 个向量对隐藏维度 2880 的模型大约是 73 万参数，和一层量级的小适配器相当，却不用在每个解码步改每一层。

## 🔬 最有意思的部分

最有意思的不是和 MOPD 打平，而是作者去看这段软提示到底学到了什么。在 GPT-OSS 数学专家上，软提示收掉了教师与学生之间 KL 差距的 86.8%，主要是让学生去检查中间结果；同样意图的书面指令最多只收掉 2.1%。提示学的是行为，不是一段可以换成人话的说明。这对「再写清楚一点 system prompt 就行」是一盆很有用的冷水：连续向量能改的，不一定能被自然语言复述出来。

另一处是独立训练优于渐进训练。直觉上，新模块应该看见已经装上的旧模块，才能学会共处。这里恰好相反：为某个特定组合去拟合新模块，既不能更好地联合使用，也不能靠冻结旧提示保住旧行为。这很像技能库里「对着当前技能清单微调下一张卡」不一定比「各自写好、用时再组合」更稳。前缀鲁棒训练提供的，只是让模块对「前面有东西」不那么脆弱，而不是让它绑定某一组邻居。

回收率超过 100% 的那些 agent / 代码设置也值得单独记一笔。DeepSWE、TMax 这类教师，有的绝对增益并不大，提示后略超教师，可能是蒸馏把输出分布收得更稳，也可能是评测噪声。作者把单专家表里的最优 checkpoint 选在了评价基准上，这些数字更像探索，不是严格的留出估计。真正压得住的，还是四域组合、持续加模块和六个留出基准那一组用最终 checkpoint 报的结果。

## 🤔 我的判断

这是一篇**面向持续后训练的方法论文**，同时把服务成本算进了主叙事。亮点有三条。第一，冻结底模、独立蒸馏、拼接组合，把「加专家」的成本从重训整网收成训一段提示，并且在四个领域上走到了和 MOPD 持平。第二，持续加入时平均每次都在涨，权重合并里那种典型遗忘（IF 专家伤害代码）在输入空间里被避开了。第三，留出域和服务开销都没有略过，软提示比「再挂一组 LoRA」更像能上线的模块形态。

局限作者写得很清楚。组合实验只有一条 Qwen3-4B 衍生底模和四个领域，专家数量再往上、领域关系更复杂时，拼接还能否继续涨，仍是开放问题；专家之间既有正迁移也有负干扰。单专家表和部分合并系数是在评价基准上选的，小增益会让回收比不稳定。每个提示要占 256 个上下文位置，注意力和 KV-cache 会随专家数增加；提示还绑在特定底模上，换骨干就要重新蒸馏，而且训练需要 RL 教师的监督。XSTest 也只覆盖了拒答行为。此外，主实验还没有解决「每次请求该用哪几个提示」——现在是按领域手工选择或全部拼上。

对工程的直接启发是：如果你已经在用多专家 RL 再合并，可以先把「巩固」从改权重改成装输入模块，尤其是在服务端要混跑不同专家、又不能接受 LoRA 那样的逐层开销时。对做 agent harness 的人，软提示库很像技能库的连续版本：独立写成模块、用时组合、加新的不必重写旧的。但不要把它理解成「一段自然语言技能卡」——它改的是行为分布，而且换模型就要重蒸馏。下一步最缺的，是自动选择该激活哪些提示，以及把提示做短，好让库可以继续长大。

一句话收束：持续后训练不必每次都改建整座模型，先把新能力做成一段插得上的软提示，往往就够用了。
