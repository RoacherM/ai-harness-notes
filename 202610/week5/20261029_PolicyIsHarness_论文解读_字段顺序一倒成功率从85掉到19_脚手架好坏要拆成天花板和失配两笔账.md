# 字段顺序一倒，成功率从 85% 掉到 19%：脚手架好坏要拆成「天花板」和「失配」两笔账

你有没有过这种体验：给 agent 换了一个明明更强的 harness，加了批量操作、加了校验工具、把 prompt 写得更周到，结果拿手头这个微调过的模型一跑，分数反而掉了。于是你把改动回滚，心想「新 harness 不行」。或者更离谱的：只是把 observation 里 JSON 字段的顺序调了一下，内容一个字没改，模型就开始乱点。

这背后是一个大家默认但很少拆开的假设：**用一个已经训好的模型去比较两个 harness，比出来的就是 harness 本身的好坏。** 自动化 harness 搜索、自进化脚手架、我们这一个月归档的 RSI 系列，几乎都是「固定模型、换 harness、看分数」这个套路。

港科大（广州）的 **Your Policy Is Secretly a Harness: The Decision Geometry of Agent Interfaces**（arXiv:2610.37255）把这个假设拆成了一个恒等式：**部署回报 = harness 的天花板 − 模型的失配**。训练只能动失配，换 harness 会同时动两项，所以冻结模型比 harness，比出来的是两件事的混合物。看完我的感受：这篇是我这一阵读到最适合拿来给「harness 进化」做体检的理论工具，而且它在 Terminal-Bench Lite 上把 Pi coding-agent、Terminus-2、mini-SWE-agent 这些真实脚手架也放进来量了一遍。

## 核心摘要

作者把 harness 形式化为一个接口（编码器、解码器、执行器三元组），它和任务环境一起诱导出一个定义在「语义动作」上的 KL 正则控制问题。在这个框架下，最优策略是动作分数的 softmax，分数等于动作的长期价值加上参考策略的对数概率，所以**一个被训到最优的策略的对数几率，恰好还原了它的训练 harness 对每个动作的相对偏好**，这就是标题里「策略其实就是 harness」的意思。再借用正则化 MDP 的性能差恒等式，部署回报精确等于天花板 C（这个 harness 下任何策略能达到的最好回报）减去失配 M（策略偏离最优、沿自己的轨迹累积的 KL）。实验分三层：在 MiniWoB++ 三类任务、六个 harness 上用 Qwen3.5-2B 做精确策略梯度后训练，几何误差下降 69% 到 90%，且每个部署 harness 下误差最低的都是在它下面训出来的 checkpoint；把 H0 训好的模型 observation 字段倒序，最优决策完全不变，成功率却从 85.0% 掉到 19.2%；加了批量点击的 H1 天花板只高 0.012，冻结模型的失配却涨了 0.123，回报掉 0.110，但在 H1 下继续训 1,024 步后，成功率 88.17%，超过原 checkpoint 在 H0 下的 85.05%。在 30 个有序 harness 互换里，冻结比较会拒绝 22 个，其中 9 个有正的恢复阈值，提升天花板的 7 个经过适应后全部超过原组合；事先算出的 T − r₂ 对收益的 Spearman 排序相关是 0.95，冻结回报变化只有 0.17。最后在 Terminal-Bench Lite 上，用 GPT-5.6-luna 当最优策略的替身，五个 coding harness 的 C̃ − M̃ 排序和真实准确率完全一致（Spearman 1.0），单看天花板或单看失配都只有 0.7。

## 🎯 为什么这件事值得写

过去一个多月，这个仓库里归档了一长串「harness 和权重谁该动」的论文：Harness-Zero 把专用 harness 的行为烤进权重，CoEvo-RSI 说脚手架进化了模型没跟上，HarnessAdapt-RL 让工具和 hook 跟着策略一起进化，HarnessScaling 和 IQuest-Q1 说只在一套脚手架里练 RL 会偏科。它们各自给了方法和现象，但一直缺一个共同的记账方式：**一次 harness 改动到底是让「能拿到的分」变多了，还是让「这个模型拿到的分」变多了？**

作者指出的问题很具体。自动化 harness 设计（ADAS、AFlow、Promptbreeder、Darwin Gödel Machine 一类）都用「固定模型在候选 harness 下的表现」给候选打分。这个打分默认模型在旧 harness 下学到的东西能原样带到新 harness。但 GUI-360 的观察已经说明，同一个接口改动可以让 GPT-4o 涨、让微调过的 Qwen 掉。如果模型的偏好本身就是绑定在训练 harness 上的，那冻结比较就会系统性地拒绝一类「其实更好、只是模型还没适应」的 harness。

所以论文问的是两个问题：**策略从它的 harness 里学到了什么？harness 一换，还剩下什么？**

## 🏗️ 机制：语义控制问题、动作分数、天花板减失配

**1. 把 harness 写成接口。** 接口 I = (c, d, e)：c 把语义状态编码成上下文，d 把模型输出解码成语义动作，e 执行动作。token 策略通过它诱导出语义策略：

$$\Pi_{\theta,\mathcal{I}}(a\mid s)=\sum_{y:\,d_{\mathcal{I}}(y;s)=a}\pi_{\theta}(y\mid c_{\mathcal{I}}(s))$$

c 和 d 都在式子里，所以**权重固定不等于语义策略固定**。重试、校验、子代理调用都算独立的决策步，controller 的记忆和剩余预算都算进状态。

**2. 最优策略编码相对动作分数。** KL 正则下最优策略是 Gibbs 形式，定义最优动作分数：

$$F^{*}_{\mathcal{I}}(s,a)=Q^{*}_{\mathcal{I}}(s,a)+\tau\log\pi^{\mathrm{ref}}_{\mathcal{I}}(a\mid s),\qquad \Pi^{*}_{\mathcal{I}}=\operatorname{softmax}(F^{*}_{\mathcal{I}}/\tau)$$

命题 3.1：两个接口最优决策等价，当且仅当它们的分数场只差一个按状态的常数；一个在训练接口下处处最优的 checkpoint，其 τ 倍对数几率恰好等于两个动作的分数差。也就是说，策略能带走 harness 诱导出的**决策**，但带不走 harness 的代码、工具，也带不走绝对价值（所有奖励加同一个常数不改变任何决策）。

**3. harness 一换，分数误差拆成三块。** 训练接口 1、部署接口 2：

| 项 | 含义 |
| --- | --- |
| 目标漂移 g₁₂ | 最优分数本身变了，即哪些动作该选变了 |
| 训练残差 e₁ | 在接口 1 下就没训到最优的那部分 |
| 读出漂移 η₁₂ | 同一份权重透过新接口表达出来的偏好变了 |

三者是向量，可以叠加也可以抵消。只改呈现、不改执行的变换，g₁₂ = 0，能单独量出读出漂移。

**4. 天花板减失配。** 性能差恒等式给出：

$$J_{\mathcal{I}}(\Pi_{\theta,\mathcal{I}})=C(\mathcal{I})-M(\theta,\mathcal{I}),\qquad M=\frac{\tau}{1-\gamma}\mathbb{E}_{d^{\Pi}}\mathrm{KL}(\Pi_{\theta,\mathcal{I}}\,\|\,\Pi^{*}_{\mathcal{I}})$$

C 只取决于 harness 和目标，不依赖权重；M 依赖 harness 和 checkpoint，并按策略自己的占用分布加权，所以常走路径上的错误最贵。由此有一个很实用的推论（推论 5.2）：一次 harness 修订让冻结模型变差，但适应后的新组合能超过原组合，当且仅当

$$M(\theta_1,\mathcal{I}_2)<T=\Delta C+M(\theta_0,\mathcal{I}_1)$$

翻成人话：**适应后在新 harness 下剩下的失配，要小于天花板的增量加上原组合本来就有的失配。** 如果 T ≤ 0，新 harness 下任何策略都不可能超过原组合，因为失配不会是负的，可以直接不试。

**5. 部署时怎么量失配。** 两条路：一是从 pilot rollout 里按 (1−γ)γᵗ 随机停，得到占用分布上的状态样本，每个状态采 N 个动作估计 KL；二是只用一部分动作对的对数几率还原中心化分数，用命题 6.1 的上界 M ≤ ε²/(4τ(1−γ)) 去卡。上界一旦低于阈值 T，就能保证适应划算。

## 🧪 关键证据

**受控实验设置。** MiniWoB++ 三类任务（click-checkboxes、click-checkboxes-soft、ascending-numbers），每个 harness 诱导的控制问题被编译成有限图，可以精确算最优策略、天花板和失配。六个 harness：

| ID | 改动 |
| --- | --- |
| H0 | 每步一个原生动作 |
| H1 | 增加任意两次点击的批量动作 |
| H2 | 提交类动作执行前自动检查 |
| H3 | 可选的程序校验工具 |
| H4 | 可选的冻结 Qwen3.5-2B 审核员 |
| H5 | 动作和动态同 H0，只加系统指令 |

模型 Qwen3.5-2B，LoRA rank 16，精确策略梯度，τ = 0.1，γ = 0.95，每个 harness 1,024 次更新，冻结基座作参考策略。

**后训练让偏好绑定到训练 harness。** 六个 harness 下几何误差都从初始化下降 69% 到 90%，在不参与更新的 held-out 任务上下降幅度和训练任务几乎一样（差不到一个百分点）。把六个最终 checkpoint 放到六个部署 harness 下，每一列误差最低的都是在该 harness 下训出来的那个。

**最优决策不变，行为大变。** H0 训好的 checkpoint，只改呈现：

| 呈现方式 | 首选动作变化的状态比例 | 失配 M | 回报 J | 成功率 |
| --- | --- | --- | --- | --- |
| 原样 | 0.0% | 0.015 | 0.423 | 85.0% |
| 字段倒序 | 52.0% | 0.484 | −0.046 | 19.2% |
| 动作菜单改成列表 | 9.2% | 0.023 | 0.415 | 86.0% |
| 动作编码平移 | 27.7% | 0.148 | 0.289 | 57.1% |
| 动作编码倒序 | 30.0% | 0.130 | 0.308 | 68.2% |
| 动作编码随机置换 | 25.3% | 0.110 | 0.328 | 67.6% |

作者做了数值核对：各变体之间天花板最大差 2.2×10⁻¹⁶，最优动作概率最大差 8.3×10⁻¹⁶。所以这里掉的分**全部来自读出漂移**，不是 prompt 格式让任务变难了。

**批量点击：先伤后补。** H0 → H1 的配对比较（95% 区间）：

| 量 | 数值 |
| --- | --- |
| 天花板增量 ΔC | 0.01248 [0.00698, 0.01754] |
| 冻结失配增量 | 0.12252 [0.11487, 0.12961] |
| 冻结回报变化 | −0.11004 |
| 恢复阈值 T | 0.02733 |
| 最终恢复差（适应后 H1 对原 H0 组合） | 0.00844 [0.00135, 0.01447] |
| 对 H0 继续训练的增益 | 0.00840 [0.00254, 0.01411] |

成功率层面：原 checkpoint 在 H0 下 85.05%，直接搬到 H1 掉到 72.90%；在 H0 下再训 1,024 步是 83.37%；在 H1 下适应 1,024 步是 88.17%。有意思的是适应过程中 checkpoint 在 H0 下的回报是下降的（A₁ = −0.036），所以两个 harness 的排序先翻转，后来才真正超过原组合。

**九个被冻结比较拒绝的互换。** 30 个有序互换里，冻结比较拒绝 22 个，其中 13 个 T ≤ 0（包括从 H5 出发的全部 5 个），剩下 9 个。适应后，提升天花板的 7 个全部超过原组合，降低天花板的 2 个（H4 → H3、H1 → H0）没有收益。7 个里有 3 个是换到 H5，也就是**只改指令、不改任何动作的 harness，也能通过它诱导的参考策略抬高天花板**。H0 → H5 比在 H0 下继续训练多 0.085 [0.078, 0.092]。

事前预测：用 T − r₂（r₂ 是直接在目标 harness 下后训练的 checkpoint 的失配）预测收益，在提前登记的 8 个互换上符号全对，Spearman ρ = 0.95；只看天花板增量 ρ = 0.86；冻结回报变化 ρ = 0.17。适应后目标失配从 0.015 到 0.146 之间降到最多 0.019。

**采样估计够不够用。** 部署时只能拿到采样动作。已知最优时，大幅变化（点击可靠性、点击成本、呈现方式）上减去采样失配能把预测误差降约一百倍，和直接频率 rollout 差不多；在决定适应值不值的小差值（百分之几的回报）上，基于失配的预测比频率 rollout 准约十倍，排序翻转点预测在同一个 checkpoint，恢复点晚一个保存点。

**真实 coding harness。** 冻结 Qwen3.5-9B（开 thinking），五个原生配置，Terminal-Bench Lite 39 题、每个 harness 跑三次：

| Harness | 每条轨迹决策数 | C̃ | M̃ | C̃ − M̃ | 准确率 |
| --- | --- | --- | --- | --- | --- |
| Terminus-2 | 4.9 | 0.431 | 0.134 | 0.297 | 64.1 ± 5.1 |
| mini-SWE-agent | 8.6 | 0.631 | 0.335 | 0.296 | 59.8 ± 7.8 |
| DeepSeek Harness | 8.6 | 0.590 | 0.382 | 0.208 | 54.7 ± 3.9 |
| Pi coding-agent | 6.6 | 0.383 | 0.206 | 0.177 | 51.3 ± 2.6 |
| DeepAgents | 14.2 | 0.261 | 0.429 | −0.168 | 47.9 ± 3.9 |

同一个模型，harness 就能把准确率从 47.9% 拉到 64.1%。只看天花板会把 mini-SWE-agent 排第一，只看失配会把 Pi 排第二，两者相减才和准确率完全同序。

诚实泼冷水：

- **coding harness 的估计只用了三道探针题**（acl-permissions-inheritance、analyze-access-logs、bank-trans-filter），每个 harness 目标和老师各 3 条轨迹，有的 harness 只有 6 到 8 条完整轨迹进入估计。五个点做 Spearman 1.0，统计上非常薄；Terminus-2 和 mini-SWE-agent 的 C̃ − M̃ 只差 0.001，准确率区间也重叠。
- 动作被压成 13 个粗类别（inspect、modify、run、plan、delegate 等），不同参数、不同效果的动作被合并，比的是类别层面的决策。老师 GPT-5.6-luna 也不是最优策略，C̃ 只是天花板的一个下界估计，M̃ 量的是到老师的距离。
- 受控实验是 2B 模型、三类 MiniWoB++ 任务、单 token 动作菜单、精确策略梯度，和真实的 RL 后训练（采样、长输出、开放动作空间）差距很大。适应后的收益本身也小，H0 → H1 最终恢复差只有 0.008 的回报、3.1 个点的成功率。
- 理论建立在 KL 正则控制和固定参考策略上，真实后训练里参考策略、奖励尺度未必满足这些前提。

## 🔬 最有意思的部分

**一是「只改指令」也算改天花板。** 直觉上 H5 只是多写了几句系统提示，动作、执行、预算都没变，应该只影响模型「读得懂读不懂」，属于失配那一侧。但在这个框架里参考策略是「冻结基座读同一份 prompt 的分布」，prompt 变了，参考策略变了，KL 正则目标下的最优回报也就变了。所以 3 个最好的互换里有 2 个是换到 H5，而从 H5 换出去的 5 个互换 T 全是负的。这对写 SKILL.md、写系统提示的人是个提醒：**你改的那几句话，在训练意义上是在改问题本身，而不只是改说明书。**

**二是失配会随决策数累积。** DeepAgents 的每步失配和 Terminus-2 差不多，但目标模型在它下面平均要做 14.2 次调用，Terminus-2 只要 4.9 次，累积起来 DeepAgents 的失配最大、准确率最低。DeepSeek Harness 则是每步失配最大，老师在它下面规划（plan）的比例是 26.5%，目标模型只有 15.1%，目标模型反而更爱 inspect。五个 harness 下目标模型都比老师更爱 inspect、更少主动 stop（Terminus-2 除外）。这给了一个很具体的诊断维度：**一个 harness 让小模型多做的那些决策，是不是它最不擅长的那类决策。**

**三是排序翻转不等于净收益。** 从 H1 适应回 H0 之后，checkpoint 已经更偏好 H0（差 0.041），但它仍然没回到原来 H1 组合的水平。论文把「恢复」（适应后组合对原组合）、「排序」（同一 checkpoint 下两个 harness 谁好）、「对继续训练的增益」三个比较分得很清楚。很多 harness 进化工作报告的其实只是第二个。

## 🤔 我的判断

**定位：测量基础设施加理论框架。** 它不提出新的 harness，也不提出新的训练算法，而是给「harness 进化」和「harness 与权重联合优化」提供了一套可以分账的度量。

亮点：

1. **一个恒等式把两类改进分开。** 天花板只看 harness，失配看 harness 和权重的配合。以后看任何「新 harness 涨了 X 点」的论文，都可以问一句：涨的是天花板还是失配？冻结比较里掉的分，是 harness 不行，还是模型没适应？
2. **给了一个可以提前算的门槛。** T ≤ 0 的互换不用试；T > 0 的，用目标 harness 下后训练 checkpoint 的失配 r₂ 就能事先估收益，排序相关 0.95。对做 harness 搜索加 RL 的团队，这是一个能省大量 rollout 预算的过滤器。
3. **把「prompt 敏感性」变成了可认证的读出漂移。** 以前说模型对格式敏感，总有人反驳是格式让任务变难了。这里控制问题证明了最优策略不变，85% 到 19% 全是读出问题。

问题与局限：

- 真实 coding harness 那一节是概念验证级别的证据，3 道题、5 个点、粗粒度动作类别、非最优老师，结论方向可信，数字不宜外推。
- 受控实验的适应收益很小，加上 2B 模型和精确梯度，离「在真实 harness 上 RL 一下就能翻盘」还有距离。
- 框架没有讨论多 harness 混训。HarnessScaling、IQuest-Q1 那条线的做法是同时在很多 harness 下训，这时候「训练 harness 的偏好」是什么、读出漂移会不会被平均掉，论文没有覆盖。

对工程的直接启发：

- **评测 harness 改动时至少报两组数：冻结模型的分，和在新 harness 下短训一轮后的分。** 只报前者，会系统性地错杀那些提升天花板的改动，比如批量动作、校验工具。
- **observation 和工具菜单的序列化格式要当作训练契约冻结。** 字段顺序、动作编码、列表还是字典，都会产生读出漂移。harness 升级时如果要改格式，要么同时改训练数据，要么做格式不变的兼容层。这和我们之前关注的固定 system prompt 保 prefix cache、协议化上下文压缩是同一种纪律。
- **给小模型配 harness，要看决策数而不只看功能。** 同一个 9B 模型，要它做 14 次决策的 harness 输给只要 5 次的 harness。如果你的 harness 会频繁派生子调用、摘要、重试，每一次都在累积失配。

一句话收束：**冻结模型比 harness，比出来的是 harness 和这份权重的默契；想知道 harness 本身值多少，得把天花板和失配分开记账。**
