# 录一遍人类操作就能写成 SKILL.md：按需翻证据，比流水线解析更好用

你有没有过这种体验：让 computer-use agent 去「把报销提交了」，它其实点得很溜，可就是不知道你们公司用哪个内部门户、要附哪几张票、提交前要核对什么。这些**组织特有的流程知识**从来不写在任务指令里，只存在于老员工的手上。最自然的办法是让人演示一遍，可录屏只告诉你「在 (812, 344) 点了一下」，**那个位置到底是什么控件？哪些步骤是规则，哪些只是这一次的具体数值？**

上海交大、复旦、南洋理工、浙大与上海奇绩智峰这篇 **Work2Skill**（arXiv:2610.12984）做了一整套方案：WorkRecorder 同步录屏、鼠标键盘事件和可用的无障碍树（AX）信息；用它构建了 WorkDemo-350，350 条经过完整性与成功率筛查的人类桌面演示；再让一个技能归纳 agent 按需翻查证据，写出符合 Agent Skills 规范的 SKILL.md。在四个执行模型上，相比不用技能，MyPCBench 平均分涨 4.67 到 10.54 分，OSWorld-Verified 子集涨 3.11 到 7.50 分，并且全面超过 ShowUI-Aloha 与 Demo2Tutorial。看完我的感受：这是 OpenAI Record & Replay、Claude「Record a skill」这类产品功能背后，第一个能拿来做方法对比的公开数据与评测协议。

## 核心摘要

Work2Skill 由三部分组成。**WorkRecorder**：把屏幕录像、输入事件、动作触发的关键帧、AX 元素名称与角色按时间戳对齐，解决「坐标不等于语义」的问题。**WorkDemo-350**：覆盖 64 个 MyPCBench Bounded Action 任务与 286 个 OSWorld-Verified 任务，每条演示都筛过完整性和任务成功，并打包同步的视觉、动作与 AX 证据，让不同归纳方法第一次能在同一批演示和同一套评测下比较。**Agentic Skill Induction**：归纳 agent 与证据检查、技能写作在同一会话里交替进行，可用 list_directory、read_file、read_visual_evidence、watch_video、extract_video_frames 等工具按需取证；写作策略要求把演示中的具体输入泛化为任务相关描述，用语义描述 UI 目标，并保留选择规则、计算、依赖、范围、停止条件、可见的完成检查和恢复路径；最后 finalize_extraction 校验结构与必要的工具调用。评测时技能作为 `<task skills>` 块追加到执行器系统提示末尾，执行时看不到原始录像。主结果：GPT-5.5 在 MyPCBench 上从 74.73 分 / 23.44% 成功率涨到 85.27 / 48.44%；换到参数或约束改变的 Jitter 变体，仍涨 3.93 到 8.64 分；GPT-5.5 写的技能交给 Qwen3.5-9B 执行也有效。

## 🎯 为什么这件事值得写

人类演示是 GUI 技能最直接的来源，因为人和 agent 共享同一个交互空间。已有工作各有短板：

| 方法 | 证据 | 问题 |
| --- | --- | --- |
| ShowUI-Aloha | 全屏帧 + 目标裁剪 | 无 AX，控件语义全靠视觉 grounding |
| Demo2Tutorial | 前后截图 | 选帧会漏掉瞬态和中间操作 |
| 两者共同 | 固定解析顺序的流水线 | 证据检查与预设阶段耦合；整段录像塞进上下文压力大 |
| 不同论文之间 | 各用各的演示和协议 | 结果混杂了归纳方法与数据、评测差异 |

对 skills 工程来说，Work2Skill 回答了两个实际问题：从演示到 SKILL.md 应该看哪些证据，以及谁来决定看什么。它的答案是证据尽量全、顺序交给 agent。

## 🏗️ 机制：对齐证据 + 主动取证 + 规范化技能

**证据链。** 每一步都关联截图、动作类型、输入内容与 AX 信息。例如「把三月食物预算改成 450 并保存」被还原成：点击单元格 B3（AX：Cell Selected）→ 输入「450」（AX：Value=450）→ Ctrl+S（AX：当前应用）。

**主动取证。** 提示词只要求必看初始、关键与终态图像，其余检查顺序与粒度由 agent 自己决定；工具引导「先粗采样视频，再细看相关动作」。草稿写完可以回头翻证据补依赖与完成检查。证据仍无法消除的不确定，必须写成可观测的条件检查，或在技能里明确标注限制。

**技能规范。** 每个连贯能力一个 SKILL.md，YAML 头含 name 与 description；共享状态或有顺序要求的阶段放在一起；技能必须脱离原始录像也能执行。finalize_extraction 记录技能哈希、检查过的源路径与运行溯源，但它只验结构与工具使用，不验正确性。

## 🧪 关键证据

**主结果（Table 2，MyPCBench，N=64）。**

| 执行模型 | No Skill 分数 / SR | 最强基线分数 | Work2Skill 分数 / SR |
| --- | --- | --- | --- |
| GPT-5.5 | 74.73 / 23.44% | 77.48（Aloha） | 85.27 / 48.44% |
| Opus-4.8 | 81.53 / 42.19% | 81.28（D2T） | 86.20 / 50.00% |
| Qwen3.5-35B-A3B | 38.38 / 9.38% | 40.61（D2T） | 44.56 / 20.31% |
| Qwen3.5-9B | 24.27 / 6.25% | 27.75（D2T） | 34.11 / 12.50% |

OSWorld-Verified 子集（N=286）上，GPT-5.5 从 74.47 到 81.97，Opus-4.8 从 79.23 到 82.34；相比更强基线领先 1.65 到 6.96 分。执行步数的变化取决于模型：Opus 和两个 Qwen 步数更少，GPT-5.5 反而更多；归纳 token 也不总是比基线少，GPT-5.5 在 MyPCBench 上每任务约 33 万 token，约为基线的两倍。

**换需求复用（MyPCBench Jitter，64 个改了实体、参数或约束的配对变体）。** 不重新归纳，直接复用原技能：分数涨 3.93 到 8.64，成功率涨 6.25 到 9.38 个百分点，步数减少 2.49 到 5.44。

**跨模型迁移。** GPT-5.5 写、Qwen3.5-9B 执行：36.66 分（比该执行器 No Skill 涨 12.39）；Qwen3.5-9B 写、GPT-5.5 执行：75.81 分（只涨 1.08）。强模型写的技能对两种执行器都更好，但再好的技能也补不上执行器之间的差距。

**证据消融（GPT-5.5，MyPCBench）。** 完整证据 85.27 / 48.44%；去掉索引图像、UI 标注或按键日志，分数掉 5.02 到 10.63，成功率掉 14.06 到 21.88 个百分点。只给「带 UI 语义的动作文本」好于只给视频，且步数最少，但两者都不如完整证据。

**主动取证对比固定流水线。** 只换系统提示，从规定阶段顺序改成 agent 自主探索：分数 +3.97，成功率 +6.25 个百分点，归纳 token 多 12.7%。

**泼冷水。** 主实验是在**被演示的同一任务**上评测，技能本质上在指导一个它见过解法的任务，涨分里有不少是「抄演示」；Jitter 才是真泛化，涨幅也确实更小。每个任务只有一条演示；OSWorld 用的是筛选后的子集；技能正确性没有独立验证，只靠下游执行结果。

## 🔬 最有意思的部分

1. **按键日志对成功率影响最大。** 去掉 KeyLogs 后成功率掉得最多：很多「完成条件」藏在输入的具体值和快捷键里，光看画面看不出来。
2. **动作文本 + UI 语义已经很能打。** 不看视频、只看结构化动作描述，分数仍然不差，步数最少。对于成本敏感的场景，这是个很实用的折中。
3. **让 agent 自己决定看什么，比规定流程强。** 这和 [Learn2Play](./20261009_Learn2Play_论文解读_经验别急着蒸馏成规则_原始轨迹加好harness才学得会陌生规则.md) 里 OpenCode 优于固定步骤自进化方法、以及 [MetaSkill](../week1/20261002_MetaSkill_论文解读_别把技能塞给Target_教Builder学元技能才配得动harness.md) 教 Builder 学元技能是同一个方向：把流程决策交还给模型。
4. **不确定就写成检查。** 证据无法确认的步骤，必须变成「执行时可观测的条件判断」，这比假装知道答案更安全，也是写技能的好习惯。
5. **技能作为纯文本插件。** 统一 `<task skills>` 包装、只改追加内容，执行循环不动，使得同一技能可以跨执行模型、跨 harness 复用。

## 🤔 我的判断

定位：**从人类演示归纳 GUI 技能的数据集 + 方法 + 评测协议**，测量基础设施与方法改进并重。

亮点三条：

1. WorkRecorder 把录屏、输入事件与 AX 对齐，解决了演示到技能最难的「坐标没有语义」问题；
2. WorkDemo-350 + 统一注入协议，让演示归纳方法第一次可以在同一批数据、同一套评测下比较；
3. 主动取证 + 规范化 SKILL.md 写作策略，在四个执行器、两个基准、换需求和跨模型场景下都有一致收益。

问题与局限：主评测是同任务复现，泛化证据主要靠 Jitter；单演示归纳，没有研究多条演示合并与冲突；AX 在很多应用里缺失或不准；归纳成本对强模型偏高；没有与「执行后自我修订技能」的方法组合。

对工程的直接启发：**(1)** 做「录一遍就生成技能」功能时，一定要同时采集输入事件与 AX，别只存视频；**(2)** 技能里写清选择规则、依赖、停止条件和可见完成检查，并把演示里的具体值泛化掉，这几项决定了 Jitter 场景能不能复用；**(3)** 用强模型归纳、弱模型执行是可行的部署组合；**(4)** 评测技能时至少做一组「换参数」变体，否则分数里混着抄演示；**(5)** 可以和 [Skill-Use](../week1/20261002_Skill-Use_论文解读_技能挂上了不等于会用_Trigger合规边界才测真使用.md) 式的过程评测配合，检查执行器是否真的按技能走。

一句话收束：**Work2Skill 证明，人类的一次 GUI 演示只要证据对齐、让 agent 按需翻看，就能写成脱离录像也能用的 SKILL.md，野心是把组织里的隐性流程直接变成 agent 的技能库。**
