# 相关不等于适用：检索来的经验第一步就花光了，每一屏重新激活才让个人 GUI 助理记得住你

你有没有过这种体验：给手机助理说一句「帮我点平常那杯咖啡」，它确实翻出了你上周的点单记录，第一步也准确打开了那个 App；可进了菜单页、规格页、结算页，它就开始乱点，仿佛那段记录从没给过它。更尴尬的是主动推荐：早上八点在家推咖啡挺贴心，晚上通勤路上再推一遍就成了打扰。

行业里把这类能力叫 **personal GUI agent / personalized memory**，主流做法是把「和任务相关的历史」检索出来，整段塞进 policy 的上下文。NTU 与阿里这篇 **ExpActivator**（arXiv:2609.33304）先做了一个很扎心的诊断：**检索来的历史几乎只在第一步有用，后面 90% 的步骤和没给历史一样。** 问题不在「找得准不准」，而在 **相关（relevance）是任务级的，适用（applicability）是决策时刻级的**。看完我的感受：这是一篇把「记忆该在哪一刻生效」讲透的小而硬的工作，对任何做 agent memory / 经验复用 harness 的人都是一记提醒：经验别只「挂上去」，要「每一步重新选」。

## 核心摘要

ExpActivator 把个性化重新表述为 **experience activation**：检索只负责把历史缩小到相关候选，真正决定用哪条经验的是当前决策时刻的情境。它是一个 **完全免训练** 的框架，有两个粒度。**Step-level activation**：执行时，用冻结 GUI backbone 自己的视觉特征（分块池化、去均值、L2 归一后拼接）把当前屏幕和候选轨迹里的每一个历史屏幕做相似度匹配，取最像的那一步所对应的历史动作作为「参考」喂给 policy，而且 **每一次观察都重新匹配**，参考可以在不同历史轨迹之间跳。**Task-level activation**：没有指令时，把语义相近的历史意图聚成「routine 邻域」，用同场景计数和以小时为单位的高斯时间核算上下文支持度，只有总支持、同场景支持、加权支持三道阈值都过才激活，否则 **主动闭嘴**。在 AndroidIntent（82 个用户、135 个 App、15,966 条历史记录）上，四个冻结开源 backbone 全部拿到最佳个性化执行：相对无历史 SSR 平均 +44%、CSR 约翻倍，相对最强记忆基线 SSR 再高约 20%，而每步只多 **144.6 个历史 token**，约为基线的五分之一；主动推荐的 MCC 约为最强基线的 **2.3 倍**，精度平均 84%。最反直觉的一条：Qwen3-VL-8B 上四个基线在首步之后的 7,140 个动作里 **与无历史条件统计上不可区分**，ExpActivator 却在同一批动作上 +8.24 点。这篇真正的价值是给「经验复用」提供了一个可测的分界：首步收益和轨迹内收益必须分开算。

## 🎯 为什么这件事值得写

个人 GUI 助理面对的指令天然是模糊的：「查一下更新」既不说哪个 App，也不说看什么，只能从这个用户的历史里补全。现有路线大致四类：

| 路线 | 怎么用历史 | 隐含假设 |
| --- | --- | --- |
| Recent | 塞最近若干条记录 | 新近即相关 |
| Retrieve | 按指令相似度检索整条轨迹 | 任务相关即每步可用 |
| LLM-UM | 离线让 LLM 写用户画像 | 抽象偏好足以指导动作 |
| HIM-Agent | 分层意图记忆、routine 原型 | 组织好了，policy 自己会判断用不用 |

它们共同的盲点是：**指令全程不变，屏幕每步都在变。** 一条检索来的轨迹能告诉你从哪开始，却不告诉你「眼前这个界面对应过去哪一步」。主动推荐同理：同一个 routine 在早八点在家和晚上通勤时都会被检索到，但只有前者该触发。

这和我们之前读过的几条主线是一回事。[Learn2Play](./20261009_Learn2Play_论文解读_经验别急着蒸馏成规则_原始轨迹加好harness才学得会陌生规则.md) 说原始轨迹比蒸馏规则更有用，[Work2Skill](./20261012_Work2Skill_论文解读_录一遍人类操作就能写成SKILL.md_按需翻证据比流水线解析更好用.md) 说按需翻证据比一次性解析更好，[ReHarness](./20261012_ReHarness_论文解读_反思写进记忆就不再改_反向修订让harness状态也能吃到下游反馈.md) 说记忆写进去之后还得能被下游反馈修订。ExpActivator 补上的是 **读取侧** 的一块：经验不仅要存对、改对，还要 **在对的那一刻被选中**。

## 🏗️ 机制：一个统一的激活式 + 两种实例

用户历史 $\mathcal{M}_u=\{r_i\}$，每条记录 $r_i=(g_i,p_i,c_i,\tau_i,\xi_i)$ 包含目标、App、场景、时间戳和轨迹，轨迹是「屏幕–动作」对的序列。两个粒度共用一个激活式：

$$
e_u^{(d)}(x)=\Gamma_d\Big(\arg\max_{b\in\mathcal{B}_u^{(d)}(x)}\kappa_d(x,b),\;x\Big),\quad d\in\{\text{step},\text{task}\}
$$

$\mathcal{B}$ 是候选集合，$\kappa$ 是与当前输入的兼容度，$\Gamma$ 把选中的历史元素变成参考（动作或意图）。

**Step-level：每一屏重新找「过去的这一步」。**

1. 先用文本编码器按目标相似度取 Top-K 条相关轨迹（去掉开头的 App 名，只留任务内容）；
2. 当前屏幕 $s_t$ 用 backbone 自己的视觉 token 分块池化，减去历史校准图的均值后归一化，拼成 $\phi(s)$；
3. 在所有候选轨迹的所有步上做联合 argmax：

$$
(i_t^*,j_t^*)=\arg\max_{i\in C_u(q),\,0\le j<T_i}\phi(s_t)^\top\phi(s_{i,j})
$$

4. 把对应的历史动作序列化成参考 $e_t$，冻结 policy 生成 $\hat a_t=\pi_\theta(q,s_t,H_t,e_t)$。

关键设计：参考 **不是指令**，policy 仍要看当前屏幕判断能不能用、目标在哪；而且匹配 **不假设当前执行和历史轨迹步号对齐**，可以从 A 轨迹的第 3 步跳到 B 轨迹的第 7 步。

**Task-level：先问「该不该说」，再问「说什么」。**

把语义相似度 $\ge\eta$ 的历史意图聚成 routine 邻域 $\mathcal{R}_j$，上下文支持度：

$$
M_j(x)=\sum_{i\in\mathcal{R}_j(x)}\mathbb{I}[c_i=c_x]\exp\!\Big(-\frac{d_{24}(\omega_i,\omega_x)^2}{2\sigma^2}\Big)
$$

$d_{24}$ 是一天 24 小时上的环形距离。资格与排序分开：总支持 $n_j\ge n_{\min}$、同场景支持 $\ge n_{\text{ctx}}$、加权支持 $M_j\ge\delta$ 三者都满足才进入候选；排序用平均每次出现的匹配度 $M_j/n_j$。候选为空就弃权。论文给的默认值是 $\eta=0.94$、$n_{\min}=12$、$n_{\text{ctx}}=4$、$\sigma=1$ 小时、$\delta=0.25$。激活出的意图同样只是参考，**不是执行授权**。

## 🧪 关键证据或主结果

**个性化执行（Table 1，节选）**

| Backbone | 最强基线 SSR | ExpActivator SSR | 最强基线 CSR | ExpActivator CSR |
| --- | --- | --- | --- | --- |
| Qwen3-VL-8B | 22.6 | **30.9** | 41.4 | **47.9** |
| MAI-UI-8B | 21.6 | **26.6** | 32.7 | **42.7** |
| Qwen3.5-9B | 21.0 | **24.3** | 39.8 | **40.9** |
| GUI-Owl-1.5-8B | 28.2 | **28.9** | 41.6 | **45.8** |

四个开源 8–9B backbone 加上 ExpActivator 后，CSR 平均约为闭源 QwenVL-Max（27.3）的 1.6 倍。

**主动推荐**：AndroidIntent 里 68% 的状态是正例，「永远推荐」就能拿 81.1% F1，所以作者改用 BA 和 MCC。基线大多贴着随机水平，MAI-UI 上三个基线行为和「永远推荐」完全一样（MCC = 0）；ExpActivator 的 MCC 在 38.9–45.2 之间，精度 82.6–86.5%。

**首步 vs 轨迹内（Table 2，Qwen3-VL-8B）**

| 方法 | 历史 token/步 | 首步 SSR | 轨迹内 SSR | 相对 Base |
| --- | --- | --- | --- | --- |
| Base | 0 | 28.26 | 18.43 | – |
| Retrieve | 730.6 | 62.06 | 18.35 | −0.08 |
| HIM-Agent | 417.8 | 62.32 | 18.26 | −0.17 |
| ExpActivator | **144.6** | **70.06** | **26.67** | **+8.24 [6.51, 10.16]** |

这张表是全文的核心：检索把首步从 28% 拉到 62%，之后几千个动作里一分没多拿。

**泼冷水**：

- 只有一个基准 AndroidIntent，82 个用户，结论能否迁移到桌面、Web、更长任务还没验证；
- 绝对数仍然很低，轨迹内 SSR 不到 27%，个性化执行远没到能放心托付的程度；
- Qwen3.5-9B 和 GUI-Owl 上相对最强基线的 SSR 提升只有 3.3 和 0.7 点，「平均 +20%」主要被 Qwen3-VL-8B 和 MAI-UI 撑起来；
- task-level 有六个手设阈值，虽然附录给了敏感性分析，但换一个用户群或场景分类体系大概率要重调；
- 方法要求保存每一步的历史截图并用 backbone 特征比对，隐私与存储成本论文基本没谈，App 改版后历史屏幕失配的问题也没测。

## 🔬 最有意思的部分

**「选」比「塞」重要，同一条轨迹差 29%。** 消融里只给一条 Top-1 轨迹：整段塞进去 SSR 18.5%，和不给历史一样；让 step-level 从同一条轨迹里只挑一个动作，SSR 23.8%。信息量完全相同，差别只在交付方式。

**刷新频率就是机制本身。** 用上一屏而不是当前屏做匹配，SSR 掉 15%；每四步才刷新一次，掉 13%；参考动作与真实动作的一致率更是掉 38%，因为过期屏幕激活的是用户已经走过的那一步。作者原话很到位：每次观察都重算不是细节优化，而是机制本身。

**没有哪条历史轨迹能单独撑起一次执行。** 92% 的 episode 从两条以上历史轨迹借参考，平均 3.4 条；相邻两步换轨迹的比例高达 55%，到第 12 步之后仍有近一半在换。四个 backbone 的统计几乎一模一样，说明这是激活规则本身的性质，而不是某个视觉编码器的偶然。这对「把一条成功轨迹当脚本回放」的思路是很直接的反证。

**时间决定何时说，场景决定说不说，频率决定说什么。** 去掉时间权重 BA 掉约 5%；去掉场景条件 BA 掉 11%，误报率从 37% 飙到 62%；频率归一不改变任何触发决策，只让推荐内容的语义分高 4%。三个分量各管一件事，拆得很干净。

**历史少的用户受益反而最多。** 按历史量分四档，最少那档（39–111 条）相对最强基线 SSR 提升 37%，说明不需要攒很长的个人记录才有效。

## 🤔 我的判断

定位：**诊断驱动的工程方法**。它没有训练任何东西，贡献主要在两处：一是把「首步收益」和「轨迹内收益」拆开测，揭穿了检索式记忆的虚高；二是给出一个极简的读取侧规则，证明经验在决策时刻被选中才值钱。

亮点三条：

1. 诊断扎实：同一 backbone、同一历史、逐步配对比较，加用户级 cluster bootstrap 置信区间，「基线轨迹内 ≈ 0」这个结论很难被反驳；
2. 便宜：免训练、不改 policy，每步只多一百多 token，四个不同视觉编码器上都成立；
3. 主动推荐上把「弃权」做成一等公民，资格与排序分离，避免了「检索到相关就开口」的骚扰式助理。

问题与局限：单一基准、绝对成功率低、部分 backbone 增益很小；依赖截图级历史与 backbone 视觉特征，隐私、存储和 UI 版本漂移都是落地时绕不开的坎；task-level 的阈值和场景分类是人工给的，离「自适应」还有距离。

对工程的直接启发：

- **(1)** 任何经验/记忆系统的评测，都把首步和后续步骤分开报，否则你可能在用 700 个 token 换一个只在第一步生效的收益；
- **(2)** 读取侧做成「检索缩候选 + 每步按当前观察重新选一条」两段式，参考只给最小粒度（一个动作或一个片段），别整段回放；
- **(3)** 匹配可以直接用 policy 自己的表征空间，省掉额外的检索模型，也天然和 policy 的「看法」对齐；
- **(4)** 主动行为（提醒、建议、自动触发）先过「该不该」闸门，阈值用绝对支持定资格、用平均匹配度定排序，误报比漏报更伤信任；
- **(5)** 和 [DerivAudit](../week1/20261001_DerivAudit_论文解读_记忆不是摘抄是推导_分布式证据悖论卡死写入闸.md) 管写入闸、[ReHarness](./20261012_ReHarness_论文解读_反思写进记忆就不再改_反向修订让harness状态也能吃到下游反馈.md) 管修订合起来看，一个完整的 harness 记忆层应该同时有写入闸、修订回路和决策时刻激活三件事。

一句话收束：**ExpActivator 证明，经验的价值不在被检索到，而在被正确的那一刻选中；把记忆从「挂在上下文里」改成「每一步重新激活」，五分之一的 token 就能换来实打实的轨迹内收益。**
