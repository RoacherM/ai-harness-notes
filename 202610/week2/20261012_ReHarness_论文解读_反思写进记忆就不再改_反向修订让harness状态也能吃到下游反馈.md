# 反思写进记忆就不再改？反向修订让 harness 状态也能吃到下游反馈

你有没有过这种体验：agent 在第二个任务上总结了一条「经验」，写进记忆库，之后每次检索都被翻出来；可那条经验其实是从一次偶然里过度概括出来的，后面任务分布一变，它就开始持续误导决策。你看着轨迹里 agent 一遍遍「严格遵循历史经验」犯同一个错，心里只有一个念头：**记忆库里的东西，为什么没人回头改？**

MIT 与 Meta MRS Research 这篇 **ReHarness**（arXiv:2610.12668）把这个问题说得很透：现有 harness 的记忆、反思、playbook 基本只有**前向信息流**，读、做、写，写完就不再根据后续效果更新；而那些会优化 harness 的方法，又要额外的回放或验证集，在严格在线的流式场景里根本拿不到。它的做法是给 harness 加一条**反向修订**：每完成一个实例，就拿这次轨迹当反馈，回头修改本次检索到的那几条反思。看完我的感受：这是把「循环神经网络」的直觉搬到了文本 harness 状态上，而且实验做得很克制，连泄漏率都量了。

## 核心摘要

ReHarness 把 harness 状态 $h_t=\{R_i\}_{i<t}$ 定义为一组反思，每个实例走三步：**前向读**（按 query 相似度取 top-k 反思给决策 agent，得到轨迹 $\tau_t=(x_t,y_t,r_t)$）；**反向修订**（修订 agent 对每条被检索的反思 $R_i$，结合它的来源轨迹 $\tau_i$ 与本次结果 $\tau_t$ 重写为 $R_i'$，新增内容必须能在 $\tau_i$ 里找到依据，$\tau_t$ 只当反馈，防止信息泄漏）；**前向写**（记忆 agent 以修订后的反思为示例，从 $\tau_t$ 写一条新反思，追加进状态）。整个过程严格在线：不回放、不用验证集、不更新权重。实验在 CL-Bench（6 任务）、MemoryBench（5 个英文写作任务）、MemoryArena（5 个领域）三个持续学习基准、Claude Opus 4.8 / GPT-5.5 / Gemini 3.7 Flash 三个 backbone 上，对比 Mem0、ReasoningBank、DoT、ACE、GEPA-Online、Top-K Raw、Full Raw。ReHarness 的平均归一化增益 **0.240**，九个组合里八个第一或并列第一，Wilcoxon + Bonferroni 检验对所有基线显著，包括最强的 Top-K Raw（p=0.039）和 Full Raw（p=0.043）。在 CL-Bench + Claude 上它的总 token 只有 Full Raw 的约三分之一（41.57M 对 142.12M），增益反而更高（0.217 对 0.191）。修订后的反思 95% 以上的事实可追溯到来源轨迹，泄漏率 0.8% 到 2.1%。

## 🎯 为什么这件事值得写

agent 越来越多在长交互流上工作，需要在不更新参数的前提下适应分布漂移。主流做法是在固定 LLM 外面套一个有状态 harness：Mem0 存原子记忆，ReasoningBank 存可复用反思，ACE 维护全局 playbook 并做增删改合并，GEPA 进化 prompt。问题有两个：

| 路线 | 状态如何更新 | 缺口 |
| --- | --- | --- |
| 前向积累（Mem0、RBank、DoT） | 每个实例后抽取或反思，追加 | 写完不根据后续效果改 |
| 一致性维护（ACE 等） | 增删改合并 | 维护的是库的连贯性，不是下游有效性 |
| 离线 / 验证驱动优化 | 回放实例或用验证集选更新 | 严格在线场景拿不到这些数据 |

结果是：过时的记忆、过度自信的反思会在状态里长期存活，反复误导决策。这和 [Learn2Play](./20261009_Learn2Play_论文解读_经验别急着蒸馏成规则_原始轨迹加好harness才学得会陌生规则.md) 里 EvoTest 把一次失败固化成禁令是同一种病。ReHarness 给的药方是：让经验也能「被反向传播」。

## 🏗️ 机制：前向读、反向修订、前向写

三步形式化：

$$
I_t=\mathrm{Retrieval}(x_t,h_t,k),\qquad y_t=\pi_D\big(x_t,\{R_i\}_{i\in I_t}\big)
$$

$$
R_i'=\pi_R(R_i,\tau_i;\tau_t),\quad \forall i\in I_t
$$

$$
R_t=\pi_M\big(\tau_t;\{R_i'\}_{i\in I_t}\big),\qquad h_{t+1}=h_t'\oplus R_t
$$

论文里的排序例子很好懂：第一次任务是「降序」，记忆 agent 写下「大数放前面」；下一次任务是「升序」，决策 agent 照着旧反思排错了。反向修订把旧反思改成「仅在降序时大数在前」，前向写再参照它生成「仅在升序时小数在前」。限定条件被补回来了，下一次检索到的就是不会误导的版本。

几个工程细节：

1. **只修被检索到的条目。** 修订成本是每实例 k 次调用（实验里 k=5），未被检索的反思保持不变。
2. **新内容必须锚定来源轨迹。** 当前轨迹只用来判断旧反思好不好用，不能把当前答案抄进旧反思，否则就是信息泄漏。
3. **修订后的反思当写作示例。** 新反思被鼓励写出示例没覆盖的视角，避免同质化。

## 🧪 关键证据

**主表（Table 1，平均归一化增益）。** 归一化增益定义为 $(r_{\text{method}}-r_{\text{stateless}})/(r_{\max}-r_{\text{stateless}})$，衡量相对无状态 backbone 的提升。

| 方法 | CL-Bench / Claude | CL-Bench / GPT | CL-Bench / Gemini | 九组合平均 |
| --- | --- | --- | --- | --- |
| Mem0 | 0.103 | 0.220 | 0.092 | 0.131 |
| RBank | 0.073 | 0.065 | 0.040 | 0.034 |
| DoT | 0.125 | 0.081 | −0.008 | 0.071 |
| ACE | 0.042 | 0.088 | 0.036 | 0.043 |
| GEPA-Online | 0.076 | 0.239 | 0.132 | 0.092 |
| Top-K Raw | 0.165 | 0.268 | 0.190 | 0.168 |
| Full Raw | 0.191 | 0.299 | 0.234 | 0.164 |
| ReHarness | 0.217 | 0.317 | 0.233 | 0.240 |

和之前几篇的观察一致：**原始上下文是很强的基线**，Top-K Raw 和 Full Raw 平均上超过大多数结构化记忆与反思方法；RBank、DoT、ACE 部分设置甚至是负增益。

**成本（CL-Bench 全任务 + Claude 一次 rollout）。**

| 方法 | 输入 token | 输出 token | 总计 | 估算费用 | 增益 |
| --- | --- | --- | --- | --- | --- |
| Top-K Raw | 52.20M | 0.46M | 52.66M | 约 85 美元 | 0.165 |
| ReHarness | 37.19M | 4.38M | 41.57M | 约 254 美元 | 0.217 |
| Full Raw | 141.68M | 0.44M | 142.12M | 约 314 美元 | 0.191 |

反思紧凑，省下的决策期输入远超修订带来的输出开销。不过在开了 prompt cache 的定价下，ReHarness 比 Top-K Raw 贵约三倍，因为输出 token 更贵。

**落地性（Table 2）。** 用 GPT-5.6-Sol 把修订后的反思拆成事实断言逐条判定：可由来源轨迹蕴含的 95.3% 到 98.7%，泄漏（只由当前轨迹蕴含）0.8% 到 2.1%，无依据 0.5% 到 2.6%；每次修订对这些比率的影响不超过 0.3%。

**反事实回放（Table 3，CL-Bench + Claude）。** 无修订 0.144，ReHarness 0.217，把修订后的状态直接用回同一实例的反事实回放 0.335。回放违反在线协议，但证明修订确实能「改对」。

**泼冷水。** 可剥削扑克上几乎没涨：手牌奖励受隐藏牌和运气影响，与策略质量弱耦合，反向修订吃到的是噪声；原始轨迹基线反而更稳，因为它把解释推迟到每手决策时。另外修订与泄漏的判定都依赖 LLM 评审，MemoryBench 的打分也是 LLM judge。

## 🔬 最有意思的部分

1. **修的是「过度概括」。** 盲频谱监测里，早期反思建议「在大段静默里补报可能的信道」，决策 agent 照做后被扣分；修订 agent 把它标成 speculative，改成「优先保留已确认的峰，而不是添加未确认的」，下一次奖励明显回升。
2. **修的也是「过时经验」。** 数据库探索里，agent 早期没检查价格列的空值，后期经验在分布变化后被修订补上了这一条件。经验不是越写越多，而是越改越准。
3. **稳定性与可塑性一起提升。** 传统持续学习里两者此消彼长；这里修订既纠正了旧错误（可塑），又减少了被错误经验反复带偏（稳定）。
4. **「锚定来源」是整个设计的安全阀。** 没有这一条，反向修订会退化成把当前答案写进记忆，看起来学得飞快，实际是在作弊。

## 🤔 我的判断

定位：**持续学习的 harness 方法突破**，核心贡献是在严格在线、无验证集、无权重更新的约束下，给文本 harness 状态补上了反向反馈通路。

亮点三条：

1. 「前向读写 + 反向修订」的循环结构简单清楚，可以直接嫁接到现有记忆或技能库上；
2. 三基准、三 backbone、七个基线，并做了配对显著性检验，结论扎实；
3. 用断言级的落地率与泄漏率约束修订，回答了「修订会不会偷看答案」这个最关键的质疑。

问题与局限：只修被检索到的条目，从未被检索的坏经验无法被纠正；在奖励噪声大的任务上修订会被误导；修订比 Top-K Raw 贵；检索固定用 query 相似度，没有探讨修订后检索策略是否也该变。

对工程的直接启发：**(1)** 给技能库或记忆库的每条记录挂上来源轨迹引用，修订时只允许用来源证据改写，当前任务结果只做评分；**(2)** 每次任务结束后，对「这次用到的技能」做一次轻量复盘，判断它是帮了还是害了，并补上适用条件；**(3)** 奖励噪声大的场景先别开反向修订，或者对修订加置信门槛；**(4)** 先跑 Top-K Raw 当基线，很多花哨记忆方法其实打不过它；**(5)** 这个思路和 [JITMem](../../202609/week4/20260925_JITMem_论文解读_记忆别在写入时裁剪_读时按任务现场策展同一条轨迹能榨出不同课.md) 互补：那边在读时现场策展，这边在用后回头修订。

一句话收束：**ReHarness 证明，harness 里的经验不该写完就封存，让每次使用的结果反向修订被用到的那几条，才能在分布漂移里既不忘也不被带偏。**
