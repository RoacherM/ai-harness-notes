# 四轮写 playbook 顶过百万局 RL：代码世界 + 神经渲染器，让 agent 边玩边进化

你有没有过这种体验：想给 agent 搭一个能「练手」的环境，结果卡在两难里。用游戏引擎和仿真器，状态清楚、规则可编程，可每换一个场景就要重做一堆 3D 资产；用视频世界模型，画面丰富、换风格容易，可状态和物理规则全埋在生成历史里，没法检查、没法改、没法写单测。行业里把前者叫 simulator，后者叫 world model，**有没有办法鱼和熊掌兼得？**

MirroS 这篇 **AgentGarten**（arXiv:2610.12374）给的答案是「代码世界」：状态和规则写成代码交给引擎，画面交给一个共享的实时神经渲染器。更让我在意的是它的后半段：预训练 agent 只看渲染画面，每轮把经验写成一条条 skill 文件进 playbook，下一轮新 agent 继承再改。捉迷藏里，**4 轮就会搭掩体，10 轮就会用坡道翻墙**，而 2019 年 OpenAI 的自博弈 RL 分别用了约 2500 万和 1 亿局。看完我的感受：这篇的方法主体是视频生成，但它给 skills / playbook 式持续学习提供了一个很好的「物理沙箱」。

## 核心摘要

AgentGarten 把环境拆成三件事：场景程序 $p$（定义物体、规则、任务），执行它的引擎（维护持久状态 $s_t$），以及共享神经渲染器 $R_\theta$（从引擎导出的深度或法线图、外观参考图、文本和视觉历史生成观测）。关键性质是**状态转移不读渲染结果**，渲染错误不会累积进状态；同一条状态轨迹可以换风格、换机位重渲。新世界由 coding agent 从一张图或一段文字写出：调用 SAM 3、Depth Anything 3、WildDet3D 等感知模型当工具，写 scene.py，再用多机位探针和碰撞、遮挡检查迭代修复。渲染器从 Cosmos 3-Nano 初始化，经几何条件化、teacher forcing、以及作者提出的 **Adversarial Forcing** 蒸馏成单 GPU 实时、block-causal 的少步生成器；后者用「精确重放」让后续损失能更新历史编码，并加入真实数据对抗目标和不需要二阶反传的精确 R1/R2 正则。agent 侧，每个角色维护一个由短 Markdown skill 文件组成的 playbook，一文件一教训；每轮结束复盘动作程序和可见画面、写新 skill，下一轮全新会话继承。除捉迷藏外，在陪伴犬、单车道桥、牧羊、矿场装载机四个世界上，同一流程 4 轮内都有提升（例如矿场分数 30 到 90.9，桥上会车 71 秒到 41 秒）。

## 🎯 为什么这件事值得写

agent 能学到什么，上限由它练习的环境决定。环境要**忠实**（状态一致、规则稳定）也要**逼真**（观测符合真实视觉分布），同时还要**便宜可扩展**。现有路线各缺一块：

| 路线 | 状态与规则 | 视觉多样性 | 新环境成本 |
| --- | --- | --- | --- |
| 仿真器 / 游戏引擎 | 显式、可检查 | 依赖 3D 资产 | 高 |
| 视频世界模型 | 隐式、不可编辑 | 丰富 | 低，但不可测 |
| AgentGarten 代码世界 | 显式，写成代码 | 由共享渲染器提供 | coding agent 自动写 |

对做 harness 与持续学习的人，这里有两个信号：一是「环境即代码」让 coding agent 成为环境作者，与 [Skill2Env](../../202609/week5/20260930_Skill2Env_论文解读_技能不够成考场_能力难度模式才把环境造硬.md)、[VHD-Play](../../202609/week4/20260924_VHD-Play_论文解读_先解数学模型再包成有状态工具_三千环境几分钱一份.md) 一脉相承；二是它把 playbook / skill 文件式的经验沉淀搬进了视觉具身场景。

## 🏗️ 机制：状态与外观解耦

形式化很干净：

$$
(s_{t+1},\pi_{t+1}) = f_p(s_t,\pi_t,a_t),\qquad c_t = h_p(s_t,\pi_t)
$$

$$
x_t = R_\theta(x_{<t}, c_{\le t}, x_0, y),\quad t\ge 1
$$

$f_p$ 不看 $x_t$，渲染器只通过 $c_{\le t}$ 看状态。颜色、材质这类条件里没有的信息由参考图 $x_0$ 和文本 $y$ 决定，并由视觉历史延续。

渲染器训练三阶段：

1. **几何条件化**：深度 / 法线编码成三通道，复用预训练 VAE 与输入投影，和 RGB token 在序列维拼接做联合注意力；训练时随机保留一种模态、加纹理抑制和平滑扭曲，缩小估计几何与引擎几何的差距。
2. **teacher forcing 适配**：每个 block 一份干净副本、一份带噪副本，用 block-causal mask 并行训练。
3. **Adversarial Forcing**：DMD 式分布匹配 + 两遍训练的精确重放（逐 block 调用 SDPA，保证与采样时逐位一致，避免 SGF 式整序列 FlexAttention 的数值漂移）+ R3GAN 相对对抗目标；利用骨干冻结，用一次 VJP 和一次 JVP 算出精确 R1/R2 及其对判别头参数的梯度，不走 FlashAttention 不支持的二阶反传。

agent 侧的「一轮练习」：读 task.md（目标、动作、限制，无解法）→ 在预算内只看相机帧行动 → 写 playbook（试了什么、看到什么、还怀疑什么、下次测什么）→ 归档。下一轮全新会话拿到 task 和所有历史 playbook。

## 🧪 关键证据

**捉迷藏里程碑（Table 3）。**

| 策略 | 自博弈 RL（Baker et al.） | 预训练视觉 agent |
| --- | --- | --- |
| 搭掩体 | 约 2500 万局训练 | 第 4 轮 |
| 坡道翻墙 | 约 1 亿局训练 | 第 10 轮 |

agent 通过提交短 Python 程序移动、抓取物体，看不到坐标、隐藏状态和对手私有观测。涌现出的 skill 文件名就很说明问题：check_shelter.md「守住入口，不只是守住镜头」，object_control.md「用小实验确认自己抓住了物体」，ramp_landing.md「坡道路线有三个独立里程碑」。

**另外四个世界（Table 4，每轮一局）。**

| 世界 | 指标 | R1 | R2 | R3 | R4 |
| --- | --- | --- | --- | --- | --- |
| 陪伴犬 | 互动分 | 13 | 14 | 19 | 19 |
| 单车道桥 | 两车到达秒数（越低越好） | 71 | 68 | 45 | 41 |
| 牧羊 | 分数 / 入圈羊数 | 60 / 3 | 90.1 / 4 | 87.6 / 4 | 88.3 / 4 |
| 矿场装载机 | 分数 | 30 | 0 | 30 | 90.9 |

**泼冷水。** 作者自己说得很清楚：4 轮对 2500 万局**不是样本效率比**。RL agent 从随机权重起步、看真值坐标；这里的 agent 自带网络规模的物体与工具常识，难点只在把抽象知识落到闭环执行。另外每轮只有一局或五局，没有方差、没有多种子，矿场曲线 30 → 0 → 30 → 90.9 的波动说明单局噪声很大；也没有「不写 playbook」的消融对照，playbook 的边际贡献无法从数字上单独确认。

## 🔬 最有意思的部分

1. **环境可重放、可重渲。** 状态轨迹与外观解耦后，同一局可以换风格、换机位再看，这对评测与数据增广都很有价值，也让「环境 bug」变成可以 diff 的代码问题。
2. **coding agent 当环境作者，并且自带验收。** 写完 scene.py 后用多机位探针、接触、碰撞间隙、遮挡查询来修复悬空物体与歧义动作，这本质上是一个 harness 里的「环境单测」。
3. **playbook 是一文件一教训。** 和 skills 生态的 SKILL.md 粒度一致；记录「还怀疑什么、下次测什么」，比单纯写结论更接近科学笔记，正好回应 [Learn2Play](./20261009_Learn2Play_论文解读_经验别急着蒸馏成规则_原始轨迹加好harness才学得会陌生规则.md) 里「规则过早固化」的问题。
4. **精确重放是一个很工程的细节。** 同样的 mask，换个 kernel 和 reduction 顺序，在有限精度下轨迹就会漂；作者坚持逐 block、同调用形状重算，换来逐位一致。

## 🤔 我的判断

定位：**环境基础设施 + 视频生成方法，附一个 playbook 式持续学习的演示**。前三分之二是渲染器，后三分之一才是 agent。

亮点三条：

1. 「状态写成代码、外观交给渲染器」的接口切得干净，环境可检查、可编辑、可扩展；
2. Adversarial Forcing 的精确重放与免二阶反传 R1/R2，是可复用的训练工程；
3. 证明了 skill 文件式 playbook 能在只有视觉观测的物理任务里带来可见的策略演化。

问题与局限：agent 实验样本极小、无消融、无方差；与 RL 的对比更多是叙事锚点；playbook 增长后如何检索、去重、淘汰没有讨论；渲染器质量对 agent 决策的影响也缺量化。

对工程的直接启发：**(1)** 做 agent 训练 / 评测环境时，把状态和观测分层，状态层写成可测代码，观测层可以随便换；**(2)** playbook 每条 skill 写成「教训 + 证据 + 待验证假设」，便于后续推翻；**(3)** 如果想复用它的结论，务必自己补「无 playbook」基线和多种子，否则无法区分进化与运气。

一句话收束：**AgentGarten 把环境变成了 coding agent 可以写、可以测、可以重渲的代码，再让 agent 用 skill 文件在里面边玩边进化，野心是让环境和 agent 一起扩展。**
