# 从零复现程序缺可验证考场：1648 黑盒环境加角色隔离，把 27B 抬过旗舰脚手架

你有没有过这种体验：SWE-bench 类任务给仓库和 issue，agent 主要在**已有代码里打补丁**；NL2Repo 类任务给需求文档，实现路径已被自然语言写死。真正从零搭系统时，工程师要自己问「还缺什么行为、架构怎么拆」。ProgramBench 把这道题变成黑盒复现——只给文档和可运行参考程序，不给源码——可原论文里**没有模型完整解出任一任务**，训练侧也几乎没有可验证环境。**没有可扩的 gym，agent 怎么学成会探索、会设计的软件工程师？**

厦门大学、华盛顿大学圣路易斯、中科院自动化所与云知声这篇 **ProgramGym**（arXiv:2610.13395）给了两块积木：Program-Env 用反馈环把仓库铸成 1,648 个 C/C++/Go/Rust 黑盒训练环境；Program-Agent 用分析 / 实现 / 审查的角色隔离工作流扛长程开发。看完我的感受：这是把 [SoftwareGym](./20261012_SoftwareGym_论文解读_一个OSWorld应用都没训_合成182个桌面软件让9B模型涨15点.md) / [CodeMidas](../../202609/week4/20260922_CodeMidas_论文解读_只靠源码榨出五千可验证coding_RL环境.md) 一路「可验证环境规模化」的思路，推到了从零程序复现这个更硬的设定。

## 核心摘要

ProgramGym 针对长程 **program reproduction**：agent 必须在无源码、无网络条件下，靠文档与参考可执行体探索可观察行为，并自主做设计决策。Program-Env 在现有 agent harness（实验里用 Claude Code）外加反馈驱动环：在线准备依赖、离线编译，用构建诊断修 sandbox；测试按功能模块并行生成，结合程序分析瞄准未覆盖行为，并用校验反馈淘汰弱断言，最终交出参考可执行体、运行时 sandbox、文档与黑盒行为测试。据此铸出 **1,648** 个训练环境（Go 约 49.6%，C++ 约 22.9%，Rust 约 18.4%，C 约 9.0%）。Program-Agent 先做分析沉淀证据，再在独立会话里交替实现与行为审查，用持久记录跨轮传递需求，并用离线编译检查与校验 checkpoint 做修订与失败恢复。在 ProgramBench 上，用这些环境轨迹 SFT 后，Qwen3.8-27B 的 Tests Passed 从 **34.87%** 升到 **42.84%**；挂上 Program-Agent（K=5）后，基座与 SFT 分别到 **55.71% / 56.25%**，超过部分旗舰模型在 mini-SWE-agent 下的成绩。

## 🎯 为什么这件事值得写

Coding agent 训练环境大多服务「在已有仓库里改」或「按需求文档实现」。从零复现要求 agent 自己发现需求边界并设计系统，监督信号只能来自**行为是否对齐**，不能来自 diff 是否像 gold patch。

| 设定 | 起点 | agent 主要做什么 | 训练环境缺口 |
| --- | --- | --- | --- |
| Issue resolution（SWE-Gym 等） | 已有仓库 + issue | 局部修补 | 有，但不练从零设计 |
| Repo generation（NL2Repo） | 需求文档 | 按规格实现 | 规格已写死，少探索 |
| MindForge 等 | CLI 程序 | 部分从零 | 监督未必按行为可验证过滤 |
| Program reproduction | 文档 + 黑盒参考 | 探索 + 设计 + 实现 | 可扩、可验证环境稀缺 |

[RecreationWorld](../../202609/week4/20260922_RecreationWorld_论文解读_对着跑着的参考应用重写一遍_混合CUA才算真干活.md) 强调对着跑着的参考应用重写；ProgramGym 把类似直觉收成可批量铸造的 gym，并配上专为长程开发设计的 harness。

## 🏗️ 机制：反馈铸环境 + 角色隔离长程工作流

**Program-Env。** 从 GitHub 按语言收仓 → 反馈环修 runtime sandbox 构建 → 并行按模块造黑盒测试并校验。构建把「在线依赖准备」和「离线编译」拆开，失败诊断回流给 harness 再修；测试子代理共 **5,918** 个，覆盖子命令、参数组合、输入输出契约等六类黑盒交互。轨迹用 DeepSeek-V4-Flash-0731 + Claude Code 拒绝采样，按测试通过率过滤后再 SFT。

**Program-Agent。** 角色隔离、会话分离：

1. **Analysis**：探索文档与参考程序，写下可观察行为证据与需求记录；
2. **Implement**：在独立会话按记录实现，先交付可编译基线，再迭代功能；
3. **Review**：独立审查行为对齐，失败则进入修订与恢复。

固定预算 $K$ 轮实现：先一次标准化 Analysis，再交替 Implement / Review。离线 `compile` 检查与已验证 checkpoint 防止上下文压缩后把可运行状态弄丢。单任务容器限制：8 核 / 16GB 内存 / 30GB 盘 / 8 小时墙钟。

## 🧪 关键证据

**主表（Table 2，ProgramBench，Program-Agent 用 K=5）。**

| 模型 | Scaffold | Tests Passed | Almost Resolved | Resolved |
| --- | --- | --- | --- | --- |
| Claude Opus 4.7 | mini-SWE-agent | 50.90% | 3.00% | 0.00% |
| Gemini 3.5 Flash | mini-SWE-agent | 53.60% | 3.00% | 0.00% |
| DS-V4-Flash-0731 | Claude Code | 57.68% | 4.50% | 0.00% |
| DS-V4-Flash-0731 | Program-Agent | 58.97% | 5.0% | 0.00% |
| Qwen3.8-27B | Claude Code | 34.87% | 3.50% | 0.50% |
| Qwen3.8-27B | Program-Agent | **55.71%** | 5.50% | 0.50% |
| Qwen3.8-27B-SFT | Claude Code | 42.84% | 1.50% | 0.00% |
| Qwen3.8-27B-SFT | Program-Agent | **56.25%** | 4.50% | 0.50% |

两层增益很清楚：**只换数据**（同 Claude Code）SFT 带来 +7.97；**只换脚手架**（同权重）Program-Agent 把基座抬 +20.84、SFT 抬到 56.25。SFT+Program-Agent 超过 Claude Opus 4.7 / Gemini 3.5 Flash 在 mini-SWE-agent 下的 Tests Passed。

**迭代预算。** Qwen3.8-27B-SFT + Program-Agent：K=1 → 43.49%，K=3 → 54.13%，K=5 → 56.25%。多轮仍在回收行为，不是一轮就饱和。

**行为变化。** 单会话 Claude Code 更偏 execute / probe；Program-Agent 把分析证据与审查轮次结构化后，实现更晚开始、失败恢复更依赖 checkpoint——和「先实现再发现需求」的塌缩相反。

**泼冷水。** Tests Passed 过 50% 时，Almost Resolved / Resolved 仍接近 0，完整复现极难；SFT 后 Almost Resolved 在 Claude Code 下从 3.50% 掉到 1.50%，说明行为通过率涨了不等于「接近全过」；环境铸造本身依赖强 harness 与高成本；评测与部分 casting 都绑在 Claude Code 生态。

## 🔬 最有意思的部分

1. **环境与脚手架拆开贡献。** 很多人把「换模型」和「换 harness」混在一个分数里；这里同 scaffold 比 SFT、同模型比 scaffold，归因清楚。
2. **黑盒测试要会拒绝错误复现。** 弱断言会把坏实现标成正样本；反馈驱动的测试精炼，是 gym 能不能训的关键。
3. **角色隔离对抗上下文遗忘。** 长程任务里「探索记录」和「实现会话」混在一起，早期证据会被挤掉；分会话 + 持久记录是工程上可抄的招。
4. **和桌面 SoftwareGym 对照。** [SoftwareGym](./20261012_SoftwareGym_论文解读_一个OSWorld应用都没训_合成182个桌面软件让9B模型涨15点.md) 合成 GUI 应用涨 OSWorld；ProgramGym 铸系统级黑盒环境涨 ProgramBench——都是「先把可验证世界做大」。
5. **Resolved≈0 的诚实。** 分数涨在 Tests Passed，不装作已经「全程序复现」——这比刷一个漂亮的 solved rate 更有用。

## 🤔 我的判断

定位：**从零程序复现的可扩展训练环境 + 长程 harness**，测量基础设施与方法改进并重。

亮点三条：

1. 反馈驱动把异构仓库铸成 1,648 个带 sandbox 与黑盒测试的可验证环境；
2. 角色隔离 Program-Agent 在不改权重时也能大幅抬 Tests Passed，并随 K 持续涨；
3. 环境 SFT 与脚手架增益可分离度量，结论对「该先造环境还是先改 harness」有直接指导。

问题与局限：完整 Resolved 仍近零；语言与仓类别偏 CLI / 开发工具；铸造与评测成本高且依赖特定 harness；尚未充分展示 RL（相对 SFT + 测试时迭代）的上限。

对工程的直接启发：**(1)** 做从零复现训练时，先保证黑盒测试能杀掉错误实现，再谈规模；**(2)** 把分析、实现、审查拆开会话，并用持久需求记录跨轮传递；**(3)** 报告时同时给同 scaffold 的数据消融与同模型的 harness 消融；**(4)** 迭代预算要画到饱和区，别只报一个 K；**(5)** 可与 [AgentGarten](./20261009_AgentGarten_论文解读_四轮写playbook顶过百万局RL_代码世界加神经渲染器让agent边玩边进化.md) 式世界模型 / playbook 进化结合，在可验证程序世界上继续做自改进。

一句话收束：**ProgramGym 证明，从零复现缺的不是又一句「更强 coding agent」，而是把仓库铸成可验证黑盒考场，再用角色隔离工作流把长程探索与实现钉在同一条开发闭环里。**
