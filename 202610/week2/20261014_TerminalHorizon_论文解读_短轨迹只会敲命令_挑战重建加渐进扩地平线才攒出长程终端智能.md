# 短轨迹只会敲命令：挑战重建加渐进扩地平线，才攒出长程终端智能

你有没有过这种体验：用一堆「会 `ls`、会 `grep`、会跑测试」的短轨迹去微调终端 agent，榜上的小任务涨了一点，可真丢过去一个半天级的专业活，它还是会在中途把关键探索、改计划和验收跳掉。更糟的是造环境的人好心帮了忙：材料里已经写好了诊断结论、参考实现甚至验证脚本，agent 只剩拼装，**训练出来的行为分布天然缺了它本该自己做的那几段。**

USTC 与阿里高德（AMAP）这篇 **TerminalHorizon**（arXiv:2610.13166）把问题钉在数据合成上：长程轨迹要的不是更多轮次，而是 **agentic behavioral patterns 及其跨阶段连接**；环境若提前替 agent 做完探索、实现或验证，这些模式就长不出来。看完我的感受：这是一篇把「终端数据质量」从覆盖度改写成「是否逼出并串起行为模式」的工程论文，对任何做 terminal / coding agent 训练数据或 RSI 考场的人都很直接。

## 核心摘要

TerminalHorizon 是一个全自动的长程终端数据合成引擎，分两段。**Challenge-Guided Long-Horizon Synthesis** 从真实专业工作出发造可执行任务，再用 **未参与构建** 的独立 agent 去解；分析其轨迹，找出构建阶段已经简化或代做的分析、实现、验证，据此重建环境，逼 agent 自己做这些活。**Progressive Horizon Expansion** 在同一目标下引入依赖先前结果与反馈的新需求，让探索、改计划、验收等模式跨阶段延展。引擎产出 **1,535** 个任务环境与 **2,852** 条轨迹（TerminalHorizon-3K），均轮次 **52.8**；用 DeepSeek-V4-Pro-0813 作 teacher、Terminus2 作 harness，对 Qwen3.5-27B 做 SFT 得到 TerminalHorizon-27B。相对基座，Terminal-Bench 1.0 / 2.0 / 2.1 分别到 **55.0% / 55.8% / 60.67%**（+8.7 / +14.2 / +13.85）；同基座同 harness 下，比用约十倍轨迹的 Terminal-Universe-27B（TB 2.0 为 52.8%）再高 **3.0** 点。收益还外溢到真实生产力榜：AutomationBench Pass / Partial +11.7 / +23.3，VitaBench +11.3，τ²-bench Airline / Retail +5.5 / +2.6；五条通识推理榜不掉反涨。另有多组 **12 小时** 预算的 RSI 案例，展示持续试错、按反馈改方法并把改进写进终交付。价值定位：用约 3K 条高密度长程轨迹，证明「模式是否被环境逼出来」比单纯堆短交互更值钱。

## 🎯 为什么这件事值得写

终端 agent 的训练数据近年主要在「可执行、可验证、可扩规模」上发力：技能组合、证据锚定的任务生成、递归扩题。作者指出这些方法扩大了覆盖，但轨迹平均仍然偏短（文中 Figure 4 的对照），短轨迹能示范命令与工具调用，却很难示范 **证据如何跨阶段累积、计划如何被反馈改写、中间结果如何变成终交付**。

两个合成陷阱被单独点出：

| 陷阱 | 表现 | 后果 |
| --- | --- | --- |
| 环境代做关键活 | 材料里已有诊断、实现或验收集 | 轨迹里缺探索 / 实现 / 验证模式 |
| 只加难或加轮次 | 更难的题或更长交互 | 模式未必跨阶段连接，仍可能是一串短行为的拼接 |

这和 [MidHarness](../week1/20261002_MidHarness_论文解读_别再只扩整条轨迹_动作边界采样验证才救终端agent.md) 的「别只扩整条轨迹」、[ProgramGym](./20261013_ProgramGym_论文解读_从零复现程序缺可验证考场_1648黑盒环境加角色隔离把27B抬过旗舰脚手架.md) 的「可验证考场」、以及仓库里多篇 RSI / harness 笔记是同一条线：**环境与数据协议决定你能训出什么行为，而不只是模型规模。**

## 🏗️ 机制：任务包 + 两段合成 + 27 种行为模式

任务包形式化为 $T=(I,E,S,V,M)$，agent 执行时只见公开部分 $P(T)=(I,E)$：指令与环境；参考解 $S$、私有验证器 $V$、执行配置 $M$ 留给构建与评测。

设计目标不是「多敲几条命令」，而是保留连接探索、诊断、构建、验证与战略协调的工作。作者把这些过程收成 **五大家族、27 种 agentic behavioral patterns**（信息探索与判断、诊断与纠错、构建与推进、验证与保障、策略与执行协调）；TerminalHorizon-3K 轨迹平均含 **8.6** 个核心模式，覆盖 25 个一级专业域。

**第一段：Challenge-Guided Synthesis。** 外环由 Planner 根据已有任务与评审记录排下一批研究方向；内环用独立执行暴露「构建时被简化或代做」的工作，再据此重建环境。关键约束是：用来验任务的 agent **不能**是造任务的那个，否则会把构建捷径洗成「看起来很难」的假长程。

**第二段：Progressive Horizon Expansion。** 在同一目标下加新需求，且新工作必须依赖先前结果与执行反馈，让模式跨阶段延展，而不是另起一套无关难题。

采集时每任务最多两条轨迹（DeepSeek-V4-Pro-0813 + Terminus2），再按附录过滤标准留下 2,852 条；SFT 最大序列长 **262,144**，3 epoch。

## 🧪 关键证据或主结果

**Terminal-Bench（Table 1，节选）**

| 模型 | 轨迹量 | Scaffold | TB 1.0 | TB 2.0 |
| --- | --- | --- | --- | --- |
| Qwen3.5-27B（基座） | – | Terminus2 | 46.3 | 41.6† |
| Terminal-Universe-27B | 32.0k | Terminus2 | – | 52.8 |
| **TerminalHorizon-27B** | **3k** | Terminus2 | **55.0** | **55.8** |

† 为官方 model card。TB 2.1 上基座 46.82 → **60.67**（+13.85）。约十分之一轨迹量仍高出同基座的 Terminal-Universe-27B，是全文最硬的数据效率证据。

**跨域迁移（Table 2）**

| 基准 | Qwen3.5-27B | TerminalHorizon-27B |
| --- | --- | --- |
| AutomationBench Pass | 5.5 | **17.2**（+11.7） |
| AutomationBench Partial | 26.4 | **49.7**（+23.3） |
| τ²-bench Airline / Retail | 79.0 / 84.9 | **84.5 / 87.5** |
| VitaBench Cross-domain | 20.5 | **31.8**（+11.3） |
| MATH-500 / GSM8K | 96.9 / 96.3 | **98.9 / 97.3** |
| AIME 2024 / 2025 | 93.3 / 86.7 | **96.7 / 93.3** |
| KOR-Bench (Cipher) | 90.1 | **91.2** |

**Teacher 对照（Table 3，100 任务抽样）**：DeepSeek-V4-Pro 相对 GLM-5.2，均轮次 53.5 vs 46.1，均反馈链 30.3 vs 19.2，精确动作重复率 13.2% vs 15.8%，通过率 50.0% vs 44.0%，因此被选为正式 teacher。

**泼冷水**：

- 主结果是 SFT，不是 RL；长程能力有多少来自「模式密度」、多少来自「更强 teacher 轨迹」仍需更细消融；
- RSI 证据以案例为主（12 小时研究预算），不是大规模受控对比；
- 评测 scaffold 固定 Terminus2，换 OpenHands / Claude Code 类 harness 的迁移未系统报告；
- 环境重建依赖「独立执行诊断」，诊断本身也是模型行为，可能引入新的合成偏差；
- 通识榜基线已经很高，+1～6 点更多是「没伤到推理」的保险，不宜过度解读。

## 🔬 最有意思的部分

**「难」不等于「该有的模式出现了」。** 作者反复强调：任务可以很复杂，但若材料已替你做完调查或实现，轨迹里仍可能只有短行为。独立执行 + 重建，是把这个假阳性从数据管线里抠掉。

**渐进扩地平线靠依赖，不靠另起炉灶。** 附录里的多代分支例子（如库状态对账、跨系统身份恢复）每代都要求前代结果成为后代前提，这才是「跨阶段连接」的可操作定义。

**数据效率打脸堆量叙事。** 3k vs 32k 轨迹、同基座同 harness，TB 2.0 仍高 3 点，说明长程轨迹的信息密度可以高于大量短交互；这对「先堆百万短轨迹再谈质量」的默认路线是一记刹车。

**RSI 被当成交付能力来展示，而不是口号。** 12 小时预算下继续实验、按反馈改方法、把有效改进留进终产物，把「长程」从榜分数延伸到研究型工作流，和仓库里 [RSI-Harness](../../202609/week3/20260916_RSI-Harness_项目解读_切场景就是切Genome_Pi脚手架的可版本化.md)、[AIDE2-RSI](../../202609/week4/20260923_AIDE2-RSI_论文解读_双环RSI改自己代码_8天刷出能打两年人工工程的研究Agent.md) 的兴趣点对齐。

## 🤔 我的判断

定位：**长程终端训练数据的合成基础设施**，方法突破感中等，工程样本价值高。

亮点三条：**(1)** 把数据质量标准改成「行为模式及其连接是否被环境逼出」；**(2)** 独立执行驱动重建，专门对付「环境代做作业」；**(3)** 约 3K 轨迹打出跨 12 榜的稳定增益，并带 RSI 案例。

问题与局限：SFT 设定、teacher 依赖、scaffold 单一、RSI 偏案例；「27 模式」分类本身是否可复现、是否过拟合自家引擎，也还需外部复现。

对工程的直接启发：**(1)** 审计现有合成环境时，专门查「材料是否已替 agent 做完探索/实现/验证」；**(2)** 扩题优先加「依赖前代结果」的需求，而不是平行加无关难题；**(3)** 用未参与构建的 agent 跑一轮诊断再重建，比只看人工 checklist 更接近论文做法；**(4)** 报告轨迹时同时报均轮次、反馈链长与模式覆盖，而不是只报条数；**(5)** 若你在做 Pi / OpenClaw / Terminus 类终端 harness 的训练数据，TerminalHorizon-3K 的「挑战重建 + 渐进扩展」协议比直接抄分数更值得搬。

一句话收束：**终端智能的瓶颈往往不在「会不会敲命令」，而在环境有没有把探索、改计划与验收留在 agent 必须自己走完的路上；TerminalHorizon 用合成引擎把这条路重新铺开了。**
