# 具身世界当图灵机：状态写进代码，决策也写代码，测试时不再调模型

你有没有过这种体验：给机器人挂上 Agent Harness，每一步都问一遍 VLM「现在该干什么」，演示很炫，延迟和费用也跟着炫；失败了去翻上下文，只看见一堆自然语言推理，很难定位是哪一个状态变量错了。另一边 VLA 把状态揉进权重，改一个任务常常要重训，还可能伤到旧任务。有没有第三条路：**把可测的状态放进变量，把决策写成可检查、可合并的代码，运行时干脆不调模型？**

南洋理工与 Ropedia 的 **Embodied Turing Machines / COAP**（arXiv:2610.12369）把具身世界看成 Embodied Turing Machine：纸带是机器人与环境状态，规则是策略。若状态表示足够准，决策就可以全部写成代码。他们提出 **Code-Only-as-Policy（COAP）**，并用 coding agent 在封闭 RSI 环里离线把共享库写出来。看完我的感受：这是一篇立场很冲的范式文，数字扎眼，局限也写得直白；对做 harness / RSI / 「代码即策略」的人，它提供的是一个可攻击的上界，而不是又一个要在环内调用的脚手架。

## 核心摘要

COAP 让代码从相机图像与本体感觉中 **测量并跟踪** 机器人、环境与任务状态，并据此做出每一步决策；同一段代码跨 episode 复用，不同任务共享一个库，**测试时环内无 VLM / VLA**。相对 VLA 与 Agent Harness（Agent-as-Policy / Harness VLA），作者归纳三项优势：**显式状态**（状态存代码变量）、**执行**（可控、可回退恢复、在线又快又便宜）、**可扩展**（新任务复用 / 继承 / 扩展共享库，能力可累积）。这三项使 COAP 适合作为 **递归自我改进（RSI）** 的介质：coding agent（文中为 Opus 5.5 Max）在固定规则下离线总结、写代码、调试，禁止为单 episode 开后门、禁止测试时用 oracle 状态，且 **不接触 benchmark 测试集**。在 RoboDojo 的 **42** 个双臂任务上，得到的库成功率 **70.24%**、进度分 **75.45**，相对当时榜首 Agent Harness 方法 PhysicalRSI（31.38% / 36.27%）高出约 **38.9 / 39.2** 个百分点，并在 Memory / Precision / Open / Generalization / Long-Horizon 五个切片上全面最高。失败归因里约 **62%** 来自状态测量上限（感知 35%、接触 27%），约 **37%** 来自代码逻辑上限。价值定位：把「agent harness 是否必须在环」这个问题用一个极端答案钉住——状态够准时，策略可以是纯代码，模型退到离线写库与产数据。

## 🎯 为什么这件事值得写

作者把当代具身策略粗分成三条，并在 Table 1 上按「显式状态 / 执行 / 可扩展」对照：

| 路线 | 状态放哪 | 在线谁决策 | 典型痛点 |
| --- | --- | --- | --- |
| VLA / WAM | 权重与近期帧 | 网络逐步输出 | 黑盒、难编辑、新任务易伤旧任务 |
| Agent-as-Policy | 上下文里的推理文本 | 每步问 LLM | 贵、慢、状态不准且难持久 |
| Harness VLA | 文本记忆 + VLA | LLM 调度 + 网络执行 | 仍每决策付模型税 |
| **COAP** | 代码变量 | 代码 | 需任务侧逻辑；泛化靠扩库 |

关键分野不是「要不要 foundation model」，而是 **模型在不在控制回路里**。Agent Harness 把模型留在环内换柔性；COAP 把模型挪到环外写库，用显式状态换可检视、可回退与零在线模型成本。这和仓库里对 harness 可版本化、RSI、以及「技能/规则应可累积」的兴趣一致，只是场景从终端/IDE 换成了双臂操作。

## 🏗️ 机制：状态作纸带，代码作规则，RSI 写库

直觉上的控制循环是：

1. `state_update(obs)`：从观测写入/更新状态寄存器；
2. `action = plan(state, goal)`：纯代码决策；
3. `execute(action)`；
4. `check_and_recover(state)`：失败则回退并再试。

执行期代码参数 $\theta$ 固定，变化的是状态 $x_t$；新布局改变的是测到的状态，而不是要求每集重写策略。共享库按感知、运动、接触、抓取等功能组织，任务脚本调用库；新能力默认关闭，避免一个任务的改动悄悄改写所有任务路径。

**离线 RSI 环**：多个 coding agent 各在 git worktree 提 diff，形成可运行分支前沿 $C_k=\{\theta_k+\Delta_{k,1},\ldots\}$。上仿真前先过 CPU 检查（数值场景下阶段是否到达目标态、网格与碰撞 / IK）；通过后再在 **validation** 布局上并行评测。调试看开发集视频并对照仿真真值状态；验收要求成功数相对当前库提升超过噪声边界 $\epsilon_q$。测试集布局不参与开发。

## 🧪 关键证据或主结果

**RoboDojo 主结果（Table 2，成功率 %）**

| 方法 | Memory | Precision | Open | Generalization | Long-Horizon | Overall SR | Score |
| --- | --- | --- | --- | --- | --- | --- | --- |
| PhysicalRSI（Agent Harness） | 46.6 | 32.5 | 24.9 | 15.6 | 37.3 | 31.38 | 36.27 |
| Awomo-0.5（最强 WAM） | 41.2 | 33.5 | 22.9 | 23.8 | 26.8 | 29.64 | 35.34 |
| Simate-beta（表中最强 VLA 档） | 33.0 | 26.9 | 8.5 | 27.9 | 43.4 | 27.96 | 33.95 |
| **COAP** | **89.9** | **75.1** | **64.1** | **65.7** | **56.4** | **70.24** | **75.45** |
| vs. best | +39.6 | +41.6 | +33.1 | +35.2 | +13.0 | **+38.86** | **+39.18** |

五维全胜，且相对最强 Agent Harness / WAM / VLA 的总体成功率为数十分的间隔，不是边角优势。

**失败结构（文内归因）**：状态测量上限约占 **62%**（感知误差 35%、接触误差 27%）；代码逻辑上限约占 **37%**（逻辑不全 29%、设计差 8%）。作者据此声称 COAP 的上界主要由「状态测得准不准」和「代码逻辑壮不壮」决定。

**泼冷水**（作者 Limitations + 读写判断）：

- **仅仿真**：感知依赖公开配置与资产（相机参数、网格、物体尺寸）；真机需重测与重调接触参数；
- **离线开发贵**：在线执行快，但每个新任务都有写库与评测成本，不能像即插即用的大模型策略那样开箱就跑；
- **泛化仍要任务侧代码**：作者承认需要少量任务特定逻辑；他们的辩护是 Agent Harness 同样常带任务级甚至 episode 级记忆；
- 主结果相对榜上方法的巨大间隔，部分可能来自「仿真可测状态 + 禁止测集泄漏」的设定与 VLA/Harness 训练评测协议并不同构，跨范式横比要谨慎；
- coding agent 写库的随机性与算力成本未系统报告。

## 🔬 最有意思的部分

**把 Agent Harness 从「默认架构」降级成「一种可选回路」。** 当状态可显式测量时，环内再问 VLM 就变成付费的柔性，而不是必选项。这对「万事皆 agent」的风气是一剂清醒剂。

**RSI 的介质换成可 diff 的库。** 每次改进是显式、可检视、可默认关闭的代码变更，而不是又一次不可解释的权重更新；这和 harness genome / 技能库可版本化的工程直觉同构。

**失败分类本身就是诊断工具。** 62% vs 37% 把「该先重感知还是先重逻辑」变成可汇报的产品决策，而不是笼统说「再 scale 一下」。

**COAP 也可当数据引擎。** 因为策略跨 episode 稳定、便宜，成功轨迹可以反哺 VLA 与 Agent Harness 训练——模型不在环，不代表模型无价值，只是价值被挪到环外。

## 🤔 我的判断

定位：**具身策略的范式样本 / 上界探索**，对「代码世界 + RSI」路线极有启发，对「真机通用操作」仍早。

亮点三条：**(1)** 显式状态 + 纯代码决策把可检视性与在线成本一次做掉；**(2)** 封闭 RSI 写共享库，且明确隔离测试集；**(3)** RoboDojo 上 70.24% 的数字足够尖锐，能逼迫社区回应「环内模型是否必要」。

问题与局限：仿真依赖重、真机未证、任务侧代码与泛化张力仍在；与 VLA/Harness 的横比协议不完全同构。

对工程的直接启发：**(1)** 设计 agent harness 时先问：哪些状态可以变成测量变量，而不是留给上下文；**(2)** 把可回退的状态机与恢复逻辑写进代码层，模型只处理测不准的残差；**(3)** RSI / 技能进化优先改可 diff 的共享库，并默认关闭新路径以免污染旧任务；**(4)** 失败日志按「状态测量 vs 逻辑」归档，而不是只存整段对话；**(5)** 对终端/IDE agent，也可借鉴「环外写库、环内少调模型」：能编译成确定性工具的，就不要每步再问一遍 LLM。

一句话收束：**COAP 不是宣布 Agent Harness 已死，而是给出一个刺耳的对照：当状态测得够准，最强的在线策略可以是一段不再调用模型的代码，模型的舞台在离线把这段代码写对。**
