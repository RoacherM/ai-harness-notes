# 脚手架进化了，模型没跟上：从档案里挑旧权重，配给新身体

你有没有过这种体验：harness 迭代了一版，加了个更聪明的上下文管理工具，把工具调用格式从 XML 换成了 JSON，回归一跑，分数反而掉了。翻日志一看，模型的意图其实是对的，只是它还在按老格式吐调用，被新 harness 一条条拒掉；或者新工具摆在那儿，它根本不会用。你一开始怀疑是 harness 改坏了，后来发现：**不是脚手架不好，是这颗「脑子」和这副「身体」对不上。**

新加坡国立大学、A*STAR 和商汤的这篇 **When Harnesses Evolve, Which Models Should Follow?**（CoEvo-RSI，arXiv:2610.25078）给这个问题起了名字：模型与 harness 共进化里的 **brain–body mismatch（脑体失配）**。它的回答也很直接：每一轮别只拿最新的模型去配最新的 harness，而是让一个元 agent 翻整个进化档案，**harness 可以从任意一代祖先改起，模型可以从任意一代检查点挑起甚至合并**，挑出最合拍的一对再做 SFT。看完我的感受：这是我读过的第一篇把「harness 改完，权重该从哪儿接」当成一等问题来做的 RSI 论文，结论对任何同时调脚手架又调模型的团队都很实用。

## 核心摘要

CoEvo-RSI 把每一轮共进化拆成两步「历史继承」。第一步是 harness 继承：先在验证集上诊断当前这一对（harness, 模型）的失败，一个 Curator 去档案里检索相关的历史设计和结果，整理成证据和 K 个修改假设；K 个独立的 harness 编辑器各拿一个假设，**自己在档案里挑起点**（不一定是最新一版），改出子代 harness。第二步是模型继承：元 agent 读检查点的来历和它们在各自 harness 下的表现，给每个子代 harness 配一个检查点，可以 one-hot 选一个，也可以给出权重用 TIES-Merging 合并多个；按验证集分数挑出最好的一对，再用它自己的拒绝采样轨迹做一轮全参 SFT，最后在「原来那对、挑出来那对、SFT 后那对」里按验证集加最小涨幅门槛决定谁晋级。所有结果，包括失败的修改，都带着谱系回写档案。作者还提出一个很便宜的诊断量 **TIMR（回合级接口失配率）**：每个模型回合里调用不存在的工具、违反接口约定或输出格式错误就记一次。实验用 Qwen3.5-9B 做任务模型，Codex 里的 DeepSeek-V4.1-Flash 当元 agent，十轮、每轮 8 个候选，只靠 SFT，在多 agent 失败归因、带权限的 text-to-SQL、智能家居指令三类垂直任务上追平或超过大得多的模型：TraceElephant 的 Who 准确率 70.78%，比 DeepSeek-V4-Pro 高 14.16 点；HomeBench VM 成功率 75.51%。消融里最关键的一条：只用最新一代的 Latest-only 在第 4 轮回退后一路垫底，完整版则在第 6 和第 8 轮**把第 4 轮的旧权重配上新 harness** 才爬回来。价值定位：给「模型和脚手架一起进化」补上了配对选择这一环，并给出一个可以直接接进 CI 的失配信号。

## 🎯 为什么这件事值得写

过去一年的自进化工作基本分两路。一路冻住模型改 harness：Meta-Harness 让提议者读完整的历史代码和轨迹，Self-Harness、AutoHarness 用执行反馈迭代提示词、工具和控制流。另一路冻住 harness 训模型：SFT、GRPO、GSPO、自蒸馏。两路在「共进化」里会合，比如 HarnessForge。

问题是，两边一起动的时候，它们会**互相漂走**：

| 失配类型 | 典型表现 | 后果 |
| --- | --- | --- |
| 接口失配 | 模型吐 XML，新 harness 只收 JSON | 意图正确的调用被拒 |
| 能力失配 | harness 新增主动上下文管理工具 | 没学过的模型乱用或不用 |
| 反向失配 | harness 收紧了流程 | 模型已有的能力被限制住 |

作者的关键观察是：解决失配的最好起点**常常不在最新一代**。某个老检查点可能恰好已经会某种操作，某个老 harness 设计可能恰好更贴合现在模型的能力。只往前看最新一代的共进化，会把这些可用的祖先丢掉。

## 🏗️ 机制：双向历史继承

**目标函数。** 对任务分布 \( \rho \)，一对 \( p=(\mathcal{H},\theta) \) 的价值是固定评估器打分的期望：

$$
J(\mathcal{H},\theta)=\mathbb{E}_{x\sim\rho}\,\mathbb{E}_{\tau\sim P_{\theta,\mathcal{H}}(\cdot\mid x)}\left[s(x,\tau)\right]
$$

**TIMR。** 设 \( n_{\text{lm}}(\tau) \) 是轨迹的模型回合数，\( v_{\tau,u}\in\{0,1\} \) 标记第 u 个回合是否出现接口违规：

$$
\text{TIMR}(\mathcal{H},\theta)=\frac{\sum_{\tau}\sum_{u=1}^{n_{\text{lm}}(\tau)} v_{\tau,u}}{\sum_{\tau} n_{\text{lm}}(\tau)}
$$

违规回合即使后面自己恢复了也照样计一次。作者明确说它只覆盖可观察的接口违规，不等于完整的脑体对齐。

**一轮的流程。**

1. **诊断**：当前对在验证集上跑一遍，得到反馈 \( F_t \)。
2. **Curator 检索**：在检索预算和上下文预算内翻档案索引，产出证据 \( e_t \) 和 K 个修改假设。
3. **harness 继承**：K 个编辑器各自浏览档案、挑一个历史 harness 当起点，吸收其他历史设计，产出子代，并记录采用了哪些祖先。
4. **模型继承**：对每个子代 harness，元 agent 根据证据和预评估结果给出合并系数 \( \boldsymbol{\alpha} \)，一个检查点就是 one-hot，多个就走 TIES：

$$
\theta(\boldsymbol{\alpha})=\text{TIES}\left(\{\theta_j\};\boldsymbol{\alpha}\right),\quad \alpha_j\ge 0,\ \sum_j\alpha_j=1
$$

5. **适配**：挑出的最好一对，在训练集上每题最多采 3 条轨迹，取第一条通过验证器的，做一轮全参 SFT（学习率 5e-6，batch 8，4 张 H100）。
6. **晋级**：在原对、选出对、SFT 后对之间比较，涨幅必须超过门槛才替换；所有结果连同谱系和合并系数写回档案。

## 🧪 关键证据

**失败归因（四个基准都是 OOD，未参与训练和选择，三次平均）。**

| 系统 | W&W Pro Who | TraceElephant Who | TraceElephant When |
| --- | --- | --- | --- |
| Qwen3.5-9B 原始 | 57.20 | 25.57 | 4.11 |
| Meta-Harness | 40.46 | 51.60 | 9.13 |
| Self-Harness | 47.94 | 49.77 | 7.76 |
| GSPO | 62.00 | 47.03 | **38.36** |
| HarnessForge | 63.03 | 50.23 | 8.68 |
| Qwen3.8-Max 直接答 | 65.03 | 47.03 | 32.42 |
| DeepSeek-V4-Pro 直接答 | 61.77 | 56.62 | 31.96 |
| **CoEvo-RSI** | **69.43** | **70.78** | 28.92 |

Who&When Hand 上 CoEvo-RSI 的 Who 是 68.39%、When 是 29.31%，高于最强的 harness 增强系统 FALAT + MiniMax-2.5（66.30、25.90），比 Self-Harness 高 11.49 点。

只改 harness 的两种方法在 TraceElephant 的 When 准确率都跌到 10% 以下；RL 基线在两个基准的 When 上反而比 CoEvo-RSI 高。Who&When Algo. 上它也没赢（Who 62.17，最强基线 68.25）。

**带权限的 text-to-SQL（RBAC Spider）。** Safe-EX 80.85%、Safe-Deny 96.64%、违规率 1.57%，略好于 Pi + MiniMax-M3（80.26、96.33、1.72）。十轮里 harness 先后长出「证据检查」「所有引用都要授权」「验证加一次有界修复」三个结构，违规率从 2.00% 降到 1.57%。OOD 的 BIRD 子集上 Safe-EX 60.15，略低于 GLM-5.3 的 60.90，但违规率最低。作者自己也承认，这种安全与效用的平衡可能部分来自更保守的拒答。

**成本。** 三轮的共进化跑一次 API 花费 2.06 到 3.69 美元，一天内结束；推理端在 Who&When Hand 上比 DeepSeek-V4.1-Flash 高 8.05 点，便宜 22 倍。

**泼冷水。** 第一，三个领域都是作者刻意挑的窄垂直任务，论文自己写了「RSI 还是过拟合」一节，承认结论不保证跨领域迁移。第二，主要对比都是「9B 共进化系统」对「大模型直接答」，很多大模型没有配专门 harness，差距里有多少来自 harness 本身不好拆。第三，消融曲线和配对热力图来自单次运行，K 的敏感性只跑了三轮。第四，TIMR 全程都压在 0.22% 以下，绝对值很小，它是不是性能差异的主因，论文给的是相关证据。

## 🔬 最有意思的部分

**一是「旧权重配新 harness」真的发生了，而且是赢的关键。** RBAC 那张 harness 乘检查点的 TIMR 矩阵里，前三轮选中的配对平均归一化 TIMR 约 0.72，第 6 到 10 轮降到 0.13；十轮里有七轮选中的正是当时可用的 TIMR 最低的检查点。五轮直接复用已有权重，之后所有新派生的检查点都和第 3 轮那个合并过。最戏剧的是第 10 轮：第 3 轮的检查点在第 4 到第 9 代 harness 下 TIMR 都很高（归一化 0.54 到 1.00），偏偏在最终 harness 下只有 0.02，并拿到全程最高的 Safe-EX。**兼容性是配对属性，不是模型属性**，只看最新一代的策略一定会错过这种组合。

**二是两种单边进化的病各不相同。** Harness-only 十轮里有八轮 TIMR 超过 1%，说明脚手架自己越改越远，模型跟不上；Model-only 的 TIMR 接近零，但 SA 封顶在 35%，说明只是「接口对得上」远远不够。两边都动、还能回头找祖先，才把准确率和兼容性同时拿住。

**三是 harness 演化出的结构很像人会写的东西。** SQL 任务里依次出现的「拒答要有证据」「每个表和列都要过权限」「验证后只修一次」，失败归因里出现的「agent 摘要恢复」「按预算覆盖证据」「证据复核」，都是可读、可审的流程件，不是黑箱提示词。这让共进化的产物可以被人接手。

## 🤔 我的判断

**定位：方法论文，但最值钱的是问题定义和 TIMR 这个信号，不是具体的榜单数字。**

亮点三条：

1. 把「脑体失配」形式化，等于给共进化加了一个以前没人显式管的约束。改 harness 时顺手量一下失配率，成本几乎为零。
2. 档案加谱系的设计让「回退到第几代、从哪一代分叉」变成元 agent 可以推理的事实，而不是工程师凭记忆。
3. 只用 SFT 加拒绝采样就做到这个程度，复现门槛低，适合小团队做垂直 agent。

问题与局限：领域窄、对照组 harness 不对等、关键分析单次运行；TIMR 只覆盖格式和接口层，能力层的失配（会不会用新工具）还没有对应的度量；元 agent 本身用的是强模型，它的判断质量对结果影响多大没有消融。

对工程的直接启发，尤其是 Pi 这类显式 Manifest、SDK 版本钉住的 harness：

- **harness 版本和模型检查点要一起打版本号，配对结果要入库。** Manifest 每变一版，就在固定回归集上把它和最近几个检查点都跑一遍，存成一张配对表。
- **把 TIMR 接进回归。** 未知工具名、参数 schema 不符、格式解析失败，按回合计数，作为 harness 变更的阻断信号之一，和任务分数并列看。
- **升级 harness 时别默认用最新模型。** 新加的工具或流程如果在老检查点上 TIMR 更低，就从老检查点接着训，或者先合并再训。
- **失败的修改也要留档。** 被拒的 harness 和检查点是下一轮最有用的反例。

一句话收束：**harness 和模型一起进化时，真正要选的不是最新的谁，而是最合拍的那一对。**
