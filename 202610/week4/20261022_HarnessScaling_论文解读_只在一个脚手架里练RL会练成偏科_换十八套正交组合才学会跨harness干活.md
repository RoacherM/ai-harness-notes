# 只在一个脚手架里练 RL 会练成偏科：换十八套正交组合，才学会跨 harness 干活

你有没有过这种体验：一个在自家 harness 里 RL 过的模型，跑内部评测分数很好看；换到 Claude Code 或 OpenClaw 里，工具名一变、观察格式一变、上下文压缩策略一变，表现立刻掉一截。你开始怀疑，它学到的到底是「怎么干活」，还是「怎么在这一个脚手架里干活」。

人大高瓴、IQuest Research 和北航的这篇 **Harness Scaling for Generalizable Agentic Reinforcement Learning**（arXiv:2610.29458）把这个问题正面摆上桌：agentic RL 过去一直在扩任务（what to solve）和扩环境（where to operate），**执行它们的 harness 却几乎总是固定的一套**。作者提出把 harness 本身当成第三条扩展轴（how to execute），并且给出一套很「实验设计学」的做法：把 harness 拆成五个组件，用强度为 2 的正交表从 243 种组合里挑 18 种来训练。看完我的感受：这是第一次有人把「训练时换脚手架」做成了可控、可复现、可消融的方法，而不是随手多挂几个 harness 碰运气。

## 核心摘要

作者把一个 harness 分解成五个组件：系统提示词 S、工具接口 T、观察 O、上下文管理 C、工作流 W。每个组件有一个基础实现和若干变换（重写提示词结构、改工具 schema 和命名、改环境反馈格式、改上下文保留或压缩方式、强加不同执行流程），每个变换只动目标组件，不动任务语义和环境。每个组件取 3 种实现，完整空间就是 \(3^5=243\) 种配置，构成一张 Hamming 图。训练集不是全量，也不是随机挑，而是用强度 2 的正交设计挑出 18 种，保证每个组件的每种实现出现次数相同，任意两个组件的任意实现两两组合出现次数也相同。RL 时每道题先均匀抽一个锚点 harness，再配上 Hamming 距离最近的 \(K-1\) 个邻居（默认 \(K=2\)），连续两步在两个相近 harness 下训练同一道题。在 ClawGym-Task 1.35 万道工作区任务上用 Qwen3-4B-Instruct 和 Qwen3-30B-A3B-Instruct、GRPO 和 PPO 各训 300 步，在 ClawGym-Bench、PinchBench、JobBench-Easy 三个基准上评测：**18 种留出配置上的平均分，4B 用 GRPO 从 29.81 涨到 39.04，30B 用 GRPO 从 37.29 涨到 42.78**；更关键的是在没见过的 Claude Code 上，结构化白盒训练平均 37.22（4B）和 41.20（30B），**反而超过了直接在 OpenClaw 这个复杂黑盒 harness 里做 SFT（35.08、38.08）和做 RL（33.38、36.28）**。还有一个很反直觉的消融：在全部 243 种配置上训练，同样预算下不如这 18 种，哪怕全量训练集里包含了评测用的配置。价值定位：把「harness 多样性」从工程直觉变成了有设计原则的训练维度。

## 🎯 为什么这件事值得写

过去一年 harness 工程有两条主线：一条是改 harness 本身（搜索、编辑、进化，比如 Meta-Harness、Harness-R1、HarnessBank）；另一条是让模型适配某个 harness（Agent Lightning、ClawGym II 这类直接在黑盒 harness 里 RL）。两条线都默认 harness 是一个固定对象。

问题在于，真实部署里 harness 是会变的：同一个模型可能同时被 Claude Code、OpenClaw、Pi、内部 agent 框架调用，每家的工具命名、观察截断、压缩阈值、工作流约束都不一样。只在一个 harness 里训，很容易训出对那套 schema 和反馈格式的依赖。这篇的切入点就是：**能不能在训练时就让模型见过「同一道题、不同执行方式」，从而学到跟脚手架无关的执行能力。**

## 🏗️ 机制：把 harness 当成一张因子设计表

**因子化空间。** 每个组件 \(F\in\{S,T,O,C,W\}\) 有基础实现 \(F^{(0)}\) 和变换 \(\tau_F^{(\ell)}\)：

$$
F^{(\ell)}=\tau_F^{(\ell)}\left(F^{(0)}\right),\qquad \mathcal{H}=\mathcal{S}\times\mathcal{T}\times\mathcal{O}\times\mathcal{C}\times\mathcal{W}
$$

两个配置之间的 Hamming 距离 \(d_{\mathcal H}\) 就是它们不同组件的个数，相邻配置只差一个组件。

**强度 2 正交设计。** 作者只保证一阶和二阶投影均衡：每个组件的每种实现出现次数相同，任意两组件之间每对实现出现 \(\lambda\) 次：

$$
N_{ij}(\ell,\ell')=\lambda,\qquad N=\lambda L^2,\qquad N\ge 1+M(L-1)
$$

\(M=5\)、\(L=3\) 时，Rao 下界是 11，取 \(\lambda=2\) 得到 \(N=18\)。243 种完整组合里大部分在训练中没出现过，正好拿来测组合泛化。

**局部感知的任务分配。** 每道题抽一个锚点，再配最近的邻居：

| 设计 | 作用 |
| --- | --- |
| 锚点均匀采样 | 不同题分散到整个训练集，保证全局覆盖 |
| 最近邻配对 | 同一道题看到「只差一两个组件」的执行方式，形成受控的局部变化 |
| 连续 K 步 | 两个 harness 各给一步梯度，优化目标本身不变（标准 clipped 目标，PPO 和 GRPO 都能用） |

方法对 RL 算法是透明的：它只决定 rollout 用哪组 (题目, harness) 实例，不改损失函数。

## 🧪 关键证据

**主表（Pass@1，三次评测平均，In-Space 是 18 种留出配置的平均）。** 以 Qwen3-4B 加 GRPO 为例：

| 基准 | 单 harness RL（留出 / Claude Code） | Harness Scaling（留出 / Claude Code） |
| --- | --- | --- |
| ClawGym-Bench | 37.33 / 38.96 | 52.78 / 45.37 |
| JobBench-Easy | 10.24 / 5.79 | 13.55 / 14.83 |
| PinchBench | 45.60 / 40.95 | 56.24 / 51.47 |
| 六列平均 | 29.81 | 39.04 |

留出配置上的平均增益：4B 用 GRPO 加 9.80、用 PPO 加 3.57；30B 用 GRPO 加 5.21、用 PPO 加 4.90。

**对黑盒 harness 的迁移。** Claude Code 作为完全没参与训练的外部 harness：4B 上 Harness Scaling 平均 37.22，黑盒 SFT 35.08，黑盒 RL 33.38；30B 上分别是 41.20、38.08、36.28。黑盒基线都是在 OpenClaw 里训的。**在简单但结构化变化的白盒 harness 里训，迁移到另一个复杂黑盒，比直接在一个复杂黑盒里训更好。**

**没付偏科税。** 30B 加 GRPO 在训练用的基础 harness 上，单 harness 59.82，Harness Scaling 59.63，只掉 0.19；同时留出配置涨 10.48，Claude Code 涨 3.60。

泼点冷水：JobBench-Easy 的绝对分很低（个位数到十几），这个基准上的差距波动意义有限；只用了 Qwen3 一个系列；附录里 OpenClaw 作为评测 harness 的结果我没细核。

## 🔬 最有意思的部分

**一是全量 243 不如精选 18。** 消融里，单 harness 换成 3 种一阶覆盖的 harness，ClawGym 留出加 11.43、黑盒加 4.84；再换成正交 18 种，又加 4.02 和 1.57；随机 18 种和全量 243 种都比正交 18 差。全量训练甚至包含了留出评测用的配置，还是输。作者的解释是固定预算下，穷举带来的是冗余，**多样性怎么组织比多样性有多少更重要**。

**二是「同题换 harness」本身有用，不只是多看一遍。** \(K=1\)（每题只配一个 harness，但不同题分散在 18 种里）已经明显好于单 harness；\(K=2\) 再涨。作者专门做了 Repeat-2 对照：同样两步调度，但两步用同一个 harness，结果涨跌不一，而 \(K=2\) 在两个基准、两种评测下都稳定更好。\(K=4\) 没有继续涨。把最近邻分配换成随机分配，ClawGym 掉 2.32 / 2.20，PinchBench 掉 3.04 / 1.24。

**三是涨的是哪类能力。** 作者按六个维度给 200 条轨迹打分：指令遵循、接口处理、观察阅读、状态跟踪、工作流遵守、错误恢复。涨得最多的是**状态跟踪、工作流遵守和错误恢复**，观察阅读涨得最少。换句话说，换脚手架训练主要练的是「环境变了还能把进度和流程维持住」，而不是读懂某种格式。两个相差四个组件的留出 harness 上，同一道题的奖励也更贴近对角线，跨 harness 一致性更高。

## 🤔 我的判断

**定位：训练方法加实验设计范式，对做 agentic RL 和维护多 harness 产品的人都直接有用。**

亮点三条：

1. 把 harness 拆成 S/T/O/C/W 五个可独立变换的组件，这个分解本身就是一份很实用的 harness 抽象清单，和 Rules/Skills/Extensions/MCP/Hooks 这类 manifest 思路可以对齐。
2. 用正交表而不是随机或穷举来选训练配置，并且用全量 243 输给精选 18 的结果证明了这一点，很有说服力。
3. 白盒结构化变化胜过黑盒直训，意味着不必拿到每个商业 harness 的内部实现，也能训出对它们更稳的模型。

问题与局限：只有 Qwen3 两个尺寸；任务分布集中在工作区类通用任务；五个组件的变换是人设计的，变换的「强度」如何影响结果没细拆；也没和「改 harness 本身」那条路线做联合对比。

对工程的直接启发：

- **自研 harness 的回归评测，至少要跑一组正交变体。** 把工具命名、观察格式、压缩阈值、工作流约束各做两三种实现，用 L18 正交表挑组合跑评测，比只在默认配置上看分更能发现模型对 harness 的依赖。
- **做 RL 或 SFT 数据时，同一道题配两个相邻 harness。** 成本只是多一步，却能明显减少对单一 schema 的过拟合。
- **对确定性 harness（比如显式 manifest、ambient 关掉的那类）尤其重要。** harness 越确定，模型越容易贴着它长；训练时主动引入受控变化，是保住可迁移性的便宜办法。
- **能力评测别只看总分。** 按状态跟踪、工作流遵守、错误恢复这类维度切片，才知道换脚手架时到底是哪种能力在掉。

一句话收束：**模型学会的不该是某一套脚手架的长相，而是脚手架换了之后还能把活干完；办法不是把所有组合都喂一遍，而是像做实验一样有设计地换。**
