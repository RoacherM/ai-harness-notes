# 同一张登录页，点「登录」后出现是正常，点「查看订单」后出现就是劫持：GUI agent 的验证器要看转移，不看屏幕

你有没有过这种体验：手机上点了一个「查看订单」，结果跳出来一个要你输邮箱和密码的登录页。页面做得很像样，logo、配色、输入框都对，你差一点就输了。如果换成一个替你操作手机的 GUI agent，它大概率会输，因为它看到的是一张「完全正常」的登录页。行业里管这类攻击叫 **transition hijack（转移劫持）**：每一张屏幕都合法，问题只出在「这一步之后不该出现这一屏」。

南洋理工、东京科学大学和 Sony AI 的这篇 **Right Screen, Wrong Transition: World Models as Verifiers for GUI Agents**（arXiv:2610.11942）把这个问题说得很透：**安全是转移的属性，不是屏幕的属性**，所以只看结果屏幕的检测器，理论上就赢不了。要判断一次转移是否正常，必须先有「这个动作之后本该出现什么」的预期，这正是世界模型的本职。看完我的感受：这篇把世界模型从「模拟器」和「规划器」之外，正式推到了第三个角色，**运行时验证器**，而且给出了一个 17 毫秒就能跑一次的工程答案。

## 核心摘要

作者提出 LGWM（Latent GUI World Model）：给定当前截图和一个结构化动作，直接预测下一屏在编码器表示空间里的样子，没有任何解码器，不渲染像素、不生成文本或代码。因为预测和观测落在同一个空间里，验证就退化成一次余弦相似度：\( q_{int} = 1-\cos(\hat z_{t+1}, z^{obs}_{t+1}) \)，不需要再请一个 VLM 当裁判。模型基于 DINOv2 ViT-B/14 编码器加 12 层 Transformer 预测器，在 185 万条真实 GUI 转移上纯自监督训练，推理时 1.73 亿参数。为了测「看屏幕必然失败」这件事，作者造了 RSWT-Bench：222 对样本里，同一张像素级相同的凭证页，一次作为合法结果出现，一次作为劫持结果出现，因此**任何只看结果屏幕的检测器期望 AUC 恰好是 0.5**。在这个基准上，免训练的一致性分数拿到 0.987 AUC，和 Gemini 3.7 Flash（0.995）、GPT-5.6 Luna（0.988）在统计上分不开，比渲染式 GUI 世界模型 gWorld-8B（0.885）和 Code2World（0.870）高约十个点，延迟却低三个数量级以上（17.1 ms 对 9 到 11 万 ms）。更有意思的是第二个读数：残差的大小只能说明「出乎意料」，判断「是否有害」时只有 0.513；而残差的方向接一个线性头，就能把有害违背和无害违背（推送通知、布局变化）分开到 0.953，此时所有提示式 VLM 都接近随机。价值定位：一个可以每步都跑的转移完整性门禁，加上一个「先便宜地筛、再贵地判」的分层验证范式。

## 🎯 为什么这件事值得写

GUI agent 和物理世界里的机器人有一个根本区别：它操作的界面是第三方做的，App、网页、广告都可能不诚实。环境本身可能在和 agent 作对。现有的 GUI 安全评测大多考的是「这一屏看起来危险吗」，于是检测器学会的是「危险屏幕长什么样」。而转移劫持专门绕开这一点：它复用一张合法屏幕，只是把它放在了错误的位置。

另一条线是 GUI 世界模型，比如 gWorld、Code2World、MobileWorld-HTML。它们确实持有「下一屏应该是什么」的预期，但它们把预期渲染成文字、DOM 或图像。作者的批评一针见血：**渲染出来的东西人能看，机器不好比**。一段文字和一张截图不是同一种对象，判断两者是否一致又变成了一个需要裁判的问题，而这个裁判本身也得被信任。原文的说法是「需要裁判的验证器没有解决问题，只是把问题挪了个地方」。再加上渲染一次要一两分钟，根本没法每一步都跑。

这和我们在 harness 里做 judge 的经验高度同构：很多时候我们让一个大模型去比「期望」和「实际」，其实是因为期望没有被表示成可以直接比较的形式。

## 🏗️ 机制 / 任务定义

**形式化。** 设 \( P^\star(s_{t+1}\mid s_t,a_t) \) 是未被篡改的界面对动作的响应分布。一次转移 \( (s_t,a_t,s_{t+1}) \) 具有完整性，当且仅当结果与 \( P^\star(\cdot\mid s_t,a_t) \) 相容。因为同一个 \( s_{t+1} \) 在一种上下文里相容、在另一种里不相容，**不存在只依赖 \( s_{t+1} \) 的函数能度量完整性**。

**架构。** 三块：

| 组件 | 做什么 | 关键设计 |
|---|---|---|
| 屏幕编码器 \( f_\theta \) | 448×224 截图映射为 32×16 共 512 个 768 维 patch token | DINOv2 ViT-B/14，分层学习率衰减微调 |
| 动作编码器 \( e_\psi \) | 动作类型 token + 文本的 MiniLM 句向量 + 坐标 token | 触点坐标和视觉 patch 共用同一套二维正弦位置编码 |
| 预测器 \( g_\phi \) | 输出下一屏完整的空间 token 图 | 12 层 Transformer；目标由 EMA 编码器提供，停梯度 |

**训练目标。** GUI 转移很稀疏，一次点击往往只改一小块。均匀损失会把容量浪费在复现不变的背景上，所以作者用像素差得到二值变化掩码，把变化区域的权重乘 8：

$$
L_{pred}=\frac{\sum_p w_p\, d(\hat z_{t+1,p},\bar z_{t+1,p})}{\sum_p w_p},\quad w_p = 1+(\lambda_{chg}-1)m_p
$$

另有两个辅助目标：VICReg 防止表示塌缩（塌缩了，所有预测都和所有观测很像，一致性分数就饱和了）；逆动力学头从前后两帧还原动作，保证表示里保留「是哪个动作造成的」（否则劫持结果和另一个动作的合法结果就分不开）。3 万步之后再加入两到三步的自回归 rollout 训练，让预测器见过自己的误差分布。

**两种读数。** 残差 \( r=z^{obs}_{t+1}-\hat z_{t+1} \)：大小用来检测（免训练），方向接线性头用来解释是否有害（唯一的监督组件）。

**RSWT-Bench。** 从 AITW 和 GUIOdyssey 的留出片段构造：劫持样本保留真实的屏幕和动作，把结果替换成来自无关片段的凭证页；关键是「供体配对」，每张被用作劫持结果的凭证页，也以像素相同的形式作为它自己那条合法转移的结果出现。外加配对安全转移、高意外但无害的真实转移、用无害供体替换的无害错配作为对照，共 966 条转移，三人盲审与构造标签一致率 96.3%。

## 🧪 关键证据或主结果

- **免训练即追平前沿 VLM。** RSWT AUC 0.987，222 对里排对 219 对；与 Gemini 3.7 Flash（p=0.07）、GPT-5.6 Luna（p=0.83）、Qwen3.7 Plus（p=0.07）无显著差异。三位人类盲评者在 20 对样本上的平均是 0.958。
- **同样的预期，不同的接口。** gWorld-8B 0.885、Code2World 0.870，而且每次至少 92.9 秒、FLOPs 多 182 倍以上，这还没算后面那个 Gemini 裁判。
- **开源 VLM 明显吃力。** Qwen3-VL-8B 0.907，Qwen2.5-VL-7B 只有 0.574，Claude Haiku 4.5 是 0.880。
- **成本。** 一次完整判定 0.408 TFLOPs、1.09 GB 显存、17.1 ms；相比 Qwen3-VL-8B 少 27 倍算力、16 倍显存、64 倍延迟，VLM 批到 8 仍差 10.9 倍。
- **信号确实来自转移先验。** 只看单帧的最强探针 0.796；拿到两帧表示和动作但不给预测器输出的监督分类器 0.833；把预测换成别的转移的预测，残差头从 0.930 掉到 0.635。

泼点冷水：RSWT-Bench 只有 222 对，而且只覆盖「凭证页劫持」这一种攻击形态；作者自己也承认，对手如果直接在 agent 的表示空间里伪造结果会更难防，但难多少没有量化。另外最强的闭源模型 Gemini 在绝对数值上仍然略高，LGWM 赢的是「同档准确率下的成本」。

## 🔬 最有意思的部分

**「意外」不等于「有害」，而且这两件事要用残差的两个不同属性来读。** 在 Harm AUC（劫持对无害错配）上，一致性分数只有 0.513，所有提示式 VLM 在 0.512 到 0.614 之间，基本是瞎猜；残差方向加线性头达到 0.953。反过来在 RSWT 上，一致性分数（0.987）又强于残差头（0.930）。一个预测出来的未来，读两次，分别回答「有没有偏离」和「偏离成了什么」。渲染式接口给不出这个：裁判返回的是一个结论，不是一个能被线性头重新解读的方向向量。

**它确实是世界模型，不是异常分数。** 作者排除了四种退化解释：预测离未来（余弦 0.618）远比离现在（0.245）近，复制当前帧的基线只有 0.230；在约 100 个同源候选里把真实下一屏排第一的比例是 68.3%，检索训练集同类动作后继的记忆基线只有 44.6%；把动作换成别的类型，原预测仍更接近真实结果的胜率 0.891，换同类型不同目标 0.800，坐标偏移 0.05 也有 0.618；自回归十步后余弦仍有 0.562，持续性基线 0.455。

**消融的写法值得学。** 每个组件只测它设计时针对的那个指标：去掉 rollout 训练，十步余弦掉 10%；去掉逆动力学，「离未来比离现在更近」的程度掉 32%；去掉 VICReg，有效秩掉 49%。不是统一报一个总分，而是一个组件对应一个可证伪的预测。

## 🤔 我的判断

**定位**：方法突破加测量基础设施。方法上，它把 JEPA 的角色反过来用：在 JEPA 里预测出来的表示只是训练编码器的借口，测试时就扔掉；在这里，预测出来的表示本身就是产品。测量上，RSWT-Bench 用「供体配对」从构造上保证了只看结果必然随机，这种「让捷径在数学上不可能」的基准设计思路，可以迁移到很多 judge 评测里。

**亮点三条**：
1. 把「验证需要裁判」这个默认前提拆掉了：预期如果和观测在同一空间，比较就是一次运算而不是一次判断。
2. 分层验证有了现实的成本基础：17 ms 的门禁每步都跑，只把少数被标记的转移交给 VLM 或渲染器复核。
3. 「检测」和「解释」被显式拆成两个读数，免训练部分不碰任何攻击标签，只有很薄的一层线性头需要监督。

**问题与局限**：攻击类型单一；训练数据以安卓和 MiniWoB 为主，桌面和复杂 Web 的泛化未知；对抗者针对表示空间的攻击没有评估；有害性线性头需要标注数据，跨攻击族迁移如何也没报告。

**对工程的直接启发**：
- 做 agent 的运行时监控时，别只检查「当前状态看起来是否危险」，要检查「这个动作之后出现这个状态是否合理」。在 coding agent 里，这对应的是「这条命令之后出现这个文件变更是否合理」。
- 给 judge 降本的一个思路：先把期望编码成可以直接比较的结构，比如预期的 diff、预期的 schema、预期的表示向量，用廉价的比较做第一道门，再把可疑的少数交给 LLM 裁判。
- 设计 judge 基准时，主动构造「只看结果必然随机」的配对样本，才能证明裁判真的用上了过程信息。

一句话收束：**渲染是给人看的，预测是给机器用的**；当环境本身不可信时，世界模型最该做的不是陪 agent 想象未来，而是替它核对已经到来的那个未来。
