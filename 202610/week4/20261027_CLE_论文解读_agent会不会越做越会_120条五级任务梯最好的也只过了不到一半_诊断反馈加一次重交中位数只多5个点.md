# agent 会不会越做越会：120 条五级任务梯，最好的系统也只过了不到一半，诊断反馈加一次重交，中位数只多 5 个点

最近一个月，「持续学习」几乎成了 harness 圈的默认卖点：Claude Code 有记忆文件，Codex 有 skills，Hermes 和 OpenClaw 都在讲经验沉淀。可你要是问一句「它真的因为做过上一件事，下一件事就做得更好了吗」，现有 benchmark 基本答不上来。GAIA 一题一题独立打分；LoCoMo、LongMemEval 测的是能不能从历史里把信息找回来，不测找回来之后活是不是干得更好；WildClawBench 这一类有持久状态，但持久状态本身并不证明 agent 变强了。

UCL 牵头（联合利物浦大学、电子科大、北大、UNC 等，通讯作者 Jun Wang）的 **Continual Learning Exam: Benchmarking Long-Horizon RSI and Experiential Learning in LLM Agents**（arXiv:2610.33956）想补的就是这一块：**把「越做越会」做成一张可以闭卷考的卷子。** 我读完的感受是：这是一份非常扎实的「考场」论文，卷子出得很用心，但它目前给出的头条数字，严格说测的是「拿到反馈之后能不能改对」，还不是「跨任务留下来的经验值多少分」，这一点作者自己也写明了。

## 核心摘要

CLE 由 50 多位行业专家出题，共 120 个任务，每个任务是一条五级的任务梯（L1 到 L5），总计 600 级，覆盖 12 个职业大类、89 个岗位。同一条梯子上的五级是同一个岗位、同一个工作语境下的五份不同差事，后面的差事会用到前面留下的东西，作者把这种依赖归成五类可迁移知识：工具与技能、数据依赖、策略、用户偏好、领域知识。环境里有 23,981 个真实输入文件（77 种扩展名）、19 个有状态的模拟应用（共 1,024 个 API），评分用 16,125 条人写的检查项，由一个隔离的多轮评估 agent 逐项核对。必须过了当前级才能解锁下一级，没解锁的级全算失败。两种预算：Trial 1 每级只能交一次，没有反馈；Trial 2 第一次没过会拿到按评分大类给出的诊断反馈，可以改一次再交。在 4 个 harness、11 个模型、17 种组合上：**最好的 Claude Code + Opus 5 在 Trial 2 也只过了 47.67% 的级，五级全通的任务只有 23.3%；17 个组合里 16 个在 Trial 2 有提升，中位数 +5.33 个点；L1 的中位通过率 62.5%，到 L5 只剩 8.33%。** 定位：一张专门考「经验能不能沿任务梯往下传」的卷子，附带一个可复现、可审计的考务系统。

## 🎯 为什么这件事值得写

过去两周我们归档的东西里，有一条线一直在问同一个问题：经验到底该存在哪、怎么用。MCCL 说记忆系统别比谁记得多，要看下一次有没有做得更好；AntiPersistence 说记忆越多 agent 越差；RAW-RAG 说花哨的记忆系统未必赢过原始对话切块加重排；RSIHub 则想把各家 agent 进化方法放到同一个评测底座上比。它们缺的是同一样东西：**一个任务之间真的有依赖、能看出「上一级学到的东西有没有被用上」的考场。**

CLE 的回答是任务梯。它在形式上把持续学习写成

$$
(\theta_{n+1}, s_{n+1}) = U_n(\theta_n, s_n, e_n)
$$

其中 $\theta$ 是模型参数，$s$ 是 harness 的持久状态（记忆、技能、其他保留下来的信息），$e_n$ 是这一阶段的经验（工具调用、返回结果、评审反馈）。模型冻结时，学习就只剩下更新 $s$。这个写法的好处是把「改权重」和「改 harness 状态」放进同一个框架，CLE 的主实验全部是冻结权重，所以它考的就是 harness 侧的学习。

作者还顺手把持续学习能力分了五级：T1 按预设规则学（现在 Claude Cowork、Codex 的记忆和 skill 流程大致在这一级），T2 在给定任务族里自己决定学什么、什么时候学、怎么学，T3 跨陌生领域自适应，T4 能为给定研究问题自己设计调查并验证新知识，T5 自己定研究目标。这个分级本身不新，但它把「RSI」和「普通的经验积累」分开说得很清楚：**在线学习、测试时训练、案例检索都可以在固定的学习流程下发生，只用这些并不构成 RSI；只有改变了「后续改进怎么产生、怎么评估」的保留变化，才算递归自我改进。**

## 🏗️ 机制：任务梯、有状态应用、隔离评审

**一条任务梯长什么样。** 论文给的完整例子是「维护和验证一颗 Ibex RISC-V 核」，岗位是 CPU 子系统验证工程师：

| 级 | 差事 | 交付 | 检查项 |
| --- | --- | --- | --- |
| L1 | 比较老核与上游最新版的顶层接口，列出所有变了的端口和参数，找出影响自家芯片和 FPGA 原型的上游修复 | 邮件回一份表格加短说明 | 25 |
| L2 | 固件负责人在 Slack 上问退休指令计数器能不能信；复用 L1 的修复清单，在自家核的仿真上跑报告人的测试程序，量出每次读数偏了多少 | Slack 线程里贴结果表 | 26 |
| L3 | 团队决定不升级而是打补丁；复用 L1 发现的「有个修复需要老核没有的信号」，改写该修复，L2 每个用例补丁前后各跑一遍，并对两个指令集参考模型做比对 | 补丁、结果表、commit message，在 GitHub 开 PR | 28 |
| L4 | 安全签核；复用 L1 清单在新 FPGA 构建上复查，证明哪些安全修复对自家核有意义，逐文件对比别的项目发的副本，同时保证 L3 的补丁还能用 | 邮件发完整补丁集和发现表 | 32 |
| L5 | 给两颗已售芯片写勘误，其中一颗是刚到手的更老的核；在老核上重跑 L2、L4 的测试，找出每个 bug 首次出现的版本，按 RISC-V 规范的版次和章节引用，改正一份旧草稿里和测量不符的地方 | Word 勘误加证据表上传共享盘 | 36 |

你能看出这套设计的用意：**L5 如果没把 L1 的清单、L2 的测量方法、L3 的补丁都记住并用对，基本不可能过。** 全 benchmark 里 120 条梯子有 88 条在任务说明或评分表里直接引用了更早级别的文件，L2 到 L5 引用比例从 60.8% 涨到 70%。检查项也逐级变多：平均 18.74 条（L1）到 36.83 条（L5），任务说明从 246 词涨到 466 词，而一份提交必须**所有**检查项都满足才算过。

**有状态应用保证「前一级做过的事真的还在」。** 19 个模拟应用（邮件、Slack、GitHub、Git、OneDrive、S3、表格、日历等）在一条梯子内共用同一个数据库，上一级建的记录、发的消息下一级还能看到；换到下一条梯子时重新初始化。harness 的持久状态则跨所有 120 条梯子一直保留，模型参数始终冻结。

**诊断反馈只给大类。** 评分表把细的检查项归到几个评估大类里；Trial 2 第一次失败时，agent 只知道哪个大类有问题，具体检查项和参考答案一律不给。这个分寸很关键：给太细就变成对答案，给太粗就没有学习信号。

**评审是一个隔离的 agent。** 每次评分请求在一个全新的 Docker 容器里跑，被测 agent 碰不到评分材料；每个 run 有独立的 API 凭证，所有请求都留日志，可以复评和审计。评估 agent 不自己解题，而是拿工具从提交物和应用的权威状态里取证，对照人写的预期结果逐项判。主实验的评审模型是 DeepSeek V4 Flash：在 12 个任务、60 份提交、732 条检查项的验证集上，和人工标注的一致率 96.86%；同一批 556 条检查项重复评三次，553 条三次结论完全一致（99.46%）。

**出题也用了 agent。** 专家写好的草稿先交给一个评审 agent，它按一份由人类专家多轮打磨的「评审 skill」检查格式、输入文件真实性、答案泄露、评分项能否核实、持续学习设计是否成立，还会切换成被测角色把整条梯子真跑一遍，然后给出会议式结论（Strong Accept 到 Reject）。拿到 Accept 以上的，再由两位随机分配的人类评审各自完整复核，两人都通过才收录。

## 🧪 关键证据

**主表（Trial 2，节选）：**

| Harness / 模型 | 总完成率 | L1 | L5（全通） | Trial 1 → 2 增益 | 成本($) |
| --- | --- | --- | --- | --- | --- |
| Claude Code / Opus 5 | **47.67%** | 85.83% | **23.33%** | +5.50 | 720.56 |
| Claude Code / Sonnet 5 | 40.17% | 74.17% | 19.17% | **+13.17** | 506.30 |
| Hermes / Gemini 3.7 Flash | 33.67% | 62.50% | 15.83% | +8.33 | 394.84 |
| Codex / GPT-5.6-Sol | 33.17% | 65.00% | 17.50% | +5.33 | 210.83 |
| Codex / GPT-5.6-Terra | 33.17% | 68.33% | 12.50% | +5.33 | 83.16 |
| Hermes / Hy3 | 27.33% | 60.83% | 10.00% | +7.00 | 16.18 |
| Hermes / Qwen3.8-Max | 26.67% | 74.17% | 2.50% | +1.00 | 134.54 |
| OpenClaw / DeepSeek V4 Pro | 10.00% | 30.00% | 3.33% | **−1.33** | 48.10 |

几个值得记住的数：

- **梯子越往上越陡。** 17 个组合 Trial 2 的中位累计通过率，L1 是 62.50%，L5 只有 8.33%。Trial 1 里每个组合都有超过一半的任务停在 0 级或 1 级；Trial 2 只有 Claude Code + Opus 5 把这个比例压到一半以下（43.33%）。
- **L1 强不等于能爬到顶。** L1 通过率和总完成率的 Spearman 相关 0.75，但和 L5 通过率只有 0.42。最典型的是 Qwen3.8-Max：L1 在 Hermes 上 74.17%、OpenClaw 上 65%，都高于中位数，到 L5 却只有 2.5% 和 1.67%，是全场最低之一。**单题能力和「沿着梯子往上带经验」是两回事。**
- **反馈在后面几级更值钱。** 增益的中位数在 L2 是 +7.5 个点、L5 是 +3.33 个点，但按各自 Trial 1 的基数算相对涨幅，L2 是 22.5%，L5 是 75%。Sonnet 5 在 L4、L5 分别涨 16.67 和 12.5 个点，全通任务从 8 个涨到 23 个；Hermes + DeepSeek V4 Pro 的 L1 反而掉了 0.83 个点，L5 却涨了 9.17 个点。
- **同一模型，harness 差很多。** Hermes 和 OpenClaw 共用六个模型，Hermes 在每一个模型、两种预算下总完成率都更高，Trial 2 的平均优势 11.42 个点（28.17% 对 16.75%），差距从 Qwen3.8-Max 的 6.83 点到 DeepSeek V4 Pro 的 17.33 点。代价是 Hermes 平均 token 用量是 OpenClaw 的 1.90 倍、成本 1.71 倍，但作者提醒这是不同工作量下的总数，不能直接说效率。
- **总完成率一样，成色可以不同。** Codex 下 Terra 和 Sol 都是 33.17%，Terra 花 83.16 美元、20.2 小时，Sol 花 210.83 美元、28.2 小时；但 Sol 全通 21 个任务，Terra 只有 15 个。Hermes + Hy3 只花 16.18 美元就拿到 27.33%，是成本前沿上的点，却跑了 80.3 小时。
- **新一代模型不一定学得更好。** 固定 Hermes，Gemini 3.6、3.7、3.8 Flash 三代对比：Trial 1 分别是 21.00%、25.33%、21.17%；3.8 的 token 用量是 3.7 的 1.6 倍多（795.78M 对 486.25M），完成的级和全通任务都更少。Trial 2 里 3.8 涨得最多（+9.5 点），但仍落后 3.7（30.67% 对 33.67%）。

诚实泼冷水：**Trial 1 和 Trial 2 的差同时包含「有诊断反馈」和「多一次提交机会」两个因素，并不能直接读成「跨任务保留的经验值多少分」。** 作者在正文里自己写了：真正要测跨任务保留知识的贡献，需要一个对照组，在每个任务开始前把 harness 重置到初始知识状态，其他全部固定。这组对照论文里没有做。另外每个组合只跑了一次完整流（每个 Trial 一次），没有方差估计；Claude Code 和 Codex 走官方订阅，其他走 OpenRouter，推理强度用各家默认，服务端差异没法完全控制。

## 🔬 最有意思的部分

**一是「L1 强、L5 弱」这个现象本身。** 它几乎是对「持续学习」最直白的定义：不是第一题做得多好，而是第五题能不能用上前四题。Qwen3.8-Max 的曲线说明，有的模型加 harness 组合单题能力很强，但每一级都像在重新开始。对做 harness 的人来说，这是一个很具体的检测信号：**拿 L1 通过率和 L5 通过率的比值当「经验传递效率」，比只看总分更能暴露问题。**

**二是反馈只给大类的设计。** 这和我们之前看过的 DeLoop、RiseHarness 是一路思路：学习信号要有，但不能把答案递过去。CLE 把这个分寸写进了考务协议，而且发现反馈的价值主要体现在后几级的相对涨幅上。这暗示了一件事：**一次「被告知哪一类出错并改对」的经历，如果被 harness 记下来，后面几级会持续受益**，前提是 harness 真的把这件事记下了。

**三是出题流水线里的「评审 skill」。** 作者把人类专家反复总结出来的审题标准写成一份可复用的 skill，让评审 agent 照着审、还要真跑一遍，再让开发团队根据反复出现的问题继续修这份 skill。这本身就是论文想考的那种 T1 到 T2 的持续学习，只不过发生在出题方这一侧。

**四是 Hermes 对 OpenClaw 的稳定优势。** 六个模型、两种预算、十二组比较全部是 Hermes 赢，这已经不太像噪声了。结合我们前几天看的 TraceTrial（OpenClaw 的 harness 义务分是四家里最高的），两篇放在一起读很有意思：**守住单次执行的义务，和跨任务把经验带下去，是 harness 的两种不同能力。**

## 🤔 我的判断

**定位：一份设计得很认真的持续学习考卷，考务系统可以直接拿来用，但头条结论还停在「反馈加重交」这一层。**

亮点：

1. 任务梯把「后面的差事依赖前面的产出」做成了显式结构，并且有 70% 的 L5 直接引用更早级别的文件，经验传递不是可有可无的。
2. 有状态应用加隔离评审加全量日志，评审一致率和重复稳定性都给了数，审计链条完整。
3. 17 个组合覆盖四个主流 harness，同一模型跨 harness 的差距（Hermes 对 OpenClaw 平均 11 点）本身就是有用的选型信息。
4. 支持任意起点的「块」评测，后面要做重置对照、换顺序、交错任务都有现成接口。

问题与局限：

- 没有「每个任务前重置 harness 状态」的对照组，跨任务经验的净贡献目前测不出来；标题里的 RSI 也还没有被直接考到。
- 每个组合每种预算只跑一遍，0.5 到 1 个点量级的差距不宜过度解读。
- 评审模型固定为 DeepSeek V4 Flash，96.86% 的一致率是在 60 份提交上测的，规模不大。
- 508 级英文、92 级中文，语言分布不均，跨语言结论要小心。

对工程的直接启发：

- **把自己的记忆或 skill 系统放到 CLE 上，务必加一组「每题前清空」的对照。** 只比 Trial 1 和 Trial 2，你测到的是改错能力；比「保留」和「清空」，测到的才是经验积累。
- **监控 L5 / L1 比值。** 它比总完成率更直接地反映经验有没有往下传。
- **诊断反馈记下来，比反馈本身更重要。** 一次「被指出哪一类出错」的经历，最好被 harness 结构化地写进持久状态，并在后续同类差事里被主动检索到。
- **同时看总完成率和全通率，同时看钱和时间。** 总完成率一样的两套配置，全通数可以差 6 个任务；便宜的那套可能慢四倍。

一句话收束：**会做第一题不难，难的是第五题还记得前四题学到了什么；这张卷子已经出好了，下一步该补的是那组清空记忆的对照。**
