# 世界模型别每步都插嘴：只在预见到坑的时候开口，黑盒 Sonnet 在 ScienceWorld 上涨 24 个点

你手上的 agent 跑的是 Claude 或 GPT 这种只能调 API 的模型，权重动不了，可它在你的具体环境里总是在同几个地方摔跤：网页上点错了筛选器、实验里忘了先把容器拿到手、明明状态没变还在重复同一个动作。能做的通常只有两种：改提示词，或者在 harness 里挂一个外部模块往上下文里塞建议。问题是，**塞什么、什么时候塞？**

「挂一个世界模型」听起来很自然：让它预测这一步动作之后环境会变成什么样，agent 就能提前看到后果。但已有工作并不乐观，Qian 等人今年初的结论是生成式世界模型对 agent 没有稳定收益，不管是每步都调还是自适应地调，有时还更差。

UW-Madison 和 AWS AI 的 **Steering Black-Box Large Language Model Agents with Pitfall Anticipation World Model**（arXiv:2610.29139）把这个问题拆成两个设计选择，各自做了对照，然后给出一个很干脆的答案：**世界模型应该预测到「下一个子目标」为止的多步未来，并且只在预见到坑的时候才开口。** 读完我的判断是：这是一篇把「外挂顾问」从「每步都说话」改成「该说才说」的工程味很浓的论文，最有价值的是它的先导研究，而不只是最后那个分数。

## 核心摘要

设定：agent 是冻结的黑盒模型 Claude Sonnet 4.5，每一步先提出一个暂定动作 $\tilde a_t$，世界模型看着历史和这个暂定动作生成一段指导 $g_t$，追加进 agent 的上下文，agent 再重新给出真正执行的动作 $a_t$（可以不改）。世界模型用 Qwen3.5-27B 训练。先导研究在 ScienceWorld 和 WebArena-Lite 上比了三种输出（只预测下一个观察、预测到下一个子目标的片段、预测到任务结束的全轨迹），发现**到下一个子目标为止最好**；又比较了「改变了 agent 动作」和「没改变」的两组指导，发现改变动作的那组里 **76.8% 是在预警失败**，没改变的那组只有 29.0%；加一个只放行预警类指导的闸门，准确率几乎追平每步都放行，黑盒调用少了不少。据此提出 PAWM：不需要时输出 `<pass>`，需要时描述即将到来的坑和怎么绕开；先在合成的「坑」数据上 SFT，再和黑盒 agent 一起做 GRPO。**结果：ScienceWorld 从 54.6% 涨到 78.9%，WebArena-Lite 从 72.7% 涨到 80.4%，两个基准上都超过 RAG、任务前指导和各种世界模型变体；直接挂到 Haiku 4.5、Opus 4.5、GLM 5、Kimi K2.5 上也都有提升。** 定位：一种可训练、可迁移的「坑预警」外挂，把世界模型从模拟器变成了按需发声的顾问。

## 🎯 为什么这件事值得写

我们这两周归档的 harness 论文，大多在讨论「怎么改 harness 本身」：RiseHarness 对照成败轨迹改 harness，AgentS4 从无标签轨迹里进化工具库，Hermit 那一路把 harness 适配器放在冻结的模型和 harness 外面单独进化。PAWM 走的是相邻但不同的一条路：**模型和 harness 都不改，在 agent 回路里插一个小模型，专门负责「这一步你要摔了」。**

这个思路的工程吸引力很直接：

1. 前沿模型只能走 API，你没法为自己的环境微调它，但你可以训练一个 27B 的顾问。
2. 顾问学的是「这个环境怎么回应动作」，不是「该做什么」，所以理论上换一个 agent 模型也能用。
3. 如果顾问大部分时候都闭嘴，额外的黑盒调用和上下文开销就能压下来。

难点在于前两篇同类工作给的信号是混乱的。PAWM 的贡献首先是把设计空间说清楚了。

## 🏗️ 机制：先回答「说什么」，再回答「什么时候说」

**回路。** 每一步：

$$
\tilde a_t \sim \pi(\cdot\mid h_t),\quad g_t \sim \omega_\theta(\cdot\mid h_t,\tilde a_t),\quad a_t \sim \pi(\cdot\mid h_t,\tilde a_t,g_t)
$$

一个细节值得抄：agent 和世界模型每一步的上下文都是**从头重建**的，而不是一直往消息列表里追加。理由有两个：WebArena 的观察是整页 HTML，重建可以压缩历史观察；更重要的是，**重建时会去掉之前所有的世界模型指导，避免上一步的建议影响后面的决策。** 这和我们之前看的 MutableTranscripts、pi-protokoll 那一路「上下文是可编辑的状态，不是只追加的日志」是同一种思路。

**问题一：世界模型该输出什么？** 三种输出用同一批轨迹、同一个 SFT 设置训练，区别只在训练目标怎么构造：

| 世界模型输出 | ScienceWorld Acc | ACR | WebArena-Lite Acc | ACR |
| --- | --- | --- | --- | --- |
| 无世界模型 | 54.6 | – | 72.7 | – |
| 只预测下一个观察 | 58.5 | 20.1 | 73.1 | 15.9 |
| 预测到任务结束 | 65.6 | 19.4 | 71.1 | 24.6 |
| 预测到下一个子目标 | **66.7** | 18.2 | **74.1** | 17.7 |

ACR 是 agent 收到指导后改了动作的比例。两个结论：单步预测信息太少，几乎没用；预测到任务结束在 WebArena 上甚至低于不用，长程预测误差累积会把一个本来走得好的 agent 带偏。**更有意思的是，ACR 最高的那一行准确率反而最低：让 agent 频繁改主意并不等于做得更对。**

**问题二：什么时候该开口？** 作者先观察到大多数指导根本没改变 agent 的动作，于是对比「改了」和「没改」两组指导：

- 词汇分析（带 Dirichlet 先验的加权 log-odds，取两个基准上的最小 z 分数）：最能区分「改了」那组的词是 without、remains、description、however、fails，几乎全是「会失败」「状态不会变」「但是」这类预警词。
- 语义分析：让 Sonnet 4.5 判断每条指导是不是在预警坑，「改了」组 76.8% 是，「没改」组只有 29.0%（卡方 181.1，p < 0.001）。
- 闸门消融：世界模型每步都生成，但用一个分类器决定放不放行。

| 闸门 | SciWorld Acc | 放行率 | 每题黑盒调用 | WebArena Acc | 放行率 | 每题调用 |
| --- | --- | --- | --- | --- | --- | --- |
| 全部放行 | 66.7 | 100% | 36.5 | 74.1 | 100% | 20.0 |
| 只放行预警 | 65.2 | 44.4% | 26.7 | 72.9 | 27.5% | 12.8 |
| 只放行非预警 | 58.4 | 52.7% | 28.8 | 70.5 | 75.0% | 16.8 |

只放行预警，准确率只掉 1 个多点，黑盒调用少了 27% 到 36%；只放行非预警，放行得更多，效果却明显更差。

**PAWM 把这两条原则烤进一个模型。** 输出空间是 `<pass>` 加上自然语言指导：输出 `<pass>` 时不注入任何东西，agent 直接执行暂定动作；否则输出「即将发生什么失败、怎么避开」，agent 重新出动作。

**阶段一：合成「坑」数据做 SFT。** 用 Sonnet 4.5 在训练集上每题以温度 1.0 跑三遍，成功失败都留着；另用一个 Sonnet 4.5 当标注员，对同一题的成功和失败轨迹做对比，找出失败轨迹开始偏离的关键步，描述潜在的坑和纠正建议，其余步骤标 `<pass>`。三种边角情况也都没浪费：

- 全成功的题：让标注员找「次优但不致命的绕路」当残余坑，避免全变成 `<pass>`。
- 全失败的题：把标准答案指导注入后重跑拿到成功轨迹，再拿来对比。
- 防止事后诸葛亮：要求标注员只用「到这一步为止 agent 已经看到的信息」来描述坑，用抽象的、一般化的措辞。

因为 `<pass>` 远多于预警，直接训练会让模型学会永远闭嘴，所以按比例降采样 `<pass>`。

**阶段二：和黑盒 agent 一起做 GRPO。** SFT 学的是「和标注员一致」，不是「真的帮到 agent」，所以第二阶段把 PAWM 放进回路，每题采样一组轨迹，用任务成败当奖励，按组内相对优势更新 PAWM（Sonnet 不动）。一个现实问题是 Sonnet 本身已经很强，很多组的奖励全是 1，优势为零没有信号。作者用了 DAPO 的动态采样，丢掉奖励完全相同的组；WebArena 上训练前准确率已经 70%，丢得太多训练太慢，于是先用 SFT 版 PAWM 把训练题各跑三遍，只保留不是三遍全对的题，最后剩 375 道。WebArena 的写操作会改网站状态、污染别的题，所以用 WebServ 给每道题起一个独立的 Incus 容器。训练用 16 张 B200。

## 🧪 关键证据

**主表（同一个 Sonnet 4.5 agent，三次平均）：**

| 方法 | SciWorld Acc | Pass@3 | WebArena-Lite Acc | Pass@3 |
| --- | --- | --- | --- | --- |
| 无指导 | 54.6 | 66.8 | 72.7 | 80.0 |
| RAG（检索最相似的已解题轨迹） | 70.2 | 78.6 | 73.3 | 81.8 |
| 任务前指导 | 69.2 | 79.3 | 74.3 | 81.8 |
| 下一观察世界模型 | 58.5 | 71.6 | 73.1 | 81.2 |
| 全轨迹世界模型 | 65.6 | 80.1 | 71.1 | 80.6 |
| 子目标世界模型 | 67.6 | 79.0 | 74.3 | 81.8 |
| PAWM（SFT） | 71.4 | 84.5 | 75.0 | 85.5 |
| PAWM + GRPO | **78.9** | **87.5** | **80.4** | **86.1** |

几个值得记住的数：

- 摘要里的「24.3%」和「7.7%」是百分点：54.6 到 78.9，72.7 到 80.4。
- **GRPO 主要涨的是 Acc，不是 Pass@3。** ScienceWorld 上 Acc 涨 7.5 点，Pass@3 只涨 3 点。作者的解读是：SFT 提供环境知识、决定上限（Pass@3），GRPO 让 agent 更稳定地达到这个上限。
- RAG 在 ScienceWorld 上其实很强（70.2），说明「同环境的成功轨迹」本身就是很有用的指导；PAWM SFT 版只比它高 1.2 点，差距主要是 GRPO 拉开的。
- `<pass>` 与预警的比例：不做平衡时放行率只有 3.2%（ScienceWorld），准确率 67.2；比例 1.0 时放行率 26.4%、准确率 72.3 最好；WebArena 上最好是 0.75（放行率 31%）。**模型会继承训练分布的先验，闭嘴的频率可以直接用数据比例调。**
- 为了公平，作者在 ScienceWorld 上对任务前指导和各种世界模型基线也做了 GRPO，PAWM 仍然最好。WebArena 上因为成本太高，只对 PAWM 做了 GRPO。
- 迁移：和 Sonnet 4.5 一起训出来的 PAWM，直接挂到 Haiku 4.5、Opus 4.5、GLM 5、Kimi K2.5 上，准确率都有提升（具体数字在图里，正文没有逐个列出）。

诚实泼冷水：主表的比较里，只有 PAWM 在 WebArena 上做了 GRPO，WebArena 上 6 个点左右的领先有一部分来自「多训了一个阶段」；GRPO 只和 Sonnet 4.5 一起做过，换模型只是直接挂上去，没有分别训练；两个基准都偏老，ScienceWorld 是文本环境；坑的标签来自 LLM 事后标注，作者也承认可能有噪声和教师偏置。还有一点：评测温度设为 0 仍然跑三遍取平均，标准差在 1 到 2 个点，几个基线之间 1 点量级的差距要谨慎看。

## 🔬 最有意思的部分

**一是「改了主意」不等于「做对了」。** 先导研究里 ACR 最高的配置准确率最低，闸门消融里放行最多的那组效果最差。这对所有往 agent 上下文里塞建议的 harness（advisor、reviewer、反思模块、guardrail）都是一个提醒：**衡量一个顾问模块，不能看它影响了多少步，要看它在关键那几步说对了没有，其余时候能不能闭嘴。**

**二是「到下一个子目标为止」这个视野。** 单步太短，全程太长，子目标是一个天然的边界。这和我们之前看的 SkillPivot（先找偏航点再对比后缀改技能）、DeLoop（拿跳出循环的那一步当正例）是同一种直觉：**有用的信号集中在少数几个决策点上，而且只需要看到下一个里程碑。**

**三是重建上下文时把旧指导删掉。** 这个设计在论文里只用一段话交代，但我觉得很值得抄。顾问的建议是针对那一步的，如果一直留在上下文里，后面几步 agent 可能会被过时的警告牵着走；每步重建、只留当前这一条，等于给建议设了一个一步的有效期。

**四是它和 RAG 的关系。** RAG 在 ScienceWorld 上就能拿到 70.2，说明这个环境里「看一遍别人怎么做成的」已经能解决大部分问题。PAWM 的增量在于把这些轨迹里的知识压成「哪里会摔、怎么绕」，再按需发出来，并且用 GRPO 对着 agent 的真实成败调过。两者其实可以叠加，论文没有试。

## 🤔 我的判断

**定位：一个对「外挂顾问应该怎么说话」做了扎实消融的方法论文，结论可以直接迁移到 harness 设计，方法本身受限于任务专用和单一 agent 训练。**

亮点：

1. 先导研究把「说什么」「什么时候说」两个隐含的设计选择单独拎出来做了对照，结论清楚，代价也给了（黑盒调用次数）。
2. `<pass>` 把「沉默」变成了一个可训练的输出，放行率能用数据比例直接调。
3. 合成数据里对全成功、全失败两类题的处理很实用，不浪费样本，还刻意防了事后信息泄漏。
4. GRPO 阶段对着黑盒 agent 的真实成败优化，而不是对着标注员优化，并且给出了零优势组的现实解法。

问题与局限：

- 世界模型是任务专用的，每个环境要重新收轨迹、重新训练；论文自己也说结论不能直接推到通用世界模型。
- 只和一个黑盒模型做过 GRPO，迁移实验只说明「有提升」，没说明「和专门训练比差多少」。
- WebArena 的对比不完全对等，ScienceWorld 的文本环境和真实 coding 或 GUI 场景距离不小。
- 没有代码链接，复现门槛不低（27B 模型、16 张 B200、每题独立容器）。

对工程的直接启发：

- **给你的 reviewer 或 advisor 模块加一个「不说话」的出口，并且统计它的放行率。** 放行率太高通常意味着它在制造噪声。
- **建议的视野设到下一个里程碑。** 比如 coding agent 里设到「这个测试跑通」或「这个文件改完」，而不是只看下一条命令或整个任务。
- **上下文重建时清掉旧建议。** 每条外部指导只对当前一步有效。
- **训练数据就从成败对比里来。** 同一题跑多遍，用对比定位偏离点，这和 RiseHarness、GRSE 用的是同一种素材，已经有成败轨迹的团队几乎可以零成本开始。

一句话收束：**好的顾问不是每步都提醒你，而是在你快摔的那一步拉你一把，其余时候安静地看着。**
