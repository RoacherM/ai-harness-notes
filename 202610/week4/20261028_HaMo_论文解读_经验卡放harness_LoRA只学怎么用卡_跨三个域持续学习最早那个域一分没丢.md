# 经验卡放 harness，LoRA 只学怎么用卡：跨三个域持续学习，最早那个域一分没丢

你有没有过这种体验：给 agent 接了一个经验库，每跑完一个任务就把轨迹总结成一条「下次这么做」，前几天效果立竿见影，过了一周分数就卡住不动了；你转头去拿这些轨迹微调模型，新任务涨得飞快，回头一测老任务，掉了一半。

这正是 agent 持续学习里那对老矛盾：**外部记忆（harness 侧）上手快但会触顶，参数更新（model 侧）学得深但会遗忘。** 大多数系统只选一边，最近我们归档的 MCCL、RAW-RAG、AntiPersistence 基本都在 harness 侧做文章，CoEvo-RSI 和 HarnessAdapt-RL 则在想怎么让两边一起动。

湖州师范学院、阿里巴巴、浙江大学和宁夏大学的 **Harness-Model Collaboration for Long-Horizon Continual Learning**（arXiv:2610.34724）给了一个很干净的分工：**经验永远留在 harness 里当卡片，模型不负责记住每条策略，只负责学会「拿到一张卡之后怎么在当前环境里执行它」。** 看完我的感受：这篇的方法本身不复杂，一个 LoRA 加一个检索覆盖选样，但它把「写记忆」和「学会读记忆」拆成两个时间尺度的做法，正好落在我们最近关心的读写分离和 adapter-only 进化上。

## 核心摘要

HaMo 把每条专家轨迹蒸馏成一张经验卡（任务描述、初始观察、策略级解题大纲），全部存进持久的外部记忆，立刻可检索；同时用一个持续更新的 LoRA adapter（rank 16，主干冻结）做**经验条件化的行为克隆**：训练输入里显式拼上检索到的经验卡，让模型学的是「在这张卡的指导下，面对当前观察该做什么动作」，而不是直接把策略背进权重。为了不在每条轨迹上都训一遍，它用留一检索算每张卡能被多少别的卡检索到，再贪心选覆盖互补的锚点轨迹，在覆盖饱和曲线的拐点截断，配合历史回放一起训练。在 ScienceWorld 域内四阶段数据增量上，Qwen3-8B 从 38.13 涨到 60.49，四阶段平均 52.22，比只用外部记忆高 13.88 点；在 ScienceWorld → ALFWorld → WebShop 跨域序列上，最终三个域 52.43 / 66.79 / 59.64，分别比 Base 高 14.88、22.26、13.96 点，而且 **ScienceWorld 学完三个域后分数和刚学完时完全一样**，同样设置下 AgentTuning 从 26.24 掉到 3.13，ETO 从 20.16 掉到 3.20，只做参数更新的消融版掉了 29.41 点。

## 🎯 为什么这件事值得写

论文开头那句话很朴素：今天完成一个长程任务的 agent，明天做相关任务时应该更好。但现实里两条路都有坑：

- **只更新模型**：把过去的轨迹拿来微调，能把经验变成持久能力，但更新频繁时成本高，而且在顺序分布漂移下会干扰旧能力。
- **只靠 harness**：把经验存在外面、用时检索，新知识立刻生效，不用重训，但**模型本身并没有变得更会理解和执行检索到的经验**。

作者的核心论点是这两种适应**天然互补，因为它们工作在不同时间尺度上**：一条轨迹里发现的策略，可能已经对后续任务有用，但还太特殊，不值得立刻改参数；先放在外面复用，等相关策略在多个任务里反复出现，再拿来当更强的监督去改模型。对长程 agent 来说，要内化的不是答案，而是**程序性能力**：理解高层策略、把它落地到变化的环境里、翻译成合适的动作。

这和我们之前看过的几条线都有交集：AntiPersistence 说「规则用完就扔，只留轨迹和结果」，MCCL 说「记忆系统要看有没有让下一次做得更好」，CoEvo-RSI 说「脚手架进化了模型没跟上」。HaMo 给的答案是：**harness 负责存，模型负责学会读。**

## 🏗️ 机制：经验卡、覆盖选样、经验条件化 LoRA

整体流程分三块。

**1. Harness 侧：经验卡与持久记忆**

每条阶段 t 的专家轨迹 τ_i，用一个大模型抽取策略级解题大纲 z_i，再和任务描述 g_i、初始可观察条件 o_i^0 组成经验卡 c_i = (g_i, o_i^0, z_i)。卡片和源轨迹一一对应。本阶段所有卡片直接并入记忆：M_t = M_{t-1} ∪ C_t。

关键点：**持久存储和训练选样是两件事。** 一张卡没被选去训练，不会从记忆里删，后面阶段照样能检索到。论文还设计了一个可选的「模型回馈 harness」步骤，即高质量轨迹训进模型之后释放对应卡片回收存储，但**所有报告的实验里这个开关都是关的**，卡片全部保留。

**2. 选样：检索覆盖而不是全量训练**

存卡很便宜，但每条轨迹都拿去训没必要，很多轨迹编码的是相似策略。做法是：

- 对卡片文本做 embedding，在候选集里做留一检索，每张卡取除自己外最近的 3 个邻居 N_3(i)；
- 反转这个关系：R_j 是「把 j 检索为邻居的那些查询卡」，|R_j| 衡量这张卡的策略能支撑多少别的轨迹；
- 只看命中次数不够，两张高频卡可能覆盖同一批查询，所以**按边际覆盖贪心选**：每次选能新增最多未覆盖查询的卡（用 lazy 优先队列实现）；
- 一直选到边际覆盖为 0，画出覆盖饱和曲线，**在拐点处截断**得到阶段训练预算 N_t^*，前 N_t^* 张卡映射回源轨迹，构成锚点集 A_t。

这个准则偏好广泛可复用的经验，同时保留那些虽然不高频、但覆盖了别的卡没覆盖的策略上下文的经验。

**3. Model 侧：经验条件化的行为克隆**

训练集 B_t = A_t ∪ B_t^old，新锚点负责适应新任务，历史回放负责保住旧行为。对每条训练轨迹，harness 给它检索或匹配一份经验 E_i，初始对话由用户请求、初始观察、注入的经验三部分组成，**和测试时的输入格式完全一样**。目标函数是：

L_t(θ) = -(1/|B_t|) Σ Σ_k log π_θ(a_{i,k} | g_i, o_i^0, h_{i,k}, E_i)

和普通轨迹监督的区别就在 E_i：普通 SFT 学的是「上下文到动作」的直接映射，这里学的是「在 harness 给的策略语境下行动」。**模型不需要把每条策略复刻进参数，只需要学会解读策略级指导，并在不同物体、观察、状态和交互历史下把它实例化。**

参数侧的约束也很克制：

- 只有一个 LoRA adapter，主干 W_0 冻结；
- 每阶段从上一阶段的 adapter 继续训（θ_t^init = θ_{t-1}），不合并进主干，也不为每个任务长出新 adapter，**可训练参数预算全程固定**；
- 每阶段训 3 个 epoch，学习率 2e-4，LoRA rank 16、α 32，A800 80GB。

推理时检索只用任务开始时就有的信息（g, o^0），不需要专家轨迹、标准大纲或未来观察；温度 0.7，每局最多 50 轮交互。

## 🧪 关键证据

**实验设置**：三个纯文本交互环境 ScienceWorld、ALFWorld、WebShop。主干 Qwen3（关闭 thinking），域内用 8B 和 14B，跨域和消融用 8B，规模消融加 1.7B 和 4B。基线：Base、Base+Harness（只挂外部经验、参数不动）、AgentTuning、ETO。指标都是各环境原生分数换算成 0 到 100。

**域内持续学习（ScienceWorld 训练集切四份、样本不重叠，每份都覆盖全部任务类型，每阶段后测完整测试集）：**

| 主干 | HaMo 起点 → 终点 | 四阶段平均 | 比 Base+Harness 平均高 | 终点比 Base 高 |
| --- | --- | --- | --- | --- |
| Qwen3-8B | 38.13 → 60.49 | 52.22 | 13.88 | 22.94 |
| Qwen3-14B | 38.61 → 61.15 | 53.09 | 12.44 | 21.20 |

一个值得注意的细节：**Stage 1 时 HaMo 两种规模都略低于 Base+Harness**，从 Stage 2 起才领先所有方法。Base+Harness 全程贴着 Base，说明在这个设置下光有外部经验提升有限。AgentTuning 和 ETO 在 8B 上整体下滑，在 14B 上第一阶段很低之后有回升，但四阶段平均都低于 HaMo。

**跨域持续学习（S → A → W，Qwen3-8B）：**

| 方法 | ScienceWorld（学完 S → 学完 W） | 最终 ALFWorld | 最终 WebShop |
| --- | --- | --- | --- |
| HaMo | 52.43 → 52.43（中间学完 A 时 54.19） | 66.79（学完 A 时 70.08） | 59.64 |
| AgentTuning | 26.24 → 3.13 | 低于 Base | 高于 Base |
| ETO | 20.16 → 3.20 | 低于 Base | 高于 Base |
| Base+Harness | 基本保持 Base | 基本保持 Base | 43.42（Base 为 45.68） |

HaMo 最终三个域都超过所有基线，对每个域最强的非 HaMo 基线分别高 13.02、19.71、5.16 点。AgentTuning 和 ETO 在最后的 WebShop 上都超过 Base，但前两个域都掉到 Base 以下，**适应了最新域并不保证保住旧能力。**

**组件消融（S → A → W）：**

- Harness only 相对 Base 变化很小；
- Model only（顺序参数更新，不挂 harness 也不回放）学新任务很猛：第一阶段 ScienceWorld 53.98，第二阶段 ALFWorld 73.72；但学完 ALFWorld 后 ScienceWorld 掉到 22.18，最终 24.57，**比它自己第一阶段低 29.41 点**；
- HaMo 最终 ScienceWorld 52.43，比 Model only 高 27.86 点；但 **Model only 最终 ALFWorld 反而更高（69.34 对 66.79）**，WebShop 上 HaMo 略好（59.64 对 58.74）。

**训练顺序消融**：三种循环顺序的最终三域总分是 178.86（S → A → W）、188.41（A → W → S）、181.94（W → S → A），所有最终域分数都超过主实验的 Base 参考。第一个学的域：S → A → W 下 ScienceWorld 维持 52.43，A → W → S 下 ALFWorld 从 66.79 涨到 73.72，W → S → A 下 WebShop 从 54.99 涨到 60.43；但最后这个顺序里 **ScienceWorld 从 55.19 掉到 47.42**，遗忘被缓解了，没有被消除。

**规模消融**：1.7B、4B、8B 上都有效，更大的模型在后续域上吸收新任务更强（论文只给了图，正文没给具体数）。

诚实泼冷水，这篇的作者自己泼得也挺彻底：

- **Model only 同时去掉了 harness 和回放**，所以这个消融支持的是「完整 HaMo 设计」，并没有分别量出锚点选样、回放、经验条件化各自贡献多少。论文 Future Work 里明确列了要做这些控制消融。
- 没有重复运行，没有方差，推理温度 0.7 也没有消融。
- 没有端到端成本：经验抽取要调大模型，每阶段都要训 LoRA，记忆维护的代价没报。
- 只有三个纯文本基准，都是 2021 到 2022 年的老环境；最长序列只有三个域、四个阶段，算不上真正的「长程持续学习」。
- 基线 AgentTuning 和 ETO 本来就不是为持续学习设计的，用它们当对照，掉分惨烈在意料之中。

## 🔬 最有意思的部分

**一是「训练输入和推理输入完全一样」这个约束。** HaMo 的经验条件化目标里，E_i 是 harness 在训练时检索或匹配给这条轨迹的经验，推理时 harness 用同样格式注入经验。这意味着 adapter 学到的不是一组任务技能，而是一个**接口能力**：给我一张策略卡，我知道怎么把它落地。论文最后一句话说得很到位：记忆里保留的策略，即使后续更新削弱了对应的行为，仍然能作为一个显式提示。换句话说，**harness 里的卡片是遗忘的保险丝**，参数忘了，卡还在，模型又恰好学过怎么读卡。

**二是选样用的是「这张卡能帮到多少别的卡」，而不是「这条轨迹分数多高」。** 留一检索加反向索引，本质上是把记忆当作一个小型检索系统，看每张卡在里面的「被引次数」，再用集合覆盖去重。它不需要额外的价值模型，不需要奖励，也不需要裁判，完全是从检索结构里长出来的信号。拐点截断给出了每阶段的训练预算，这一点很像我们之前讲过的「测量门控」思路：不是看到新数据就训，而是看新数据在覆盖上还能带来多少增量。

**三是 WebShop 案例里那两个「什么都没改变」的点击。** 任务要求焦糖味、巧克力涂层威化、4.41 盎司、60 美元以下。Base 打开一个榛子味产品，当成焦糖匹配直接买了，得 25 分；HaMo 注意到候选标题里写的是「Triple Dark」，不能证明是焦糖味，于是去查可选口味，执行了 `click[caramel]` 和 `click[4.41 ounce]`，再核对 41.99 < 60 才下单，得 100 分。作者说这是在照着检索到的卡里「对照当前任务重查需求」的指令做，**而且它用的是当前任务的 60 美元预算，不是参考卡里的 70 美元**。但作者也老实承认：那两次点击既没改变可见观察也没带来即时奖励，案例不能拆开检索指导和参数适应各自的功劳。这个案例真正说明的，是「经验卡写的是策略而不是动作序列」时，模型必须自己完成把旧约束换成新约束的那一步，这正是 HaMo 想让 LoRA 学会的东西。

## 🤔 我的判断

**定位：一个结构清楚的 harness 与 model 双时间尺度持续学习框架，证据偏初步，但分工思路值得直接借鉴。**

亮点：

1. **写与读彻底分开。** 卡片的写入（蒸馏、存储）全在 harness 侧，模型只训「读卡执行」这个能力。这和我们之前标注的 Codex generate_memories / use_memories 分离是同一个方向，只是 HaMo 把「读」这一侧做成了可训练的 adapter。
2. **adapter 预算固定。** 一个 LoRA 一路续训，不合并、不膨胀，主干冻结。对想做「冻结主干、只进化外挂」的人来说，这是一个可以直接对照的基线配置。
3. **选样信号零额外模型。** 检索覆盖加拐点截断，只依赖 embedding 和集合运算，便宜、确定、可复现，很适合当 harness 里决定「哪些经验值得进训练集」的一道代码闸门。

问题与局限：

- 关键组件没有单独消融，你没法知道效果主要来自回放、选样还是经验条件化。如果主要来自回放，那这篇的新意就打折了。
- Model only 在 ALFWorld 上反而更高，说明经验条件化在某些域上会稀释学习强度，HaMo 换来的是平衡，不是全面领先。
- 检索用的是卡片相似度，论文自己也说下一步要学会「何时检索、何时拒绝不合适的卡、何时中途刷新指导」，也就是**相似不等于适用**这个老问题（我们在 ExpActivator 那篇里也见过）还没解决。

对工程的直接启发：

- **把经验库的写入格式当成接口规范来设计。** HaMo 的卡片只有三个字段：任务、初始条件、策略大纲。字段越固定，模型越容易学会通用的「读卡」能力；如果卡片写法每次都不同，adapter 就要额外学格式。
- **训练选样可以用检索图来做。** 如果你的 harness 已经有经验检索，几乎零成本就能算出每条经验的反向命中数和边际覆盖，拿它决定下一轮 LoRA 训哪些轨迹，比按分数或按时间挑更不容易冗余。
- **遗忘保护可以放在 harness 层。** 不要指望参数记住所有旧技能，让卡片一直留在记忆里，模型只要还会读卡，旧任务就有兜底。这对做 adapter-only harness 进化的人很实用：主干和 harness 都不改，只换 adapter 加经验库。

一句话收束：**经验交给 harness 存，模型只学会怎么读，遗忘就从参数问题变成了检索问题。**
