# rubric 奖励会在训练中失灵：先分清是没信号还是虚高，再分别去改采样、引导和评分标准

用 rubric 当奖励做开放式生成的 RL，前一百步通常很顺：分数在涨，样本也在变好。再往后，你会看到训练奖励继续往上走，拿更强的模型去盲评却发现质量停了。翻样本，策略学会了开头先夸一句、结尾再声明「已满足所有要求」；另一些条款八条 rollout 全过，组内没有任何对比；还有一些条款八条全挂，策略根本摸不到。这三种情况看起来都是「奖励不好用了」，可病根不同，该动的地方也不同。

阿里巴巴 Token Hub 联合蒙特利尔大学和 Mila 的这篇 **HarnessRL: Co-Evolving Policies with a Just-in-Time Training Harness for Open-Ended RL**（arXiv:2610.26426）把这件事拆得很细：先在一次 GRPO 训练里量出**有 61.6% 的回答对存在奖励失效**，再把任务采样、rollout 引导和 rubric 条款当成训练期 harness 的三个接口，每种失效路由到对应接口去修，并且每个改动都要在当前冻结策略上实测一遍才接受。看完我的感受：这是我见过把「judge 会漂」这个问题处理得最像工程系统的一篇，诊断、路由、验收三层分得很开。

## 核心摘要

训练期 harness 写成 \(H_t=(p_t,g_t,c_t)\)：\(p_t\) 是任务采样分布，\(g_t\) 是挂在任务后面的特权引导字段，\(c_t\) 是带符号权重的自然语言条款集合，由一个固定 judge 逐条二值打分。作者把奖励失效分成三类：**blind**（全组都拿不到分，没有对比）、**saturated**（全组都拿满，没有对比）、**spurious**（能区分回答，但区分方向和真实质量不一致）。在 Qwen3.5-4B 的 GRPO 训练中，用更强的 oracle judge 做组内两两比较，27.6% 的回答对没有可用对比，34.0% 有对比但不可靠，其中 19.8% 被奖励排反了。HarnessRL 用一个训练期记忆存每次任务抽样的 rollout、rubric 历史和训练动态，由归因器给每条条款贴标签：blind 路由到引导接口，saturated 路由到采样接口，spurious 路由到 rubric 接口；提议器给出候选改动，**即时（JIT）评审在参数冻结的当前策略上测量改动效果，落在校准过的接受区间内才接受**，被拒的带着测量结果退回重提，最多 3 轮。在新整理的五领域 Rubric-Mix-10k 上，**Qwen3.5-4B 域内 64.5、域外 49.8，比最强基线 AMARIS++ 高 3.0 和 2.8；Qwen3.5-9B 高 2.9 和 3.1**；训练结束时奖励与 oracle 的一致率 48.9%，GRPO 是 38.4%；最佳域外 checkpoint 出现在第 250 步，GRPO 要到第 475 步。价值定位：rubric 进化、引导调度、课程采样三条线第一次被放进同一个带验收的闭环。

## 🎯 为什么这件事值得写

已有方法要么进化 rubric（EvoRubric、AMARIS），要么用特权引导帮探索（RuscaRL、SkillRL），要么调课程（SEC）。作者的关键观察是：**只改一边，失效会转移到另一边。** 引导帮策略满足了固定 rubric，条款就饱和了，饱和的组没有优势信号；rubric 收紧了却没有引导，条款又超出策略能力，变成 blind。实验也印证了这一点：RuscaRL 把 blind 从 12.0% 降到 10.0%，saturated 却从 15.6% 升到 17.1%；AMARIS 把 saturated 和 spurious 降到 13.0% 和 29.7%，blind 却升到 13.3%。

对做 judge 和 eval 的人，这篇的意义在于：它把「奖励是否还在衡量质量」变成了训练过程中持续监控、按类型修复的对象，而不是训练前一次性写好的配置。

## 🏗️ 机制：三个接口、两种索引、三个角色

**一、三个接口。**

- **采样**：任务权重 \(w_t^i\) 从 1 逐级降到 \(\gamma_1\ge\gamma_2\ge\gamma_3\)（冷启动设为 0.61、0.38、0.17），每次抽样带重要性修正 \(u_t=1/(Np_t^i)\)，保证改的只是抽样频率、不改各任务对目标的期望贡献。
- **引导**：每个任务可挂 `<criterion>`（改写的目标条款）、`<reference>`（来自本任务或匹配条款的捐赠任务的正负例）、`<critique>`（上一组的不足）三种字段，每个训练季度上限减一，训练结束时全部撤掉，评测时不带任何引导。
- **rubric**：奖励为 \(r_t=\sum_m\lambda_{t,m}s_{t,m}/\sum_m\max(\lambda_{t,m},0)\)，支持新建、改写、删除、调权、合并、拆分；种子里固定的锚点条款只能调权，每次操作后按固定份额重新缩放，防止影响力漂移。

RL 目标是在 GRPO 上加采样分布、引导和重要性权重：

$$
\mathcal{J}(\theta_t)=\mathbb{E}_{x_t\sim\text{Cat}(p_t),\,Y_t\sim\pi_{\theta_{\text{old}}}(\cdot\mid x_t,g_t)}\big[u_t\,\mathcal{L}(\theta_t;x_t,Y_t,c_t)\big]-\beta D_{\text{KL}}(\pi_{\theta_t}\|\pi_{\text{ref}})
$$

**二、训练期记忆。** 每次任务抽样存一条记录：rollout 组和评分矩阵、当时的 harness 和提议动作、该任务的奖励轨迹和更新历史。时间索引按任务取历史，用来区分持续性失效和单步噪声、避免重复一个已被撤销的改动；语义索引按条款文本做向量检索（bge-base-en-v1.5，top-k=4，余弦相似度下限 0.82），给 `<reference>` 找跨任务捐赠样例。

**三、归因器。** 问三个问题：策略够不够得着（当前组和历史记录都没满足就是 blind，历史满足过只是这次没有就算噪声）；是否已经掌握（近几步全组满足就是 saturated）；满足条款是否反映质量（对比满足和不满足的 rollout，若只有满足的那批共享表面合规、长度博弈、部分覆盖、谄媚或过度拒绝，就是 spurious）。还有一个措辞检查，指出条款里允许表面通过的具体短语。

**四、JIT 评审。** 改动必须在当前冻结策略上实测：

$$
\Delta_c=\bar r_t-\bar r(Y_t,\tilde c_{t+1}),\qquad \Delta_g=\bar r(\tilde Y_t,c_t)-\bar r_t,\qquad \Delta_w=(w_t^i-\tilde w_{t+1}^i)\,\bar r_t
$$

rubric 改动在同一组已记录回答上重新打分，**修 spurious 必须让分数下降**（作者引用前人结论：奖励上升不能证明 rubric 改对了）；引导改动在冻结参数下带候选引导重新采样一组，分数要上升；采样改动不查询策略。\(\Delta_g\) 和 \(\Delta_c\) 必须落在接受区间：引导 [10.2, 28.0]、rubric [3.1, 28.0] 分，下限是独立组间和重复打分的零变化 95 分位，上限是组内奖励极差的中位数。太弱算无效，太强也拒：论文图示里一个引导改动 \(\Delta_g=+31.7\) 超过上限，被判为过强退回。另外新写的条款必须在组内有区分度，常数条款对梯度没有贡献。

## 🧪 关键证据

**主结果（最佳 checkpoint，三个种子均值）：**

| 方法 | 4B 域内 | 4B 域外 | 9B 域内 | 9B 域外 |
| --- | --- | --- | --- | --- |
| GRPO | 57.8 | 43.9 | 63.6 | 51.4 |
| RuscaRL | 60.8 | 44.3 | 65.8 | 51.7 |
| SkillRL | 60.4 | 44.6 | 65.4 | 52.0 |
| EvoRubric | 60.7 | 46.2 | 65.9 | 53.5 |
| AMARIS | 60.9 | 46.5 | 66.0 | 53.8 |
| AMARIS++ | 61.5 | 47.0 | 66.6 | 54.2 |
| **HarnessRL** | **64.5** | **49.8** | **69.5** | **57.3** |

对 AMARIS++ 的差距，配对 bootstrap 95% 区间在 4B 是域内 [2.4, 3.6]、域外 [2.0, 3.5]，每个种子都更好，种子标准差都低于 1 分。域外评测里只有 WritingBench 用训练 judge，MedQA、GPQA-Diamond、RoleBench、IFBench 都是各自的官方协议，能检验收益是否超出被 harness 改过的奖励本身。引导类方法域内涨 3 分左右、域外几乎不涨（RuscaRL 44.3 对 GRPO 43.9），rubric 类方法域外迁移更好。

**消融（Qwen3.5-4B）：**

| 配置 | 域内 | 域外 |
| --- | --- | --- |
| HarnessRL | 64.5 | 49.8 |
| 去掉评审 | 59.5 | 45.9 |
| 去掉评审和记忆 | 58.1 | 44.1 |
| 只改引导 | 60.6 | 46.3 |
| 只改 rubric | 61.2 | 47.2 |
| 采样换成 SEC | 63.9 | 49.2 |
| 引导换成 RuscaRL | 63.6 | 48.1 |
| rubric 换成 EvoRubric | 63.3 | 48.4 |

去掉评审和记忆后域外 44.1，和 GRPO 只差 0.2，**收益大头来自「评审加记忆」，不是三个接口本身**。

**训练动态。** 第 500 步时 blind、saturated、spurious 三类占比，GRPO 是 12.0、15.6、34.0，HarnessRL 是 10.5、13.4、27.2。被撤销的 rubric 改动比例 HarnessRL 最终只有 1.6%，AMARIS++ 是 18.2%，去掉评审和记忆是 22.3%。有检索证据支撑的候选接受率 71%，没有的是 44%；58% 的 `<reference>` 来自跨任务捐赠。引导字段在第 75 步达到每任务平均 1.6 个的峰值，到第 350 步 86% 的任务已经不带任何引导；接受的 rubric 改动从第一个百步窗口的 1,240 个降到最后的 140 个。人工核验：三位标注者对 200 个归因标签和 200 个接受的 rubric 改动做盲评，blind、saturated、spurious、agree 标签的认可率是 97.0%、98.0%、86.0%、90.0%，82.5% 的 rubric 改动被认为针对了诊断出的失效。

**成本。** 每 100 步 GRPO 4.3 集群小时，HarnessRL 6.7（评审 1.2、归因和提议 0.7、记忆 0.4、更长的引导 rollout 0.1），外加一次性冷启动 0.75。但 HarnessRL 在第 250 步、17.5 集群小时就到最佳域外点，GRPO 在第 475 步、20.4 小时。同样 17.5 小时内，GRPO 域外 43.8，AMARIS++ 46.9，HarnessRL 49.8。不做最佳 checkpoint 选择、直接看第 500 步，HarnessRL 仍是 64.5 和 49.4，比 AMARIS++ 高 3.0。

## 🔬 最有意思的部分

**一是修 spurious 条款时要求分数下降。** 这是整篇最反直觉也最对的设计。rubric 被策略钻了空子，正确的改动应该让那组「靠空子拿分」的回答掉分。只看分数上升来接受 rubric 改动，等于奖励 judge 变宽松。

**二是接受区间有上限。** 引导改动让分数涨太多同样被拒，因为那通常意味着引导几乎给出了答案，策略学不到可迁移的东西。这和 HarnessAdapt-RL 里「近答案提示反而有害」是同一个结论，从另一个方向被验证了。

**三是一个任务上的完整轨迹。** 纤维素滤纸那道题，第 30 步把一条种子条款换成羟基数量和偶联化学的条款；第 55 步没有 rollout 提到偶联反应，挂上 criterion 和 reference；第 130 步目标达成后撤掉，同时任务权重降到 \(\gamma_1\)。从 130 步到 260 步，组内奖励从 100.0 掉到 32.8，oracle 质量却从 58.1 涨到 61.0。**训练奖励下降、真实质量上升**，这条曲线本身就说明固定 rubric 的奖励曲线不能当训练健康度看。

## 🤔 我的判断

**定位：rubric RL 里「judge 漂移」问题最系统的工程解，诊断和验收设计可直接借鉴；场景是单轮开放式生成，不是多步 agent。**

亮点：

1. 失效三分类配 oracle 量化，把「奖励不好用了」从感觉变成可监控的比例。
2. 提议和接受由不同调用完成，接受依据是实测而不是模型自评，区间上下限都有统计来源。
3. 对照做得全：单接口、换成已有方法、去掉评审、去掉记忆、匹配算力、不选 checkpoint，结论都站得住。

需要注意：

- 只在 Qwen3.5-4B 和 9B 上做，judge 和三个 evolver 角色都是 gemma-4-31B-it；冷启动只跑 4B，9B 复用其参数。
- 任务都是单轮生成，没有工具调用和多步交互，迁移到 agentic RL 时 rollout 引导的重采样成本会高很多。
- 主表报告的是各评测集上的最佳 checkpoint，作者补了第 500 步结果来回应选择偏差，但域内评测仍用训练 judge 和种子 rubric 打分。
- oracle 是 Claude Sonnet 5，与人工一致性 Kendall τ 约 0.8，分析结论依赖它。论文没有单独的局限性章节。

对搭 agent harness、做 judge 和 eval 的直接启发：

- **训练面板里加三类失效占比。** 组内全对、全错、和独立 oracle 排反，分别监控，不要只看平均奖励。
- **rubric 改动用「同一组回答重新打分」验收。** 修空子时要求分数下降，新条款要求组内有区分度。
- **引导要能撤，并且有上限。** 训练期辅助在目标达成后主动撤掉，涨分太多的辅助直接拒。
- **给自动改动配记忆和撤销率指标。** 被撤销比例高说明提议在来回摇摆，这在自动改 skill、改 prompt 的系统里同样适用。

一句话收束：**奖励是会过期的，训练 harness 的工作是持续判断它坏在哪，再只修那一处，并且先测后改。**
