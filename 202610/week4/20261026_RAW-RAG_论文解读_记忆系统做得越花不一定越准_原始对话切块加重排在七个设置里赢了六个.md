# 记忆系统做得越花不一定越准：原始对话切块加重排，在七个设置里赢了六个

你有没有过这种体验：给 agent 接了一套「智能记忆」，抽原子事实、建图、做冲突更新、定期合并，跑起来又慢又贵，回答一个「我上周说想去哪」还是会漏。然后有人把原始聊天记录切块、向量检索、再用 cross-encoder 重排一下，效果居然不差。你心里开始犯嘀咕：前面那一大套到底在帮忙还是在添乱？

西安交通大学、上海交通大学等的这篇 **Is Complex Agentic Memory Always Needed? Naive RAG Is Stronger Than We Thought**（arXiv:2610.30755）把这个嘀咕做成了系统实验。作者提出的 **RAW-RAG** 刻意朴素：不做任何 LLM 抽取、摘要、建图或变更，原始历史按 256 token 窗口切块，dense 检索取 128 个候选，cross-encoder 重排取前 15 个，交给 reader 自己去理状态变化。看完我的感受：这篇的价值不在于「RAG 赢了」，而在于它把记忆系统的差距拆成了**证据覆盖率**和**读者利用率**两件事，并且用 oracle 实验证明，写入时丢掉或改写的信息，读的时候怎么找都补不回来。

## 核心摘要

在 LoCoMo、LongMemEval、MEME、MemoryAgentBench 四个基准、七个「基准加 reader 模型」设置上，RAW-RAG 在其中六个排第一（不算 Full-context），比最强的 agentic 记忆系统高 0.13 到 5.53 个点；唯一落后的是 DeepSeek-V4-Flash 读 MEME，MemMachine 领先 1.52 点。两个前置诊断很关键：审计 Mem0 发现 UPDATE 加 DELETE 只占写入决策的 4.39%（LoCoMo）和 2.46%（LongMemEval），真正生效的变更只有 1.90% 和 1.34%；把变更全部关掉、只允许 ADD/NONE，LoCoMo 准确率反而从 67.36% 涨到 69.42%。在 MEME 上直接把按时间排好的原始证据给 reader，DeepSeek-V4-Flash 在级联更新题上 82.32%、失效题上 91.54%，说明强 reader 能从原始证据里自己重建状态。在 RAW-RAG 上再叠加原子事实抽取、摘要增强、图扩展三种记忆管理，**全部掉分**，原子事实一项让 MemoryAgentBench 总分掉 19.62 点。效率上，10 个 MEME episode 的写入加检索 RAW-RAG 只要 305.91 秒，比 EverMemOS 快 30.4 倍；BEAM-1M 近百万 token 对话的累计写入时间 0.33 小时，对比 Memora 的 26.95 小时。

## 🎯 为什么要重新审视「RAG 不够做长期记忆」

常见的两条反对理由：一是概念上的，RAG 面向静态语料，而长期对话里有被覆盖的事实、删除和依赖链式的状态变化；二是经验上的，此前评测里 RAG 往往输给 agentic 记忆。

作者对第一条的回答是上面的 Mem0 审计和 MEME oracle：变更操作很少发生、很少生效，强 reader 读原始证据就能解级联。对第二条，作者回顾了 14 篇前作，指出不少 RAG 基线用的是过粗的检索单元、受限的检索深度或者根本没有重排。所以问题不是 RAG 能不能做记忆，而是此前比的 RAG 有没有被认真配置。

## 🏗️ RAW-RAG 的配置

| 环节 | 设置 |
| --- | --- |
| 写入 | 对话按时间序列化，带消息时间戳和图片 caption；256 token 窗口、32 token 重叠；平铺向量索引 |
| 检索 | 问题向量化，余弦相似度取 128 个窗口 |
| 重排 | cross-encoder 对问题与窗口联合打分，取前 15 |
| 阅读 | 原始窗口文本加问题交给 reader，由 reader 自己处理时间顺序与状态变化 |

附录给的主要组合是 Qwen3-Embedding-4B 加 Qwen3-Reranker-4B。消融（MemoryAgentBench，20,000 次配对分层 bootstrap 加 Holm 校正）显示：去掉重排掉 3.92 点；只返回 1 条掉 11.73 点；final-k 取 5、10、30、60 都在基线 1.3 点以内；取 120 反而掉 14.57 点；chunk 从 128 到 1,024 没有显著差别。也就是说**重排加适中深度是必需的，具体 chunk 和 k 不敏感**。

**在 RAW-RAG 上加记忆管理（MemoryAgentBench Total，基线 48.32）：**

| 叠加 | Total | 变化 |
| --- | --- | --- |
| 原子事实抽取 | 28.70 | -19.62（test-time learning 从 47.68 掉到 15.37） |

## 🔬 最有意思的部分：覆盖率比利用率更决定胜负

作者定义**覆盖率**为检索结果含有充分证据的问题比例，**利用率**为证据充分时答对的比例。MemoryAgentBench 上各系统覆盖率从 19.07% 到 45.29%（RAW-RAG 最高），利用率只在 80.00% 到 89.71% 之间；MEME 上覆盖率跨度 40.66 点，利用率跨度 21.04 点。RAW-RAG 的利用率并不是最高的（MEME 上 73.76%，低于 EMem 的 86.55%），它是靠覆盖率赢的。

更进一步，作者区分**结果覆盖**（取到答案值）和**路径覆盖**（还取到推出它所需的时间顺序或依赖规则）。在 MEME 跟踪与级联题上，取到答案值的前提下也取到完整路径的比例：RAW-RAG 62.34%，MemMachine 56.70%，MemU 只有 9.62%。很多系统抽出了「当前值」，却丢了「为什么是这个值」。

最有说服力的是 oracle 实验：给每个系统**完整导出的记忆库**加上金标位置信息，在 5,000 token 预算下选证据，再和直接给原始证据（61.60%）对比。保留原始对话内容的 RAW-RAG 和 MemMachine 分别到 57.54% 和 57.46%，而做了变换的记忆库差距大得多，Mem0 和 MemU 落后约 30 点；去掉打包上限后，七个库都仍比原始证据低 7.58 到 29.38 点，置信区间都不含零。**写入时被丢弃或改写的信息，检索做得再好也补不回来。**

## 🤔 我的判断

**定位：一篇很有必要的「基线校准」论文，结论对做 agent 记忆的人是一记警钟。**

亮点：

1. 把「复杂记忆是否必要」拆成变更频率、读者能力、覆盖与利用、写入信息损失四个可测问题，每个都有对应实验。
2. 消融用了配对 bootstrap 和多重比较校正，统计上比多数记忆论文严谨。
3. 写入成本和延迟对比非常直观，百万 token 对话上相差两个数量级。

需要注意：

- 只覆盖离线对话问答基准，作者明确说不代表交互式、多模态或操作型场景；agent 执行轨迹、代码库状态这类记忆可能是另一回事。
- 结论依赖强 reader。MEME oracle 上 GPT-4o-mini 的级联题只有 1.83%，作者也提到显式状态维护可能对弱 reader 或减少跨查询重复推理有用。
- 原始历史长期保存有存储和隐私成本，删除约束下怎么做没有讨论。
- 部分对比沿用前作公开分数，作者在附录 A 说明了对齐设置，但不同系统的运行条件仍不完全一致。

对搭 agent 记忆的直接启发：

- **任何记忆方案都先和一个认真配置的 RAW-RAG 对比。** 原始切块、dense 检索、cross-encoder 重排、k 取 10 到 30，这是新的最低基线。
- **写入时保留原文。** 抽取、摘要、图都可以作为额外索引，但不要替换原文；这和上周的 AntiPersistence、今天上午的 MCCL 都指向同一点，记忆的价值要用下游行为来验，而不是看存了多少结构。
- **监控覆盖率而不是只看准确率。** 用 judge 或确定性检查算「检索结果是否含充分证据」，它比 reader 改进更能解释系统差异。
- **检索要带上依赖路径。** 对状态类问题，按时间顺序把相关的更新链一起取回，而不是只取最新值。

一句话收束：**记忆系统先别急着变聪明，先把原话留住、把证据找全，再证明你多加的那一层真的有用。**
