# 接口别再靠人写：让 agent 从无标签轨迹里进化自己的工具库，27B 开源模型在 OSWorld V2 超过 Opus

看 computer-use agent 的录屏，最让人着急的往往不是它不会推理，而是它被接口卡住：一行代码就能写完的表格，它一个单元格一个单元格地点；要找一个函数，它在 shell 里把两千行文件全打印出来再看截图。你知道给它一个批量写单元格的函数、一个读网页文本的函数就好了，可这些接口和「什么时候用哪个」的知识，至今都是人在读轨迹、手写、再打包成新框架发布。

Simular 联合 UCSB、康奈尔和 CMU 的这篇 **Evolving Agent Interfaces**（arXiv:2610.28601）提出 **Agent S4**：任务 agent 的模型和 harness 都不动，让一个 meta-agent 读任务 agent 在合成任务上的轨迹（没有成功标签），把接口和使用知识当成一个软件仓库来改，再用种群进化挑仓库，挑选依据是 meta-agent 永远看不到的验证集分数。看完我的感受：它把「接口设计」从发布前的人工决定，变成了可以从经验里搜索出来的对象，而且把「谁看训练证据、谁看验证分数」的隔离做得很干净。

## 核心摘要

作者把可复用的接口和知识表示成一个持久仓库 \(R=(\mathcal{I}(R), K(R))\)：前者是可执行的接口代码，后者是能力说明、可复用流程、配置和「何时如何用」的笔记。任务 agent 通过 harness 已有的 IPython 代码执行工具调用仓库，用 `capabilities` 列出接口、`doc` 看文档、`call` 调用。进化过程：从种群里用二元锦标赛按验证分选父代，meta-agent 读父代仓库、它们的训练轨迹和谱系笔记，做变异（增删改一个仓库的接口和知识）或交叉（把两个仓库合成一个连贯的后代），后代冻结后跑训练任务和验证任务，不论分数高低都加入种群。训练任务是合成的、无标签的；验证任务的指令、轨迹、诊断和分数对 meta-agent 全部不可见，只影响选父代。任务 agent 和 meta-agent 都用 Qwen3.8-27B，跑在改过的 Prime Agent harness 里。**在 108 题的 OSWorld V2 上，进化出的仓库让 Qwen3.8-27B 拿到 21.30% 二元成功率，是同模型固定接口 Qwen CUA（5.56%）的 3.8 倍，高于 GPT-5.5（13.00%）和 Claude Opus 4.8（20.60%），每题成本 1.10 美元，约为二者的 4.3% 和 1.5%**。在 169 题的 ScienceBoard 上，成功率从 Qwen CUA 的 41.4% 到 58.58%。价值定位：给「skill 只能重组已有动作、不能扩展动作空间」这个问题一个直接的回答：进化接口本身。

## 🎯 为什么这件事值得写

作者点出固定接口的三个问题：进步绑定人工，每个新任务族和新模型都要有人读轨迹、写原语再发框架；静态接口和任务不匹配时，现在的做法是堆测试时算力而不是换更好的接口；把经验沉淀成 skill 的方法继承了同样的上限，**skill 是已有观察和动作的组合，蒸馏只能重排接口允许的东西，不能扩展它。**

这和我们关心的 skill 与 harness 分工直接相关：skill 是「怎么用」，接口是「能做什么、能看到什么」。Agent S4 进化的是后者，同时把使用知识写在接口的 docstring 里一起进化。

形式化目标很简单，在目标任务分布上最大化期望得分：

$$
R^\star\in\arg\max_R\ \mathbb{E}_{x\sim\mathcal{D}}\left[J(A,R,x)\right],\qquad (I_t,a_t)\sim M(\cdot\mid g,h_t,\mathcal{I}\cup\mathcal{I}(R),K(R))
$$

## 🏗️ 机制：仓库、种群、非对称证据

**一、种子仓库很小。** 约 550 行 Python 和 shell，4 个模块共 15 个基础接口：截图、点击、按键、读当前窗口、调 grounding 模型；读无障碍树、列窗口；列 Chrome 标签、开新标签；读写 GNOME 设置、提取 Office 文件结构和文本。没有任何一个针对基准里的具体应用，进化后仓库里多出来的每个接口和笔记都是进化加的。

**二、选择与算子。** 种群搜索从变异开始，变异和交叉交替；二元锦标赛从合格变体里均匀抽两个，取验证分高的；交叉的第二个父代排除第一个。10 步之后，分数最低的 5 个变体失去当父代的资格，但谱系记录保留。线性进化对照组则每步只变异最新的后代。

**三、非对称评估。** meta-agent 只拿到训练轨迹，验证分数通过选父代间接起作用，从不直接反馈给编辑。验证分定义为

$$
F_{\text{val}}(R)=\frac{1}{|\mathcal{T}_{\text{val}}|}\sum_{x\in\mathcal{T}_{\text{val}}}V_x\big(\text{Rollout}(A,R,C,x)\big)
$$

**四、合成任务。** OSWorld V2 用 30 个、ScienceBoard 用 48 个合成训练任务，各配 15 个官方验证任务。合成任务由 GPT-6 Astra 当协调者、GPT-5.6-Sol 当作者和独立审核者生成；作者看不到官方任务、评测器和任务 agent 轨迹，审核者逐项比对用途、依赖、操作和交付物以排除与基准重叠；全程没有任何一步给任务 agent 的尝试打分或产生参考答案。

**五、预算。** 任务 rollout 上限 300 步（一步是一次完整的 assistant 回复，可含多个动作），OSWorld V2 每次构建给 meta-agent 两小时，ScienceBoard 一小时；每个搜索 30 个后代。

## 🧪 关键证据

**OSWorld V2 全量 108 题（外部模型数据取自 OSWorld V2 原文）：**

| 方法 | 接口 | 二元 (%) | 部分分 (%) | 每题成本 ($) |
| --- | --- | --- | --- | --- |
| MiniMax M3 (single) | 固定 | 4.60 | 22.30 | 2.40 |
| Kimi K2.6 (single) | 固定 | 4.60 | 22.10 | 6.60 |
| Qwen CUA (Qwen3.8-27B) | 固定 | 5.56 | 20.69 | 1.39 |
| 进化仓库（有 scratch VM） | 进化 | 19.44 | **51.06** | 1.27 |
| **进化仓库（无 scratch VM）** | 进化 | **21.30** | 46.90 | **1.10** |
| Claude Opus 4.8 (batched) | 固定 | 20.60 | 54.80 | 72.40 |
| GPT-5.5 (batched) | 固定 | 13.00 | 49.50 | 25.50 |

**拆开看增益来源（同为 Qwen3.8-27B 加 Prime Agent）：**

| 条件 | 二元 (%) | 部分分 (%) |
| --- | --- | --- |
| 无仓库 | 15.74 | 44.93 |
| 种子仓库 | 19.44 | 44.90 |
| 线性进化，有 scratch VM | 19.44 | 47.17 |
| 种群进化，有 scratch VM | 19.44 | 51.06 |
| 种群进化，无 scratch VM | 21.30 | 46.90 |

种子仓库把每题成本从 1.36 美元降到 1.11 美元。scratch VM 让 meta-agent 能打开应用试代码，带来更多新接口（12 个新接口、253 个扩展，对比无 VM 的 4 个和 127 个），部分分更高，但最高的二元成功率反而出自无 VM 的版本。

**ScienceBoard 全量 169 题：** Qwen CUA 41.4%，种子仓库 55.03%，进化仓库 58.58%（解出 99 题对 93 题），每题平均模型调用从 61.7 降到 58.9，仓库函数从 15 个涨到 64 个，新增 ChimeraX 命令接口、在活动会话里跑的 GRASS GIS 模块、一次算多个表达式的 KAlgebra 计算器；KAlgebra 上成功率从 48% 到 68%。

**重复验证很关键。** ScienceBoard 上 if-003 和 if-004 首次验证都是 73.33%，第二次评估把均值拉到 60.00% 和 66.67%；最终入选的 if-016 四次分别是 73.33%、66.67%、73.33%、73.33%，均值 71.67%。只看首次分数会把 if-003 排进前列。

## 🔬 最有意思的部分

**一是进化出来的接口长什么样。** 无 VM 版本里最关键的几个都是进化加的：`run_batch` 一次调用执行一串 GUI 动作；`browser.api` 从已登录的标签页内部直接调页面自己的后端，带着页面的 cookie、header 和 origin，不用重写认证；`soffice_convert` 每次用新的 profile、加硬超时，并且「不信任退出码」，docstring 里直接写着这些差异都是轨迹里让 agent 浪费回合的坑。**使用知识就写在接口文档里，和代码一起被选择。**

**二是报销任务的对照。** 固定接口的 Qwen CUA 一封封点开收据邮件，点了五次下载警告的「保留」，两次在下载完成前打开发票，为了找 500 美元的 NeurIPS 扣款滚动八次、点四次「加载更多」。用进化仓库的 agent 用 `browser.api` 直接拿邮箱数据和附件链接，自己想到用 `curl` 下载三个 PDF、`pdftotext` 读，再复用浏览器接口查银行流水交叉核对。

**三是效率提升没有表面上那么均匀。** 在各自满分的任务上，进化仓库平均工具调用少 7.1%（103.7 对 111.6），但全部 108 题的均值几乎一样（162.1 对 163.2），在两边都满分的 11 题上反而从 87.8 涨到 103.2。作者自己点明：更短的满分轨迹描述的是各自成功的子集，不是匹配任务上的统一提速。单个照片交付任务上倒是很明显：工具调用 299 降到 167，带图结果 68 降到 14，耗时 97.5 分钟降到 51.1 分钟，得分 0.50 到 1.00。

## 🤔 我的判断

**定位：把「接口进化」作为与模型、harness 并列的第三条改进轴，方向对、工程扎实，但标题数字里混着 harness 的贡献。**

亮点：

1. 训练证据和选择证据隔离得很彻底，meta-agent 看不到验证集任何内容，合成任务生成也不碰官方任务和答案。
2. 种群加交叉确实有用：OSWorld 有 VM 的那次运行里，第 24 步由第 2 步和第 6 步交叉得到最高部分分，早期分支在很多步之后仍有价值。
3. 接口分类（系统级、应用级、跨应用、任务级）和「新接口与扩展分开计数」很适合拿来审计自己的工具库。

需要注意：

- 3.8 倍是对比 Qwen CUA 这个纯 GUI 固定接口。换到能写代码的 Prime Agent、不给任何仓库就已经是 15.74%；种子仓库到 19.44%，进化再到 21.30%。按 108 题折算，大致是 17、21、23 题的差别，**进化本身的增量约两道题**。
- 全量评测的 108 和 169 题包含了用于选择的 15 个验证任务，而且 OSWorld V2 上没有做重复验证去噪，作者说是因为成本太高。
- 只用了一个模型，meta-agent 和任务 agent 是同一个 Qwen3.8-27B；成本只算解题调用，不含仓库构建；外部模型用的是 500 步参考 harness，和这里的 300 步 Prime Agent 不完全同条件。
- 论文没有单独的局限性章节。

对搭 agent harness 的直接启发：

- **把工具库当成可版本化、可进化的仓库，而不是 system prompt 里的一段说明。** `capabilities / doc / call` 三段式渐进披露，任务 agent 按需读文档，上下文开销小。
- **把踩坑经验写进工具 docstring。** 「不信任退出码」「max_chars 故意放在第一个参数」这种知识，跟着接口走比单独存成 skill 更不容易丢。
- **改工具的 agent 不该看到评测集。** 只给它训练轨迹，用隐藏的验证分做选择，这套非对称设计可以直接搬到自动生成 MCP 工具或 skill 的流程里。
- **验证集上重复评估再选。** 单次长程任务方差很大，首次高分常常是运气。

一句话收束：**skill 只能在已有动作里排列组合，想让 agent 做得更好，有时要让它改的是接口本身。**
