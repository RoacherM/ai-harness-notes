# 经验别锁死在一个 harness：共享多模态记忆，才能让不同 agent「集体学」

你有没有过这种体验：同一类题，Codex 跑通留下一堆教训，换 DeepSeek Harness 或换骨干却要从零踩坑；记忆模块要么绑死在宿主权重里，要么是另一套跟骨干同尺寸的笨重读写，贵且难迁移。MIT-IBM / Rochester 这篇 **EpiCon**（arXiv:2609.37923）把命题写成：**不更新 host 参数，用共享多模态记忆做 agent 集体学习**——题内文本指引与视觉证据共进化，题间经验进持久银行，且**别的 harness / 骨干也能复用并继续往里写**。看完我的感受：这和今早的 DerivAudit（记忆是否可从历史推导）形成互补——那边审计「写进去的是不是真的」，这边做「写进去的能不能跨系统还值钱」；对 multi-harness / 持续学习外部记忆两条线都很硬。

## 核心摘要

EpiCon（Episodic Consolidation）在 MAS 之外挂专用 **memory harness**，由两个独立训练的 **2B** 模型驱动：**Memory Controller**（题级：联合修订文本指引与图像区域，并门控是否注入视觉记忆）与 **Tree Self-Organizer**（跨题：对经验树做 Place / Merge / Split+Lift / Consolidation，并检索规则或具体经验）。银行独立于 MAS；构建期可写入，评测期历史银行冻结。数据：约 25K 经 replay 筛选的文本–视觉记忆变换 + 6.5K 树操作演示。评测 **11** 榜、四多模态域、两 harness（Codex / DeepSeek-Harness）× 多骨干。单次作答协议下，骨干尺寸 EpiCon 宏均分相对最强外部记忆基线高 **1.9–5.9** 分；**2B** 变体相对 No Memory 仍 **+1.7–4.9**，记忆操作时间相对骨干尺寸记忆模型降 **67–74%**。冻结银行跨骨干 / 跨 harness 迁移宏均约 **+3.2 / +4.2**；另一 harness 演化银行后，原贡献方再解还可再涨约 **+2.1 / +3.2**。资源：https://zzzmyyzeng.github.io/EpiCon。

## 🎯 为什么这件事值得写

MAS 把通信与分工做得很热闹，但**经验资产**常停在「本系统本骨干」：换脚手架就失效，或用骨干当记忆模型又贵又慢。EpiCon 的分野有三：（1）题内共进化文本+视觉，而不是只存字幕式摘要；（2）题间树化巩固出可检索规则；（3）明确测 **frozen-bank 跨 harness/骨干迁移** 与 **他系统续写反哺原系统**——这才叫「集体学习」，而不是单 agent 反思循环。对关心 OpenClaw/多 harness 桥接与外部记忆的人：这是可插 memory harness 的强样本。

## 🏗️ 机制：Controller × Tree × 银行

**题级。** 记忆 \(W=(M^{\mathrm{text}},M^{\mathrm{vis}})\)；每次尝试后 Controller 据题、图、旧记忆、答案与轨迹提出联合更新（保留/替换/删除视觉区域），harness 校验裁剪；门控 \(g\in\{0,1\}\) 决定下一步是否注入视觉记忆（不删存储，只控输入）。

**跨题。** 组织器维护经验树：叶为题级课，内部节点聚类与摘要；巩固条件由支持度、失败、冲突与证据强度约束。检索：冻结文本编码器召回候选 → 组织器选规则 / 具体经验 / 空。

**训练。** 两枚 Qwen3.5-2B LoRA；监督来自 CAMEL / Codex / DeepSeek-Harness 轨迹，经教师生成 + replay（Repair 转败为胜、Compress 保胜缩短）与结构校验筛选。Host MAS 参数始终不动。

**评测协议关键。** 主表与迁移实验：历史检索开启、**题级多轮更新关闭、每题单次作答**——避免「多试几次」冒充记忆增益。

## 🧪 关键证据

- **主结果（Table 1）**：四宿主配置下骨干尺寸 EpiCon 宏均最佳；2B 变体仍稳赢 No Memory，并在性能–时间图上落在经验帕累托前缘。
- **迁移**：Codex+Qwen 建的银行给 Codex+Gemma / DeepSeek+Qwen 用，宏均约 +3.2 / +4.2（如 MATH-Vision 25.8→33.0，ParseBench 52.4→65.7）。
- **跨 harness 演化**：原银行经「对方」再写 1k 题后，原方宏均 +2.1（Codex）/ +3.2（DeepSeek）；但任务不匀——ParseBench 上弱方演化可能拉低强方分数，提示集体记忆有**污染/风格冲突**风险。
- **消融**：无银行时仅 Controller 多试仍涨；视觉共进化 + 自适应注入优于纯文本或始终注入；树组织显著优于扁平库（ParseBench 52.2→67.3）；换 GPT-5.6-Luna 作求解器，冻结 2B 记忆组件仍四点全升。

泼冷水：构建题与评测为项目自定义划分；部分榜波动大；树操作监督未逐条下游 replay；集体演化存在负迁移切片；主战场是多模态文档/图表/视觉数学，不是 SWE。

## 🔬 最有意思的部分

1. **记忆 harness 与求解 harness 解耦**——银行可插拔，host 只消费检索结果；这比「把记忆焊进 agent loop」更利于多脚手架世界。
2. **单次作答测历史复用**：把「经验是否真值钱」从「再试一次」里拆出来，方法论干净。
3. **2B 专模 vs 骨干零样本当记忆**：时间砍六七成、分数只小幅让步——工程上极有说服力。
4. **自适应视觉注入**：降 MAS 时间约 17–25%，说明「何时看图」本身是可学控制，不是永远多模态狂炫。
5. **集体学习的双刃剑**：跨系统续写能涨分，也能在强项榜上伤原系统——需要治理（过滤、冲突标记、分域银行），不能无脑 merge。

## 🤔 我的判断

定位：**跨 harness 共享的多模态外部记忆系统 + 集体学习实证**（系统/方法论文）。亮点三：

1. 题内共进化与题间树巩固拆开测；
2. 冻结银行迁移与双向演化直接服务 multi-harness 叙事；
3. 2B 记忆专模给出清晰成本曲线。

局限：非编码主战场；负迁移治理未产品化；与 DerivAudit 式「假记忆写入闸」尚未闭环。对 Byron：**(1)** 多 harness 桥接层应暴露**可插经验银行**接口，而不是各脚手架私有笔记；**(2)** 记忆写入要配冲突/支持度元数据，防弱系统污染强系统；**(3)** 优先训小 Controller/Organizer，避免每次用 27B 骨干当记忆操作系统；**(4)** 与今早 [DerivAudit](./20261001_DerivAudit_论文解读_记忆不是摘抄是推导_分布式证据悖论卡死写入闸.md) 联读：一边管「能不能稳定挡住假写」，一边管「真经验能不能跨系统复利」；接 [JITMem](../202609/week4/20260925_JITMem_论文解读_记忆别在写入时裁剪_读时按任务现场策展同一条轨迹能榨出不同课.md) / [LIMBO](../202609/week4/20260924_LIMBO_论文解读_经验回放别全塞进提示_按任务在线配记忆预算.md)。

一句话收束：**经验若只服务产生它的那个 harness，集体学习就是空话——EpiCon 用共享多模态银行证明：换脚手架也能接着涨分，但要防污染。**
