# 压缩和子代理把轨迹切成好几段，RL 还在把同一个优势广播给每一段？

你有没有过这种体验：线上 agent 早就靠 context compaction 和 subagent 撑长任务了，一条轨迹里上下文被重写好几次、分叉出好几个子会话；可训练时用的 agentic RL 还假设「一条 rollout 就是一段连续累加的上下文」。最常见的折中是**广播**：整条轨迹的成败优势原样复制给每个会话的每个 token。于是一次把关键证据压丢了的 compaction，和一次真正带回答案的子代理，拿到的是同一个梯度信号。**推理时已经是多会话了，训练信号能不能也细到会话？会话该开几个，能不能也被学出来？**

HKUST(GZ) LARK 实验室与华为等的 **Mosaic**（arXiv:2610.22174）先把这个设定正式命名为 Multi-Session Agentic RL，再给出一个不需要 critic 的两层优化：轨迹层按「成功用得少、失败探得多」调制优势，会话层用「这一段让正确答案变得更好生成了多少」当即时奖励并按会话类型分别归一化。看完我的感受：这篇和今天的 [CarryOn](./20261019_CarryOn_论文解读_别再压缩对话历史_让文件和状态本身当进度载体.md) 正好是一对，CarryOn 从 harness 侧说别再压缩对话历史，Mosaic 从训练侧说既然要压缩、要分叉，那就**把每一次压缩和分叉都当成可以被打分的状态转移**。

## 核心摘要

Mosaic 把一条轨迹 \(\tau_i\) 表示成 \(N_i\) 个会话的集合，每个会话可以是 normal（常规推理与工具调用）、compact（把接近上限的上下文压成新前缀）或 subagent（主 agent 委派子任务，结果并回主上下文）。**轨迹层**在 GRPO 组内按成败拆子组，把会话数 \(N_i\) 映射成子组内的中心化秩 \(u_i\in[-1,1]\)，优势乘以 \(1-\rho u_i\)（\(\rho=0.2\)），只改幅度不改符号：成功轨迹会话越少优势越大，失败轨迹会话越多优势越大（鼓励探索），结果奖励仍然主导；全对或全错的同质组另设回退项，保证全错组里没有轨迹拿到正优势。**会话层**用更新前策略计算正确答案的平均对数似然当势函数 \(\Phi\)，一个会话的奖励就是它输出状态与输入状态的势差，再按会话类型在组内分别归一化，最后一段（含最终答案）置零，以 \(\lambda_r=0.1\) 叠加到轨迹优势上。在 BrowseComp 上用 Qwen3.5-4B、REDSearcher_RL_1k 训一个 epoch：compaction 场景 Mosaic **38.86%**，广播 35.31%（相对 +10.1%），平均会话数 **3.17 → 2.35**；subagent 场景 32.46% 对 31.44%，会话数 4.43 → 3.77。价值定位：**给「压缩 / 分叉 / 合并」这些 harness 机制补上训练侧的信用分配**，并把问题从「开几个会话」改写成「每个会话产生了多少有用进展」。

## 🎯 为什么这件事值得写

现代 harness 里，打断上下文连续性的机制已经是常态：Claude Code、OpenClaw、Pi 一类都有 compaction 或 subagent。我们归档过的几条线也都在推这个方向：[MutableTranscripts](../../202609/week4/20260928_MutableTranscripts_论文解读_对话别只追加纠错_把历史改成可编辑状态剪掉上下文污染.md) 把历史改成可编辑状态，[LongHarness](../week2/20261014_LongHarness_论文解读_证据和结论别埋在对话历史里_共进化状态才把一亿token语料问对.md) 让状态与证据脱离对话历史，[Subagents-vs-Skills](../../202609/week3/20260921_Subagents-vs-Skills_论文解读_技能该塞进主上下文还是开子代理.md) 讨论什么时候该开子代理。

但训练侧大多还停在单会话假设。结果就是推理与训练不一致：单会话训出来的模型，推理时开 compaction 或 subagent 的收益有限，作者的 Table 1 也证实了这点。之前 [SLCA-GRPO](../../202609/week5/20260929_SLCA-GRPO_论文解读_工具段和总结段别共用一个优势_分段锁信用.md) 已经指出工具段和总结段不该共用一个优势；Mosaic 把这个思路从「同一上下文里的不同段」推广到「不同会话」。

| 训练方式 | 会话结构 | 信用分配 | 会话数是否被约束 |
| --- | --- | --- | --- |
| 单会话 GRPO | 一段连续上下文 | 轨迹级 | 不适用 |
| 广播 | 多会话 | 每个会话复制同一轨迹优势 | 否，会话数随训练上涨 |
| IGPO | 单会话 | 回合级信息增益 | 否 |
| **Mosaic** | 多会话 | 轨迹级（会话数调制）+ 会话级边际增益 | 是，成功少用、失败多探 |

## 🏗️ 机制：轨迹层调制 + 会话层塑形

**轨迹层：三条序约束。** 作者先写下希望优势满足的排序：C1 成功轨迹会话越多（成本越高）优势越低；C2 失败轨迹会话越少（探索不足）优势越低；C3 结果奖励必须主导，多开会话不能让失败轨迹排到成功轨迹前面。实现上按 \(R_i\in\{0,1\}\) 拆子组 \(G_1,G_0\)，在子组内按 \(N_i\) 升序取中心化秩：

$$
u_i = 2\,\frac{\mathrm{rank}_{G_{R_i}}(N_i)-1}{|G_{R_i}|-1}-1,\qquad
\hat A_i^{\mathrm{sat}} = (1-\rho\,u_i)\,\hat A_i^{\mathrm{traj}}
$$

因为成功轨迹 \(\hat A>0\)、失败轨迹 \(\hat A<0\)，同一个乘子自然对两边起相反作用。用秩而不是原始会话数，是为了对长尾轨迹稳健。全成功组用 \(-\beta_1 u_i\)（\(\beta_1=0.2\)），全失败组用 \(\beta_0\min(u_i,0)\)（\(\beta_0=0.1\)），后者保证失败轨迹不会拿到正优势。

**会话层：答案似然势差。** 把会话看成状态转移 \(v_{i,j-1}\to v_{i,j}\)，用更新前策略 \(\pi_{\bar\theta}\) 定义势函数：

$$
\Phi(y^*\mid x, v)=\frac{1}{L}\sum_{\ell=1}^{L}\log\pi_{\bar\theta}(y^*_\ell\mid x, v, y^*_{<\ell}),\qquad
r^{\Delta}_{i,j}=\Phi(y^*\mid x,v_{i,j})-\Phi(y^*\mid x,v_{i,j-1})
$$

直觉是：一段搜索带回了有用证据、一次压缩去掉了噪声、一个子代理交回了高质量结果，正确答案就更容易被生成；反之，压丢关键事实或引入误导信息会让势下降。不同类型会话的增益分布差别很大（normal 靠外部证据，compact 取决于保留与去噪，subagent 同时受子任务执行和交接质量影响），所以**按类型在组内分别归一化**；最后一个会话置零，避免最终答案本身把似然抬高、污染分布。最终会话优势：

$$
\hat A^{\mathrm{session}}_{i,j}=\hat A^{\mathrm{sat}}_i+\lambda_r\,\hat r_{i,j}
$$

**实验设置。** ReAct 循环，两个工具 `search`（Serper）与 `visit`（Jina Reader）；deepseek-v4-flash 当答案判定裁判；每个会话上限 128K token；subagent 不嵌套；rollout batch 16、group size 8。

## 🧪 关键证据

**主结果（Table 1 / Table 2，BrowseComp）。**

| 方法 | 单会话推理 | Compact 准确率 | Compact 会话数 | Subagent 准确率 | Subagent 会话数 |
| --- | --- | --- | --- | --- | --- |
| Qwen3.5-4B 原始 | 23.22 | 24.80 | 1.70 | 21.64 | 2.98 |
| 单会话 GRPO | 31.99 | 34.68 | – | 31.91 | – |
| 单会话 IGPO | 28.52 | 31.36 | – | 24.64 | – |
| 多会话广播 | – | 35.31 | 3.17 | 31.44 | 4.43 |
| **Mosaic** | – | **38.86** | **2.35** | **32.46** | **3.77** |

单会话训练的模型直接拿去做多会话推理收益有限，说明多会话能力不会自己泛化出来。原始模型单会话失败的 972 题里，多会话推理加多会话训练能救回一部分，Mosaic 救回的更多（Fig. 3a）。

**训练动态（Fig. 4）。** Mosaic 的轨迹奖励涨得比广播快且更高；两者的会话数都随训练上涨，但 Mosaic 的会话数更早走平。

**消融（Fig. 3c/d）。** 轨迹层和会话层各自都有贡献；compaction 场景两者叠加有明显额外增益，subagent 场景叠加只多一点。作者的解释：compaction 轨迹是线性的，subagent 轨迹更像 DAG，一个会话会影响多个后续会话，用势差估的即时奖励未必等于它对最终结果的真实贡献。

**会话质量（Table 2）。** 正信息增益会话占比：compaction 37.36%（原始）→ 47.74%（广播）→ **59.92%**（Mosaic），每会话平均增益 0.30 → 0.86 → 0.89；subagent 27.39% → 41.15% → **51.04%**，0.41 → 0.74 → 0.80。广播是三项指标一起涨（会话数也涨），Mosaic 是会话数不再涨、质量和分配继续涨。

**算力（Fig. 3b）。** 与回合级信息增益的 IGPO 相比，会话级计算势差的前向耗时大幅下降，准确率还更高。

**泼冷水。** 会话层奖励需要 ground-truth 答案 \(y^*\) 来算似然，BrowseComp 这种短答案任务很合适，开放式交付（写代码、写报告）里要换成别的势函数；subagent 场景的领先只有约 1 个点，而且单会话 GRPO 直接推理已经到 31.91，比广播还略高；只在一个基准、一个 4B 模型、1000 条训练题上训了一个 epoch；会话数只是成本与探索的代理指标，推理时模型并不知道一条轨迹最终会有几个会话、会不会成功；训练在同地交替的 rollout / 训练设置下进行，异步与 partial rollout 下的偏差作者自己也列为未解问题。

## 🔬 最有意思的部分

1. **同一个乘子对成功和失败起相反作用。** 不需要两套规则，只靠优势符号就实现了「成功求省、失败求探」，而且严格不翻转结果排序。这是我见过把成本信号塞进 GRPO 最干净的写法之一。
2. **全局归一化会系统性压低 compaction。** compaction 会话的原始增益均值本来就低，统一归一化会让它几乎总拿负信号；按类型归一化后，好压缩和坏压缩才能被区分。这条对任何「多种动作共用一个奖励尺度」的设计都适用。
3. **最后一段置零。** 最终答案会把正确答案似然一下抬高，若不置零，会话层信号几乎全被最后一段吃掉。很小的一个工程细节，但决定了势差信号能不能用。
4. **有效的多会话优化不是开更多会话。** 广播靠多开会话涨分，Mosaic 靠提高每个会话的有用进展涨分；作者把核心问题改写成「能从执行的会话里榨出多少进展」，这和 harness 侧控制 compaction 频率、子代理数量的直觉一致。
5. **作者点名黑盒 harness 里的 RL。** 讨论部分明确把 Claude Code 这类编排不透明的 harness 当下一步目标，还提到丢弃推理 token 或工具返回这类「隐性断档」也该被视为会话边界。

## 🤔 我的判断

定位：**训练侧的信用分配方法 + 一个值得被广泛采用的问题设定**。方法本身不复杂，价值在于把 compaction / subagent 从「推理技巧」变成「可以被奖励的状态转移」。

亮点三条：

1. 轨迹层用秩调制优势，在不翻转结果排序的前提下把会话成本与探索写进目标；
2. 会话层用答案似然势差做无 critic 的过程信号，并按会话类型分别归一化；
3. 用会话数量、质量、分配三维分析解释了涨分来源，而不是只报准确率。

问题与局限：依赖短答案的 ground truth；subagent DAG 结构下即时奖励与真实贡献错位；规模与基准都偏小；异步训练下的组构造与陈旧样本处理未解。

对工程的直接启发：**(1)** 如果线上 harness 用了 compaction 或 subagent，训练 rollout 就该用同一套循环采，单会话训练的收益不会自动迁移；**(2)** 想在 RL 里引入成本信号，优先考虑「组内秩 × 有界乘子」，不要直接把会话数或 token 数当奖励项；**(3)** 评估一次 compaction 好不好，可以用「压缩前后正确答案似然的变化」当离线诊断指标，也可以借来评 harness 的压缩 prompt；**(4)** 多种动作类型共存时，按类型分别归一化过程奖励；**(5)** 子代理交接质量值得单独建模，Mosaic 的 DAG 消融已经暗示线性势差不够。

一句话收束：**harness 已经把一条任务拆成了很多段，训练就不该再把它当成一段；给每一次压缩和分叉记一笔账，agent 才会学会少开无用的会话。**
