# 小模型先干，看隐状态像不像失败再叫旗舰接手，接手之后还得拴着它

你有没有过这种体验：computer-use agent 一个任务动辄几十上百步，全程跑旗舰模型账单吓人；换成小开源模型又经常在第三步就点错菜单。于是你想做「弱模型先干，搞不定再升级」，结果卡在两个问题上：**什么时候该升级？升级之后旗舰模型自己也会绕圈迷路，它是个黑盒 API，谁来盯它？** 再起一个大模型逐步审查太贵，专门训一个监控器又要标注数据。

Simular 与 UW–Madison 的 **LEASH**（arXiv:2610.22280）给的答案很省：只用弱模型自己的隐状态。先在一小批留出任务上记录弱模型成功和失败时的隐状态，运行时看当前隐状态在 Mahalanobis 距离下更像失败还是更像成功；这个分数既决定开局要不要直接交给强模型、运行中哪一步交接，也在交接后让弱模型换成影子观察者，每三步跟跑一次，分数一高就把强模型待执行的动作撤回、让它加大推理力度重想。看完我的感受：这是我们之前归档的 [JEV-as-a-Judge](../../202609/week4/20260924_JEV-as-a-Judge_论文解读_自信就收下不确定就升级_决策裁判三分钱顶住强模型.md)「自信就收下、不确定就升级」在长程 agent 上的版本，而且多了一层少有人做的**交接后监督**。

## 核心摘要

LEASH 把弱到强升级形式化为预算约束下的序贯停止问题：用总升级率 \(p_{\mathrm{esc}}\) 当成本代理，最大化任务成功率。不确定性来自弱模型最后一层隐状态：任务 prompt 最后一个 token 的 \(h_0\)（查询通道）和每步动作最后一个 token 的 \(h_t\)（动作通道）；在留出参考集上按任务成败与 Manager 判定的子目标成败打标签建参考库，拟合共享协方差的高斯判别模型，分数 \(u = d^2_{\mathrm{Pass}} - d^2_{\mathrm{Fail}}\)，越大越像失败。动作通道的隐状态在生成动作时本来就算出来了，**不需要额外前向，也不需要训练监控器**。三层门：开局门按 \(u_q\) 直接路由，运行门按 \(u_a\) 在第一次超阈值时交接，交接后影子门按弱模型跟跑得到的 \(u_{\mathrm{sh}}\) 触发撤回重想（每任务最多 6 次，改变过 2 次动作后停止）。阈值按参考集分位数设定，目标开局 25%、总升级 50%。在 OSWorld 262 个评测任务、四个开源弱模型、Claude Opus 5 当强模型与 Manager 的设定下：同升级率时比随机升级高 **6.55–11.94 点**；Qwen3.5-35B-A3B 做弱模型时 **73.66%** 成功、每任务 **$0.4117**，与全程 Opus（72.90%、$0.5094）持平而成本低 19.2%；恢复弱模型与全程 Opus 之间 75–102% 的差距，成本是全程 Opus 的 69–81%。价值定位：**无训练、可插拔的升级与监督信号**，把「什么时候叫大模型」和「叫来之后谁看着它」用同一个分数解决。

## 🎯 为什么这件事值得写

模型路由和级联（FrugalGPT、RouteLLM）在单轮问答上已经很成熟，但长程 agent 有两个新难点：一是升级时机，不只是「哪道题」还有「第几步」；二是交接之后强模型也会陷进重复动作循环，而它的内部状态不可见、口头自信又不可靠。

之前的做法各有代价：

| 方法 | 升级信号 | 额外成本 | 交接后监督 |
| --- | --- | --- | --- |
| 逐步 LLM 审查 | 另一个大模型判断 | 每步一次重推理 | 通常没有 |
| StepWise 等训练监控器 | 专门训练的模块 | 标注 + 训练 | 没有 |
| 采样型不确定性 | 多次采样一致性 | 每步多次生成 | 没有 |
| Progress Advantage | 参考策略对比 | 额外参考模型 | 没有 |
| **LEASH** | 弱模型隐状态与成败参考库的距离 | 几乎为零（复用激活） | 影子观察 + 撤回重想 |

这和我们一直跟的 judge / 校准线直接相连：[FailConf](./20261015_FailConf_论文解读_agent能学会预言自己失败吗_结果锚定置信度校准.md) 问 agent 能不能预言自己失败，[JevAgentHarness](./20261016_JevAgentHarness_论文解读_孤立题答对不等于能控住agent_决策模型要拟合阈值才共享控制.md) 说决策模型要拟合阈值才能共享控制。LEASH 给出了一个不训练、只用表征距离的实现，还把阈值直接绑到预算上。

## 🏗️ 机制：一个分数，三道门

**参考库。** 在与评测集不相交的留出任务上（99 个任务的参考池），让弱模型在 Manager 引导下、不升级地跑一遍。查询库 \(\mathcal{B}_q=\{(h_{i,0},y_i)\}\) 用任务成败；动作库 \(\mathcal{B}_a=\{(h_{i,t},y_{i,t})\}\) 让每一步继承所在子目标段的结局（Manager 判完成为 Pass、需要修订为 Fail，否则用最终任务结局）。

**不确定性分数。** 先按库统计量逐维标准化 \(z_c(h)\)，再用正则化的共享类内协方差 \(\Sigma_{c,\lambda}=\hat\Sigma_c+\lambda_c I\)：

$$
d^2_{c,y}(h)=(z_c(h)-\mu_{c,y})^\top\Sigma_{c,\lambda}^{-1}(z_c(h)-\mu_{c,y}),\qquad
u_c(h)=d^2_{c,\mathrm{Pass}}(h)-d^2_{c,\mathrm{Fail}}(h)
$$

和 OOD 检测里的相对 Mahalanobis 不同，它减的不是类无关背景距离，而是到相反结局的距离，得到一个更尖锐的「像失败」信号。拟合只需要各类均值和一次 SVD，库变大可以直接重拟合。

**阈值绑预算。** 开局门 \(g_0=\mathbb{I}[u_q(h_0)>\tau_q]\)，运行门 \(g_t=\mathbb{I}[u_a(h_t)>\tau_a]\)。目标开局升级比例 \(p_q\)、总升级率 \(p_{\mathrm{esc}}\)，则运行门只需在开局门留下的任务里再升级 \(p_a=(p_{\mathrm{esc}}-p_q)/(1-p_q)\)：

$$
\tau_q=Q_{1-p_q}\{u_q(h_{i,0})\},\qquad
\tau_a=Q_{1-p_a}\{U_i : u_q(h_{i,0})\le\tau_q\},\quad U_i=\max_t u_a(h_{i,t})
$$

用每条轨迹的最大分数定 \(\tau_a\)，因为一步超阈值就会交接；所有分数都是参考集上任务分组 10 折的折外分数。实验统一设 \(p_q=0.25\)、\(p_{\mathrm{esc}}=0.5\)。交接时强模型拿到指令、当前截图和弱模型最近几步，接管到任务结束。

**影子监督。** 交接后，每个强模型已执行的动作都按弱模型自己的动作格式追加进弱模型历史；在交接后第一步和此后每三步，让弱模型对当前观察生成一个候选动作（只记录，不执行，也不给强模型看），取同位置隐状态算 \(u_{\mathrm{sh}}\)。超过参考库逐步分数第 90 百分位就触发：把强模型对话截回本步开始，删除待执行动作，追加一条中性 checkpoint 消息，让它用更高推理力度重新决定。弱模型的候选动作刻意不给强模型，避免被弱模型带偏。

**理论。** 在共享协方差的高斯假设下，分数等于弱模型失败对数几率的两倍（差一个常数），由 Neyman–Pearson 论证可得：同升级率下，开局门捕获的弱模型失败比例最大；若升级收益随分数单调不减，开局门也最大化总成功率。运行门的最优停止分析留作未来工作。

## 🧪 关键证据

**主结果（Table 1，OSWorld，每任务 50 步预算）。**

| 弱模型 | 单独成功率 | 随机升级（同升级率） | **LEASH** | 升级率 | LEASH 成本 |
| --- | --- | --- | --- | --- | --- |
| EvoCUA-8B | 42.37 | 59.98 | **67.18** | 45.4% | $0.3627 |
| Qwen3.5-35B-A3B | 37.40 | 61.72 | **73.66** | 64.1% | $0.4117 |
| Nemotron-3 (30B-A3B) | 45.04 | 55.41 | **66.03** | 43.1% | $0.3500 |
| Qwen3.8-27B | 51.91 | 63.30 | **69.85** | 51.1% | $0.3622 |
| 全程 Claude Opus 5 | – | – | 72.90 | 100% | $0.5094 |
| 全程 Claude Sonnet 4.5 | – | – | 59.16 | 100% | $0.4038 |

四个 LEASH 配置都高于全程 Sonnet 4.5，其中三个更便宜：对多数弱模型来说，选择性地叫旗舰比全程跑中档模型又准又省。

**对比已有方法（Table 2，EvoCUA-8B）。** StepWise 升级 49.6%、成功 58.40%；Progress Advantage 升级 46.9%、成功 62.98%；LEASH 升级 45.4%、成功 **67.18%**。

**组件消融（Table 4，Qwen3.5-35B-A3B）。** 弱模型单独 37.40%；加 Manager 41.15%（$0.1372）；加升级 **67.94%**（$0.4050）；再加影子监督 **73.66%**（$0.4117）。最大一跳来自升级，影子监督只多花约 0.7 美分就再加 5.7 点。

**影子到底抓到了什么（Table 5）。** 被影子触发过的 31 个任务里，全程 Opus 只成功 51.6%，没触发的已升级任务全程 Opus 成功 74.5%，说明触发集中在真难的轨迹上；在触发子集上，有影子 64.5%，无影子 48.4%。

**升级时机重要（Fig. 5）。** 在最常被升级的子集上，LEASH 64.6%、$0.67；把交接时机打乱后 60.4%、$0.79；全程 Opus 62.5%、$0.86。

**不确定性估计本身（Table 3 / 6）。** 运行时逐步 AUROC，LEASH 的池化 LDA 在两个弱模型上都最高（0.609 / 0.575），但绝对值只是中等；开局阶段 Qwen3.8-27B 上反而是概率型基线更好。参考库从 40 扩到 99 个任务，开局 AUROC 从 0.701 升到 0.770（Qwen3.5-35B-A3B）。

**泼冷水。** 全程 Opus 基线**不带 Manager**，而 LEASH 一开局就用 Opus 5 当 Manager 拆子目标、在子目标边界核验进度，「持平全程 Opus 且便宜 19%」里混了 Manager 脚手架的贡献；Qwen3.5-35B-A3B 实际升级了 64% 的任务，所谓弱模型优先在这个配置里其实大半交给了强模型；运行时 AUROC 只有 0.58–0.61，信号能用但远谈不上准；需要能读隐状态的白盒弱模型，API 小模型用不了；作者自己承认影子监督工作在分布偏移下（弱模型看的是强模型轨迹），干预效果没有做因果隔离；只测了 OSWorld；理论只覆盖开局门，且要求升级收益随分数单调，两边都搞不定的任务会违反这个条件。

## 🔬 最有意思的部分

1. **监控器就是执行者自己。** 生成动作时的激活顺手拿来算分，零额外前向。对成本敏感的 harness，这比再挂一个 LLM 审查员现实得多。
2. **白盒小模型监督黑盒大模型。** 强模型不可见，但弱模型可以跟跑它的轨迹、用自己的表征给出「这一步我看着都悬」的信号。这是弱到强监督在推理时一个很具体的落地形态。
3. **干预不告诉强模型怎么做。** checkpoint 只撤回动作、提高推理力度，不给弱模型的候选。监督者只负责「停一下」，不负责「替你决定」，避免弱模型把强模型带偏。
4. **阈值直接对着预算定。** 不去校准失败概率，只用分数排序加分位数，把「我愿意升级多少比例」直接翻成阈值；用每条轨迹的最大分数而不是逐步分位，避免实际升级率远超预期。
5. **参考库越大越准。** 40 到 99 个任务 AUROC 稳定上升，意味着部署后不断把新轨迹的成败写回库就能自我变好，和经验库类的 RSI 天然兼容。

## 🤔 我的判断

定位：**工程可用的升级与监督框架**，方法不复杂，贵在把开局路由、运行升级、交接后监督三件事用一个零成本信号串起来，并给了预算对齐的阈值设定法。

亮点三条：

1. 无训练、无额外前向的表征距离不确定性，参考库可增量重拟合；
2. 交接后影子监督与撤回重想，填上了弱到强升级里普遍被忽略的那一半；
3. 四个弱模型、两个已有方法、时机打乱、库规模、触发子集分析，证据面比较完整。

问题与局限：Manager 混入导致与全程强模型的对比不够干净；运行时信号区分度中等；白盒限制；OSWorld 单一领域；影子干预缺因果验证。

对工程的直接启发：**(1)** 自托管小模型做主执行者时，把每步动作 token 的隐状态存下来，配上成败标签就是一个免费的失败检测器；**(2)** 升级阈值用「目标升级比例 + 参考集分位数」来定，比拍一个置信度阈值更好控成本；**(3)** 交接后不要放手，至少保留一个廉价的跟跑信号和撤回重想的通道，并设上限（如每任务最多 6 次）防止反复打断；**(4)** 监督信号只触发强模型反思，不把弱模型的答案塞给它；**(5)** 评估级联系统时，基线要和实验组用同一套 Manager / 脚手架，否则节省的成本里有多少来自脚手架说不清。

一句话收束：**升级不是把活甩给大模型就完事；用小模型自己的隐状态决定什么时候放它出来，也用同一个信号在它跑偏时拉一把，才配叫有绳子的升级。**
