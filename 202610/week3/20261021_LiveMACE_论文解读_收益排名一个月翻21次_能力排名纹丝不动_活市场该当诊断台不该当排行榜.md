# 收益排名一个月翻了 21 次，能力排名纹丝不动：活市场该当诊断台，不该当排行榜

你有没有过这种体验：看一个「大模型实盘炒币」的榜单，今天 A 第一，下周 B 第一，月底又换成 C。你想从里面看出哪个模型更会用工具、更会记经验、更守规矩，结果什么也看不出来，因为收益同时被行情、仓位历史和模型行为搅在一起。**结果分数回答了「赚没赚」，回答不了「凭什么赚」。**

新国立和复旦的 **LiveMACE**（arXiv:2610.09872，论文里叫 LiveMACEBench）就是冲着这个问题来的。它让五个前沿模型在真实的加密货币和美股行情里做 30 天纸面交易，但关注点不是谁赚得多，而是在同一个 ReAct 底座上分别加上工具、持久记忆、规则、多智能体四种机制后，**模型有没有真的把机制用起来**。看完我的感受：交易只是外壳，这篇真正的贡献是一套「**机制可用、机制被有效使用、最终收益**」三者分开测的过程评测框架，对做 agent judge 和 harness 诊断的人很有参考价值。

## 核心摘要

LiveMACE 的环境是一个不可重置的持久纸面交易账户（初始资金 1 万美元），覆盖 6 种加密货币和 17 只美股，行情分别来自 Hyperliquid 和 Alpaca 的 SIP 数据。所有 agent 在同一张时间网格上每 4 小时做一轮决策，一轮里可以多步推理、调工具、下零到多笔单，仓位带到之后每一轮。五种受控配置：Base（固定工具集的 ReAct）、Tool Use（305 个工具的动态路由）、Persistent Memory（跨轮存取经验）、Rule Following（R0 > R1 > R2 的分层交易规则，且必须写明检查了哪些规则）、Multi-Agent Collaboration（经理带专家团队再单独执行）。评测五个模型：GPT-5.4、DeepSeek-V3.2、Gemini-3.1-Pro、Grok-4.20、Qwen3-Max，时间是 2026 年 4 月 13 日到 5 月 13 日。每种机制都配了「LLM 裁判打分 + 轨迹客观指标」两类度量。核心发现是**结果和能力的落差**：四种配置下，累计收益排名在 30 天里分别发生 21、19、19、29 次两两反转，而对应的能力排名只有 0、5、8、2 次；而且能力冠军和收益冠军经常不是同一个模型。价值定位：一套把 agent 机制拆成「接入、使用、效果」三段测量的过程评测方法，外加一批可以直接借用的轨迹指标。

## 🎯 为什么这件事值得写

Alpha Arena、Agent Market Arena、AI-Trader 这类实盘基准已经不少，它们回答的都是「哪个模型赚得多」。问题是，收益是一个闭环的产物：行情在变，早先的仓位会影响后面的每一步，模型行为又有多个层面。**在这种环境里，结果分数几乎无法归因。**

LiveMACE 把问题从「排名」换成「诊断」：

| 测量对象 | 它回答的问题 | 典型指标 |
| --- | --- | --- |
| 任务结果 | agent 最后达成了什么 | 累计收益、最大回撤、尾部损失 |
| 受控机制效应 | 加上某个机制之后变了什么 | 同模型有无记忆的回撤差、ReAct 与多智能体的收益差 |
| 过程诊断 | 这个机制有没有被用、怎么用的 | 工具路由质量、记忆使用质量、规则可审计性、证据整合度 |

这正好对应 harness 工程里最常被混淆的三件事：**给了 agent 一个能力，不等于它会用；它会用，也不等于结果会变好。**

## 🏗️ 机制：同一个活市场，四种受控机制，两类度量

**环境与节奏。** 所有 agent 共享同一张 4 小时决策网格，市场在两轮之间继续变化，收益在更细的时间点上用账户净值快照计算。账户不可重置，没有任务定义的终止状态，30 天只是观察窗口。

**四种机制各自怎么测。**

1. **工具使用。** 305 个候选工具（295 个照公开 API 规格复刻），通过一个 `select_tools` 元工具动态路由。裁判打四项：工具相关性 TR、调用效率 IE、信息覆盖 IC、证据忠实度 EF；客观指标三项：路由质量 RQ、有效调用率 VCR、无幻觉率 HFR。合成工具调用分 TCS。
2. **持久记忆。** 裁判打记忆内容质量 MCQ（可泛化性、信息密度、多样性贡献）和记忆使用质量 MUQ（检索是否及时、取回后是否真被采纳）；客观指标是相对同模型无记忆配置的最大回撤变化和尾部损失变化。四项等权合成记忆分 MS。
3. **规则遵循。** 程序化检查器逐笔判 R0、R1 硬约束和 R2 软偏好，得到硬规则通过率 HPR 和软规则满足度 SRS，合成规则满足分 RSS，硬规则不过时软规则不计分；裁判再读推理和合规说明，打规则覆盖 RC 和冲突处理 CH，合成规则可审计分 RAS。
4. **多智能体协作。** 两个客观指标：角色多样性 RD（惩罚单一角色主导）和证据整合 EI（各专家产出的证据有没有进到经理的最终决策），平均得到可观测协作分 OCS。

**裁判稳健性。** 主裁判是 Qwen3.5-397B-A17B。工具使用部分用 DeepSeek-V4-Pro 在同样 680 条轨迹上复评，后者平均高 0.048 分，但模型排序完全一致；分维度看，信息覆盖在正负 0.1 内的一致率 95.6%，调用效率只有 69.4%。规则审计部分换了三个裁判，两两 Spearman 相关平均 0.83。

## 🧪 关键证据

**能力画像：没有全能冠军。**

| 模型 | 工具 TCS | 记忆 MUQ | 规则 RSS | 协作 OCS |
| --- | --- | --- | --- | --- |
| GPT-5.4 | **0.894** | 0.762 | 0.634 | 0.265 |
| DeepSeek-V3.2 | 0.789 | 0.680 | 0.847 | **0.806** |
| Gemini-3.1-Pro | 未测 | 0.497 | **0.872** | 0.738 |
| Grok-4.20 | 0.760 | **0.855** | 0.751 | 未测 |
| Qwen3-Max | 0.864 | 0.742 | 0.612 | 0.516 |

Grok-4.20 在工具配置下收益最高，工具调用分却最低；DeepSeek-V3.2 在规则配置下收益领先，规则满足度最高的却是 Gemini-3.1-Pro。

**规则配置：收益几乎一样，守规矩程度天差地别。** DeepSeek-V3.2 和 GPT-5.4 最终收益分别是 +5.765% 和 +5.738%，硬规则通过率却是 0.877 对 0.682。Gemini-3.1-Pro 收益只有 +3.503%，HPR、RSS、RAS 三项全是最高（0.888、0.872、0.882）。

**多智能体：收益涨了，风险也涨了。** 相对同模型 ReAct，多智能体让 GPT-5.4、DeepSeek-V3.2、Gemini-3.1-Pro 的累计收益分别多了 2.45、3.72、2.57 个点，Qwen3-Max 反而少了 4.39 个点。四个模型的大幅盈利次数都变多了，最大回撤和平均尾部损失也都变大了：Qwen3-Max 多出 6 次大幅盈利，最大回撤却增加 2.85 个点，最终收益更低。

**泼冷水。** 第一，每个「模型乘配置」只有一条 30 天轨迹，没有重复，收益层面的结论统计力很弱，这也是作者自己强调「收益不可归因」的原因。第二，过程指标里一半是 LLM 裁判，调用效率和证据忠实度这类需要判断冗余和边际信息价值的维度，跨裁判一致率只有 69% 到 81%。第三，只有一个月、一种行情；四种机制分开加，没有测组合。第四，几个模型版本已经不是最新，Grok 的协作分和 Gemini 的工具分缺失，横比不完整。

## 🔬 最有意思的部分

**一是「排名反转次数」这个度量本身。** 作者把每天的排名序列拿出来，数相邻两天里两两交换位置的次数。收益排名在工具配置下反转 21 次，工具调用分排名一次都没反转；协作配置下是 29 次对 2 次。这个对比很有说服力：**一个指标如果排名天天翻，它测到的多半是环境噪声，而不是 agent 的稳定属性。** 做任何长时程 agent 评测，都可以拿这个检验自己的指标是不是在测能力。

**二是工具使用里「覆盖」掩盖了「效率」。** 四个模型的信息覆盖都在 0.8 以上（0.809 到 0.911），调用效率却是裁判四项里最差的（0.581 到 0.731）。也就是说，agent 可以靠多调几次工具把信息凑够，最终看起来「信息充分」，过程却很浪费。工具发现和工具执行还是两种独立的失败：Qwen3-Max 路由质量最低（0.736）但有效调用率接近完美（0.978），Grok-4.20 路由更好（0.805）但有效调用率只有 0.666。只有 GPT-5.4 两头都强（0.920、0.998）。

**三是记忆的三段各自独立。** 同一个记忆机制，五个模型走出了完全不同的路：GPT-5.4 检索 332 次，只存了 1 条记忆，反复用一条宽泛规则，那条记忆内容质量最高（0.978），可记忆库根本不长；Gemini 存了 93 条、内容质量 0.938，使用质量却最低（0.497）；Grok 只存 12 条、内容质量 0.760，使用质量最高（0.855）。下游效果上，五个带记忆的 agent 全都降低了尾部损失，四个降低了最大回撤；DeepSeek 和 Grok 的收益优势在后期变大，Gemini 从全期负差转为后期正差，而记忆库停在一条的 GPT 没有任何类似改善。**存得多、存得好、用得好，是三个不同的能力。**

**四是「机械合规」和「可审计合规」会分家。** DeepSeek-V3.2 规则满足分 0.847，可审计分只有 0.623：很多合规的决策里几乎没有明确的规则检查、没有数字证据，有些甚至基于错误的持仓状态，只是碰巧没违规。另一类失败出现在单资产集中度上限 R1-02 上，GPT-5.4 和 Qwen3-Max 常违反它，原因不是无视规则，而是**把现有仓位、新增订单和价格变动合起来估算成交后敞口时算错了**。这和 coding agent 里「规则读懂了但状态算错了」是同一类问题。

**五是多个 agent 不等于有协作。** 同一个多智能体 harness，GPT-5.4 几乎塌缩成单角色工作流（角色多样性 0.012），收益照样涨；Qwen3-Max 证据整合还不错（0.751）但角色单一（0.282），收益反而跌；DeepSeek-V3.2 最均衡（0.760、0.852），收益涨得也最多。**光看「用了多智能体架构」和最终收益，你根本不知道里面到底有没有发生协作。**

## 🤔 我的判断

**定位：过程评测方法论的实用样本，交易场景是载体，指标设计是重点。**

亮点三条：

1. 「接入、使用、效果」三段分开测的框架很清楚，四种机制各有一套客观指标加裁判指标的组合，而且硬约束用程序检查、推理质量用裁判，分工合理，符合「代码检查优先于 LLM 裁判」的思路。
2. 用排名反转次数检验指标稳定性，是一个便宜、通用、很有说服力的元评测手段。
3. 机械合规和可审计合规的区分，对任何需要「agent 说明自己为什么这样做」的场景（审计、金融、医疗）都直接有用。

问题与局限：单轨迹无重复，收益层的结论只能当观察；部分裁判维度一致性不高；四种机制分开测，真实 harness 往往是组合；模型阵容不完整。

对工程的直接启发：

- **给 harness 里的每个机制配一个「使用度」指标。** 记忆就看写入数、检索后被采纳的比例；工具就看路由命中率和有效调用率；子代理就看角色多样性和证据是否进了最终决策。机制上线后先看它有没有被用，再谈效果。
- **把规则遵循拆成程序可判的硬约束和需要裁判的说明质量。** 硬约束用代码 gate，说明质量用 judge 抽检；两者分开报告，别让「碰巧合规」混进高分。
- **长时程评测先做排名稳定性检验。** 如果你的指标在相邻检查点之间频繁反转，先别拿它做决策。
- **记忆评测要分三段。** 存了什么、取没取、取了用没用，各自单独打分；只看「记忆库大小」或「最终效果」都会误判。

一句话收束：**活市场里赚钱靠运气的成分太大，但它逼出来的每一次查工具、翻记忆、对规则，都是能被看清的。**
