# 派子代理、中途自查，能不能从 harness 规则变成模型自己的本能？

你有没有过这种体验：给 agent 配了一套精心写好的编排规则，什么时候开子代理、子代理回来要交什么、连续几轮没进展就强制反思一次，规则越写越长，效果却时好时坏。换一个模型，规则又得重调。更糟的是，agent 在某条错误线索上兜圈子二十轮，你的「三轮无进展就反思」规则恰好没触发，因为它每轮都觉得自己有进展。**编排和自检到底该写在 harness 里，还是练进模型里？**

上海人工智能实验室 Sage-A1.5 团队的技术报告（arXiv:2610.28578）给出了一个明确的站队：练进模型。他们在 35B 总参、3B 激活的 MoE 上，把「怎么拆任务、派给谁、给什么上下文、怎么合并结果」和「什么时候该停下来核对证据、换方向」都当成训练目标，而不是交给外部框架的固定规则。看完我的感受：这份报告真正值得抄的不是榜单，而是**子代理结构化回执的协议设计**和**用外部监督者造数据、推理时把监督者撤掉**的那套数据构造法。

## 核心摘要

Sage-A1.5 在 Agents-A1 的基础上，把 agent 能力拆成两个维度：能力覆盖（能做哪些领域）和能力组合（执行时怎么组织这些能力）。后者靠两件事落地。一是 **Agentic Orchestration**：主 agent 通过 `spawn_subagent` 把子任务派给上下文隔离的并行子代理，每个子代理回一个 JSON，带答案、自评状态（ok、unknown、insufficient_evidence、conflict、ambiguous 五选一）、证据（来源、摘录、支撑哪条结论）和未解决问题；训练时主 agent 轨迹和每条子代理轨迹各自当成独立样本，前者学拆分和综合，后者学独立调查和结构化汇报。二是 **Agentic Verification**：造数据时让一个监督模型盯着执行模型，在重复搜索、长时间没进展、关键结论待确认这三类节点插入核对，再把监督提示删掉、把反思揉进模型自己的推理文本；推理时只需在系统提示加一句 `Verification protocol:enabled`，不需要额外工具、在线监督者或 harness 规则。之后用 Claude Code、Codex 和内部 harness 采集多领域示范做 SFT，再用「结果 RL + 多教师在线蒸馏」按样本混合监督，把搜索、SWE、MLE、科研、长上下文几个领域教师合成一个模型。主要数字：BrowseComp 81.7（开编排 82.8），SWE-Bench Pro 61.2，MLE-Bench-Lite 65.2，PinchBench 90.0（在 OpenClaw 上跑，高于报告里列出的 Kimi-K3、GLM-5.3、GPT-5.6-sol），ALE-CLI 19.1。验证模式在 BrowseComp 教师上把准确率从 81.0 拉到 85.5，同时输出 token 和轮数都略降。价值定位：一份「把 harness 行为内化进权重」的工程样本，配了可直接复用的委派协议和数据构造套路，但消融证据偏薄。

## 🎯 为什么这件事值得写

过去一年做 agent 的主流路线是「模型负责单步能力，harness 负责组织」：子代理调度、上下文压缩、反思触发、预算控制都写在框架里。这条路的好处是可控，坏处是规则和模型强绑定，换模型就失配，而且规则只能按表面信号触发（轮数、token 数、重复调用），看不到「这一步的推理其实建在一个没核实的前提上」。

Sage-A1.5 的立场是反过来：**组织方式本身应该是学出来的能力**。报告里有一句话说得很直白，任务委派、并行协作、证据审查、策略修正，应该成为模型能力，而不是只依赖外部框架里的固定规则。

这和我们最近读过的几篇形成了有意思的对照：

| 路线 | 代表 | 组织逻辑放在哪 |
| --- | --- | --- |
| harness 自进化 | SelfEvolvingHarness、Harness2 | 外部脚手架，靠验证集和回归预算改 |
| harness 规则 + 小模型路由 | LEASH | 外部路由器看隐状态决定何时升级 |
| 进度写进文件 | CarryOn | 外部状态载体，模型读写 |
| **组织练进权重** | **Sage-A1.5** | **模型自己决定何时拆、何时查** |

对维护 MMP 这类确定性 harness 的人来说，这篇是一个必须正面回应的反方：如果模型自己就会分工和自查，harness 里那一层还剩什么？

## 🏗️ 机制：两种组合模式、一份回执协议、一种去监督化的数据构造

**两种并行组合。** 报告用逻辑式做了一个很好记的区分：

$$
\text{Exploratory}: A \lor B \lor C \qquad \text{Constructive}: A \land B \land C
$$

探索式是同一个问题派几个子代理走不同假设，主 agent 比较后收窄方向；构造式是把任务拆成互补子问题并行做，主 agent 负责拼装、检查依赖和一致性。真实任务两者交替出现。

**委派接口和结构化回执。** 主 agent 每个委派项给三样东西：自包含的子任务、相关背景（证据和约束）、期望的输出格式。子代理回执的 JSON 有四块：

| 字段 | 内容 |
| --- | --- |
| answer | 子任务结论 |
| status | ok / unknown / insufficient_evidence / conflict / ambiguous |
| evidence | url、摘录或摘要、支撑了哪条结论 |
| unresolved_issues | 剩下的缺口和问题 |

这个 status 枚举是整篇最实用的东西。它让主 agent 不用读完子代理的全部输出就能决定下一步，也给轨迹筛选提供了信号。

**训练任务怎么造。** 编排能力用两类任务练：约束引导的长程搜索，和多源研究综合。前者延续 A1 的关系链构造，选定一个答案实体，从它的几个相关实体各拉一条链，组成星形树，把每条分支变成一条线索、隐去专名后合成一道题。天然适合并行，因为每条线索可以独立派出去查。

**Agentic Verification 的去监督化。** 造数据时有两个模型：执行模型做实时搜索和阅读，监督模型在三类节点插入核对（重复搜索、持续无进展、关键结论待确认）。每次核对只能用当时已有的证据，区分已确认事实和未验证假设，并给出具体的下一步方向。然后执行模型按核对结果继续跑。清洗时把监督提示和控制消息全删掉，反思文本并入模型自己的推理。推理时没有监督者，模型自己决定何时查、查什么、查完怎么走。

**统一后训练。** 每条学生 rollout 带领域和 harness 标签，按样本选择监督方式：

$$
\mathcal{L}_{\text{post}}(x)=\lambda_{\text{out}}(x)\,\mathcal{L}_{\text{RL}}(x)+\lambda_{\text{proc}}(x)\,\mathcal{L}_{\text{OPD}}(x)
$$

结果奖励便宜的领域走纯 RL（奖励是领域分数减去格式和协议违规罚分）；MLE 和编排这类结果贵、出得慢的走纯在线蒸馏，用对应领域教师的逐 token 反向 KL；指令遵循和长上下文两者都用。编排任务里学生同时扮演主 agent 和子代理，一份回执在发送者轨迹里被监督，在接收者轨迹里只当观测。

## 🧪 关键证据

**编排和验证的增量（这是本文核心主张的直接证据）。**

| 配置 | BrowseComp | DeepResearch Bench II |
| --- | --- | --- |
| Qwen3.5-35B-A3B | 61.0 | 42.3 |
| Sage-A1.5 不开编排 | 81.7 | 43.7 |
| Sage-A1.5 开编排 | **82.8** | 47.5 |
| 编排教师 | 81.6 | **53.6** |

| 模式 | BrowseComp | 输出 token | 轮数 |
| --- | --- | --- | --- |
| Qwen3.5-35B-A3B | 61.0 | 14,851 | 65.2 |
| 验证教师，普通模式 | 81.0 | 23,245 | 84.8 |
| 验证教师，验证模式 | **85.5** | 21,962 | 82.1 |

**和大模型的横向对比（节选，原文表 1）。**

| 基准 | Sage-A1.5 | Agents-A1 | Kimi-K3 | GLM-5.3 | GPT-5.6-sol |
| --- | --- | --- | --- | --- | --- |
| BrowseComp | 81.7 | 75.5 | 91.2 | 76.2 | 90.4 |
| SWE-Bench Pro | 61.2 | 43.6 | 63.3 | 64.6 | 64.6 |
| MLE-Bench-Lite | 65.2 | 43.9 | 72.7 | 72.7 | 77.3 |
| PinchBench | **90.0** | 76.9 | 88.2 | 86.6 | 87.3 |
| ALE-CLI | 19.1 | 10.2 | 27.6 | 28.5 | 28.6 |
| IFBench | **81.6** | 80.6 | 72.1 | 53.4 | 72.7 |

**泼冷水。** 第一，编排在 BrowseComp 上只涨 1.1 个点，DeepResearch Bench II 涨 3.8，而且学生开了编排（47.5）离编排教师（53.6）还有 6 个点，说明合并多个教师之后编排能力有明显损耗，报告在局限里也承认「统一模型没完全保住每个领域教师的峰值」。第二，验证模式的 4.5 个点和 token 下降是在**教师**上测的，不是最终模型；token 对比只算「两种模式都给出答案」的配对样本，存在幸存者偏差。第三，编排和验证的训练都集中在搜索和研究综合，SWE、MLE 上没有对应消融，「组织能力跨领域迁移」目前没有证据。第四，横向对比里大模型的数字多取自各自报告，评测 harness 不统一；PinchBench 用 DeepSeek-V4-Flash 当裁判，23 题跑五次，样本很小。第五，BrowseComp 用了「超过 300 次工具调用或撑满上下文就清空重跑，最多 5 轮」的策略，这是 harness 层面的重试，和「不靠 harness」的叙事有点张力。

## 🔬 最有意思的部分

**一是 status 枚举把「子代理说不知道」变成了一等公民。** 大部分子代理协议只回一段文字结论，主 agent 很难区分「查到了」和「编了一个」。Sage-A1.5 强制子代理在 insufficient_evidence、conflict、ambiguous 之间选一个，相当于在每条回执上挂了一个小裁判标签。50 频道研究的案例里，StarPlus 子代理拿到的委派前提是「运营方是 Sony」，它把前提当假设处理，查到冲突后改成 Disney Star / JioStar，主 agent 随后用这个修正调整了跨频道关系。**委派下去的前提可以被子代理推翻**，这比单纯的并行加速有价值得多。

**二是「监督者只在造数据时存在」这个设计。** 这是把 harness 规则蒸馏进权重的一个干净模板：先用外部规则加强模型做出好轨迹，再把规则痕迹抹掉，让模型学到「在什么情境下自己会这么做」。触发条件（重复搜索、无进展、关键结论）本来就是我们会写进 harness 的规则，区别在于模型学到的是情境到行为的映射，而不是轮数阈值。代价是失去了可审计性：你没法再从配置文件里看出它什么时候会反思。

**三是验证带来净省 token。** 直觉上加反思会更贵，结果在配对样本里输出 token 少了约 5.5%，轮数少了约 3%。机制解释是反思打断了无效探索。这一点对 coding agent 的成本优化有直接启发：与其压缩上下文，不如更早发现自己在兜圈子。

**四是 MLE 的「窗口化 RL」和 SWE 的防泄漏细节。** WIRL 把两次实验结果之间的所有交互打包成一个窗口共享奖励，不等任务结束就能更新策略；SWE 采集前要从 Git 对象库里删掉暴露参考修复的对象，因为只把工作区重置到基础提交并不能从对象库里删掉它们，评测时才恢复。还有一个很朴素但常被忽略的做法：对每个候选任务同时跑参考补丁和空补丁，空补丁必须拿零分。这和 FDE-Gym 的「什么都不做 = 0」锚点是同一个思路。

## 🤔 我的判断

**定位：工程样本，「组织能力内化」路线的一个可信但证据偏薄的起点。**

亮点三条：

1. 委派接口加五值 status 的结构化回执，是一份可以直接搬进任何多代理 harness 的协议，哪怕你不训练模型。
2. 「外部监督造数据，推理时撤掉监督」的去监督化流程，给「把 harness 规则蒸馏进模型」提供了一个可复现的模板。
3. 按样本混合结果 RL 和多教师在线蒸馏，解决了「有的领域奖励便宜、有的领域奖励又贵又慢」的现实问题，并且把 harness 标签留在训练数据里。

问题与局限：编排和验证的直接增量小，关键消融做在教师而不是最终模型上；组织能力只在搜索类任务上训练和验证；多教师合并有损耗；横向对比的评测条件不统一。

对工程的直接启发：

- **先抄协议，再谈训练。** 在自己的 harness 里给子代理回执加 status、evidence、unresolved_issues 三个必填字段，主 agent 遇到 conflict 或 insufficient_evidence 就强制追查，这一步零训练成本。
- **把委派前提显式标成假设。** 派子任务时把「我以为是 X」单独列出来，允许子代理推翻它，并要求推翻时给证据。
- **对 MMP 这类确定性 harness，这篇不是威胁而是分工建议。** 模型可以学会何时反思，但何时允许花钱、何时允许写文件、何时必须停，仍然该是 harness 的显式规则。可以把「内化的自查」当成 harness 规则之下的一层软能力，而不是替代品。
- **做评测时加空补丁和参考补丁两条基线**，并把 Git 对象库的泄漏当成真实风险处理。

一句话收束：**会分工、会回头可以练进权重，但「回执里写明自己没把握」这条协议，今天就该写进你的 harness。**
