# 裁判看见参考才认对：推导缺口卡死工具参数验收

你有没有过这种体验：agent 工具调用里某个参数明明对——车辆 ID 在上一轮搜索结果里、默认值就写在 schema 里——可挂在门前的裁判模型硬是给到阈值之下，把本该放行的调用拦下来。你把截断窗口开大一点，History-only 的错杀会少一点，但默认值和需要推断的值还是过不去。**问题到底出在「信息不够」还是「裁判根本不会自己推」？**

The Fin AI 与 Yale、Cardiff 这篇 **DeRef**（arXiv:2610.18497）把答案钉死了：七个裁判、含 System One 的 CLM 与 Jev，都更愿意跟着输入里显式出现的参考值走；正确值只要对裁判「看不见出处」，接受率就会系统性掉一截，作者把这段落差叫 **derivation gap（推导缺口）**。看完我的感受：这不是再训一个更强裁判就能抹平的偏差，而是验收栈缺了一层「先写出期望值」的证据；补上之后，连埋源到截断外的对照集都能从接近随机抬到 98 以上。

## 核心摘要

工具调用裁判逐参数打分，但正确参数有五条推导路径——Visible（对话里直接可见）、History-only（在完整历史里但被截断裁掉）、Format（格式归一后才匹配）、Default（schema 默认或 don't-care）、No-source（无文本出处需推断）。作者在 FCRB、CFB、FinTrace 上测七个裁判（CLM、Jev、Qwen3-4B/8B、Qwen3.8-27B、Llama-3.1-8B、Mistral-7B），用「接受 80% 正确参数」的法官阈值 $\tau$ 定义 $\mathrm{Gap}_\tau(p)=A_\tau(\textsc{Visible})-A_\tau(p)$。CFB/FinTrace 上 out-of-view 缺口对每个裁判都显著，落在 **22.67–36.13** 点；无截断的 FCRB 上 Default 反而最大，**14.40–50.51** 点，说明缺口不只是截断伪影。源重定位对照把正确值埋到截断外、留错误 distractor 在视野内，四个主裁判 argument AUROC 从 **91.89–99.88** 掉到 **39.80–49.03**，对可见错误值的 AUROC 甚至只有 **26.71–39.88**。DeRef 用独立 deriver（主实验为 Qwen3.8-27B，thinking on）读完整未截断历史、看不见候选，为每个参数写出期望值与出处，再塞进裁判截断输入；12 组裁判×基准全部抬高 AUROC（**+1.44–22.14**），平均显著高于最强先验 RevisEval，埋源对照上抬到 **98.40–99.59**。价值定位：它把「裁判跟参考」从轶事变成可测机制，并给出不改裁判权重的工程补丁。

## 🎯 为什么这件事值得写

Agent 管线里，参数级裁判既是 reward model，也是执行前 guard。BFCL、ProvenanceGuard、ToolPRM 都在按参数查，但几乎没人按「值是怎么推出来的」切片错误。这和 [LLM-as-Judge](../../202609/week3/20260917_LLM-as-Judge_论文解读_裁判只是评测栈的一层如何搭闭环.md) 里「裁判只是评测栈一层」同一焦虑：你以为它在验正确性，其实它在做**可见证据匹配**。

更刺痛的是 System One。仓库里已有 [JEV-as-a-Judge](../../202609/week4/20260924_JEV-as-a-Judge_论文解读_自信就收下不确定就升级_决策裁判三分钱顶住强模型.md) 与 [JustAskJev](../../202609/week4/20260928_JustAskJev_论文解读_对齐失败检测别为每条准则再解码_一次问多题零样本就能筛.md) 讨论过 Jev/CLM 这类「直接吐概率」的快裁判；DeRef 明确写到 Jev 在「必须推导而非读出」时落后 GPT-6，而本文实测里 CLM、Jev 同样带着显著 derivation gap——**快裁判并没有逃过「跟参考」这条癖好**。

| 现象 | 常见解释 | DeRef 的证据 |
| --- | --- | --- |
| History-only 错杀 | 截断丢信息 | 全历史能收窄缺口，但不治 No-source；埋源对照里裁判会**偏向可见错误值** |
| Default 错杀 | 用户没提所以犹豫 | FCRB 无截断、schema 写明默认，缺口仍最大；复述 schema 几乎不救，写出推导的 reference 才救 |
| 放大模型 | 27B 会自己推 | Qwen3.8-27B out-of-view 缺口仍显著（12.29–29.76） |

## 🏗️ 机制：五条推导路径 + 独立 Derived Reference

**任务。** 历史 $H$ 含用户轮次、既往调用与完整返回；agent 提议函数 $f$ 的参数 $v_i$。裁判看上下文 $X$（可截断）与候选，输出 $s(v_i\mid a_i,X)\in[0,1]$。

**路径（按匹配优先级）。** Visible → History-only → Format → Default → No-source。正确性由基准金标决定，与路径无关。基率不能解释主要缺口：FCRB 默认正确率 77% vs Visible 75%；CFB History-only 83% vs Visible 82%。FinTrace No-source 正确率仅 45%（Visible 97.5%），低基率可能贡献了一部分缺口。

**Plain 输入。** 故意模拟部署：保留最近几步，每条 tool return 截到 1000 字符（OpenAI Agents SDK 有类似 trimmer；Anthropic 长跑 agent 也会清旧返回）。FCRB 单轮无截断。

**DeRef 两步。** (1) deriver 读完整 $H$ + schema，**不看候选**，为每个参数写期望值与出处（历史定不下来就明说）；(2) 把 reference 插进裁判输入（历史之后、函数描述之前），裁判本身零改动、仍看截断 Plain。同一状态的所有候选共享一份 reference，避免候选泄漏。主实验 deriver 固定为 Qwen3.8-27B。

## 🧪 关键证据

**Table 1：推导缺口（点）。**

| Judge | FCRB Out-of-view | FCRB Default | CFB Out-of-view | CFB History-only | FinTrace Out-of-view | FinTrace No-source |
| --- | --- | --- | --- | --- | --- | --- |
| CLM | 8.15 | 31.93 | 30.76 | 66.63 | 25.95 | 28.28 |
| Jev | 8.11 | 20.26 | 22.67 | 59.39 | 27.78 | 27.47 |
| Qwen3-8B | 0.63 | 14.40 | 33.30 | 74.87 | 24.04 | 25.72 |
| Qwen3.8-27B | 12.29 | 36.03 | 25.99 | 57.08 | 29.76 | 31.68 |
| Mistral-7B | 12.25 | 50.51 | 36.13 | 80.54 | 30.68 | 32.47 |

CFB 上 Qwen3-8B 的 $\tau$ 可以低到 0.002 仍接受 80% 正确参数，CLM 则到 0.631——所以必须按法官定 $\tau$，不能共用一个阈值比接受率。

**Table 2：argument AUROC（DeRef vs 先验）。**

| Judge | 输入 | FCRB | CFB | FinTrace |
| --- | --- | --- | --- | --- |
| CLM | Plain → DeRef | 72.51 → **89.59** | 63.41 → **85.55** | 83.36 → **89.10** |
| Jev | Plain → DeRef | 90.83 → **93.30** | 75.01 → **88.73** | 89.11 → **93.10** |
| Qwen3-8B | Plain → DeRef | 78.79 → **89.48** | 66.79 → **83.13** | 85.15 → **92.28** |
| Qwen3.8-27B | Plain → DeRef | 91.95 → 93.39 | 78.92 → **95.09** | 89.31 → 92.25 |

RevisEval 是最强先验；DeRef 在 12 对中赢 10、显著赢 8；仅 Qwen3.8-27B 在 FCRB/FinTrace 上略输 0.32/0.27（不显著）。Self-generated reference（裁判自己从截断输入写期望）最多比 Plain 高 3.01，全面低于 DeRef。给全历史而不给 reference，平均仍比 DeRef 低 11.58（CFB）/4.35（FinTrace）。裁判开 thinking 也补不回：Qwen3.8-27B thinking on 仍比「读 DeRef + thinking off」低 2.82–10.92。

**消融（CFB × Qwen3.8-27B）。** DeRef 95.09；deriver 不看全历史 85.46（−9.63）；换 Qwen3-8B deriver 88.56；deriver 关 thinking 88.18；只留解析出的期望值 90.90。全历史下「有 reference + thinking off」最好（96.01），说明增益来自 reference 本身。

**泼冷水。** 每条参数一个金标，reference 点名后可能误杀同样正确的另一写法；CFB/FinTrace 错误标签有作者构造成分，双人审计各抽 100 条未能确认 3%/4%，最坏情形分析下 DeRef 对 Plain 的增益仍显著；FinTrace No-source 缺口对四裁判中的三个并未被 DeRef 收窄；主结果固定一个 deriver；未评测前沿通用 LLM 当裁判。

## 🔬 最有意思的部分

1. **裁判会跟着错误参考走。** 把 reference 里正确值换成同状态错误值、其余文字不动：CFB/FCRB 上四裁判在 0.5 阈值下，正确接受率掉 15.36–57.07，错误接受率升 20.38–57.79，AUROC 从 92.16–99.91 掉到 42.63–77.92；连 Plain 原本判对的也会被推翻。
2. **匹配片段也能洗白错误候选。** 按候选出现处从全历史抽 snippet（必然含该值）塞进输入，59 个错误 History-only 上四裁判均分升 14.28–39.39；0.5 阈值下 CLM/Jev/Qwen3-8B 会接受其中 28–49 个。
3. **「信息在视野里」不等于「算参考」。** FCRB 142 个 DeRef 认定「该用默认」的正确默认：复述 schema + 列请求相关词，接受率最多动 6.18；写出推导的 reference 把接受抬到 73.02–88.06。
4. **藏候选很关键。** 让 deriver 看见候选的 DeRef-v 在 CFB 上更高、在 FCRB/FinTrace 更低，且把错误候选写成期望值的频率最高可到 DeRef 的六倍——所以主方案坚持盲推。
5. **System One 不是例外。** CLM 输入长度默认 2048、埋源对照也不给全历史，仍被 DeRef 拉回 98+；这和只换更大 LLM 裁判是两条不同的工程路。

## 🤔 我的判断

定位：**测量基础设施 + 可插拔验收补丁**。它量清了「裁判跟参考」这条机制，并用独立 deriver 把缺口变成可修的输入问题，而不是再训一轮裁判权重。

亮点三条：

1. 按推导路径切片，把截断、默认、无出处三类错误分开量，而不是只报总分；
2. 源重定位 + reference 替换两组对照，把因果钉在「显式参考」上，而不只是相关；
3. DeRef 零改裁判、共享 reference、盲推 deriver，工程上可以直接挂在现有 guard / ToolPRM 前面。

问题与局限：金标单值假设；部分错误标签有噪声；No-source 仍难；deriver 家族未铺开；伦理上错 reference 会系统性翻盘，高风险调用仍需人审或非裁判闸。

对工程的直接启发：**(1)** 工具参数验收不要假设裁判会「自己从历史推」——截断窗口里没有出处的正确默认/推断值，按本文几乎注定吃亏；**(2)** 在裁判前加一层**看不见候选**的 reference 生成，比给全历史或让裁判开 thinking 更划算；**(3)** ProvenanceGuard 式「带着候选去摘证据」会有确认偏误，优先盲推；**(4)** 部署时把 derived reference 和分数一起留档，方便审计为什么放行；**(5)** 评 System One（CLM/Jev）时务必按推导路径切片，别只看整体 AUROC——和 [JustAskJev](../../202609/week4/20260928_JustAskJev_论文解读_对齐失败检测别为每条准则再解码_一次问多题零样本就能筛.md) 的「一次问多题」可以叠用，但先把参考补上。

一句话收束：**裁判验的不是「对不对」，而是「输入里有没有写着它该是什么」；DeRef 证明，先盲写出那句参考，推导缺口才从系统性错杀变成可修的输入问题。**
