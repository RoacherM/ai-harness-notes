# 涨分不等于会持续学习：共享提示词越改越忘，相似检索还会撞车

你有没有过这种体验：给 agent 配了一套「自进化」机制，跑一周 SQL 任务，提示词里攒了一堆漂亮的规则，分数也涨了；第二周换去做工具调用，发现它开始对用户「先查一下 schema」；第三周回头再跑 SQL，上周学会的东西已经被压成了一行。总分看着还是正的，可你心里清楚：**它不是在积累，是在来回覆盖。**

Google DeepMind 和 Mila 的这篇 **Are Self-Evolving Agents Continual Learners?**（arXiv:2610.25858）把这个直觉做成了一套正经的持续学习实验。它不提新方法，只问一个问题：今天主流的「冻住权重、改 harness」的自进化 agent，放进一条会漂移的任务流里，算不算合格的持续学习者？看完我的感受：这是近期**最该被做 harness 自进化的人读一遍**的诊断论文。它把「可塑性和稳定性此消彼长」这条老规律，第一次清楚地钉在了提示词、记忆和脚手架代码上。

## 核心摘要

作者把三种代表性的非参数自进化方法放进四条漂移任务流里：**ReasoningBank**（把每个 episode 蒸馏成一条记忆，按 query 相似度取最近一条注入）、**GEPA**（反思式改写系统提示词里的共享策略段）、**Meta-Harness**（用 coding agent 改整个工作区，包括系统提示词、记忆和技能文件、控制器代码 `harness.py`，并且只在当前子块验证集上涨分才接受）。四条流分别隔离主题漂移（三个 BIRD 数据库）、工作流漂移（BFCL-Miss 要求追问缺参，BFCL-Base 惩罚多余追问）、领域漂移（ScienceWorld 到 BFCL 到 BIRD）和三者串联的复合漂移。每组 50 道训练题连续成块，任务标签和块边界都不告诉 agent，底座固定为 Gemini 3.6 Flash 加 ReAct 循环。评测上，每 50 步存一次 harness 快照，在所有组的独立留出集上各跑 8 次，再把结果拆成**块内可塑性 P** 和**跨块稳定性 S**（包括块开始前对没见过任务的干扰 I，和块结束后的遗忘 F）。结论三条：自进化在多数流上确实涨了总分（四流平均终点优势 GEPA +3.7、ReasoningBank +2.5、Meta-Harness +1.4）；但 **12 个「方法乘场景」点上 P 和 S 的相关系数是 -0.72（p=0.008）**，最能学的一定最不稳；自改写方法的失败来自「全局共享面」，检索方法的失败来自「相似度不等于兼容」。价值定位：一份给 harness 自进化补上持续学习度量的方法论，加三类可以直接拿去排查的失败机制。

## 🎯 为什么这件事值得写

过去一年 harness 自进化的论文几乎都在单一基准上报告「涨了多少」：GEPA 在一个任务族上改提示词，Meta-Harness 在一个任务族上搜脚手架，ReasoningBank 在一个任务族上攒记忆。可真实部署从来不是单一任务族：同一套 harness 要服务一串异质任务，**为任务 A 做的每一次修改，都会作用在之后所有任务上**。

这篇论文的价值在于把问题换了一个框：harness 本身就是跨任务携带的状态，那它就该接受持续学习的标准体检。

| 视角 | 以前怎么看自进化 | 这篇怎么看 |
| --- | --- | --- |
| 评测对象 | 单任务族终点分数 | 漂移任务流上每个检查点、每个组的分数 |
| 好坏标准 | 涨分 | 涨分的来源是均衡增益，还是用别的组的损失换来的 |
| 失败归因 | 「提示词写得不好」 | 干扰、压缩覆盖、行为反转、检索撞车 |

这和我们之前读过的 EvoHarnessBench（脚手架越加越忘）、SelfEvolvingHarness（新鲜验证集加回归预算）是一条线上的，但这篇第一次把三种主流方法放在同一底座、同一流、同一套 P/S 度量下横比，结论更硬。

## 🏗️ 机制：任务流、三种演化器、P/S 分解

**任务流的形式化。** 任务流由 K 个任务族和权重序列定义，第 t 步的输入从混合分布里采样：

$$
x_t \sim P_t = \sum_{k=1}^{K} w_{t,k}\,\mathcal{D}_k
$$

漂移流里 \( w_t \) 是分段常数的 one-hot：每一块只来自一个组。非参数自进化只更新 harness \( c \)，权重 \( \theta \) 冻结：

$$
c_{t+1} = f\left(c_t, \mathcal{H}_t\right)
$$

**四条流。**

1. 主题漂移：BIRD-F1 到 BIRD-Code 到 BIRD-TP，任务形式不变，每个库有自己的 schema 和本地约定；
2. 工作流漂移：BFCL-Miss 到 BFCL-Base，同一套 API，前者要求追问缺失参数，后者参数齐全、多问一句就扣分；
3. 领域漂移：ScienceWorld 到 BFCL-Base 到 BIRD-F1，观测和动作空间全变；
4. 复合漂移：BIRD-Code 到 BIRD-F1 到 BFCL-Miss 到 BFCL-Base，主题、领域、工作流三种变化依次出现。

**三种演化器的「可编辑面」逐级扩大。** ReasoningBank 只在系统提示词尾部的固定槽位注入 top-1 记忆；GEPA 改写系统提示词主体里的策略段；Meta-Harness 可以同时改提示词、记忆和技能文件以及控制器代码，提议者跑在 opencode 里，同样用 Gemini 3.6 Flash。环境说明（preamble）属于环境，任何方法都不能改。

**度量。** 设 \( A[t,k] \) 是快照 \( c_t \) 在组 k 留出集上的准确率，\( B_k \) 是种子 harness 的基线。块内可塑性看组 k 自己的块结束时涨了多少：

$$
P = \frac{1}{K}\sum_{k}\left(A[\tau_k,k]-B_k\right)
$$

稳定性由两部分组成：块开始前在没见过的组上跌破基线多少（干扰 \( I_k \)），块结束后到流末尾掉了多少（遗忘 \( F_k \)）：

$$
S = -\frac{1}{K}\sum_k \left(I_k + F_k\right)
$$

这套拆法的好处是：**同样 +3 的总分，可以是每组都涨一点，也可以是当前组涨很多、别的组被拖下水**，前者才叫持续学习。

## 🧪 关键证据

**总体与分解（四流平均，单位为百分点）。**

| 方法 | 终点优势 | 可塑性 P | 稳定性 S |
| --- | --- | --- | --- |
| ReasoningBank | +2.5 | +3.3 | **-1.9** |
| GEPA | **+3.7** | **+6.2** | -4.3 |
| Meta-Harness | +1.4 | 正文未单独汇总 | 领域流 -3.1、复合流 -4.4 |

三种方法的平均优势（所有检查点平均）落在 +1.8 到 +3.1 之间。

GEPA 在工作流漂移上可塑性 +11.0，复合漂移 +7.5，也是每个场景里最不稳的；ReasoningBank 稳定性最好（领域流 -0.4、复合流 -1.4），代价是可塑性只有 GEPA 一半左右。主题漂移上三种方法的净变化接近零或略负（GEPA -1.7、ReasoningBank +0.3、Meta-Harness -1.5）。

**Meta-Harness 的「稳」是假象。** 它在主题流和工作流流上稳定性看起来不错（-0.3、-0.5），原因是验证闸拒掉了一半以上的候选修改，后面几块基本冻结。去掉这个闸，稳定性立刻掉到 -3.1 和 -5.5。

**交错混合也救不了共享提示词。** 把四组均匀打散成混合流（相当于梯度持续学习里的 rehearsal），GEPA 的终点优势反而从 +5.8 掉到 +0.9，BIRD-F1 跌到 -4.5。各组规则依然在同一段提示词里抢地盘。

**泼冷水。** 第一，只用了一个底座 Gemini 3.6 Flash，更强模型会不会更擅长「分区写规则」没有测。第二，每组 50 道训练题、50 道留出题，块内只有 50 步，很多差值只有一两个点，论文主表没有给置信区间。第三，三种方法都按原始设定跑，没有给任何一种加上任务识别或分区机制，所以结论是「现有方法不行」，不是「这条路不行」。

## 🔬 最有意思的部分

**一是「先学的规则提前伤人」。** 复合流里，两块 BIRD 训练完、一道 BFCL 题都还没见，BFCL-Miss 就已经跌了 6.8 点（GEPA）和 4.8 点（Meta-Harness）。翻出第 100 步的提示词一看：两种方法都把「必须先用 sqlite3 探索 schema、交互式验证」写进了全局系统提示词。到了 BFCL-Miss，这条规则让 agent 去调查询类工具，而不是开口问用户缺了什么参数。**写给 SQL 的好习惯，在另一类任务上就是坏习惯**，而共享提示词没有任何机制区分。

**二是遗忘的形态是「压缩」。** 作者把 GEPA 策略段的每一行按首次写入的块打标签，跟踪字符占比。主题流里，BIRD-F1 的规则从第 50 步占 100% 降到第 150 步的 40.2%，准确率同步从 +7.5 掉到 -2.0。复合流更狠：进入 BFCL-Miss 后，GEPA 把 7 个 BIRD 小节共 3,386 字符压成一个 1,034 字符的通用小节，BIRD-F1 占比从 59.5% 掉到 5.8%，+4.0 的增益到流末尾归零。有意思的是，领域流里 GEPA 偶尔会自发「只追加不改写」，ScienceWorld 的 6 个小节原样保留，遗忘为 0，但这种行为不可靠，换一条流就消失了。

**三是同一域里的行为反转。** 工作流漂移最致命：BFCL-Miss 和 BFCL-Base 用同一套 API、措辞几乎一样，模型根本意识不到任务变了。种子 agent 在 BFCL-Miss 上只有 3.8% 到 5.8% 的回合会追问；GEPA 学完 BFCL-Miss 把追问率提到 29.8%（准确率 +15.5），学完 BFCL-Base 又把规则改成「直接执行」，追问率降到 11.2%，准确率回落 13.0 点。Meta-Harness 更戏剧：第 150 步它在提示词、记忆、技能三个文件里同时写下「缺参时禁止猜测调用」，第 175 步一次被接受的修改把三个文件全部覆盖成「按顺序立即执行工具」，追问率从 60.8% 跌到 8.5%。

**四是相似度检索的两种病。** ReasoningBank 没有相似度阈值，所以任何一组在自己的块开始前，100% 的回合都会拿到外组记忆：复合流里每一个 BFCL-Miss 回合都被塞了一条 BIRD 的 SQL 反思。加阈值也不够：同为 text-to-SQL 的不同数据库之间，最近邻相似度 0.60 到 0.64，和完全不同领域之间的 0.56 到 0.63 几乎分不开。更糟的是**检索撞车**：BFCL-Miss 和 BFCL-Base 的跨组最近邻相似度 0.835 到 0.840，和组内 0.834 到 0.837 没有区别，流末尾 52% 的 BFCL-Miss 回合取到的是 BFCL-Base 的「直接执行」记忆。**语义相似说明话题相近，不说明那条轨迹的工作流适用于眼前这个任务。**

## 🤔 我的判断

**定位：诊断型论文，度量和失败机制的价值远大于结论本身。**

亮点三条：

1. 把 harness 当成持续学习的状态来体检，P/S 分解加「块前干扰」这一项，补上了自进化评测里最缺的一块。只报终点分数的自进化论文，以后都应该被追问一句「拿谁的损失换的」。
2. 提示词字符占比追踪是一个很便宜、很直观的遗忘探针，任何用共享提示词或共享 AGENTS.md 承载经验的系统都可以照做。
3. 「验证闸带来的稳定是冻结带来的稳定」这个发现很重要：门控不等于持续学习，它可能只是让系统停止学习。

问题与局限：单底座、小样本、无置信区间；没有尝试最直接的补救（按任务类型分区的提示词、带工作流标签的记忆键、阈值加拒绝注入），所以留给读者的是问题而不是答案；Meta-Harness 的提议者跑在 opencode 而执行 agent 是朴素 ReAct，两者能力不对等，对它的比较略不公平。

对工程的直接启发，尤其是 Pi 这类显式 Manifest 的 harness：

- **经验要分区写，不要往一个全局提示词里堆。** Rules/Skills 应该带适用条件（任务类型、工具集、工作流签名），默认不加载，命中才注入；这正是 Manifest 显式化和关掉 ambient 的意义。
- **记忆检索的键不能只有 query 文本。** 至少要加上工作流或结果标签（这次是「追问」还是「直接执行」），并设拒绝阈值，宁可不注入也不要注入外组记忆。
- **回归集要覆盖「还没来的任务」。** 评测自进化时，除了老任务的遗忘，还要测一组尚未训练的任务，看新规则会不会提前伤人。
- **把「改写型修改」和「追加型修改」区分开审。** 一次修改如果删除或压缩了旧规则，应该比纯追加接受更严格的门槛。

一句话收束：**自进化 agent 今天会学，但还不会记；要让它成为持续学习者，先得让 harness 知道每条经验该写给谁。**
