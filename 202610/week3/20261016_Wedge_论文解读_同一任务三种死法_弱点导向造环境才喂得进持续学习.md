# 同一任务三种死法：弱点导向造环境，才喂得进持续学习

你有没有过这种体验：导航 / 具身 agent 已经能在仿真里「平均还行」，你继续堆随机场景、甚至专挑它失败过的 hard example 做适配——结果有的策略几乎不动，有的在训练域涨了、换个仿真器又吐回去。同一句任务「去找那个物体」，有的死在目标几乎看不见，有的死在要先走很长一段看不见目标的盲路径。**如果失败原因是策略特异的，那「为任务造环境」是不是问错了——该问的是「为当前策略还没学会的机制造环境」？**

UNC Chapel Hill 的 Yue Zhang、Han Lin、Zun Wang、Yidong Huang、Zaid Khan、Mohit Bansal 这篇 **Wedge / WEDGE**（arXiv:2610.19420）把失败从诊断报告升级成 **可执行的造环境规格**：对比成功 / 失败 rollout，让 LLM 提出可计算的弱点特征 → 自动过覆盖 / 非冗余 / 可预测 / 增量价值四闸 → 映射到可控因子（目标摆放、起点、布局）→ 在弱区间造环境 → 再用 5 次 rollout 校准，只留 2–3/5 成功的「学得动」样本 → 按原机制适配（RL / LoRA / in-context）。看完我的感受：这是把 [FailConf](./20261015_FailConf_论文解读_agent能学会预言自己失败吗_结果锚定置信度校准.md) 式「失败信号」和 [EMHO](./20261015_EMHO_论文解读_模型冻住改脚手架_经验轨迹让具身harness自己进化.md) / [ReHarness](../week2/20261012_ReHarness_论文解读_反思写进记忆就不再改_反向修订让harness状态也能吃到下游反馈.md) 式「外围也要吃反馈」接到 **环境生成器** 上——失败→训练数据闭环，不只改权重或脚手架。

## 核心摘要

Wedge（weakness-guided environment generation）在同一 ObjectNav 任务上诊断策略特异弱点：诊断集上每轮抽 15 成 / 15 败，用场景 / 任务 / agent 原语让 Gemini-2.5-Pro 提出可执行 Python 特征（如 `target_visibility`、`blind_path_ratio`、`room_hops`）；顺序校验覆盖率 \(\tau_{\mathrm{cov}}=0.95\)、Spearman 非冗余 \(\tau_\rho=0.85\)、三分位成功率差 \(\Delta_f\geq 10\) 点且 holdout 方向一致、以及 CVD AUC 增量 \(\geq 0.01\)。每轮只盯 ΔSR 最大的一条弱点造环境，并对候选做 5 次 rollout，保留成功次数为 2–3 的中间难度。三 agent：ProcTHOR 训的 DD-PPO（弱点 `target_visibility`，ΔSR **28.5**）继续 RL 10M 步，ProcTHOR SR **82.1→85.6**；HM3D 训的 Uni-NaVid（`blind_path_ratio`，ΔSR **37.3**）在 ProcTHOR 上 LoRA 自成功轨迹，ProcTHOR **51.6→55.7**、回测 HM3D **69.2→73.4**；Gemini-3.8-flash（`blind_path_ratio`，ΔSR **37.6**）用弱点匹配成功轨迹做 in-context，ProcTHOR **41.0→44.3**、HM3D **57.9→64.2**。三者均稳赢匹配预算的 random / hard-example；硬例挖掘在 Uni-NaVid 上 ProcTHOR 涨了却几乎不迁移 HM3D。迭代再诊断：DD-PPO / Uni-NaVid 主弱点仍在，Gemini 第一轮后主弱点迁到 `target_room_remoteness`。校准子集仅占弱点匹配环境的 **16%**（668/4215），却高于用全集合适配（85.4 vs 84.4 SR）。价值定位：**持续学习用的策略条件环境生成**——把失败模式写成可验证、可控制、可校准的造世界规格。

## 🎯 为什么这件事值得写

仿真让造环境变便宜，但「更真实 / 更多样 / 更难」不等于「当前策略还缺什么」。任务条件生成（为「找杯子」造房）仍可能反复喂策略已会的机制，漏掉它真正崩的那一截。Wedge 的核心分野是：**生成目标从任务规格改成策略失败模式**——同一任务、不同策略，该造的世界可以完全不同。

这和 harness / 持续学习栈几条线索对齐：

- [EmbodiedCLBench](../week2/20261012_EmbodiedCLBench_论文解读_做过一道基础题就涨三倍_再做五道却不再涨_具身持续学习卡在经验提取.md)：经验提取与再练内容决定持续学习是否卡住；
- [EMHO](./20261015_EMHO_论文解读_模型冻住改脚手架_经验轨迹让具身harness自己进化.md)：轨迹驱动外围进化；Wedge 则驱动 **环境侧**；
- [SkillPivot](../../202609/week4/20260925_SkillPivot_论文解读_失败别整轨反思_先找偏航点再对比后缀改技能.md)：失败要定位到可改的点，而不是整轨空反思；
- [FailConf](./20261015_FailConf_论文解读_agent能学会预言自己失败吗_结果锚定置信度校准.md)：失败结局可当校准标签——Wedge 进一步问：失败分布能不能当 **造数据规格**？

| 造环境方式 | 条件对象 | 风险 |
| --- | --- | --- |
| 真实感 / 多样性优先 | 世界统计 | 与当前策略弱点无关 |
| 任务条件生成 | 任务描述 | 忽略策略已掌握部分 |
| Hard-example 挖掘 | 成败标签 | 可能过难 / 不迁移 |
| **Wedge** | 可验证弱点特征 | 需原语与可控仿真因子 |

## 🏗️ 机制：诊断 → 验证 → 造弱区间 → 校准 → 适配

**问题形式。** 给定预训练策略 \(\pi\)，要从其成功 / 失败对比中找出环境特征 \(f\)，再生成落在弱区间、且对 \(\pi\)「学得动」的训练 episode。

**弱点发现（Fig. 2）。** 冻结策略跑诊断集 \(\mathcal{D}\)。LLM 基于结构化原语（场景布局、目标可见性相关量、路径与房间跳转、覆盖 / 重访 / 是否进过目标房等）提出：假设 + 短理由 + **可执行**特征函数。例：`blind_path_ratio` = 目标首次可见前路程 / 总路径，刻画「要先盲走多久」。

**四闸验证（Appendix）。** 覆盖 → 非冗余 → 可预测（三分位 ΔSR、显著性、70/30 holdout）→ 增量 AUC。不过任一闸就换一批对比样本再提案。最终 \(\mathcal{F}_\pi\) 为该策略的弱点集；每轮适配只取 ΔSR 最大者，避免多弱点对应不同因子时因果缠在一起。

**造环境（Fig. 3）。** 由特征依赖的因子决定算子：如抬/压 `target_visibility` 就在房内挪目标；控 `blind_path_ratio` 就重采样起点或布局。只保留特征值落在诊断集上「弱于全局成功率」的区间的候选；布局不够时再生成新布局。

**Rollout 校准。** 弱点匹配 ≠ 可学：太易给不出梯度，太难几乎采不到成功示范。对每个候选滚 5 次，留 \(n_{\mathrm{succ}}\in\{2,3\}\)。DD-PPO 用校准后的 668 个环境继续 RL；Uni-NaVid 在与 HM3D 共享的六类物体上对自成功轨迹 LoRA；闭源 Gemini 则把成功轨迹写成 in-context 示例（从 64 条练习轨迹里选 1 条 worked example，基线同预算）。

**迭代。** 适配后再跑同一诊断流程：主弱点可能仍在，也可能迁移——下一轮造环境跟新诊断走。

## 🧪 关键证据

**策略特异诊断（Table 1）。** 同任务三画像：DD-PPO 吃 `target_visibility`（ΔSR **28.5**，并挖出互补的 `doorway_visibility`）；Uni-NaVid / Gemini 都吃 `blind_path_ratio`（**37.3 / 37.6**），Uni-NaVid 次要还有 `room_hops`（34.8）。**有用训练环境取决于当前策略，而不是任务标签 alone。**

**ProcTHOR 域内适配。** DD-PPO：预训练 82.1；random 82.3、hard-mined 82.4 几乎不动；Wedge R1/R2 **85.4 / 85.6**，SPL 58.2→**59.8**。Uni-NaVid：random self-rollout 反而掉到 46.6；hard 到 53.1；Wedge **54.5→55.7**（SPL 35.3→**38.5**）。Gemini：zero-shot 41.0；random 40.7、hard 41.8；Wedge **43.7→44.3**。

**跨仿真器迁移（ProcTHOR 适配后测 HM3D，不再训）。** Uni-NaVid：hard 在 ProcTHOR 有收益但 HM3D 停在 **69.0**（预训练 69.2）；random 掉到 67.1；Wedge 到 **73.4**（SPL 约 28.6）。Gemini：random/hard HM3D **58.0 / 60.9**；Wedge R1/R2 **63.5 / 64.2**。说明弱点条件信号比「难」更能跨域。

**再诊断（Fig. 4a）。** DD-PPO 主弱点仍是可见性，且首轮后近似饱和；Uni-NaVid 仍盲路径、继续小涨；Gemini 主弱点迁到 `target_room_remoteness`——闭环能确认残留弱点，也能发现新瓶颈。

**增益集中在弱区间（Fig. 4b）。** DD-PPO 在 Bowl / Laptop / AlarmClock 等小而难看目标上增益更大；Gemini 长盲路径段 **+7.0 SR**，短路径几乎不动。

**校准消融（Table 2）。** 全弱点匹配 4,215 环境 → 84.4 SR；校准 2–3/5 的 **668（16%）** → **85.4**。Uni-NaVid 上加硬例占比（hard-heavy 25.1%）反而略伤。无引导硬挖掘要约 **2×** 候选评估量才凑够同样多的「难目标摆放」（约 8.4k vs 4.2k 候选，42k vs 21k rollout）。

**泼冷水。** 依赖可程序化原语与可控仿真因子，换到不可随意改布局的真实世界会难很多；诊断 LLM 本身是 Gemini-2.5-Pro，提案质量未系统换模型消融；导航 ObjectNav 设定，操作 / 长期家务等更复杂动作空间是否同构未证；Gemini 适配只塞极少 in-context 例，上限可能还高。

## 🔬 最有意思的部分

1. **「难」不等于「对症」。** Hard-mined 在 Uni-NaVid 上域内有效、HM3D 无效；Wedge 两边一起涨——持续学习数据该按 **机制弱点** 筛，不是按失败标签筛。
2. **中间难度校准是一等公民。** 弱点匹配后仍有大量已会或尚不可达样本；2–3/5 成功带把「可学世界」从「暴露弱点的世界」里抠出来。
3. **同一框架吃三种适配器。** RL 续训、LoRA 自模仿、闭源 in-context——说明造环境规格可以跟 **原训练机制** 解耦，只替换数据分布。
4. **再诊断揭示非平稳弱点。** 适配会改失败面；固定一张弱点表做多轮课程，会训错下一轮。这和 [ReHarness](../week2/20261012_ReHarness_论文解读_反思写进记忆就不再改_反向修订让harness状态也能吃到下游反馈.md)「写进记忆的反思也要能被下游反馈改」同构：**诊断本身也要闭环。**
5. **和 EMHO 的分工。** EMHO 冻模型改脚手架；Wedge 冻（或轻改）策略、改世界分布——harness 进化与环境进化是持续学习的两扇门。

## 🤔 我的判断

定位：**面向 agent 持续适配的策略条件环境生成框架**（方法 + 诊断协议），主题落在 failure→training data / continual learning，而不是纯视觉导航刷分。

亮点三条：

1. 把失败对比落成可执行、可自动验证的弱点特征，而不是口头失败 taxonomy；
2. 造环境 + rollout 校准两段式，同时对准「暴露弱点」与「学得动」；
3. 跨三种 agent / 适配机制，且 ProcTHOR→HM3D 迁移与迭代再诊断证据扎实。

问题与局限：强依赖可程序化仿真控制；诊断 LLM 与原语词表会限制可发现弱点空间；任务仍是室内 ObjectNav；真实机器人上的因子映射未展开。

对工程的直接启发：**(1)** 做持续学习数据管道时，先挖 **策略特异、可计算的失败特征**，再映射到可控生成因子；**(2)** 四闸（覆盖 / 非冗余 / 可预测 / 增量）可直接借到其他「LLM 提案特征」场景，避免故事型弱点；**(3)** 保留中间成功率带，别只喂全败或全胜；**(4)** 每轮适配后 **重诊断**，允许主弱点迁移；**(5)** 评迁移时至少留一个生成域外的评测域——否则 hard example 很容易「域内自嗨」。

一句话收束：**失败不该停在报表里；把它写成可验证的弱点规格，世界生成器才能按每个策略还缺的那一截机制，造出真正喂得进持续学习的数据。**
