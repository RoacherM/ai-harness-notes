# 读对却做错：System One 在 agent 循环里的决策失败不是读不懂

你有没有过这种体验：挂在 agent 循环里的快裁判——Jev、CLM、各种 letter/pointer head——在微软延迟面板上只要几十到两百毫秒，账单也便宜，可一旦选错动作，你只能盯着一个错误概率分布干瞪眼。没有 chain-of-thought 可读。你不知道它是没看懂上一步工具失败了，还是事实都读对了却仍去拿错的微波炉。**「读错」和「决策错」在最终动作准确率上是同一类失败——可工程上该修状态表示，还是该把组合交给代码？**

CMU 的 Yubo Li、Ramayya Krishnan、Rema Padman 这篇 **Reading Right, Acting Wrong**（arXiv:2610.18579）用行为学办法拆开：同一冻结决策状态上，把「下一步动作」和「事实探针」各自独立作答，交叉成四种可观测结局。看完我的感受：对强快系统来说，**错动作多半跟在正确阅读后面**；而且越准，这种「读对却做错」占比越高——这不是弱模型噪音，而是强 System One 的特征失败。

## 核心摘要

作者冻结一份 **65,228** 条记录的基准（其中 **19,663** 条配对测试状态），覆盖 ALFWorld、BabyAI-Text、TextWorld、τ²-bench、工具选择、网页导航与编码轨迹；金标只由 agent 已见信息计算，可接纳动作全部放进上下文。评测十七个快系统（托管 API、开权 System One、冻结 LLM 的 System One 读出、以及 thinking-off 似然读出）并以 GPT-6.1 为推理参照。主结论四条：(1) 六个最准系统上，**73–85%** 的决策错误发生在「每个测得事实都答对」的状态，且该份额随准确率上升；(2) 十四个合格快系统在同一 **141** 个状态上全部「事实对、动作错」，置换零假设期望为零；(3) 在探针**按构造足以决定动作**的生成状态上，从轨迹同时读写+决策会掉 **20–45** 点，用模型自己的事实答案可收回 **15–28** 点，**用代码从事实答案合成动作可达 0.96–1.00**；(4) 回到真实状态，benchmark 探针最多只加约 **7** 点，ALFWorld 上「下一步子目标」对 JEV 可加 **16.3** 点，任意事实块最多约 **5**。价值定位：把 System One 的失败从「黑箱错动作」变成可诊断的「读 vs 决策」面板，并指出 agent 该让模型多用窄问题读、把组合交给代码/规划器。

System One 家族（TypeSafe JEV、OpenAI Decisions、Clef、Kev、CLM、Laya、各类 letter/pointer 读出）中位延迟约 **27–225 ms**，对比开权 LLM 似然读出 **317–947 ms**、GPT-6.1 约 **2.3 s**。便宜到可以每步都问，但错了也没有推理链可审计——所以必须用配对探针做行为诊断，而不是事后编理由。

| 结局 | 含义（作者刻意限制） |
| --- | --- |
| U1D1 | 测得事实全对且动作对 |
| U1D0 | 事实全对、动作错——暗示决策失败，但需探针充分才可归因 |
| U0D1 | 有事实错但仍动作对——不证明捷径 |
| U0D0 | 都错 |

## 🏗️ 机制：配对测量 + 充分性判据

**决策状态 $s$**：目标、已执行历史与观察、规则/策略、可接纳动作集 $A(s)$。模型必须从 $A(s)$ 选一个，从不生成动作；金标 $G(s)$ 只由 agent 可见信息计算。

**事实探针**：上一步是否成功、位置与持有物、子目标是否完成、动作是否被允许等——每题在同一状态上**独立**作答，答案不进其他题的输入。

**充分性（模型无关）**：对共享探针向量的状态组 $S$，若 $\bigcap_{s\in S} G(s)\neq\emptyset$，则探针组足以支撑「U1D0 → 决策失败」的诊断。作者另构造满足该条件的生成状态，再回看真实状态。

**受控变体**：去掉历史、最小对观察编辑、声明规则变更、轨迹长度与关键观察距离梯子；外加延迟/成本面板与校准。

## 🧪 关键证据

**Table 2（19,663 配对测试，节选）。** JEV 决策准确率 $D=0.763$，事实全对份额 $U=0.833$，错误中 U=1 占比 **73.1%**；Eikos-27B $D=0.795$（最快系统最高）、错误中 U=1 占 **77.7%**；Gemma-4-31B 似然读出 $D=0.811$、**80.9%**；GPT-6.1 $D=0.884$、**85.2%**。准确率越高，读对却做错的错误份额越大（Figure 3b）。

**结构化而非噪音。** 十四个合格快系统产生的 53,382 次 U1D0 事件里，**56%** 落在至少七个系统共同失败的状态（置换零假设仅 16%）；同一 **141** 个状态上全部十四个都 U1D0（零假设期望约 0）。GPT-6.1 在这 141 个上准确率仅约 **40%**。

**组合失败（§6.1，1,200 生成测试状态）。** 探针按构造充分时：多数系统「只给事实」远好于「原始轨迹」；用自身探针答案几乎收回缺口（JEV 0.791→0.968，+17.7）；**代码从事实答案合成动作**达 0.996（JEV）/1.000（Clef）。置信度级联：JEV 在置信度 <0.7 时才二次询问，约 **38%** 状态二次请求即可到 **0.932**。

**真实状态缺的是子目标（§6.2–6.3）。** 2,783 真实配对上，正确探针答案对多数快系统只加 **2.9–7.1** 点。644 个 ALFWorld 状态上，决策向事实块对 JEV 仅 +5.3，**下一步子目标 +16.3**，事实+子目标 **+21.3** 到 0.929；JEV 单独问子目标正确率仅 **66.8%**，且 41% 的独断错误是「事实对、子目标错」。对 Clef/Gemma，子目标块帮助更小，且近半错误发生在「事实与子目标分题都答对」之后——说明瓶颈因系统而异。

**校准差异大于准确率差异。** ECE：Cygnet **2.6%**、JEV **6.8%**、Torchcast **7.2%**，Vega-27B 可到 **26.6%**；Gemma 似然读出均值置信 **0.98** 对准确率 **0.79**（ECE 19.1%）。政策编辑读对但按编辑行动的比例仅 **22–72%**（摘要）。

**泼冷水。** 配对结局是行为证据，不识别内部计算；探针不穷尽全部相关事实；冻结轨迹非闭环执行；部分 ALFWorld 共置 receptacle 标签噪声使主结论偏保守；部署栈/读出/输入上限因系统而异。

## 🔬 最有意思的部分

1. **越强越「读对却做错」。** 这不是讽刺弱模型，而是准确率上升后，剩余错误更集中在决策侧——leaderboard 分数会掩盖这种结构。
2. **同一批状态打败所有快系统。** 141 个共享 U1D0 状态是比均匀抽样更锋利的诊断样本。
3. **自己的答案 + 代码组合** 在充分探针设定下几乎封顶；GPT-6.1 几乎无增益，因为它的错误本身是误读，自写摘要会复读错误。
4. **不完整摘要会拉偏。** 列出「未访问 receptacle」会把 Gemma/Qwen 从已知物体的 fetch 拽去 search；额外信息非中性。
5. **和 DeRef 同谱系。** DeRef 说裁判跟可见参考；本文说决策模型读对事实却不会组合成动作——都指向「别假设单次前向会自己完成组合」。

## 🤔 我的判断

定位：**System One / Jev 族的诊断基础设施**，不是再刷一个动作准确率榜。

亮点三条：

1. 配对探针把「读 vs 决策」变成四种可计数结局，并给出模型无关的充分性判据；
2. 「生成充分状态 → 代码组合修复」与「真实状态缺子目标」两段对照，把失败类型拆开；
3. 成本/延迟/校准同台，提醒「快 ≠ 便宜到可盲目信任」。

问题与局限：单决策冻结轨迹；探针覆盖有限；部分标签噪声；闭环与多步后悔未测。

对工程的直接启发：**(1)** 评 Jev/CLM/Decisions 不要只报 $D$，至少报 U1D0 份额与共享失败状态；**(2)** 部署模式对齐作者意图——**多窄问题并行读，组合交给代码/规划器**，不确定状态再级联二次询问；**(3)** 真实家务类任务优先显式子目标，而不是再塞一堆事实摘要；**(4)** 用原生置信度做升级闸前先看 ECE——和 [JEV-as-a-Judge](../../202609/week4/20260924_JEV-as-a-Judge_论文解读_自信就收下不确定就升级_决策裁判三分钱顶住强模型.md) 的「不确定就升级」同一逻辑；**(5)** 与 [DeRef](./20261015_DeRef_论文解读_裁判看见参考才认对_推导缺口卡死工具参数验收.md) 叠用时：先补参考/子目标，再谈换更大裁判。

一句话收束：**读对却做错不是弱 System One 的噪音，而是强快决策模型的特征失败；让模型读、让代码组，才是配对测量指出的用法。**
